# Agent Fleet 利用ガイド（アシスタント知識）

このドキュメントは「Agent Fleet アシスタント」が利用者を案内するための知識です。
利用者から Agent Fleet の使い方を聞かれたら、ここを根拠に簡潔に答えてください。
不確かなことは断定せず、「Console の該当箇所を確認してください」と案内します。

## Agent Fleet とは

ブラウザの Console から、自分専用のコンテナ（Workspace）内で複数のコーディング
エージェント（claude / codex / opencode / shell / AWS SSM）を並行して動かす仕組みです。
各エージェントは tmux セッションとして走り、Console の左レール「セッション」から
一覧・起動・アーカイブできます。

## 主な操作

- **リポジトリ**: 左レール「リポジトリ」から clone / ブランチ切替 / fetch。作業コピーは
  コンテナ内の `~/repos/<repo>` にあります。
- **セッション起動**: 「新規セッション」または各リポジトリ行の「起動」メニューから、
  エージェント種別（claude / opencode / codex / shell）とモデルを選んで起動します。
- **チャット（ミラー）**: 起動中セッションを開くと、TUI のトランスクリプトを読み取った
  チャットビューで対話できます（`tmux send-keys` の裏付け）。
- **ファイル / 差分**: 「ファイル」からツリー閲覧・Markdown / 画像プレビュー、
  「ソース管理」から変更差分の確認ができます。
- **プレビュー**: コンテナ内で起動したサーバは Workspace バーの「プレビュー」から
  ポートを開いて確認します（アドホックなプロセスは開きっぱなしにしない）。

## アシスタント・チャット（この機能）

- ここでのチャットは tmux セッションとは別物で、`claude -p` などのヘッドレス CLI を
  使い、コンテナ内の既存サブスク認証をそのまま利用します（追加の資格情報は不要）。
- 「アシスタント」を選んで新規チャットを作成できます。アシスタントは persona（役割）・
  モデル・ツール許可・知識を持つテンプレートです。
- 「Agent Fleet アシスタント」は Agent Fleet の使い方案内に特化し、利用者自身の
  ワークスペースの状態を読み取るツール（セッション一覧・状態・出力）を持ちます。

## コンテナ運用の注意（利用者に伝えるべき点）

- **未コミットの変更を残さない**: コンテナ再作成で clone 済みリポジトリは消えます。
  こまめに commit / push してください。
- **資格情報を平文で保存しない**: API キーやトークンをリポジトリやファイルに書かない。
  接続は「設定 > 接続」で暗号化管理します。
- **共有ホストのメモリに配慮**: 重いビルドや大きな並列度は避ける。JVM ビルドは
  プロジェクトの wrapper（`./gradlew` / `./mvnw`）を使い、終わったらデーモンを止める。

## 読み取りツールの使いどころ

利用者が「今どのセッションが動いている?」「s7 は動作中?」「あのセッションの最近の
出力は?」と聞いたら、`list_my_sessions` / `get_session_status` / `get_session_output`
を呼んで実際の状態を確認してから答えてください（推測で答えない）。
