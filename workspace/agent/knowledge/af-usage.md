# Agent Fleet 利用ガイド（アシスタント知識）

このドキュメントは「Agent Fleet アシスタント」が利用者を案内するための知識です。
利用者から使い方を聞かれたら、ここを根拠に、画面に表示される日本語を使って簡潔に
答えてください。不確かなことは推測せず、読み取りツールまたは Console の表示を確認します。

## Agent Fleet とは

ブラウザの Console から、自分専用の作業環境（ワークスペース）で複数のコーディング AI を
動かす仕組みです。セッションは、1 つの仕事に対応する**会話・作業場所・実行状態のまとまり**です。
ターミナルや専用の CLI プロセスと 1 対 1 とは限りません。

Codex / OpenCode の新しいセッションでは、次の**実行方式**を選べます。

- **マネージド（既定）**: 共有の実行基盤を使い、チャット表示から操作します。ターミナルはありません。
- **ターミナル（CLI）**: セッションごとに CLI の対話画面を起動し、ターミナルから直接操作します。

Claude はターミナル（CLI）、shell / SSM はターミナルだけを使います。`driver`、`runtime`、
TUI、PTY、tmux は内部の実装用語です。利用者への通常の案内では使わず、仕組みを聞かれたときだけ
説明します。tmux はターミナル（CLI）の画面をブラウザ切断後も保持するために使われますが、
利用者が tmux コマンドを直接操作する必要はありません。

## 画面と主な操作

画面最上部にはテナント選択、通知、設定、アカウント操作があります。その下の
**ワークスペース操作バー**には、状態、起動・停止、「はじめる」、プレビュー、画面分割があります。
左ペインには、アシスタント、メモキュー、リポジトリ、その他のセッション、ファイルが並びます。

- **新しい仕事を始める**: ワークスペース操作バーの「はじめる」から、チャット、リポジトリ、
  ホーム、shell、SSM のいずれかを選びます。リポジトリ行の「起動」からもセッションを作れます。
- **リポジトリ**: 左ペインの「リポジトリ」からクローンし、作業コピーやセッションを確認します。
  作業コピーはワークスペース内の `~/repos/<repo>` にあります。
- **セッション**: チャット表示から会話を読み書きします。ターミナル（CLI）のセッションだけは
  「チャット ⇄ ターミナル」で表示を切り替えられます。マネージドにはターミナル表示がありません。
- **ファイルと差分**: 「ファイル」からツリーや Markdown・画像を表示し、「ソース管理」から
  変更差分やコミット履歴を確認します。
- **プレビュー**: ワークスペース内で起動した Web サービスは、ワークスペース操作バーの
  「プレビュー」にポート番号を入れて開きます。表示方法は 2 つあり、用途で使い分けます。
  - **ペインで開く**: アクティブペインに Console 内蔵ブラウザで表示します。Vite の HMR、
    WebSocket、SSE、Spring Boot など、更新が入る／操作するアプリはこちらを案内します。
    同時に開けるのは最大 2 ページ、表示は最大 1600×1200・約 12fps です。ポートがまだ
    listen していないときは `target-unreachable` と表示され、サーバー起動後に「再読込」で
    復旧します。`crashed` / `disconnected` はコンテナ内 Chromium の停止や接続断で、
    ツールバーの「再接続」で復旧します。
  - **軽量プレビュー**: `/preview/{ポート}` を新しいタブで開きます。単純な HTTP 表示なら
    これで十分です。
  - スマートフォン表示では現状「ペインで開く」導線がないため、その旨を伝えてください。
- **コマンドパレット**: **Ctrl+P**（macOS は **⌘P**）で、画面の操作・セッション・
  リポジトリを検索して実行できます。端末入力を優先する設定で端末にフォーカスがある場合は、
  既定の **Ctrl+K → ;**（macOS は **⌘K → ;**）を案内してください。**Tab** で
  コマンド／変更ファイル／ファイルを切り替え、**?** でショートカット一覧を開けます。

## セッションを中断・整理する

迷ったらセッション行のメニューで**「停止する」**を選びます。会話と一覧が残り、あとで再開できます。

- **停止する**: 処理を止め、「停止中」として一覧に残します。
- **アーカイブする**: 終わった AI セッションを、会話を残したまま普段の一覧から隠します。
- **作り直す**: 現在の会話をアーカイブし、同じ作業場所で新しい会話を始めます。
- **削除する**: shell / SSM などを一覧から消します。元には戻せません。

ワークスペース自体を停止しても、リポジトリ、未コミットの変更、セッション一覧、接続情報は残ります。
停止中もセッション一覧は見られますが、中身の操作にはワークスペースの起動が必要です。

## アシスタントチャット

左ペインの「アシスタント」は、リポジトリや継続的な作業状態を持たないチャットです。
通常の質問は新規チャットへ入力します。ファイルの翻訳・要約は、ファイルの右クリックメニューにある
「アシスタントで翻訳」「アシスタントで要約」から始められます。

常設されるのは、Agent Fleet の案内、複数セッションを扱うフリート・オペレーター、SRE の相談など、
固有の知識やツール権限を持つアシスタントです。利用者は名前、役割、モデル、ツール許可、知識を
設定したアシスタントを自分で作ることもできます。

アシスタントのモデルを指定しなければ、新しい会話にはエージェント別の既定モデルが記録されます。
現在の既定は codex が **Luna**、opencode が **Nemotron** です。利用者がモデルを指定した場合はその値を
優先し、既存の会話のモデルは変わりません。既定名や提供可否が不確かなときは、会話の表示または
設定画面を確認して案内してください。

エージェント（claude / codex）のサブスクリプション使用量とレート制限は、ワークスペースバーの
使用量チップのほか、アシスタントに聞けば実際の値（5時間枠・週間枠の使用率と解除日時）を
確認して答えます。opencode には使用量の取得元がありません。
セッションごとの現在のコンテキスト使用量と累積消費トークンも、ミラー画面のコンテキストバーの
ほか、アシスタントに聞けば実際の値を確認して答えます（shell / SSM セッションは対象外）。

「Agent Fleet アシスタント」は読み取り専用です。セッションへの指示、新しいセッションの作成、
セッションの停止・再開、メモの追加・送信が必要なら「フリート・オペレーター」を案内します。
フリート・オペレーターによる停止は再開可能な「停止中」で、会話と作業は残ります。
フリート・オペレーターもファイルを直接編集せず、作業セッションを通じて実行します。

## 会話を引き継いで分岐する

稼働中の claude / codex / opencode セッションでは、行の **⋯** メニューから引継ぎ先エージェントを
選べます。これは会話全文をそのまま複製する操作ではありません。フリート・オペレーターが元セッションの
状況を確認し、要点・未完了タスク・変更済みファイル・次の作業の引継ぎ案を示します。

利用者が引継ぎ案、作業フォルダ、開始エージェントを明示的に同意した後だけ、新しいセッションを
作成します。元のセッションは残ります。依頼時に「今は案だけ作って」「同じエージェントで別の方針を
試したい」と言われたら、この確認手順を案内してください。

## データを失わないための注意

- ワークスペースの通常の**停止・起動**では、リポジトリや未コミットの変更は消えません。
- 設定の危険な操作にある**「ワークスペースを作り直す」**は `~/repos` を削除します。
  **「ホームを掃除する」**は接続情報以外のホームも削除します。どちらも実行前にコミット・push が必要です。
- API キーやトークンをリポジトリやファイルへ平文で保存しません。接続は設定画面で管理します。
- 重いビルドや大きな並列度を避けます。JVM ビルドはプロジェクトの wrapper
  （`./gradlew` / `./mvnw`）を使い、不要なデーモンや開発サーバーを残しません。

## 読み取りツールの使いどころ

利用者が「今どのセッションが動いている?」「このセッションは動作中?」「最近の出力は?」と
聞いたら、`list_my_sessions` / `get_session_status` / `get_session_output` を使い、実際の状態を
確認してから答えてください。ターミナルが無いことだけを理由に、停止中または履歴が無いと判断してはいけません。
