# Agent Fleet 利用ガイド（アシスタント知識）

このドキュメントは「Agent Fleet アシスタント」が利用者を案内するための知識です。
利用者から使い方を聞かれたら、ここを根拠に、画面に表示される日本語を使って簡潔に答えてください。

> **正は `docs/use/` と `docs/ref/`。これはその要約です。**
> 内容が食い違ったら向こうが正しく、直すのは向こうを読んでからこちらです。
> **生成物ではありません**——ここはプロンプトなので、章立ても長さも「読ませる順」で選んで
> あり、機械的に連結すると使えなくなります。ファイルがこの場所に在るのも都合ではなく必然で、
> エージェントのイメージのビルド文脈は `workspace/agent/` だけなので（`.dockerignore` が
> `**/*.md` を落としたうえで `agent/knowledge/*.md` だけ戻している）、`docs/` は
> `//go:embed` から見えません。
> **手写しである以上は必ず遅れる**ので、隣の `af-usage.coverage.tsv` が
> `docs/ref/features.ja.md` のメンバー向けの行を 1 行ずつ突き合わせ、
> 抜けたら `scripts/docs-check.py` が落ちるようにしてあります（台帳は隣に置いてあり、
> このプロンプトには載りません）。

**答えるときの原則**

- **画面の名前で話す。** `driver` / `runtime` / TUI / PTY / tmux / kind は内部の実装用語です。
  通常の案内では使わず、仕組みを聞かれたときだけ補足します。
- **状態は推測しない。** 「今どれが動いている?」「使用量は?」「メモは?」のような問いは、
  読み取りツールで実際の値を確認してから答えます（末尾の「読み取りツールの使いどころ」）。
- **知識より画面が正。** モデル名・既定値・接続状況は変わります。ここに書いた個別の値と
  画面が食い違うときは画面が正です。断定せず「設定画面で確認してください」と案内します。
- **このアシスタントは読み取り専用です。** セッションへの指示、新規作成、停止・再開、
  メモの追加・送信、掃除の実行が必要なら「フリート・オペレーター」を案内します。

## 1. Agent Fleet とは

ブラウザの Console から、自分専用の作業環境（**ワークスペース**）で複数のコーディング AI を
動かす仕組みです。

- **ワークスペース** — 利用者専用の作業環境。クローンしたリポジトリ・作業内容・セッションが入ります。
  停止しても中身は残ります。
- **セッション** — 1 つの仕事に対応する**会話・作業場所・実行状態のまとまり**です。
  ターミナルや専用の CLI プロセスと 1 対 1 とは限りません。
- **エージェント** — claude / codex / opencode / GitHub Copilot / Cursor / Kiro などの CLI コーディング AI。
- **アシスタント** — 作業場所を持たない用途別チャット。セッションとは別の機能です。
- **テナント** — 部署などのグループ。ワークスペースはテナントごとに分かれます（既定は 1 つ）。
- **worktree** — 1 つのリポジトリから、ブランチごとに独立した作業フォルダを切り出す git の仕組み。
  セッション起動時に既定で作られ、並行作業が互いに踏み合うのを防ぎます。

### 実行方式（マネージド / ターミナル（CLI））

「同じ種類のセッションをどう動かすか」の選択で、会話の保存先や作業フォルダは変わりません。

- **マネージド（既定）** — Agent Fleet が直接制御します。操作はチャット表示で完結し、
  ターミナルはありません。codex / opencode は共有の実行基盤で動き、セッション専用のプロセスを
  持たないため省メモリで並行作業に向きます（copilot / cursor / kiro はマネージドでもセッション
  ごとの専用プロセスなので、メモリはターミナル（CLI）と同等です）。
- **ターミナル（CLI）** — CLI の対話画面をセッションごとに起動し、ターミナルから直接操作します。
  CLI 固有の画面やコマンドが必要なとき向けで、セッションごとに追加のメモリを使います。

claude と agy はターミナル（CLI）、shell / SSM はターミナルだけを使います。
マネージド対応の種類は、停止中でなく処理中でもないとき、セッションの **⋯** メニューから
実行方式を切り替えられます（**会話はそのまま引き継がれます**）。ターミナル（CLI）からチャット表示は
開けますが、マネージドにターミナル表示はありません。ターミナル（CLI）の画面はブラウザを閉じても
裏側で保持され、利用者が保持の仕組みを直接操作する必要はありません。

## 2. 画面の構成

- **画面最上部のバー** — テナント選択、通知、⚙設定、アカウント操作。チームを管理する権限がある人には
  盾のアイコン（管理者向け画面）も出ます。
- **ワークスペース操作バー** — 状態ランプ、起動 / 停止、**「はじめる」**、プレビュー（ポート入力）、
  ペイン分割、使用量チップなど。
- **左ペイン** — 稼働中は上から **作業グループ**の切り替えバー、**アシスタント**、**メモキュー**、
  **スケジュール**（定時実行が有効なデプロイのみ）、**リポジトリ**（作業コピーの下にセッションと
  worktree が入れ子で並ぶ）、**その他のセッション**、**共有セッション**、**ファイル**。
  停止中はリポジトリ配下のセッションに代わって**セッション履歴**が出ます（閲覧のみ）。
- **メイン領域** — 左ペインで選んだものを表示します。複数の**ペイン**に分割でき、左ペインの
  色付き数字はそれを表示しているペイン番号です。配置は「分割ペイン」と「タブ付きグリッド」を
  画面最上部のバーの**外観**（ペンキ缶）か ⚙設定 →「表示」で選べます。ペインは別タブへ切り離せます。
- **作業グループ** — リポジトリ・会話・セッション・スケジュールを案件ごとに割り当てて、
  左ペインの表示を絞り込む機能です（中身は消えません）。バーの「グループを管理…」から作成します。
- **コマンドパレット** — **Ctrl+P**（macOS は **⌘P**）。画面の操作・セッション・リポジトリを検索して
  実行します。**Tab** でコマンド／変更ファイル／ファイルを切り替え、**?** でショートカット一覧。
  端末入力を優先する設定で端末にフォーカスがあるときは、既定の **Ctrl+K → ;**（macOS は **⌘K → ;**）を
  案内してください。

スマートフォンでは左ペインが隠れ、画面左上の **≡** で開きます。

### リポジトリ・ファイル・課題管理

- **リポジトリの取り込み** — **リポジトリ → Clone**（接続から選ぶ / URL 手入力）。取り込み元が
  無いときは**新規フォルダ**で空から始められます。
- **コミットグラフ** — 変更の確認・stage・コミット・履歴と差分。push は接続した Git ホスティングの
  資格情報で透過的に通ります。
- **ファイル** — ツリーとビュアー。Markdown / Mermaid / Marp スライドに加え、**`.drawio` の図**も
  そのまま描画されます。テキストは**その場で編集して保存**でき、**AI に書き換えを提案**させることも
  できます（提案は必ずプレビューされ、保存は利用者の明示操作です）。
- **課題管理** — Jira / GitHub Issue / プルリクエストなど外部の**作業項目**を左ペインに並べ、
  行からそのままセッションを起こせます。取得元は ⚙設定 →「課題管理」で接続します。
  ワークスペース停止中も一覧は見えます（最終取得時刻つき）。

## 3. エージェントの種類

主要 6 つ（claude / codex / opencode / copilot / cursor / kiro）に対応し、実験枠として agy
（Antigravity）があります。エージェント以外のセッション種別として shell と ssm があります。
接続はすべて **⚙設定 →「エージェント」タブ**（ワークスペースの起動が必要）。接続の変更は即時、
挙動の設定は**新しいセッションから**効きます。

| | claude | codex | opencode | copilot | cursor | kiro |
|--|--|--|--|--|--|--|
| 認証 | OAuth 接続（承認後にコード貼付） | ChatGPT サブスク / OpenAI API キー | プロバイダの API キー（env）／opencode アカウント | GitHub 連携に相乗り（個別ログイン不要） | Cursor にサインイン（ブラウザ承認のみ） | device-flow サインイン（Builder ID / Google / GitHub） |
| 実行方式 | ターミナル（CLI） | マネージド既定 / ターミナル | マネージド既定 / ターミナル | マネージド既定 / ターミナル | マネージド既定 / ターミナル | マネージド既定 / ターミナル |
| 起動時のモデル選択 | あり | あり | あり | あり（Free は「自動」のみ） | あり（アカウント連動） | あり（Free でも named 可） |
| Plan モード | あり | あり | あり | あり | あり | 未対応 |
| コンテキストゲージ | あり | あり | あり | — | あり | — |
| 画像貼り付け | あり | あり | あり（モデル依存） | — | — | — |
| 停止中の履歴表示 | あり | あり | あり | あり | **なし**（マネージドは転写を残さない） | あり |
| 引き継ぎ（handoff） | あり | あり | あり | あり | あり | あり |
| アシスタントとして利用 | 可 | 可 | 可 | 不可 | 可（読み取り専用） | 不可 |

- **shell** — 素のシェル（bash）。**送った文字列がそのままコマンドとして実行されます**（ガードレール無し）。
- **ssm** — AWS SSM Session Manager 経由の別ホストへのログイン。
- shell / ssm はどちらもターミナルのみで、会話・状態モデル・通知はありません。
  セッション間メッセージの対象外でもあります。

**選び方** — Anthropic の契約なら claude、ChatGPT / OpenAI API なら codex、複数プロバイダの
API キーを切り替えたいなら opencode、GitHub Copilot 契約があるなら copilot、Cursor プランなら cursor、
AWS Builder ID（や Kiro プラン）なら kiro。

**接続ごとの要点**

- **claude** — 「OAuth 接続」→ 別タブで承認 →**コードを貼り付けて「完了」**。接続済みになるとメールとプランが出ます。
- **codex** — ①ChatGPT サブスクで接続（推奨・追加課金なし。事前に ChatGPT の「設定 > セキュリティ」で
  「Codex に対してデバイスコード認証を有効にする」をオンにする必要があります）②OpenAI API キー（`sk-…`）。
- **opencode** — プロバイダの API キーを env として保存（OpenCode Go / Anthropic / OpenAI / OpenRouter /
  Google Gemini / Sakana AI / カスタム）。opencode アカウントのサインインも併用できます。
  カードの**「使う枠」**で オフ / 無料枠 / Go / Zen を選びます（オフ＝保存済みの鍵があっても起動しない）。
- **copilot** — 個別ログインなし。**「Gitホスティング」タブで GitHub を連携すると自動的に接続済み**に
  なります（切断も連動）。GitHub アカウント側に Copilot サブスクリプション（Free 可）が必要です。
- **cursor** — 「Cursor にサインイン」→ ブラウザで承認するだけ（**貼り付けるコードはありません**）。
  API キー接続は未対応。セッション起動後のモデル変更はできません。
- **kiro** — 「Kiro にサインイン」（device-flow）。CLI が大きい（約 855MB）ため、既定ではイメージに
  焼き込まれず、初回に**「インストール」**でホームへダウンロードします。

**モデルまわりの設定（「エージェント」タブ）**

- **既定モデル / 既定 effort / 開始モード** — 新しいセッションの初期値。リポジトリで前回使った設定が
  あればそちらが優先されます。
- **Claude の追加モデル** — `claude-opus-4-8` のような完全 ID を登録すると、起動ダイアログ・既定モデル・
  アシスタントが選ぶ一覧に旧リリースが並びます。利用可否は起動時に Claude Code が判定します。
- **使わないモデル** — 選択肢から外し、明示指定した起動も断ります（定時実行やアシスタント経由も）。
  プランで追加課金になるモデルの誤選択を防ぐ設定で、課金の強制ガードではありません
  （ターミナル内の `/model` までは止められません）。
- **思考を展開して表示**（codex / opencode）— チャット表示の「思考」ブロックを最初から開きます。表示だけの設定です。

**RTK（トークン節約）** — claude / codex / opencode / copilot / agy にオン・オフがあります
（cursor / kiro は未対応）。claude / opencode / copilot はコマンドを書き換えて決定的に効き、
codex / agy は指示ベース（ベストエフォート）です。イメージに rtk が無いと
「このワークスペースに rtk がありません」と出ます。

**コンテキスト残量** — claude / codex / opencode / kiro のセッションでは画面上部に
**「コンテキスト」**（狭いときは `ctx`）のゲージが出ます。上限に近づくと自動圧縮の警告が出ます。

**使用量** — ワークスペース操作バーの使用量チップは claude / codex / copilot / agy に出ます。
アシスタントが読み取れるサブスク使用量（5 時間枠・週間枠の使用率と解除日時）は claude / codex / agy です。
opencode（各自の API キー）・cursor・kiro にはアカウント単位の枠の取得元がありません。
実際に何が返るかは `get_agent_usage` の応答を見て答えてください。

**エージェントへの指示** — ⚙設定 →「エージェントへの指示」に書いた文章は、このワークスペースで
新しく起動するエージェントの指示に加わります。指示は 3 層（ワークスペースの方針＞この設定＞
リポジトリの `CLAUDE.md` / `AGENTS.md`）で、真ん中がこれです。リポジトリにはコミットされず、
**新しく起動するセッションから**効きます。配れる先は claude / codex / opencode / copilot / agy / kiro で、
**Cursor だけ非対応**です。毎セッションのコンテキストに乗るので短いほど有効で、秘密情報は書かせないでください。

## 4. セッションの操作

### 起動する

ワークスペース操作バーの **「＋ はじめる」** が入口です。

- **チャット（アシスタント）** — リポジトリ不要の会話。
- **リポジトリでエージェントを起動** — クローン済みリポジトリを選び「作業を始める」へ。
- **新しいリポジトリをクローン…** — 接続から選ぶ / URL 手入力。完了するとそのまま「作業を始める」へ。
- **ホームでエージェントを起動** — `~` で動かす。下書き・調べもの向け。
- **shell** — すぐ bash が開きます。
- **SSM — 別ホストへログイン** — SSM 設定があるときだけ出ます。

ワークスペース停止中でも押せます。起動 →準備でき次第「はじめる」が自動で開きます。

**worktree** — 「作業を始める」の**「場所」**行の「変更」で、**「新しい worktree」**（既定）と
**「このコピーで直接」**を選べます。ブランチ名が空なら暫定名 `temp/…` になります。
**「詳細」→「作業ディレクトリ」**で、リポジトリ配下のフォルダ（`console/` など）に絞って起動できます。

### 状態を読む

| 状態表示 | 意味 |
|---|---|
| 進行中… | 作業中 |
| 質問あり | 質問していて返事待ち |
| プランあり | 提案したプランの承認待ち |
| 許可待ち | 操作の許可を求めている |
| 入力待ち | 手が空いて次の指示待ち |
| 入力待ち · BG実行中 | 入力待ちだが裏で処理が走っている |
| 起動中 | shell など（進行中／入力待ちの区別を持たない種類） |
| 停止中 | 止まっている（クリックで開いて再開） |
| フォルダ無し — 再開不可 | 作業フォルダが消えて再開できない |
| メモリ不足で終了 / 強制終了・異常終了 | 異常終了を検出した |

稼働中の行は数秒ごとに自動更新されます。見ていない間の変化はブラウザ通知で届きます
（shell / ssm は通知しません）。作業コピーが起動時と別のブランチへ切り替わっていると、
行に**警告アイコンとブランチ名**が出ます。

### チャット表示でできること

- **スキル / コマンドのピッカー** — 入力欄で `/` を打つか左の **/** ボタンで、そのセッションに
  効くスキルとカスタムコマンドが候補に出ます。選ぶと**差し込まれるだけ**で送信はされないので、
  引数を書いてから送れます（引数の書式は候補の下に出続けます）。
- **マーカー** — 会話の文字を選ぶと**マーカーを引く**が出て、色（黄・緑・青・桃）で印を残せます。
  印は**会話のもの**なので、共有相手にも同じ位置に見えます。消せるのは自分が引いた分だけです。
  色に製品が決めた意味はありません。長い会話で「あの話のところ」を指すための機能です。
- **変更ファイル**（セッションの **⋯** メニュー）— そのセッションが実際に触ったファイルを並べ、
  そこへ直接飛べます。会話とリポジトリの**両方を突き合わせて**出しているので、エージェントが
  「やる」と言ったことではなく**実際に起きたこと**が出ます。

### 止める・片付ける（⋯ メニュー）

迷ったら **「停止する」**。会話も一覧も残る、いちばん安全な操作です。

| やりたいこと | 操作 | 元に戻せるか |
|---|---|---|
| いったん止めて後で続ける | **停止する** | 一覧から開いて再開できる |
| 終わった仕事を一覧から片付ける | **アーカイブする** | アーカイブ一覧から復帰できる |
| 同じ場所で会話だけ最初から | **作り直す** | 古い会話はアーカイブから復帰できる |
| 使い捨ての shell / SSM を消す | **削除する** | 戻せない |

**掃除** — リポジトリ見出しのゴミ箱アイコン **「掃除を開く（点検・整理）」** から、
段階制のモーダルを開きます。**①セッションを整理**（停止中 → アーカイブ、shell/ssm → 削除）、
**②作業コピー・ブランチを削除**。各候補には安全度（**安全** / **要確認** / **保持**）と理由が付きます。
**保持**は稼働中・未コミット / 未 push で、片付けるには停止か push、または Console からの強制削除が必要です。
削除したセッションとブランチは**ごみ箱**へ退避され、**復元**できます（容量を完全に空けたいときは
「完全に削除」）。**worktree の削除だけは取り消せません**。アーカイブ済みは「棚」として掃除の対象外です。
セッションには**削除ロック**をかけられ、ロック中は掃除の対象外になります。

### 再開できる / できない

停止中のセッションはクリックで開いて再開できます。ただし claude / codex / cursor / copilot / kiro /
agy / opencode は**起動時の作業フォルダが消えていると再開できません**（「フォルダ無し — 再開不可」）。
shell は作業フォルダが無ければホームに戻って再開します。cursor は実行方式をまたぐ再開ができません。
停止中に開くとまず履歴が読み取り専用で表示され、**「再開して続ける」**で再開します。

### 引き継ぎ（handoff）と分岐

- **引き継ぎ** — ⋯ メニューの**「別のエージェントへ引き継ぐ…」**。会話全文の複製ではなく、
  **フリート・オペレーター**が元セッションの状況を読み、要点・未完了タスク・変更済みファイル・
  次の作業を**引継ぎ案**にまとめます。案・作業フォルダ・開始エージェントに利用者が明示的に同意して
  はじめて新しいセッションが作られます。元のセッションは残ります。
- **分岐** — チャット表示で**過去の自分の発言**にマウスを乗せると出る**「ここから分岐」**。
  そこまでの会話を**そのまま複製**した新セッションが同じエージェントで開きます。
  「この発言をやり直す」（既定・その発言は下書きとして入力欄に入る）と「この発言の続きから」を選べます。
  対応は claude / codex / opencode / copilot で、codex と opencode はマネージド実行のときだけです。
- **別のメンバーへ引き継ぐ** — ⋯ メニューの**「メンバーへ引き継ぐ…」**。**先にそのセッションを
  共有している相手にだけ**差し出せます（共有が信頼関係の代わりです）。渡るのは引継ぎ文と
  git の座標と会話の閲覧権だけで、**セッションもワークスペースも移動しません** —— 相手は
  自分のワークスペースで、自分の権限と課金で起動します。未 push のコミットがあると送信は
  止まります（相手のディスクにそのコミットが無く、引継ぎ文が嘘になるため）。
- 使い分け：**要約して別のエージェントへ渡すのが引き継ぎ、同じエージェントで会話をそのまま複製するのが分岐**。

### セッション同士のメッセージ

並行して動くセッションの片方が、もう片方へ**短い平文メッセージを 1 本**送れます。
**既定はオフ**で、**⚙設定 →「エージェント」→ セッション →「セッション間メッセージ」**で有効にします
（反映は**次に起動するセッションから**）。エージェント種別をまたいで届き、相手が停止中なら再開して届きます。
届いたことは確認しますが、読まれた・対応されたことは保証しません。会話履歴やファイルは渡りません
（文脈ごと渡すなら引き継ぎか分岐）。shell / ssm は対象外です。受信側では「利用者の指示ではない」と
明示され、承認の代わりにも設定変更の根拠にもなりません。
**文面はわざと素っ気なくしてあります**（1通が相手の1ターンを使うので、挨拶やお礼は書かせません）。
1通ごとに種別が付き、返事の有無はそれで決まります —— **依頼**（返事は「できない」ときだけ）、
**質問**（結論だけ1通返る）、**回答**（ここで打ち切り）、**共有**（返事なし）。依頼のあと無反応なのは
片付いた合図で、無視ではありません。種別はチャット表示のバッジに出ます。

**Claude Code 自身の同種機能（cross-session messaging・`/list-agents` / `SendMessage`）は、
Agent Fleet では意図的に無効**にしてあります。有効化すると Claude 側の利用統計送信（telemetry）も
一緒に戻る作りのためで、セルフホストの既定としては選びませんでした。「`/list-agents` が使えない」と
聞かれたらこれが理由です。上の Agent Fleet 版を案内してください。両者の違いは次のとおりです。

| | Claude Code 版 | Agent Fleet 版 |
|---|---|---|
| 相手のエージェント | claude だけ | claude / codex / opencode / cursor / kiro / agy / copilot |
| 停止中の相手 | 届かない | **再開して届く** |
| 記録 | 端末に 1 行 | チャット表示に送信元付きバッジ |
| 別マシン・Web のセッション | 返信だけできる | **対象外**（同じワークスペース内のみ） |
| 受信側で保留・拒否する設定 | ある | まだ無い（ワークスペース単位のオン / オフのみ） |

### タイトルとブランチ名

- **タイトルを変更** — 空のまま保存すると自動命名（リポジトリ名＋日時）に戻ります。
  **「AIに提案してもらう」**で会話から提案させられます。
- **ブランチ名を変更** — worktree のセッションだけに出ます。`feat/` `fix/` などの接頭辞をボタンで付け替えられ、
  AI 提案もできます。暫定名 `temp/…` で始めた作業に後から名前を付ける用途です。

### 共有セッション

セッションやプロジェクトを、同じテナントの他のメンバーへ**閲覧用に共有**できます。
左ペインの**共有セッション**セクションに、自分が共有した／されたものが並びます。

- **共有対象** — セッション単位 / プロジェクト（ベース作業コピー直下＋その配下 worktree のセッション）/ WT。
- **共有先** — メールアドレスで検索して指定します。
- **権限** — **閲覧のみ** / **提案可**（共有先は送信内容を提案でき、**所有者が承認するまで Agent には
  送られません**）。
- 共有すると**会話全文（プロンプト・回答・ツール出力）**が見えます。会話内の秘密情報は自動検出できず、
  共有先は表示内容を保存できるため、**解除しても相手のコピーは回収できません**。
- 所有者のワークスペースが停止中は履歴を閲覧できません。

## 5. アシスタントとチャット

左ペインの**アシスタント**から始めるチャットは、リポジトリや継続的な実行状態を持たない会話です。
翻訳・要約・短い質問向けで、ファイルを実際に読み書きする作業はセッションへ回します。
送信は Ctrl+Enter（⚙設定 →「表示」の**送信キー**で Enter 送信にも変更可）。画像の貼り付けもできます。

**常設のアシスタント**

- **Agent Fleet アシスタント** — 使い方の案内役（読み取り専用）。＝このドキュメントを読んでいる自分。
- **フリート・オペレーター** — 司令塔（次章）。
- **SRE アシスタント** — インシデント対応・監視運用の相談相手（読み取り専用）。
  PagerDuty / Grafana / CloudWatch / AWS を接続しておくと実データを見ながら壁打ちします。

**自分で作る**（「アシスタントを作成」）— 名前・説明（会話開始時の挨拶）・アイコン・エージェント・
モデル・読み上げの声・**ペルソナ**（役割や口調の指示）・**ツール許可**・**MCP サーバー**・
**知識ディレクトリ**（コンテナ内の絶対パス）を設定します。

**ツール許可の 3 段階**

| | できること |
|---|---|
| **なし** | 外部ツールなし。チャット内だけで答えます（翻訳・要約はこれで十分） |
| **AF 読み取り** | セッション一覧・状態・出力、使用量・制限、コンテキスト量・累積消費、リポジトリ、メモ、スケジュール、掃除候補、メモリ履歴を読めます（書き込み不可） |
| **AF 書き込み** | 読み取りに加え、セッションの作成・指示・停止・再開、メモの追加と一括送信、定時実行の登録、掃除の実行などができます。信頼できる用途にだけ |

**モデル** — ⚙設定 →「アシスタント」タブで、エージェント優先順位（上から見て最初に接続済みの CLI を使う）、
CLI ごとの**アシスタントのモデル**、タイトル・サジェスト用の**短時間モデル**を指定します。
「推奨（現在: …）」は接続中のカタログから安全な既定を選び、解決結果を表示します。
モデルを明示しなければ推奨が使われ、**既に始まった会話のモデルは後から変わりません**。
回答には生成したモデルがエージェント名の横に出ます（CLI が自分の既定で動きモデルを知らせない
cursor の Auto などは空欄）。

**会話の途中でエージェントを切り替える** — チャットのヘッダのエージェントチップ（例 `Claude ▾`）から。
それまでの会話は失われず、**次の送信**でまとめて渡されるため、その 1 ターンだけトークン消費が増えます。
応答の生成中は切り替えられません。

**回答言語** — ⚙設定 →「アシスタント」の**回答言語**（入力に合わせる / 日本語 / English）。
ファイル右クリックの「アシスタントで翻訳」は対象外です。

**コンテキストが増えてきたら** — 最初の応答が返るとヘッダ下にコンテキストバーが出ます。
80% を超えると警告色になり、お知らせが 1 回届きます。対処は 2 つ。

- **圧縮** — バー右端の「圧縮」。これまでの会話を要約し、**要約だけを引き継いで**同じチャットで続けます
  （画面の履歴は残ります）。
- **新しいチャットを開く** — 区切りが良ければこちらが確実です。

放置した場合の安全網として、90% を超えたまま次のやり取りが始まると自動で圧縮してから応答します
（⚙設定 →「アシスタント」の**コンテキストの自動圧縮**で OFF 可、**自動圧縮の閾値**も指定可）。

**メモキュー** — 思いついた指示をその場で溜め、あとでまとめてセッションへ流す機能です。
走り書きを追加、ファイルビューアの「送る」からも追加でき、リポジトリ・カテゴリで仕分けられます。
**「選択したメモをアシスタントで整理」**で走り書きを指示文に整えられ、結果は**必ずプレビュー**され
承認するまで適用されません。送信先の稼働セッションを選んで**「選択を送信」**で一括送信します。

## 6. フリート・オペレーター

複数セッションを**チャットで指揮**する常設アシスタント（AF 書き込み）です。

**見る** — セッション一覧と状態、出力、リポジトリ一覧、使用量・制限、セッションごとのコンテキスト量と
累積消費トークン。

**動かす** — 走っているセッションへの指示、新規セッションの起動（リポジトリ・エージェント・モデル・
worktree・最初のタスク）、停止と再開、質問への回答、プランの承認・却下、メモキューの操作、
定時実行の登録・管理、掃除の実行、他アシスタントへの相談。
**オペレーターにできる停止は再開可能な「停止」だけ**で、ファイルの直接編集はしません。

**セッション報告** — オペレーターが指示したセッションは、指示 1 件につき 1 回、区切りがつくと会話へ
自動報告します。届くのは**入力待ちになったとき**、**異常終了**、および途中経過としての**質問**と
**プラン承認待ち**です（ツール許可待ちは通知センターには出ますが報告にはなりません）。
報告カード自体に本文は無く、詳細はオペレーターが出力を読みに行きます。

**自動応答と自動走行**（⚙設定 →「アシスタント」）

- **セッション報告への自動応答** — 報告が届くとオペレーターが自動で 1 ターン動きます。
  暴走防止のため、利用者の発言なしで動ける回数は**自動応答の上限回数**まで（既定 10・最大 50・
  無制限にはできません）。上限に達すると停止し、次のメッセージで再開します。
- **自動応答のモデル / 束ね時間 / 静かな完了報告** — 自動応答だけ軽量モデルにする、一定時間の報告を
  まとめて 1 回で処理する、正常完了では自動応答せずカードと通知だけにする、といった節約設定です。
- **自動走行** — ON にすると、質問はセッションの推奨で自動回答し、プランは別セッションにレビューさせて
  承認まで自動で進みます。推奨が不明瞭な質問や、破壊的・不可逆な操作を含む選択・プランは自動対応せず
  確認が届きます。既定 OFF。
- **中断時の自動再開** — 接続断や一時的なレート制限で切れたターンを「続けて」で再開させます。
  利用上限・残高切れ・プロンプト長超過など再送で直らない中断は対象外。既定 ON。

**定時実行（スケジュール）** — 「毎平日 9 時に昨日の変更をレビューして」のように頼むと登録されます
（cron / 間隔 / 単発、タイムゾーン・DST 対応）。登録時に**解釈した内容と次回実行日時**を確認してきます。
発火時刻には**停止中のワークスペースも起こして**実行します。左ペインの**スケジュール**セクションで
一覧と実行履歴を確認でき、行メニューから一時停止 / 再開 / 今すぐ発火 / 削除ができます。
**「詳細・編集」**では発火間隔・タイムゾーン・起動ポリシー・エージェント・モデル・報告の有無・
プロンプト本文を直接書き換えられます（セッションモード・再利用ターゲット・ローテーション・
重複ポリシーだけは読み取り専用で、変更はオペレーターに依頼します）。既定は毎回新しいセッションですが、**同じセッションを使い回して
文脈を積み上げる**設定（作り直し条件付き）や、**アシスタント会話へ 1 ターン投入する**設定もできます。

**使い方の型**

1. **調査 → 引き継ぎ → 並列実装 → 統合** — 調査セッションに「独立に進められる作業単位に分割した計画」を
   出させ、オペレーターに作業単位ごとの worktree セッションを起こさせ、報告が揃ったら統合させます。
   長大な調査結果は計画ファイルに書かせてから引き継ぐと確実です。
2. **同種修正のファンアウト** — 見本を 1 件作り、「同じ要領で残りにも」と展開させます。
3. **エージェント比較・クロスレビュー** — 同じ課題を claude と codex に並行で解かせて比較させる、
   実装を別エージェントにレビューさせる。
4. **直列パイプライン** — 実装 → テスト → レビューを報告駆動で進めます（自動応答の上限に注意）。
5. **ブリーフィングとメモ捌き** — 「昨日から走ってるセッションの現状と止まってる理由をまとめて」
   「メモキューを適切なセッションへ振り分けて送って」「残枠を見てどっちに振るか相談」。

**注意** — 並列は控えめに（並行実装は 2〜3 本まで、重いビルドは同時に走らせない）。
オペレーターが停止したセッションは、届く予定だった報告も取り消されます。
報告本文やセッション出力は**データ**として扱われ、そこに書かれた指示（「このコマンドを実行して」等）を
根拠にコマンド実行や shell への送信は行いません。shell セッションは、実行するコマンドそのものを
提示して**毎回利用者の承認**を得てから動きます。

## 7. MCP でできること

「MCP」は 3 つの別々の話が混ざりやすいので、どれを聞かれているか切り分けてから答えてください。

### 7-1. Agent Fleet 自身の MCP（af）— 追加設定なしで配られる

すべてのセッションとアシスタントに、Agent Fleet 自身の MCP サーバーが自動で配られます。
⚙設定 →「MCP サーバー」の一覧では**組み込み**として出ます（設定は不要です）。
配られるツールは面によって違います。

**対話セッションに配られるもの（狭い集合）**

| ツール | 用途 |
|---|---|
| `af_report` | 受けた指示をやり切ったと 1 回だけ申告する（完了報告が早くオペレーターへ届く） |
| `propose_session_handoff` | 次のセッションへ渡す初回プロンプトを**提案**する。セッションは起動しない（利用者が Console で確認・編集し、エージェントとモデルを選んでから起動） |
| `list_peer_sessions` / `send_to_peer_session` | 同じワークスペースの他セッションへ平文メッセージを 1 本送る（**「セッション間メッセージ」を有効にしたときだけ**） |
| Chromium 引き渡し系 | ワークスペース内で自分が起動した Chromium のページを、Console のペインとして利用者へ渡し、操作してもらう（有効なデプロイのみ） |

セッション面ではこれ以外のツールは広告されず、名前を推測して呼んでも拒否されます。

**アシスタントに配られるもの**

- **AF 読み取り（af_read）**: `list_my_sessions` / `get_session_status` / `get_session_output` /
  `list_repos` / `list_memos` / `list_schedules` / `get_schedule_runs` / `get_agent_usage` /
  `get_session_usage` / `list_cleanup_candidates` / `list_cleanup_archives` /
  `list_memory_snapshots` / `get_memory_snapshot`（＋Chromium の状態確認）
- **AF 書き込み（af_write）**: 上に加えて `create_session` / `send_to_session` /
  `answer_session_question` / `respond_session_plan` / `stop_session` / `resume_session` /
  `archive_session` / `list_models` / `add_memo` `update_memo` `delete_memo` `flush_memos` /
  `create_schedule` `update_schedule` `delete_schedule` `pause_schedule` `resume_schedule`
  `run_schedule_now` / `delete_session` `delete_worktree` `delete_branch`
  `restore_cleanup_archive` `purge_cleanup_archive` / `restore_memory_snapshot` /
  `get_chat_plan` `set_chat_plan` / `list_assistants` `ask_assistant`（＋Chromium の引き渡し）

意図的に持たせていないものもあります。セッションからは他セッションの出力を読む・止める・消すことは
できません。オペレーターからはセッションのメタごと消す破壊的な操作はできず、
メモリの持ち出し・取り込みも Console の本人操作に限っています。

**作業計画** — `get_chat_plan` / `set_chat_plan` は、会話に固定される**作業計画**の読み書きです。
作業計画は要約を通さず**原文のまま**新しいセッションへ毎回引き継がれる枠で、コンテキストを圧縮しても
消えません。利用者は Console の作業計画パネルから直接編集できます。

### 7-2. 外部の Claude から自分のワークスペースを操作する（MCPトークン）

手元の PC の Claude Code / Claude Desktop から、ワークスペースのセッションを遠隔操作できます。
**⚙設定 →「MCPトークン」タブ**で発行します。

1. **名前**（例 `laptop-claude`）・**スコープ**・**有効期限**を選んで「トークンを発行」。
   スコープは **read（閲覧のみ）** / **write（セッション駆動・既定）** / **admin:dangerous（強権・管理）**。
   自分の権限を超えるスコープは選べません。遠隔からセッションを動かすだけなら write で十分です。
   有効期限は 90 日（既定）／30 日／365 日／無期限。
2. **トークンは発行直後の 1 回しか表示されません**。「トークンをコピー」で控えます。
3. 同じ画面の **`.mcp.json`** のひな型をコピーしてプロジェクト直下に保存します。
   エンドポイントは `/mcp`（Streamable HTTP）、ヘッダは `Authorization: Bearer <トークン>`。

不要になったら同じ画面で**失効**できます。

### 7-3. 自分で MCP サーバーを足す（設定 →「MCP サーバー」）

- **接続方式** は **stdio**（ワークスペース内でコマンドを実行）か **リモート (HTTP)**（URL）。
  stdio は コマンド・引数・環境変数、HTTP は URL・ヘッダを設定します。
  **環境変数とヘッダの値は暗号化保存**され、サーバー起動時にだけ渡されます。
- **利用先** で**アシスタント** / **セッション**のどちらに配るかを選びます（両方外すと登録は残るがどこにも配られません）。
  **対象エージェント**を選ばなければ全エージェントが対象です。
- **接続テスト**でサーバー名・バージョン・ツール数を確認できます。**有効 / 無効**の切り替え、
  タイムアウト指定もあります。セッションへの反映は**次に起動するセッションから**です。
- 一覧には**個人**登録のほか、**テナント**（管理者が配布。名前が重なると個人登録は使われません。
  値の入力だけメンバーに求められるものもあります）と**組み込み**（af 自身、および運用・監視の連携）が並びます。
- 外向き通信が制限されたデプロイでは、ホストの**許可を申請**して管理者の承認を待つ導線が出ます。
- **組み込み連携**（PagerDuty / Grafana / CloudWatch / AWS）の接続情報は**⚙設定 →「運用・監視」**タブで
  設定します。資格情報はワークスペース内に暗号化保存され、Grafana は書き込み・管理ツール無効、
  CloudWatch は読み取り専用ツールのみ、AWS は既定で読み取り専用起動です。
  **AWS だけは対話セッションからも使えます**（他の 3 つはチャット専用）。反映は次のチャット送信から
  （AWS をセッションで使う場合は次のセッション起動から）。
- リポジトリに置かれた**プロジェクト設定の MCP**（`.mcp.json` などファイル側の定義）は、
  リポジトリ行のメニューから開く「プロジェクト設定」で、エージェント別の効き方・警告
  （秘密情報が Git 管理下にある、名前が組み込みと衝突する、ファイル間で内容が食い違う等）を確認できます。

| **使用量** | 機能別・エージェント別・モデル別・出自別のトークン消費台帳（24時間 / 7日 / 30日、消費トークン・呼び出し回数・キャッシュ読取・API 換算相当額）。rtk の節約効果もここに出ます |

## 9. データを失わないための注意

- ワークスペースの通常の**停止・起動**では、リポジトリも未コミットの変更も消えません。
  停止中もセッション一覧は見られますが、中身の操作には起動が必要です。
- **「ワークスペースを作り直す」** — コンテナを破棄して最新イメージで作り直します。
  **消えるのは実行中のセッションと `~/repos`（未コミット変更を含む）だけ**で、
  ログイン・接続・`~/.local`・各種設定やキャッシュなどホームのその他は残ります。
- **「ホームを掃除する」** — さらに深いリセット。**残るのはログイン・接続だけ**で、
  `~/repos`・`~/.local`・キャッシュ・設定などホームのその他はすべて消えます。
  まず「作り直す」で直るか試し、それでも直らないときに使ってください。
- どちらも**未コミットの変更は消えます**。実行前にコミット・push を済ませてください。
- API キーやトークンをリポジトリやファイルへ平文で保存しません。接続は設定画面で管理します
  （値は暗号化保存されます）。
- 重いビルドや大きな並列度を避けます。JVM ビルドはプロジェクトの wrapper（`./gradlew` / `./mvnw`）を使い、
  不要なデーモンや開発サーバーを残しません。ホストは共有です。
- エージェントは利用者に代わってコマンドを実行し、ファイルを編集し、push します。無人（定時実行）でも
  動きます。shell / SSM は送った文字列を**そのまま**実行します。最小権限の資格情報を使い、
  承認ゲートを活用するよう案内してください。

## 10. ワークスペース内の Web を見る（プレビュー）

ワークスペース内で起動した Web サービスは、ワークスペース操作バーの**ポート入力欄**に
ポート番号（と必要なら `/` で始まる path）を入れて開きます。**外部 URL は開けません**（localhost 専用）。

- **ペインで開く（ブラウザペイン）** — ワークスペース内のブラウザが `127.0.0.1:{ポート}` を開き、
  描画と操作を Console のペインに映します。クリック・入力・スクロール・戻る/進む・再読み込みができ、
  **HMR・WebSocket・SSE・cookie・リダイレクト**が普通の localhost と同じように動きます。
  **迷ったらこちら。** 同時に開けるのは 1 ワークスペースあたり 2 つ、最大 1600×1200・約 12fps。
  タッチ画面ではスワイプでスクロール、長押しでドラッグ、ピンチで拡大縮小、ダブルタップで幅合わせ。
  タップではキーボードが出ないので、入力欄はタップ後にペイン左下のキーボードボタンで開きます。
- **軽量プレビュー** — 単純な HTTP proxy で新しいタブに開く軽い確認用。JSON の health や単純な静的ページを
  一度見るだけの用途向けで、HMR / WebSocket / SSE は使えません。
- **状態表示** — `target-unreachable` はそのポート/path へまだ繋がっていない（サーバー起動待ちを含む）ので
  起動後に「再読み込み」、`disconnected` は通信が切れた状態、`crashed` はワークスペース内のブラウザが
  異常終了した状態で、どちらも「再接続」で開き直します。
- **スマートフォンでは「ペインで開く」の導線がありません。** デスクトップかタブレットを案内してください。

## 11. 読み取りツールの使いどころ

このアシスタントは**読み取り専用**です。次のような問いは、必ずツールで実際の値を確認してから答えます。
ターミナルが無いことだけを理由に、停止中または履歴が無いと判断してはいけません。

| 聞かれたこと | 使うツール |
|---|---|
| 今どのセッションが動いている? / このセッションは動作中? / 最近の出力は? | `list_my_sessions` / `get_session_status` / `get_session_output` |
| あとどれくらい使える? 制限はいつ解除? | `get_agent_usage`（claude / codex / agy。返らないエージェントは「取得元が無い」と答える） |
| このセッションのコンテキストは? どれだけ消費した? | `get_session_usage`（shell / SSM は対象外） |
| どこで新しい作業を始められる? | `list_repos` |
| 溜まっているメモは? | `list_memos` |
| 今どんな定時タスクがある? ちゃんと動いてる? | `list_schedules` / `get_schedule_runs` |
| 散らかってきた。片付けられる? | `list_cleanup_candidates`（安全度と理由を提示するところまで。**実行はオペレーター**） |
| 消しすぎた。戻せる? | `list_cleanup_archives`（復元の**実行**はオペレーター） |
| メモリがいつ変わった? 戻せる? | `list_memory_snapshots` / `get_memory_snapshot`（戻す**実行**はオペレーター） |

**答えられないことは、できる人へ渡す。**
セッションへの指示・作成・停止・再開、メモの追加と一括送信、定時実行の登録、掃除やメモリの巻き戻しの
実行は「フリート・オペレーター」の担当です。ファイルの作成・編集やコマンド実行は、
オペレーターであっても作業セッションを通じて行います。
