エージェントが操作中のブラウザページを人へ引き渡せるようになり、最後のクリックだけを
自分で行えます。Console は日本語に倒れることなく表示言語で一貫して応答します。
**本リリースで Docker Compose の導入手順が変わります: コンテナイメージは image tar の
読み込みではなく GHCR からの pull で取得します。**

### 破壊的変更（Docker Compose 版のみ）

- **イメージはレジストリから取得します。** リリースに
  `agent-fleet-images-<版>.tar.gz` は添付しなくなりました。control-plane と workspace の
  イメージは GHCR へ公開します（`ghcr.io/k-k1/agent-fleet/control-plane:<版>` と
  `ghcr.io/k-k1/agent-fleet/workspace:<版>`）。導入は「tar を DL → `load-images.sh`」から
  `docker compose pull` に変わり、`install-compose.sh` と同梱 runbook もそのように
  なりました。パッケージは public なので**レジストリへのログインは不要**です。

  既存デプロイの更新手順: `.env` に `REGISTRY=ghcr.io/k-k1/agent-fleet` と
  `VERSION=0.6.0` を設定し、`WS_IMAGE` を
  `ghcr.io/k-k1/agent-fleet/workspace:0.6.0` に向けたうえで、従来の `load-images.sh` の
  代わりに `docker compose pull` と `docker pull "$WS_IMAGE"` を実行してください。
  データ・`AF_MASTER_KEY`・その他の設定は一切変わりません。

  レジストリに到達できないホストには 2 つの経路を用意しています。2 つのイメージを社内
  レジストリへミラーして `REGISTRY` をそこへ向けるか、`deploy/compose/release.sh --save`
  で自分でビルド・エクスポートして従来どおり `load-images.sh` を使うかです。スクリプトと
  air-gap の runbook はこのためにバンドルへ残してあります。

  理由: image tar は見かけほどオフライン導入ではありませんでした。イメージは lean なので
  ワークスペースは初回起動時にエージェント CLI を各配布元から取得しますし、そもそも
  エージェントはモデルのエンドポイントに到達できなければ動きません。実益は「レジストリが
  不要」の 1 点だけで、その代償が 1 リリースあたり約 960MB でした。

- **native 版と AWS / ECS 経路に影響はありません。** native のワンライナー導入と
  `af start` は変更なし、ECS も従来どおり ECR へ push します。

### 新機能

- **ブラウザページを人へ引き渡す。** ワークスペース内でエージェントが headless Chromium を
  操作しているとき——フォーム入力やサイト内の作業を進めているとき——その生きたページを
  あなたへ渡せるようになりました。エージェントがリンクを提示し、Console のペインでページが
  開き、クリック・スクロール・キーボード入力（日本語 IME も）を行ってから返せます。
  detach で閉じるのは Console 側の表示だけで、エージェントのブラウザ・ページ・セッションは
  生きたまま残ります。公開・送信・同意といった最終クリックをエージェントが代行することは
  ありません——そこを人へ渡すことが本機能の目的です。
- **「思考」を展開して表示（エージェント別）。** codex と opencode の思考ブロックは
  セッションチャットで常に畳まれ、毎ターン開く必要がありました。設定 › エージェント ›
  各カード › 動作設定に**「思考を展開して表示」**を追加し、エージェント種別ごとに独立して
  設定できます。既定はオフなので、有効にしない限り従来どおりです。

### 改善

- **Console が表示言語で応答します。** 表示言語を英語にすると、ビルトインアシスタント
  （案内役・フリート・オペレーター・SRE）が日本語ではなく英語で回答します——persona が
  日本語固定だったことが、回答が日本語へ倒れる最大の要因でした。返信サジェスト・圧縮引き
  継ぎ・作業計画・Files 由来のアドホック操作も表示言語に従います。persona は会話の作成時に
  スナップショットされるので、切り替えは**新しい会話から**効き、開いている会話は動きません。
- **完了報告がどちらの言語でも読めます。** 報告カードは、あなたと、同じ本文をプロンプトと
  して受け取るオペレーターアシスタントという 2 人の読み手に 1 本の文字列で応えていました。
  これを分離し、カードは**事実だけ**を述べて表示言語で描画され、指示は注入の瞬間に組み立て
  られます。副作用として、カードから「get_session_output で確認し…」といったモデル向けの
  指示が消えました。
- CLI のピン: Claude Code 2.1.220 / Codex 0.146.0 / OpenCode 1.18.11 /
  GitHub Copilot 1.0.77 / Antigravity 1.1.9 / Cursor 2026.07.23 / Kiro 2.16.0 /
  rtk 0.44.2。

### 修正

- **WS バーの使用量チップが丸一日凍結することがありました。** 使用量（rate limit）を
  捕捉するため Claude の statusLine をラップしていますが、「すでに自分がラップ済みか」の
  判定を実行ファイルのパスで行っていました。別パスから起動するたびに既存のコマンドを
  他人のものとみなして再ラップし、そのつど全体をシェルクォートするため層ごとに膨張します。
  実機では 13 層・798KB まで育ち、ついに statusLine 自体が実行できなくなって使用量の捕捉が
  黙って止まっていました。判定をパス非依存のマーカー方式に変え、張り直す前に自分の層を
  すべて剥がすようにし、結果が大きすぎる場合は捕捉専用へフォールバックします。既に壊れて
  いる設定は次回起動時に自動で修復されます。

### アップグレード時の注意

migration はありません。**Compose 環境はレジストリ pull への切り替えが必要です**——
具体的な `.env` の編集内容は上の「破壊的変更」を参照してください。レジストリに到達
できないホストは、同梱 runbook の「Air-gapped install」節が該当します。native 版は
従来どおりワンライナーで更新できます。「思考を展開して表示」の既定はオフ、言語まわりの
変更はアップグレード後に作成した会話から効きます。
