リポジトリの取り込みが非同期のジョブになり、大きな clone / checkout が「失敗したのに成功に
見える」ことがなくなりました。設定を 1 個のファイルで別の環境へ持っていけるようになり、
`ecs-ec2` の配備は作り直しても外向きの IP を保ちます。`ecs-ec2` で Workspace が起動できない、
起動が遅い、という不具合もまとめて直しています。

### New

- **リポジトリの取り込みが、経過を見られるジョブになりました。** 分単位かかる clone /
  checkout はロードバランサに 60 秒で切られ、画面は「フォルダができていれば成功」と
  補っていました。Subversion は開始 1 秒でフォルダを作るので、あとから失敗した取り込みも
  消えた取り込みも成功と報告されていました。取り込みが終わったかどうかの根拠は、これから
  ジョブの状態だけです。中止には確認が入り、一覧が走行中の作業コピーを取り合うことも
  なくなりました。
- **設定を 1 個のファイルで書き出し / 取り込みできます。** 設定 > ワークスペースから、
  個人設定・AWS SSM の登録・エージェントへの指示をまとめて持ち出せます。接続のトークンや
  API キーは常に除外します。取り込みは足すだけで、すでにあるものは理由を添えて飛ばします。
- **`ecs-ec2` の配備が外向きの IP を保ちます。** NAT gateway の Elastic IP は、利用企業の
  ファイアウォールに登録される唯一の送信元アドレスですが、スタックを消すと解放されて
  いました。どのスタック操作でも手放さないようにし、立て直すときに前の世代のアドレスを
  指せるようにしました — Upgrade notes を参照してください。
- **停止したままのスロットを終了し、root ボリュームを返します。** 停止で止まるのは計算資源
  だけで、root ボリュームは箱が消えるまで課金され続けるため、停止中スロットのディスクが
  プールの上限まで積み上がっていました。
- **テナント上限を検証します。** 全テナントの合計がスロットプールの容量を超えているときは
  設定画面が知らせます。負の上限がそのまま保存でき、そのテナントが Workspace を 1 つも
  開けなくなる、ということもなくなりました。

### Improved

- `ecs-ec2` で Workspace の起動が速くなりました。一度作ったタスク定義を Control Plane の
  再起動をまたいで再利用し、サービスは「1 ワークスペース 1 タスク」に固定しています。

### Fixed

- **スロットプールが埋まると、Workspace が二度と起動できなくなることがありました。**
  空けた箱がその Workspace の乗れない型で、配置が永久に拒否され続けるためです。誰も使えない
  箱は、必要なら片付けて建て直すようにしました。
- **使用量のチップが、上限に近いアカウントでも 0% と表示することがありました。** 読み取り先が
  失われたまま黙って何も報告しない状態も、自分で張り直すようにしました。
- **AWS Organizations のメンバーアカウントで「費用が誰にも割り当てられていません」という
  赤い警告が出続けていました。** 実際には按分できていて、金額も画面に出ている状態でした。
- **丸数字などが、日本語の隣で細く小さく描かれていました**（差分やビューア）。
- **タブが溢れてスクロールバーが出ると、中クリックでタブを閉じられませんでした。**

### Upgrade notes

`ecs-ec2` では NAT gateway の Elastic IP を保持するようになったので、`teardown` でも
残ります。配備を畳み切るときは手で解放してください（未使用の EIP は課金されます）。
`NatEipAllocationId` は**新規または立て直しの配備にだけ**渡してください。稼働中のスタックに
渡すと、そのスタック自身が確保したアドレスであっても NAT gateway が置換されます。

エージェント CLI の固定版：Claude Code 2.1.246、OpenCode 1.18.23、Antigravity 1.1.21、
Kiro 2.19.2。その他は 0.12.2 から変わりません。
