Workspace が動くマシンを、テナントがメンバーごとに選べるようになりました（Graviton
を含みます）。`.drawio` のベンダーアイコンが描かれるようになり、管理画面に「作る」
しか無かった操作へ削除が加わりました。壊れて見えていたセッションの修正も入っています。

### New

- **Workspace が動くマシン種別を、テナント・メンバーごとに選べます（`ecs-ec2`）。**
  運用者が名前付きのクラス——アーキテクチャと CPU 世代、それぞれのメモリの梯子——を宣言し、
  テナント管理者がテナントの既定と、メンバー詳細での個別指定の 2 段で選びます。メモリの
  選択肢と「乗る箱」はクラスに合わせて描き直されます。出荷時の既定は *standard*（m7i）と
  *saver*（m6i）の 2 つで、どちらも x86_64 です。誰かが選ぶまで誰も動きません。Graviton
  （arm64）のクラスも宣言できます。⚠️ の警告はアーキテクチャを跨ぐときだけ出します。home
  の中の CLI は次回起動で入れ直しになるからです。**rtk は動く arm64 ビルドが存在しない**
  ため、arm64 のクラスに乗るメンバーはトークン削減を使えません。クラスが 1 つしか無い
  デプロイでは、選択肢そのものが出ません。
- **`.drawio` のベンダーアイコンが描かれます。** AWS・Azure・GCP・Kubernetes・BPMN・
  ラックの図形は、これまで枠と色だけに落ちていました。ステンシルは同梱の台帳に照らして
  Control Plane 経由で取得しディスクにキャッシュするので、フレーム自身が外へ出ることは
  ありません。外向き通信の無いデプロイ向けに `control-plane drawio-preseed` で事前投入
  できます（既定 49 セット、`--all` で 203 セット全部）。
- **空のテナントと、除名済みメンバーの行を管理画面から削除できます。** テナントは、
  有効な membership・Workspace の行・内部リポジトリが残っている間は拒否します（DB の行が
  home やボリュームへの唯一の手掛かりであり得るため）。拒否の理由はどれが残っているかを
  述べます。membership は、無効かつ Workspace を破棄済みであれば削除できます。
- **アカウントメニューに、稼働中の版とイメージを表示します（ECS）。** そこにあったのは
  Console バンドルのビルド刻印で、Control Plane の版でも、運用者が上げ下げするイメージ
  タグでもありませんでした。障害報告には両方が要ります。

### Improved

- **予約テナント `af-golden` を管理画面から隠しました。** 費用も、人の費用としてではなく
  共有インフラへ寄せます。golden の自動焼き直しにより、このテナントと 2 つの予約
  membership が実在のメンバーと並んで出ていました。
- ガイドに `.drawio` ペインの説明を加え、開いて試せるサンプルとして Agent Fleet 自身の
  構成図をリポジトリに置きました。

### Fixed

- **デプロイを再起動すると、停止中のセッションがすべて壊れたターミナルに見えて
  いました。** 開くと「切断されました」と出ます——ターミナルの履歴はメモリ上にあるため、
  履歴の残っていないセッションを、通信が落ちた場合と区別できていませんでした。さらに悪い
  ことに、戻る道も一緒に消えていました。リクエストが 1 回失敗しただけで一覧が空になり、
  再開ボタンごと消えることがあり、再開に失敗するとスピナーが回り続けて再試行できません
  でした。
- **Claude のセッションがミラーで無言になることがありました。** claude はいくつかの操作
  ——フルスクリーン TUI への切り替え、サインイン、モデル変更——で自分自身を起動し直し、
  その際に我々が渡した会話 id を落としたコマンドラインを組み直すため、こちらが見ていない
  新しい会話を始めていました。使用量・中断検知・完了報告も同時に落ちていました。
- **Copilot と Cursor のセッションも同じ形で無言になることがありました。** CLI が採番した
  id を読むのではなく、こちらが id を渡している種別がこの 2 つでした。
- **ミラーの作業過程が勝手に開閉し**、読んでいる位置が数千 px 単位でずれていました。一度
  畳んだターンは畳んだままで、変えるのは利用者のクリックだけになりました。
- **Postgres のデプロイでメモのカテゴリが壊れていました。** テーブルが移されておらず、
  カテゴリの呼び出しがすべて失敗していました。Console はそのエラーを空リストに畳むので、
  障害ではなく「カテゴリという機能が何もしない」ように見えていました。

### Upgrade notes

Postgres にメモのカテゴリのテーブルを足す追加専用のマイグレーションが 1 本走ります。
手作業はありません。エージェント CLI の固定版は 0.9.3 から変わりません。

`ecs-ec2` では、マシン種別を使うのにスタックの再デプロイが必要です。`30-ingress` に
`Ec2DefaultSlotClass` と `Ec2SlotAmiArm64`、`40-ec2-pool` に `SlotAmiIdArm64` が加わり、
出荷時の `Ec2SlotTypes` の既定は *standard* + *saver* になりました。既存スタックは
デプロイ時の値を保ち、既定クラスも変わらないので、再デプロイで誰かが動くことはありません。
arm64 のクラスには、これに加えて arm64 の AMI パラメータと、arm64 向けに公開された
workspace イメージが必要です。AMI 無しで arm64 を宣言すると Control Plane は起動を拒否
します。
