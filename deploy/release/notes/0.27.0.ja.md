メンバーは `af-gcloud-exec` で Google Cloud のコマンドを自分として実行できるようになりました。AWS と同じく、プロファイルは
設定に置き、ログインは Console で済ませます。WS バーにはどの AWS／Google Cloud プロファイルがサインイン済みかが出て、
AWS はプロファイル 1 つだけをログアウトできます。Managed セッションのキューに入ったピア・オペレーター・スケジュールの
メッセージは、停止や Agent の再起動を越えて残るようになりました。ECS では「作り直し」「ホームを掃除」「破棄」が EFS の
ホームに届き、ecs-ec2 のスロットは次の起動での置き換えを予約できます。ECS の CP タスクロールはさらに絞りました。独自 AMI や
権限を絞ったデプロイ用ロールを使う運用者には確認することがあります。

### New

- **Google Cloud プロファイル。** 設定 › Google Cloud にメンバーのプロファイル（プロジェクト、クォータプロジェクト、アカウント、
  なりすますサービスアカウント、一覧から選ぶリージョンとゾーン）を置き、
  `af-gcloud-exec --profile <name> --project <id> -- <command>` で gcloud、GKE への `kubectl`、Terraform をそのプロファイルの
  短命なトークンで実行します。ログインは Console で済ませ、Google の認証情報は Agent Fleet に保存しません。初回の実行で
  Google Cloud SDK をホームに入れます。WS バーのバッジで、どのプロファイルがログイン済みかが分かります。

### Upgrade notes

- **ECS: CP タスクロールを絞りました。** EC2 への書き込みはこの配備のスロットとエンジンのインスタンスだけになり、起動できる
  のは Amazon 所有か公開のイメージからだけです。スロットやエンジンの起動テンプレートが自前の AMI を指していると
  `UnauthorizedOperation` で失敗します。
  ([#1423](https://github.com/k-k1/agent-fleet/issues/1423),
  [#1522](https://github.com/k-k1/agent-fleet/issues/1522))
- **ECS: `update.sh` はスタックを `CAPABILITY_NAMED_IAM` でデプロイし**、`af-<stack>-cp-…-<region>` という名前の
  マネージドポリシーを作ります。権限を絞ったデプロイ用ロールには `deploy/aws/ecs/cfn/PARAMETERS.md` にある IAM ポリシーの
  アクションも要ります。ecs-ec2 ではスロットプールのスタックを 20-platform より先にデプロイします。
  ([#1576](https://github.com/k-k1/agent-fleet/issues/1576))
- **ecs-ec2: 0.26.0 より前に起動したスロットを新しいユーザーデータへ移すには**、`Ec2SlotTerminateAfterSec` を設定するのでは
  なく、設定 › 管理 › スロットで予約し、ユーザーに停止と起動をしてもらいます。この移行のためだけに設定していたなら 0 に
  戻してください。
  ([#1473](https://github.com/k-k1/agent-fleet/issues/1473))
- **0.25.0 以前からの更新**: 0.26.0 の Security の節にある運用者の作業はそのまま必要です。
