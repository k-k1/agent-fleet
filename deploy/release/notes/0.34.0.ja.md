MCP のサインインが両方向で使えるようになりました。claude.ai や ChatGPT などのリモート MCP クライアントは、
トークンを貼り付ける代わりにサインインして Agent Fleet に接続できます。OAuth が必要な MCP サーバーには設定から
サインインでき、セッションから使えます。EC2 プールのスロットは強制停止でき、ホスト側のメモリの余裕が増えました。
Jira CLI は不安定なネットワークでも動くようになりました。

### 新機能

- **リモート MCP クライアントがサインイン（OAuth）で接続できます。** claude.ai・ChatGPT・Claude Code などの MCP クライアントは、
  Personal Access Tokenを貼り付ける代わりに Console へのサインインで接続し、テナントと読み取り／書き込みの権限を
  選べます。既定ではオフで、運用者が `AF_MCP_OAUTH=1` でオンにします。設定 › 接続 › MCP トークン に接続済みアプリと
  最近の呼び出しが並び、そこで取り消せます。テナント管理者はテナント単位でオフにでき、配備管理者は信頼する
  クライアントのホストを管理画面で編集できます。クライアントがセッションに送った入力には **MCP 経由** と表示されます。
  ([#2433](https://github.com/k-k1/agent-fleet/issues/2433),
  [#2434](https://github.com/k-k1/agent-fleet/issues/2434),
  [#2455](https://github.com/k-k1/agent-fleet/issues/2455),
  [#2457](https://github.com/k-k1/agent-fleet/issues/2457),
  [#2531](https://github.com/k-k1/agent-fleet/issues/2531),
  [#2542](https://github.com/k-k1/agent-fleet/issues/2542),
  [#2567](https://github.com/k-k1/agent-fleet/issues/2567))
- **OAuth が必要な MCP サーバーにサインインできます。** 設定 › MCP サーバー で、リモートサーバーの認証に
  **OAuth** を選んで **サインイン** を押します。サインインが必要かどうかは接続テストが教えてくれます。セッションは
  ワークスペース内の中継を通してサーバーに届くので、トークンが CLI の設定に書かれることはありません。claude・
  copilot・cursor で使えることを確かめています。テナントが配布するサーバーはまだ OAuth を使えません。
  ([#2479](https://github.com/k-k1/agent-fleet/issues/2479),
  [#2485](https://github.com/k-k1/agent-fleet/issues/2485),
  [#2549](https://github.com/k-k1/agent-fleet/issues/2549),
  [#2568](https://github.com/k-k1/agent-fleet/issues/2568),
  [#2580](https://github.com/k-k1/agent-fleet/issues/2580))
- **応答しなくなった EC2 プールのスロットを強制停止できます。** ECS と SSM のエージェントが黙ったスロットを、
  配備管理者がプール画面の **停止（強制）** で止められます。メンバーが次に開始すると同じスロットが起きます。
  ([#2449](https://github.com/k-k1/agent-fleet/issues/2449))
- **フォルダのコンテキストメニューに「ここでシェルを開く」** が加わり、そのフォルダでシェルのセッションを始めます。
  ([#2460](https://github.com/k-k1/agent-fleet/issues/2460))
- **Jira のコメントを編集・削除できます。** セッションで `jira issue comment edit` と `delete` を使えます。
  ([#2477](https://github.com/k-k1/agent-fleet/issues/2477))
- **Muse Code のコントリビューターモード**を、設定 › エージェント の Muse Code のカードでオンにできます。
  ([#2535](https://github.com/k-k1/agent-fleet/issues/2535))

### 改善

- **MCP サーバーの登録フォームがリモートサーバーを前提にした形になりました。** 表示名と認証方式（なし・Bearer
  トークン・カスタムヘッダー・OAuth）を選び、ID は名前から決まります。
  ([#2550](https://github.com/k-k1/agent-fleet/issues/2550))
- **Jira CLI が不安定なネットワークでも動きます。** 読み取りはやり直し、固まったコマンドは時間切れで終わり、
  時間切れになった `issue create` は作られたかもしれない課題を示し、使えなくなった接続は 1 行でそう伝えます。
  エージェントへの指示で、CLI より Atlassian の MCP ツールを優先させることもできるようになりました。
  ([#2476](https://github.com/k-k1/agent-fleet/issues/2476),
  [#2532](https://github.com/k-k1/agent-fleet/issues/2532),
  [#2538](https://github.com/k-k1/agent-fleet/issues/2538),
  [#2539](https://github.com/k-k1/agent-fleet/issues/2539),
  [#2543](https://github.com/k-k1/agent-fleet/issues/2543))
- **ECS-EC2: どのスロットでもホスト用に 2 GiB を残し**、ECS と SSM のエージェントをメモリの回収から守ります。
  忙しいワークスペースがスロットを応答不能にすることはなくなりました。8 GiB のスロットではワークスペースの上限が
  6.4 GiB から 6 GiB になります。
  ([#2451](https://github.com/k-k1/agent-fleet/issues/2451),
  [#2452](https://github.com/k-k1/agent-fleet/issues/2452))
- **ECS-EC2: 停止しきれないタスクの後ろで止まった開始**は、いつまでも「開始中」ではなく、理由を添えて
  ブロック中と表示します。
  ([#2447](https://github.com/k-k1/agent-fleet/issues/2447))

### アップグレードの注意

- **ECS のデプロイ:** **停止（強制）** を使う前に `20-platform` スタックを、新しいスロットがエージェントを
  守るように `40-ec2-pool` スタックをデプロイしてください。8 GiB のスロットのワークスペースは、次の開始から
  使えるメモリが 0.4 GiB 減ります。
- **MCP のサインイン**はオプトインです。`AF_MCP_OAUTH=1`（と `AF_MCP_ENABLED=true`、`https` の
  `PUBLIC_BASE_URL`）を設定してください。ホスト型のクライアントは各社のサーバーから `/mcp` に来るので、
  インターネットから届く必要があります。`AUTH=proxy` の場合は、どのパスをゲートウェイに通さないかを運用ガイドで
  確認してください。
