Signing in is no longer tied to Google: any OpenID Connect provider or GitHub can be
enabled, and one deployment can be divided into departments that own their own sign-in
page, roster and permitted networks. On AWS there is a new runtime that keeps each
person's home on a disk that survives a stop, with the cloud bill shown per member
beside it. In the Console, `.drawio` files open as diagrams, every session lists the
files it changed, and passages of a conversation can be highlighted for the people you
shared it with.

### New

- **Sign in with any OpenID Connect provider, or with GitHub.** Google sign-in was the
  only way in, which ruled out every company that runs on Microsoft 365. Any OIDC
  provider can now be enabled — Entra ID, Okta, Keycloak, Auth0, Cognito, GitLab — by
  listing it in `AF_OIDC_PROVIDERS` and giving it an issuer, a client ID and a secret;
  the sign-in screen then shows one button per enabled provider, labelled how you name
  it. GitHub is available too, gated on membership of an organisation you name (there is
  no user-facing OIDC for GitHub, so it is a separate adapter, and it refuses to enable
  itself without an organisation list). Several providers can run side by side.
  **Google needs no change**: its settings keep their existing names, and a deployment
  that only uses Google looks and behaves exactly as before. A provider whose
  configuration is incomplete is disabled with a warning rather than taking everyone
  else's sign-in down with it — startup only fails when no provider is left at all. One
  deliberate refusal to start: a Microsoft issuer left on `common`/`organizations`
  without a tenant allowlist, because that would put every holder of a Microsoft account
  at your front door, and a personal account can change its email address at will. Setup
  is covered end to end in the operator guide, including what to do on the identity
  provider's side, and in the Compose, EC2 and ECS examples.
- **One person keeps one workspace across an email change, a second provider, or a
  second sign-in method they add themselves.** Who you are used to be derived from your
  email address, and that address is also the name of your workspace's home directory —
  so a surname change or a domain merger at the identity provider grew a second, empty
  workspace, and signing in through a different provider did the same. Sign-ins are now
  recorded against the provider's own immutable account id, so the same person keeps one
  workspace, one home and one set of stored credentials through both. Settings gains an
  **Account** tab listing the sign-in methods attached to you, where you can add another
  one — you are already signed in, so it is your own consent that attaches it, not an
  administrator's claim about an address — and detach one you no longer use (never the
  last one, and never the one the current session is using). A sign-in whose email
  address matches nobody deliberately becomes a **new** person rather than being
  attached to an existing one, and says so on a screen right after sign-in.
- **One deployment can be split into departments, each with its own sign-in page,
  roster and sign-in methods.** A tenant now has a login URL of its own
  (`/login/<slug>`), a roster that decides who gets in — one ledger instead of the old
  split between an environment allowlist and the membership table — and its own list of
  sign-in methods. A tenant administrator can register a method for their own directory
  (an OIDC issuer, or a GitHub organisation) without anyone editing a file on the host
  or restarting the control plane; **it does nothing until a deployment administrator
  approves it**, which is the point — being able to declare who someone is would
  otherwise be enough to impersonate them. The list a tenant sees is a single one: its
  own rows and the deployment's own methods side by side, each with an *accept* and a
  *show as a button* toggle, so a subsidiary can let head-office staff in without
  putting a button they cannot use on the page. Methods hidden that way are hidden on
  the plain `/login` too, and the screen tells you when hiding only takes effect once
  you hand out the tenant's URL. Registering a second app registration against an issuer
  already in use is refused at save time rather than silently locking your colleagues
  out later. Tenant administrators get their own **Tenant settings** dialog for all of
  this, plus members, sessions, usage, audit and MCP distribution for their tenant; the
  admin dialog is now deployment administrators only, and was rebuilt on the same left
  rail with a drill-down into one tenant.
- **A tenant administrator can restrict which networks their members connect from.**
  Until now the only control was the load balancer's ingress CIDR — deployment-wide, and
  only reachable by re-applying CloudFormation. A tenant can now list the addresses its
  own members may connect from, in the Console. **This is not a network defence**: the
  request still reaches the control plane and is rejected after the session is
  validated, so it does nothing for pre-authentication vulnerabilities, denial of
  service or scanning — the screen says so. What it does is keep a credential-holder
  from reaching data from a place you have not allowed. `/mcp` and `/git` are
  deliberately out of scope, since those come from the member's own container.
- **A new AWS runtime keeps a workspace's home on a disk that survives a stop
  (`ecs-ec2`).** Each person gets an EBS volume that follows them onto a pooled EC2
  slot, instead of a network file system shared by everyone. Small files are 8–30×
  faster to write, which is what a `node_modules` install or a Go build spends its time
  on; the home genuinely persists across stop and start; and workspace sizes are no
  longer bounded by Fargate's 16 vCPU / 120 GiB. Start time is *not* a reason to choose
  it — measured against Fargate's warm restart it is a wash. Slots are kept warm, put to
  sleep rather than handed back, and only evicted at the ceiling; a home unused for long
  enough can be moved to a snapshot and restored on the next start (opt-in, per tenant),
  and a new person's home can be created from a pre-warmed *golden* snapshot instead of
  an empty disk. New homes are spread across availability zones and a spare copy is
  taken periodically, so one zone going down does not take everyone with it. Operators
  get a slot-pool view — what you are paying for right now, which slots are asleep, and
  where each home is — and a **destroy workspace** action for people who have already
  left. Selecting the runtime is a one-line profile change, and the Fargate adapter is
  untouched.
- **Workspace size is something you choose, per person and per tenant.** Memory, CPU and
  disk are held as three independent axes, with tenant ceilings alongside the existing
  per-person limits. On `ecs-ec2` the screen tells the truth about that runtime instead:
  CPU is not settable, the memory figure is what decides which machine you land on
  rather than a hard cap, and the disk figure is the size of your persistent home (it is
  fixed when the home is created, and cannot be shrunk). Separately, on ECS runtimes the
  build artefacts that are expensive on network storage and cheap to rebuild — Go build
  cache, Go modules, `uv` — are relocated to a local work disk when a working copy is
  created, which is the moment that matters; `~/.npm` deliberately stays on the
  persistent home so the first install of the day needs no network.
- **What your cloud provider actually charges, per member.** Alongside the existing
  hours-used figures there is now real spend, taken from Cost Explorer and shown in the
  admin dialog, in tenant settings, in your own settings and on a member's detail page
  (total, by day, by service, over a period you choose). The tags the figures rest on are
  applied by the control plane, and the cost allocation keys are activated automatically
  because forgetting that step causes a permanent hole in the data that cannot be
  back-filled. The personal figure is deliberately **not** called "your cost": only part
  of a bill attaches to a person at all, and the label says that the shared part is not
  included.
- **`.drawio` files open as diagrams.** A `.drawio` file used to show as raw XML. It now
  renders in the file pane, with a switch back to the XML source (which keeps the
  editor, saving, conflict handling and external-change tracking it always had). Ctrl or
  ⌘ with the wheel zooms about the pointer, a bare wheel pans, two fingers pinch, a drag
  pans, and a double tap toggles fit and 1:1. The diagram follows your light/dark theme,
  background included. The viewer is bundled — no external requests — and runs in a
  sandboxed frame.
- **Every session lists the files it changed.** A collapsible band under the mirror's
  header, and a fourth mode in the command palette, answer "what did *this session*
  touch" — a question the four existing file lists could not, because they are all
  organised by working copy or repository. The list is built from the session's own edit
  calls and reconciled against the working tree, so a file that has since been committed
  is marked **committed** rather than lumped in with files that show no diff, and each
  turn ends with a chip naming what that turn changed. Claude, Codex, OpenCode, Cursor
  and Copilot are all covered, with `+N −M` counts where the transcript carries them.
- **Highlight passages of a conversation, and the highlights reach the people you shared
  it with.** Select text in the mirror and mark it in one of four colours; clicking a
  mark shows who made it and when, and lets you remove it. Marks are delivered to a
  shared view of the same session, and a share with write access can add its own — so a
  reviewer can point at the three lines they mean instead of describing where they are.
  The conversation itself is never copied into the control plane's database.
- **Shared conversations carry more of the session.** The contents of a handoff proposal
  are visible to the people you shared with, not just the fact that one happened; the
  view remembers where you were reading and lands at the end the first time (it was not
  reliably landing at the end at all); each tab is named after the session and carries
  its agent's icon instead of all reading "Shared session"; and the hover chip leads
  with the session name.
- **Swipe between running sessions on a phone.** With the drawer closed, a left swipe
  moves to the next running session and a right swipe goes back — the set and the order
  are the ones the left pane would show, filtered by your working set. The mirror
  remembers where you were reading in each session, and a **replies from the top**
  control jumps to the start of the latest reply rather than its end.
- **File paths in a reply are links.** An agent writes the thing you most want to open —
  `docs/65.md`, `src/a.ts:73`, `_act-parts/` — as inline code, which used to mean
  retyping it. Paths that actually exist are now links: a file opens in a pane, a folder
  opens the left pane, expands to it and hands the keyboard over so the arrow keys work
  from where you landed. Resolution happens in the workspace, so a path an agent wrote
  relative to the repository root resolves even when its working directory is a
  subfolder.
- **A Claude session tells you its login has expired.** Until now the only sign was the
  aftermath: the session sat there as *waiting for input*, prompts you sent stayed
  *waiting to appear*, and nothing ever started — because the CLI's terminal will accept
  your keystrokes long after it can no longer start a turn. Expiry is now read from the
  same credentials the CLI itself uses, so the session badge reads **login expired —
  sign in again**, the connection card in settings drops the green pill and shows the
  date instead of claiming you are still connected (with an *expires in N days* warning
  from three days out), and sending a prompt is refused with the reason rather than
  disappearing. Keys still reach the pane, so you can run `/login` in the terminal to
  recover.
- **A session stopped by a usage limit says so, and when it comes back.** Hitting a
  five-hour or weekly limit left the session reading *waiting for input*, exactly like
  one that had finished its work. It now reads **waiting for the limit to lift**, with
  the reset time that was already being reserved for the automatic resume. A balance or
  spending limit is a different answer — nothing lifts by waiting — so it reads
  **balance limit — needs raising** instead.
- **A message from one session to another has to say what it is.** Sending now requires
  an intent — *request*, *question*, *answer* or *notice* — and the envelope tells the
  receiving session what kind of reply is expected, which is the part that was missing:
  a "got it" costs the other side a whole turn. A request is answered only if it cannot
  be done; a notice is answered not at all.
- **A new installation starts closed, and shows people what to do before they are
  invited.** The templates now default to invite-only provisioning, and someone who
  signs in without a membership gets a screen explaining that they need an invitation,
  instead of a Console where every request fails with a toast.
- **The AWS ingress template can turn on a WAF** — rate limiting and IP reputation only,
  both off by default. Signature rule sets are deliberately not offered: this product
  carries code, shell commands and file contents as ordinary traffic, so a core rule set
  would reject normal work at random and look like a bug in the product.

### Improved

- **Terminal panes are much cheaper to draw in Chrome.** A style rule that asked "does
  this pane contain tabs?" made Chrome re-check the whole pane on every change inside
  it — and a terminal rewrites its rows on every frame. Measured on a real browser with
  a full 40×80 screen redrawn each frame: 127.9 ms per frame → 59.8 ms.
- **Idle sessions and workspaces now stop by themselves.** The timeouts existed but
  defaulted to *never*, so a deployment left overnight kept everything running and paying.
  The defaults are one hour for a session and two for a workspace; a tenant can still
  override either, and an explicit `0` still means never (it used to be quietly read as
  "unset" and replaced by the default).
- **ECS deployments show the same update badges as Docker ones.** "A new build is
  available" and "restart required" were implemented for Docker and native only, so an
  ECS deployment could be running an old workspace image with nothing on screen to say
  so. A one-command update path for ECS comes with it.
- **The skill picker gives the description a line of its own.** Name, argument hint and
  origin badge on the first line, description in full width on the second — the
  description used to be truncated to almost nothing.
- **Shared conversations honour your mirror settings.** Font size and typeface now apply
  to the shared view as well, and the "jump to latest" pill sits where the mirror's does.
- **The appearance popover** is ordered language → pane layout → light/dark, and every
  row is labelled.
- **A transient provider failure no longer ends the turn** for OpenCode and Codex
  sessions. Retryable failures are now classed as an interruption and picked up by the
  same managed resume path Claude already had — a short "continue" as a new turn, so the
  original prompt is never re-sent and its side effects are not repeated.
- **Traffic to S3 leaves through a gateway endpoint** on ECS deployments, and access
  logs now carry the status code.
- **Guides**: a walk-through for setting up sign-in methods, covering the identity
  provider's side as well as the Console's, and the member and operator guides follow
  the new screens.
- Pinned CLI versions: Claude Code 2.1.238, Codex 0.149.0, OpenCode 1.18.19, GitHub
  Copilot 1.0.80, Antigravity 1.1.17, Kiro 2.19.0, Cursor 2026.08.11, rtk 0.45.0.
  Supporting tools: gh 2.98.0, Go 1.26.7, AWS CLI 2.36.28.

### Fixed

- **The Console froze for seconds at a time in Chrome.** Firefox was unaffected. Panes
  were dropping and rebuilding healthy GPU contexts on every hide, reveal and redraw,
  until the browser's per-tab limit pushed out a context that a *visible* terminal was
  still using; the terminal then fell back to drawing text through the page layout,
  which measures every distinct character by writing it into the document and reading
  its width back. A Japanese screen has thousands of distinct characters and a fresh
  cache each time, which is where the seconds went. Terminals now fall back to a canvas
  renderer instead, contexts are only rebuilt when they were genuinely lost, and a
  budget keeps panes from evicting one another. Measured on the same screen: a 119 ms
  longest block became 0 ms. Touch devices are unchanged.
- **Learning and history in the settings were wiped on every device at once.** Reply
  suggestions' learned chips, pins, SSM usage history and key assignments could all
  return to their initial state together. The whole settings object is saved as one
  write and the last writer wins, and loading the stored copy failed silently — so a
  device that started with defaults saved them over everything. Accumulated values are
  no longer overwritten with an empty one, and nothing is sent until the stored copy has
  been read.
- **Free text typed into a Claude question was thrown away.** When a question offered
  previews for its options, the free-input row is replaced by a per-option notes field,
  and the keystrokes that would have submitted it were rejected before they were
  delivered — so pressing *submit* did nothing at all, and what you typed came back as
  *user declined to answer questions*. Your text is now sent as a note against the
  question and lands against the right one. In the same area: a question you dismissed
  was rendered as though it had been answered, with the placeholder text parsed as your
  answer; it now carries a **dismissed** badge.
- **A question or plan awaiting approval was shown twice.** The agent sent the pending
  payload separately on the assumption that the transcript did not have it yet, but
  Claude writes the tool call at the moment it asks — so both arrived and both were
  drawn.
- **The usage graph stayed one turn behind** until you pressed refresh several times.
  Reading usage kicks off a fold of the transcripts into the ledger, which takes about
  20 seconds, and the response did not say it was doing so — so the numbers you got back
  were always the pre-fold ones. The response now carries that fact and the screen picks
  up the result.
- **A line like `[on hold]: …` disappeared from the mirror.** In Markdown, `[label]:
  target` is a link reference definition, which renders nothing. A Japanese sentence has
  no ASCII spaces, so an ordinary bullet matched that shape exactly and the whole line
  vanished; later mentions of the same label turned into links to it.
- **The first instruction at launch did not arrive.** Starting a session from "begin
  work" left nothing running in the background — the prompt was only sent while its view
  was on screen, so it appeared to be sent at the moment you first opened the tab — and
  the same instruction could show twice, one of them stuck as *waiting to appear* until
  a reload. Delivery now happens in the workspace, independent of what is on screen.
- **"Cannot reach the workspace agent" when the agent had in fact answered.** Opening a
  terminal for a stopped session reported a connection failure, while the agent had
  replied correctly — that there was no session running and no terminal history left to
  show (the history is in memory, so a container restart empties it). The real answer is
  now surfaced; a genuine unreachable agent still reports one.
- **Scheduled runs with completion reports off had no badge in the mirror.** Their origin
  was recorded only on the branch that also carried a report address, so the most common
  kind of schedule — and every automatic resume after a usage limit — was
  indistinguishable from something you typed yourself.
- **Closing a tab jumped to an unrelated one.** It moved along the row; it now returns to
  the tab you were on before, which is what you want after opening a file from the mirror
  and closing it again. Separately, opening and closing a modal switched the selected tab
  back to an older one.
- **Horizontal swipes stopped working entirely in some sessions on a phone.** The guard
  that suppresses a swipe over horizontally scrollable content was reading a value that
  CSS computes as scrollable even for a purely vertical scroller — so one unbreakable
  long string in a transcript (a `sha256:…`, a URL) was enough to make the whole
  transcript refuse swipes. Long strings now wrap, and the guard checks what it meant to
  check.
- **Option descriptions in a Claude question were clipped to two lines** on a phone,
  where they are hardest to read and most needed.
- **Every shared-session tab was labelled "Shared session".** Opening more than one made
  them indistinguishable; tabs now carry the session's own name and the coloured icon
  for its agent, in the main area and in a popped-out tab.
- **OpenCode started with a plan selected that you never chose.** An unset or unknown
  value was treated as Zen, so saving a single key could put a billed path into use
  without being asked. A new workspace now uses nothing until you pick one in
  Settings › Agents.
- **The member guide would not open on ECS deployments.** The guides are staged from the
  control-plane image at start and mounted read-only by the Docker and native runtimes;
  the ECS adapter was never wired up, so the directory stayed empty and the menu item
  did nothing. They are now fetched instead of mounted. In the same area, a JDK can be
  installed from Settings › toolchains with one button.
- **OAuth sign-in inside a workspace failed right after a wake** on ECS. Waking rolls the
  service, and for the minute or two that takes, requests can land on either the old or
  the new task — while the CLI's login flow keeps its state in one process. The wake now
  waits for the deployment to settle.
- **The first start of an ECS workspace could return a gateway timeout**, because the
  health check was awaited inline.
- **"Restart required" lit up when nothing had changed.** The check compared image
  digests, and a rebuild that hit the cache produces a new digest for identical content;
  it now compares a fingerprint of the content.

### Upgrade notes

Nothing to migrate by hand. Nine additive migrations run at start (provider accounts,
tenant login rules and tenant-defined sign-in methods, per-workspace CPU, tenant network
restrictions, cloud cost); they hold no data from before the upgrade and are ignored by
an older build, so a rollback is safe. Existing people are matched by email exactly as
before and pick up their provider account on their next sign-in — home directories do
not move. Nothing about sign-in changes until you set `AF_OIDC_PROVIDERS` or register a
method for a tenant.

Three defaults changed:

- **Idle stop is on**: one hour for a session, two for a workspace. Set
  `AF_SESSION_IDLE_TIMEOUT` / `AF_WS_IDLE_TIMEOUT` to `0` to keep the old behaviour — an
  explicit `0` is now honoured, where before it was replaced by the default.
- **New installations are invite-only.** Only the templates changed — `.env.example`,
  which `install-compose.sh` copies, and the ECS `AfProvision` parameter. An existing
  `.env` that does not mention `AF_PROVISION` behaves exactly as before, and the value
  compiled into the control plane is still `auto`. Redeploying an existing ECS stack
  *will* pick up the new parameter default; everyone already in the roster keeps working,
  and only automatic acceptance of newcomers stops.
- **ECS work disk defaults to 50 GiB** so that the relocation of build artefacts is
  actually reached (it requires 30 GiB or more). Existing stacks keep the value they were
  deployed with; `WsDiskGiB=0` restores the previous behaviour. The 30 GiB above the free
  allowance costs about $2.9 a month while the task runs.

The `ecs-ec2` runtime is opt-in — a one-line profile change — and the Fargate path is
unchanged. Cost figures require Cost Explorer; the control plane activates the cost
allocation tag keys it needs on first use, which is a write to the account's billing
settings and the only one it makes. Compose deployments pull the new images as usual and
native installs update with the one-liner.
