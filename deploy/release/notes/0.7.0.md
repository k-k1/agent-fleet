OpenCode now signs in with your opencode.ai account from the Console and lets you
choose which plan its sessions run on, interrupted Claude turns pick themselves
back up without an assistant in the loop, and AWS's Agent Toolkit joins the
built-in MCP integrations.

### New

- **Sign in to OpenCode from the Console.** OpenCode used to accept only a pasted
  API key; signing in with an opencode.ai account meant running the CLI yourself in
  a terminal session. Settings › Agents › OpenCode now runs the device flow for
  you — you confirm the code shown, and the running daemon picks the credential up
  without a restart. The API-key path is untouched and the two coexist; either one
  on its own is enough.
- **Choose which OpenCode plan a workspace uses.** The card has a *plan* selector —
  free tier, Go, or Zen. The free tier needs no credentials at all, so a workspace
  set to it can launch while disconnected, and no `OPENCODE_API_KEY` is injected —
  a workspace you decided to run on the free tier will not quietly bill your Go
  quota just because a key is still saved. The card also links to your usage page
  and, after a limit is hit, shows which quota ran out and when it resets. It does
  not show a percentage — that number is not available from anywhere, and a
  plausible-looking guess is worse than nothing.
- **Agent Toolkit for AWS as a fourth built-in MCP integration.** Alongside
  PagerDuty, Grafana and CloudWatch, AWS's own MCP server can be connected from
  Settings › Connections › Ops & monitoring. It is read-only by default: the tools
  that call ~15,000
  AWS actions or run arbitrary scripts appear only if you turn on *write tools*.
  It is also the one built-in that is handed to coding sessions, not just to chat —
  its whole point is building things on AWS.
- **Interrupted turns resume by themselves.** When a Claude turn dies mid-flight on
  a retryable error — a stream idle timeout, a dropped connection — the agent now
  waits out a backoff and sends "continue" itself, up to twice, instead of leaving
  the session parked until someone notices. Sessions started straight from the
  Console, which have no assistant conversation attached to them, are covered too.
  Nothing is sent while a turn is running or while a question, plan or permission
  prompt is waiting. The mirror labels the injected prompt *auto-resume*. On in
  Settings › Agents › Claude.
- **An agent can propose the next session.** A working agent can hand you a ready
  first prompt, and a name, for the session that should continue its work. The
  proposal is saved and shows up in the mirror where you can edit or discard it;
  starting it goes through the normal launch dialog, so you still pick the agent
  and the model. Nothing is created until you say so.
- **Start a session in a subfolder.** Launching from a repository or worktree row
  can now put the agent in any folder beneath the working copy — useful in a
  monorepo when the task only touches `console/` or `apps/web`. The working copy
  itself is unchanged as far as worktree handling, cleanup and grouping are
  concerned; only the agent's working directory moves. The last folder you used is
  remembered per repository and offered as the default. Forks, relaunches and
  `create_session` over MCP carry it along.
- **Pull the parent repo's commits into a worktree.** The worktree row's badge now
  distinguishes "parent is ahead by N", "your work can fast-forward into the parent"
  and "diverged", and a right-click item fast-forwards the parent's commits into
  the worktree when it is a straight descendant. Diverged histories are refused
  rather than merged.
- **Keep a list of Claude models.** Claude Code has no account-linked model
  catalogue, so a full model ID for an older model could only be typed at launch
  and was gone next time. Settings › Agents › Claude now holds a list you maintain:
  it feeds the launch dialog, the default-model setting and `list_models` over MCP.
  Malformed and duplicate IDs are dropped on both sides; whether a model actually
  answers is still Claude Code's call.
- **Tab cycles reply suggestions.** Typing in the composer filters the suggestion
  chips by prefix; Tab now walks them into the input the way shell completion does,
  Shift+Tab walks back, and one full turn returns what you typed. The chip row stays
  frozen while you cycle, so the list does not shift under you.
- **Copy a quote block, wrap a code block.** Markdown quote blocks got a copy
  control, and code blocks a wrap toggle for long lines.
- **Five more surface colours.** The appearance palette goes from 6 to 11 — teal,
  rose, pink, indigo and graphite — for the five tintable surfaces. All five were
  measured against the light theme's selected-segment contrast, the constraint that
  actually binds, and none fall below the existing worst case.

### Improved

- **An expired Claude login now looks like a failure, and offers the fix.** A
  session whose credentials had expired showed the CLI's own text as an ordinary
  reply ("Please run /login"), which is not an action you can take from the
  Console, while the agent card still read as connected — `claude auth status` only
  inspects the local credential and does not know the server revoked it. The error
  is now rendered as a red error block like Codex's and OpenCode's, and the card
  offers re-authentication instead of a disconnect-and-reconnect dance.
- **Usage limits are visible where they stop you.** A managed Codex session stopped
  by a usage limit used to fall back to "waiting for input"; it now carries the same
  *blocked — needs attention* badge Claude has. Model-specific Claude limits, which
  end the turn with a 429 and no menu instead of opening the rate-limit dialog, are
  detected too — they used to be reported as a completed answer with no reason
  anywhere.
- **Answering a multiple-choice question is two steps.** Clicking an option used to
  submit it immediately, with no way back; the choice is now selected first and
  confirmed with a button. Options that carry a preview show it next to the choice.
- **Reply-suggestion learning treats full-width and half-width as the same.** A
  phrase typed with a full-width `！` no longer occupies a second slot next to its
  half-width twin, in the chips and in the settings list. The chip row shows up to
  20 learned replies (was 12) and keeps 100 (was 60).
- Settings › Toolchains lists the four AWS/ops MCP components under *Tool versions*.
- Pinned CLI versions: Claude Code 2.1.224, Codex 0.147.0, OpenCode 1.18.15,
  GitHub Copilot 1.0.78, Antigravity 1.1.11, Cursor 2026.08.04, Kiro 2.16.2,
  rtk 0.44.2.

### Fixed

- **A turn could vanish from the mirror for good.** Claude appends to its transcript
  in 4 KiB writes, so a long line is written in pieces and a reader can catch one
  half-written. The reader counted that fragment as a line and moved its cursor past
  it, while the parser threw the unparsable fragment away — so every later read
  started after a turn that had never been delivered. It looked like "the TUI's
  answer never reaches the mirror", with a prompt stuck on "pending" underneath it.
  Partial trailing lines are now left for the next read.
- **A schedule could fire forever where nobody could see it.** Schedule rows have no
  foreign key to the membership that owns them, so when that membership was disabled
  or removed the row stayed and kept firing as a no-op every slot — invisible in the
  list and in the run history, since both are scoped by membership. The first such
  skip now disables the schedule and records why, so it reappears as a paused
  schedule if access is restored.
- Three more schedule fixes: schedules were filtered out in working sets, disappeared
  when `whoami` was pinned at boot, and a failed list fetch was rendered as "none
  yet" instead of an error.
- **A worktree whose submodules were never fetched now says so and repairs itself.**
  Killing a launch mid-fetch left the checkout wedged in a state git itself reports
  as healthy; the launch continues in the background, the condition is surfaced, and
  fetch/checkout repair is offered.
- **A correction no longer contradicts the abort report that just went out.** With
  reports now arriving minutes after the interruption, the compensating check read
  the interruption's own freshness as "it started working again" and issued a
  retraction.
- **Tables written with full-width `｜` render as tables.** A Japanese IME commits
  the pipe as U+FF5C, so a table that looks fine in the editor collapsed into one
  paragraph in the preview. The repair is deliberately narrow — a table with any
  half-width pipe, or a mixed row, is left alone, because a full-width pipe is also
  the only way to put a bar inside a cell. Long-vowel marks are no longer flattened
  to hyphens, and header-only full-width rows are covered.
- **Reply suggestions were built from progress chatter.** The window was two turns
  wide, and a normal tool-using answer emits several "trimming two spots" style
  progress lines — so the model often saw none of the actual answer or request.
  Consecutive messages from the same speaker are folded together and the window is a
  character budget rather than a turn count.
- OpenCode fixes: the model list is read from the running daemon (the CLI does not
  see the login), sign-in no longer 500s right after the daemon starts, disconnecting
  actually clears the credential, an API-key change reaches the running daemon, the
  sign-in instructions describe confirming a code rather than pasting one, and the
  usage-page URL can be pasted as-is. OpenCode's final answer also reaches the mirror
  live instead of on the next refresh.
- Mirror fixes: opening a session lands at the bottom, switching sessions
  re-initialises there, the handoff card sits at the time it was proposed instead of
  taking the conversation's landing spot, the answer footer shows when the turn
  finished rather than when it started, a `"` in an answer no longer truncates the
  display, a chosen option no longer turns into "free input", and composer scrolling
  moved to Ctrl+↑↓ / PgUp・PgDn / Ctrl+End.
- Launch dialog fixes: the phone soft keyboard no longer opens by itself, the order
  is agent → model → prompt again, and a failed connection check is retried instead
  of latching (a workspace that was merely stopped could leave the launch button
  permanently disabled).
- Model settings picked on one device are synced back on another, agent tiles scroll
  horizontally with the wheel, the Chromium hand-off tools reach interactive
  sessions, and `node_modules` exclusion now applies through a symlink.

### Upgrade notes

Nothing to migrate. The old OpenCode *model list* setting is converted to the new
plan selector automatically (hide-zen → Go, everything else → Zen); check the card
if you had it set. Auto-resume for interrupted Claude turns is on by default and
can be turned off in Settings › Agents › Claude. The AWS integration is read-only
until you enable its write tools. Compose deployments pull the new images as usual;
native installs update with the one-liner. Workspaces need a Stop → Start to pick up
the newly pinned agent CLIs.
