0.12.0 で実際の `ecs-ec2` 配備を立てて見つかった修正が 3 件です。Graviton で立てたはずの
Control Plane が黙って x86_64 で上がる、AWS Organizations のメンバーアカウントでは
メンバー別の費用が出ない、作ったばかりのワークスペースにエージェントのメモリを取り込めない、
の 3 つを直しました。

### Fixed

- **`standup.sh --cp-arch arm64` が、アーキを検査したあとに既定のアーキで配備して**
  いました。フラグの値はイメージの整合チェックには届いていましたが、スタックには渡って
  いなかったため、「arm64 に対応している」と報告しつつ Control Plane は x86_64 で
  動いていました。
- **AWS Organizations のメンバーアカウントではコスト配分タグを読めず**、メンバー別の
  費用が「利用できません」になり、Control Plane が毎ティック権限エラーを記録していました。
  按分が効いているかどうかは、有効化の状態ではなく実際の費用の値から判定するように
  しました。有効化は AWS 側の反映に最大 1 日かかるので、利用者が知りたいことの答えとしても
  こちらが正確です。
- **作ったばかりのワークスペースへエージェントのメモリを取り込むと、最後の段で失敗して**
  いました。プレビューは通るのに適用だけが失敗する形で、新しい環境で真っ先にやることが
  そのまま踏みます。失敗したときの表示も「取り込みに失敗しました」だけでなく、原因を
  述べるようにしました。
