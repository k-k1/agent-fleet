各バージョンはワークスペースの rootfs も含めて 1 つの GitHub Release になり、ネイティブパッケージは amd64 に加えて
arm64 の Linux 向けにも出ます。Managed セッションの停止は 2 段になりました。1 回目は実行中のターンだけを止めてキューを残し、
2 回目でキューも捨てます。ミラーは claude が書いている途中の返答を表示します。AWS では「作り直し」と「ホームを掃除」が
成功と報告して何も消していませんでした。ecs-ec2 では動くようになり、ecs では断ります。ワークスペースやホストの AWS 認証情報を
エージェントのセッションに渡さなくなりました。AWS とクラウド上の Docker の配備では運用者の作業があります。

### Security: ワークスペースやホストの AWS 認証情報をエージェントのセッションに渡さなくなりました

このリリースより前は、エージェントのセッションやターミナルで AWS プロファイルを指定しないコマンドが、メンバーではなくワークスペース自身の AWS の ID で黙って動くことがありました。素の `aws`、SDK の既定の認証情報チェーン、Gradle／Maven のデプロイプラグインのようなビルドツールが該当します。その ID は、ECS ではワークスペースのタスクロール、ecs-ec2 ではインスタンスメタデータ（IMDS）経由の EC2 スロットのインスタンスプロファイル、インスタンスプロファイルを持つ Docker ホストではそのプロファイルでした。こうしたコマンドは今後「Unable to locate credentials」で失敗します。メンバーは `af-aws-exec --profile <name> --account <id> -- <command>` で自分として AWS コマンドを実行します。

変わったこと:
- ECS／ecs-ec2: Agent は起動するすべてのもの（tmux のペインと MCP サーバーを含む）からコンテナの認証情報の変数を取り除き、AWS_EC2_METADATA_DISABLED=true を設定します。
- Docker: Control Plane はワークスペースのコンテナを AWS_EC2_METADATA_DISABLED=true で起動します。
- ecs-ec2 のスロット: スロットのユーザーデータに ECS_AWSVPC_BLOCK_IMDS=true。
- ec2-single: テンプレートが IMDSv2 とホップ制限 1 を必須にします。
- update.sh はスロットプールのスタック（40-ec2-pool）も再デプロイします。ecs-ec2 で見つけられないときは止まるので、--pool-stack <stack> で指定してください。

運用者が行う作業:
1. いつもどおり更新します（ECS は update.sh、Docker は compose の pull／up とワークスペースのイメージ）。
2. ecs-ec2: 更新前に起動したスロットは古いユーザーデータのままで IMDS に届き、ワークスペースの Stop → Start は同じスロットに戻ります。ingress スタックの Ec2SlotTerminateAfterSec を設定し（推奨 14400）、Control Plane のスイーパーで退役させてください。スイーパーは終了前にホームを外し、ホームを消すことはありません。その後、利用者にワークスペースを Start してもらうと新しいスロットが作られます。deploy/aws/ecs/README.md の「Moving retained slots onto new user data」を参照してください。
   🔴 2026-10-03 訂正（#1473）: スロットの入れ替え予約が入ったリリース以降は、この目的に Ec2SlotTerminateAfterSec を使わないでください。設定 → 管理 → スロットで古いスロットを予約し（「N 台すべてを入れ替え予約…」は起動テンプレートの $Latest より古いスロットだけを選びます）、利用者に停止 → 起動してもらいます。次の起動ごとにホームが新しいスロットへ移り、古いスロットは終了します。Ec2SlotTerminateAfterSec はその時間停止していたスロットをすべて恒久的に終了するので、次の起動が遅くなりスロットのキャッシュも失われます。すべての配備が望むわけではありません。この移行のためだけに設定したなら 0 に戻してください。
3. Docker／compose: 動いているワークスペースは作られたときの環境のままで、`docker compose up -d` や Docker の再起動では変わりません。更新後に Console ですべてのワークスペースを Stop → Start し、AF_WS_WORKLOAD_AWS を変えたときも同じようにしてください。
4. ec2-single: このリリースより前に作ったインスタンスには `aws ec2 modify-instance-metadata-options --instance-id <id> --http-tokens required --http-put-response-hop-limit 1 --http-endpoint enabled` を実行してください。スタックの更新で適用しないでください。Ubuntu の AMI パラメータが解決し直され、インスタンスが置き換わることがあります。
5. クラウド上のその他の Docker ホスト: IMDSv2 とホップ制限 1 を必須にするか、ワークスペースのブリッジから 169.254.169.254 への通信を拒否する DOCKER-USER ルールを追加してください。compose に新しい権限は要りません。
6. オプトインを切った状態でワークスペースのシェルから確認します: `echo ${AWS_EC2_METADATA_DISABLED:-unset}` が true を出す。プロファイルなしの `aws sts get-caller-identity` が「Unable to locate credentials」で失敗する。`curl -s -o /dev/null -m 3 -w '%{http_code}' -X PUT -H 'X-aws-ec2-metadata-token-ttl-seconds: 60' http://169.254.169.254/latest/api/token` が 200 を出さない。環境変数は表示しないでください。

オプトイン: Control Plane の AF_WS_WORKLOAD_AWS=1 は ECS のタスクロールをセッションに戻し、SDK のメタデータ参照の抑止をやめます。ネットワークの遮断は外さないので、Docker のワークスペースにホストのインスタンスプロファイルを渡すことはありません。ワークスペースには次の Start で効きます。

対象外: ネイティブのランタイムのワークスペースはメンバー自身のマシンで動き、そのマシンのインスタンスロールを持ったままです。プロセスが自分のプロセスツリーから ECS のコンテナ URI を意図して読むことはまだできます（Agent トークンと同じ、同一ユーザーの境界）。

### Upgrade notes

- **リリースの添付ファイル**: 別の `rootfs-<r>` リリースはなくなり、rootfs は `v<version>` に添付されます。各リリースの
  `SHA256SUMS` はそのリリースの添付ファイルをちょうど列挙します。導入済みの環境と `af update` は何もしなくて大丈夫です。
  `rootfs-<r>` リリースから取得するスクリプトやミラーだけが追従を要します。
  ([#1345](https://github.com/k-k1/agent-fleet/issues/1345))
- **`AF_MASTER_KEY` なしで人をサインインさせる配備**は、起動時に警告をログに出し、super admin にバナーを出します。止まりはしません。
  ([#1080](https://github.com/k-k1/agent-fleet/issues/1080))
- **`PUBLIC_BASE_URL` がないと、内部 git のクローン・push・LFS は 503 を返すようになりました。** 内部 git を使うなら設定してください。
  ([#1212](https://github.com/k-k1/agent-fleet/issues/1212))
- **`AF_USAGE_SAMPLE_INTERVAL`・`AF_GIT_GC_INTERVAL`・`AF_SCHEDULER_INTERVAL`・`AF_CLOUD_COST_INTERVAL` は `0` で本当に止まるようになりました。**
  ([#1186](https://github.com/k-k1/agent-fleet/issues/1186))
- **他メンバーのセッションを止める管理者用 MCP ツールは `stop_user_session` になりました。** 旧名では一度も動いていませんでした。
  ([#1188](https://github.com/k-k1/agent-fleet/issues/1188))
- **セッションの AWS 認証情報**: 上の Security の節を見てください。AWS やクラウド上の Docker ホストのすべての配備に作業があります。

  いる場合はクラスター名と同じにしてください。`retain` のデータスタック名は 37 文字までです。稼働中の配備で EFS バックアップを
  有効にする手順は ECS の runbook にあります。
