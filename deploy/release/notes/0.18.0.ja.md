セッションが自分でセッションを起こして世話できるようになり、自前エンジンのモデルを
Console から離れずに探して取り込めるようになりました。画像生成は配備自身の ComfyUI で
動かせるようになり、配備ごとに色と名前を付けて複数の環境を一目で見分けられます。

### New

- **セッションが自分でセッションを起こし、世話できるようになりました。** 子に仕事を渡し、
  自分が起こした子を一覧し、出力を読み、停止・再開できます——指示・回答・削除はどの
  セッションにもできません。既定 OFF、設定 > エージェントにあり、1 つのセッションが同時に
  持てる子の本数もそこで決めます（1〜6・既定 3）。
- **どのセッションも自分が属するフリートを見られるようになりました。** これまでの opt-in が
  どこでも ON になり——OFF にしていたワークスペースも含めて——設定項目は無くなりました。
  メモは追加だけでなく編集もできます。
- **左ペインで関連するセッションと worktree が入れ子になりました。** worktree はそれを作った
  セッションの下に入り、同じ family には同じ色の縦線が付きます。引き継ぎ提案から起動した
  セッションも、提案元の family に入るようになりました。
- **起動されていない引き継ぎを抱えた行がそう表示されます。** これまでは「やることが残って
  いないセッション」と同じ見た目でした。
- **配備ごとに色と名前を付けられます。** 設定 > 管理 > 見た目で選ぶと、favicon・ホーム画面の
  アイコン・ログイン画面・アプリ名がそれに従います。再デプロイは要らないので、同じイメージを
  dev と本番へ配っても見分けが付きます。
- **モデルを Console から検索できます。** 取り込み画面から Hugging Face と Civitai を検索でき、
  各行にライセンス・サイズ・コンテキスト長が出ます。エンジンを 1 つも動かしていない配備でも
  カタログを閲覧できます——立てるかどうかを決めようとしている配備こそ、それを見たい人です。
- **Hugging Face のトークンを Console から入れられます。** gated のリポジトリ（SD3.5 と
  FLUX.1 のすべて）を取り込むのに CloudFormation を回す必要が無くなりました。
- **画像生成を配備自身の ComfyUI で動かせます。** SDXL・SD3.5・FLUX.1・FLUX.2 klein・
  Z-Image に対応し、要求ごとにモデルを名指しでき、いまどれが載っているかも分かります。
- **エンジンが買う GPU を Console から選べます。** 運用者が配備に段（クラス）の梯子を宣言し、
  管理者がその中から段を選ぶので、VRAM の要るモデルのためにスタックを更新せずに済みます。
- **メモのカテゴリ見出しに ＋ が付きました。** そのカテゴリへ直接追加でき、書きかけの下書きと
  アップロード済みの画像はそのまま持ち越されます。

### Improved

- **エンジンが早く使えるようになりました。** 起動時は要求されたモデルだけを載せ、残りは背後で
  取りに行きます。モデルの入れ替えも速くなりました。

### Fixed

- **生成した画像が会話に出ないことがありました。** 後ろで何か 1 つでも動くと、カードが畳まれた
  「作業過程」の中に落ち、そもそも作られなかったように見えていました。
- **opencode の起動メニューに既定のモデルしか出ず**、「接続とプランをご確認ください」と
  無関係なことを言っていました。
- **「終わったら停止」を指示したセッションが、背景で動いているコマンドを残したまま停止して
  いました。** アイドル停止と同じように、終わるのを待つようになりました。

### Upgrade notes

- **推論エンジンを使っている ECS の配備は、更新の前に `params/60-engines` から
  `LlmModelFile` と `ImageModelFile` の行を消してください。** テンプレートから無くなった
  ため、渡したまま更新すると `Parameters: [ImageModelFile] do not exist in the template`
  で止まります。失われるものはありません——モデルは Console から選びます。
- **他に何も変えていなくても、この更新で Control Plane が 1 度入れ替わります。** タスク
  定義が小文字ではなく `X86_64` / `ARM64` を持つようになり、リビジョンが 1 つ増えるためで
  す。入れ替わりは無停止で、`CpArch` の書き方はこれまで通りです（`x86_64` / `arm64`）。
- 新しいエンジンの機能 2 つは opt-in で、同じファイルで設定します。ComfyUI は
  `ImageEngine=comfy`、GPU の梯子は `LlmInstanceClasses` / `ImageInstanceClasses` です。
  書かなければ何も変わりません。値は
  `deploy/aws/ecs/cfn/PARAMETERS-60-engines.md` にあります。
