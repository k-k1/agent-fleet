Token usage is broken down by feature, files open for edit in the Console, and
things you lock stay put — plus auto-resume when a turn dies mid-flight.

### New

- **Usage by feature** — Settings gains a usage tab with graphs over token spend
  (and real USD where the CLI reports it). Session turns and the fleet's own
  helper calls (assistant chat, titles, reply suggestions, compact, auto-turns,
  bridge replies, …) share one ledger, so you can see which feature is eating
  the budget rather than only the subscription chips on the workspace bar.
- **Text and code editing in the File pane** — open a file for edit, keep a dirty
  buffer with undo, and save through the workspace with revision checks. Markdown
  keeps edit / preview / split (including Marp); other text uses a code editor.
  Navigation, reload and workspace teardown refuse to throw away unsaved work
  until you choose save, discard or cancel.
- **Deletion locks** — pin a session, a working copy (clone or worktree), or an
  assistant conversation so neither a manual delete nor automatic prune can
  remove it. Enforcement is on the agent REST layer, so Console, operator tools
  and chat-bridge paths all hit the same 403. Archive and halt still work
  (they do not destroy the object).
- **Auto-resume after an aborted turn** — when a turn dies for a reason that
  resending would fix (disconnect, transient rate limit), the fleet operator can
  restart it on the linked conversation. Cap is two automatic retries; after
  that it escalates to you. Toggle under Settings › Assistant (on by default).
  Sessions started only from the Console (no conversation link) are not
  auto-resumed — you still get the notification.
- **Per-purpose model picks for the assistant** — each CLI can set a model for
  assistant chat and a separate one for helper generation (titles, suggestions,
  …). A **Recommended** choice resolves from the live catalogue and connection
  (for example OpenCode Go accounts get a Go-friendly pair); the settings UI
  shows the concrete model in effect.

### Improved

- OpenCode's model list can be shaped for Go / Zen catalogues.
- OpenCode managed: failed turns surface clearly instead of vanishing.
- Mobile settings open from a list rather than a single long sheet.
- Dist README opens with a short product pitch (en/ja).
- README and docs screenshots refreshed (including the usage view).

### Fixed

- Opening another chat could mix answers between conversations.
- Re-presented plans did not keep the correct approval badge on the mirror.
- Deletion-lock state lagged in the Console until a refresh; lock is now
  relayed and held through the control plane so the UI updates immediately.
- File save/restore races: timed-out PUTs no longer proceed after the client
  gave up; recovery GETs serialize behind the write mutex so a stale 200 cannot
  look like success; discard waits until disk is settled; concurrent snapshots
  respect the commit boundary.
- Usage ledger: dropped folds, blocked writes and double-counts closed;
  duplicate `(ref, idx)` rows no longer inflate totals.
- Guard cancel now propagates interrupt and I/O timeouts cleanly.

### Upgrade notes

No migration or configuration change is required. Auto-resume defaults to on;
turn it off under Settings › Assistant if you prefer every abort to wait for
you. Existing workspaces have no deletion locks until you set them.
