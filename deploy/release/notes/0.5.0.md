Working sets split the Console's left pane by project, you can register your own MCP
servers, an agent's memory is versioned and portable, and the editor can propose a
change you review as a diff.

### New

- **Working sets.** Group repos, chats and sessions per project and switch the left
  pane between them, so a busy fleet shows only what the work in front of you needs.
  Schedules follow the same switch.
- **Your own MCP servers.** Register stdio or remote HTTP servers from Settings, point
  them at the assistant, at sessions, or both, and test the connection before saving.
  Tenant admins can distribute a server to everyone.
- **Agent memory management.** An agent's memory files are kept under version control:
  browse the history and diffs, restore one file or the whole memory to a point in
  time, and export or import a bundle to move memory between environments (scanned for
  secrets before anything leaves).
- **AI change proposals in the editor.** Ask for an edit on the file you have open and
  review the result as a diff before accepting — nothing is written until you accept.
- **Skill picker in the session chat**, with arguments, including a skill that belongs
  to a different agent kind.
- **Comments on a plan.** Annotate a passage and send every comment at once.
- **Automatic recovery from Claude usage limits.** The no-cost "wait for the reset"
  option is confirmed for you, a one-time resume is booked for when the limit lifts,
  and both appear in the notification centre.
- **Switch agent mid-conversation**, and **hide the models you never use** per agent
  kind — they drop out of the pickers and are refused at launch.
- **Work plans survive a handoff** — the assistant's plan is carried into the next
  conversation verbatim instead of being flattened into the summary.

### Improved

- **Assistant ↔ session traffic costs far fewer tokens** — earlier compaction, batched
  auto-turns, clipped output tails, a lighter model for automatic replies and quiet
  completion reports. All five knobs sit in Settings.
- **Light mode was redone against measured contrast**, so grey-on-white text is
  readable across the Console rather than only in the obvious places.
- **Cleanup is staged** — archive, then remove worktrees, then reclaim the shelf — and
  each candidate explains why it is one.
- **Worktrees can be created on an existing branch**, and the same branch can no longer
  be checked out twice.
- The workspace bar shows a **Restart required** badge when the running backend is
  behind the deployed one.
- Files in the left pane group by project and branch; schedules can finish quietly (the
  new default); Markdown shows YAML front matter as properties and links commit hashes
  and session ids automatically.
- Clearer names: the SCM pane is now **Commit graph**, and Settings' "Mirror" is
  **Session chat**.
- Pinned CLI versions: Claude Code 2.1.220, Codex 0.146.0, OpenCode 1.18.10, GitHub
  Copilot 1.0.77, Antigravity 1.1.9, Cursor 2026.07.23, Kiro 2.16.0, rtk 0.44.1.

### Fixed

- **A session could stay "working" forever** after the usage-limit menu appeared, with
  no way back short of a restart.
- **OpenCode 1.18.8 lost every MCP tool** — its new protocol era requires fields the
  fleet was not sending.
- **Completion reports could vanish**, assistant sessions on OpenCode never delivered
  one at all, and Codex sessions could fail to report.
- **Searching files, or opening the skill picker, could black out the Console.**
- The restart-required badge stayed lit permanently on Docker fleets, and AI-suggested
  subjects carried a preamble and ignored the display language.

### Upgrade notes

Nothing to do. Working sets start empty, so the left pane behaves exactly as before
until you create one. Schedules now finish quietly by default — switch completion
reports back on per schedule if you relied on them. Claude usage-limit auto-resume
defaults to on, under Settings › Agents › Claude.
