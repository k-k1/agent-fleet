Working sets split the Console's left pane by project, you can register your own
MCP servers for the assistant and for sessions, an agent's memory is versioned and
portable, and the editor can propose a change you review as a diff.

### New

- **Working sets** — group repos, chats and sessions per project and switch the
  left pane between them, so a busy fleet shows only what the work in front of you
  needs. Schedules follow the same switch.
- **Your own MCP servers** — register MCP servers from Settings (stdio or remote
  HTTP), point them at the assistant, at sessions, or both, and test the connection
  before saving. Tenant admins can distribute a server to everyone; a personal
  registration that a tenant one shadows is flagged rather than silently ignored.
- **Agent memory management** — an agent's memory files are kept under version
  control: browse the history, see the diff, restore one file or the whole memory
  to a point in time, and export/import a bundle to move memory between
  environments (scanned for secrets before anything leaves). Codex memory is
  managed too, and the fleet operator can reach it through MCP.
- **AI change proposals in the editor** — ask for an edit on the file you have
  open and review the result as a diff before accepting or rejecting it; the
  generation channel is read-only, so nothing is written until you accept. The
  editor also follows changes made outside it — a clean buffer reloads itself, a
  dirty one tells you instead of overwriting your work.
- **Skill picker in the session chat** — pick a skill from the composer, with its
  arguments, including a skill that belongs to a different agent kind (injected as
  a prompt rather than copied into the session).
- **Comments on a plan** — select a passage in a plan, annotate it, and send every
  comment at once from the session chat. Free text sent to a session that is
  waiting for plan approval is now refused rather than read as an answer.
- **Automatic recovery from Claude usage limits** — the limit menu is confirmed
  automatically (the no-cost "wait for the reset" option), a one-time resume is
  booked for when the limit resets, and both the limit and the resume appear in
  the notification centre. On by default; the menu is confirmed for you even when
  you turn the resume off.
- **Switch agent mid-conversation** — change which CLI an assistant chat runs on
  without starting a new conversation.
- **Unused models** — hide the models you never use, per agent kind. They drop out
  of the pickers and are refused at launch.
- **Work plans survive a handoff** — the assistant's work plan is carried into the
  next conversation verbatim instead of being flattened into the summary, and it
  can be pinned so later turns keep it.

### Improved

- Assistant ↔ session traffic costs far fewer tokens: earlier compaction, batched
  auto-turns, clipped output tails, a lighter model for automatic replies and
  quiet completion reports — all five knobs sit in Settings.
- The usage tab shows what rtk saved as a full card: chart, granularity switch and
  a table view.
- Light mode was redone against measured contrast, so grey-on-white text is
  readable across the Console instead of only in the obvious places.
- Files in the left pane group by project and branch, and the filter matches
  slugs, branch names and folder names.
- Cleanup is staged — archive, then remove worktrees, then reclaim the shelf — and
  each candidate explains why it is one. A deletion-locked session keeps its
  worktree.
- Worktrees can be created on an existing branch (fetch and fast-forward
  included), and the same branch can no longer be checked out twice.
- Reply suggestions can be pinned and have a per-chip menu; the row scrolls
  sideways with the wheel.
- The workspace bar shows a **Restart required** badge when the running backend is
  behind the deployed one.
- Schedules can finish quietly (new default) or report completion as before.
- Markdown shows YAML front matter as properties, and links commit hashes, session
  and conversation ids automatically.
- Clearer names: the SCM pane is now **Commit graph**, and Settings' "Mirror" is
  **Session chat**.
- Pinned CLI versions: Claude Code 2.1.220, Codex 0.146.0, OpenCode 1.18.10,
  GitHub Copilot 1.0.77, Antigravity 1.1.9, Cursor 2026.07.23, Kiro 2.16.0, rtk 0.44.1.
- Notices in chat follow your display language instead of being stored in one.
- A review pass over the Console, the control plane, the workspace agent and the
  docs closed around 200 smaller issues.

### Fixed

- A session could stay "working" forever after the usage-limit menu appeared, with
  no way back short of a restart.
- OpenCode 1.18.8 lost every MCP tool: the new protocol era requires `ttlMs` and
  `cacheScope` in `tools/list`, and the fleet was not sending them.
- Completion reports could vanish when a report waiting behind a background
  sub-agent met a false "idle" detection.
- Assistant sessions on OpenCode never delivered their completion report.
- Codex sessions could fail to report because the fleet's own MCP tools started
  without the agent API credentials.
- The skill picker could black out the whole Console, and did not filter when it
  was opened from its button.
- "Unused models" matched more models than it should have.
- Searching files could blank the screen.
- The file view's header buttons overlapped the pane controls.
- The restart-required badge stayed lit permanently on Docker fleets.
- AI-suggested subjects carried a preamble and ignored the display language.
- Reply suggestion rows could stick, and ✨ suggestions kept a stray heading line.
- Tick labels on the rtk chart sank below the baseline.

### Upgrade notes

No migration or configuration change is required. Working sets start empty, so the
left pane behaves exactly as before until you create one. Schedules now finish
quietly by default — switch completion reports back on per schedule if you relied
on them. Claude usage-limit auto-resume defaults to on, under Settings › Agents ›
Claude.
