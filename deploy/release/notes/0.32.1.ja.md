0.32.0 の修正リリースです。メモリの提案は頼まない限りバックグラウンドで動かなくなり、止めた opencode セッションの
履歴が再び表示され、同梱の Jira CLI は `jira init` なしで課題を作れるようになりました。

### 修正

- **メモリの提案が、オンにしたとたん自動で動いていました。** 自動のレビューは別のスイッチ **自動でも提案させる**
  （既定はオフ）になりました。**終わったセッションからメモリを提案させる** だけをオンにしている間は、
  **メモリを提案させる（今すぐ）** を選んだときにレビューします。レビューを動かせるエージェントがないときは、
  設定にそう表示します。
  ([#2358](https://github.com/k-k1/agent-fleet/issues/2358),
  [#2356](https://github.com/k-k1/agent-fleet/issues/2356))
- **止めた opencode セッションの会話履歴が、Console で空になっていました。**
  ([#2379](https://github.com/k-k1/agent-fleet/issues/2379))
- **`jira init` をしていないと `jira issue create -p KEY` が失敗し**、設定があるときは別のプロジェクトの課題タイプを
  使っていました。
  ([#2369](https://github.com/k-k1/agent-fleet/issues/2369),
  [#2373](https://github.com/k-k1/agent-fleet/issues/2373))
- **Jira の作業項目の最初のプロンプトが、エージェントに Jira MCP サーバーを使わせていました。** 今は `jira` CLI で
  チケットを読みます。
  ([#2367](https://github.com/k-k1/agent-fleet/issues/2367))
- **ロードバランサーの後ろでセッションが失われる MCP サーバーでも、接続テストが成功していました。** 今はその問題を
  伝えます。
  ([#2368](https://github.com/k-k1/agent-fleet/issues/2368))

### 改善

- **テナント › 外部からのメモリ利用** で、テナント管理者は、メンバーが Agent Fleet の外のエージェントから
  Agent Fleet メモリを使うのを止められます。既定は許可です。
  ([#2318](https://github.com/k-k1/agent-fleet/issues/2318))
- **設定の Jira カードが、ボード・スプリント・エピックを使えないことを表示します。** 接続に Jira Software の
  スコープがないときで、テナント管理者がすべきことも示します。
  ([#2372](https://github.com/k-k1/agent-fleet/issues/2372),
  [#2377](https://github.com/k-k1/agent-fleet/issues/2377))

### アップグレードの注意
