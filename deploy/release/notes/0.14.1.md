A workspace setting could not be saved at all on a deployment backed by Postgres, and
the user guide would not open from inside a workspace. Preview settings now show the URL
you actually have.

### Improved

- **A preview name can live in a hosted zone of its own.** `PreviewHostedZoneId` points
  the preview certificate and DNS record at a different zone from the Console's, which is
  what a sibling name (`pv.example.com` beside `af.example.com`) needs when the Console's
  own name is the delegated zone.

### Fixed

- **On a deployment backed by Postgres, saving a workspace setting always failed.**
  Reading them back quietly returned the defaults, so the screen looked normal and only
  pressing save said otherwise: the agent CLI to use, the ports a preview exposes and
  whether it is public had never been stored.
- **The user guide did not open from inside a workspace.** The button led to the guide's
  front page, which was the one file not delivered to the container.
- **The preview settings show the URL you have**, and reissuing one now says what it did
  — pressing it while the workspace was stopped used to look like nothing had happened.
- **The tool version list showed "(timeout)"** for OpenCode and Copilot on a slow first
  start, and could contradict itself about the same binary.

### Upgrade notes

Nothing to do. `PreviewHostedZoneId` defaults to `HostedZoneId`, so an existing stack is
unchanged. Agent CLI pins are unchanged from 0.14.0.
