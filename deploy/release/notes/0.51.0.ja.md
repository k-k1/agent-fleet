スペースで作業を始めたり引き継いだりできる場面が増え、スペース全体で 1 つのエージェントメモリのプロジェクトを共有します。配布された MCP サーバーはサインインを共有でき、稼働中のビューには最近停止したセッションが出ます。自動実行は、別のエージェントに移したセッションも追い続けます。

### Improved

- **スペース** — 受信箱の依頼や画像スタジオのエージェント、メモの自動実行の場所にスペースを選べます。引き継ぎやプランのレビューは元のスペースで始められ、スペース内から `create_session` で起動する子は既定で新しいスペースに入ります。 ([#5220](https://github.com/k-k1/agent-fleet/issues/5220), [#5222](https://github.com/k-k1/agent-fleet/issues/5222), [#5223](https://github.com/k-k1/agent-fleet/issues/5223), [#5232](https://github.com/k-k1/agent-fleet/issues/5232))
- **スペースのエージェントメモリ** — 自分のスペースはすべて「Spaces」プロジェクトを共有し、別のスペースで保存したメモリを思い出せます。 ([#5221](https://github.com/k-k1/agent-fleet/issues/5221))
- **MCP の OAuth** — テナント管理者は要求するスコープを指定でき、同じ OAuth クライアントと認可サーバーを使う HTTPS サーバーでは、メンバーごとに 1 回のサインインを共有できます。共有サインインを切断するとグループ全体が切断されます。Google Workspace の MCP サーバーとのサインインの互換性も改善しました。 ([#5173](https://github.com/k-k1/agent-fleet/issues/5173), [#5175](https://github.com/k-k1/agent-fleet/issues/5175))
- **Claude Code と OpenCode の Bedrock** — 経路ゲートウェイが有効でポリシーが許可していれば、従来のデプロイ設定なしで、印を付けた AWS プロファイルを Bedrock 経路に使えます。 ([#3282](https://github.com/k-k1/agent-fleet/issues/3282))
- **稼働中のビュー** — 過去 24 時間以内に停止したセッションもカードに出ます。見出しを開くと、停止から時間が経ったものや停止時刻が不明でカードに出ていないものの件数が見えます。 ([#5155](https://github.com/k-k1/agent-fleet/issues/5155))
- スケジュールの詳細から再利用するセッションを開けます。保存していない編集は、戻るボタンで続けられます。 ([#5298](https://github.com/k-k1/agent-fleet/issues/5298))
- **サービスの稼働状況のウォッチ** — GitHub、Bitbucket Cloud、Jira Software Cloud、Confluence Cloud の公開ステータスページで、障害からの復旧を待てます。 ([#5204](https://github.com/k-k1/agent-fleet/issues/5204))
- セッションのウォッチには、リンクの横に表示名と Git ブランチが出ます。タイマーの予定時刻はブラウザのタイムゾーンで表示します。 ([#5305](https://github.com/k-k1/agent-fleet/issues/5305), [#5324](https://github.com/k-k1/agent-fleet/issues/5324))
- 日英ガイドの検索で、ページに追加したキーワードも見つかります。最近停止したセッション、再利用セッション、スペースのメモリ、ウォッチのリンク、Bitbucket のマージチェックの説明も追加しました。 ([#5064](https://github.com/k-k1/agent-fleet/issues/5064), [#5321](https://github.com/k-k1/agent-fleet/issues/5321))
- **ワークスペースのイメージ** — エージェント CLI を OpenCode 2.4.2、Copilot 1.0.116、Antigravity 1.5.18 に更新しました。その他の同梱ツールでは AWS CLI 2.42.4、GitHub CLI 2.106.0、bkt 0.41.1 が入ります。 ([#5211](https://github.com/k-k1/agent-fleet/issues/5211))

### Fixed

- **自動実行と利用上限** — 予約した自動再開が追加の承認を待たずに動きます。Console は利用上限で待機していることを示し、停止後も条件を満たせば別のエージェントへ移せます。移した実行は、移動先の実行が落ち着くまで枠を使い続けます。 ([#5212](https://github.com/k-k1/agent-fleet/issues/5212), [#5292](https://github.com/k-k1/agent-fleet/issues/5292), [#5293](https://github.com/k-k1/agent-fleet/issues/5293))
- セッション間のメッセージが配送中なら、自動実行は終了を待ちます。添付や最初のプロンプトが新しいセッションに届かなかったときも、メモが残ります。 ([#5270](https://github.com/k-k1/agent-fleet/issues/5270), [#5077](https://github.com/k-k1/agent-fleet/issues/5077))
- 使用中のスペースで 2 本目のエージェントを起動するときは確認が出ます。起動の途中や、稼働中のセッションを確認できないときは、スペースや作業コピーの削除が止まります。 ([#5230](https://github.com/k-k1/agent-fleet/issues/5230), [#5122](https://github.com/k-k1/agent-fleet/issues/5122))
- ファイルブラウザではスペースのフォルダと目印のファイルが保護されます。フォルダ名が同じでも、セッション一覧ではスペースとリポジトリを分けて表示します。 ([#5231](https://github.com/k-k1/agent-fleet/issues/5231), [#5219](https://github.com/k-k1/agent-fleet/issues/5219), [#5278](https://github.com/k-k1/agent-fleet/issues/5278))
- スペースの作業を受け取ったメンバーは新しいスペースで始め、元のファイルが送り手の側に残るとわかります。日本語の引き継ぎで別のエージェントへ移すときは、要約の終わりを見つけられます。 ([#5233](https://github.com/k-k1/agent-fleet/issues/5233), [#5291](https://github.com/k-k1/agent-fleet/issues/5291))
- Bitbucket のプルリクエストの詳細に、コンフリクトがなくてもマージを止めているチェックの理由が出ます。詳しい理由が確認できない場合は Bitbucket での確認を案内します。 ([#5306](https://github.com/k-k1/agent-fleet/issues/5306))
- ウォッチの通知がメンバーのメッセージと別に表示されます。Codex では、Code Mode の呼び出しの後も、AWS プロファイルのバッジがそれを使ったツール呼び出しに付きます。 ([#5299](https://github.com/k-k1/agent-fleet/issues/5299), [#5295](https://github.com/k-k1/agent-fleet/issues/5295))
- 稼働中の Docker ワークスペースを起動し直す操作で、Control Plane の再起動で古くなった Agent のアドレスを修復します。 ([#5257](https://github.com/k-k1/agent-fleet/issues/5257))

### Upgrade notes

- Claude Code または OpenCode の Bedrock 経路を従来の設定で有効にしていた場合は、新しい Control Plane のもとでワークスペースを再起動する前に、ワークスペースイメージを更新してください。古い Agent が必要とする設定は、新しい Control Plane からは渡されません。
