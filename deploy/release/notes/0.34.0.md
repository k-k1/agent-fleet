MCP sign-in works in both directions. Remote MCP clients such as claude.ai and ChatGPT can connect to
Agent Fleet by signing in instead of pasting a token, and you can sign in to MCP servers that require
OAuth from Settings so your sessions can use them. EC2 pool slots get a force-stop and more memory
headroom for the host, and the Jira CLI copes with a flaky network.

### New

- **Remote MCP clients connect by signing in (OAuth).** claude.ai, ChatGPT, Claude Code and other
  MCP clients sign you in to the Console and you choose the tenant and read or write access, instead of pasting a
  Personal Access Token. Off by default: the operator turns it on with `AF_MCP_OAUTH=1`. Settings ›
  Connections › MCP tokens lists your connected apps with their recent calls and lets you revoke them.
  A tenant admin can switch it off for the tenant, and a deployment administrator edits which client hosts are
  trusted in the Admin panel. Input a client sends to a session is marked **Via MCP**.
  ([#2433](https://github.com/k-k1/agent-fleet/issues/2433),
  [#2434](https://github.com/k-k1/agent-fleet/issues/2434),
  [#2455](https://github.com/k-k1/agent-fleet/issues/2455),
  [#2457](https://github.com/k-k1/agent-fleet/issues/2457),
  [#2531](https://github.com/k-k1/agent-fleet/issues/2531),
  [#2542](https://github.com/k-k1/agent-fleet/issues/2542),
  [#2567](https://github.com/k-k1/agent-fleet/issues/2567))
- **Sign in to MCP servers that require OAuth.** In Settings › MCP servers, choose **OAuth** as the
  authentication of a remote server and press **Sign in**; the connection test already tells you when
  a server needs it. Sessions reach the server through a relay in your workspace, so the token is never
  written into a CLI's configuration. claude, copilot and cursor have been seen using it; servers
  distributed by the tenant cannot use OAuth yet.
  ([#2479](https://github.com/k-k1/agent-fleet/issues/2479),
  [#2485](https://github.com/k-k1/agent-fleet/issues/2485),
  [#2549](https://github.com/k-k1/agent-fleet/issues/2549),
  [#2568](https://github.com/k-k1/agent-fleet/issues/2568),
  [#2580](https://github.com/k-k1/agent-fleet/issues/2580))
- **Force-stop a wedged EC2 pool slot.** A deployment administrator can stop a slot whose ECS and SSM agents went
  silent with **Stop (force)** on the pool screen; the member's next Start wakes the same slot.
  ([#2449](https://github.com/k-k1/agent-fleet/issues/2449))
- **Open shell here** in a folder's context menu starts a shell session in that folder.
  ([#2460](https://github.com/k-k1/agent-fleet/issues/2460))
- **Edit and delete Jira comments** with `jira issue comment edit` and `delete` in a session.
  ([#2477](https://github.com/k-k1/agent-fleet/issues/2477))
- **Muse Code contributor mode** can be switched on in the Muse Code card of Settings › Agents.
  ([#2535](https://github.com/k-k1/agent-fleet/issues/2535))

### Improved

- **The MCP server forms start from a remote server** with a display name and an authentication choice
  (none, Bearer token, custom headers or OAuth); the ID follows the name.
  ([#2550](https://github.com/k-k1/agent-fleet/issues/2550))
- **The Jira CLI survives a flaky network.** Reads are retried, a hung command times out, a timed-out
  `issue create` lists the issues it may have created, and an expired connection says so in one line.
  Agent instructions may now prefer an Atlassian MCP tool over the CLI.
  ([#2476](https://github.com/k-k1/agent-fleet/issues/2476),
  [#2532](https://github.com/k-k1/agent-fleet/issues/2532),
  [#2538](https://github.com/k-k1/agent-fleet/issues/2538),
  [#2539](https://github.com/k-k1/agent-fleet/issues/2539),
  [#2543](https://github.com/k-k1/agent-fleet/issues/2543))
- **ECS-EC2: the host keeps 2 GiB of every slot** and its ECS and SSM agents are protected from memory
  reclaim, so a busy workspace no longer takes the slot dark. An 8 GiB slot's workspace is now capped
  at 6 GiB instead of 6.4 GiB.
  ([#2451](https://github.com/k-k1/agent-fleet/issues/2451),
  [#2452](https://github.com/k-k1/agent-fleet/issues/2452))
- **ECS-EC2: a Start stuck behind a task that cannot finish stopping** is shown as blocked with the
  reason instead of an endless "starting".
  ([#2447](https://github.com/k-k1/agent-fleet/issues/2447))
- **Muse Code 1.4.12** is supported, and its new record kinds show as one-line summaries.
  ([#2575](https://github.com/k-k1/agent-fleet/issues/2575))

### Upgrade notes

- **ECS deployments:** deploy the `20-platform` stack before using **Stop (force)**, and the
  `40-ec2-pool` stack so new slots protect their agents. Workspaces on 8 GiB slots get 0.4 GiB less
  memory from their next start.
- **MCP sign-in** is opt-in: set `AF_MCP_OAUTH=1` (with `AF_MCP_ENABLED=true` and an `https`
  `PUBLIC_BASE_URL`). Hosted clients reach `/mcp` from their vendors' servers, so it has to be
  reachable from the internet; behind `AUTH=proxy`, see the operator guide for which paths bypass the
  gateway.
