stable-diffusion.cpp の画像エンジンを退役させました——動かしている配備が無かったためです。
そこに溶接されていた OpenAI Images のクライアントは残し、汎用化して `openai-compat` に
改名したので、OpenAI 互換の画像サーバなら何にでも行を宣言できるようになりました。

### New

- **`external` / `remote` の行から、任意の OpenAI 互換画像サーバに当てられるようになりました。**
  `provider: "openai-compat"` で行を 1 本宣言するだけです。

  ```json
  {"key":"oai-image","api":"images","provider":"openai-compat",
   "url":"http://<host>:<port>","health":"/v1/models","lifecycle":"external"}
  ```

  行がモデルを宣言しているときだけ `model` が送られます——宣言が無ければ何も送りません、
  これまでどおりです。サイズも行から取り、モデル名からの推測はもうしません。サーバが
  bearer を要求するなら `AF_ENGINE_API_KEY_<KEY>` から読みます。`<KEY>` は行の `key` を
  大文字にしたうえで、**英数字以外の文字を全部 `_` に置き換えたもの**です——上の例の行
  （`"key":"oai-image"`）が読むのは `AF_ENGINE_API_KEY_OAI_IMAGE` であって
  `AF_ENGINE_API_KEY_OAI-IMAGE` ではありません（ハイフンはシェルの環境変数名に使えません）。
  🔴 **この経路は宣言済み・試験済みですが、それはこのプロジェクト自身の試験用の偽サーバに
  対してだけです。実在の OpenAI 互換サーバに当てた実績はまだありません**——当てるまでは
  未実証として扱ってください。

### Improved

- **この build が serve できない provider を名乗る行が、黙って消えなくなりました。** 以前は
  `sdcpp` を名乗ったままの行があると `generate_image` が `tools/list` から消えるだけで、
  エラーも印も一切出ませんでした。いまはコントロールプレーンが読み込み時にその行 1 本に付き
  1 行ログを出し、管理者用の**「推論エンジン」**の画面（隣にある「推論エンジンのモデル」の
  画面ではありません）がその行に印を付け、名乗っている provider 名を表示します。

### Upgrade notes

- **`ImageEngine` は、それが選んでいたエンジンごと無くなりました。** image ロールは ComfyUI を
  動かすだけで選ぶものが無いので、パラメータ自体を `60-engines` から削除しました。退役した
  エンジンにしか意味の無かった 2 つ——`ImageImageTag`（その ECR タグ）と `ImageExtraArgs`
  （`sd-server` の追加フラグ）——も同様で、`deploy` はこの 3 つのどのキーも拒みます。
  `ImageComfyImageTag` は無関係でそのまま残ります——パラメータファイルを編集するときに
  取り違えないでください。`EcrSdcpp` の ECR リポジトリと、そこにある 2.31 GB のイメージも
  消えました。
- 🔴 **今回だけ、`60-engines` を `20-platform` より先に更新してください**——`update.sh` の
  通常の順序とは逆です。`60-engines` は `20-platform` がこの版でもう作らなくなった
  export（`EcrSdcppUri`）を import していたためで、`20-platform` を先に更新すると
  CloudFormation がまだ使われている export の削除を拒んでロールバックします。`update.sh`
  自身がこれを検知します——手元の `60-engines` スタックがまだ `EcrSdcppUri` を import
  しているなら、何にも触れる前に止まり、`60-engines` だけを先に更新する
  `aws cloudformation deploy` のコマンドをそのまま印字します。そのコマンドを実行してから、
  改めて `update.sh` をいつもどおり実行してください。
- **`ImageEngine` に何が書いてあっても自動で落とされます。** `standup.sh` は捕捉済みの
  パラメータファイルから値に関わらずこの行を消し、`update.sh` は何も渡しません——稼働中の
  スタックが持っていた値は次の更新で単に失われます。それが「パラメータが消えた」という
  ことです。いつもどおりスクリプトを実行する以外にすることはなく、それは `sdcpp` でも
  `comfy` でも同じです。`deploy` はテンプレートが宣言していないキーを値に関わらず拒むので、
  `ImageEngine` を手で渡している deploy コマンドがあれば、そこからは外してください。

エージェント CLI のピンは 0.20.0 から変わっていません。
