AWS では、ワークスペースの通信を任意の egress ゲートウェイ経由にでき、すべての接続を発信元のワークスペースと
一緒に記録し、許可リストを強制できます。テナント管理者は OAuth でサインインする MCP サーバーを配布でき、
Agent Fleet のメモリには専用の MCP エンドポイントができました。ツールチェーンでは JDK と Node.js のパッチを
最新に保てます。

### 新機能

- **AWS: ワークスペース用の egress ゲートウェイ（プレビュー）。** `00-network` で `EgressRoute=gateway` を
  指定すると、ワークスペースの通信が専用の Elastic IP を持つゲートウェイから出ます。管理画面の **通信** の
  許可リストが ECS のワークスペースにも効き、すべての接続が発信元のワークスペースと一緒に記録されます。
  `pause.sh` と `standup.sh` は NAT ゲートウェイと一緒に止めて戻します。有効にする前にアップグレードの注意を
  読んでください。
  ([#2717](https://github.com/k-k1/agent-fleet/issues/2717),
  [#2728](https://github.com/k-k1/agent-fleet/issues/2728),
  [#2729](https://github.com/k-k1/agent-fleet/issues/2729),
  [#2742](https://github.com/k-k1/agent-fleet/issues/2742),
  [#2759](https://github.com/k-k1/agent-fleet/issues/2759),
  [#2665](https://github.com/k-k1/agent-fleet/issues/2665))
- **egress の生イベントは 30 日保存されます**（`AF_EGRESS_EVENT_RETENTION_DAYS`、`0` で無期限）。削除の前に
  S3 へアーカイブすることもできます。
  ([#2675](https://github.com/k-k1/agent-fleet/issues/2675),
  [#2699](https://github.com/k-k1/agent-fleet/issues/2699),
  [#2732](https://github.com/k-k1/agent-fleet/issues/2732))
- **OAuth の MCP サーバーをテナントに配布できます。** テナント管理者は、認証が OAuth のリモート MCP サーバーを
  配布でき、サーバー側に事前登録したクライアントも付けられます。各メンバーは設定からサインインし、資格情報は
  配布されません。
  ([#2479](https://github.com/k-k1/agent-fleet/issues/2479))
- **Agent Fleet のメモリに専用の MCP エンドポイント `/mcp/memory` ができました。** そのためのトークンや
  claude.ai のコネクタはメモリのツールにしか届かず、セッションや管理のツールには届きません。外部から呼ぶ
  メモリのツールは、リポジトリの URL でプロジェクトを選べるようになりました。
  ([#2764](https://github.com/k-k1/agent-fleet/issues/2764),
  [#2765](https://github.com/k-k1/agent-fleet/issues/2765),
  [#2766](https://github.com/k-k1/agent-fleet/issues/2766))
- **作業項目から GitHub のプルリクエストをマージできます。** GitHub がマージできると答えたときだけ、確認の
  あとで実行します。
  ([#2632](https://github.com/k-k1/agent-fleet/issues/2632))
- **Bitbucket のプルリクエストにも作業の報告をコメントできます。** Bitbucket の接続が `pullrequest:write`
  スコープを持つときに使えます。
  ([#2709](https://github.com/k-k1/agent-fleet/issues/2709))
- **不要になった JDK と Node.js のバージョンをアンインストールできます。** 設定 › ツールチェーン ›
  **インストール済みのバージョン** から行います。
  ([#2648](https://github.com/k-k1/agent-fleet/issues/2648))

### アップグレードの注意

- **`/mcp` 経由で呼ぶメモリのツール: `memory_save` と `memory_forget` に `scope` が必須になりました。**
  `scope: project` には `project` か `repository` が要ります。既定に頼っていたクライアントは、何を渡すべきかを
  示すメッセージで拒否されます。
  ([#2765](https://github.com/k-k1/agent-fleet/issues/2765))
- **AWS（ECS）: ネットワークスタックは `update.sh` の前後に手で更新します。** ワークスペースが専用の
  サブネットに移り、S3 エンドポイントにポリシーが付くため、`deploy/aws/ecs/README.md` の
  「Upgrading from v0.34.x」に従ってください。バックアップを取り、`00-network` を
  `S3EndpointEnabled=false` で change set 経由で deploy し（6 リソースの追加と `S3Endpoint` の削除）、
  `update.sh` を実行し、走っているワークスペースをすべて停止・起動してから、`00-network` を
  `S3EndpointEnabled=true` で deploy します。ネットワークスタックには `--capabilities CAPABILITY_IAM`
  が必要になりました。
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716),
  [#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **新しい `00-network` を既定値のまま deploy しないでください。** `S3EndpointEnabled` の既定は `true`
  で、そのままだとエンドポイントが、まだ再起動していないすべてのワークスペースの S3 リクエストを拒否します
  （AccessDenied）。古いサブネットに残っているワークスペースは `update.sh` が一覧にします。
  ([#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **AWS: S3 エンドポイントの新しいポリシーは、ワークスペースだけでなくプライベートサブネットのすべてに
  適用されます。** Control Plane、`ecs-ec2` のスロットホスト、エンジンは、このエンドポイントを通る
  同一リージョンの S3 リクエストのうちポリシーが許可しないものが AccessDenied になります（NAT への
  フォールバックはありません）。許可されるのは ECR のレイヤーバケット、AL2023 のリポジトリ、SSM Agent 更新と
  ECS エージェントのダウンロード用バケット、`60-engines` のモデルバケット、`10-data` が作成する省略可能な
  エグレスアーカイブ用バケットです（自前のバケットは拒否されます）。Control Plane から別のバケットを
  使っている場合、バケットを足すパラメータはテンプレートにありません。`S3EndpointEnabled=false` にする
  （S3 は NAT を通り、データ処理料金がかかります）か、エンドポイントを残したまま
  `deploy/aws/ecs/cfn/00-network.yaml` の `S3Endpoint` のポリシーを独自に変更して管理してください。
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716))
- **AWS: Fargate のワークスペースは、起動ごとのイメージ取得に NAT のデータ処理料金がかかるようになりました。**
  ワークスペース用サブネットには S3 エンドポイントがないためです。`ecs-ec2` のスロットは引き続き
  エンドポイント経由で取得します。
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716))
- **AWS: `00-network` を v0.34.x のテンプレートに戻すと、パラメータ `GatewayEipAllocationId` と
  `GatewayEipAddress` がなくなります。** 次に `EgressRoute=gateway` へ切り替えるときは両方を渡し直して
  ください（README「Upgrading from v0.34.x」の Rollback）。
  ([#2728](https://github.com/k-k1/agent-fleet/issues/2728))
- **AWS: 稼働中のスタックのパラメータを空にするには `deploy/aws/ecs/clear-params.sh` を使ってください。**
  `aws cloudformation deploy --parameter-overrides Key=` は、リハーサルでは空になりませんでした。
  （README を参照）。
  ([#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **AWS: デプロイするプリンシパルに権限の追加が必要です。** 新しいオプション機能のためのもので、
  Elastic IP の関連付け、起動テンプレート、Auto Scaling グループ、エグレスゲートウェイのインスタンスロールと
  Secrets Manager のシークレット、`pause.sh` と `standup.sh` がそれを確認するための `ssm:SendCommand` と
  `ssm:GetCommandInvocation`、エグレスアーカイブ用の S3 バケットの作成です。`deploy/aws/ecs/README.md` の
  「Minimal IAM」を参照してください。
- **AWS: エグレスゲートウェイはオプトインのプレビューです。** `00-network` の `EgressRoute` は `gateway`
  を指定しない限り `nat-gateway` のままです。`gateway` はワークスペースのすべての接続を記録し、許可リストを
  強制できますが、ゲートウェイ、リレー、ワークスペース用サブネット、pause/standup、このアップグレード手順は
  テスト用のデプロイでのみ検証済みで、本番環境ではまだです。ワークスペースに許可登録すべき 2 つ目のエグレス
  アドレスができ、SSH の git など HTTP 以外のエグレスは通らず、横取りした 443 番ポートはゲートウェイ内で
  中継します（設計上認めた例外）。
  ([#2717](https://github.com/k-k1/agent-fleet/issues/2717),
  [#2759](https://github.com/k-k1/agent-fleet/issues/2759))
- **AWS: エグレスイベントのアーカイブは既定でオフです。** `10-data` に省略可能なパラメータ
  `EgressArchive` と `EgressArchiveRetentionDays` が加わりました。`EgressArchive=create` で deploy して
  `update.sh` を実行するまで何も変わりません。
  ([#2732](https://github.com/k-k1/agent-fleet/issues/2732))
