### アップグレードの注意

- **AWS（ECS）: ネットワークスタックは `update.sh` の前後に手で更新します。** ワークスペースが専用の
  サブネットに移り、S3 エンドポイントにポリシーが付くため、`deploy/aws/ecs/README.md` の
  「Upgrading from v0.34.x」に従ってください。バックアップを取り、`00-network` を
  `S3EndpointEnabled=false` で change set 経由で deploy し（6 リソースの追加と `S3Endpoint` の削除）、
  `update.sh` を実行し、走っているワークスペースをすべて停止・起動してから、`00-network` を
  `S3EndpointEnabled=true` で deploy します。ネットワークスタックには `--capabilities CAPABILITY_IAM`
  が必要になりました。
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716),
  [#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **新しい `00-network` を既定値のまま deploy しないでください。** `S3EndpointEnabled` の既定は `true`
  で、そのままだとエンドポイントが、まだ再起動していないすべてのワークスペースの S3 リクエストを拒否します
  （AccessDenied）。古いサブネットに残っているワークスペースは `update.sh` が一覧にします。
  ([#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **AWS: S3 エンドポイントの新しいポリシーは、ワークスペースだけでなくプライベートサブネットのすべてに
  適用されます。** Control Plane、`ecs-ec2` のスロットホスト、エンジンは、ポリシーに載っていない S3
  バケットに対して AccessDenied になります（NAT へのフォールバックはありません）。載っているのは ECR の
  レイヤーバケット、AL2023 のリポジトリ、SSM Agent 更新と ECS エージェントのダウンロード用バケット、
  `60-engines` のモデルバケット、任意のエグレスアーカイブバケットです。Control Plane から別のバケットを
  使っている場合、バケットを足すパラメータはテンプレートにありません。`S3EndpointEnabled=false` にする
  （S3 は NAT を通り、データ処理料金がかかります）か、`deploy/aws/ecs/cfn/00-network.yaml` の
  `S3Endpoint` のポリシーにバケットを追加してください。
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716))
- **AWS: Fargate のワークスペースは、起動ごとのイメージ取得に NAT のデータ処理料金がかかるようになりました。**
  ワークスペース用サブネットには S3 エンドポイントがないためです。`ecs-ec2` のスロットは引き続き
  エンドポイント経由で取得します。
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716))
- **AWS: `00-network` を v0.34.x のテンプレートに戻すと、パラメータ `GatewayEipAllocationId` と
  `GatewayEipAddress` がなくなります。** 次に `EgressRoute=gateway` へ切り替えるときは両方を渡し直して
  ください（README「Upgrading from v0.34.x」の Rollback）。
  ([#2728](https://github.com/k-k1/agent-fleet/issues/2728))
- **AWS: 稼働中のスタックのパラメータを空にするには `deploy/aws/ecs/clear-params.sh` を使ってください。**
  `aws cloudformation deploy --parameter-overrides Key=` は、リハーサルでは空になりませんでした。
  スクリプトは change set で変更を適用し、各値を読み戻して確認します。
  ([#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **AWS: デプロイするプリンシパルに権限の追加が必要です。** 新しいオプション機能のためのもので、
  Elastic IP の関連付け、起動テンプレート、Auto Scaling グループ、エグレスゲートウェイのインスタンスロールと
  Secrets Manager のシークレット、`pause.sh` と `standup.sh` がそれを確認するための `ssm:SendCommand` と
  `ssm:GetCommandInvocation`、エグレスアーカイブ用の S3 バケットの作成です。`deploy/aws/ecs/README.md` の
  「Minimal IAM」を参照してください。
- **AWS: エグレスゲートウェイはオプトインのプレビューです。** `00-network` の `EgressRoute` は `gateway`
  を指定しない限り `nat-gateway` のままです。`gateway` はワークスペースのすべての接続を記録し、許可リストを
  強制できますが、ゲートウェイ、リレー、ワークスペース用サブネット、pause/standup、このアップグレード手順はテスト用のデプロイでのみ検証済みで、本番環境ではまだです。ワークスペースに許可登録すべき 2 つ目のエグレス
  アドレスができ、SSH の git など HTTP 以外のエグレスは通らず、横取りした 443 番ポートはゲートウェイ内で
  中継します（設計上認めた例外）。
  ([#2717](https://github.com/k-k1/agent-fleet/issues/2717),
  [#2759](https://github.com/k-k1/agent-fleet/issues/2759))
- **AWS: エグレスイベントのアーカイブは既定でオフです。** `10-data` に省略可能なパラメータ
  `EgressArchive` と `EgressArchiveRetentionDays` が加わりました。`EgressArchive=create` で deploy して
  `update.sh` を実行するまで何も変わりません。
  ([#2732](https://github.com/k-k1/agent-fleet/issues/2732))
