テナントと配備の管理者が、メンバーが使えるモデルの経路を選べるようになり、禁止したものはメンバーの画面から
消えます。Console の左ペインはアクティビティバーで一度に一つのビューを出す形になり、メモの自動実行は待って
いるメモの整理と作業項目の受け付けができるようになりました。ECS の EC2 では、メンバーが次の起動を一段上の
サイズにブーストできます。ECS では `update.sh` の前に `10-data` の更新が要るので、アップグレードの注意を
先に読んでください。

### 新機能

- **モデルの利用:** テナント設定 → 運用 →「モデルの利用」（配備全体は管理画面の「配備全体 › モデルの
  利用」）で、資格情報の種類と送り先で経路を制限できます。サブスクリプションは使わせない、Amazon Bedrock
  だけ、従量課金のキーは一社を除いてすべて、といった形です。各層は上の層を狭めることしかできず、ページは
  どの層が何を隠しているかを示し、提供される経路にはその出どころ・付与・予算が出ます。禁止した経路は、
  起動ダイアログ、エージェントと認証情報のページ、画像生成、アシスタントから消えます。
  ([#4169](https://github.com/k-k1/agent-fleet/issues/4169),
  [#4376](https://github.com/k-k1/agent-fleet/issues/4376))
- **設定を認証情報中心に整理:** サインインとキーは設定 →「モデルの認証情報」に移り、プロンプトの送り先
  ごとにまとまって、各カードにどのエージェントが使えるかが出ます。設定 →「エージェント」はエージェント
  ごとに一枚のカードで、オン・オフ、既定の経路、実行場所を持ち、「セッション」と「画像生成」はそれぞれの
  ページになりました。([#4169](https://github.com/k-k1/agent-fleet/issues/4169))
- **アクティビティバー:** Console の左端に並ぶアイコンの列で、左ペインに出すビューを一つ選び（セッション、
  アシスタント、課題トラッカー、メモキュー、スケジュール、ファイル）、ホームなどのペインを開きます。見て
  いないビューの知らせはアイコンの印でわかります。
- **メモの自動実行・実行前の整理:** カテゴリごとに、自動で実行する前にワークスペースの中のモデルが、
  実行待ちのメモを統合・分割・移動できるようになりました。選んだメモを手で整理することもでき、前後の
  プレビューを見てから適用します。整理はどれも実行履歴に残り、元に戻せます。
  ([#4152](https://github.com/k-k1/agent-fleet/issues/4152))
- **メモの自動実行・作業項目:** Issue・チケット・プルリクエストの「自動実行に追加」で、その項目へのリンクを
  自分のメモ付きでカテゴリに入れられます。リンクを一つだけ持つ実行は、セッションをその項目に結び付け、
  ブランチ名もその項目から付けます。([#4404](https://github.com/k-k1/agent-fleet/issues/4404))
- **メモの自動実行・自分のセッションの承認を省く:** カテゴリごとに、自分で起動したセッションが追加した
  メモを、承認のカードなしで受け付けられます。初期値はオフです。
  ([#4151](https://github.com/k-k1/agent-fleet/issues/4151))
- **ECS EC2 のブースト:** テナントの管理者が許可すると、メンバーは設定 →「マシン」から、
  次の起動を同じクラスの一段上のサイズに、期限付きで上げられます。月あたりの時間の予算は保存されますが、
  まだ強制されません。([#4335](https://github.com/k-k1/agent-fleet/issues/4335))
- **ECS EC2 の軽いスロットのクラス:** 読む・直す・小さなコマンドを走らせるのが主なメンバー向けに、4 GiB の
  クラス（`m8g.medium`、`t4g`、`t3`）を任意で足す方法を運用ガイドに載せました。
  ([#4332](https://github.com/k-k1/agent-fleet/issues/4332))
- **Docker Compose の egress の囲い（任意、実機の Docker ではまだ試していません）:** ワークスペースの
  ネットワークから外への経路をなくし、egress プロキシだけを出口にできます。
  ([#1181](https://github.com/k-k1/agent-fleet/issues/1181))

### アップグレードの注意

- **ECS: `update.sh` の前に `10-data` を更新してください。** `ecs-ec2` では、メンバーの EFS アクセス
  ポイントをワークスペースのタスクではなくスロットがマウントするようになり、`update.sh` は `10-data` に
  新しい出力ができるまで止まります。すべてのワークスペースを 0.47.0 で止めて起動し直したら、
  `EfsWorkspaceIngress=deny` にしてワークスペースのタスクからファイルシステムを閉じます（Fargate では
  `allow` のまま）。ECS のアップグレードガイドの「`ecs-ec2`: ワークスペースのタスクを NFS から切り離す」を
  見てください。([#3903](https://github.com/k-k1/agent-fleet/issues/3903))
- **ECS で `EgressRoute=gateway` に切り替えるとき:** まず `GatewayRouteEnabled=false` で `00-network` を
  デプロイし、`update.sh` を実行して、ゲートウェイが最初のポリシーを適用するのを待ってから `true` に
  します。手順は egress ゲートウェイのガイドにあります。
  ([#4399](https://github.com/k-k1/agent-fleet/issues/4399))
- **egress ゲートウェイを使う ECS:** 次に `00-network` をデプロイすると、費用のタグを付けるために
  ゲートウェイのインスタンスが一度だけ置き換わります（AMI の更新と同じ短い停止です）。

（ほかは 0.46.0 から変わりません）。
