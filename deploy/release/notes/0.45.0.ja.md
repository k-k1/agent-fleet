`watch` で GitHub のリリースとタグ、PR で最初に失敗したチェック、別のセッションの入力待ちや停止を
待てるようになり、ミラーにセッションの有効なウォッチが並びます。テナントの管理者はスタートの起動の
既定値とチームのリポジトリを決められ、ECS の EC2 プールには固着したスロットの検知、dark のスロットの
救出（オプトイン）、登録済みスロットの強制停止が加わりました。サインインや Git プロバイダーが別の
ホストへのリダイレクトの後ろにある場合は、アップグレードの注意を読んでください。

### 新機能

- **`watch` のソースと種類が増えました:**
  - GitHub のリリースとタグ（`github.release.published`、`github.tag.created`）。名前のパターンを
    指定でき、プレリリースも数えられます。
    ([#3970](https://github.com/k-k1/agent-fleet/issues/3970))
  - `pr.checks.failing`。ほかのチェックが動いている間に 1 つでも失敗すると、ヘッドのコミットごとに
    1 回知らせます。既存の `pr.checks.*` のウォッチにも届きます。
    ([#4054](https://github.com/k-k1/agent-fleet/issues/4054))
  - `fleet` ソース。子やピアのセッションが入力待ちになった・停止した・クォータが戻ったことを知らせる
    ので、親が保険にタイマーを置く必要がなくなります。
    ([#3969](https://github.com/k-k1/agent-fleet/issues/3969))
- **ミラーのウォッチ:** 入力欄の上のパネルにセッションの有効なウォッチが並び、そこから終了できます。
  入力待ちの状態チップには待っている件数が出て、PR のウォッチのリンクは作業項目のダイアログで
  開きます。([#3947](https://github.com/k-k1/agent-fleet/issues/3947),
  [#3951](https://github.com/k-k1/agent-fleet/issues/3951),
  [#4010](https://github.com/k-k1/agent-fleet/issues/4010))
- **テナントの起動の既定値:** テナント設定の「**メンバーの既定**」で、起動ダイアログの初期値（エージェント・
  モデル・実行方式・権限の確認・予算）、スタートで先頭に並べるチームのリポジトリ、Grafana や AWS の
  サインインのリンクなどの運用の設定を決められます。メンバーは自分の既定を持つこともでき、まだ
  クローンしていないチームのリポジトリはスタートにクローンのショートカットとして出ます。
  ([#3884](https://github.com/k-k1/agent-fleet/issues/3884),
  [#3976](https://github.com/k-k1/agent-fleet/issues/3976))
- **ターミナルから Jira の添付ファイル:** `jira issue attachment add | list | download | delete`。
  ([#3945](https://github.com/k-k1/agent-fleet/issues/3945))
- **ディスク残量が少ないときの掃除:** 残量の通知が空けられる量の見込みを示し、その場で掃除を
  始められます。`af-clean` で同じ掃除をターミナルからも行えます（`--apply` を付けない限り
  ドライランです）。([#3880](https://github.com/k-k1/agent-fleet/issues/3880),
  [#3882](https://github.com/k-k1/agent-fleet/issues/3882))
- **ECS の EC2 プール:**
  - **固着した**スロット（エージェントは応答するのにワークスペースが応答しない）も dark と同じように
    知らせます。プールの画面には、スロットが dark になってからの時間と救出の段階が出ます。
  - **救出の段階**は、設定しない限りオフです。`AF_ECS_EC2_DARK_SLOT_ACTION=rescue` は dark のスロットを
    止めて home を解放し（その home の Start は別のスロットに載ります）、`quarantine` はさらに、
    再び dark になったスロットをプールから外します。`AF_ECS_EC2_WEDGED_SLOT_ACTION=release` は固着した
    スロットの home を解放します。
  - 「**停止（強制）**」を登録済みのスロットにも、確認のチェックを付けて出します。ページを閉じても
    最後まで進みます。インスタンスの登録を解除した場合は、載っていたメンバーの次の Start が新しい
    スロットを起動し、home をそこへ移します。

  ([#3963](https://github.com/k-k1/agent-fleet/issues/3963),
  [#3964](https://github.com/k-k1/agent-fleet/issues/3964),
  [#3965](https://github.com/k-k1/agent-fleet/issues/3965),

### 改善

- **ウォッチを間違えにくくなりました。** 同じ `watch` を繰り返すと既存のものが返り、重なったウォッチの
  通知は 1 つにまとまります。ワークフローやパイプラインのウォッチは、作る 10 分ほど前に始まった実行も
  数えます。([#4051](https://github.com/k-k1/agent-fleet/issues/4051),
  [#4033](https://github.com/k-k1/agent-fleet/issues/4033))
- **Copilot・Cursor・Kiro・Antigravity のセッション**が、前のターンの終わりを新しいターンの終わりと
  取り違えなくなりました。Copilot・Cursor・Antigravity では、CLI が受け取らなかった入力は「作業中」の
  ままにならず、「入力が届かなかった」として終わります。
  ([#4007](https://github.com/k-k1/agent-fleet/issues/4007),
  [#4047](https://github.com/k-k1/agent-fleet/issues/4047))
- **クラウドのコマンド名:** `af-gcloud-exec` の実行は、実行の行とログインのカードに gcloud のコマンドを
  出します。AWS の確認カードは `aws` の操作を示し、頼んだセッションへのリンクを付けます。
  ([#4036](https://github.com/k-k1/agent-fleet/issues/4036),
  [#4034](https://github.com/k-k1/agent-fleet/issues/4034))
- **マネージドの OpenCode** でも、デプロイが提供する Bedrock のモデルルートを使えます（これまでは
  ターミナル（CLI）だけでした）。([#4004](https://github.com/k-k1/agent-fleet/issues/4004))
- **認証情報を載せた通信は元のホストから出ません。** トークンを載せた呼び出し（Jira・GitHub・Bitbucket・
  サインイン・Control Plane）は、別のホストや平文の HTTP へのリダイレクトに従わず、失敗します。
  ([#4070](https://github.com/k-k1/agent-fleet/issues/4070),
  [#3952](https://github.com/k-k1/agent-fleet/issues/3952))
- **Console のガイドへのリンクは agent-fleet.org/docs を新しいタブで開きます。** 画面の表示もガイドと
  同じ言葉にそろえました。([#3463](https://github.com/k-k1/agent-fleet/issues/3463),
  [#4039](https://github.com/k-k1/agent-fleet/issues/4039))

### アップグレードの注意

- **ID プロバイダー・Git プロバイダー・Jira が、トークンや API の呼び出しに別のホストへのリダイレクトで
  答える場合**、その呼び出しは従わずに失敗するようになりました。設定をリダイレクト先の URL に向けて
  ください。([#4070](https://github.com/k-k1/agent-fleet/issues/4070))
- **ECS の EC2 プール: 固着したスロットの報告は既定でオンです**
  （`AF_ECS_EC2_WEDGED_SLOT_ACTION=detect`）。該当するインスタンスに `af-wedged-since` のタグを付けます。
  権限は Control Plane がすでに持っているものを使います。止めるには `off` にします。上の救出の段階は
  設定するまでオフのままで、CloudFormation のテンプレートは変わっていません。
  ([#3963](https://github.com/k-k1/agent-fleet/issues/3963))
