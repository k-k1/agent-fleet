Agent memory gets its own view in the Console, and each memory opens and edits like a file. Memo
auto-run gets an Auto-run view of its runs, and queue messages can wait for one another or be
handed back. Members and tenant administrators can see a daily usage history, and Claude Code lets
you choose who resumes a session after a usage limit.

### New

- **Memory view:** an activity-bar view lists the agent memories of the project on screen, with
  search, scope and type filters and the tidy-up's pending proposals. A memory opens in a pane of
  its own where you can read, edit, pin or forget it and see its history, with the same unsaved-text
  guards as a file. ([#4567](https://github.com/k-k1/agent-fleet/issues/4567),
  [#4568](https://github.com/k-k1/agent-fleet/issues/4568),
  [#4569](https://github.com/k-k1/agent-fleet/issues/4569))
- **Auto-run view:** an activity-bar view lists memo auto-run runs by category, with the work item,
  the pull request and its state, and the sessions each run started. A row menu stops a run's
  sessions or deletes its worktree, "Clear finished runs" tidies up ended runs, and the icon is
  badged when a run waits for you or its first turn failed. Auto-run sessions leave the Sessions
  view, and scheduled sessions move under their schedule in the Schedules view.
  ([#4646](https://github.com/k-k1/agent-fleet/issues/4646),
  [#4670](https://github.com/k-k1/agent-fleet/issues/4670),
  [#4674](https://github.com/k-k1/agent-fleet/issues/4674),
  [#4727](https://github.com/k-k1/agent-fleet/issues/4727),
  [#4728](https://github.com/k-k1/agent-fleet/issues/4728))
- **Shared sessions view:** sessions shared with you get their own activity-bar view, badged while
  a handoff is offered to you. ([#4645](https://github.com/k-k1/agent-fleet/issues/4645))
- **Memo auto-run, order and hand-back:** a queue message can wait until others of its queue have
  run cleanly and their pull requests have merged. A run can hand its message back to the queue for
  later, and you can return a run to the queue yourself.
  ([#4540](https://github.com/k-k1/agent-fleet/issues/4540),
  [#4541](https://github.com/k-k1/agent-fleet/issues/4541))
- **Memo auto-run, follow-ups:** releasing a memo also approves a bounded number of follow-up memos
  its run adds (4 by default, set per category), shown as "Follow-up K of M" with a Stop chain
  button. ([#4606](https://github.com/k-k1/agent-fleet/issues/4606))
- **Memo auto-run, end a run:** an open run can be ended from its history row, which stops its
  sessions and frees its slot without archiving them.
  ([#4515](https://github.com/k-k1/agent-fleet/issues/4515))
- **Usage history:** under the running-time grid, a member sees a daily table of CPU, memory and
  pressure readings for their workspace, and a tenant administrator sees the same for every member
  and the tenant as a whole. ([#4414](https://github.com/k-k1/agent-fleet/issues/4414),
  [#4493](https://github.com/k-k1/agent-fleet/issues/4493))
- **Claude usage-limit resume:** Settings → Agents → Claude Code chooses **Resume with AF**
  (default; the workspace may stop and wake for it), **Continue with Claude** (Claude Code's own
  wait) or **Off**. ([#1422](https://github.com/k-k1/agent-fleet/issues/1422))
- **Codex launch defaults:** a new preference, "Remember Codex's own model and reasoning level",
  can be turned off so a model picked in a Terminal codex no longer carries into new sessions left
  on Default. ([#4590](https://github.com/k-k1/agent-fleet/issues/4590))
- **Fleet Operator:** it can read memo auto-run categories and their run history, and tells you
  which Console control to press to change them. ([#4626](https://github.com/k-k1/agent-fleet/issues/4626))
