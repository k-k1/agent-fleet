### New

- **画像エンジンの箱を「提案（offer）の一覧」から選びます。** そのうち 1 つを Spot に
  できます。`params/60-engines` の `ImageOffers` に買ってよいものを順に並べると、上から
  試し、箱が来なければ次へ落ちます——Spot の在庫が無い日でもエンジンは起動します。
  何も書かなければ、これまでどおり全部オンデマンドです。llm 役に Spot の行はあえて
  用意していません——会話の途中で終了予告が来ると、コールドスタートをやり直すことになる
  ためです。
- **設定 > エンジンに、提案の一覧・いま走っている提案・今回試した順が出ます。** クラスを
  選ぶとその提案に固定され、「自動」に戻すとまた上から落ちるようになります。
- **推論エンジンの画面を「推論エンジン」と「推論エンジンのモデル」に分けました。** 前者は
  モード・状態・GPU の段・稼働実績、後者はカタログ・取り込み・上流の検索です。モデル側は
  役割（文章 / 画像）と モデル / LoRA のタブで分かれ、LoRA は学習元のファミリーが行の頭に
  出ます。テナント設定の「推論エンジンのモデル」も同じ画面です。
- **モデルを探すとき、取り込む前に「できないこと」が出ます。** Civitai の「ログイン済み
  アカウントにしか配らない」ファイル（上位 20 件のうち 13 件がそうでした）・商用不可・要
  クレジット表記・有料 / 早期アクセス・NSFW・スキャン警告、Hugging Face の gated は「規約に
  同意」と「作者の承認待ち」の別まで。LoRA を探すときは LoRA だけが並びます。
- **ファミリーと推奨パラメータが埋まった状態で取り込めます。** 上流の「SDXL 1.0」
  「Illustrious」などからこの配備のファミリーを推定して選び、作者が書いている Steps / CFG /
  サンプラーを**その一文の引用つきで**フォームに入れます。値はモデルの行に保存され、生成の
  ときにファミリーの既定へ欄ごとに上書きされます（空欄は既定のまま）。推定できないときは
  空のままにします。

### Upgrade notes

- **`ImageCapacityOptionType` は撤去しました。**これまで設定していない配備は何もせずに
  更新できます（capacity provider が 1 本増えるだけで、挙動は変わりません）。
  🔴 **いま `ImageCapacityOptionType=SPOT` で走っている配備は、先に `ON_DEMAND` へ戻す更新を
  現行の版で流してから**この版を取り込んでください——新しい Spot の provider が、古い provider が
  持っている名前を要求するので、飛ばすと同名衝突で失敗しロールバックします。そのあと
  `params/60-engines` からこの行を消します。
- Spot は `ImageOffers` に `spot` の行を書いたときだけ使われます。書く前に、Spot を一度も
  使っていないアカウントなら service-linked role（`AWSServiceRoleForEC2Spot`）を作り、Spot の
  クォータ（`L-3819A6DF`・既定は 0）を確かめ、その行に複数のインスタンス型を並べてください
  ——1 型だけでは在庫不足で断られました。書式は
  `deploy/aws/ecs/cfn/PARAMETERS-60-engines.md`「The offers」にあります。
- これまで GPU クラスの梯子が無かった配備で初めて提案を宣言するときは、一覧を効かせるために
  Control Plane の再起動（`update-service --force-new-deployment`）が 1 回要ります。
