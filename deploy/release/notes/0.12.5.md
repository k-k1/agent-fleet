On `ecs-ec2` deployments, a workspace whose machine had failed could not be started
again. Agent Fleet now moves it to a healthy machine on its own.

### Fixed

- **A workspace could get stuck with every start attempt timing out** (a `504` in the
  Console, indefinitely) on `ecs-ec2`. This happened when the machine hosting the
  workspace stopped responding while still appearing healthy to AWS — starting the
  workspace waited for a machine that was never coming back, and no amount of retrying
  helped. Agent Fleet now gives up on such a machine after a few minutes, takes it out
  of service with the reason recorded on it, and starts the workspace on another one.
  The home disk is moved across intact, and the person does not have to press start
  again. If no healthy machine can be found either, the workspace returns to `stopped`
  so it can be retried, rather than hanging.
