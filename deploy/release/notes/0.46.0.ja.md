テナントの管理者が許可すると、メモのカテゴリにたまった実行待ちのメモを、ボタン一つで、または決めた
上限の中で自動で、セッションとして実行できるようになりました。エージェントの再認証は新しいサインインが
終わるまで今のログインを保ち、ECS の EC2 プールで隔離されたスロットを Console から戻せます。ECS では
`update.sh` の前に `10-data` の更新が要るので、アップグレードの注意を先に読んでください。

### 新機能

- **メモの自動実行:** メモのカテゴリに指示・エージェント・上限を設定すると、実行待ちのメモがセッション
  として実行されます。「今すぐ実行」で始めるほか、いつでも、決めた時間帯に、または決めた件数がたまったら
  自動で始められます。セッションが追加したメモはあなたの承認を待ち、カテゴリごとに実行履歴、一時停止と
  再開、通知があります。テナントの管理者がテナント設定 →「運用」→「メモの自動実行」で許可するまでは
  ブロックされています。
  ([#4148](https://github.com/k-k1/agent-fleet/issues/4148),
  [#4149](https://github.com/k-k1/agent-fleet/issues/4149))
- **隔離された ECS の EC2 スロットを Console から戻せます:** プールから外されたスロットを、タグを手で
  消さずにプールの画面から戻せます。
  ([#4019](https://github.com/k-k1/agent-fleet/issues/4019))
- **「未配信」のチップ:** 入力が CLI に届かなかったセッションは、セッションの一覧とペインの見出しにそう
  表示されるので、送り直すべきだと分かります。
  ([#4222](https://github.com/k-k1/agent-fleet/issues/4222))

### アップグレードの注意

- **ECS: 内部の Git リポジトリは専用のファイルシステムに移ります。** 0.45.x までは Control Plane の
  タスク自身のディスクにあり、タスクが入れ替わるたびに失われていました。`update.sh` の前に、まだ読める
  リポジトリを写し出して `10-data` を更新してください。手順は ECS のアップグレードのガイドの
  「Control Plane のデータルート」にあります。`10-data` を更新するまで `update.sh` は止まります。
  ([#4089](https://github.com/k-k1/agent-fleet/issues/4089))
- **メモの自動実行は、テナントの管理者が許可するまでブロックされています。** すべての Control Plane と
  Console が 0.46.0 になってから許可してください。自動で始まる実行を使うメンバーは、ワークスペースを
  再起動してください。
- **ECS で `EgressRoute=gateway` を使っている場合:** ゲートウェイの修正は `00-network` にあり、
  `update.sh` はこれをデプロイしません。今のパラメーターのまま、変更セットで `00-network` を更新して
  ください。

エージェント CLI のピン: Claude Code 2.1.325、Copilot 1.0.112、Antigravity 1.5.9、Kiro 3.3.0、Muse
1.4.20-R8619.1（ほかは 0.45.0 から変わらず）。
