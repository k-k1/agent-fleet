# 新機能・修正の索引

公開済みの全リリースを新しい順に並べ、新機能と修正を 1 項目 1 行で載せた索引です。
版ごとのノートが答えるのは「この版に自分に関係するものがあるか」で、この索引が答えるのは
「あの機能はいつ入ったか」「あれを直したのはどの版か」です。30 個のファイルを開かずに済みます。

各行の頭には、それがどの面の話かを **[プレビュー]**・**[ecs-ec2]**・**[ミラー]** のように
付けています。1 行に畳むと「どの機能に対する修正なのか」が見えなくなるためです。

更新のしかた:

- 新しい版の節を**publish の作業の一部として**先頭に足します（手順は [README.md](README.md)）。
  台帳に行があるのにここに節が無いと `release-gate` が落ちます。日本語版のこのファイルも
  英語版（[SUMMARY.md](SUMMARY.md)＝正）と一緒に更新します。
- 1 項目 1 行。その版のノートから畳みます。Upgrade notes はノート側に残し、ここには入れません。
- **CLI ピン**の行は、その版で**動いたものだけ**を並べます（行が無い＝動いていない）。値は
  準備中のノートではなく**ビルド元 commit** から取ります。ノートを書いてから publish まで
  の間にピンが上がることがあるためです:
  `git show <build-commit>:workspace/Dockerfile | grep -E '^ARG (CLAUDE_CODE|OPENCODE|CODEX|COPILOT|AGY|CURSOR|KIRO|RTK)_VERSION='`
  を前の版のビルド元 commit と差分します。
- 載せるのは [index.tsv](index.tsv) にある版だけです。用意したものの publish しなかった版の
  ノートも残っています（0.8.1・0.12.5）。何が出たかを決めるのはファイルの有無ではなく台帳です。

- **[エンジン]** 取り込み画面から Hugging Face と Civitai を検索。各行にライセンス・サイズ・コンテキスト長

- **[エンジン]** Hugging Face のトークンを Console から登録。gated のリポジトリ（SD3.5・FLUX.1）に CloudFormation の実行が要らなくなった
- **[エンジン]** エンジンが買う GPU のクラスを Console から選ぶ（運用者が宣言した段の梯子から。`LlmInstanceClasses` / `ImageInstanceClasses`）
- **[エンジン]** 起動時は要求されたモデルだけを載せ残りは背後で同期。モデルの入れ替えも速くなった
- **[画像生成]** 配備自身の ComfyUI を provider に追加（SDXL・SD3.5・FLUX.1・FLUX.2 klein・Z-Image。`ImageEngine=comfy`）。要求でモデルを名指しでき、いま載っているモデルも分かる
- **[メモ]** カテゴリ見出しの ＋ からそのカテゴリへ直接追加（下書きとアップロード済み画像は持ち越す）

**Fixed**

- **[ミラー]** 後ろで何か動くと生成した画像が会話に出ない（カードが畳まれた「作業過程」に落ちていた）
- **[エージェント]** opencode の起動メニューに既定のモデルしか出ず、接続とプランのせいにされる
- **[セッション]** 「終わったら停止」が、背景で動いているコマンドを残したまま停止する
- **[メモ]** セッションに「メモに追加して」と頼むと、メモキューでなくエージェント自身の記憶に書かれることがあった
