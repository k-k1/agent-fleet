スケジュールが、保存した作業項目クエリに新しい結果が出たときだけセッションを起動できるようになり、
チャットのスレッドから `!start` と `!attach` で新しいセッションを始めたり、別のセッションへ移したり
できます。Bitbucket Pipelines の実行も GitHub Actions と同じように待て、設定 › マシン からビルド成果物・
使われていない Gradle のバージョン・古い `~/.af-work` のフォルダを片付けられます。Muse Code 自身の
メモリも、Claude Code と同じように履歴を取って取り込みます。ECS のテンプレートやデプロイが提供する
Bedrock ルートを使っている場合は、アップグレードの注意を読んでください。

### 新機能

- **ゲート付きのスケジュール:** 毎回新しいセッションを起動する繰り返しのスケジュールを、保存した
  作業項目クエリに前回の発火から変わった一致があるときだけ動かせます（スケジュールの「**詳細・編集**」の
  「**ゲート**」、または `create_schedule` / `update_schedule` の `gate` 引数）。1 日の発火回数と発火の
  間隔には上限があり、「**今すぐ実行**」はゲートを通しません。
  ([#1763](https://github.com/k-k1/agent-fleet/issues/1763),
  [#3809](https://github.com/k-k1/agent-fleet/issues/3809))
- **チャットからセッションを始める・移す:** セッションの Discord や Slack のスレッドで、
  `!start <プロンプト>` はそのスレッドのセッションと同じ設定で新しいセッションを始め、
  `!attach <セッション>` はスレッドを別のセッションに結び付けます。
  ([#1566](https://github.com/k-k1/agent-fleet/issues/1566))
- **`watch` で Bitbucket Pipelines の実行**とパイプラインの次の実行を待てます。種類は GitHub Actions と
  共通の `ci.run.completed` / `ci.run.failed` です（従来の `github.workflow_run.*` も使えます）。
  Bitbucket の接続に Pipelines を読む権限が必要です。
  ([#3875](https://github.com/k-k1/agent-fleet/issues/3875))
- **設定 › マシン でのディスクの片付け:**
  - 「**動いていない作業コピーのビルド成果物**」は、30 日誰も触っていない作業コピーから
    `node_modules`・`.next`・`target`・`.gradle` を、確認とプレビューを経てから消します。
  - 「**~/.af-work の古いフォルダ**」は、自分で作ったフォルダのうち指定した日数変更のないものを並べ、
    チェックしたものを消します。
  - 「**ツールのキャッシュ**」に、`~/repos` の下のどの `gradle-wrapper.properties` も使っていない
    Gradle のバージョンの行が 2 つ増えました。

  どれも自動では動かず、消したものは元に戻せません。
  ([#3800](https://github.com/k-k1/agent-fleet/issues/3800),
  [#3881](https://github.com/k-k1/agent-fleet/issues/3881),
  [#3202](https://github.com/k-k1/agent-fleet/issues/3202))
- **Muse Code 自身のメモリ**も、Claude Code や Codex と同じくメモリのスナップショットに残り、戻せます。
  エージェントメモリのスイッチをオンにすると、Muse のプロジェクトのメモも取り込みます。
  ([#3860](https://github.com/k-k1/agent-fleet/issues/3860),
  [#3858](https://github.com/k-k1/agent-fleet/issues/3858))
- **メモリの自動整理が、終わった作業のメモリの退役を提案できます。** 課題やプルリクエストの状態は
  GitHub の接続で確かめます。退役したメモリは削除せずにアーカイブし、元に戻せます。
  ([#3788](https://github.com/k-k1/agent-fleet/issues/3788))
- **lint の自動マーク**（設定 › エージェントメモリ、既定はオフ）で、ワークスペース がアイドルの間に
  `af-memory lint --apply` がひとりでに動きます。
  ([#3767](https://github.com/k-k1/agent-fleet/issues/3767))
- **文字のコントラスト**（設定 › 表示: 標準・強め・最強）で、このブラウザの Console 全体の文字を
  はっきりさせます。([#3786](https://github.com/k-k1/agent-fleet/issues/3786))
- **ECS の EC2 プール:** home を持ったまま ECS と SSM のエージェントがどちらも応答しないスロットを、
  Control Plane が `pool.slot_dark_detected` の監査記録 1 件と、インスタンスの `af-dark-since` タグで
  知らせます。知らせるだけで、止めたり移したりはしません。
  ([#2450](https://github.com/k-k1/agent-fleet/issues/2450))

### アップグレードの注意

- **デプロイが提供する Bedrock ルートを一度でもオンにした場合**（`AF_PROVIDED_ROUTES=1`）: ルート発行用の
  トークン `AF_ROUTE_ISSUE_TOKEN` は秘密情報の経路でワークスペースに渡るようになりましたが、オンの間に
  登録したタスク定義のリビジョン（ECS）には、古い値が平文の `environment` に残っています。Control Plane と
  すべてのワークスペースが 0.44.0 になってから、1 人なら `POST /api/admin/rotate-bridge-tokens`、全員なら
  `af-cp advance-bridge-epochs`（件数の確認だけ）に続けて `af-cp advance-bridge-epochs --yes` で無効に
  します。**`--yes` を実行すると、動作中のすべてのワークスペースのトークンがその場で無効になります。**
  静かな時間帯に行い、すぐにワークスペースを再起動してください。古いリビジョンは必要に応じて登録解除します。
  ([#3452](https://github.com/k-k1/agent-fleet/issues/3452))
- **ECS: `30-ingress` を S3 経由でデプロイできるようになりました。今回の更新では使いません。**
  テンプレートはインラインの上限（51,200 バイト）を超えてよくなりましたが、0.44.0 ではまだ上限より
  小さいため、`update.sh` はこれまでどおりインラインでデプロイし、上限を超えたときだけ自動で 20-platform の
  `CfnTemplatesBucket` を使います。`cfn/30-ingress.yaml` を手で `aws cloudformation deploy` するときは
  `--s3-bucket "$CFN_BUCKET" --s3-prefix cfn` を付けてください。`CFN_BUCKET` は 20-platform の出力
  `CfnTemplatesBucket` から取ります。実行する人には、そのバケットのオブジェクト（`arn:aws:s3:::<bucket>/*`）
  への `s3:PutObject` と `s3:GetObject` が必要です。このリリースで変わった CloudFormation のテンプレートは
  ありません。新しいパラメータや IAM はなく、ingress のスタックはタスク定義の新しいリビジョンだけでその場で
  更新されます（ロードバランサー・リスナー・ターゲットグループには触りません）。
  ([#3550](https://github.com/k-k1/agent-fleet/issues/3550))
- **ECS: `update.sh` は `50-tts` や `60-engines` が失敗しても続けます。** 30-ingress までデプロイし、
  最後にスタック名を挙げた `FAILED:` の行を出して、0 以外で終わります。スタックを直して、もう一度
  実行してください。([#3555](https://github.com/k-k1/agent-fleet/issues/3555))
- **ECS の EC2 プール: 応答しないスロットの報告は既定でオンです**
  （`AF_ECS_EC2_DARK_SLOT_ACTION=detect`）。該当するインスタンスに `af-dark-since` のタグを付けます。
  タグ付けの権限は Control Plane がすでに持っているものを使います。止めるには `off` にします。
  ([#2450](https://github.com/k-k1/agent-fleet/issues/2450))
- **新しい片付けとメモリの機能については作業不要です。どれもひとりでには動きません。** 「~/.af-work の古い
  フォルダ」に並ぶのは、メンバーが自分で作ったフォルダ（セッションのフォルダは、アーカイブしたものも含めて
  並びません）のうち、どのプロセスも使っておらず、指定した日数変更のないものだけで、消えるのはメンバーが
  チェックして確認したものだけです。lint の自動マークは既定でオフで、退役の提案はメンバーがオンにした
  メモリの自動整理からだけ出ます。([#3881](https://github.com/k-k1/agent-fleet/issues/3881))
