The workspace image is now published for arm64 as well as amd64, so an `ecs-ec2` deployment
can run Graviton slots on the official images. The code is identical to 0.15.0.

### Improved

- **The published workspace image covers arm64.** An `ecs-ec2` deployment can declare a
  Graviton slot class and run it on the image from this release; until now an operator had to
  build that image themselves. The control-plane image has covered both architectures since
  0.11.0.

### Upgrade notes

**To offer Graviton slots**, set the pool stack's `SlotAmiIdArm64` to the arm64
ECS-optimized AMI, then add a class with `arch=arm64` to `Ec2SlotTypes` and pass the same AMI
as `Ec2SlotAmiArm64` — the control plane refuses to start when an arm64 class is declared
without it. Adding a class moves nobody: `Ec2DefaultSlotClass` still decides where a member
with no choice of their own lands. A member who does move reinstalls their home's
architecture-dependent tools on the next start, which costs them one slow start.

Coming from 0.14.x, the Python 3.11 → 3.13 note in 0.15.0 applies to this release too.

Agent CLI pins are unchanged from 0.15.0.
