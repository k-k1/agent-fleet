A Terminal (CLI) claude session can run on an Anthropic API key, and one that stops at its
subscription usage window can carry on there instead of waiting. Sessions can be told about their
pull request's CI failures and review feedback, the AWS egress gateway can pass SSH git and
database traffic to named destinations, and ecs-ec2 slots follow Amazon's AMI updates without a
stack deploy.

### New

- **Claude on an Anthropic API key.** Under **Model route** in the launch dialog, a Terminal claude
  session can run on the Anthropic API key saved on the OpenCode card (billed per use) instead of
  this workspace's claude.ai login. A session with no route behaves as before.
  ([#3281](https://github.com/k-k1/agent-fleet/issues/3281),
  [#3344](https://github.com/k-k1/agent-fleet/issues/3344),
  [#3317](https://github.com/k-k1/agent-fleet/issues/3317))
- **Continue on the API route at a usage window.** A claude session started on the subscription
  route that stops at its usage window offers **Continue on the API route**, after a confirmation
  of what it costs. The switch is one-way.
  ([#3283](https://github.com/k-k1/agent-fleet/issues/3283))
- **Sessions hear about their pull request's feedback.** With **Settings › Agents › Session ›
  Tell sessions about their PR's feedback** on, a session is told when CI fails on its PR or a
  reviewer asks for changes, and is started first if it was stopped. It is off by default.
  ([#3129](https://github.com/k-k1/agent-fleet/issues/3129))
- **SSH git and databases through the AWS egress gateway.** An administrator can name a
  destination and port as a **TCP port** entry in Admin › Egress (members can propose one); in
  enforce, other non-HTTP traffic is dropped and recorded. See Upgrade notes.
  ([#3369](https://github.com/k-k1/agent-fleet/issues/3369),
  [#3399](https://github.com/k-k1/agent-fleet/issues/3399))
- **Amazon Corretto JDKs.** Settings › Toolchains offers Corretto beside Temurin for each Java
  major, and the two can be installed side by side.
  ([#3411](https://github.com/k-k1/agent-fleet/issues/3411))

### Improved

- **ecs-ec2 slots follow Amazon's AMI updates by themselves.** The Control Plane reads the current
  ECS-optimized AMI about hourly and launches slots with it; a slot on an older AMI is replaced at
  its next start, and the Slots tab says why a slot is outdated.
  ([#3318](https://github.com/k-k1/agent-fleet/issues/3318))
- **Cloud command runs fold into the tool call that ran them** in the conversation, with repeats
  collapsed into one line with a count, and `af-gcloud-exec` runs are recorded like `af-aws-exec`'s.
  ([#3329](https://github.com/k-k1/agent-fleet/issues/3329))
- **Range presets:** Running time, Cloud cost and the uptime heatmap have **This month**, **Last month**
  and **Last 30 days**. ([#3383](https://github.com/k-k1/agent-fleet/issues/3383))
- **Issue and pull request URLs** in a conversation, chat or document open the work item modal,
  as `#N` references already did. ([#3365](https://github.com/k-k1/agent-fleet/issues/3365))
- **Egress enforce keeps the workspace's own installs working:** the download hosts of Settings ›
  Toolchains and of the agent CLIs are allowed by default (`storage.googleapis.com` is still yours
  to add, for Antigravity and Chromium on x64).
  ([#3432](https://github.com/k-k1/agent-fleet/issues/3432))
- **Settings › Agents opens faster**, and the repository list polls less while the Console is
  unattended. ([#3385](https://github.com/k-k1/agent-fleet/issues/3385),
  [#3333](https://github.com/k-k1/agent-fleet/issues/3333))

### Upgrade notes

- **ECS deployments:** run `update.sh` as usual. It deploys `20-platform`, which gives the Control
  Plane the read of Amazon's AMI parameters; until then slots keep the AMI from the stack. The first
  new AMI after the upgrade makes every slot outdated at once, and each is replaced at its next
  start. ([#3318](https://github.com/k-k1/agent-fleet/issues/3318))
- **AWS egress gateway, for `tcp:` entries only:** deploy `00-network` by hand (`update.sh` never
  does). This replaces the gateway instance, so workspaces are without egress for a few minutes.
  Before switching to enforce, have each destination's firewall admit the gateway's egress address.
  The ECS README, "Egress gateway", has the details.
  ([#3369](https://github.com/k-k1/agent-fleet/issues/3369))
