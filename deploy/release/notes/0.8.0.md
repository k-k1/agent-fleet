A session's conversation can now be shown to another member of your tenant, a new
session can branch from any past message with the conversation copied as-is, the main
area lays out as a tabbed grid as well as split panes, and sessions can send each other
a one-line message without going through you.

### New

- **Share a conversation with another member (shared sessions).** "Keep an eye on
  where this investigation goes", "while you review it, here is how we got here" —
  a session's conversation can be opened, read-only, by another member of the same
  tenant. Share from the **⋯** menu of a session or repository row, choosing one of
  three targets: a single **session**, a single **worktree**, or the whole **project**
  (the base working copy plus the sessions in the worktrees under it — usually what
  you want when each session gets its own worktree). Pick the recipient by searching
  their email address, and the permission: **view only**, or **may propose**, where the
  recipient can compose something for the agent that **does not reach it until you
  approve**. Shared conversations appear in the recipient's left pane under *Shared
  sessions*, grouped by owner and project, with the same rendering as your own mirror —
  state badges, inline Edit/Write diffs, a "jump to latest" pill — and a colour you can
  set separately in Settings › Display, so the pane you are reading someone else's work
  in doesn't look like your own. **Sharing exposes the whole conversation**: your
  prompts, the agent's replies and tool output. Secrets that ended up in it are not
  detected for you, and unsharing cannot recall a copy the recipient already saved.
- **Messages between sessions.** A session can send one short message to another
  session in the same workspace — "I just rebased develop, pull `api.ts` before you
  carry on", or the answer to a question the other one was blocked on. Turn it on in
  Settings › Agents › Session; it is **off by default** and applies to sessions
  started from then on. Unlike the equivalent built into Claude Code (which stays
  disabled here — enabling it would switch Claude's usage telemetry back on),
  messages cross agent kinds: claude to codex, opencode to cursor, and every other
  pairing among claude / codex / opencode / cursor / kiro / agy / copilot. A message
  also reaches a **stopped** session, which is resumed to receive it, and delivery is
  confirmed rather than fired and forgotten.

  What a message is not: it carries plain text only — no conversation history, no
  files — so passing the context itself is still a handoff or a branch. The receiving
  agent is told the message did not come from you, and cannot treat it as your
  approval for a permission prompt or as a reason to edit its configuration; commands
  written in the body arrive as inert text. Raw shell sessions (shell / ssm) can
  neither send nor receive, since text sent to them would run verbatim. Each message
  is badged in the chat view with the session that sent it, so it never blends into
  what you typed.
- **Branch from a past message.** Hovering one of your own past messages offers
  **"Branch here"**, which starts a **new session** carrying the conversation up to
  that point — the current session is left exactly as it is. Two modes: **redo this
  message** leaves the message out and puts your original wording back in the composer
  as a draft, and **continue after it** carries the message and its reply over. Use it
  when the exact wording matters and a summarising handoff would lose it. Supported on
  claude, codex, opencode and GitHub Copilot sessions (codex and opencode in managed
  execution only, since a CLI launch has no way to pass a branch point).
- **Tabbed grid layout.** The main area can now switch each cell by **tab** instead of
  splitting it — pick it from the **Appearance** popover in the top bar, or under
  Settings › Display › *Main area layout*. Tabs can be
  reordered by dragging, dropped on a cell edge to split it, scrolled horizontally when
  they overflow, and shrink to a minimum width rather than pushing each other out. Each
  session tab carries a **state badge**, so you can tell which one is working and which
  is waiting for you before selecting it. The choice is stored per device, and the two
  layouts are remembered separately, so moving between them disturbs neither.
- **Your own standing instructions for every agent.** Settings › *Agent instructions*
  adds what you write to every agent started in this workspace from then on — the
  language reports should be in, when you want to be asked first, which tools to
  prefer. It sits between the fleet-wide workspace guide (your operator's, and it wins
  on a conflict) and a repository's committed `CLAUDE.md` / `AGENTS.md`, is never
  committed anywhere, and reaches claude, codex, opencode, GitHub Copilot, agy and
  Kiro. Cursor is the only kind that cannot take it and says so with the reason. Each
  row shows the file it was written to and whether it is actually in effect.
- **See the MCP servers a repository commits.** *Project settings*, from a repository
  row's menu, lists the MCP definitions checked into the repo (`.mcp.json` and its
  per-agent equivalents) with per-agent status and warnings — a secret already under
  Git, a name clash, files that disagree with one another. You can **copy** an entry to
  another agent's file (dialect conversion, conflict handling and a preview before it
  is written, with values maskable) and **add a file to Git's ignore list** when it
  should not have been committed.
- **The browser pane works with touch.** On a tablet, swipe to scroll with momentum,
  tap to click, press and hold to drag, and pinch to zoom — a pinch re-lays the page
  out at a narrower width instead of stretching the picture, so text stays legible, and
  **double-tap** switches between fit-to-width and life size. A tap deliberately does
  not raise the keyboard (it would appear on every link press); the keyboard button at
  the bottom left of the pane does.
- **Switch tabs inside a page an agent handed you.** When an agent's script drives
  several Chromium tabs, the attached pane can now be pointed at another tab
  (*Retarget*) instead of closing it and asking the agent for a fresh link.
- **What you did in a handed-over page reaches the session.** Completing or cancelling
  a browser hand-off used to update only the Console, so the agent that asked for it
  sat there as if nothing had happened; the result is now delivered into the
  conversation (resuming the session if it had stopped), and a result written just
  before an agent restart is swept up and delivered at start.
- **Codex screenshots show in the mirror.** Images Codex captures with `view_image`
  are rendered in the conversation instead of appearing as a path you cannot see.
- **Sakana AI as an OpenCode provider preset.** Settings › Agents › OpenCode offers it
  alongside OpenCode Go, Anthropic, OpenAI, OpenRouter and Gemini (`SAKANA_API_KEY`,
  Fugu / Fugu Ultra).
- **Archive a repository's stopped sessions in one action.** Right-click a repository
  row in the left pane: AI sessions are archived and shell / SSM ones deleted, the same
  split the cleanup modal's first stage makes. It covers the sessions directly in that
  folder — a worktree is its own folder and is not swept up with the parent.
- **Markdown code blocks wrap by default.** The per-block toggle was the only way to
  wrap a long line and it did not persist; wrapping is now a setting (Settings ›
  Display), on by default.

### Improved

- **Reading a shared conversation got much faster.** The history view no longer
  re-syncs the whole inventory on every poll, and its responses are compressed —
  authorisation is still checked on every request.
- **The assistant can be turned off outright.** Settings › Assistant gains *off* as a
  fourth choice next to the plan selector: a hard lock that keeps overriding even if an
  API key or an OAuth sign-in shows up later, which the "effectively off while
  disconnected" default could not promise.
- **A message between sessions can be 16 KiB** (was 4 KiB), enough to carry a stack
  trace or a diff excerpt.
- **Running several control-plane replicas is safe under contention.** Workspace
  lifecycle operations are fenced with an advisory lock and a lease, so a replica that
  lost its lease can no longer act on a runtime another one owns; workspace activity is
  shared between replicas, the idle-stop reaper joins the same fence and re-checks
  idleness after waiting, and an orphaned idle-stop intent is reclaimed on the next
  Start.
- **Untracked files in the change list open the file view** when clicked, like tracked
  ones.
- **Confirmation dialogs focus the confirm button**, so stop and delete can be
  confirmed from the keyboard without tabbing to it.
- **The built-in Agent Fleet MCP server takes a fresh name each launch.** A repository
  that committed a server called `af` could take its place on every agent kind but
  claude, silently killing self-reporting, handoff proposals and the Chromium hand-off
  for sessions in that repository. Tool names are unchanged; only the configuration key
  moves.
- **The member guide gained a settings chapter and a much larger troubleshooting
  chapter**, covering every tab of the settings dialog, the badge and menu tables, the
  editor, git and the operator view. The distribution README follows the current
  feature set.
- Pinned CLI versions: Claude Code 2.1.231, Codex 0.147.0, OpenCode 1.18.18, GitHub
  Copilot 1.0.79, Antigravity 1.1.12, Cursor 2026.08.11, Kiro 2.18.0, rtk 0.45.0.
  Supporting tools: gh 2.97.0, Go 1.26.5, AWS CLI 2.36.22, mcp-grafana 1.1.0,
  CloudWatch MCP 0.1.8, and a Chromium security build (the previous pin was withdrawn
  from the archive, which broke workspace image builds).

### Fixed

- **Every click, key and scroll in a handed-over browser page was thrown away.** An
  attachment starts in view-only, and the pane sent input that the agent silently
  rejected — a live picture in which nothing you did had any effect and no error said
  why. Handing a page over now puts it in your control as intended. In the same area:
  the hand-off link could point nowhere, a fixed debugging port could attach you to
  another session's browser (it now takes any free port and verifies the browser's
  identity), fit-to-width did nothing, dragging and copy/paste did not work, a
  background tab produced no frames until it was brought forward, the first screencast
  frame could be lost to a race, and an unopened link expired after 10 minutes rather
  than 30 (now adjustable).
- **A terminal from the previously selected tab kept showing.** With one component per
  cell, switching tabs reused the container and the old session's terminal stayed
  painted over the new one.
- **A pane popped out into its own browser tab leaked its WebGL context**, so opening
  and closing several eventually broke rendering.
- **Codex answered the wrong question in a multi-question prompt.** Answers to the
  other questions were pasted into the free-input field of the first.
- **Sending an image with a caption to Codex left the composer stuck** "waiting to
  appear" — the closing marker was not stripped from the caption. A turn where you sent
  only an image also stopped disappearing from the transcript afterwards.
- **Pressing send twice in quick succession wedged the composer.** The duplicate
  submission raced and left the turn permanently "waiting to appear".
- **Only the last handoff proposal survived.** An agent that proposed more than one had
  the earlier ones overwritten.
- **A session running a slash command was reported as idle.** The spinner check missed
  the form the CLI uses for slash commands, so the session looked finished while it was
  still working.
- **The state badge read "waiting for permission" during a plan approval or a
  multiple-choice question**, because the badge trusted a transient state instead of
  the payload.
- **Comments on a plan that never got delivered were still marked sent.**
- **The assistant fell back to OpenCode's free tier while nothing was connected.** The
  chat backend only checked whether the binary existed, so a workspace with no
  credentials at all quietly used a free model — not acceptable under some tenants'
  policies. It now uses the same connected check that gates interactive sessions.
- **The share list showed only old archives.** Sharing a repository covered just the
  sessions directly under the base working copy, and archived sessions were listed,
  so the recipient could open a share and find nothing current in it. A repository
  share now means the whole project, archived sessions are hidden, worktrees are
  identified by branch name, and the tree can be collapsed.
- **A model ID that was an exact match could be judged ambiguous** when another ID had
  it as a prefix; Claude model IDs containing square brackets are accepted.
- **Codex's per-thread configuration merges rather than replaces.** Project-scoped MCP
  servers were therefore reported wrongly for Codex sessions.
- **The lightweight preview failed to resolve the tenant** on sub-requests, so pages
  that fetched anything came up broken.
- **Front matter that is not valid YAML** is read line by line as `key: value` instead
  of being dropped.
- Display fixes: quoted Markdown was too dim to read in dark mode, the pop-out and
  close buttons sat in the tab strip instead of the view header, the buttons at the top
  right of a mirror floated toward the middle in a tabbed grid, the status chip and
  work plan were stranded mid-row in the assistant chat header, and the Appearance
  popover wrapped its eleven colour swatches onto a second row, which hid where one
  surface's row ended and the next began.

### Upgrade notes

Nothing to migrate — the new tables for shared sessions are applied at start. Sharing
does nothing until you create a share, and messages between sessions stay off until you
turn them on in Settings › Agents › Session (both apply to sessions started afterwards).
Markdown code blocks now wrap by default; turn it off in Settings › Display if you
preferred the horizontal scroll. Agent instructions start empty. Compose deployments
pull the new images as usual and native installs update with the one-liner; workspaces
need a Stop → Start to pick up the newly pinned agent CLIs.
