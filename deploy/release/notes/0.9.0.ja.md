ログインが Google 固定でなくなりました。任意の OpenID Connect プロバイダと GitHub を
有効にでき、1 つのデプロイを部署（テナント）へ分けて、部署ごとにログイン画面・名簿・
接続を許す場所を持たせられます。AWS には、各自の home が停止をまたいで残るランタイムが
増え、その隣にメンバーごとのクラウド費用（実費）が並びます。Console では `.drawio` が
図として開き、セッションが直したファイルの一覧が出て、会話の一節にマーカーを引いて
共有先へ届けられるようになりました。

### 新機能

- **Google 以外の OpenID Connect プロバイダ、および GitHub でログインできます。** これまで
  入口は Google サインインだけで、Microsoft 365 で運用している会社は設置できませんでした。
  任意の OIDC プロバイダ — Entra ID / Okta / Keycloak / Auth0 / Cognito / GitLab — を
  `AF_OIDC_PROVIDERS` に並べ、issuer・クライアント ID・シークレットを与えれば有効になり、
  ログイン画面には有効なプロバイダの数だけボタンが、付けた名前で並びます。GitHub も使えます
  （ユーザーログイン用の OIDC が存在しないため専用の入口で、指定した組織のメンバーであることを
  必須にします。組織の指定が無ければプロバイダごと無効になります）。複数の併用もできます。
  **Google 側の変更は不要**で、設定名は従来どおり、Google だけのデプロイは見た目も挙動も
  これまでと同じです。設定が足りないプロバイダは警告付きで無効になるだけで、他の人のログインを
  巻き添えにしません（有効なプロバイダが 1 つも残らないときだけ起動を中止します）。意図的に
  起動を止めるケースが 1 つあります。Microsoft の issuer を `common` / `organizations` の
  ままテナント許可リスト無しで置いた場合で、これを許すと Microsoft アカウントを持つ全員が
  入口に立ち、個人アカウントは email を付け替えられるためです。設定手順は、IdP 側の作業まで
  含めて運用者向けガイドに通しで書きました（Compose / EC2 / ECS の設定例にもあります）。
- **email が変わっても、別のプロバイダから入っても、自分で 2 つ目のサインイン方法を足しても、
  同じ人は同じワークスペースのままです。** これまで「誰か」は email から導かれていて、その
  email はワークスペースの home ディレクトリ名そのものでした。そのため IdP 側で姓が変わったり
  ドメインが統合されたりすると空のワークスペースがもう 1 つ生え、別のプロバイダから入った
  ときも同じことが起きました。今後はプロバイダ側の不変なアカウント ID に対してログインを
  記録するので、どちらの場合も 1 つのワークスペース・1 つの home・1 組の保存済み資格情報が
  保たれます。設定に**アカウント**タブが増え、自分に紐づいたサインイン方法の一覧と、2 つ目を
  足すボタンが出ます（ログイン済みの本人が押す＝本人の同意で紐づくので、管理者がアドレスを
  名乗る形にはなりません）。使わなくなった方法は外せます（最後の 1 つと、いま使っている方法は
  除きます）。どの既存 email とも一致しないログインは、既存の人へ結び付けず**新しい人**として
  扱い、ログイン直後に画面でそう伝えます。
- **1 つのデプロイを部署（テナント）に分け、部署ごとにログイン画面・名簿・サインイン方法を
  持たせられます。** テナントは自分のログイン URL（`/login/<スラッグ>`）と、誰が入れるかを
  決める名簿を持ちます（env の許可リストと membership の二重台帳をやめ、名簿 1 つにしました）。
  テナント管理者は自分のディレクトリのサインイン方法（OIDC の issuer、または GitHub 組織）を
  ホストのファイル編集も CP の再起動も無しで登録できますが、**デプロイ管理者が承認するまで
  動きません**。ここが要点で、「誰であるかを宣言できる」ことは、そのまま他人になりすませる
  ことを意味するためです。テナントが見る一覧は 1 本で、自分の行とデプロイ共通の方式が同じ
  並びに出て、行ごとに［受け入れる］［ボタンに出す］が付きます。子会社が本社の人を通しつつ、
  押せないボタンを画面に出さない、という形が作れます。隠した方式は素の `/login` にも出なく
  なり、隠す指定が効くのはテナントの URL を配ったときだけであることを画面がその場で伝えます。
  すでに使われている issuer に 2 つ目のアプリ登録を足す操作は、保存の時点で止めます（通すと、
  後から同僚全員がログインを拒否されるという遠い場所に事故が落ちます）。テナント管理者には
  **テナント設定**モーダルが用意され、サインイン方法のほかメンバー・セッション・使用量・監査・
  MCP 配布を自分のテナントの分だけ扱えます。管理モーダルはデプロイ管理者専用になり、同じ
  左レール＋テナントのドリルダウンへ作り直しました。
- **テナント管理者が、自分のメンバーの接続元ネットワークを絞れます。** これまでの手段は
  ロードバランサの許可 CIDR だけで、デプロイ全体・CloudFormation の再適用が必要でした。今後は
  テナント単位の許可リストを Console から編集できます。**これはネットワーク防御ではありません。**
  要求は CP まで届き、セッションが検証された**あとで**拒否されるので、認証前の脆弱性・DoS・
  探索には効きません（そう画面にも書いてあります）。効くのは「資格情報を持った人が、許されて
  いない場所からデータに触る」ことだけです。`/mcp` と `/git` は対象外です（送信元が本人の
  コンテナのため）。
- **AWS に、home が停止をまたいで残るランタイムが増えました（`ecs-ec2`）。** 全員で共有する
  ネットワークファイルシステムではなく、各自の EBS ボリュームがプールされた EC2 スロットへ
  付け替わる形です。小さいファイルの書き込みが 8〜30 倍速く（`node_modules` の導入や Go の
  ビルドが時間を使うのはここです）、home は停止・起動をまたいで本当に残り、ワークスペースの
  大きさが Fargate の 16 vCPU / 120 GiB に縛られなくなります。**起動時間は採用理由になりません**
  — Fargate の温かい再起動と実測で互角です。スロットは温かいまま保たれ、返却ではなく休眠させ、
  上限に達したときだけ立ち退かせます。長く使われていない home は snapshot へ退避して次の起動で
  復元でき（テナント単位のオプトイン）、新規の home は温まった *golden* snapshot から作れます。
  新しい home はアベイラビリティゾーンへ分散し、予備を定期的に取るので、1 つの AZ の障害が
  全員を巻き込みません。運用者にはスロットプールの画面（いま何台ぶん払っているか／どれが
  眠っているか／誰の home がどこにあるか）と、退職者向けの**ワークスペース破棄**が付きます。
  採用はプロファイル 1 行の切り替えで、Fargate 側の実装は 1 行も変えていません。
- **ワークスペースの大きさを、人ごと・テナントごとに決められます。** メモリ・CPU・ディスクを
  独立した 3 軸として持ち、既存の 1 人あたり上限と同じ形でテナント上限も置けます。`ecs-ec2`
  では画面がそのランタイムの実態を言うように変えました — CPU は設定できず、メモリの値は上限
  ではなく「どの箱に乗るか」を決める必要量で、ディスクの値は永続 home の大きさです（home の
  作成時にだけ効き、縮小はできません）。あわせて ECS 系では、ネットワークストレージで高くつき
  再生成が安い生成物（Go のビルドキャッシュ・Go モジュール・`uv`）を、作業コピーを作る時点で
  ローカルの作業ディスクへ逃がします。`~/.npm` は意図的に永続 home に残すので、朝いちばんの
  導入がネットワーク無しで走ります。
- **クラウドが実際に請求している額を、メンバーごとに出します。** これまでの稼働時間に加えて、
  Cost Explorer から取った実費を、管理モーダル・テナント設定・個人設定・メンバー詳細に出します
  （合計／日次推移／サービス別内訳／期間指定）。土台になるタグは CP が打ち、コスト配分キーの
  有効化も CP が自動で行います（忘れると後から埋められない恒久的な欠測になるためです）。個人向けの
  ラベルは意図的に「あなたのコスト」にしていません。請求のうち人に紐づくのは一部だけなので、
  共有分を含まないことを欄に明記しています。
- **`.drawio` が図として開きます。** これまで `.drawio` は生の XML が出るだけでした。ファイル
  ペインで図として描き、XML ソースへ切り替えることもできます（ソース側では従来どおり編集・
  保存・競合処理・外部変更の追従が効きます）。Ctrl / ⌘ ＋ ホイールで指した点を軸に拡大縮小、
  素のホイールでパン、2 本指でピンチ、ドラッグでパン、ダブルタップで「収まり ↔ 等倍」。図は
  ダーク／ライトのテーマに追従します（背景も含めて）。ビューアは同梱で外部通信は無く、
  サンドボックスされたフレームの中で動きます。
- **セッションが直したファイルの一覧が出ます。** ミラーのヘッド直下の折りたたみ帯と、コマンド
  パレットの 4 つ目のモードが、「**このセッションが**何を直したか」に答えます。既存の 4 つの
  ファイル一覧はどれも作業コピー・リポジトリ軸なので答えられなかった問いです。母集合は
  セッション自身の編集呼び出しで、作業ツリーと突き合わせるため、すでにコミットされたものは
  **コミット済み**として出ます（差分が無いだけのものと混ざりません）。各ターンの末尾にも、
  そのターンが直したものを示すチップが付きます。claude / codex / opencode / cursor / copilot に
  対応し、転写に材料があれば `+N −M` まで出します。
- **会話の一節にマーカーを引くと、共有先にも届きます。** ミラーの本文を選んで 4 色のマーカーを
  引き、クリックすると誰がいつ引いたかが分かり、消せます。マーカーは同じセッションの共有ビューへ
  配られ、書き込み権のある共有先は自分で引くこともできます — レビューする人が「どこの話か」を
  文章で説明する代わりに、その 3 行を指せます。会話の本文が CP のデータベースへ複製されることは
  ありません。
- **共有した会話に、セッションの中身がもっと乗ります。** 引き継ぎ提案は「したらしい」だけでなく
  中身が読めるようになり、表示位置を覚えて再訪時は続きから、初回は末尾に着地します（そもそも
  末尾に着地できていませんでした）。タブは「共有セッション」の固定文字列ではなくセッション名と
  エージェントの色付きアイコンになり、ホバーチップの 1 行目にもセッション名が出ます。
- **スマホの横スワイプで稼働中のセッションを行き来できます。** drawer を閉じた状態で ← は次の
  セッション、→ は前のセッションです。対象と順序は左ペインで見えている集合と同じで、作業
  グループの絞り込みに従います。ミラーはセッションごとに表示位置を覚え、末尾からでも
  **返信を頭から**で最新の返信の先頭へ飛べます。
- **返信の中のパスがリンクになります。** エージェントがいちばん開きたい座標をインラインコードで
  書く（`docs/65.md`、`src/a.ts:73`、`_act-parts/`）ため、そこだけ手で打ち直す必要がありました。
  実在するものだけをリンクにし、ファイルはペインで、フォルダは左ペインを開いて展開し、
  キーボードごと渡します（着地した行から ↑↓ が効きます）。解決はワークスペース側で行うので、
  作業ディレクトリがサブフォルダのときにエージェントがリポジトリルート基準で書いたパスにも
  当たります。
- **Claude セッションが認証切れを知らせます。** これまで気づけるのは事後だけでした。
  セッションは**入力待ち**のまま、送ったプロンプトは**反映待ち**のまま、何も始まらない —
  CLI の端末はターンを開始できなくなった後も文字と Enter を受け取り続けるためです。今後は
  CLI 自身が使うのと同じ資格情報から期限を読み、セッションのバッジは**認証切れ — 再認証が
  必要**になり、設定の接続カードは緑のピルをやめて期限日を出し（3 日前からは「あと N 日で
  期限切れ」）、プロンプトの送信は理由付きで断られます（消えて終わりではなくなりました）。
  キー操作は従来どおりペインへ届くので、端末で `/login` を踏んで回復できます。
- **利用上限で止まったセッションが、その旨と再開時刻を出します。** 5 時間枠や週次の上限に
  当たったセッションは「入力待ち」になっていて、正常に終わったセッションと見分けが付きません
  でした。**制限解除待ち**として、自動再開のために既に押さえてあった解除時刻とともに出します。
  残高・支出の上限は待っても解除されない別物なので、**残高上限 — 増枠が必要**と出します。
- **セッション間のメッセージに種別が必須になりました。** 送信時に *request* / *question* /
  *answer* / *notice* のいずれかを指定し、封筒が受け取る側に「どんな返信を期待しているか」を
  伝えます。抜けていたのはここで、「承知しました」の 1 通が相手のセッションの 1 ターンを丸ごと
  消費します。request は**できないときだけ**返し、notice には返しません。
- **新規インストールは閉じた状態で始まり、招待前の人に何をすればよいかを見せます。** テンプレート
  の既定を招待制にし、membership を持たない人がログインしたときは、要求のたびにトーストが 1 つ
  ずつ出る Console ではなく「招待が必要です」と伝える画面が出ます。
- **AWS の ingress テンプレートで WAF を有効にできます**（レート制限と IP 評価だけ・どちらも
  既定オフ）。署名系のルールセットは意図的に用意していません。この製品はコード・シェルコマンド・
  ファイルの中身を普通の本文として運ぶので、Core rule set を入れると正常な操作がランダムに
  拒否され、しかも製品のバグに見えるためです。

### 改善

- **Chrome でのターミナルペインの描画がずっと軽くなりました。** 「このペインはタブを持つか」
  を問うスタイル規則のために、Chrome はペイン内部が変わるたびに判定をやり直していました。
  ターミナルは毎フレーム行を書き換えます。実ブラウザでの計測（40×80 の画面を毎フレーム
  書き換え）で 1 フレーム 127.9ms → 59.8ms。
- **アイドルのセッションとワークスペースが自動で止まります。** 仕組みはありましたが既定が
  「止めない」だったので、一晩置いたデプロイは誰も触っていないまま起動し続け、課金も続いて
  いました。既定はセッション 1 時間・ワークスペース 2 時間です。テナント単位の上書きは従来
  どおりで、明示的な `0` は「止めない」として効きます（従来は未設定として既定値に化けていました）。
- **ECS のデプロイでも、docker 構成と同じ更新バッジが出ます。** 「新しいビルドがあります」
  「要再起動」の判定が docker / native にしか無く、ECS では古いワークスペースイメージのまま
  走っていても画面には何も出ませんでした。ECS 向けの更新をワンコマンドで出す経路も付きます。
- **スキルピッカーの説明が 1 行を占めます。** 1 行目が起動文字列＋引数ヒント＋出所バッジ、
  2 行目が説明の全幅表示になり、ほとんど省略されて読めなかった説明が読めます。
- **共有した会話にもミラーの表示設定が効きます。** 文字サイズとフォントが共有ビューにも適用され、
  「最新へ」のピルもミラーと同じ位置・寸法になりました。
- **外観ポップ**の並びを 言語 → ペイン配置 → ダーク／ライト にし、どの行にもラベルを付けました。
- **一時的なプロバイダー失敗でターンが終わらなくなりました**（OpenCode / Codex）。再試行可能な
  失敗を中断として分類し、Claude が既に持っていた managed の再開経路に載せます。新しいターンとして
  短い「続けて」を送るので、元のプロンプトが再送されることはなく、副作用も重複しません。
- **S3 への通信がゲートウェイエンドポイントを通ります**（ECS）。アクセスログには状態コードが
  出るようになりました。
- **ガイド**: サインイン方式の設定を IdP 側の作業まで含めて通しで書いた章を追加し、メンバー／
  運用者向けガイドも新しい画面に追随しました。

### 修正

- **Chrome で Console が数秒フリーズしていました。** Firefox では起きません。ペインは
  hide / reveal / redraw のたびに健全な GPU コンテキストまで捨てて作り直しており、ブラウザの
  タブあたりの上限に達すると、**表示中の**ターミナルが使っているコンテキストが追い出されて
  いました。追い出されたターミナルは文字をページのレイアウト経由で描く方式へ落ち、その方式は
  字種ごとに文字を書き込んで幅を測り直します。日本語の画面は字種が数千あり、そのたびに
  キャッシュが空から始まる — 数秒はここに消えていました。今後は canvas による描画へ落ち、
  コンテキストは本当に失われたときだけ作り直し、予算を設けてペイン同士が追い出し合わない
  ようにしました。同じ画面での計測で、最長ブロック 119ms が 0ms に。タッチ端末は従来どおりです。
- **設定の学習・履歴が、全端末でまとめて初期化される事故が起きました。** 返信サジェストの
  学習チップ、ピン、SSM の利用実績、キー割当が揃って初期状態に戻ります。保存は設定全体を
  1 回で書き「最後の書き手が勝つ」形で、保存済みの読み込みは失敗しても無言で戻っていたため、
  既定値で始まった端末がそれを全部の上に書いていました。累積する値を空で潰さないようにし、
  保存済みを読めるまで送らないようにしました。
- **Claude の質問へ入力した自由文が捨てられていました。** 選択肢に preview が付く質問では
  自由入力の行が選択肢ごとの注記欄に置き換わり、そこへ送るための打鍵が配送層で弾かれて
  いたため、「回答を送信」を押しても何も起きず、**質問への回答を拒否した**という結果で返って
  いました。今後は質問に対する注記として、正しい行へ送られます。同じ箇所で、却下した質問が
  回答済みのように描画され、定型文が回答として解釈されていた問題も直り、**却下**バッジが
  付きます。
- **承認待ちの質問／プランのカードが 2 枚出ていました。** Agent は「承認待ちのものはまだ転写に
  無い」前提で payload を別送していましたが、claude は訊いた時点でツール呼び出しを書くため、
  両方が届いて両方が描かれていました。
- **使用量グラフが 1 ターン古いままで、再取得を何度か押すまで最新になりませんでした。** 使用量の
  読み出しは転写を台帳へ折り込む処理を起動しますが、それには実測 ~20 秒かかるため待ちません。
  応答がその事実を黙っていたので、返ってくる数字は必ず折り込み前でした。応答が折り込み中で
  あることを載せ、画面が結果を拾うようにしました。
- **`[保留]: 日本語…` のような行がミラーで消えていました。** Markdown の `[ラベル]: 行先` は
  リンク参照定義で、それ自体は何も描画しません。日本語の文は ASCII 半角スペースを含まないため、
  普通の箇条書きが丸ごとその形に一致して行ごと消え、さらに文書内の後続の同じラベルがその文への
  リンクになっていました。
- **起動時の最初の指示が届きませんでした。** 「作業を始める」からセッションを起動しても
  バックグラウンドでは何も始まらず（そのビューが画面に出ている間しか送信されないため、後から
  タブを開いた瞬間に送信されたように見えます）、同じ指示が 2 通表示されて片方が**反映待ち**の
  まま残る（リロードでしか消えない）ことがありました。配達をワークスペース側へ移し、画面に
  何が出ているかと無関係にしました。
- **Agent は答えているのに「ワークスペースエージェントに到達できません」と出ていました。**
  停止中セッションの端末を開くと接続失敗として表示されていましたが、実際には Agent が
  「セッションは走っておらず、表示できる端末履歴も残っていない」と正しく答えていました
  （履歴はメモリ上なのでコンテナ再起動で空になります）。本当の理由が出るようになり、本当に
  到達できない場合は従来どおり到達不能として報告します。
- **完了報告 OFF のスケジュール投入に、ミラーのバッジが付きませんでした。** 由来の記録が
  「報告先がある」枝の中にあったため、いちばん多い形のスケジュールと、利用上限の解除後の
  自動再開が、自分で打った入力と区別できませんでした。
- **タブを閉じると無関係のタブが出ていました。** 並びの隣へ移っていたのを、直前に表示していた
  タブへ戻すようにしました（ミラーからファイルを開いて閉じたときに必ず表に出ます）。あわせて、
  モーダルを開いて閉じると選択タブが古いものへ戻る問題も直しました。
- **特定のセッションでだけ、スマホの横スワイプが丸ごと効かなくなっていました。** 「横スクロール
  できる領域の上ではスワイプを見送る」入口ガードが、縦だけのスクローラでも「横スクロールできる」と
  読める値を見ていたため、転写に折り返し位置を持たない長い文字列（`sha256:…` や URL）が 1 つ
  混ざるだけで、転写全域がスワイプを受け付けなくなっていました。長い文字列を折り返すようにし、
  ガードの判定も本来見るべきものに直しました。
- **Claude の質問で、選択肢の説明がスマホで 2 行に切られていました**（いちばん読みにくく、
  いちばん必要な場面です）。
- **共有セッションのタブがすべて「共有セッション」と表示されていました。** 複数開くと
  見分けが付きませんでした。タブにはセッション名と、そのエージェントの色付きアイコンが
  出ます（メイン領域でも、切り離したタブでも）。
- **OpenCode が、選んでいない枠で起動していました。** 未設定・不明値を Zen 扱いしていたため、
  鍵を 1 本保存しただけで課金経路が無断で動く可能性がありました。新しいワークスペースは
  設定 > エージェント で明示的に選ぶまで何も使いません。
- **ECS のデプロイで利用ガイドが開きませんでした。** ガイドは CP イメージから起動ごとにステージ
  され、docker / native が read-only でマウントする方式ですが、ECS アダプタだけ未配線でディレクトリが
  空のままでした。マウントではなく取得で届けるようにしました。同じ周辺で、JDK を 設定 > toolchains
  からワンボタンで導入できます。
- **ワークスペース内の OAuth ログインが、wake 直後に失敗していました**（ECS）。wake はサービスを
  ローリングさせるため、その 1〜2 分は要求が新旧どちらのタスクにも着地しうる一方、CLI のログイン
  フローは 1 つのプロセスに状態を持ちます。wake がデプロイの収束を待つようにしました。
- **ECS のワークスペースの初回起動がゲートウェイタイムアウトを返すことがありました**（ヘルスチェックを
  同期で待っていたため）。
- **何も変わっていないのに「要再起動」が点灯していました。** 判定がイメージの digest を比べており、
  キャッシュに当たった再ビルドは同じ内容でも別の digest になるためです。内容の指紋を比べるように
  しました。

### アップグレード時の注意

手作業の移行はありません。起動時に 9 本の追加マイグレーションが走ります（プロバイダアカウント、
テナントのログイン規則とテナント定義のサインイン方法、ワークスペースの CPU、テナントの接続元制限、
クラウド費用）。いずれもアップグレード前のデータは持たず、古いビルドは無視するので切り戻しも
安全です。既存の利用者は従来どおり email で一致し、次回ログイン時に自分のプロバイダアカウントを
記録します — home ディレクトリは動きません。`AF_OIDC_PROVIDERS` を設定するか、テナントに方式を
登録しない限り、ログインまわりは何も変わりません。

既定値が 3 つ変わります:

- **アイドル停止が有効になりました**（セッション 1 時間・ワークスペース 2 時間）。従来どおりに
  戻すには `AF_SESSION_IDLE_TIMEOUT` / `AF_WS_IDLE_TIMEOUT` に `0` を設定してください。明示的な
  `0` は効くようになりました（従来は既定値に化けていました）。
- **新規インストールは招待制になりました。** 変えたのはテンプレートだけです（`install-compose.sh`
  がコピーする `.env.example` と、ECS の `AfProvision` パラメータ）。`AF_PROVISION` を書いていない
  既存の `.env` は 1 バイトも挙動が変わらず、CP に焼き込まれた既定は `auto` のままです。既存の
  ECS スタックは再デプロイするとこの新しい既定を拾いますが、名簿に載っている人は全員そのまま
  通り、止まるのは新規の自動受け入れだけです。
- **ECS の作業ディスクの既定が 50 GiB になりました。** 生成物の退避は 30 GiB 以上のときだけ有効に
  なる設計で、従来の既定（無料枠 20 GiB）ではどのデプロイも条件を満たしていませんでした。既存の
  スタックはデプロイ時の値を保持します。`WsDiskGiB=0` で従来どおりに戻せます。無料枠を超える
  30 GiB 分は、タスク稼働中のみの課金で月 $2.9 ほどです。

`ecs-ec2` ランタイムはオプトイン（プロファイル 1 行）で、Fargate 側の経路は変わりません。費用の
表示には Cost Explorer が必要です。コスト配分タグのキーは CP が初回に有効化します（これは CP が
アカウントの請求設定へ書き込む唯一の箇所です）。Compose のデプロイは従来どおり新しいイメージを
取得し、native インストールはワンライナーで更新できます。
