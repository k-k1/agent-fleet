### Upgrade notes

- **AWS (ECS): the network stack is updated by hand, around `update.sh`.** Workspaces move to
  subnets of their own and the S3 endpoint gets a policy, so follow "Upgrading from v0.34.x" in
  `deploy/aws/ecs/README.md`: back up, deploy `00-network` with `S3EndpointEnabled=false` through a
  change set (it adds six resources and removes `S3Endpoint`), run `update.sh`, stop and start
  every running workspace, then deploy `00-network` with `S3EndpointEnabled=true`. The network
  stack now needs `--capabilities CAPABILITY_IAM`.
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716),
  [#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **Do not deploy the new `00-network` with its defaults.** `S3EndpointEnabled` defaults to `true`,
  and the endpoint then refuses (AccessDenied) the S3 requests of every workspace that has not been
  restarted yet. `update.sh` lists the workspaces still in the old subnets.
  ([#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **AWS: the S3 endpoint's new policy applies to everything in the private subnets, not just
  workspaces.** The Control Plane, the `ecs-ec2` slot hosts and the engines get AccessDenied (there
  is no NAT fallback) for any S3 bucket the policy does not list: the ECR layer bucket, the AL2023
  repositories, the SSM Agent update and ECS agent download buckets, the `60-engines` models bucket
  and the optional egress archive bucket. If you use other buckets from the Control Plane, the
  template has no parameter to add one: set `S3EndpointEnabled=false` (S3 then goes through the NAT
  and pays its data processing) or add the bucket to the `S3Endpoint` policy in
  `deploy/aws/ecs/cfn/00-network.yaml`.
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716))
- **AWS: Fargate workspace starts now pay NAT data processing for the image pull**, because
  workspace subnets have no S3 endpoint. `ecs-ec2` slots still pull through the endpoint.
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716))
- **AWS: rolling `00-network` back to v0.34.x's template drops the `GatewayEipAllocationId` and
  `GatewayEipAddress` parameters**, so the next switch to `EgressRoute=gateway` must pass both
  again (README "Upgrading from v0.34.x", Rollback).
  ([#2728](https://github.com/k-k1/agent-fleet/issues/2728))
- **AWS: to empty a parameter of a live stack, use `deploy/aws/ecs/clear-params.sh`**, not
  `aws cloudformation deploy --parameter-overrides Key=`, which did not clear it in a rehearsal.
  (see the README).
  ([#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **AWS: the deploying principal needs more permissions** for the new optional pieces: Elastic IP
  association, launch templates, Auto Scaling groups, an instance role and a Secrets Manager secret
  for the egress gateway, `ssm:SendCommand` and `ssm:GetCommandInvocation` for `pause.sh` and
  `standup.sh` to check it, and S3 bucket creation for the egress archive. See "Minimal IAM" in
  `deploy/aws/ecs/README.md`.
- **AWS: the egress gateway is opt-in and a preview.** `00-network`'s `EgressRoute` stays
  `nat-gateway` unless you set `gateway`, which records every workspace connection and can enforce
  an allowlist. The gateway, its relay, the workspace subnets, pause/standup and this upgrade path were verified on a
  test deployment only, not yet in production. It gives workspaces a second egress address to
  allow-list, drops non-HTTP egress such as SSH git, and relays intercepted port 443 inside the
  gateway (an accepted exception to its design).
  ([#2717](https://github.com/k-k1/agent-fleet/issues/2717),
  [#2759](https://github.com/k-k1/agent-fleet/issues/2759))
- **AWS: the egress event archive is off by default.** `10-data` has two new optional parameters,
  `EgressArchive` and `EgressArchiveRetentionDays`; nothing changes until you deploy it with
  `EgressArchive=create` and run `update.sh`.
  ([#2732](https://github.com/k-k1/agent-fleet/issues/2732))
