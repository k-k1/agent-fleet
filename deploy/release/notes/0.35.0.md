On AWS, workspaces can now leave through an optional egress gateway that records every connection
with the workspace that made it and can enforce the allowlist. Tenant admins can distribute MCP
servers that sign in with OAuth, Agent Fleet memory gets an MCP endpoint of its own, and Toolchains
keeps JDK and Node.js patches current.

### New

- **AWS: an egress gateway for workspaces (preview).** Set `EgressRoute=gateway` on `00-network`
  and workspace traffic leaves through a gateway of its own, with its own Elastic IP, so the Admin
  panel's **Egress** allowlist applies to ECS workspaces too and every connection is recorded with
  the workspace that made it. `pause.sh` and `standup.sh` stop and restore it with the NAT gateway.
  See the Upgrade notes before turning it on.
  ([#2717](https://github.com/k-k1/agent-fleet/issues/2717),
  [#2728](https://github.com/k-k1/agent-fleet/issues/2728),
  [#2729](https://github.com/k-k1/agent-fleet/issues/2729),
  [#2742](https://github.com/k-k1/agent-fleet/issues/2742),
  [#2759](https://github.com/k-k1/agent-fleet/issues/2759),
  [#2665](https://github.com/k-k1/agent-fleet/issues/2665))
- **Raw egress events are kept for 30 days** (`AF_EGRESS_EVENT_RETENTION_DAYS`, `0` keeps them),
  and can be archived to S3 before they are purged.
  ([#2675](https://github.com/k-k1/agent-fleet/issues/2675),
  [#2699](https://github.com/k-k1/agent-fleet/issues/2699),
  [#2732](https://github.com/k-k1/agent-fleet/issues/2732))
- **Distribute OAuth MCP servers to a tenant.** A tenant admin can distribute a remote MCP server
  whose authentication is OAuth, optionally with a client registered in advance at the server;
  each member signs in from Settings and no credential is distributed.
  ([#2479](https://github.com/k-k1/agent-fleet/issues/2479))
- **Agent Fleet memory has its own MCP endpoint, `/mcp/memory`.** A token or claude.ai connector
  made for it reaches only the memory tools, not your sessions or the admin tools. Memory tools
  called from outside can now pick the project by repository URL.
  ([#2764](https://github.com/k-k1/agent-fleet/issues/2764),
  [#2765](https://github.com/k-k1/agent-fleet/issues/2765),
  [#2766](https://github.com/k-k1/agent-fleet/issues/2766))
- **Merge a GitHub pull request from its work item**, when GitHub says it can be merged, after a
  confirmation.
  ([#2632](https://github.com/k-k1/agent-fleet/issues/2632))
- **Report back on Bitbucket pull requests** when the Bitbucket connection holds the
  `pullrequest:write` scope.
  ([#2709](https://github.com/k-k1/agent-fleet/issues/2709))
- **Uninstall JDK and Node.js versions** you no longer need from Settings › Toolchains ›
  **Installed versions**.
  ([#2648](https://github.com/k-k1/agent-fleet/issues/2648))

### Upgrade notes

- **Memory tools called through `/mcp`: `memory_save` and `memory_forget` now need `scope`**, and
  `scope: project` needs `project` or `repository`. A client that relied on the default is refused
  with a message naming what to pass.
  ([#2765](https://github.com/k-k1/agent-fleet/issues/2765))
- **AWS (ECS): the network stack is updated by hand, around `update.sh`.** Workspaces move to
  subnets of their own and the S3 endpoint gets a policy, so follow "Upgrading from v0.34.x" in
  `deploy/aws/ecs/README.md`: back up, deploy `00-network` with `S3EndpointEnabled=false` through a
  change set (it adds six resources and removes `S3Endpoint`), run `update.sh`, stop and start
  every running workspace, then deploy `00-network` with `S3EndpointEnabled=true`. The network
  stack now needs `--capabilities CAPABILITY_IAM`.
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716),
  [#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **Do not deploy the new `00-network` with its defaults.** `S3EndpointEnabled` defaults to `true`,
  and the endpoint then refuses (AccessDenied) the S3 requests of every workspace that has not been
  restarted yet. `update.sh` lists the workspaces still in the old subnets.
  ([#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **AWS: the S3 endpoint's new policy applies to everything in the private subnets, not just
  workspaces.** The Control Plane, the `ecs-ec2` slot hosts and the engines get AccessDenied (there
  is no NAT fallback) for any same-region S3 request through the endpoint that the policy does not
  allow. The allowed buckets are the ECR layer bucket, the AL2023 repositories, the SSM Agent update
  and ECS agent download buckets, the `60-engines` models bucket and the optional egress archive
  bucket that `10-data` creates (a bucket of your own is refused). If the Control Plane uses other
  buckets, the template has no parameter to add one: set `S3EndpointEnabled=false` (S3 then goes
  through the NAT and pays its data processing), or keep the endpoint and maintain a customized
  `S3Endpoint` policy in `deploy/aws/ecs/cfn/00-network.yaml`.
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716))
- **AWS: Fargate workspace starts now pay NAT data processing for the image pull**, because
  workspace subnets have no S3 endpoint. `ecs-ec2` slots still pull through the endpoint.
  ([#2716](https://github.com/k-k1/agent-fleet/issues/2716))
- **AWS: rolling `00-network` back to v0.34.x's template drops the `GatewayEipAllocationId` and
  `GatewayEipAddress` parameters**, so the next switch to `EgressRoute=gateway` must pass both
  again (README "Upgrading from v0.34.x", Rollback).
  ([#2728](https://github.com/k-k1/agent-fleet/issues/2728))
- **AWS: to empty a parameter of a live stack, use `deploy/aws/ecs/clear-params.sh`**, not
  `aws cloudformation deploy --parameter-overrides Key=`, which did not clear it in a rehearsal.
  See the README.
  ([#2763](https://github.com/k-k1/agent-fleet/issues/2763))
- **AWS: the deploying principal needs more permissions** for the new optional pieces: Elastic IP
  association, launch templates, Auto Scaling groups, an instance role and a Secrets Manager secret
  for the egress gateway, `ssm:SendCommand` and `ssm:GetCommandInvocation` for `pause.sh` and
  `standup.sh` to check it, and S3 bucket creation for the egress archive. See "Minimal IAM" in
  `deploy/aws/ecs/README.md`.
- **AWS: the egress gateway is opt-in and a preview.** `00-network`'s `EgressRoute` stays
  `nat-gateway` unless you set `gateway`, which records every workspace connection and can enforce
  an allowlist. The gateway, its relay, the workspace subnets, pause/standup and this upgrade path were verified on a
  test deployment only, not yet in production. It gives workspaces a second egress address to
  allow-list, drops non-HTTP egress such as SSH git, and relays intercepted port 443 inside the
  gateway (an accepted exception to its design).
  ([#2717](https://github.com/k-k1/agent-fleet/issues/2717),
  [#2759](https://github.com/k-k1/agent-fleet/issues/2759))
- **AWS: the egress event archive is off by default.** `10-data` has two new optional parameters,
  `EgressArchive` and `EgressArchiveRetentionDays`; nothing changes until you deploy it with
  `EgressArchive=create` and run `update.sh`.
  ([#2732](https://github.com/k-k1/agent-fleet/issues/2732))
