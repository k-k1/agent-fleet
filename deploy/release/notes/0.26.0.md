Each version is now one GitHub Release that carries the workspace rootfs too, and the native package
ships for arm64 Linux as well as amd64. Stop in a Managed session now takes two steps: the first ends
the running turn and keeps what is queued, and a second also discards the queue. The mirror shows a
claude reply while it is being written. On AWS, Recreate and Clean home used to report success and
remove nothing; they now work on ecs-ec2 and are refused on ecs. AWS credentials of the workspace or
its host are no longer handed to agent sessions; operators of AWS and cloud Docker deployments have
steps to take.

### Security: AWS credentials of the workspace or its host are no longer handed to agent sessions

Before this release, a command in an agent session or terminal that named no AWS profile could silently run as the workspace's own AWS identity instead of the member. This covered a bare `aws`, an SDK's default credential chain, or a build tool such as a Gradle/Maven deploy plugin. On ECS that identity was the workspace task role; on ecs-ec2, the EC2 slot's instance profile through instance metadata (IMDS); on a Docker host with an instance profile, that profile. Such commands now fail with "Unable to locate credentials". Members run AWS commands as themselves with `af-aws-exec --profile <name> --account <id> -- <command>`.

What changed:
- ECS / ecs-ec2: the Agent removes the container credential variables from everything it starts and sets AWS_EC2_METADATA_DISABLED=true, including tmux panes and MCP servers.
- Docker: the Control Plane starts workspace containers with AWS_EC2_METADATA_DISABLED=true.
- ecs-ec2 slots: ECS_AWSVPC_BLOCK_IMDS=true in the slot user data.
- ec2-single: the template requires IMDSv2 with hop limit 1.
- update.sh also redeploys the slot-pool stack (40-ec2-pool); on ecs-ec2 it stops if it cannot find it — name it with --pool-stack <stack>.

Operator action required:
1. Upgrade as usual (update.sh on ECS; compose pull/up plus the workspace image on Docker).
2. ecs-ec2: slots launched before the upgrade keep the old user data and can still reach IMDS, and a workspace Stop → Start returns to the same slot. Retire them through the Control Plane's sweeper by setting Ec2SlotTerminateAfterSec on the ingress stack (14400 recommended); the sweeper detaches the home before terminating and homes are never deleted. Then have users Start their workspaces, which builds new slots. See deploy/aws/ecs/README.md, "Moving retained slots onto new user data".
3. Docker / compose: running workspaces keep the environment they were created with; `docker compose up -d` and a Docker restart do not change it. Stop → Start every workspace in the Console after upgrading, and again after changing AF_WS_WORKLOAD_AWS.
4. ec2-single: for an instance created before this release run `aws ec2 modify-instance-metadata-options --instance-id <id> --http-tokens required --http-put-response-hop-limit 1 --http-endpoint enabled`. Do not apply it by updating the stack: the Ubuntu AMI parameter re-resolves and can replace the instance.
5. Other Docker hosts in a cloud: require IMDSv2 with hop limit 1, or add a DOCKER-USER rule rejecting 169.254.169.254 from the workspace bridges. Compose needs no new privileges.
6. Verify from a workspace shell with the opt-in off: `echo ${AWS_EC2_METADATA_DISABLED:-unset}` prints true; `aws sts get-caller-identity` with no profile fails with "Unable to locate credentials"; `curl -s -o /dev/null -m 3 -w '%{http_code}' -X PUT -H 'X-aws-ec2-metadata-token-ttl-seconds: 60' http://169.254.169.254/latest/api/token` does not print 200. Do not print the environment.

Opt-in: AF_WS_WORKLOAD_AWS=1 on the Control Plane hands the ECS task role back to sessions and stops suppressing the SDKs' metadata lookup. It never removes a network block, so it does not give Docker workspaces the host's instance profile, and it reaches a workspace at its next Start.

Not covered: workspaces on the native runtime run on the member's own machine and keep that machine's instance role; a process can still deliberately read the ECS container URI from its own process tree (same same-user boundary as the Agent token).

### New

- **Native package for arm64 Linux.** `install.sh` and `af update` pick the package for the machine
  they run on. Versions before 0.26.0 have no arm64 package.
  ([#1345](https://github.com/k-k1/agent-fleet/issues/1345))
- **Two-stage Stop for Managed sessions.** The first Stop ends the running turn only; your queued
  follow-ups and peer messages then run one per turn. Stop again, or pick **Stop and discard the
  queue**, to discard what is still queued; a notice lists it and **Put back** returns your own input
  to the input box. Queued bubbles have **Back to input** and **Remove**. Terminal (CLI) sessions keep
  the CLI's own Esc.

  it stopped. Tenant admins see the auto-stop and its reason in the member list.

- **Claude Code's push notifications reach the notification center.** ([#1069](https://github.com/k-k1/agent-fleet/issues/1069))

### Upgrade notes

- **Release assets**: there is no separate `rootfs-<r>` release any more; the rootfs is attached to
  `v<version>` and each release's `SHA256SUMS` lists exactly its assets. Installed copies and
  `af update` need nothing; only a script or mirror that downloads from `rootfs-<r>` releases has to
  follow. ([#1345](https://github.com/k-k1/agent-fleet/issues/1345))
- **A deployment that signs people in without `AF_MASTER_KEY`** now logs a warning and shows a banner
  to super admins; nothing stops. ([#1080](https://github.com/k-k1/agent-fleet/issues/1080))
- **Without `PUBLIC_BASE_URL`, internal git's clone, push and LFS routes now answer 503.** Set it if
  you use internal git. ([#1212](https://github.com/k-k1/agent-fleet/issues/1212))
- **`AF_USAGE_SAMPLE_INTERVAL`, `AF_GIT_GC_INTERVAL`, `AF_SCHEDULER_INTERVAL` and
  `AF_CLOUD_COST_INTERVAL` set to `0` now really turn their loop off.**
  ([#1186](https://github.com/k-k1/agent-fleet/issues/1186))
- **The admin MCP tool that stops another member's session is now `stop_user_session`.** Under the
  old name it never ran. ([#1188](https://github.com/k-k1/agent-fleet/issues/1188))
- **AWS credentials in sessions**: see the Security section above; it has steps for every
  deployment on AWS or a cloud Docker host.
- **ECS**: the CP role may run SSM commands, and write the tags that fence them, only on its own slot
  instances; if you override
  `AF_ECS_EC2_POOL`, keep it equal to the cluster name. A `retain` data stack's name may be at most
  37 characters, and enabling the EFS backup on a live deployment is in the ECS runbook.
  ([#1182](https://github.com/k-k1/agent-fleet/issues/1182),
  [#1419](https://github.com/k-k1/agent-fleet/issues/1419),
  [#1195](https://github.com/k-k1/agent-fleet/issues/1195))
