修正 1 件で、対象は自前の推論エンジンを動かす `ecs-ec2` の配備です。エンジンツールの
イメージを手で選んだことのない配備では、モデルの取り込みが 1 バイトも取得しないまま失敗し、
しかも画面に届く行は原因ではなく資料へのポインタだけでした。

### Fixed

- **`EngineToolsImageTag` が最初から入っていた値のままの配備で、モデルの取り込みが
  両ロールとも失敗していました。** テンプレートが要求するスクリプトの契約が、その
  イメージの話す契約より新しく、取得と転送の各ステップが起動を拒んでいました。
  0.21.0 と 0.22.0 の両方が該当し、自分でタグを選んでいた配備は最初から無関係です。

### Upgrade notes

- **更新すれば直ります。** `update.sh` が、この最初の値のままのスタックを対応する
  イメージへ移し、パラメータとして明示するので値が戻ることもありません。自分で選んだ
  タグはそのままにします——独自のタグを使い続けるなら、この版の
  `deploy/aws/ecs/engine-tools/` から焼き直してください。
- **0.21.0 / 0.22.0 に留まる場合**、パラメータ 1 つで直ります。スタックの他の値は動きません。

  ```sh
  aws cloudformation deploy --stack-name af-ecs-engines \
    --template-file deploy/aws/ecs/cfn/60-engines.yaml \
    --parameter-overrides EngineToolsImageTag=2026-09-18 \
    --capabilities CAPABILITY_NAMED_IAM --no-fail-on-empty-changeset
  ```

エージェント CLI のピンは 0.22.0 から変わっていません。
