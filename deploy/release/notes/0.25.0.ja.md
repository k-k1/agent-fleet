課題管理から始めたセッションのブランチ名が、リポジトリ自身の規則（git-flow の設定、
`.agent-fleet/branches`、Bitbucket のブランチモデル）に従うようになりました。課題管理の開いている
プルリクエストには CI の状態と衝突が出ます。`af-aws-exec` が AssumeRole と `credential_process` の
プロファイルを扱えるようになり、設定 › AWS プロファイル/SSM ではプロファイルの行からログインできます。
起動に失敗したマネージドのセッションは、CLI が出力した内容を示します。

### New

- **ブランチ名がリポジトリの規則に従います。** 課題管理からセッションを始めると、リポジトリの
  `.agent-fleet/branches`、git-flow の設定（`.gitflow` またはクローンの `gitflow.*`）、Bitbucket の
  ブランチモデルから、ブランチ名と起点を埋めます。どの規則が起点を決めたかを示し、規則に合わない名前には
  注記を出します。名前を断ることはありません。名前を変えるダイアログにはリポジトリのブランチ種別が並び、
  ブランチ名のテンプレートで `{ref}`・`{num}`・`{project}`・`{type}`・`{prefix}` が使えるように
  なりました。Console から git-flow を初期化する機能はまだです
  （[#1126](https://github.com/k-k1/agent-fleet/issues/1126)）。
  ([#1120](https://github.com/k-k1/agent-fleet/issues/1120),
  [#1124](https://github.com/k-k1/agent-fleet/issues/1124),
  [#1125](https://github.com/k-k1/agent-fleet/issues/1125))
- **課題管理の開いているプルリクエストに CI の状態とマージの衝突が出ます。** 失敗・実行中・成功と、
  ベースと衝突しているときの印です。GitHub がまだ答えていないときは何も描きません。
  ([#1113](https://github.com/k-k1/agent-fleet/issues/1113))
- **課題の「開始済み」の一覧にセッションの名前が出ます。** その後アーカイブされたセッションは、
  そこから元に戻せます。
  ([#1108](https://github.com/k-k1/agent-fleet/issues/1108))
- **`af-aws-exec` が、自分で定義した AssumeRole（`role_arn` ＋ `source_profile`）と
  `credential_process` のプロファイルを扱えます。** `--account` でアカウントを名指ししたときだけで、
  先に経路全体を確かめ、短命の資格情報だけを渡します。設定の SSO プロファイルからロールを引き受ける
  形はまだです（[#1109](https://github.com/k-k1/agent-fleet/issues/1109)）。
  ([#1107](https://github.com/k-k1/agent-fleet/issues/1107))
- **設定 › AWS プロファイル/SSM**（旧「AWS SSM」）のプロファイルの行に**ログイン**とログイン状態の
  バッジが付きました。コマンドに求められる前にサインインしておけます。
- **起動に失敗したマネージドのセッションは、CLI が最後に出力した数行を示します。** 秘密情報は
  取り除いたうえでの表示で、「時間内に起動しませんでした」だけで終わらなくなりました。
  ([#1076](https://github.com/k-k1/agent-fleet/issues/1076))
- **`create_session` で子セッションの推論の強さ（effort）を指定できます**（`model` も必要です）。
  ([#1068](https://github.com/k-k1/agent-fleet/issues/1068))
