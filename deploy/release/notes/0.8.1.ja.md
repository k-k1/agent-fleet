ログインが Google 固定でなくなりました。任意の OpenID Connect プロバイダを有効にでき、
email が変わっても、別のプロバイダから入っても、同じ人は同じワークスペースのままです。
Chrome で数秒フリーズする問題も解消し、認証が切れた Claude セッションは、送ったものを
黙って飲み込む代わりにその旨を伝えるようになりました。

### 新機能

- **Google 以外の OpenID Connect プロバイダでログインできます。** これまで入口は Google
  サインインだけで、Microsoft 365 で運用している会社は設置できませんでした。任意の OIDC
  プロバイダ — Entra ID / Okta / Keycloak / Auth0 / Cognito / GitLab — を
  `AF_OIDC_PROVIDERS` に並べ、issuer・クライアント ID・シークレットを与えれば有効になり、
  ログイン画面には有効なプロバイダの数だけボタンが、付けた名前で並びます。複数の併用も
  できます。**Google 側の変更は不要**で、設定名は従来どおり、Google だけのデプロイは
  見た目も挙動もこれまでと同じです。設定が足りないプロバイダは警告付きで無効になるだけで、
  他の人のログインを巻き添えにしません（有効なプロバイダが 1 つも残らないときだけ起動を
  中止します）。意図的に起動を止めるケースが 1 つあります。Microsoft の issuer を
  `common` / `organizations` のままテナント許可リスト無しで置いた場合で、これを許すと
  Microsoft アカウントを持つ全員が入口に立ち、個人アカウントは email を付け替えられるため
  です。設定手順は運用者向けインストールガイドと、Compose / EC2 / ECS の設定例にあります。
- **email が変わっても、別のプロバイダから入っても、同じ人は同じワークスペースのままです。**
  これまで「誰か」は email から導かれていて、その email はワークスペースの home ディレクトリ
  名そのものでした。そのため IdP 側で姓が変わったりドメインが統合されたりすると空の
  ワークスペースがもう 1 つ生え、別のプロバイダから入ったときも同じことが起きました。今後は
  プロバイダ側の不変なアカウント ID に対してログインを記録するので、どちらの場合も 1 つの
  ワークスペース・1 つの home・1 組の保存済み資格情報が保たれます。どの既存 email とも
  一致しないログインは、既存の人へ結び付けず**新しい人**として扱い、ログイン直後に画面で
  そう伝えます。2 つのアカウントにログインできることが証明するのは両方を操作できることだけで、
  同一人物であることではなく、ワークスペースを共有した後の結合は取り消せないためです。
- **Claude セッションが認証切れを知らせます。** これまで気づけるのは事後だけでした。
  セッションは**入力待ち**のまま、送ったプロンプトは**反映待ち**のまま、何も始まらない —
  CLI の端末はターンを開始できなくなった後も文字と Enter を受け取り続けるためです。今後は
  CLI 自身が使うのと同じ資格情報から期限を読み、セッションのバッジは**認証切れ — 再認証が
  必要**になり、設定の接続カードは緑のピルをやめて期限日を出し（3 日前からは「あと N 日で
  期限切れ」）、プロンプトの送信は理由付きで断られます（消えて終わりではなくなりました）。
  キー操作は従来どおりペインへ届くので、端末で `/login` を踏んで回復できます。

### 改善

- **Chrome でのターミナルペインの描画がずっと軽くなりました。** 「このペインはタブを持つか」
  を問うスタイル規則のために、Chrome はペイン内部が変わるたびに判定をやり直していました。
  ターミナルは毎フレーム行を書き換えます。実ブラウザでの計測（40×80 の画面を毎フレーム
  書き換え）で 1 フレーム 127.9ms → 59.8ms。

### 修正

- **Chrome で Console が数秒フリーズしていました。** Firefox では起きません。ペインは
  hide / reveal / redraw のたびに健全な GPU コンテキストまで捨てて作り直しており、ブラウザの
  タブあたりの上限に達すると、**表示中の**ターミナルが使っているコンテキストが追い出されて
  いました。追い出されたターミナルは文字をページのレイアウト経由で描く方式へ落ち、その方式は
  字種ごとに文字を書き込んで幅を測り直します。日本語の画面は字種が数千あり、そのたびに
  キャッシュが空から始まる — 数秒はここに消えていました。今後は canvas による描画へ落ち、
  コンテキストは本当に失われたときだけ作り直し、予算を設けてペイン同士が追い出し合わない
  ようにしました。同じ画面での計測で、最長ブロック 119ms が 0ms に。タッチ端末は従来どおりです。
- **Agent は答えているのに「ワークスペースエージェントに到達できません」と出ていました。**
  停止中セッションの端末を開くと接続失敗として表示されていましたが、実際には Agent が
  「セッションは走っておらず、表示できる端末履歴も残っていない」と正しく答えていました
  （履歴はメモリ上なのでコンテナ再起動で空になります）。本当の理由が出るようになり、本当に
  到達できない場合は従来どおり到達不能として報告します。
- **Claude の質問へ入力した自由文が捨てられていました。** 選択肢に preview が付く質問では
  自由入力の行が選択肢ごとの注記欄に置き換わるため、入力した文字は無関係な行へ入り、
  そのまま確定され、**質問への回答を拒否した**という結果で返っていました。今後は質問に対する
  注記として送られます。同じ箇所で、却下した質問が回答済みのように描画され、定型文が回答
  として解釈されていた問題も直り、**却下**バッジが付きます。
- **共有セッションのタブがすべて「共有セッション」と表示されていました。** 複数開くと
  見分けが付きませんでした。タブにはセッション名と、そのエージェントの色付きアイコンが
  出ます（メイン領域でも、切り離したタブでも）。

### アップグレード時の注意

移行作業も設定変更もありません。どのプロバイダのアカウントでログインしたかを記録する
テーブルが起動時に追加されますが、アップグレード前のデータは持たず、古いビルドはこの
テーブルを無視するので切り戻しも安全です。既存の利用者は従来どおり email で一致し、
次回ログイン時に自分のプロバイダアカウントを記録します — home ディレクトリは動きません。
`AF_OIDC_PROVIDERS` を設定しない限り、ログインまわりは何も変わりません。Compose の
デプロイは従来どおり新しいイメージを取得し、native インストールはワンライナーで更新
できます。エージェント CLI のピン止め版は 0.8.0 から変更ありません。
