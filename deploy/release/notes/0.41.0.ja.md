ターミナル（CLI）の claude セッションを Anthropic API キーで動かせるようになり、サブスクリプションの
利用枠で止まったセッションは、リセットを待たずにそちらで続けられます。セッションは自分のプルリクエストの
CI の失敗とレビューの指摘を知らされるようになり、AWS の egress ゲートウェイは指定した宛先への SSH git と
データベースの通信を通せるようになり、ecs-ec2 のスロットはスタックをデプロイしなくても Amazon の AMI
更新に追従します。

### 新機能

- **Anthropic API キーで動く claude。** 起動ダイアログの **モデルのルート** で、ターミナルの claude
  セッションを、このワークスペースの claude.ai ログインの代わりに OpenCode カードに保存した Anthropic
  API キー（従量課金）で動かせます。ルートを選ばないセッションはこれまでどおりです。
  ([#3281](https://github.com/k-k1/agent-fleet/issues/3281),
  [#3344](https://github.com/k-k1/agent-fleet/issues/3344),
  [#3317](https://github.com/k-k1/agent-fleet/issues/3317))
- **利用枠で止まったら API ルートで続ける。** サブスクリプションのルートで始めた claude セッションが
  利用枠で止まると、費用の確認のあとで **API ルートで続ける** を選べます。切り替えは一方向です。
  ([#3283](https://github.com/k-k1/agent-fleet/issues/3283))
- **セッションが自分のプルリクエストへのフィードバックを知る。** **設定 › エージェント › セッション ›
  PR へのフィードバックをセッションに伝える** をオンにすると、PR で CI が失敗したときやレビューで修正を
  求められたときにセッションへ伝えます。止まっているセッションは先に起動します。既定はオフです。
  ([#3129](https://github.com/k-k1/agent-fleet/issues/3129))
- **AWS の egress ゲートウェイで SSH git とデータベース。** 管理者は 管理 › 通信 で宛先とポートを
  **TCP ポート** のエントリとして指定できます（メンバーは提案できます）。enforce では、それ以外の HTTP
  でない通信は落とされて記録されます。アップグレードの注意を参照してください。
  ([#3369](https://github.com/k-k1/agent-fleet/issues/3369),
  [#3399](https://github.com/k-k1/agent-fleet/issues/3399))
- **Amazon Corretto の JDK。** 設定 › ツールチェーン で、Java のメジャーごとに Temurin と並んで Corretto
  を選べ、両方を並べてインストールできます。
  ([#3411](https://github.com/k-k1/agent-fleet/issues/3411))

### 改善

- **ecs-ec2 のスロットが Amazon の AMI 更新に自分で追従。** Control Plane が現行の ECS 最適化 AMI を
  約 1 時間ごとに読み、それでスロットを起動します。古い AMI のスロットは次の起動で置き換わり、スロット
  タブには古いとされた理由が出ます。
  ([#3318](https://github.com/k-k1/agent-fleet/issues/3318))
- **クラウドコマンドの実行行が、それを実行したツール呼び出しの中にたたまれます。** 繰り返しは件数つきの
  1 行にまとまり、`af-gcloud-exec` の実行も `af-aws-exec` と同じように記録されます。
  ([#3329](https://github.com/k-k1/agent-fleet/issues/3329))
- **期間のプリセット:** 稼働時間・クラウド費用・稼働のヒートマップに **今月**・**先月**・**直近30日**。
  ([#3383](https://github.com/k-k1/agent-fleet/issues/3383))
- **会話・チャット・文書の中の Issue とプルリクエストの URL** は、`#N` の参照と同じようにワークアイテムの
  モーダルで開きます。([#3365](https://github.com/k-k1/agent-fleet/issues/3365))
- **egress の enforce でもワークスペース自身のインストールが動きます:** 設定 › ツールチェーン とエージェント
  CLI のダウンロード元を既定で許可します（`storage.googleapis.com` は、Antigravity と x64 の Chromium の
  ために、引き続き必要なら追加してください）。
  ([#3432](https://github.com/k-k1/agent-fleet/issues/3432))
- **設定 › エージェント の表示が速くなり**、Console を放置している間はリポジトリ一覧の取得を控えます。
  ([#3385](https://github.com/k-k1/agent-fleet/issues/3385),
  [#3333](https://github.com/k-k1/agent-fleet/issues/3333))

### アップグレードの注意

- **ECS のデプロイ:** いつもどおり `update.sh` を実行してください。`20-platform` がデプロイされ、
  Control Plane が Amazon の AMI パラメータを読めるようになります。それまでスロットはスタックの AMI の
  ままです。アップグレード後に最初の新しい AMI が出ると、すべてのスロットが一度に古い扱いになり、それぞれ
  次の起動で置き換わります。
  ([#3318](https://github.com/k-k1/agent-fleet/issues/3318))
- **AWS の egress ゲートウェイ（`tcp:` エントリを使う場合だけ）:** `00-network` を手でデプロイして
  ください（`update.sh` はデプロイしません）。ゲートウェイのインスタンスが置き換わるので、数分間
  ワークスペースから外へ出られません。enforce に切り替える前に、各宛先のファイアウォールでゲートウェイの
  送信元アドレスを許可してください。詳しくは ECS の README の「Egress gateway」にあります。
  ([#3369](https://github.com/k-k1/agent-fleet/issues/3369))
