モデルの取り込みがテナント管理者にも開かれ、配備自身の ComfyUI での画像生成が
編集・インペイント・LoRA・seed に対応し、画像エンジンを Spot で買えるようになりました。
メンバーの home ディスクを止めずに拡張でき、課題管理で開いたプルリクエストにレビューと
CI の状態が出ます——GitHub のプルリクエストも再び出るようになりました。

### New

- **テナント管理者がモデルを検索して取り込めます。** super admin がテナントのダイアログで
  許可すると、そのテナントの管理者のテナント設定に「推論エンジンのモデル」が現れ、検索・
  取り込み・自分のテナントの取り込みジョブ・カタログ（表示のみ）が使えます。モード・GPU の
  クラス・有効化・Hugging Face のトークンは super admin のままです。
- **配備自身の ComfyUI での画像生成が編集とインペイントに対応しました。** 5 つのモデル
  ファミリーすべてで使えます。要求に LoRA（重み付きで 4 本まで）と seed を付けられるので、
  同じ絵を再現できます。モデルがまだインスタンスへ同期中のうちに届いた要求は、失敗せずに
  待つようになりました。
- **画像エンジンの箱を「提案（offer）の一覧」から選びます。** そのうち 1 つを Spot に
  できます。`params/60-engines` の `ImageOffers` に買ってよいものを順に並べると、上から
  試し、箱が来なければ次へ落ちます——Spot の在庫が無い日でもエンジンは起動します。
  何も書かなければ、これまでどおり全部オンデマンドです。llm 役に Spot の行はあえて
  用意していません——会話の途中で終了予告が来ると、コールドスタートをやり直すことになる
  ためです。
- **llm エンジンも LoRA を受け付けます。** カタログのモデルの上に LoRA の行を登録すると、
  固定の preset として提供されます。
- **分割されたモデルを 1 行として登録できます。** 取り込み・登録フォームでモデルファミリーと
  複数のファイルをそれぞれの役割（拡散モデル・テキストエンコーダ・VAE）付きで指定でき、
  既存の行にファイルを足せます。Hugging Face や Civitai の URL を貼ると各欄に展開されます。
- **メンバーの home ディスクを止めずに拡張できます**（ecs-ec2）。メンバー詳細で `disk_gb` を
  増やすと既存のボリュームがオンラインで広がります。減らしてもボリュームはそのままです。
  メンバー詳細は「サイズと上限」「操作」「取り消せない操作」に並べ直しました。
- **隔離されたスロットを Console から終了できます**（ecs-ec2）。確認の前に ID と隔離の理由が
  出て、理由は監査ログに残ります。
- **課題管理でプルリクエストを開くと、その場で取り直します。** 下書きか・競合の有無・
  レビューの状況・CI の結果・base と head・差分の量が出ます。主ボタンは GitHub / Bitbucket
  で開くになり、セッションの起動はその下に移りました。
- **設定 > 環境に、上流の CLI リリース監視が生きているかが出ます。** 取得元が失敗しているか、
  最終成功が 48 時間より古いときだけ警告します。Control Plane が公開の GitHub issue を匿名で
  読んでおり、外向き通信の無い配備ではこの行が出ないだけです。

### Improved

- **取り込み画面のモデル検索で分かることが増えました。** Hugging Face / Civitai のページへの
  リンクと公開日が出て、カタログの各行にライセンスと、非商用のものは誰がいつ同意したかが
  出ます。検索結果を選ぶとそのままファイル一覧へ進み、手登録のモデルにもライセンスを
  書けます。
- **llm エンジンの VRAM 判定に KV キャッシュが入りました。** モデル自身のヘッダから読むので、
  載らない GPU クラスを勧めなくなりました。梯子の `vramMiB` はカードの物理量で書きます
  （L4 なら 22000）。
- **エンジンが動いている間に有効化したモデルが、再起動なしで届きます。** エンジンのタブも
  読みやすくなりました。ボタンはボタンらしく、有効/無効はバッジに、検索結果はカードに
  なり、ComfyUI が実際に使った VRAM は梯子を決める人のために CloudWatch へ出ます。
- **セッションを起こしたセッションが、その子の題名を付け替えられます。** 人が Console で
  付けた題名は変えられません。
- **ミラーのセッションと会話のリンクに、マウスオーバーで題名が出ます。**
- **左ペインのスケジュールがアシスタントの直下に来ました。**
- **エージェントの種別と接続サービスが各社のブランドマークで出ます。** セッション一覧・
  設定のカード・ワークスペースバーのいずれもです。
- **認証情報を保存しなかった Subversion のチェックアウトに、後から入れられます。** 行の
  メニューか設定 > 接続からで、セッション内で直接叩く `svn` にも効きます。SVN の
  チェックアウトからの引き継ぎで worktree を勧めなくなりました。

### Fixed

- **配備自身の ComfyUI での画像生成が、Console だけの設定では最後まで通りませんでした。**
  SD3.5 は 1 枚も出ず、ファミリーを宣言していないモデルは使えず、モードの変更が稼働中の
  セッションに届かず、インスタンスの入れ替わりをまたいだ生成は再試行せずに失敗して
  いました。provider を指定しないときは、自分の Antigravity や Codex のプランより先に
  配備自身のエンジンを試すようになりました。
- **Control Plane の入れ替え直後に、ツール一覧にある `generate_image` が「許可されていない
  ツール」として拒否されることがありました。**
- **課題管理に GitHub のプルリクエストが出ませんでした。** 既定のクエリが違うものを訊いて
  いました。保存済みのクエリは書き換わらないので、Upgrade notes を見てください。
- **適用に失敗した GPU クラスをやり直せず**、梯子を変えても Control Plane を入れ替えるまで
  届きませんでした。
- **モデルの取り込み**: 行を purge すると他の行がまだ使っているファイルまで消え、必要な
  ファイルの足りない行が有効化でき、ログインの要る Civitai の資産と規約に同意していない
  Hugging Face のリポジトリが一般的な失敗として返っていました。
- **`<repo url>` のような山括弧の語が、ミラーとビュアーで消えていました。**
- **メモ**: 展開した長いメモを畳めず、1 件だけの送信に見出しと項番が付いていました。
- **CloudFormation のパラメータ説明で、ASCII でない文字が `?` になっていました。**

### Upgrade notes

- **推論エンジンを使っている ECS の配備は、更新の前に `params/60-engines` に使っている
  役ごとの `LlmEnabled=true` / `ImageEnabled=true` があることを確かめてください。** モデル
  系のパラメータ 6 つ（`LlmModelS3Key`・`LlmModelIds`・`LlmContextTokens`・
  `LlmMaxOutputTokens`・`ImageModelS3Key`・`ImageModelIds`）がテンプレートから無くなり、
  モデルは Console のカタログから選びます。モデルのキーを書くだけで役を立てていて
  `Enabled` が空の配備は、普通のスタック更新で役が——動いているエンジンごと——黙って
  消えます。`standup.sh` と `update.sh` はこのスイッチを引き継いで標準出力にそう言いますが、
  手で打つ `aws cloudformation deploy` は引き継がないので、同じ更新で
  `<役>Enabled=true` を渡してください。詳細は
  `deploy/aws/ecs/cfn/PARAMETERS-60-engines.md` の "Upgrading" にあります。
- **この版で最初に回す `update.sh` は `20-platform` も更新します。** 新しい `af-engine-tools`
  イメージ（エンジンの fetch と取り込みの手順がテンプレートからここへ移りました）の ECR
  リポジトリと、home ディスクを広げる権限を足すためです。スクリプトは change set を先に
  印字し、何も置き換えないときだけ実行してから、イメージを GHCR から ECR へ写して
  60-engines を配備します。印字を読む以外にすることはありません。イメージが GHCR に無いと
  言われたら、先に `engine-tools-image` ワークフローを回してください。
- **`ImageCapacityOptionType` は撤去しました。**これまで設定していない配備は何もせずに
  更新できます（capacity provider が 1 本増えるだけで、挙動は変わりません）。
  🔴 **いま `ImageCapacityOptionType=SPOT` で走っている配備は、先に `ON_DEMAND` へ戻す更新を
  現行の版で流してから**この版を取り込んでください——新しい Spot の provider が、古い provider が
  持っている名前を要求するので、飛ばすと同名衝突で失敗しロールバックします。そのあと
  `params/60-engines` からこの行を消します。
- Spot は `ImageOffers` に `spot` の行を書いたときだけ使われます。書く前に、Spot を一度も
  使っていないアカウントなら service-linked role（`AWSServiceRoleForEC2Spot`）を作り、Spot の
  クォータ（`L-3819A6DF`・既定は 0）を確かめ、その行に複数のインスタンス型を並べてください
  ——1 型だけでは在庫不足で断られました。書式は
  `deploy/aws/ecs/cfn/PARAMETERS-60-engines.md`「The offers」にあります。
- どのテンプレートも change set に説明文だけの差分が多数出ます（非 ASCII の除去と散文の
  短縮）。挙動は変わりません。
- **課題管理の保存済み GitHub クエリは書き換わりません。** ⚙ > 課題管理で
  `is:open involves:@me` に直してください（レビュー待ちも見るなら 2 本目に
  `is:open review-requested:@me`）。クエリの `OR` は、ワークスペースを新しいイメージで
  起動し直してから効きます。
- 0.17.0 以前から上げる場合は 0.18.0 のノートも当てはまります——アーキテクチャの綴りで
  Control Plane が 1 度入れ替わり、`LlmModelFile` / `ImageModelFile` も無くなっています。

エージェント CLI のピン: Claude Code 2.1.268 / Antigravity 1.2.1。ほかは 0.18.0 から
変わっていません。
