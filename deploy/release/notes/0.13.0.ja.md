GitHub / Jira / Bitbucket の課題・プルリクエストが左ペインに並び、その 1 件から作業を
始められるようになりました。`ecs-ec2` ではワークスペースごとにメモリ上限が入り、重い
ワークスペース 1 つが箱ごと巻き添えにすることがなくなります。

### New

- **作業項目（GitHub の Issue / PR、Jira の課題、Bitbucket の PR）が左ペインに並び、
  その 1 件から作業を始められます。** 行を開くと内容が出て、そこから起動先（リポジトリ、
  新規または既存の worktree）を選ぶと、プロンプト・セッション名・ブランチ名まで入った
  状態で始まります。一覧は Workspace が停止中でも出ます——「止まっている Workspace を
  チケットから起こす」のがこの機能の要だからです。
- **接続はテナントごとに GitHub / Jira / Bitbucket。** Jira は API トークンでも OAuth でも
  つながり、設定には「課題管理」タブができました。並ぶのは保存クエリの結果で、絞り込みの
  UI ではなくクエリそのものを編集します。
- **作業の報告をチケットへ書き戻せます。** ブランチと変更ファイルという事実は Agent Fleet が
  下書きし、文章は利用者が書いて投稿ボタンを押します。自動では投稿されず、エージェントから
  この経路には到達できません。要約も生成しません。
- **`ecs-ec2` のワークスペースにメモリ上限が入りました。** 1 つのワークスペースが箱の管理系
  まで枯渇させることがなくなります（実際にスロットが数時間死にました）。表示されるサイズは
  実際に使える方で、箱の大きさは括弧で添えます。プールのディスクが飽和したときにメールで
  知らせる警報も選べます（既定は OFF）。

### Fixed

- **Workspace が二度と起動できなくなり、毎回 504 が返ることがありました。** 外からは箱が
  健康に見えるのに、中の OS が死んでいる状態です。そうした箱は待たずに捨て、Workspace を
  別の箱へ置き直すようにしました。
- **狭い画面（実際にはスマートフォン）で、実行中のターンが「入力待ち」と表示されて**
  いました。
- **他のセッションから届いたメッセージが、自分の発言のように見えていました。** どこから
  来たかを示すバッジが付かないことがありました。
- **退役したモデルで起動に失敗したとき、理由が利用可能なモデルの一覧に埋もれて**
  いました。近い候補を挙げ、そのモデルが退役したことを述べるようにしました。
- **環境変数に `CI` を足すと、Cursor のセッションがバナーだけの死んだ画面になって**
  いました。打鍵も無視されます。Cursor はこの変数を見つけると対話 UI を出さないので、
  CLI へ渡さないようにしました。

### Upgrade notes

`ecs-ec2` のワークスペースはメモリ上限付きで動きます。箱は自分の管理系のために予備を
確保し（公称サイズの 1/5・1〜2 GiB の範囲）、残りが利用者の取り分です。`Ec2HostReserveMb`
（`AF_ECS_EC2_HOST_RESERVE_MB`）で変更・無効化でき、`PoolAlarmEmail` でディスク飽和の
警報を有効にできます（既定は OFF）。使える量が箱の大きさと一致しなくなるため、画面には
両方を出します。

エージェント CLI の固定版：Claude Code 2.1.247、Codex 0.150.1、Copilot 1.0.81、
Antigravity 1.1.22、Cursor 2026.08.25、Kiro 2.20.1。その他は 0.12.4 から変わりません。
