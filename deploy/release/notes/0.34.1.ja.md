0.34.0 で出た `/mcp` エンドポイントと MCP のサインイン（OAuth）を、ECS のデプロイでも有効にできるように
なりました。0.34.0 のテンプレートには、これらを設定する手段がありませんでした。

### 改善

- **ECS: `/mcp` と MCP のサインインのスタックパラメータが加わりました。** `30-ingress` スタックの
  `McpEnabled`・`McpOAuth`・`McpOAuthTrustedHosts` が、対応する Control Plane の変数を設定します。3 つとも
  既定はオフなので、設定するまでアップグレードで何も変わりません。
  ([#2595](https://github.com/k-k1/agent-fleet/issues/2595))
- **ECS: Control Plane の設定が 3 つ、`30-ingress` から設定できるようになりました**（`SessionTtl`・
  `GithubAllowedEmails`・`KmsDataKeyCacheTtl`）。既定は空で、今の挙動のままです。
  ([#2595](https://github.com/k-k1/agent-fleet/issues/2595))

### 修正

- **compose の `.env.example` の `AF_MCP_ENABLED=1` のコメントを外しても、`/mcp` はオフのままでした。**
  Control Plane が受け付けるのは `true` だけだからです。例は `true` になり、MCP のサインインの設定と並べました。
  ネイティブ実行とローカル開発用スクリプトも、MCP のサインインの変数を渡すようになりました。
  ([#2595](https://github.com/k-k1/agent-fleet/issues/2595))

### アップグレードの注意

- **ECS のデプロイ:** いつもどおり `update.sh` を実行してください。0.34.0 を飛ばした場合は、0.34.0 の注意にある
  `20-platform` と `40-ec2-pool` の適用も必要です（`update.sh` が両方行います）。MCP のサインインつきで `/mcp` を
  有効にするには、`30-ingress` を `--parameter-overrides McpEnabled=on McpOAuth=on` でもう一度デプロイします。
  ほかのパラメータは値をそのまま引き継ぎます。完全なコマンドは ECS の README にあります。`McpEnabled=on`
  がない限り、Personal Access Token を含めて `/mcp` はオフのままです。
