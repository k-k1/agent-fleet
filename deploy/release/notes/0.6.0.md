An agent can now hand you the browser page it is driving, so you take over for the
final click; the Console speaks English end to end instead of falling back to
Japanese. **Docker Compose installs change in this release: the container images
are pulled from GHCR instead of being loaded from an image tarball.**

### Breaking changes (Docker Compose edition only)

- **Images now come from a registry.** Releases no longer carry
  `agent-fleet-images-<version>.tar.gz`; the control-plane and workspace images
  are published to GHCR as `ghcr.io/k-k1/agent-fleet/control-plane:<version>` and
  `ghcr.io/k-k1/agent-fleet/workspace:<version>`. Installing goes from
  "download the tar → `load-images.sh`" to `docker compose pull`, which is what
  `install-compose.sh` and the bundled runbook now do. No registry login is
  needed — the packages are public.

  Upgrading an existing deployment: set `REGISTRY=ghcr.io/k-k1/agent-fleet` and
  `VERSION=0.6.0` in your `.env`, point `WS_IMAGE` at
  `ghcr.io/k-k1/agent-fleet/workspace:0.6.0`, then `docker compose pull` and
  `docker pull "$WS_IMAGE"` in place of the old `load-images.sh` step. Your data,
  `AF_MASTER_KEY` and every other setting are untouched.

  A host that cannot reach a registry has two supported paths: mirror the two
  images into an internal registry and point `REGISTRY` at it, or build and
  export them yourself with `deploy/compose/release.sh --save` and keep using
  `load-images.sh`. The script and the air-gap runbook stay in the bundle for
  exactly this.

  Why: the image tar was never the offline install it looked like — the images
  are lean, so a workspace still fetches the agent CLIs from their vendors on
  first start, and an agent is useless without reaching its model endpoint. Its
  one real benefit was "no registry required", at a cost of ~960 MB per release.

- **The native edition and the AWS/ECS path are unaffected.** The native
  one-liner install and `af start` are unchanged, and ECS still pushes to ECR.

### New

- **Hand a browser page to a human.** When an agent is driving a headless
  Chromium in your workspace — filling in a form, working through a site — it can
  now pass that live page to you: it gives you a link, the page opens in a Console
  pane, and you click, scroll and type in it (Japanese IME included) before
  handing it back. Detaching closes only the Console's view; the agent's browser,
  page and session stay alive. The agent never performs the final publish, send or
  consent click for you — that hand-off is the point.
- **Show reasoning expanded, per agent.** Codex and OpenCode reasoning blocks were
  always collapsed in the session chat and had to be opened every turn. Settings ›
  Agents › (each card) › behaviour now has *Expand thinking*, set independently
  per agent kind. Off by default, so nothing changes unless you turn it on.

### Improved

- **The Console speaks your display language.** With the display language set to
  English, the built-in assistants (guide, fleet, operator, SRE) now answer in
  English rather than Japanese — their personas were the single biggest reason
  replies fell back. Reply suggestions, compaction handoffs, work plans and
  ad-hoc file actions follow the display language too. Personas are snapshotted
  when a conversation is created, so switching applies to new conversations and
  leaves open threads alone.
- **Completion reports are readable in either language.** A report card used to be
  one string serving two readers — you, and the operator assistant it is fed to as
  a prompt. The two are now separate: the card states the facts and is rendered in
  your display language, while the instructions are built at injection time. As a
  side effect the card no longer shows model-facing text like "check with
  get_session_output".
- Pinned CLI versions: Claude Code 2.1.220, Codex 0.146.0, OpenCode 1.18.11,
  GitHub Copilot 1.0.77, Antigravity 1.1.9, Cursor 2026.07.23, Kiro 2.16.0,
  rtk 0.44.2.

### Fixed

- **The usage chip in the workspace bar could freeze for a day.** Claude's status
  line is wrapped so the fleet can capture rate-limit data from it, and the check
  for "did we already wrap this?" compared executable paths. Any run from a
  different path re-wrapped the existing command, shell-quoting the whole thing
  each time — one fleet reached 13 layers and 798 KB, at which point the status
  line could no longer be executed at all and usage capture silently stopped. The
  wrapper is now identified by a marker instead of a path, its own layers are
  stripped before re-wrapping, and an oversized result falls back to
  capture-only. Existing broken configurations repair themselves on next start.

### Upgrade notes

Nothing to migrate. **Compose deployments must switch to registry pulls** — see
the breaking-changes section above for the exact `.env` edits; the "Air-gapped
install" section of the bundled runbook covers hosts with no registry access.
Native installs update with the usual one-liner. *Expand thinking* is off by
default; the language changes apply to conversations created after the upgrade.
