A maintenance release for AWS deployments, from standing one up end to end. Read-aloud
never worked on ECS at all, a workspace created after the Control Plane started could
not be reached from it, and the two screens a brand-new deployment shows first — the
first-run guide and the reason a workspace will not start — were blank. Bitbucket can
now be connected on ECS as well.

### Fixed

- **A workspace created after the Control Plane started was unreachable from it.** Every
  Console panel that reads the workspace — sessions, repositories, the file tree, tool
  versions, chat — answered 502, while the workspace itself was running normally. The
  cause is a property of AWS Service Connect: a client alias is not DNS, it is a line the
  ECS agent writes into the task's `/etc/hosts` when the task starts, so a service added
  to the namespace afterwards is invisible to a task that is already running. Nothing
  healed it — not time, not a workspace restart — only replacing the Control Plane task.
  In practice that meant **the first workspace of a fresh deployment, and every new
  member's first workspace**, were dead until somebody restarted the Control Plane.
  Resolution now falls back to Cloud Map when the alias cannot be resolved.
- **Read-aloud on ECS always failed.** The Control Plane calls Amazon Polly with its task
  role, but the role was never granted `polly:SynthesizeSpeech`, so every attempt ended in
  a 502. It failed in the worst way: the provider reports itself ready on the presence of
  a region alone, so the Console kept offering playback and only the click failed.
- **The voice shown while speaking could name a character that was not speaking.** With
  the engine set to automatic, the Control Plane decides where each sentence goes, but the
  Console labelled the playback from the settings alone — so a deployment without a
  VOICEVOX engine showed a VOICEVOX character while Polly was reading. The volume
  adjustment meant for that character was applied on the same mistaken basis.
- **A workspace that could not start said nothing.** The reason was returned and thrown
  away: the button flashed "starting" and settled back on "unknown" with no message. The
  state now reads *No tenant* rather than *Unknown* when that is the cause, the tooltip
  says what to do next, and any failure to start is reported.
- **The first-run guide never appeared for a new user.** It was attached to the empty
  state of a terminal pane, but a new user's Console opens with no pane at all — so the
  one audience it exists for was the one that never saw it.

### New

- **Bitbucket can be connected on ECS.** The OAuth consumer's key and secret had no way
  into a CloudFormation deployment, leaving those installations with only the email + API
  token paste. Set `BitbucketOauthKey` and put the secret at
  `<SsmPrefix>/bitbucket-oauth-secret`; the consumer's callback URL must be exactly
  `https://<your-fqdn>/api/oauth/bitbucket/callback`.

### Improved

- Settings for VOICEVOX — its speaker, the character list, emotional styles, the pause
  after particles and the katakana reading of English — are hidden on deployments that
  have no VOICEVOX engine, where they could be chosen but never took effect. The engine
  itself is dropped from the choices there, and the administrator's engine toggle is held
  at *off* with the reason, instead of appearing switchable.

### Upgrade notes

No migration. Two of the fixes are in the CloudFormation templates rather than the image,
so an ECS deployment should re-deploy the stacks as well as move the tag:

- `20-platform` grants the Control Plane `polly:SynthesizeSpeech`. Without re-deploying it,
  read-aloud stays broken on this release too. It is an IAM-only change; the running task
  picks it up without a restart.
- `30-ingress` gained `BitbucketOauthKey` (optional).
- The README's stand-up procedure was missing `--capabilities CAPABILITY_AUTO_EXPAND` for
  `10-data`, which declares `Transform: AWS::LanguageExtensions`. Following the old
  procedure verbatim failed with `Requires capabilities`.
