AWS デプロイ向けの保守リリースです。実際に 1 本立ち上げて分かった問題を直しました。
ECS では読み上げがそもそも動いておらず、Control Plane の起動後に作られた Workspace に
到達できず、新規デプロイが最初に見せる 2 つの画面が空白でした。

### Fixed

- **Control Plane の起動後に作られた Workspace に、Control Plane から到達できません
  でした。** Workspace 自体は正常に動いているのに、それを読む Console の画面がすべて
  502 を返し、Control Plane のタスクを置き換える以外に回復手段がありませんでした。実際
  には、新規デプロイの最初の Workspace と、新しいメンバーの最初の Workspace が、誰かが
  再起動するまで死んでいたことになります。解決できないときは Cloud Map へ退避します。
- **ECS で読み上げが常に失敗していました。** Control Plane のタスクロールに
  `polly:SynthesizeSpeech` が付与されていませんでした。最悪の形で失敗します——プロバイダ
  自身は「使える」と報告するので、Console は再生を提供し続け、押した瞬間だけ失敗します。
- **再生中に表示されるボイスが、実際に話していないキャラクターを指すことがありました。**
  そのキャラクター向けの音量調整も同じ誤りの上で適用されていました。
- **起動できない Workspace が何も言いませんでした** — ボタンが「起動中」を一瞬出して
  「不明」に戻るだけでした。原因がそれなら*テナント無し*と表示し、起動の失敗は必ず
  報告します。
- **新規ユーザーに初回ガイドが出ませんでした。** ターミナルペインの空状態に紐づいて
  いましたが、新規ユーザーの Console はペインが 1 つも無い状態で開きます。

### New

- **ECS で Bitbucket を接続できます。** `BitbucketOauthKey` を設定し、シークレットを
  `<SsmPrefix>/bitbucket-oauth-secret` に置いてください。コンシューマのコールバック URL は
  `https://<your-fqdn>/api/oauth/bitbucket/callback` と完全に一致する必要があります。

### Improved

- VOICEVOX エンジンの無いデプロイでは、VOICEVOX 関連の設定を隠しました。選べるのに何も
  効かない状態でした。

### Upgrade notes

修正のうち 2 件はイメージではなく CloudFormation テンプレート側にあるので、ECS の
デプロイはタグの移動に加えてスタックの再デプロイが必要です。

- `20-platform` が Control Plane に `polly:SynthesizeSpeech` を付与します。再デプロイ
  しないと、本リリースでも読み上げは壊れたままです。IAM のみの変更なので、稼働中の
  タスクは再起動なしで拾います。
- `30-ingress` に `BitbucketOauthKey`（任意）が加わりました。
- README の構築手順に、`10-data` の `--capabilities CAPABILITY_AUTO_EXPAND` が抜けて
  いました。旧手順のままだと `Requires capabilities` で失敗します。
