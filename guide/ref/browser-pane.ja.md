# ブラウザペイン — 利用契約

[English](browser-pane.md) | 日本語

ワークスペースの中で動いている Web アプリを見せる手段は 2 つあり、**選び間違えるとやり取りが
1 往復無駄になります**。このページは、その両方の約束ごとをまとめたものです。

## 2 つの経路

| 用語 | 約束ごと |
|---|---|
| **ブラウザペイン**（ボタンは「ペインで開く」）| ワークスペース内の Chromium が `http://127.0.0.1:{port}{path}` を直接開き、描画と入力だけを Console のペインへ中継する。HMR・WebSocket・SSE・cookie・リダイレクト・絶対パスのアセット、そして**人が操作する必要があるもの**はこちら。|
| **軽量プレビュー** | HTTP プロキシを新しいタブで開く低負荷の経路。JSON・ヘルスチェックのエンドポイント・単純な静的ページを**一度見るだけ**の用途に限る。HMR / WebSocket / SSE は使えず、ルートパス・絶対パスのアセット・リダイレクト・cookie のパスに依存するアプリの動作は保証しない。|
| **Page** | ペインが持つ一時的な Chromium の Page と、それ専用のブラウザコンテキスト。ワークスペースあたり何個まで持てるかは[上限](limits.ja.md#製品として固定のもの)にあり、Page 同士で cookie もストレージも共有しない。|

**迷ったらブラウザペインを使います。** 軽量プレビューは「HTTP の応答を 1 回見るだけ」と言い切れる
ときに使う、リソースを節約するための例外です。

どちらの開き方（ポートとパスの欄、どのボタンが既定になるか）もメンバー向けの手順で、
[起動した Web アプリを見る](../user/preview/browser-pane.ja.md#開く)にあります。ポート `7700` は Agent 自身が使うので開けません。

## どちらを選ぶか（代表例）

構成別の表（Node / Vite、Spring Boot、API のみ、フロントエンド + API）は
[起動した Web アプリを見る — 構成ごとの例](../user/preview/browser-pane.ja.md#構成ごとの例)にあります。原則は、HMR・WebSocket・SSE・
cookie・リダイレクト・絶対パスのアセットが要るものはブラウザペイン、HTTP の応答を 1 回見るだけなら軽量プレビューです。

## 状態と復旧

ペインに出る 3 つの状態（`target-unreachable`・`disconnected`・`crashed`）の意味と対処は
[起動した Web アプリを見る — 困ったとき](../user/preview/browser-pane.ja.md#ペインに状態が出て画面が出ない)にあります。
その前提として、復旧のための操作（再接続・Console の再読み込み・ワークスペースの停止 → 起動）はどれも、
現在のポートとパスから**新しい Page を作る**ため、cookie・ストレージ・入力途中の内容は復元されません。

## ライフサイクルとリソースの上限

- 表示中のブラウザ接続があるあいだは、ワークスペースは停止せずに動き続けます。
- ペインが非表示になるか、Console を開いているブラウザのタブがバックグラウンドになると、描画を止めます。
  Page は猶予（[上限](limits.ja.md#製品として固定のもの)参照）のあいだだけ保持してから解放します。戻ったとき、保持中なら同じ Page を使い、解放後なら
  保存済みのポートとパスから新しい Page を作ります。
- ペインそのものをレイアウトから取り除くと、Page を解放します。ペインが残る場合
  （最後のペインを閉じて空の表示に戻したときなど）は上の猶予の扱いになり、**その猶予中も
  Page の上限を消費することがあります**。
- ワークスペースを停止すると一時的な Page は捨てますが、レイアウトに保存したポートとパスは残ります。起動後、
  表示中のペインは同じ接続先から自動で作り直されます。
- 上限（Chromium のプロセス数・同時に開ける Page の数・ビューポート・フレームレート）は
  [上限](limits.ja.md#製品として固定のもの)にあります。
  **動画や高いフレームレートが要る確認には使わないでください。**

## 範囲と既知の制約

- **汎用のブラウザではありません。** トップレベルで移動できるのはループバックの HTTP(S) だけで、
  外部へのリダイレクトは止めます。
- Console のドロワーは、接続中の Page のコンソールメッセージと捕捉されなかったエラーを、上限つき（[上限](limits.ja.md#製品として固定のもの)）で
  保持し、`error` / `warn` を先に見せます。**永続的なログではなく、DevTools の代わりにもなりません**
  （DOM・Network・Sources・Storage はありません）。
- アップロードとダウンロード・クリップボード・ドラッグ & ドロップ・音声・動画・WebRTC・権限の確認ダイアログ・
  複数のタブは対象外です。
- **スマートフォンでは入口が `⋯` の中に移ります。** スマートフォンの幅ではワークスペース操作バーに
  「プレビュー」ボタンがなく、右端の `⋯` を開くと、同じポート／パスの欄と「ペインで開く」が
  並んだポップオーバーが出ます。そこから先はデスクトップと同じです（ツールバー・キャンバスのタップ・
  日本語入力・Console のドロワー）。

## ブラウザペインが無い配備

ワークスペースを `kubernetes` ランタイム（プレビュー版。[配備形態](deploy-targets.ja.md)）または `ecs`（Fargate）で動かす配備には、**ブラウザ機能が一切ありません**。
ブラウザペインも、エージェント向けの Chromium の接続も、ヘッドレス Chromium もありません。
`kubernetes` のワークスペースの Pod は Pod Security の `restricted` レベルで動きます。このレベルでは NoNewPrivs が立ち
（setuid の `chrome-sandbox` が権限を上げられない）、ランタイム既定の seccomp プロファイル
（ユーザー名前空間を作れない）もかかります。Fargate のタスクには `SYS_ADMIN` を足せないため、
同じ既定の seccomp が、setuid ヘルパーが作ろうとする名前空間を拒否します。どちらの場合も Chromium のサンドボックスが
起動できません。サンドボックスなしで Chromium を動かすことはしない方針です。
`ecs-ec2`・`docker`・`native` はこの制約を受けません。

代わりに、次のように表示されます。

- **プレビュー**の「ペインで開く」は押せない状態で表示され、ツールチップと下のヒントが理由を示します。
  **軽量プレビュー**はほかの配備と同じく使えます。
- セッション行のポートは、ペインではなく軽量プレビュー（新しいタブ）で開きます。
- 保存済みのレイアウトから復元されたブラウザペインは、ページの代わりに理由を表示し、同じポートとパスを
  軽量プレビューで開くボタンを出します。同じように復元された Chromium の接続のペインは、開くローカルの
  ポートがないので理由だけを表示します。
- エージェントにはブラウザツールそのものが提示されません。それでも名前で呼んだ場合は、同じ説明を付けて
  `browser_unavailable` を返します。

これは配備のランタイムで決まるので、その配備の全メンバーで同じです。ワークスペースが止まっているあいだも表示されます。

## ワークスペースの中で働くエージェントへ

**あなたには、このペインを開く・操作する・見るツールがありません。** ペインは人のものです。
正確なポートとパスを伝え、プレビュー →「ペインで開く」へ案内してください。
**自分で見ていないペインを根拠に「表示は正しい」と言わないでください。** 自分で確かめる
必要があるなら、自前のヘッドレス Chromium を動かし、そうしたことを明記してください。
環境変数 `AF_BROWSER_UNAVAILABLE` が設定されているワークスペースには、ペインもヘッドレス Chromium も
ありません（[上](#ブラウザペインが無い配備)）。テストと HTTP での確認で確かめ、人には軽量プレビューを
案内し、画面は確認していないとはっきり伝えてください。
