# リポジトリ種別 — 何に対応しているか

[English](repos.md) | 日本語

作業コピーがどこから来られるか、来た後に Console が何をできるか。差は見た目の話では
ありません——**横断検索の無いプロバイダは作業項目の受信箱の駆動方法を変え、
プルリクエストの無いプロバイダはレビュー導線に出せるものを根本から変えます**。

✓ = 対応、— = 非対応 / 該当なし。

| 機能 | GitHub | Bitbucket | 内部 git | SVN | ローカル |
|---|:--:|:--:|:--:|:--:|:--:|
| Console からアカウント接続 | ✓ | ✓ | ✓¹ | ✓² | — |
| OAuth でサインイン | ✓³ | ✓ | — | — | — |
| トークン / アプリパスワードでサインイン | ✓ | ✓ | ✓¹ | ✓² | — |
| テナントが登録した OAuth アプリ | ✓ | ✓ | — | — | — |
| リポジトリの一覧と選択 | ✓ | ✓ | ✓ | — | — |
| private リポジトリ | ✓ | ✓ | ✓ | ✓ | ✓ |
| クローン / チェックアウト | ✓ | ✓ | ✓ | ✓ | ✓⁴ |
| 認証を透過した push | ✓ | ✓ | ✓ | ✓ | — |
| ブランチと worktree | ✓ | ✓ | ✓ | —⁵ | ✓ |
| コミットグラフと差分 | ✓ | ✓ | ✓ | —⁵ | ✓ |
| 大きなファイル（LFS）| ✓ | ✓ | ✓ | — | ✓ |
| 受信箱に Issue を出す | ✓ | — | — | — | — |
| 受信箱にプルリクエストを出す | ✓ | ✓⁶ | — | — | — |
| リポジトリ横断の検索 | ✓ | —⁷ | — | — | — |
| 項目への書き戻し（コメント）| ✓ | —⁸ | — | — | — |

¹ 内部プロバイダは配備自身がホストし、資格情報はメンバーシップ毎に**都度導出**されます
（保存しません）。接続する手順そのものがありません。

² URL ＋ 基本認証。自己署名証明書はチェックアウト毎に明示的に信頼できます。

³ GitHub は Copilot エージェントの接続も兼ねます。GitHub を接続すると Copilot も
接続され、切ると一緒に切れます。

⁴ 「ローカル」はリモートの無い作業コピー——ここで始めた新規フォルダや、自分で
クローンしたもの。動きますが、どこへも push されません。

⁵ SVN のチェックアウトはフラットな作業コピーです。ブランチ・worktree・コミット
グラフの画面は git の形をしているので該当しません。

⁶ Bitbucket が出すのは**プルリクエストだけ**で、課題トラッカーは読みません。

⁷ **Bitbucket にはリポジトリ横断の検索 API がありません。**クエリはワークスペース
（普通はリポジトリも）を名指しする必要があります。Console はそのクエリを**書かせずに
組み立てます**——ワークスペースの無いクエリは空で返り、それは
「自分に割り当てが無い」と**見分けがつきません**。

⁸ 読み取りだけを足したのは意図的です。コメントの投稿にはアプリのより広い権限が要り、
それは**テナント管理者が権限を広げ、全員が再認可する**変更になります。一覧を出すために
払う値段ではありません。Console は Bitbucket の行にそのボタンを出しません。

## 課題管理は別の軸

トラッカーはコードのホストと同じ製品とは限りません。Jira は Bitbucket や GitHub の
隣に座り、別に接続します。

| トラッカー | 出すもの | 書き戻し |
|---|---|---|
| GitHub | Issue とプルリクエストを 1 つのクエリで | ✓ コメント |
| Jira | Issue | ✓ コメント |
| Bitbucket | プルリクエスト | — |

**プロバイダからの 404 は「無い」の根拠には決してなりません。**「あなたには見えない」
とも完全に整合するので、それを不在として扱うと**受信箱が黙って取りこぼします**。

## この表に無いもの

そもそも**その配備からプロバイダへ到達できるか**は egress の話であって、プロバイダの
能力ではありません（[deploy-targets.md](deploy-targets.ja.md) とテナント設定を参照）。
