# af-scratch

[English](af-scratch.md) | 日本語

ビルドの生成物をワークスペースの作業ディスクへ移し、元の場所にシンボリックリンクを残します。作業ディスクがあるのは
一部の配備だけです。そこではホームがネットワークストレージで、小さいファイルの多いツリーが遅く、作業ディスクは
ローカルで速いディスクです。**作業ディスクの中身は、ワークスペースを停止すると消えます**。置くのは、ビルドで作り直せる
生成物だけにしてください。作業ディスクのないワークスペースでは、af-scratch は何もしません。

af-scratch とは別に、作業ディスクが 30 GiB 以上あり（既定の値です。配備がこの値と対象を変えられます）、書き込めれば、ワークスペースの起動が Go のビルドキャッシュ、Go のモジュール
キャッシュ、uv のキャッシュを作業ディスクへ移します。`node_modules` と npm のキャッシュはどれも移さず、`.venv` は自分で指定したときだけ移ります。

## 書式

```sh
af-scratch <dir>...
af-scratch --status
af-scratch --auto [<root>]
```

| 形 | 動作 |
|---|---|
| `<dir>...` | ディレクトリをそれぞれ作業ディスクへ移し、シンボリックリンクに置き換えます。まだないディレクトリは、作業ディスクの移し先へのリンクになります |
| `--status` | いま移しているものを、それぞれのサイズと一緒に出します |
| `--auto [<root>]` | `<root>`（既定はいまのディレクトリ）の下のプロジェクトがこれから作る生成物を移します。ワークスペースが、クローンや作業コピーを新しく作るたびに実行します |

引数なしで実行すると、使いかたを表示して終了コード 1 で終わります。`--help` はありません。渡すとディレクトリ名として
扱われます。

## 移し先

ディレクトリは `$AF_WS_SCRATCH/artifacts/` の下に、元の絶対パスのまま移ります。2 つのプロジェクトの `target` が
ぶつかることはありません。

```
$ af-scratch target
af-scratch: target を作業ディスクへ移しています…
af-scratch: target -> /scratch/artifacts/home/dev/repos/shop/target（Workspace 停止で消えます）
```

停止したあともリンクは残りますが、リンク先はなくなっています。af-scratch はすでにあるリンクには触らないので、
ディレクトリを作り直すには `mkdir -p "$(readlink target)"` を実行するか、リンクを消してから `af-scratch target` を
もう一度実行します。

## 自分で移すとき

| ディレクトリの状態 | 動作 |
|---|---|
| すでにシンボリックリンク | 何もしません。リンク先を表示します |
| ある | 作業ディスクへ移してからリンクします。この 1 回は、ホームから全部を読むので遅くなります。**作業ディスクの移し先にすでにあったものは、先に削除します** |
| ない | 作業ディスクの移し先にリンクします。移し先がなければ空で作ります。あれば（停止前の移動の残りなど）、中身ごとそのまま使います |
| 名前が `node_modules` | 断ります。npm は次のインストールでリンクの `node_modules` を実体のディレクトリに置き換え、`npm ci` はその前に作業ディスク側を空にします |
| 名前が `.venv` | 警告を出して移します。`uv venv` と `uv sync` はリンク越しに使えますが、`python3 -m venv .venv` は失敗します |

af-scratch は、指定したものを git が追跡しているかどうかを確かめません。**追跡しているファイルや未コミットの作業は
指定しないでください**。停止で消えます。

## `--auto` が移すもの

`<root>` の下 3 階層まででプロジェクトのファイルを探します。`.git`、`node_modules`、`.venv`、`target`、`build`、
`dist` の中には入りません。

| プロジェクトのファイル | 移すディレクトリ |
|---|---|
| `Cargo.toml`、`pom.xml` | 隣の `target` |
| `build.gradle`、`build.gradle.kts` | 隣の `build` |

それぞれのディレクトリについて、手で移すときより厳しい規則に従います。

- シンボリックリンクには触りません（ほかの作業コピーと共有するために、自分で張ったリンクかもしれないため）
- すでにあって、git が**無視していない**ディレクトリには触りません
- すでにあって、git が無視しているディレクトリは、移してリンクします
- ないディレクトリは、新しい空のディレクトリにリンクします。最初のビルドから作業ディスクに書き込まれます

そのため、新しいチェックアウトには空の `target` や `build` のリンクがあります。`[ -d build ] || …` のような確認は
これをビルド済みと見なすので、ビルドは条件を付けずに実行してください。

`--auto` が `node_modules` と `.venv` を移すことはありません。作業ディスクがなければ何もせずに終わります。
終了コードはいつも 0 です。

## `--status`

```
$ af-scratch --status
/home/dev/repos/shop/target                                  412M
/home/dev/repos/app/build                                    96M
```

元のパスがまだシンボリックリンクであるディレクトリを出します。対象は、元のパスが `/` から数えて 6 階層までのものです
（`/home/dev/repos/shop/app/target` が 6 階層）。一度も移していなければ `逃がしているものはありません。` と出ます。
移したことはあってもリンクが 1 つも残っていなければ、何も出ません。

## 環境変数

| 変数 | 効果 |
|---|---|
| `AF_WS_SCRATCH` | 作業ディスク。配備が設定します。設定されていなければ、af-scratch は何もしません |
| `AF_WS_SCRATCH_AUTO=0` | `--auto` を止めます |
| `AF_WS_SCRATCH_AUTO_DEPTH` | `--auto` が `<root>` の下を何階層まで探すか。既定は 3 です |

## 終了コード

| 値 | 意味 |
|---|---|
| 0 | 完了。`--auto` はいつもこれです |
| 1 | 作業ディスクがない（`AF_WS_SCRATCH` が設定されていない）、引数がない、または `node_modules` を指定した（ほかに指定したディレクトリは処理します）。移動やリンクに失敗したときもこれで、シェルのエラーを表示し、それ以降は処理しません |
