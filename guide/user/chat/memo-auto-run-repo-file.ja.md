# 自動実行の設定をリポジトリに置く

[English](memo-auto-run-repo-file.md) | 日本語

リポジトリは、メモのカテゴリの[自動実行](memo-auto-run.ja.md)の設定を、1 つのファイル `.agent-fleet/autorun.yaml` に持てます。
このファイルはほかのコードと同じようにレビューされ、履歴が残ります。ファイルの内容は、あなたが Console で自分の設定との違いを見て承認するまで、反映されません。

## 全体像

| あなたがやること | Agent Fleet がやること |
|---|---|
| リポジトリの既定ブランチに `.agent-fleet/autorun.yaml` をコミットする。カテゴリ名ごとに項目を書く | まだ何もしません。ファイルを読むのは、あなたが頼んだとき、または配備の設定で定期的に読み直すときだけです |
| カテゴリの「**自動実行の設定**」を開き、「**ファイルを確認**」を押す | ワークスペースが、リモートにあるリポジトリの既定ブランチからファイルを読みます。Console には、ファイルとあなたの設定とで値が違う項目が並びます |
| 納得した項目にチェックを入れて承認する | チェックした項目に、ファイルの値をあなたのカテゴリの設定として保存します。どのコミットを承認したかも記録します |
| チェックを入れない項目がある | その項目は、あなたの値のままです |

- 設定はあなたのものです。そのリポジトリに同じ名前のカテゴリを持つメンバーは、それぞれ自分で承認します。承認しても、ほかの人の設定は変わりません
- ファイルは、リモートの既定ブランチから読みます。手元の作業コピーや作業用のブランチからは読みません。セッションは作業中のファイルを変えられますが、自分の実行の起動に使われる設定は変えられません
- ファイルからは決して読まない設定があります（後述）。自動実行をオンにすることもその 1 つです

## 始める前に

- カテゴリがリポジトリに属している必要があります。リポジトリのないカテゴリには「**リポジトリの設定ファイル**」が出ません
- ファイルを確認するときは、ワークスペースが起動している必要があります。ファイルはそこで読みます
- 配備の設定でこの機能を切ることができます。切られていると「リポジトリの設定ファイル」は出ません（[配備の変数](../../ref/settings.ja.md#配備の変数)）

## ファイルを書く

いちばん早いのは、いまの自分の設定から始めることです。「**自動実行の設定**」で「**YAML で書き出す**」を押し、「**コピー**」か「**ダウンロード**」をして、その内容を `.agent-fleet/autorun.yaml` としてリポジトリのいつものレビューを通してコミットします。

ファイルは次のような形です。

```yaml
version: 1
categories:
  issue-rounds:
    agent_kind: claude
    model: opus
    effort: high
    spend_cap_usd: 30
    max_active: 2
    batch: 1
    open_after: 3
    max_fires_per_day: 20
    max_task_hours: 12
    continuation_max: 4
    instruction_file: docs/runbooks/issue-rounds.md
```

- `version: 1` は必須です。ほかの版のファイルは、推測で読まずに誤りとして扱います
- `categories` の下のキーは、メモキューに表示されているとおりのカテゴリ名です。Console でカテゴリの名前を変えると、ファイルのほかの項目に当たるか、どれにも当たらなくなります
- ファイルに書かれていないキーは比べません。あなたの値のままです
- 知らないキーは誤りとして扱い、黙って無視はしません。書き間違えたキーが、反映される設定のように見えることはありません
- ファイルの大きさは 64 KB までです

### キー

| キー | 「自動実行の設定」の項目 |
|---|---|
| `agent_kind`、`model`、`effort`、`route` | エージェント、モデル、エフォート、エージェントのルート |
| `spend_cap_usd` | 費用の上限（USD）。`0` は上限なし |
| `max_active` | 同時に動かすセッション数 |
| `batch` | 1 セッションに渡すメモの数 |
| `open_cron`、`open_minutes`、`tz` | 実行するタイミング: 時間帯を決める（開始の cron 式、長さ（分）、タイムゾーン） |
| `open_after` | 実行するタイミング: 実行待ちがたまったら（件数） |
| `max_fires_per_day` | 1 日の実行回数 |
| `max_task_hours` | 期限超過とみなすまでの時間（時間） |
| `worktree` | 毎回、新しいワークツリーで実行する。ファイルで指定できるのは `true` だけです |
| `tidy` | 実行の前に、待っているメモを整理する。ファイルで指定できるのは `false` だけです |
| `continuation_max` | 承認なしで実行が追加できる続きの数 |
| `instruction` | 指示。ファイルの中に直接書きます |
| `instruction_file` | 指示。リポジトリのほかのファイルから読みます（次の節） |

値の範囲は Console と同じです（[項目](memo-auto-run.ja.md#項目)）。Console で保存できない値は、その行の誤りとして出ます。
YAML がほかの型として読んでしまう文字列は、引用符で囲みます（`model: "1.5"`）。

### 指示を別のファイルに置く

`instruction_file` には、リポジトリのファイルを 1 つ指定します。その中身全体が指示になるので、長い手順書を普通の Markdown ファイルとしてレビューできます。

- パスはリポジトリのルートからの相対パスで、区切りは `/`、`..` は使えません
- `autorun.yaml` と同じコミットから読みます。ほかのブランチからは読みません
- UTF-8 の普通のテキストファイルで、16 KB までです。指示の欄と同じ上限です
- `instruction` と `instruction_file` は、どちらか一方だけを書きます

### ファイルで指定できないもの

次のものは、ファイルに何が書いてあっても Console でしか変えられません。ファイルにあると「**ファイルからは反映しないもの**」に警告が出て、ファイルのほかの部分はそのまま使えます。

| ファイルに書いたもの | Console だけで変える理由 |
|---|---|
| `enabled` | 自動実行をオンにする（またはオフにする）こと |
| `accept_own_sessions` | 「自分で起動したセッションのメモは、承認なしで受け付ける」は承認を省くもの |
| `tidy_destinations` | 整理で、すぐ実行される状態のままメモを移してよいカテゴリ |
| `worktree: false` | ワークツリーではなく作業コピーで実行すること |
| `tidy: true` | 整理の実行をオンにすること |
| 時間帯としきい値の両方を外すこと（`open_cron: ""` と `open_after: 0`） | そのカテゴリは、メモが待ったとたんに始まるようになります |

ファイルに書くのは名前だけで、秘密の値は書きません。認証情報に見える値（API キー、トークン、秘密鍵、URL の中のパスワード）は誤りとして扱います。それを含む指示のファイルも同じです。

## 違いを承認する

1. 「**メモキュー**」ビューで、カテゴリの「**自動実行の設定**」を開きます
2. 「**リポジトリの設定ファイル**」の「**ファイルを確認**」を押します。読んだブランチとコミット、前回あなたが承認したコミットが出ます
3. 「**リポジトリの設定と違いがあります**」の下に、項目ごとに、いまの値、ファイルの値、その行番号が並びます
4. 反映する項目にチェックを入れ、「**選んだ N 件を承認**」を押します

- 「**上限が上がります**」の付いた項目は、上限を上げます。費用の上限を上げる（またはなくす）、同時に動かすセッション数、続きの数、1 日の実行回数を増やす、のどれかです。よく読んでください
- 「**実行するタイミング**」は 1 つの項目です。時間帯としきい値の設定は、まとめて承認するか、どれも承認しないかのどちらかです
- 承認で反映されるのは、表示されていた内容そのものです。そのあいだにファイルに新しいコミットが入ったり、あなたの設定が変わったりすると、承認は断られ、カードがファイルを読み直します。新しい違いを見て、もう一度承認してください
- 承認する前に、ダイアログで編集中の内容を保存するか取り消してください
- 承認するとダイアログが閉じます。保存された設定は、開き直すと見られます

ファイルに誤りがあると、カードに「**このファイルは反映できません。いまの設定がそのまま使われます。**」と出て、誤りが行番号付きで並びます。既定ブランチで直すまで、比較はしません。

## ファイルが変わったことに気づく

カテゴリには、最後に読んだ結果が残ります。違いか誤りが見つかっていると、メモキューのカテゴリの見出しに印が付き、「自動実行の設定」に、いつどのコミットを読んだかが出ます。

この記録は、「ファイルを確認」を押したときと、配備で定期的な読み直しをオンにしている場合は、「自動で実行する」がオンでワークスペースが起動しているカテゴリを読み直したときに作られます。読み直しでワークスペースが起動されることはなく、何かが反映されることもありません。読み直しがない配備では、ファイルへのコミットは、もう一度確認したときに初めて出ます。

## うまくいかないとき

| 表示 | やること |
|---|---|
| 「所有者のワークスペースが起動している必要があります。」 | ワークスペースを起動して、もう一度確認します |
| 「既定ブランチに .agent-fleet/autorun.yaml はありません。」 | ファイルがまだリモートの既定ブランチにありません。そこにマージします。作業用のブランチは読みません |
| 「ファイルに「…」の項目はありません。」 | ファイルに、カテゴリ名と同じキーがありません |
| `instruction_file` の誤り | そのコミットにファイルがない、UTF-8 の普通のテキストファイルでない、16 KB を超えている、または認証情報を含んでいるように見える、のどれかです |
| 「差分を表示した後に、リポジトリの設定ファイルかいまの設定が変わりました。」 | 確認のあとで、ファイルかあなたの設定が変わりました。カードがファイルを読み直すので、いま出ている内容を承認します |
