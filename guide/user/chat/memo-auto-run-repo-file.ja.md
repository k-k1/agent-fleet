# 自動実行の設定をリポジトリに置く

[English](memo-auto-run-repo-file.md) | 日本語

リポジトリは、メモのカテゴリの[自動実行](memo-auto-run.ja.md)の設定を、1 つのファイル `.agent-fleet/autorun.yaml` に持てます。
このファイルはほかのコードと同じようにレビューされ、履歴が残ります。ファイルの内容は、あなたが Console で自分の設定との違いを見て承認するまで、反映されません。

## 全体像

| あなたがやること | Agent Fleet がやること |
|---|---|
| リポジトリの既定ブランチに `.agent-fleet/autorun.yaml` をコミットする。カテゴリ名ごとに項目を書く | まだ何もしません。ファイルを読むのは、あなたが頼んだとき、または配備の設定で定期的に読み直すときだけです |
| カテゴリの「**自動実行の設定**」を開き、「**ファイルを確認**」を押す | ワークスペースが、リモートにあるリポジトリの既定ブランチからファイルを読みます。Console には、ファイルとあなたの設定とで値が違う項目が、すべてチェックの入った状態で並びます |
| 反映しない項目のチェックを外し、残りを承認する | チェックした項目に、ファイルの値をあなたのカテゴリの設定として保存します。どのコミットを承認したかも記録します |

- 設定はあなたのものです。そのリポジトリに同じ名前のカテゴリを持つメンバーは、それぞれ自分で承認します。承認しても、ほかの人の設定は変わりません
- ファイルは、リモートの既定ブランチから読みます。手元の作業コピーや作業用のブランチからは読まないので、そこでの編集がそのまま取り込まれることはありません。ただしこれは歯止めで、保証ではありません。ワークスペースのセッションは、あなたと同じ git のサインインを使います。反映されるのは、すべての違いと、ファイルのパス・ブランチ・コミットをカードで見たうえで、あなたが承認したものだけです。カードには、ファイルをどのリモートから読んだかは出ません。気になるときは、ワークスペースでリポジトリの `origin` を確かめます
- ファイルからは決して読まない設定があります（後述）。自動実行をオンにすることもその 1 つです

## 始める前に

- カテゴリがリポジトリに属している必要があります。リポジトリのないカテゴリには「**リポジトリの設定ファイル**」が出ません
- ファイルを確認するときも承認するときも、ワークスペースが起動している必要があります。ファイルはそのたびにそこで読みます
- 配備の設定でこの機能を切ることができます。切られていると「リポジトリの設定ファイル」は出ません（[配備の変数](../../ref/settings.ja.md#配備の変数)）
- 承認するには、組織の管理者がメモの自動実行を許可している必要があります（[自動実行を許可する](../../admin/defaults/memo-auto-run.ja.md)）。許可されるまでは、ファイルを確認して違いを見ることはできますが、承認はできません

## ファイルを書く

いちばん早いのは、保存済みのカテゴリから始めることです。そのカテゴリの「**自動実行の設定**」で「**YAML で書き出す**」を押し、「**コピー**」か「**ダウンロード**」をします。書き出されるのは、そのカテゴリ 1 つだけです。

- リポジトリにまだファイルがなければ、`.agent-fleet/autorun.yaml` として、リポジトリのいつものレビューを通してコミットします
- ファイルがすでにあれば、`categories` の下のそのカテゴリの項目だけを書き写します。書き出した内容でファイルを上書きすると、ほかのカテゴリの項目がすべて消えます

ファイルは次のような形です。

```yaml
version: 1
categories:
  issue-rounds:
    agent_kind: claude
    model: opus
    effort: high
    spend_cap_usd: 30
    max_active: 2
    batch: 1
    open_cron: ""
    open_after: 3
    max_fires_per_day: 20
    max_task_hours: 12
    continuation_max: 4
    instruction_file: docs/runbooks/issue-rounds.md
```

- `version: 1` は必須です。ほかの版のファイルは、推測で読まずに誤りとして扱います
- `categories` の下のキーは、メモキューに表示されているとおりのカテゴリ名です。Console でカテゴリの名前を変えると、ファイルのほかの項目に当たるか、どれにも当たらなくなります
- ファイルに書かれていないキーは比べません。あなたの値のままです。例外は時間帯の長さとタイムゾーンで、ファイルがしきい値に切り替えると消えます（[実行するタイミング](#実行するタイミング)）
- 知らないキーは誤りとして扱い、黙って無視はしません。書き間違えたキーが、反映される設定のように見えることはありません
- ファイルの大きさは 64 KiB までです

### キー

| キー | 「自動実行の設定」の項目 |
|---|---|
| `agent_kind`、`model`、`effort` | エージェント、モデル、エフォート |
| `route` | エージェントのセッションが使うルート。ダイアログには欄がなく、ファイルから設定します。そのエージェントが受け付けるルートである必要があります |
| `spend_cap_usd` | 費用の上限（USD）。`0` は上限なし |
| `max_active` | 同時に動かすセッション数 |
| `batch` | 1 セッションに渡すメモの数 |
| `open_cron`、`open_minutes`、`tz` | 実行するタイミング: 時間帯を決める（開始の cron 式、長さ（分）、タイムゾーン） |
| `open_after` | 実行するタイミング: 実行待ちがたまったら（件数） |
| `max_fires_per_day` | 1 日の実行回数 |
| `max_task_hours` | 期限超過とみなすまでの時間（時間） |
| `worktree` | 毎回、新しいワークツリーで実行する。ファイルで指定できるのは `true` だけです |
| `tidy` | 実行の前に、待っているメモを整理する。ファイルで指定できるのは `false` だけです |
| `continuation_max` | 承認なしで実行が追加できる続きの数 |
| `instruction` | 指示。ファイルの中に直接書きます |
| `instruction_file` | 指示。リポジトリのほかのファイルから読みます（後述） |

値の範囲は Console と同じで（[項目](memo-auto-run.ja.md#項目)）、組み合わせも Console で保存できるものである必要があります。Console で保存できない値や組み合わせは、その行の誤りとして出ます。
YAML がほかの型として読んでしまう文字列は、引用符で囲みます（`model: "1.5"`）。

### 実行するタイミング

時間帯としきい値は同時には設定できません。ファイルはメンバーそれぞれの設定に重ねられ、その設定がもう一方を使っていることもあります。使わないほうを、オフとして書いておきます。

- しきい値: `open_after` に `open_cron: ""` を添えます（例のとおり）。`open_cron: ""` がないと、時間帯を使っているメンバーでは時間帯が残り、誤りになります
- 時間帯: `open_cron`、`open_minutes`、`tz` に `open_after: 0` を添えます

時間帯からしきい値に切り替えると、時間帯の長さとタイムゾーンも一緒に消えます。ファイルに書く必要はありません。時間帯がないのに、`0` 以外の `open_minutes` や `""` 以外の `tz` を書くと誤りです。
時間帯かしきい値を持つカテゴリを、どちらもない状態にすることは、ファイルではできません。そうなると、実行できるメモがあり空きがあるたびに実行が始まるためで、これは Console だけで変えられます（後述）。すでにどちらもないカテゴリは、そのままにできます。

### 指示を別のファイルに置く

`instruction_file` には、リポジトリのファイルを 1 つ指定します。その中身が指示になるので、長い手順書を普通の Markdown ファイルとしてレビューできます。指示の欄と同じく、先頭と末尾の空白や空行は取り除かれます。

- パスはリポジトリのルートからの相対パスで、区切りは `/` です。`..`、先頭の `./`、末尾の `/` は使わず、そのままの形で書きます
- `autorun.yaml` と同じコミットから読みます。ほかのブランチからは読みません
- 普通のファイル（リンク、フォルダ、サブモジュールではないもの）で、NUL を含まない UTF-8 のテキスト、16 KiB までです。指示の欄と同じ上限です
- `instruction` と `instruction_file` は、どちらか一方だけを書きます

### ファイルで指定できないもの

次のものは、ファイルに何が書いてあっても Console でしか変えられません。ファイルにあると「**ファイルからは反映しないもの:**」に警告が出て、その項目のほかの部分はそのまま使えます。

| ファイルに書いたもの | Console だけで変える理由 |
|---|---|
| `enabled` | 自動実行をオンにする（またはオフにする）こと |
| `accept_own_sessions` | 「自分で起動したセッションのメモは、承認なしで受け付ける」は承認を省くもの |
| `tidy_destinations` | 整理で、すぐ実行される状態のままメモを移してよいカテゴリ |
| `worktree: false` | ワークツリーではなく作業コピーで実行すること |
| `tidy: true` | 整理の実行をオンにすること |
| 時間帯かしきい値を持つカテゴリを、どちらもない状態にする値 | そのカテゴリは、実行できるメモがあり空きがあるたびに実行を始めるようになります |

### ファイルに秘密を書かない

ファイルに書くのは名前だけで、秘密の値は書きません。よく知られた認証情報の形をした値（AWS のアクセスキー、GitHub や GitLab のトークン、Slack・Anthropic・OpenAI・Google の API キー、秘密鍵のブロック、JSON Web Token、URL の中のパスワード、`password:` や `api_key:` などのあとに引用符で書いた値）は誤りとして扱います。それを含む指示のファイルも同じです。
この検査は網であって、スキャナーではありません。ほかの形は見逃しますし、Console だけのキーの値はそもそも読みません。検査を通ったファイルでも秘密を含みうるので、一度コミットするとリポジトリの履歴に残ります。書き出した内容もファイルも、コミットの前に読んでください。

## 違いを承認する

1. 「**メモキュー**」ビューで、カテゴリの「**自動実行の設定**」を開きます
2. 「**リポジトリの設定ファイル**」の「**ファイルを確認**」を押します。読んだブランチとコミット、前回あなたが承認したコミットが出ます
3. 「**リポジトリの設定と違いがあります**」の下に、行ごとに、いまの値、ファイルの値、その行番号が並びます。**最初はすべての行にチェックが入っています**
4. 反映しない行のチェックを外し、「**選んだ N 件を承認**」を押します。N は行の数ではなく設定の数です。「実行するタイミング」は 1 行で数件になることがあります

- 「**上限が上がります**」の付いた行は、上限を上げます。費用の上限を上げる（またはなくす）、同時に動かすセッション数、続きの数、1 日の実行回数を増やす、のどれかです。そのつもりがなければチェックを外します
- 「**実行するタイミング**」は 1 行です。時間帯としきい値の設定は、まとめて承認するか、どれも承認しないかのどちらかです
- ある設定だけを承認した結果が、Console で保存できない組み合わせになるときは、承認は断られます。たとえば、エージェントと、別のエージェントだけが受け付けるルートの組み合わせです。エージェントとルートは一緒にチェックします
- 承認のときにファイルを読み直し、表示されていた内容そのものを反映します。既定ブランチに新しいコミットが入っていたとき（ファイルに触れないコミットでも）や、あなたの設定やカテゴリの名前が変わっていたときは、承認は断られ、カードがファイルを読み直します。**読み直した違いは、またすべての行にチェックが入った状態で出ます**。反映しない行のチェックを外してから承認してください
- 承認する前に、ダイアログで編集中の内容を保存するか取り消してください
- カテゴリの名前が（別のタブなどで）変わっていると、カードにそう出て、承認は進みません。ダイアログを閉じ、カテゴリの「自動実行の設定」を開き直します
- 承認するとダイアログが閉じます。保存された設定は、開き直すと見られます

ファイル全体か、このカテゴリの項目に誤りがあると、カードに「**このファイルは反映できません。いまの設定がそのまま使われます。**」と出て、誤りが並びます。行番号の分かるものには行番号が付きます。ほかのカテゴリの項目の誤りでは、あなたのカテゴリの比較は止まりません。既定ブランチで直すまで、比較はしません。
ファイルをそもそも読めないときは、カードの中に、違いの代わりに読み取りのエラーが出ます（次の表）。

## ファイルが変わったことに気づく

自動実行の設定を保存済みのカテゴリには、応答のあった最後の読み取りの結果が残ります。その読み取りで違いかファイルの誤りが見つかっていると、メモキューのカテゴリの見出しに印が付き、「自動実行の設定」に、いつどのコミットを読んだかが出ます。設定を保存していないカテゴリには何も残りません。

この記録は、「ファイルを確認」を押したときと、配備で定期的な読み直しをオンにしている場合は、「自動で実行する」がオンでワークスペースが起動しているカテゴリを読み直したときに作られます。読み直しでワークスペースが起動されることはなく、何かが反映されることもありません。

印が表すのは、いまのファイルではなく、最後の読み取りの結果です。

- 最後の読み取りで違いがなかったとき、またはファイルやカテゴリの項目がなかったときは、印は出ません
- 最後の読み取りのあとでカテゴリの名前や設定を変えると、その記録は当てはまらなくなり、印は消えます
- 失敗した読み取り（リモートにつながらない、ファイルが大きすぎる、UTF-8 のテキストでない）では何も変わりません。前の記録が、印があってもなくても、そのまま残ります
- ファイルへのコミットは、次に読むまで分かりません。あなたが確認するか、配備に読み直しがあればそのときです

確かめるには「ファイルを確認」（2 回目からは「もう一度確認」）を押します。

## うまくいかないとき

| 表示 | やること |
|---|---|
| 「所有者のワークスペースが起動している必要があります。」 | ワークスペースを起動して、もう一度確認します |
| 「既定ブランチに .agent-fleet/autorun.yaml はありません。」 | ファイルがまだリモートの既定ブランチにありません。そこにマージします。作業用のブランチは読みません |
| 「ファイルに「…」の項目はありません。」 | ファイルに、カテゴリ名と同じキーがありません |
| カードの中の「リポジトリの既定ブランチから設定ファイルを読めませんでした。いまの設定はそのままです。」 | 読み取りのエラーです。たとえば、リモートにつながらない、ファイルが 64 KiB を超えているか UTF-8 のテキストでない、ワークスペースにリポジトリのクローンがない、ワークスペースの Agent が古く `instruction_file` を読めない、などです。Agent が古いときは、ワークスペースに「[要再起動](../troubleshooting/workspace.ja.md#電源ボタンの横に要再起動と出る)」と出ていれば再起動します。出ていなければ、ワークスペースの更新が配備されているかを、配備の管理者に確かめます。直してから、もう一度確認します |
| `instruction_file` の誤り | そのコミットにファイルがない、普通の UTF-8 のテキストファイルでない、16 KiB を超えている、NUL を含む、認証情報を含んでいるように見える、またはパスがそのままの形でない、のどれかです |
| 「a queue opens in a window or after a number of messages, not both」 | ファイルをあなたの設定に重ねた結果、両方が有効になっています。ファイルが片方を設定し、あなたの設定がもう片方を使っているか、ファイル自身が両方を設定しています。使わないほうをオフとして書きます（[実行するタイミング](#実行するタイミング)） |
| 「差分を表示した後に、リポジトリの設定ファイルかいまの設定が変わりました。もう一度確認してから承認してください。」 | 確認のあとで、既定ブランチかあなたの設定が変わりました。カードがファイルを読み直すので、チェックを見直してから、いま出ている内容を承認します。カテゴリの名前が変わっていたときは、先に「自動実行の設定」を開き直します |
