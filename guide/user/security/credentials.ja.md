# 認証情報を安全に扱う

[English](credentials.md) | 日本語

トークン・API キー・ログインをどこに置けば、エージェントに安全に使わせられるかをまとめています。
置き場所を決めておけば、プロンプトやリポジトリにシークレットが紛れ込むことはありません。

## 全体像

| あなたがやること | Agent Fleet がやること |
|---|---|
| サービスへの接続を **⚙設定** に登録する | 値をワークスペースの中に保存し、`git`・`gh`・`jira`・`af-aws-exec` などのコマンドに使わせる |
| プロンプト・指示・リポジトリにシークレットを書かない | 設定を書き出すファイルに、接続を入れない |
| 外部クライアント用のトークンは、ワークスペースではなく手元のクライアントでだけ使う | この配備自身の `/mcp` をセッションに登録しようとすると断る |
| 要らなくなった接続を外す・失効する | 外した接続は、次の呼び出しから使わない |

## 置き場所を決める

認証情報は、種類ごとに決まった設定のタブに置きます。エージェントはそこから使うので、コマンドに書き添える必要はありません。

| 認証情報 | 置き場所 | 詳しく |
|---|---|---|
| GitHub・Bitbucket のトークン | ⚙設定 →「Git ホスティング」 | [Git のサービスを接続する](../code/connect-git.ja.md) |
| エージェントのログイン・API キー | ⚙設定 →「エージェント」 | [エージェントを選ぶ](../agents/choose.ja.md) |
| Jira・Confluence | ⚙設定 →「課題管理」 | [Jira を使う](../integrations/jira.ja.md) |
| AWS | ⚙設定 →「AWS プロファイル/SSM」の SSO プロファイル | [AWS SSO を使う](../integrations/aws-sso.ja.md) |
| Google Cloud | ⚙設定 →「Google Cloud」 | [Google Cloud を使う](../integrations/gcloud.ja.md) |
| MCP サーバーのトークン・ヘッダー | ⚙設定 →「MCP サーバー（セッションで使う）」の「認証」 | [セッションに MCP サーバーを追加する](../integrations/mcp-servers.ja.md) |

- MCP サーバーの値は暗号化して保存され、画面には二度と表示されません。URL にユーザー名とパスワードを埋め込むと、保存が断られます
- AWS と Google Cloud には、長く使えるキーを置きません。エージェントは `af-aws-exec`・`af-gcloud-exec` を通して、ログインから得た有効期限の短い権限でコマンドを 1 つずつ実行します
- OAuth でサインインした MCP サーバーは、ワークスペースの中の中継を通して呼ばれます。トークンがエージェントの設定に書かれることはありません

## シークレットを書かない場所

次の場所は、エージェントや人がそのまま読むテキストです。トークンやパスワードを書かないでください。

- セッションやアシスタントへのプロンプト
- [エージェントへの指示](../agents/instructions.ja.md)と、リポジトリの `CLAUDE.md`・`AGENTS.md`
- リポジトリのファイル（`.env`、プロジェクト直下の `.mcp.json` など）。うっかりコミットすると、履歴に残ります
- Agent Fleet のメモリ、メモ、受信箱のメッセージ

接続の画面がないサービスのキーが要るときは、ワークスペースの中で、リポジトリの外のファイルに置いてください。

## エージェントに届く範囲を知る

エージェントは、ワークスペースの中であなたと同じユーザーとして動きます。そのため、あなたが接続したサービスには、エージェントも
あなたの権限で届きます。エージェントが読んだファイルや依存パッケージに仕込まれた指示も、同じ権限で動きうると考えてください。

- トークンは、作業に要る権限だけで作ります
- 本番の AWS プロファイルは「**使用前に確認**」をオンにし、コマンドに `--account` を付けます（[AWS SSO を使う](../integrations/aws-sso.ja.md#もっと安全に使う)）
- 使わなくなった接続は外します

## 外に出るものに気をつける

| 場面 | 起きること |
|---|---|
| [会話を共有する](../team/share.ja.md) | 共有先には、プロンプト・回答・ツールの出力まで会話の全文が見えます。共有を解除しても、相手が保存したものは戻りません |
| 受信箱で送る | 本文は、配備にテナントのキーがあれば暗号化して保存されます。運用者は復号できます |
| Discord・Slack に全文を送る | シークレットらしい文字列は自動で伏字になります。それでも、チャットのサーバーが自分のものであるときだけ使います（[Discord・Slack とつなぐ](../integrations/chat-bridge.ja.md)） |
| 設定を書き出す | 接続は入りません。書き出したファイルは人に渡せます（[設定を書き出す・取り込む](../workspace/export-import.ja.md)） |

## Console のトークンと Cookie をワークスペースに置かない

「**MCP トークン・接続アプリ**」で発行するトークンは、あなたのメンバーの権限そのままでワークスペースを動かせます。
Console の Cookie は、サインイン中のあなたそのものです。

- どちらも、セッションへのプロンプトやワークスペースのファイルに置かないでください。置いても Agent Fleet には検出できません
- トークンは、手元の PC の Claude Code や Claude Desktop など、ワークスペースの外のクライアントでだけ使います
- 理由と、つないではいけない組み合わせは [この配備の /mcp をセッションにつながない](../outside/external-claude.ja.md#この配備の-mcp-をセッションにつながない) にあります

## 漏れたかもしれないとき

1. Console のトークンなら、「**MCP トークン・接続アプリ**」で「**失効**」を押します。OAuth の接続なら「**接続済みアプリ**」の行で「**失効**」を押します
2. サービスへの接続なら、そのサービスの側でトークンやキーを無効にし、⚙設定でつなぎ直します
3. 会話を共有していたなら、共有を解除します
4. 管理者に知らせます
