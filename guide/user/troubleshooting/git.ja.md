# クローンや認証に失敗する

[English](git.md) | 日本語

リポジトリのクローン、private リポジトリの認証、submodule の取得がうまくいかないときに、原因と直し方を探せます。

## クローンに失敗する

- **接続を確かめます。** private リポジトリは、先に GitHub や Bitbucket を接続しておく必要があります。⚙設定 →「Git ホスティング」で、そのサービスが「**未接続**」になっていないか見てください（[Git のサービスを接続する](../code/connect-git.ja.md)）
- **URL とブランチ名に打ち間違いがないか確かめます。**
- submodule の取得に失敗しても、親のクローンは成功します。submodule は下の節を見てください

## private リポジトリで認証のエラーになる

⚙設定 →「Git ホスティング」で、そのサービスが「**接続済み**」か確かめます。

- 未接続なら、OAuth かトークンで接続します。接続すれば、クローンも push もトークンを入れずに通ります
- 接続済みなのに失敗するときは、カードに出ている文を読みます。「**GitHub の接続を更新できませんでした。…**」や、Bitbucket がトークンを拒否したときの直し方は [Git のサービスを接続する](../code/connect-git.ja.md#困ったとき) にあります

## セッションが「submodule がない・壊れている」と言う

大きな submodule は、起動までに取得しきれないことがあります。取得は裏で続き、終わると通知が届きます。

- 途中で切れた submodule は、その作業コピーで次にセッションを起動したときに自動で直ります
- 急ぐときは、端末でその作業コピーに入って `git submodule update --init --recursive` を実行します

詳しくは [リポジトリをクローンする](../code/clone.ja.md#困ったとき) にあります。
