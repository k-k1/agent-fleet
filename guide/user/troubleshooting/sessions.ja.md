# セッションが再開できない・見当たらない

[English](sessions.md) | 日本語

セッションが一覧から消えた、再開できない、途中で止まった、共有や定時実行が動かないときに、原因と直し方を探せます。

## 左ペインからセッションやリポジトリが消えた

まず、左ペインのいちばん上のバーが「**すべて**」になっているか見てください。
作業グループを選んでいると、そのグループに入っていないリポジトリ・会話・セッションは表示されません。消えたわけではないので、「すべて」に戻せば元どおりです。

それでも見当たらないときは、次を確かめます。

- **アーカイブしていないか**。アーカイブの一覧から復帰できます
- **掃除で片付けていないか**。削除したセッションは、ごみ箱から戻せます

どちらも [終わったセッションを片付ける](../sessions/cleanup.ja.md#アーカイブする復帰する) に手順があります。

## 「一覧を更新できません（最後に取得した一覧を表示中）」と出る

左ペインの「**リポジトリ**」に出ます。何も消えていません。いまリポジトリの一覧を読めなかったので、最後に取れた一覧を出しています。

- ワークスペースに届かなかっただけなら、Console が再試行を続け、一覧は自動で戻ります
- ワークスペースがエラーを返したときは、再試行しません。出せる一覧がなければ「**リポジトリの一覧を読み込めません**」と出ます。ページを再読み込みするか、このワークスペースへのアクセス権を確かめてください

## 「フォルダ無し — 再開不可」と出る

セッションを起動した作業フォルダが消えています。作業コピーを worktree ごと削除したあとによく起きます。
消えた worktree は元のパスに作り直して、セッションを戻せます。手順は [セッションを止める・再開する](../sessions/stop-resume.ja.md#フォルダ無し-再開不可と出て行を開けない) にあります。

## claude のセッションが「会話ログが削除されている」と言って再開できない

「再開」を押すと「**このセッションの会話ログが削除されているため再開できません。…**」と「**新しい会話を始める**」が出ます。
claude の会話ログが消えていて、Agent Fleet のバックアップもない状態です。

ふつうはここまで来ません。Agent Fleet は次の 2 つで会話を守っています。

- ワークスペースの claude の設定で、古いログを日数で消す動きを止めています
- 停止したセッションのログのバックアップを持ち、ログが消えていれば再開のときに戻します。戻したときは、会話に「**会話ログが削除されていたため、Agent のバックアップから会話を復元しました。…**」と出ます

このメッセージが出るのは、最初のバックアップより前にログが消えたときか、自分の claude の `settings.json` で `cleanupPeriodDays` を小さくしていたときです。
`cleanupPeriodDays` を `0` にすると、claude は会話を保存しなくなります。

- 「**新しい会話を始める**」を押すと、古い文脈なしで同じセッションのまま続けられます。残っていた古いログやバックアップは、削除されずに退避されます
- 自分で `cleanupPeriodDays` を小さくしていたなら、外してください

再開のしかたは [セッションを止める・再開する](../sessions/stop-resume.ja.md#再開する) にあります。

ターンが完了した記録が Agent Fleet に残っていない古いセッションは、ログが消えていても見分けられません。その場合は警告なしに空の会話で始まります。

## 「バックアップから会話ログを復元できませんでした」と出る

バックアップはありますが、戻すのに失敗しました。読めないフォルダ、ディスクの空き不足、その間に別のログができていた、などが原因です。
バックアップは残っているので、原因を直してからもう一度再開してください。
邪魔になっていた中身のないログは、`.superseded.<数字>` という名前で退避されていることがあります。

## ターンが途中で切れた

プロバイダーのエラーや接続断、利用上限で、ターンが途中で終わることがあります。そのときは通知が届くので、気づかないまま放置されることはありません。

時間をおけば直る中断は、次の設定によって自動で続きから再開します。どれも既定ではオンです（[Claude を接続する](../agents/claude.ja.md#動作設定)・[Codex を接続する](../agents/codex.ja.md#動作設定)）。

| 設定 | 再開するもの |
|---|---|
| ⚙設定 →「エージェント」の「**中断したターンの自動再開**」 | Claude のターンが、接続断・一時的なレート制限・時間切れで切れたとき。連続 2 回まで |
| ⚙設定 →「エージェント」の「**利用上限リセット後の自動再開**」 | Claude と Codex（マネージド）が利用上限で止まったとき。上限が解ける時刻に 1 回だけ |
| ⚙設定 →「アシスタント」の「**中断時の自動再開**」 | アシスタントが指示したセッションのターンが切れたとき。連続 2 回まで |

依頼の内容や残高切れ、プロンプトの長さが原因の中断は、やり直しても同じように失敗するので、自動では再開しません。
届いた通知やエラーを読んで、原因を直してから送り直してください。

## セッションを別のエージェントへ移せない

作業中のセッションや、質問・プラン・承認があなたを待っているセッションは移せません。ターンが終わるのを待つか停止し、先に答えてください。

- 停止したマネージドの Cursor のセッションは、会話が残っていないので移せません
- shell と ssm のセッションには、移す会話がありません

移せるセッションの条件は [別のセッションやエージェントに引き継ぐ](../sessions/handoff.ja.md#移せるセッション) にあります。

## 掃除で消せないものがある

安全度が「**保持**」の候補は、掃除では触りません。理由は行に出ています。

| 理由 | やること |
|---|---|
| 稼働中 | 先にセッションを停止する |
| 未コミット・未 push | commit か push をすると「安全」か「要確認」に変わる |
| 削除ロック中 | セッションの ⋯ メニューでロックを外す |

それでも消すときの手順と、消したものを戻す手順は [終わったセッションを片付ける](../sessions/cleanup.ja.md#困ったとき) にあります。

## 共有したのに、相手に見えない・古い会話しか出ない

- **共有した範囲を確かめます。** セッション単位の共有は、そのセッション 1 本だけです。セッションごとに worktree を作っているなら、**プロジェクト**単位（ベースと、その下の worktree のセッション）で共有すると全体が見えます
- **アーカイブしたセッションは、共有先の一覧から外れます。** 共有の設定は残っているので、アーカイブから復帰すれば、また見えます
- **あなたのワークスペースが止まっている間は、相手は履歴を読めません。** 相手の画面にもそう出ます
- 一覧はときどき更新されます。すぐ反映したいときは、共有セッションの「**最新に更新**」を押します

共有のしかたは [会話を共有する](../team/share.ja.md) にあります。

## 共有されたセッションから送ったのに、エージェントが動かない

権限が「**提案可**」のときは、入力した内容は**所有者が承認するまでエージェントに届きません**。
所有者の共有セッションに「**承認待ち N 件**」が出るので、確かめて「**承認して送信**」を押してもらってください。
権限が「**閲覧のみ**」なら、送信欄はありません。

送ったかどうか確かめられなかったときは、二重に送らないよう、自動では送り直しません。「**結果を照会**」で状態を確かめてください（[会話を共有する](../team/share.ja.md)）。

## 定時実行が動かない

左ペインの「**スケジュール**」で、その行を確かめます。

| 見えるもの | 意味とやること |
|---|---|
| 「**停止中**」のタグ | 一時停止しています。行のメニューの「**再開**」で戻す |
| 「**実行履歴**」に「**スキップ**」が並ぶ | 見送られた。前の実行がまだ動いていた、対象の会話が実行中かなくなっていた、テナントで同時に動かせる数の上限に達していた、など。理由は行にカーソルを合わせると出る |
| 時刻やプロンプトが違う | 行のメニューの「**詳細・編集**」で直す |
| 「スケジュール」がない | この配備では定時実行が無効になっている |

「**今すぐ発火**」を押すと、定時と同じ経路で動くか確かめられます。動き出すまで 1 分ほどかかることがあります。
詳しくは [決まった時刻に実行する](../fleet/schedules.ja.md) にあります。

## 通知が来ない

- ブラウザで、Console からの通知を許可しているか確かめます
- そのセッションの画面を開いている間は、通知は出ません
- shell と ssm のセッションは、状態の通知を出しません
- 「**ライブ更新を一時停止中 — クリックで再開**」が出ているウィンドウは、しばらく操作がなかったので更新を止めています。押すと再開します

通知の種類の切り替えは [セッションの状態を読む](../sessions/status.ja.md#通知を受ける) にあります。

## claude が `/list-agents` を知らない・ほかのセッションに送れないと言う

Claude Code 自身のセッション間のメッセージは、Agent Fleet では使えないようにしてあります。オンにすると Claude の利用統計の送信も一緒に戻るためです。

代わりに Agent Fleet のものを使います。⚙設定 →「エージェント」の「**セッション間メッセージ**」をオンにしてください（既定ではオフです）。
種類の違うエージェントにも、停止中のセッションにも届きます。

オンにしても使えないときは、そのセッションがオンにする前から動いていないか確かめます。
設定が効くのは次に起動するセッションからなので、動いているセッションは再起動するまで変わりません。
違いの一覧は [セッション同士でやりとりさせる](../fleet/messages.ja.md#claude-code-の同じような機能は使わない) にあります。
