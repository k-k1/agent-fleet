# MCP・クラウド・Jira が動かない

[English](integrations.md) | 日本語

登録した MCP サーバーが使えない、AWS や Google Cloud のコマンドが止まる、`jira` がエラーで終わる、外から接続したアプリにツールが出ないときに、原因と直し方を探せます。

## 登録した MCP サーバーがセッションやアシスタントで使えない

⚙設定 →「MCP サーバー（セッションで使う）」で、上から順に確かめます。

1. サーバーが**有効**になっているか
2. 詳細設定の**利用先**に「セッション」か「アシスタント」が入っているか、**対象エージェント**を絞りすぎていないか
3. 「**テナント配布と名前が重なるため使われていない個人登録があります**…」と出ていないか。同じ名前のテナントのサーバーが優先されます
4. 「**接続テスト**」を押して、サーバー名とツールの数が返ってくるか

変更が効くのは、次に起動するセッションからです。動いているセッションは、再起動するまで変わりません。
値の入れ忘れや、外への通信の許可の申請は [セッションに MCP サーバーを追加する](../integrations/mcp-servers.ja.md#困ったとき) にあります。

## 接続テストは通るのに、セッションでは `Session not found` になる

MCP のセッションをメモリに持つサーバー（ステートフルな Streamable HTTP）が、**セッションアフィニティなしで複数のインスタンスで動いている**と起きます。
あるインスタンスが発行したセッション ID を、次のリクエストを受けた別のインスタンスが知らないためです。
接続テストがこの状態を見つけると、「**サーバーが、自ら発行したセッション ID を拒否しました。…**」と出ます。

Agent Fleet の側では直せません。サーバーを次のどれかにします。

- ステートレスにする（ステートレスな Streamable HTTP のモードなど）
- インスタンスを 1 つにする
- 同じ `Mcp-Session-Id` のリクエストを、いつも同じインスタンスに振り分ける

ロードバランサーの Cookie によるスティッキーセッションでは解決しません。Claude Code は MCP のリクエストで Cookie を送り返さないためです。
サーバーを直したら、セッションを再起動してください。接続テストは [セッションに MCP サーバーを追加する](../integrations/mcp-servers.ja.md#接続テストで確かめる) にあります。

## MCP サーバーの行に「再サインインが必要」「追加の権限が必要」と出る

OAuth のサーバーの行の状態です。OAuth のサーバーは、サインインしている間だけセッションとアシスタントに渡されます。

| 行の表示 | 意味 | やること |
|---|---|---|
| 「**再サインインが必要**」 | 保存されているサインインを更新できなくなった | 「**もう一度サインイン**」を押す。それまで、新しく起動するセッションにはサーバーが渡されない |
| 「**追加の権限が必要**」 | ツールに要る権限を、まだ許可していない | 「**追加の権限を許可する**」を押す。いまの権限に足して、サインインし直す |
| サインインが終わっていないという案内 | サインインを始めたまま戻ってこなかった | [セッションに MCP サーバーを追加する](../integrations/mcp-servers.ja.md#サインインが最後まで終わらない) の手順でやり直す |

## 外から接続したアプリに、ツールが出てこない

⚙設定 →「MCP トークン・接続アプリ」の「**接続済みアプリ**」で、そのアプリの「**最近の呼び出し**」を開きます。
リクエストの HTTP ステータスと、`tools/list` が返したツールの数を確かめてください。

- 一覧が空に見えるときは、更新を押します
- 必要なら、アプリからつなぎ直します

詳しくは [リモートの MCP クライアントをサインインでつなぐ](../outside/oauth-client.ja.md#接続できるのにツールが出ない) にあります。

## Jira のボード・スプリント・エピックが「利用できません」と出る

Jira Software のスコープがない OAuth の接続です。⚙設定 →「課題管理」の Jira のカードに「**ボード・スプリント・エピック: 利用できません。…**」と出て、`jira init` やボードのコマンドは認可のエラーになります。

1. テナント管理者に、Atlassian のアプリへのスコープの追加と、テナントの Jira のカードで Jira Software のオプションにチェックを入れることを頼みます
2. そのあとで、Jira を一度つなぎ直します

それまで `jira init` を繰り返しても変わりません。課題の表示・一覧・作成・コメントには、このスコープは要りません（[Jira を使う](../integrations/jira.ja.md#ボードスプリントエピックを使う)）。

## `jira issue create` や `comment add` が終了コード 124 で終わった

ラッパーが、制限時間でコマンドを打ち切りました。**課題やコメントはすでにできているかもしれない**ので、すぐには実行し直さないでください。
Jira で確かめてから、なければ作り直します。確かめ方は [Jira を使う](../integrations/jira.ja.md#書き込みが終了コード-124-で終わった) にあります。

## `jira` が終了コード 3 で終わった

`jira issue create` や `jira issue edit -b` で、説明文だけを設定できませんでした。
`create` のあとは課題がすでにあるので、作り直さないでください。説明文は `jira issue edit` で設定します（[Jira を使う](../integrations/jira.ja.md#課題を作ったら終了コード-3-で終わった)）。

## AWS のコマンドが「Unable to locate credentials」と言う

コマンドが、あなたの資格情報を見つけられませんでした。ワークスペース自身の権限は、あなたのシェルには渡されません。
資格情報を設定するのではなく、⚙設定のプロファイルを使って `af-aws-exec` で実行します。

```
af-aws-exec --profile <名前> --account <ID> -- <コマンド>
```

直し方は [AWS SSO を使う](../integrations/aws-sso.ja.md#unable-to-locate-credentialsと出る)、オプションの一覧は [af-aws-exec](../../ref/cli/af-aws-exec.ja.md) にあります。

## `af-gcloud-exec` が終了コード 3 で終わった

終了コード 3 がログインの意味になるのは、ラッパーがそう言ったとき（「the login was requested in the Agent Fleet Console …」「Google Cloud login required …」）だけです。
トーストか ⚙設定からログインするか、表示された端末用のコマンドを実行してから、もう一度実行してください。
それ以外のときは、コマンド自身の終了コードです。そのコマンドのエラーを読みます（[Google Cloud を使う](../integrations/gcloud.ja.md#困ったとき)）。
