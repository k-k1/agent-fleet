# エージェントにログインできない・モデルが出ない

[English](agents.md) | 日本語

エージェントのログインが切れた、使いたいモデルが選べない、アシスタントが答えなくなったときに、原因と直し方を探せます。
エージェントごとの接続のしかたは [エージェントを選ぶ](../agents/choose.ja.md) から各ページをたどってください。

## claude のセッションに「Select login method」などのログインの画面が出る

接続はたいてい切れていません。ログインの問題ではなく、claude の対話画面が初回のセットアップをやり直しているだけです。

- セッションを**再開**するか、⋯ メニューの「**作り直す（今の会話はアーカイブへ）**」で直ることがほとんどです
- ターミナルで `/login` を実行してもかまいません

接続の状態は、⚙設定 →「エージェント」の Claude のカードで確かめられます（[Claude を接続する](../agents/claude.ja.md#接続する)）。

## 「ログインが切れています」と出て、エージェントが止まった

会話のエラーに「**再認証**」が出ます。押すと ⚙設定 →「エージェント」が開き、そのエージェントのカードまで移動します。
そこでログインし直せば、セッションはそのまま続きから動かせます。

- ログインし直すと、同じエラーの表示が「**再認証済みです。…**」に変わり、ボタンが消えます
- Claude で「**中断したターンの自動再開**」がオンなら、止まったところから自動で続きが始まります。続きのやり取りには「**自動再開**」のバッジが付きます
- エラーの表示は赤いまま残ります。一度失敗したことの記録なので、消えません
- しばらく待っても続きが始まらないときは、その会話に「続けて」と送れば、同じところから再開します

## 「認証切れ — 再認証が必要」と出て、送っても何も始まらない

ワークスペースの Claude のログインの期限が切れています。認証情報はまだ残っているので、ターミナルはふつうの入力待ちに見えますが、送ってもターンは始まりません。
そのため Console は入力待ちではなく「**認証切れ — 再認証が必要**」を出して、送信を断ります。

1. ⚙設定 →「エージェント」の Claude のカードで「**再認証**」を押します
2. ログインし直せば、セッションを止めずに続けられます

ログインのしかたは [Claude を接続する](../agents/claude.ja.md#接続する)、Codex は [Codex を接続する](../agents/codex.ja.md#接続する) にあります。

- Codex も、ターンがログイン切れで落ちたあとは、ログインし直すまで送信を断ります。断ったときのトーストと「**再認証**」は、そのエージェントのカードを開きます
- 起動ダイアログにもログインの期限切れが出ますが、起動はできます。ただし最初の指示は届かず、そのことを「**再認証**」付きのトーストで一度だけ知らせます。ログインし直してから、もう一度指示を送ってください

期限が近づくと、カードに「**あと N 日で期限切れ**」が出ます（残り 3 日以内）。CLI 自身の警告は残り 1 日を切ってから少しの間しか出ないので、切れる前に気づけるのはこのカードです。

## アシスタントのチャットに「Claude のログインが切れています」と出る

アシスタントの会話でも、同じ原因で「**Claude のログインが切れています。再認証してから、もう一度送信してください。**」と出ます。

- 「**再認証**」で Claude のカードを開いて、ログインし直します
- 「**再送する**」で、失敗したメッセージをもう一度送ります

元のエラーは「詳細」に残ります。アシスタントのチャットは [アシスタントに質問する](../chat/assistant.ja.md#チャットとセッションを使い分ける) にあります。

## codex を接続したいのに、承認しても先に進まない

ChatGPT のサブスクで接続するには、ChatGPT の「**設定 > セキュリティ**」で「Codex に対してデバイスコード認証を有効にする」をオンにしておきます。
オフのままだと、承認しても接続が終わりません（[Codex を接続する](../agents/codex.ja.md)）。

## 使いたいモデルが選べない・指定したのに起動を断られる

そのエージェントのカードの「**使わないモデル**」に入っている可能性があります。
入れたモデルは起動ダイアログ・既定のモデル・アシスタントが選ぶ一覧から消え、名前を指定した起動も断られます。定時実行のモデル欄やアシスタント経由の起動も同じです。
外し方は [エージェントを選ぶ](../agents/choose.ja.md#使わないモデルを外す) にあります。

Claude で特定のリリース（`claude-opus-4-8` のような完全な ID）を使いたいときは、同じ画面の「**Claude の追加モデル**」に登録すると選択肢に並びます。

## 起動ダイアログに「既定」しか出ない

codex・opencode・copilot・cursor・kiro・agy・lcpp・muse は、ダイアログを開いたときにモデルの一覧を取りに行きます。
「**モデル一覧を取得しています…**」がしばらく出るのは正常です。消えるまで待ち、そのあとに出た文言で判断します。

| 出ている文言 | やること |
|---|---|
| 「**選べるモデルを設定ですべて除外しています**…」 | そのエージェントのカードの「**使わないモデル**」を見直す |
| 「**いまの課金の選択では、選べるモデルが 1 つもありません**…」 | opencode のカードの「**opencode.ai への課金**」を見直す（[OpenCode を接続する](../agents/opencode.ja.md)） |
| 「**既定のモデルのみ利用できます（接続とプランをご確認ください）**」 | エージェントが空の一覧を返しています。カードで接続とプランを確かめる。GitHub Copilot の Free プランは Auto だけなので、これが正常 |
| 「**モデル一覧を取得できませんでした。ワークスペースの起動直後かもしれません**…」 | 一覧を取りに行けていません。起動直後は Agent がまだ待ち受けていないので、数十秒おいてダイアログを開き直す |

## opencode のセッションが「作業中」のまま何も返ってこない

会話の上に「**プロバイダがエラーを返し、エージェントが再試行しています（N 回目）: …**」が出ていないか見てください。
opencode がプロバイダーのエラーを再試行しています。原因と直し方は [OpenCode を接続する](../agents/opencode.ja.md#プロバイダがエラーを返しエージェントが再試行していますと出る) にあります。

この帯が出るのはマネージドのセッションです。ターミナル（CLI）のセッションには帯がなく、opencode 自身の再試行の出力がターミナルに出ます。

## opencode を起動すると「この opencode のバージョンには対応していません」と出る

ワークスペースで動く opencode のバージョンが 2 より古くなっています。たいていは、自分で入れたものか、バージョンを固定したものです。
Agent Fleet が動かせるのは opencode 2（`@opencode/cli`）だけなので、古いバージョンを消すか 2.x に固定してから、セッションを起動し直してください（[OpenCode を接続する](../agents/opencode.ja.md)）。

## アシスタントが自動で進めるのをやめた

自動応答の上限に達しています。暴走を防ぐため、あなたの発言なしに続けて動ける回数には上限があります（既定は 10、最大は 50）。
**次のメッセージを送ると再開します。**

- 上限は ⚙設定 →「アシスタント」の「**自動応答の上限回数**」で変えられます。無制限にはできません
- 正常な完了報告で自動応答させたくないときは、同じ画面の「**静かな完了報告**」をオンにします。報告カードと通知だけが届きます

自動応答のしくみは [フリート・オペレーターに任せる](../fleet/operator.ja.md#報告を受け取る) にあります。

## アシスタントのチャットが、コンテキストが上限を超えたと言って答えない

会話が長くなりすぎています。次のどちらかで続けます。

- コンテキストバーの右端の「**圧縮**」で、要約を引き継いで続ける
- 新しいチャットを開いて、要点だけを渡す

使用率が 90 % を超えたまま次のやり取りを始めると、先に自動で圧縮されます。それより前に上限を超えると、この状態になります。
⚙設定 →「アシスタント」の「**自動圧縮の閾値（トークン）**」を下げておくと、起きにくくなります（[アシスタントに質問する](../chat/assistant.ja.md#会話が長くなったら圧縮する)）。
