# 手元の Claude Code の作業をワークスペースに移す

[English](move-work-in.md) | 日本語

手元の PC の Claude Code で始めた作業を、ワークスペースのセッションで続けられます。ノート PC を閉じても作業を止めたくないときに使います。

## 全体像

| あなたがやること | エージェントがやること |
|---|---|
| スキル `af-move` を一度だけ保存する | — |
| 手元の Claude Code で `/af-move` と入力する | 手元の Claude がコミットの中身を見せ、あなたの OK を待つ |
| コミットを OK する | 手元の Claude が push し、引き継ぎメモを書き、ワークスペースにセッションを作る |
| Console でそのセッションを開く | ワークスペースのセッションが、push されたコミットから始まっているかを確かめ、メモを要約して指示を待つ |

移るのは、push したコードと引き継ぎメモです。会話そのもの、それまでのツールの出力、push していないものは手元に残ります。

## 始める前に

- 手元の Claude Code が、`write` のスコープで `/mcp` につながっていること。[サインイン](oauth-client.ja.md#接続する)でも
  [トークン](external-claude.ja.md#トークンを発行する)でもかまいません。サインインでつなぐなら、サーバーを自分のユーザー用に登録して、
  Claude Code の MCP のメニューから認証します

  ```sh
  claude mcp add --transport http --scope user agent-fleet https://<Console のアドレス>/mcp
  # 続けて Claude Code の中で: /mcp → agent-fleet → Authenticate。確認ページでは write を選ぶ
  ```

- 移す先のリポジトリが、ワークスペースにすでにあること
- ワークスペースが起動していること

## スキルを保存する

次のスキルを、手元の PC の `~/.claude/skills/af-move/SKILL.md` に一度だけ保存します。

````markdown
---
name: af-move
description: この作業を Agent Fleet のセッションに移す（要約で引き継ぐ）
disable-model-invocation: true
argument-hint: "[次のセッションに伝えたいこと]"
---
この作業を Agent Fleet に移したい。次の順で進めて、各段階の結果を短く報告して。

1. `git status` と現在のブランチを見せて。未コミットの変更があれば、何をコミットするか一覧で見せて私の OK を
   待つ。OK が出たら WIP コミットして今のブランチを push する。`.env`・鍵・トークンなど秘密を含むファイルは
   コミットしない。push 後の `git rev-parse HEAD` を控える。
2. `git remote get-url origin` をホストと `owner/name` のパス（`.git` は除く）に分ける。agent-fleet の
   `list_repos` を呼び、`remote` がそのホストで `remotePath` がそのパスのものを残す。worktree はクローンと同じ値を
   持つので、`name` に `@` が付いていないものを優先する。1 つも残らなければ止まって教えて。複数残ったら一覧を
   見せて私に選ばせて。その `path` を使う。
3. 下のテンプレートで引き継ぎメモを書く（日本語、4000 字以内）。会話に出てきたトークン・パスワード・
   社外秘の値は書かない。
4. agent-fleet の `create_session` を呼ぶ: `dir` = 手順 2 の path、`worktree` = true、
   `branch` = push したブランチ名、`title` = 作業の短い件名、`initial_prompt` = 手順 3 のメモ。
5. 返ってきたセッション名を教えて。それ以降、このセッションではコードを変更しないで。

補足: $ARGUMENTS

--- 引き継ぎメモのテンプレート ---
これは Agent Fleet の外で動いていた Claude Code セッションからの引き継ぎです。

- ブランチ: <branch> / 引き継ぎ時点のコミット: <sha>
- 最初に `git rev-parse HEAD` が <sha> と一致するか確認すること。一致しなければ `git fetch origin` のあと
  `git merge --ff-only <sha>` を実行し、もう一度 `git rev-parse HEAD` を確かめること。HEAD が <sha> になるまでは
  作業しないこと。fast-forward できない、または HEAD がまだ違うときは、止まって報告すること。
- 元の作業フォルダ: <絶対パス>。メモ中のパスはこれ基準なので、今の作業ツリーのルート基準に読み替えること。

## ゴール
## 済んだこと
## いまの状態（最後の依頼の原文、未解決の問題、失敗しているテスト）
## 次にやること
## 決めたこと・やってはいけないこと

上を読み、理解した内容を 3 行で要約して次の一手を提案したら、指示を待って止まること。
````

## 作業を移す

1. 移したい Claude Code のセッションで `/af-move` と入力します。続けて、次のセッションに伝えたいことを書き添えてもかまいません
2. Claude が、コミットする内容を一覧にして OK を待ちます。`.env`・鍵・トークンなどの秘密を含むファイルはコミットしません
3. OK すると、push、引き継ぎメモの作成、セッションの作成まで進み、セッションの名前を教えてくれます
4. Console でそのセッションを開きます。セッションは push されたコミットから始まっているかを確かめ、メモを要約して、次の一手を提案して待っています
5. 手元のセッションは閉じます。1 つのブランチを 2 つのセッションで触ると、互いの作業がぶつかります

ワークスペースのセッションは、新しい worktree で、push したブランチをもとにした一時ブランチで作業します。
元のブランチに作業を戻したいときは、セッションにそのブランチへ push するよう頼んでください。

引き継ぎメモは、「**MCP 経由**」の印が付いた最初の指示として届きます。セッションはこれを同僚の依頼として扱い、あなたの承認とはみなしません
（[セッションに届く指示の見え方](external-claude.ja.md#セッションに届く指示の見え方)）。権限の確認やプランへの回答は、いつもどおり Console でしてください。

## 困ったとき

### 「push されたコミットから始まっていない」と報告される

セッションは、push されたコミットまで自分で fast-forward してから始めます。それでも報告されるときは、push したブランチと
ワークスペース側のブランチが分かれています。手元で push した内容を確かめてから、`/af-move` をやり直してください。

### Claude がリポジトリを見つけられずに止まる

移す先のリポジトリがワークスペースにありません。Console で [クローン](../code/clone.ja.md) してから、もう一度 `/af-move` を実行してください。
