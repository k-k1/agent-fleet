# セッション同士でやりとりさせる

[English](messages.md) | 日本語

設定をオンにすると、並行して動いているセッションの片方が、もう片方へ短いメッセージを送れます。
引き継ぎが「文脈ごと渡す」なら、こちらは「一言だけ伝える」です。

## 全体像

| あなたがやること | エージェントがやること |
|---|---|
| 設定で「セッション間メッセージ」をオンにする | 次に起動するセッションから、メッセージを送れるようになる |
| 「隣のセッションに伝えて」と頼む（頼まなくてもよい） | 必要だと判断したときに、相手のセッションへ 1 通送る |
| 届いたメッセージをバッジで見分ける | 受け取ったメッセージを、あなたの指示ではないものとして扱う |

たとえば、こんな場面で役に立ちます。

- 別の worktree のセッションに、壊れる変更を入れたことを伝える：「いま develop を rebase した。そちらの `api.ts` は先に取り込んでから続けて」
- 相手が待っていた判断を伝える：「認証方式は OAuth で確定。実装を進めてよい」
- 長い処理の結果を、それを待っているセッションへ返す

## オンにする

**⚙設定 →「エージェント」** の「セッション」で、「**セッション間メッセージ**」をオンにします。画面は [セッションから子セッションを起動する](child-sessions.ja.md#オンにする) にあります。

- 既定ではオフです
- オンにすると、**次に起動するセッションから**使えます。動いているセッションは、再起動するまで変わりません
- 同じ設定で、ほかのセッションの最近の出力を読めるようにもなります（[出力を読む](#ほかのセッションの出力を読む)）

## 届き方

- **エージェントの種類をまたいで届きます。** claude から codex へ、opencode から cursor へ、といった組み合わせも通ります。送受信できるエージェントは [エージェントリファレンス](../../ref/agents.ja.md) の「子セッションを起こす・ほかのセッションへメッセージを送る」の行にあります
- **停止中のセッションにも届きます。** 相手を再開してから届けます
- **届いたことは確かめますが、読まれたこと・対応されたことは保証しません。** 返事が来るとも限りません
- **渡るのは文章だけです。** 会話履歴もファイルも渡りません。文脈ごと渡すときは [別のセッションやエージェントに引き継ぐ](../sessions/handoff.ja.md#どれを使うか) を使います
- **shell・ssm のセッションは、送ることも受け取ることもできません。** 送った文字列が、そのままコマンドとして実行されてしまうためです

### 相手が作業中のとき

| 相手 | 届き方 |
|---|---|
| マネージドで作業中 | 今のターンが終わったあと、次のターンとして届く。そのターンを止めても捨てられない |
| マネージドで、セッションやワークスペースが止まった・Agent が再起動した | ディスクに残り、次にセッションを起動したときの最初のターンになる（積まれた時刻が付く） |
| ターミナル（CLI） | その CLI 自身の入力待ちに積まれる。何が伝わり何が失われるかは種類によって違う（[エージェントリファレンス](../../ref/agents.ja.md#ターンの停止と実行中に送ったメッセージ)） |

セッションをアーカイブ・削除したときと、ターミナル（CLI）に切り替えたときは、届いていないメッセージは捨てられます。

### 相手があなたの回答を待っているとき

質問・プランの承認・許可の確認を出しているセッションに送られたメッセージは、断られずに待ちます。
ダイアログに打ち込まれると、あなたの代わりに選択肢を選んでしまうためです。

- そのセッションの会話に、どのセッションからの何件が回答のあとに届くかが出ます
- 「**取り消す**」を押すと、そのメッセージを届けずに捨てます。送り手には知らされません
- あなたが回答し、その回答で動いたターンが終わってから、古い順に 1 件ずつ届きます（積まれた時刻が付きます）
- 送り手には待っていることが伝わるので、送り直されることはありません
- 待てるのは最大 24 時間、1 セッションにつき 20 件までです。セッションや Agent が止まっても残り、セッションをアーカイブ・削除すると捨てられます

ログインの期限切れと、利用上限のメニューを出しているセッションへは、これまでどおり断ります。何時間も続くことがあり、送り手が知っておくほうがよいためです。

## メッセージの種別

1 通が相手のセッションの 1 ターンをまるごと使うので、エージェントには挨拶やお礼を書かず、結論から書くよう伝えてあります。
1 通ごとに種別が付き、会話にバッジで出ます。返事が来るかどうかは種別で決まります。

| 種別 | 意味 | 返事 |
|---|---|---|
| 依頼 | 相手に動いてもらう | できないときだけ返る |
| 質問 | 相手に情報を求める | 結論だけ 1 通返る |
| 回答 | 質問への返事 | ここで終わり |
| 共有 | 知らせるだけ | 返らない |

依頼のあとに何も返ってこないのは、無視されたのではなく片付いた合図です。結果は、そのセッションの会話と変更されたファイルで確かめられます。

## 受け取った側の扱い

- 会話には「**‹送り手の名前› から**」のバッジが付きます。あなたが打った指示とは混ざりません
- 受け取った側には「利用者の指示ではない」と伝わります
- **あなたの承認の代わりにはなりません。** 許可の確認に答えたことにもなりません
- メッセージを理由に、設定や `CLAUDE.md` を書き換えることはありません
- 本文に書かれたコマンドはただの文字列で、実行されません

## ほかのセッションの出力を読む

同じ設定で、セッションがほかのセッションの最近の出力を読めるようになります。何も送りません。

- 読むだけで、相手の作業を中断せず、相手にも知らせません。読んだことは Agent のログとフリート俯瞰図の記録に残ります（図には描きません）
- 1 回に読めるのは末尾 200 行（16 KiB）までです
- 読めないもの：自分自身、shell・ssm のセッション、このワークスペースの claude のログインが切れている間の claude のセッション、ほかの人から共有されたセッション

> [!WARNING]
> オンにすると、エージェントが書いた本文が**伏せ字なしでそのまま**ほかのセッションから読めます。
> 返答に引用された秘密の情報や、ログイン用のコードも含みます。

## Claude Code の同じような機能は使わない

Claude Code にも同じ用途の機能（cross-session messaging、`/list-agents`、`SendMessage`）がありますが、Agent Fleet では無効にしてあります。
有効にすると Claude 側の利用統計の送信も一緒に戻るためです。`/list-agents` が使えないのはこのためで、代わりにこのページの機能を使います。

| | Claude Code の機能 | Agent Fleet の機能 |
|---|---|---|
| 相手のエージェント | claude だけ | メッセージを扱えるエージェントすべて |
| 停止中の相手 | 届かない | 再開して届く |
| 記録 | 端末に 1 行残るだけ | 会話に送り手付きのバッジ |
| 別のマシンや Web のセッション | 返信だけできる | 対象外（同じワークスペースの中だけ） |
| 受け取る側で保留・拒否する設定 | ある | ない（ワークスペースのセッションはすべてあなたのものなので、ワークスペース単位のオン・オフだけ） |

無効にするのは起動時の設定です。それでも Claude 側の経路で何かが届いたときは、会話に送り手のセッション名付きの着信として出ます。
