# フリート・オペレーターの使いかたの例

[English](operator-patterns.md) | 日本語

フリート・オペレーターに頼むときの、よく効く型を 5 つ紹介します。そのままプロンプトの下書きに使えます。
オペレーターの始め方と、できることは [フリート・オペレーターに任せる](operator.ja.md) にあります。

## 全体像

| 型 | 向いている作業 |
|---|---|
| [調査して、分けて、並列に実装する](#調査して分けて並列に実装する) | 原因の調査から修正までを、いくつかの独立した作業に分けられるもの |
| [同じ直しを何か所にも当てる](#同じ直しを何か所にも当てる) | 同じ修正を、いくつものリポジトリやモジュールに当てるもの |
| [エージェントを比べる・クロスレビューする](#エージェントを比べるクロスレビューする) | 解き方が割れる設計の課題や、別の目でレビューしたいもの |
| [実装・テスト・レビューを順に流す](#実装テストレビューを順に流す) | 前の工程の結果で、次にやることが決まるもの |
| [状況をまとめてもらう・メモを捌く](#状況をまとめてもらうメモを捌く) | 動かす前に様子を知りたいとき |

## 調査して、分けて、並列に実装する

いちばんおすすめの型です。調査と実装で、動かすセッションの数を変えます。

1. **調査**：まずふつうにセッションを 1 本起動して調べさせます。「原因を調べて、**独立に進められる作業に分けた修正計画**をまとめて」のように、あとで分けやすい形で出させるのがこつです。計画が大きくなるなら、ファイルに書いてコミットさせておきます（オペレーターはセッションの出力を主に末尾から読むためです）
2. **引き継ぎ**：オペレーターに頼みます

   > セッション◯◯の調査結果を読んで、作業ごとにセッションを分けて進めて

   オペレーターは元のセッションの出力を読み、要点を新しいセッションの最初のタスクに入れて渡します
3. **並列に実装**：作業ごとに worktree のセッションが起動するので、互いのファイルを踏みません。軽い修正は軽いモデル、難所は重いモデル、のように振り分けも頼めます
4. **まとめ**：報告がそろったら、オペレーターに結果を要約させ、まとめ役のセッションに「各ブランチを取り込んでテストを通して」と指示させます。最終レビューとマージはあなたが行います

## 同じ直しを何か所にも当てる

同じ直しを、いくつものリポジトリやモジュールに当てたいときの型です。見本の 1 件と、その展開に分けます。

1. まず 1 か所を自分のセッションで直し、やり方を固めます
2. オペレーターに頼みます

   > セッション◯◯でやった修正と同じ要領で、残りの △△ と □□ にもセッションを起動して当てて

   オペレーターは見本のセッションの出力から要領をまとめ、それぞれのセッションに渡します
3. 報告が届くたびにオペレーターが結果を確かめ、漏れや失敗だけをあなたに上げてきます

## エージェントを比べる・クロスレビューする

オペレーターはエージェントの種類をまたいで見ているので、同じ課題を claude・codex・opencode に並行して解かせて比べられます。

> この課題を claude と codex の 2 つのセッションで別々に解かせて。両方の報告が来たら、やり方の違いを表で比べて

> セッション A の実装を、別のエージェントのセッション B にレビューさせて。指摘は A に戻して

## 実装・テスト・レビューを順に流す

報告を、次の工程のきっかけにする型です。最初に段取りを伝えておけば、報告ごとにオペレーターが判断して次へ進めます。

> 実装が終わったらテストを流して。落ちたら直させて、通ったらレビューの観点でもう一周して

自動応答の回数には上限があります（既定 10 回、最大 50 回）。長い流れでは、節目で「続けて」と声をかけるか、⚙ 設定 →「アシスタント」の「**自動応答の上限回数**」を引き上げてください。

## 状況をまとめてもらう・メモを捌く

動かす前の「見る」だけでも役に立ちます。

| やりたいこと | 頼み方 |
|---|---|
| 席を外したあと・翌朝に様子を知る | 「昨日から動いているセッションの今の様子と、止まっている理由をまとめて」 |
| たまったメモを振り分ける | 「メモキューにたまっているものを、内容ごとに合うセッションへ振り分けて送って」 |
| 終わったセッションを片付ける | 「役目が終わったセッションを確かめて、要らないものは止めて」「片付けられるものを見せて」 |
| 利用枠の残りを見て振り分ける | 「claude と codex、どっちがまだ利用枠に余裕ある？」「この大きめのタスク、制限を考えるとどっちに振るのがいい？」 |
| コンテキストが詰まったセッションを探す | 「コンテキストが詰まってきているセッションはある？」 |

- 止めたセッションは再開できるので、消えるわけではありません。オペレーターが示す一覧を承認すれば、終わったものをアーカイブや削除で片付けることもできます
- コンテキストが詰まったセッションには、指示を重ねる代わりに要点をまとめて新しいセッションへ渡すのがおすすめです（[調査して、分けて、並列に実装する](#調査して分けて並列に実装する) の手順 2）
- メモを思いついたときにためておく使い方は [メモをためて渡す](../chat/memos.ja.md) にあります
