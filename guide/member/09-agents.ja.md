# 09. エージェント — 接続の仕方と選び方

[English](09-agents.md) | 日本語

接続はすべて **⚙設定 → 「エージェント」タブ**から行います（ワークスペースの起動が必要）。

## 対応エージェントと選び方

Agent Fleet が動かすセッションの種別は 11 個あります。それぞれが何に対応しているか（実行方式・履歴・Plan モード・
使用量チップ・指示の配布など）、サインインの仕方、出る状態、選び方は、すべて
[エージェントリファレンス](../ref/agents.ja.md#どれを選ぶか)にまとめています。接続の変更は即時、
挙動設定は各エージェントの**新しいセッションから**反映されます。以降の節は、⚙設定 → 「エージェント」の
カードごとの説明です: [Claude](#claude)・[Codex](#codex)・[OpenCode](#opencode)・
[GitHub Copilot](#github-copilot)・[Cursor](#cursor)・[Kiro](#kiro)・
[Antigravity（agy）](#antigravityagy)・[Muse Code](#muse-code)・[lcpp](#lcpp)。

どの種別がマネージドで、どの種別がターミナル（CLI）で動くかは[エージェントリファレンス](../ref/agents.ja.md)に、
それぞれの選び方は [03 セッションを始める](03-starting-sessions.ja.md#実行方式-マネージドとターミナルcli)にあります。
マネージドのチャット表示は、左ペインのリポジトリを使わないアシスタントチャットとは別です。

接続がうまくいったかは、⚙設定 → 「エージェント」タブの各カードで確認できます。
**「接続済み」** と表示され、claude / codex ならログインしているアカウント（メール）と
プランも出ます。1 つ接続すれば、新規セッションの種類にそのエージェントが並ぶように
なります（[03](03-starting-sessions.ja.md)）。

> **自律実行についての注意。** エージェントは利用者に代わってコマンドを実行し、ファイルを
> 編集し、push します。無人（定時実行）でも、権限確認を省くモードでは毎回尋ねずに実行する
> こともあります。shell / SSM セッションは送った文字列を**そのまま**実行します。これらは
> 破壊的・不可逆になりえます。バックアップを保持し、最小権限の認証情報を使い、承認ゲート
> （shell コマンドの確認、チャットブリッジの承認 / 却下）を活用してください。
> あわせて [11 たくさんのセッションを動かす](11-many-sessions.ja.md) も参照してください。

**shell** は素のシェル、**ssm** は AWS SSM 経由のリモートログインで、どちらもターミナルのみで、
会話・状態モデル・通知はありません。muse のセッションはツールの承認を求めないので、上の注意書きは
`shell` と同じように muse にも当てはまります（[Muse Code](#muse-code)）。ほかのエージェントも
含めて、種別ごとに出る状態は[エージェントリファレンス](../ref/agents.ja.md#ミラーに出る状態)に
まとめています。

## モデルの価格と使用量チップ

モデルの一覧には、各モデルの **API 定価**（100 万トークンあたりの入力 / 出力）とコンテキスト長が
並び、選んだモデルの下にはキャッシュ読取の単価と公開日も出ます。値は models.dev の公表値で、
**従量課金で API を使ったときの定価**です。claude・codex・agy をサブスクリプションで使う場合の
請求額ではありません（opencode は実際に課金される opencode 側の価格です）。codex が廃止を
予告しているモデルと、models.dev で非推奨のモデルには「廃止予定」が付きます。cursor・muse・lcpp と、
claude のティア別名（Opus など）には出しません。値の出どころが無いか、別名が
どのモデルになるかが CLI の版で変わるためです。登録した claude の完全 ID には出ます。

使用量チップが増えると WSバーが狭くなるため、**バーに残るのは直近に使った 2 つだけ**です。
残りは右の **「+N」** に畳まれ、押すと中で開けます（畳まれていても値は取り続けるので、
開いた瞬間に取り直すことはありません）。上限に近づいた（95% 以上／Full reset を持つ）
チップは、しばらく使っていなくても表に出ます。各チップのドロップダウンの
**「WS バーでの表示」** で、そのエージェントを **常に出す**／**自動**（既定）／
**常に畳む** から選べます。3 つ目を常に出したいときは「常に出す」を選んでください
（「常に畳む」は上限に近づいても表に出しません）。スマホでは ⋯ の中に縦に並ぶため、
畳みません。

WSバーの使用量チップは、アカウント単位の利用枠（使える量の上限）を読み取れるエージェント
にだけ表示されます。どの種別が対象かは、[エージェントリファレンス](../ref/agents.ja.md)の「使用量 / 残量チップ」の行にあります。

## アシスタントチャットの既定モデル

各アシスタントで個別にモデルを指定でき、claude の
既定は管理者が配備全体で変えることもできます。会話用途のため高速・低コストの
ティアを既定にしています: claude → Sonnet 5 · codex → 一覧にある最新の Luna（執筆時点で `gpt-6-luna`） · opencode →
一覧にあれば `opencode-go/glm-5.2`、無ければ `opencode/nemotron-3-ultra-free` · agy → Gemini 3.5 Flash · cursor → Cursor 自身の既定
（Auto）。muse は高速ティアではなく、推奨のままにすると、contributor 用ではない Muse Code の最新モデルを選びます。
Meta に会話を使われるかどうかは、モデルとは別に、自分の Contributor モードの設定に従います（[エージェントリファレンス](../ref/agents.ja.md)のアシスタントチャットの注）。そもそもどの種別が
アシスタントチャットになれるかは、同じ表の「アシスタントチャットとして利用」の行にあります。たとえば
cursor のアシスタントは**読み取り専用**で動きます。

## Claude

「エージェント」タブの **Claude** で **「OAuth 接続」** を押すと、ログインが新しいタブで
開きます。自分のブラウザで承認し、表示された**コードを貼り付けて「完了」** します
（タブが自動で開かないときは「ログインリンク ↗」から開けます）。接続済みになると
メールとプラン（例: `…@gmail.com · pro`）が表示されます。

Claude の挙動は同じ画面で切り替えられます。

- **既定モデル**：claude セッションを起動するときの初期選択モデル。Opus / Sonnet / Haiku などのティア別名はそのティアの最新版に追従し、登録した完全モデル ID は特定のリリースに固定します。
- **Claude の追加モデル**：`claude-opus-4-8` のような完全 ID を登録すると、旧リリースが起動ダイアログ・既定モデル設定・MCP `list_models` の通常の選択肢になります。Claude Code の OAuth サブスクリプションにはアカウント連動のカタログ取得口がないため、利用できるかはセッション起動時に Claude Code が確認します。登録を削除しても既存セッションの設定は書き換えません。
- **使わないモデル**：選ばせたくないモデルを外します。外したモデルは起動ダイアログ・設定・アシスタントが選ぶ一覧（MCP `list_models`）から消え、明示的に指定した起動（定時実行のモデル欄やアシスタント経由も含む）は断られます。プランによって追加課金になるモデル（例: Claude の Team プランの Fable は API クレジット扱い）の誤選択を防ぐための設定です。エージェントごとに設定でき、除外した時点で「既定モデル」やリポジトリごとの前回値も自動で外れます。除外は選んだモデル 1 つだけに効きます（`gpt-5.4` を外しても `gpt-5.4-mini` は別モデルとして残ります）。ただし claude のティア名（`fable` など）は別名なので、その別名を含む完全なモデル名にも効きます。なおターミナル内で `/model` を打つなど CLI 自身の操作までは止められません。これは選択の事故防止であって課金の強制ガードではありません。
- **思考を展開して表示**：セッション画面の「思考」ブロックを最初から開いた状態で出します。既定はオフ（畳んだ状態で、見出しをクリックすると読めます）。claude の思考は、ツールを次々に走らせている間に「いま何をしているか」を短くまとめた文章で、ターミナルに出ているものと同じです。長い自動作業の途中では、これが唯一の文章になることもあります。表示だけの設定で、エージェントの動き方は変わりません（codex / opencode 側の同じ設定とは独立です）。
- **返答をストリーミング表示**：Claude が返答を書いている間、セッション画面に「書いている途中」のブロックとしてどう表示するか。書き終えると通常の返答に置き換わります。3 択です。**文字送り**（既定）は届いた文を 1 文字ずつ、チャットアプリのように表示します。**行ごと**は届いた行をそのまま表示します。**オフ**は書き終えた返答だけを表示します。どちらでも画面に届くのは書き終えた行なので、長い段落はまとめて届きます。ツール実行の合間に書かれる文章は、これまでどおり書き終えてから表示されます。端末で「視差効果を減らす」を設定していると、文字送りは行ごとと同じ動きになります。表示だけの設定で、ターミナルとエージェントの動作は変わりません。
- **リモートコントロール**：手元の Claude アプリなどから、走っているセッションを遠隔操作する機能のオン / オフ。新しいワークスペースでは既定オフ（必要ならここでオンにします）。
  - **必要なもの**：`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` が設定されている間、Claude はリモートコントロールを開始しません。ワークスペースのイメージは通常この変数を設定しています。その状態では Claude セッション自体は動きますが、リモートコントロールのセッションは黙って作られません。
  - **トグルの効果**：オンの間、**以後に起動する** Claude セッションは、この停止を引き継ぐ環境から外した状態で起動します。これでリモートコントロールの起動を妨げる要因が1つ外れます。次にセッションを起動または再開したときから効き、すでに走っているセッションは起動時の設定のままです。オフに戻すと、その後に起動するセッションはイメージの既定どおりに戻ります。トグルが書くのはワークスペースのユーザー設定で、プロジェクトやローカルの Claude 設定ファイルが `remoteControlAtStartup` を上書きすることもあります。
  - **外すのは引き継ぐ環境だけ**：`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` がユーザー・プロジェクト・ローカル・管理設定いずれかの Claude `settings.json` の `env` にも書かれていると、Claude は起動後にそれを設定し直すので、リモートコントロールは接続しません。その場合は書かれているファイルから削除してください。トグルは、それらの設定ファイルの `env` に書かれた変数を削除・変更しません。
  - **Trusted Devices（信頼済みデバイス）を必須にしている組織**：イメージは `DISABLE_TELEMETRY` も設定したままで、この変更もそのまま残します。設定されている間、リモートコントロールには Claude Code v2.1.283 以降が必要で、組織が Trusted Devices を必須にしていると接続できません。その場合、このトグルだけでは足りません。
  - **この停止が抑えていた他の動作**：トグルをオンにして起動したセッションでは、この変数による抑止が外れるので、リリースノートの取得、PR/MR のステータスバッジの確認、利用可否の確認（たとえば高速モードが使えるか）が行われ、`/feedback` も使えます。テレメトリ（メトリクス）、エラーレポート、自動更新は、それぞれの変数を残すので止めたままです。
  - **わかっていないこと**：これらのセッションで Claude が機能フラグを取得するかどうか（残してある `DISABLE_TELEMETRY` も、上流のドキュメントによればその取得を止めます）。取得する場合に Anthropic へ何が送られるか。どちらも未測定です。
- **通知**：セッションの状態変化を通知するかどうか。
- **RTK（トークン節約）**：後述。

> **「Select login method」やログイン画面が出てしまうときは** → セッション側の
> 一時的な状態で、接続そのものは生きていることがほとんどです。対処は
> [21 困ったとき](21-troubleshooting.ja.md) を見てください。端末内で手動 `/login` する
> 従来のやり方も併用できます。

## Codex

**Codex** は 2 通りで接続できます。

- **ChatGPT サブスクで接続**（推奨）：Plus / Pro の利用枠を使い、追加課金なし。デバイスコード方式です。事前に **ChatGPT の「設定 > セキュリティ」で「Codex に対してデバイスコード認証を有効にする」をオン**にしておく必要があります（これがオフだと承認しても進みません）。
- **API キーで接続**：OpenAI API の従量課金（`sk-…`）。

接続の流れは GitHub と同じ 3 ステップ（コードをコピー → リンクを開いて貼り付け →
承認を待つ）です。

**動作設定**には、codex の思考（chain-of-thought）の見せ方もあります。

- **思考を展開して表示**：セッション画面の「思考」ブロックを最初から開いた状態で出します。既定はオフ（畳んだ状態で、見出しをクリックすると読めます）。表示だけの設定で、エージェントの動き方は変わりません。エージェントごとに独立していて、同じ設定が claude / opencode 側にもあります。

## OpenCode

カードには 2 つのコントロールがあり、決めていることが違います。

**「opencode を使う」** はエージェントぜんぶの電源です。**オフ**のあいだ opencode は起動
しません。API キーを保存していても、アカウントにログインしていても、あとから鍵を足しても
同じです。新しいワークスペースはこの状態から始まるので、自分で選ぶまで opencode.ai には何も
つながりません。

**「opencode.ai への課金」** はオンにすると出てきて、**opencode.ai の使い方だけ**を決めます。
どれを選んでも、自分でつないだプロバイダ（Anthropic・OpenRouter など）とフリートの自前
エンジンのモデルは起動一覧に残ります。

| 選択 | 起動一覧に出るもの | 必要なもの |
|---|---|---|
| **使わない（自分の鍵だけ）** | 自分のプロバイダと自前エンジンだけ。`OPENCODE_API_KEY` は保存されていても注入しません。 | 自分のプロバイダキー 1 本（または自前エンジン） |
| **無料モデルのみ** | 認証なしで使える opencode.ai のモデル。混雑と上限に左右されます。 | 不要 |
| **Go（定額）** | サブスクの id（`opencode-go/…`）。 | API キー（ログインは任意） |
| **Zen（従量）** | 従量課金の id（`opencode/…`）。Go 契約もあれば両方。 | アカウントのログインか API キー |

選んだ枠のモデルが 1 つも無いとき（Go 契約が無いのに Go を選んだ場合など）、起動一覧は Zen
に切り替わります。切り替わったことはカードに表示されます。意図した枠で課金したいときは、認証か契約を
確認してください。

**API キー**は、プリセットから選ぶと env 名が自動で埋まります。

- **opencode.ai**（`OPENCODE_API_KEY`・Go と Zen で同じキー）/ **Anthropic** / **OpenAI** / **OpenRouter** / **Google Gemini** / **Sakana AI**（`SAKANA_API_KEY`・Fugu / Fugu Ultra）/ **カスタム…**（env 名を自分で指定）

キーを貼って **「接続」** すると保存され、opencode 起動時に注入されます。複数のキーを
登録でき、起動時に接続済みプロバイダのモデルを選べます。いまの枠が注入しないキーは、消さずに
「この枠では注入しません」と表示されたまま残ります。

キーや課金の選択を変えても、**稼働中の opencode serve には自動では反映されません**
（serve は起動したときの設定のまま動きます）。反映が要る変更をすると、カードに
「再起動するまで反映されません」という案内と **「opencode serve を再起動して反映」**
ボタンが出ます。再起動すると、応答の途中だった opencode セッションは区切りを待ってから
中断されるので、手が空いているときに押してください。

ほかのエージェントと動きが違う点がいくつかあります。

- **読まれるのは `AGENTS.md` だけです。** opencode は `CLAUDE.md` に切り替えて読むことは
  せず、`CLAUDE.md` しかないリポジトリでは opencode に何も渡りません。opencode に守らせたい
  ことは、リポジトリの `AGENTS.md` に書いてください。あなた自身の **「エージェントへの指示」** は
  opencode にも届きます。Agent Fleet が opencode のグローバルな `AGENTS.md` の
  目印付きブロックに書き込み、**⚙設定 →「エージェントへの指示」** の行に、書き込み先と、実際に効いて
  いるかが表示されます。このブロックは保存のたびに書き直されるので、手で触らないでください。
- **ターミナル（CLI）セッションは 1 つのサーバーを共有します。** ターミナル（CLI）セッション
  は、セッションごとに専用のサーバーを起動する代わりに、Agent Fleet が動かしている opencode
  サーバー（必要なときに起動します）につながります。ターミナルセッションを 1 つ増やすたびに
  メモリがおよそ 150〜250 MB 少なくて済みます（アイドル状態のセッションで計測）。会話・環境・状態は
  セッションごとに別々のままです。そのサーバーが用意できないとき（起動に失敗した、または管理者がワークスペースで
  そのサーバーを止めている）は、自動的に専用サーバーで起動します。管理者がセッションごとの専用
  サーバーに固定することもできます
  （[operate/03](../operate/03-run.ja.md#opencode-2ターミナルセッションと共有サーバー)）。
  セッションは、起動したときのモードのまま動き続けます。
- **質問はフォームです。** opencode が質問してくると、チャット画面に質問カードが出ます。
  質問ごとに 1 つの入力欄があり、選択肢を選ぶか、自分で入力して答えます。**キャンセルして会話に戻る**
  を押すとフォームは取り下げられ、エージェントは続きを進めます。マネージドセッションと、共有サーバー上の
  ターミナル（CLI）セッションで同じように使えます。質問が複数のフォームや複数選択の項目があるフォームも
  同様です。カードが開いている間にターミナルで答えた場合は、カードが「すでに回答済み」と表示するだけです。
  専用サーバーで動くターミナル（CLI）セッションでもカードは表示されますが、質問が複数のフォームや
  複数選択の項目があるフォームはターミナル画面で答えます（質問が 1 つなら、カードのボタンがキーを
  押してくれます）。待機中のフォームは、opencode サーバーが再起動すると失われます。
- **ToDo リストは既定ではありません。** opencode 2 の `todowrite` ツールは、自分の opencode 設定で
  `experimental.todo` を有効にしたときだけ使えます（2.1.4 で確認：既定はオフ）。無効のままなら
  セッション画面に ToDo リストは表示されませんが、正常な動きです（接続が切れたわけではありません）。
  有効にすると、直近の `todowrite` 呼び出しのリストが表示されます。

**動作設定**では、opencode の思考（chain-of-thought）の見せ方も選べます。

- **思考を展開して表示**：セッション画面の「思考」ブロックを最初から開いた状態で出します。既定はオフ（畳んだ状態で、見出しをクリックすると読めます）。表示だけの設定で、エージェントの動き方は変わりません（claude / codex 側の同じ設定とは独立です）。

### プロバイダがエラーを返したとき

opencode は、レート制限や過負荷のようなプロバイダのエラーを再試行します。その間、マネージドのセッション画面には
単なる作業中ではなく、試行回数とプロバイダのメッセージを出す帯（「プロバイダがエラーを返し、エージェントが
再試行しています（N 回目）: …」）が出ます。回答が始まるかターンが終わると消え、ターンはいつでも停止できます。
ターミナル（CLI）のセッションにこの帯は出ず、ターミナルに opencode 自身の表示が出るだけです。

マネージドのセッションでは、再試行しても直らないエラー（リージョンやプライバシーの設定、クォータや課金残高の枯渇、誤った API キー）は、
プロバイダのメッセージ付きでターンを**失敗**として終わらせ、帯は次の入力まで「プロバイダのエラーは再試行しても
直らないため、ターンを停止しました: …」と出ます。「requires Global regions」のメッセージなら、プロバイダ
アカウントのプライバシー／リージョン設定を変更してください（opencode Go ならopencode.ai のワークスペースの
Privacy 設定）。クォータや課金ならアカウントへのチャージを、キーなら該当カードでキーの入れ替えを
（[21](21-troubleshooting.ja.md)）。

### opencode 2 での違い

イメージで動くのは opencode 2 です。opencode 1 を使っていたワークスペースでも、会話はそのまま残ります。
そこで opencode 2 が初めて起動すると、opencode のデータベースをその場で変換し、既存のセッションを
同じセッション ID のまま 1 回だけ取り込むので、マネージド・ターミナル（CLI）のどちらでも続きから
再開できます。opencode 2 で始めた会話は opencode 1 からは見えないので、あとで 1 に戻すとそれらは
失われます。管理者がイメージを opencode 1 に戻している場合、上の `AGENTS.md`・共有サーバー・
質問フォーム・ToDo の説明は当てはまりません（[operate/03](../operate/03-run.ja.md#opencode-1-に戻す)）。

## GitHub Copilot

**copilot**（GitHub Copilot CLI）に個別のログインはありません。**git プロバイダの
GitHub を連携すると自動的に「接続済み」になります**（「Git ホスティング」タブ > GitHub。切断も GitHub
側に連動します）。前提として、その GitHub アカウントに **Copilot のサブスクリプション**
（Free プラン含む）が必要です。無い場合は最初の指示でエラーになります。

- 起動時のモデル選択肢は**プランに応じて自動で切り替わります**。Free プランは
  「自動（Copilot が選択）」のみ、有償プランではそのアカウントで選べるモデルが並びます。
- Free プランは月間の利用枠が小さめです。使用量は GitHub 側の設定画面で確認できます。

## Cursor

**cursor**（Cursor CLI）は「エージェント」タブの **Cursor** カードで
**「Cursor にログイン」** を押します。認可リンクが表示されるので、ブラウザで開いて
承認するだけです（**貼り付けるコードはありません**。承認するとカードが自動で
「接続済み」になります）。前提として Cursor のアカウントが必要です。API キーでの接続は
未対応です。

- 起動時のモデル選択肢は、**そのアカウントで使えるモデルがそのまま並びます**
  （ライブ取得）。セッション起動後のモデル変更はできません。
- プラン残量は Cursor のダッシュボードで確認してください。
- ターミナル（CLI）のセッションでは、終わったターンごとのトークン数が ⚙設定 →
  「エージェント使用量」に記録されます。Agent Fleet が `~/.cursor/hooks.json` に足す `stop` の
  エントリが送るもので、同じファイルのほかのエントリはそのまま残ります。数字は cursor 自身の報告
  なので「一部のみ」の扱いになり、Auto で動いたターンはモデル名 `default` で記録されます。
  マネージドの cursor セッションのターンは、この方法では記録されません。

## Kiro

**kiro**（Kiro・旧 Amazon Q Developer CLI）は「エージェント」タブの **Kiro** カードで
**「Kiro にログイン」** を押します。**device-flow** のログインで、確認コード付きの
認可リンクが表示されるので、ブラウザで開いて承認します（Builder ID / Google / GitHub
など）。承認するとカードにアカウントのメールとともに「接続済み」が表示されます。API キーでの
接続は未対応です。

- **オンデマンド導入。** Kiro の CLI は大きい（~855MB）ため、既定では**イメージに焼き込まれ
  ません**。初めて使うときに各自の home ディレクトリへダウンロードされます。接続カードに
  進捗付きの **「Kiro を導入」** ボタンが出てから、ログインへ進みます
  （Kiro をイメージに焼き込んでいる配備では同梱済みです）。固定された新しい版があるとカードに
  **「Kiro を更新」** が出て、先に更新しておけます。Terminal（CLI）で起動すると、起動時に固定の版へ
  自動で更新されます。更新中も、すでに動いている Kiro のセッションは、再起動するまで古い版で動き続けます。
- 起動時のモデル選択肢はライブ取得で、**Free プランでも named モデルが選べます**
  （Auto、Claude Sonnet / Haiku ほか）。reasoning effort の別ピッカーはありません。
- **マネージド（既定）** と **ターミナル（CLI）** の両方に対応します。そのほかに kiro が
  何に対応しているか（履歴・コンテキストゲージ・Plan モードなど）は
  [エージェントリファレンス](../ref/agents.ja.md)にあります。

## Antigravity（agy）

**agy**（Antigravity CLI）は実験枠です。カードには「実験枠（クォータ小・Antigravity IDE / Jules
と共有）」と表示され、起動メニューには「Antigravity を起動（実験枠）」として並びます。

「エージェント」タブの **Antigravity** カードで **「OAuth 接続」** を押すと、Google のログインが
新しいタブで開きます。承認したら、claude と同じように表示されたコードを貼り付けて「完了」
を押します。接続済みになると、カードにアカウントのメールとプランが出ます。もう 1 つの認証方式の
「GCP プロジェクト（準備中）」は、まだ選べません。agy が動かないホストでは、カードに
「このホストでは利用できません（…）」と出て、agy は起動の選択肢に出ません。

- **ターミナル（CLI）のみです。** agy にマネージド実行はありません。
- 起動時のモデル選択肢は、そのアカウントで使えるものをその場で取得します。reasoning effort は
  モデル名に含まれるので、別のピッカーはありません。WSバーには使用量（5 時間と週）が出ます。
  agy がほかに何に対応しているかは[エージェントリファレンス](../ref/agents.ja.md)にあります。
- **バックグラウンドのコマンド。** agy は `run_command` で走らせたコマンドが
  始まると、コマンドを動かしたままターンを終えます。そのコマンドが動いている間、行は
  **「入力待ち · BG 実行中」** と表示され、セッションはアイドル扱いになりません。ただし、
  バックグラウンドの作業がワークスペースを起こしておくのは既定で最長 2 時間です（配備で
  変えられます）。それを過ぎると、コマンドが動いていてもワークスペースはアイドル停止する
  ことがあります。もっと長いビルドには **自動停止しない** を使います
  （[05](05-stopping-and-tidying.ja.md#セッションを自動停止させない)）。agy が閉じないままのターン（CLI が
  ターンの途中で落ちたなど）は、変化のないまま 1 時間たつと進行中の表示が外れます。ただし、
  そのターンのコマンドがまだ動いているあいだは外れません。
- **Agent Fleet は agy の設定にフックを 1 つ足します。** セッションがどの会話を持っていて、
  作業中かどうかを知るために、`~/.gemini/config/hooks.json` に `agent-fleet` という名前の
  エントリを足し、起動のたびに書き直します。同じファイルにある別の名前のエントリはそのまま
  残ります。フックからの報告がまだないときは、agy の会話データベースから状態を読みます。
  起動のたびに、作業フォルダを信頼済みにして agy が信頼の確認で止まらないようにし、agy の
  テレメトリ設定をオフに保ちます。
- **画像生成。** 「Antigravity (agy)」は、セッションが使える画像の経路の 1 つです
  （[13](13-images.ja.md#セッションに画像を作らせる)）。agy 自身の image-generator
  サブエージェントを通して、1 回の呼び出しで 1 枚を作ります。編集で渡せる参照画像は 3 枚までです
  （Codex の経路は 5 枚）。参照画像はその実行専用のフォルダにコピーされ、実行が読めるのはその
  フォルダだけです。ログインしているアカウントで画像生成が提供されていないときは、
  「the signed-in Antigravity/Gemini account is not offered image generation (agy says: …)」
  というエラーで失敗します。
- RTK は **指示ベース（ベストエフォート）** です（[RTK](#rtkトークン節約)）。

## Muse Code

**Muse Code** はマネージド専用の種別です。起動メニューに出るには 2 つが揃っている必要が
あります。

1. ⚙設定 → 「エージェント」の **Muse Code** カードで **「Muse Code を導入」** を押します（約 299 MB、
   ホームへ 1 回だけ。終わると自動でログイン画面になります）。ピンされた新しい版があるとカードに
   その旨が表示され、**「Muse Code を更新」** が出ます。押すまでは導入済みの版が使われ続け、稼働中の muse
   セッションは再起動するまで古い版で動きます。
2. その後ログインします。**「Meta アカウントでログイン」** は承認リンクとコードを表示するので
   ブラウザで承認します。貼り戻すコードはありません。サブスク契約ならこちらです。**「API キーを使う」**
   は従量課金の経路で、キーを保存すると保存済みのアカウントのログインは消えて従量課金になるため、
   アカウントでログイン済みなら先に切断してください。

同じカードの **「動作」** 設定で、モデルと reasoning effort を指定し、Muse Code の
**contributor モード**を切り替えられます。オンの間は会話が Meta の製品改善に使われることがあります。
既定はオフで、各セッションは作成時のモードを停止・再開をまたいでも保ちます。詳しくは
[エージェントリファレンス](../ref/agents.ja.md) を参照してください。

稼働中の muse セッションでは、入力欄の横の **`/`** ボタンがそのセッション自身のスキルを並べ、
選ぶとそのスキルが走ります（[04](04-conversation.ja.md#スキルやコマンドを呼び出す)。一覧に何が入るかは
[エージェントリファレンス](../ref/agents.ja.md)にあります）。利用上限で muse のターンが止まったときは、
上限が解けると自分で再開します（状態は同じリファレンスにあります）。

カードには muse の課金のされ方が出ます。Meta アカウントでログインしていればプランの範囲、API キーで
接続していれば従量課金です。ワークスペースの環境変数にも API キーが設定されていると、保存済みのログインより
そちらが優先されるため、カードの表示にかかわらず従量課金になる、という警告がカードに出ます。プランで使いたい
ときは、その環境変数を外してください。

> **muse のセッションはツールの承認を一度も求めません。** 承認を検討する前にすべての
> ツール呼び出しがポリシーで許可されます。Workspace のコンテナ内ではサンドボックスを
> 構築できないためです。muse のセッションはこのワークスペースへの届き方が `shell` と
> 同じと考えてください。

Agent Fleet からは見えない muse セッション内の動作（自前の定時実行・セッション間
メッセージ・セッション一覧）の詳細は [エージェントリファレンス](../ref/agents.ja.md#muse-agent-fleet-からは見えないもの) を参照してください。

## lcpp

**lcpp** はフリート自前の llama.cpp エンジンです。ログインも別途のインストールも不要で、
セッション起動ダイアログから他の種別と同じように起動できます。

⚙設定 → 「エージェント」のカードには 2 つの操作があります。**「llama.cpp を使う」**（既定はオン）が
電源で、オフにすると起動導線から消え、ほかの経路からの起動も拒まれます（稼働中のセッションは
動き続けます）。「**自分の接続先**」は、配備のエンジンの代わりに自分のネットワークにある
llama-server へセッションを向けます。URL（と、要るなら API キー）を入れて **「接続を確認」** を押すと
build・窓・モデルが出て、起動ダイアログのモデル一覧はそのサーバーのものになります。設定して
いるあいだ lcpp のセッションはそこへ直結し（テナント管理者のエンジン可否は効きません）、
画面最上部の**チャット**のピルも配備のエンジンでなくその接続先（**接続中**／**届いていません**／
**確認中**と、見つかったモデル）を報告します（[バッジ](badges-and-menus.ja.md#画面最上部のエンジンのピル)）。
欄を空にすると配備のエンジンに戻ります。

最初のセッションの前に、
[lcpp: 実機計測で分かったこと](../ref/agents.ja.md#lcpp-実機計測で分かったこと)を読んでください。
最初のターンは分単位で待つこと、文脈窓には選ぶ価値のある下限があること、動作確認済みのモデルのファミリーが
限られることが書かれています。

ほかに知っておくこと:

- **外部（MCP）ツールは必要になるまで読み込みません。** 有効にした MCP サーバのツールのスキーマが数千文字を超えると、毎ターン全部を送らず、小さな 3 つのツール（`tool_search`・`tool_describe`・`tool_call`）で必要なものを探して使います。小さい文脈窓を圧迫しないためです。承認は他のツールと同じ扱いで、履歴には実際に呼ばれたツールの名前が出ます。lcpp 自身のツール（read・edit・bash など）は常に送られます。管理者は、配備全体でどちらの動きにも固定できます。

## コンテキスト残量を見る

コンテキストゲージのある種別（[エージェントリファレンス](../ref/agents.ja.md)の「コンテキスト使用量ゲージ」の行）のセッションでは、画面上部に **「コンテキスト」**（狭いときは
`ctx`）のゲージが出ます。今の会話が使っているトークン量と上限、そのうちキャッシュ再利用・
新規キャッシュ・未キャッシュの内訳は、表示にマウスを重ねると確認できます。上限に近づくと
「まもなく自動圧縮される可能性があります」と警告が出ます。長い作業で「急に文脈が
薄くなった」と感じたら、ここを見てください。チャット表示ではターンごとの
トークン消費推移も見られます。

## RTK（トークン節約）

ほとんどのエージェントに **「RTK（トークン節約）」** のオン／オフ設定があります。エージェントが
実行するコマンドを賢く書き換えて、消費トークンを抑える仕組みです。このワークスペースの
イメージに RTK が含まれていない場合は「このワークスペースに rtk がありません」と表示されます。

どのエージェントに設定があり、それぞれでどう効くか（毎回コマンドが書き換わるのか、「rtk を使ってね」と
促す指示だけでベストエフォートなのか）は、[エージェントリファレンス](../ref/agents.ja.md)の
「RTK（トークン節約）」の行と脚注にあります。

## エージェントへの指示（自分の働き方を一度だけ書く）

**⚙設定 → 「エージェントへの指示」** に書いた文章は、このワークスペースで新しく起動する
エージェントの指示に加わります。報告の言語や口調、確認を取ってほしい場面、使ってほしいツールなど、
**毎回プロンプトに書いていること**をここへ移すと、以後は書かずに済みます。

指示には 3 つの層があり、この設定は**真ん中**にあたります。

| 層 | 誰のものか | 変えられるか |
|----|-----------|-------------|
| ワークスペースの方針 | フリート全体（運用者） | ここからは変えられません（衝突したらこちらが優先） |
| **エージェントへの指示** | **あなた個人** | **この設定** |
| リポジトリの指示（`CLAUDE.md` / `AGENTS.md`） | チーム全員（コミットされる） | リポジトリを編集 |

- **リポジトリにはコミットされません。** 同僚には影響しない、あなただけの設定です。
- **新しく起動するセッションから**効きます。実行中のセッションは、起動時に読んだ内容のままです。
  例外は lcpp です。書き込むファイルが無く、行には「毎ターン システムプロンプトへ追加」と出て、
  実行中の lcpp セッションにも次のターンから反映されます。
- どの種別に配れるかは、[エージェントリファレンス](../ref/agents.ja.md)の「エージェントへの指示が届く」の行にあります
  （opencode には専用のブロック経由で届きます。[OpenCode](#opencode)を参照）。対応していない種別も、
  設定画面には行として出て理由が書かれます。
- 行ごとに**どこへ届くか**（書かれたファイル。lcpp はシステムプロンプト）と**いま効いているか**が出ます。「保存できたが効いていない」
  ときは理由がその行に出ます。
- 長さの上限があります。ここに書いた内容は**毎セッションのコンテキストに毎回乗る**ので、
  短いほどよく効きます。
- **秘密（API キーやトークン）は書かないでください。** 複数のエージェントが読む平文です。
- エージェントメモリがオンの間は、同じ指示ファイルのあなたの文章の隣に、メモリのツールについての短い固定の注意書きも
  Agent Fleet が書きます（copilot と Kiro には専用のファイル、lcpp にはシステムプロンプトで渡します）。記憶そのものは入らず、
  エージェントメモリをオフにすると、あなたの文章には触れずにその部分だけ消えます（[18 エージェントメモリ](18-agent-memory.ja.md#設定)）。

## 自分の Claude Code 設定を持ち込む

一部は設定画面で足りています。**⚙設定 →「エージェントへの指示」** はグローバルな `CLAUDE.md` に当たり（前節）、
**⚙設定 →「MCP サーバー（セッションで使う）」** は MCP を扱います。個人の**スキル**は **⚙設定 →「スキル」** で見られます（読み取り専用。Claude だけでなく Codex・OpenCode・Muse の分も、置き場所・どれが優先されるか・中身まで）。個人の**フック・サブエージェント**には設定画面がありません。
ワークスペースでは、Claude Code の設定フォルダ `/var/lib/af/claude` に置く普通のファイルです
（お使いの配備でのパスは、シェルで `echo $CLAUDE_CONFIG_DIR` を実行すると確認できます）。
手元のマシンの `~/.claude` に当たるものです。

| 何を | どこへ | チームと共有されるか |
|------|--------|----------------------|
| チームで共有したいフック・スキル・サブエージェント | リポジトリの `.claude/`（コミットする） | 共有される |
| 自分のスキル | `<設定フォルダ>/skills/<名前>/SKILL.md` | 共有されない |
| 自分のサブエージェント | `<設定フォルダ>/agents/<名前>.md` | 共有されない |
| 自分のフック | `<設定フォルダ>/settings.json` の `hooks` キー | 共有されない |

- **動きますが、手で扱う Claude Code の機能です。** Agent Fleet はこれらのファイルを検査しません（スキルを一覧で見る画面だけがあります）。
  Claude Code 2.1.293 で、使い捨ての設定フォルダに置いて確かめました。`SessionStart` フックは実行され、
  スキルとサブエージェントはセッションの一覧に出ました。`skills/` のスキルは、セッション画面のスキル選択にも出ます。
  頼りにする前に、実際のセッションで自分の分を試してください。Claude はこれらを**セッションの起動時**に
  読むので、変更は以降に起動するセッションから効きます。
- **残ります。** このフォルダは専用のストレージにあり、停止・開始も、**ワークスペースの作り直し**
  （消えるのは `~/repos` だけ）も、ホームの掃除も影響しません。
- **編集はシェルかターミナル（CLI）のセッションから行います。** Console のファイルブラウザはこのフォルダを
  見せません（ログイン情報も入っているためです）。`.credentials.json` と `.claude.json` はどこにもコピーしないでください。
  **`settings.json`・自分のフックのコマンド・コミットする `.claude/` に秘密を入れないでください。**
  `env` やコマンドラインに API キーやトークンを書かないことです。サインインや認証情報は
  **⚙設定 → 接続** に置きます。
- **`settings.json` の中の Fleet 自身のフックは編集しないでください。** Agent は Console に状態を伝えるフック
  （実行中・回答待ち、保留中の質問やプラン、権限の確認、通知の転送）を足します。コマンドが `session-status` または
  `session-push-notification` を実行するエントリがそれです。ほかに、`/model` が claude の「Switch model?」
  （プロンプトキャッシュの警告）で止まらないよう "allow" を返す `PreModelSwitch` のエントリもあります
  （切り替え後の次のメッセージでは、履歴全体がキャッシュの効かない料金で読み直されます）。RTK のエントリ（`rtk hook claude`）は編集ではなく
  **⚙設定 →「エージェント」→ Claude → RTK** で切り替えます。Fleet のエントリが無いと、そのセッションの状態が
  Console に出なくなります。Agent は起動時に足し直します。
- **自分のフックと、ほかのキーは残ります。** Agent は自分のエントリをコマンドで見分けるので、同じツールの
  マッチャー（たとえば `Bash`）に置いた自分のフックは、RTK を入り切りしても残ります。既知の限界として、
  コマンドに `session-status` という語そのものを含む自分のフックは Fleet のものと取り違えられます。
  自分のフックのコマンドにこの語を使わないでください。
- **フックは手元ではなくワークスペース向けに書きます。** 頼ってよいのはイメージにあるもの（bash・jq・node・python）と、
  `~/.local` に自分で入れたものだけです。自分のマシンのパスはここにありませんし、`/usr`・`/opt`・`/tmp` などはイメージの状態に戻るので、スクリプトはホームに置いてください。
- **`claude -p` を起動するフックには `env -u AF_SESSION_NAME` が要ります。** 子の claude はセッションの識別を引き継ぎ、
  Fleet の状態フックが入った同じ `settings.json` も読みます。すると子の動きが親セッションのものとして報告され、
  状態が乱れることがあります。`env -u AF_SESSION_NAME claude -p …` の形で起動してください。この前半は Agent のコードを
  読んで得た内容です。自分のフックを一度動かして、セッションの状態が正しいままか確かめてください。

エージェントに `~/.claude` などのエージェント内部の状態を読まない・触らないよう求めるワークスペース方針は、
エージェント自身に向けたものです。あなたが上の操作をすることを禁じてはいません。エージェントがこれらのファイルを扱うのは、
あなたが頼んだときだけで、頼めるのは個人のスキル・サブエージェント・フックだけです。認証情報と Fleet 自身の
フックのエントリは、エージェントも触れません。
