# 20. 設定 — ⚙設定モーダルの全タブ

[English](20-settings.md) | 日本語

個々の設定の**使いどころ**は各章に書いてあるので、この章は**地図**として使ってください。
深い説明がある項目はその章へのリンクを置いています。

## 開き方と構成

画面最上部のバーのアカウントメニューにある **⚙設定** で開きます。左レールが 4 つのグループに分かれています。

| グループ | 何が入るか |
|---|---|
| **個人設定** | 表示 / アカウント / キー操作 / 読み上げ / 通知 / 利用枠ボード / アシスタント / AI 補助 / エージェントへの指示 / エージェントメモリ / メモリのスナップショット |
| **接続** | エージェント / Git ホスティング / 運用・監視 / 課題管理 / チャット連携 / MCP サーバー（セッションで使う） / AWS プロファイル/SSM / Google Cloud |
| **外部からのアクセス** | MCP トークン・接続アプリ（外部からこのワークスペースを操作するためのトークンと接続アプリ） |
| **ワークスペース** | エージェント使用量 / クラウド費用 / 稼働時間 / マシン / ツールチェーン / データベース / プレビュー用サブドメイン / 内部リポジトリ / 書き出し / 取り込み / 危険な操作 |

- 最後に開いたタブを覚えているので、次に開くとそこから始まります。
- **スマホでは一覧 → 詳細のドリルダウン**です。戻る操作で一覧に戻り、もう一度で閉じます。
- チームの**メンバー・上限・監査**の管理は、権限のある人にだけ出る**別のモーダル**、同じメニューの
  **テナント設定**です（[admin/](../admin/README.ja.md)）。**管理**（盾のアイコン）は配備全体のものです。
- 一部のタブは**ワークスペースの起動が必要**です（設定の実体がワークスペース内にあるため）。
  停止中はその旨と「ワークスペースを起動」ボタンが出ます。

### いつ反映されるか

これを取り違えると「設定したのに変わらない」になります。

| タイミング | 対象 |
|---|---|
| **即時** | 表示・キー操作・読み上げ・通知、接続の追加と削除、停止中セッションのアーカイブ期間（次の一覧更新から） |
| **次に起動するセッションから** | エージェントの動作設定、エージェントへの指示、セッション間メッセージ、セッションからのセッション起動、過去セッションの検索（オフにすると起動中のセッションの検索もその場で断る）、Agent Fleet のメモリ（同じく）、画像生成、MCP サーバー |
| **次のチャット送信から** | アシスタントの設定、運用・監視の接続（アシスタントで使う場合） |
| **ワークスペースの停止 → 起動** | ツールチェーン（タイムゾーン・言語のバージョン）、マシン（管理者が変えたサイズ・種類） |

**保存先も 2 種類**あります。テーマ・背景色・メイン領域の配置は**このブラウザだけ**に保存され、
それ以外（フォント・文字サイズなど）はサーバーに保存されて別の PC やブラウザでも追従します。
サーバーへの保存に失敗すると、設定画面の上部に「設定をサーバーに保存できていません」と出ます。
その間、エージェントは前の設定のまま動くので、「再送」を押してください。

## 個人設定

### 表示

見た目まわりをまとめて扱います。

- **言語**・**地域の形式**・**タイムゾーン**：地域の形式（日付と数値の書き方）は既定で表示言語に、
  タイムゾーンは既定でブラウザに従います。「ブラウザに合わせる」は今日のゾーンのコピーではなく独立した
  設定値なので、移動すると一緒に変わります。ゾーンを選ぶと固定できます。セッションミラーを含む Console の日時と、
  Agent が書き出すファイル（Markdown エクスポート）の時刻に使われ、変更はワークスペースを
  再起動しなくてもすぐ反映されます。
  「ブラウザに合わせる」のときは、Console を開いたときや戻ってきたときに、このブラウザのゾーンをワークスペースにも
  伝えます。そのため Agent 自身が書く文面（利用上限の再開通知・再オープンしたレポートの注記・Markdown エクスポート）も、
  ワークスペースの時計ではなくそのゾーンで表示されます。複数の端末を使う場合は最後に使った端末のゾーンが採用され、
  ゾーンを固定していれば常に固定が優先されます。Control Plane が書く文面は
  スケジュール自身のゾーンのままです。ただし、タイムゾーンか地域の形式を選んでいれば、スケジュール一覧の
  「次回実行」は自分のゾーンで表示され、詳細ではゾーンが違うときにスケジュール側の時刻も添えます。
- **カラーテーマ**：アプリ全体に加えて、**セッション** / **共有セッション** / **アシスタント**の面ごとに
  色を変えられます（「継承」でアプリのテーマに従います）。面ごとに色を変えておくと、ペインを並べたときに
  どれがどれか一目で分かります。
- **ターミナル**：フォントと文字サイズ、**Ctrl+C / Ctrl+V でコピー・貼り付け**（既定はオン。Ctrl+C がコピーになるときと
  プログラムの中断になるときは [ターミナルを使う](../user/files/terminal.ja.md#コピーと貼り付け) にあります）。
- **ファイルビューア**：タブ幅・行番号・折り返し・ミニマップ、Markdown 表示（[ドキュメントや図を表示する](../user/files/view.ja.md)）。
- **朗読ビュー** / **ファイルアイコン**（アイコンセット）。
- **テナントごとに外観を分ける**（2 つ以上のテナントに所属しているときだけ出ます。既定はオフ）：テーマと背景色を
  この端末でテナントごとに覚え、テナントの切り替えに合わせて切り替えます。オフにすると、今見えている外観がすべての
  テナントで使われます（保存済みの外観は残ります）。
- **メイン領域の配置**：**分割ペイン**（境界をドラッグして並べる）と**タブ付きグリッド**
  （各マスをタブで切り替える）を選べます。**このブラウザだけ**に保存され、2 つの配置はそれぞれ別に
  覚えているので行き来しても崩れません（[02](02-console-basics.ja.md)）。よく切り替えるなら、
  画面最上部のバーの**外観**（ペンキ缶）からも同じ切り替えができます。

### アカウント

いまのアカウントに紐づいた**サインイン方法**（Google / Microsoft / GitHub …）の一覧です。
どの方法で入っても、同じワークスペース・同じホーム・同じ設定になります。

- **サインイン方法を追加**：会社が複数のサインイン方法を用意している場合（例: 本社は Microsoft、
  出向先の子会社は GitHub）、2 つ目を自分のアカウントに足せます。押すとその方式のサインインへ飛び、
  戻ってくると一覧に増えます。
- 追加できるのは、**いまのアカウントと同じメールアドレスを名乗る方法**だけです。別のアドレスの
  アカウント同士を 1 つにまとめることはできません（後から戻せないため）。
- その方式の入場条件（GitHub なら**組織のメンバーであること**、許可されたメールドメイン）も
  満たしている必要があります。紐づけは条件の抜け道ではありません。
- すでに**別の人のアカウント**で使われている方式は追加できません。
- サインイン画面で「このメールアドレスは、すでに別のサインイン方法で使われています」と出た人は、
  **いつも使っている方法でサインインしてから**ここで足すのが正しい直し方です。
- **解除**：使わなくなった方法は一覧から外せます。ワークスペース・ホーム・秘密情報はそのままで、
  あとから同じ方法をもう一度追加できます。外せないのは次の 2 つで、ボタンが押せない理由は
  ボタンにマウスを乗せると読めます。
  - **いまサインインしている方法**：先に別の方法でサインインし直してから解除してください。
  - **残り 1 つの方法**：解除するとどの方法でも入れなくなり、自分では戻せません
    （パスワードもメール送信も無い仕組みのため）。

### キー操作

- **ショートカットの割り当て**：直接キー（`Alt+1` など）とアプリ全体の 3 キーを変更できます。
  リーダー配下のシーケンス（例: リーダー → `p` → `r`）は構造上の操作なので変更できません。
  **?** でいつでも一覧を開けます。
- **端末入力の優先**：オンにすると、端末にフォーカスがある間は Ctrl 系のキーをすべて端末へ渡します。
  アプリ側はリーダーだけが有効で、そこからコマンドメニュー／パレットに到達できます。
- **shell / SSM 端末へキーをすべて渡す**：上よりさらに強く、リーダー（Ctrl/⌘+K）とパレット（Ctrl/⌘+P）も
  渡して純粋な端末にします。対象は shell / SSM だけで、エージェントの端末は従来どおりです。既定オフ。
- **送信キー**：**Ctrl+Enter 送信（Enter で改行・既定）** と **Enter 送信（Shift+Enter で改行）** から
  選びます。セッションのチャットとアシスタントのチャットに共通で効きます。
- **返信サジェスト**：コンポーザーの上に短い返信の候補チップを出します（[セッションに返事をする](../user/sessions/reply.ja.md#返信サジェストを使う)）。
  ここで学習済みの候補の消去・ピン留めの解除ができます。消去は 2 種類で、**1回だけの候補を消去**は
  1 回しか送っていない使い捨ての言い回しだけを落とし（ピン留めは残ります・また送れば学習し直します）、
  **学習をすべて消去**は学習と「消した候補」をまとめて初期状態へ戻します。

### 読み上げ

セッションやアシスタントの回答を音声で読み上げます。

- **声**：音声エンジン（ずんだもん（VOICEVOX）/ Polly / 自動）、話者、**セッションごとに声を変える**
  （キャラクターのプールから割り当て）、感情の読み分け、読み上げ速度。
- **自動読み上げ**：新しい回答を自動で読む、**作業過程を小声で読む**、開いている全ペインで読む、
  長い回答は要約して読む、確認・質問を読み上げる。
- **読み方**：コード片を省略、助詞のあとで一呼吸、英語をカタカナ読み、**読み仮名辞書**
  （`表記=読み` を 1 行に 1 件）。
- **詳細**：バックグラウンドでの再生と音量、ペイン位置に合わせた左右振り、音声キャッシュ。
- **音声通知**：セッションの状態変化と、利用上限のリセットを声で知らせます。どれを読み上げるかは
  通知タブで選びます。
- **読み上げ言語**：自動（表示言語に従う）/ 日本語 / English。エンジンが「自動」のとき、
  English なら Polly の英語話者に切り替わります。アシスタントの**回答言語**とは別の設定です。
- 「設定を初期状態にリセット」で読み上げ設定だけを戻せます（読み仮名辞書は残ります）。

### 通知

- **デスクトップ通知を許可**：ブラウザにまだ尋ねていない間だけ出て、通知の許可を求めます。
  ブラウザがこのサイトの通知をブロックしているときはその旨を表示します（戻せるのはサイトの設定だけです）。
- **セッションの音声通知**のオン・オフ：下の表の「読み上げ」列の親スイッチです（通知センターの
  スピーカーボタンと同じ設定）。
- **通知の表**：通知の種類ごとに 1 行、動作ごとに 1 つのスイッチがあります。

  | 行 | 対象 |
  |---|---|
  | ターン完了 | セッションがターンを終えて入力待ちになった |
  | ターン完了（子セッション） | 同上。別のセッションが `create_session` で起動したセッション |
  | 回答が必要 | 確認・計画の承認・許可の要求 |
  | 利用上限のリセット | 当たっていた Claude／Codex の 5 時間利用枠・週次利用枠がリセットされた |
  | セッションからの報告 | セッションがアシスタントの会話に報告した |
  | プルリクエスト | セッションのブランチのプルリクエストがマージできる状態になった（オープン・チェック成功・コンフリクトなし・承認済みかレビュー不要。Bitbucket では誰かが承認したもの。push したコミットごとに 1 回）、またはマージ・クローズされた。[PR へのフィードバック](11-many-sessions.ja.md#pr-へのフィードバックをセッションに伝える)をオンにしていれば、セッションの PR にコンフリクトが起きたときや、セッションに伝えられなかった（アーカイブ済み）CI・レビューのフィードバックも |
  | レート制限 | セッションがレート制限に達した、または制限後に再開した |
  | スケジュール実行 | スケジュール実行の完了・失敗・見送り |
  | 引き継ぎ | 引き継ぎの受信・受け入れ・期限切れ、返した引き継ぎからの起動 |
  | クラウドへのログイン | AWS・Google Cloud へのログインが必要、または SSO の期限が近い |
  | ターミナルの通知 | セッション内のプログラムが OSC 9／99／777 を送った |
  | その他のお知らせ | アシスタントの会話の一時停止・コンテキスト逼迫、サブモジュールの同期、ターン後の停止、起動の打ち切り、メモリの提案、（管理者向けに）メンバーのホームの空き不足・メンバーのワークスペースの無応答・メンバーのツールのインストール失敗、今後増える種類 |

  - **未読ドット**：オフにすると届いた時点で既読にします（セッションの赤いドットも未読数も付かず、
    通知センターには既読の行として残ります）。この列はほかのブラウザにも反映されます（既読の印がもともと
    共通のため）。「回答が必要」「引き継ぎ」「クラウドへのログイン」は人の対応を待つ通知なので
    オフにできません。
  - **OS の通知**と**読み上げ**：このブラウザだけの設定です（スマホと机の PC で変えられます）。読み上げは
    「セッションの音声通知」がオンのときに鳴ります。利用上限のリセットだけは、読み上げタブの
    「音声読み上げ」がオンなら鳴ります。
  - 既定はすべてオンで、表ができる前の通知と同じ動きです。表に置き換わった 2 つのスイッチは設定を
    そのまま引き継ぎます。「子セッションの入力待ちを通知」は子セッションの行（3 つとも）に、
    「制限リセットの通知」は利用上限のリセットの行になりました。
  - 作業中のペインに出ているセッションの通知は、表の設定にかかわらず表示も読み上げもしません。
- **サービス通知**：Discord / Slack へ**接続を切らずに送信だけ**を止められます。
  接続そのものと、サービスごとに送るイベントの選択は「チャット連携」タブです（[Discord・Slack とつなぐ](../user/integrations/chat-bridge.ja.md#届く通知を決める)）。
- 通知の履歴は、画面最上部のベルから開く**通知センター**（過去 7 日間）で読めます。未読の赤いドットの意味と
  消え方は [アイコン・バッジ・メニュー](badges-and-menus.ja.md#セッションの表示) にあります。

### 利用枠ボード

利用上限に対する自分の状況を、このテナントの誰に・どこまで見せるかを選びます。選ぶまでは非公開で、設定は
テナントごとです。このタブには公開しているテナントがすべて表示され、その下に、メンバーが自分に公開している
状況が並びます。選べる内容と値の読み方は [12](12-collaboration.ja.md#利用上限に対する自分の状況をメンバーに見せる) にあります。

### アシスタント

アシスタントチャットとフリート・オペレーターの挙動です（[10](10-chat-memo.ja.md)・
[11](11-many-sessions.ja.md)）。

- **回答言語**：入力に合わせる / 日本語 / English。変わるのはチャットの回答だけです
  （読み上げの言語は**読み上げ**タブ）。
- **エージェント優先順位**：新しい会話は、上から見て最初に接続済みの CLI で作られます。
  会話はその CLI のまま続きます。その CLI が使えないとき（未接続、または利用制限中）は、
  その回だけこの順で最初に使える CLI が代わりに応答し、会話にその旨のお知らせが残ります。
  代わりは元の CLI より上の CLI になることもあります。制限が解ければ次のターンから元に戻ります。
  タイトルや返信候補などの補助生成は別の順位で動きます（**AI 補助**タブ）。
- **アシスタントのモデル**：CLI ごとに指定します。
  「推奨（現在: …）」は接続中のカタログから安全な既定を選び、いま何に解決されているかも表示します。
  価格とコンテキスト長は [09](../user/agents/usage.ja.md#モデルの定価を見る) にあります。
- **セッション報告への自動応答**：報告が届いたときオペレーターが自動で 1 ターン動きます。
  付随するのは**自動応答の上限回数**（既定 10・最大 50・無制限にはできません）、**自動応答のモデル**（報告の確認は
  定型作業なので軽量モデルにすると節約になります）、**自動応答の束ね時間**（この時間内の報告をまとめて 1 回で処理）、
  **静かな完了報告**（正常完了では自動応答せずカードと通知だけにする）です。
  [11](11-many-sessions.ja.md#セッション報告と自動応答) も参照。
- **自動走行**：質問とプラン承認まで自動で進めます。既定オフ（同じ節）。
- **中断時の自動再開**：接続断や一時的なレート制限で切れたターンを再開させます。既定オン。
- **コンテキストの自動圧縮**と**自動圧縮の閾値（トークン）**：長くなった会話を自動で要約引き継ぎします
  （[10](10-chat-memo.ja.md#会話が長くなってきたらコンテキストの目安)）。
- **セッション出力の取得上限**：オペレーターがセッションの出力を読むときの上限（既定 32 KiB）。
  大きいほど会話に蓄積されてトークン消費が増えます。全文はいつでもチャット表示で読めます。
- **外観**：アシスタント面のテーマと背景色（このブラウザだけに保存）。

### AI 補助

セッション・ミラー・File ペインで動く、**1 回きりの AI 生成**の設定です。アシスタントとの
会話ではありません（実装は共有していますが、出てくる場所が違います）。

- **エージェント優先順位**：補助生成に使う CLI の順位。アシスタントとは別に並べられます。
  チャットは強いモデルを選びたいのに対し、補助生成は常時動くので安くて速いものを選びたいためです。
  未接続の CLI と利用制限中の CLI は飛ばし、生成中に制限に当たったら次の CLI で 1 回だけやり直します。
- **短文生成のモデル** / **文章生成のモデル**：短文はタイトル・ブランチ名・返信候補、
  文章はファイル編集の提案・計画の更新に使います。用途が違うので既定も別です。
  短文の「推奨」は、その CLI が一覧に出しているモデルのうち **models.dev の公表単価がいちばん安いもの**
  （codex・agy。安いモデルが新しく出ると自動で切り替わります）、文章の「推奨」はその 1 つ上の
  決まったティアです。単価が取れないときは従来の既定に戻ります。いま何に解決されているかは
  「推奨（現在: …）」に出ます。muse はどちらも、`-contributor` でも非表示でもない最新のモデルです。
  該当が無いとき（モデル一覧が読めないときも）は、contributor の既定で動かさず、補助生成を行いません。
  Muse Code の contributor モード（設定 › エージェント › Muse Code）は、これらのターンにも適用されます。
- **AI 補助生成を使う機能**：8 機能それぞれに 1 枚のカードがあります。オフにするとボタン自体が
  出なくなり、カードのエージェント／モデルの行も畳まれます。
  - **セッションのタイトル提案**：自動で出る提案バナーと、セッションの「表示名を変更」の
    「AI に提案してもらう」。
  - **チャットのタイトル提案**：アシスタントの「タイトルを変更」の「AI に提案してもらう」。
    チャットには自動提案のバナーはありません。
  - **ブランチ名の提案**：worktree の作成やブランチ名の変更で使います。
  - **返信候補（セッション）** / **返信候補（チャット）**：ミラーとチャットのコンポーザーに
    それぞれ独立に出る ✨ ボタン。押したときだけ消費します。片方をオフにしても、もう片方には
    影響しません。入力履歴から学習する**返信サジェスト**（キー操作タブ）は AI を使わない別機能です。
  - **ファイル編集の提案**：File ペインで選択範囲と指示から置換文を作らせます。
  - **作業計画の更新**：アシスタント・チャットの計画を、直近のやり取りから作り直す「更新」ボタン。
  - **回答の翻訳（ミラー）**：ミラーで、表示言語と違う言語で返ってきた回答に出る「翻訳」ボタン
    （[回答を自分の言語で読む](../user/sessions/translate.ja.md)）。訳はエージェント／モデルごとに残るので、
    この機能のエージェントやモデルを変えると次の押下は作り直しになります（前の訳は戻せば残っています）。
  - **自動翻訳**：上の「翻訳」ボタンを、ターンが完了した時点で自動的に押します（既定はオフ）。
    対象は**そのセッションを開いて見ている間に届いた回答**だけです。翻訳の設定のうち、これだけは
    押さなくても消費します。

  各カードは、上の優先順位・モデルとは別に**このカード 1 枚だけ**のエージェントを選べます
  （既定は「自動（優先順位）」）。エージェントを 1 つに決めると、そのエージェントのモデルも
  個別に選べます。「自動」のままではモデルは既定に従うだけで、具体的な 1 個は選べません。
  カードの「いま使うのは」は、実際に今その機能が使うエージェントです（未取得のうちは表示しません）。

## 接続

### エージェント

エージェントごとのカードで、接続と動作設定を行います。[エージェントを選ぶ](../user/agents/choose.ja.md) と、各エージェントのページにあります。

**セッション**グループには、**停止中セッションのアーカイブ**（既定＝配備の期間で、配備で変えていなければ 7 日／1・3・7・14・30 日／しない）、**セッション間メッセージ**、**セッションからのセッション起動**（と
**子セッションの同時本数**）、**過去セッションの検索**（既定オン。セッションが
`search_sessions` ツールでこのワークスペースの過去の会話を検索できます。コマンドパレットの「会話」はこの設定に
関係なく使えます。[02](02-console-basics.ja.md#コマンドパレット) を参照）、**画像生成**と**画像生成の優先順位**（配備のエンジンがそれぞれの名前で先、CLI の経路が後）があります。→
[11 たくさんのセッションを動かす](11-many-sessions.ja.md#セッション同士でメッセージを送る)・
[11 たくさんのセッションを動かす](11-many-sessions.ja.md#セッションから別のセッションを起こす子セッション)・
[セッションに画像を作らせる](../user/images/from-session.ja.md)

### Git ホスティング

GitHub・Bitbucket の接続、コミットの作者、保存した Subversion の認証情報です。GitHub の接続は GitHub Copilot の接続も兼ねます。
[Git のサービスを接続する](../user/code/connect-git.ja.md) にあります。

### 運用・監視

PagerDuty・Grafana・CloudWatch・AWS を **SRE アシスタント**につなぐ設定です。接続のしかたと、アシスタントがそれで何をするかは
[監視ツールとつなぐ](../user/integrations/ops-monitoring.ja.md) にあります。

### 課題管理

左ペインの**課題管理**に課題やプルリクエストを出すための、Jira の接続です。接続と保存クエリは
[課題管理サービスを接続する](../user/integrations/issue-tracker.ja.md) にあります。

### チャット連携

Discord・Slack の Bot の接続と、届く通知の設定です。接続の手順と、返信で答える方法は
[Discord・Slack とつなぐ](../user/integrations/chat-bridge.ja.md) にあります。

### MCP サーバー（セッションで使う）

セッションとアシスタントが使う MCP サーバーの登録、3 つの出自、接続テスト、OAuth のサインインは
[セッションに MCP サーバーを追加する](../user/integrations/mcp-servers.ja.md) にあります。外部のアプリからこのワークスペースを
操作させるには、**外部からのアクセス**の [MCP トークン・接続アプリ](#mcp-トークン接続アプリ) を開いてください。

### AWS プロファイル/SSM

`af-aws-exec` と SSM セッションがログインに使う AWS プロファイル（共通設定）と、社内の別ホストへ SSM でログインするための
SSM ホスト（個別）の登録です。プロファイルは **IAM Identity Center（SSO）** か **別のプロファイルからロールを引き受ける** かの 2 種類で、SSO の行には
**ログイン**と、ログイン中なら**ログアウト**があり、ロールを引き受ける行の**ログアウト**は元のプロファイルのログインを終わらせます（確認の画面で元を示します）。ログイン・ログアウトの動きと 2 つの種類は
[AWS SSO を使う](../user/integrations/aws-sso.ja.md) に、SSM ホストは [SSM で EC2 にログインする](../user/integrations/aws-ssm.ja.md) にあります。

### Google Cloud

`af-gcloud-exec` がコマンドを実行するときに使う Google Cloud のプロファイルです。登録・取り込み・ログインと、WS バーの
Google Cloud バッジは [Google Cloud を使う](../user/integrations/gcloud.ja.md) にあります。

ワークスペースが動いているマシンの大きさと、メモリ・ディスクの使用状況、ディスクの空けかたです。

タイムゾーンと Node.js / Java / Go のバージョン、ツールのバージョン、エージェント CLI の更新です。

[データベースを使うテストを動かす](../user/workspace/databases.ja.md#console-から管理する) にあります。

[プレビュー用のサブドメインを使う](../user/preview/subdomains.ja.md) に、開発用 OIDC IdP の欄（issuer、client id、アプリの設定例、テスト用ペルソナ）は

### 内部リポジトリ

### 書き出し / 取り込み

自分の設定をファイル 1 つにまとめて持ち出し、別の環境で読み戻します。
[設定を書き出す・取り込む](../user/workspace/export-import.ja.md) にあります。

### 危険な操作

ワークスペースの作り直しとホームの掃除です（実行できる配備だけ）。何が残り何が消えるかは
[ワークスペースを作り直す](../user/workspace/recreate.ja.md) にあります。
