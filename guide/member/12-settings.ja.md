# 12. 設定 — ⚙設定モーダルの全タブ

[English](12-settings.md) | 日本語

個々の設定の**使いどころ**は各章に書いてあるので、この章は**地図**として使ってください。
深い説明がある項目はその章へのリンクを置いています。

## 開き方と構成

画面最上部のバーの **⚙設定** で開きます。左レールが 3 つのグループに分かれています。

| グループ | 何が入るか |
|---|---|
| **個人設定** | 表示 / アカウント / キー操作 / 読み上げ / 通知 / アシスタント / AI 補助 / エージェントへの指示 / エージェントメモリ / メモリのスナップショット |
| **接続** | エージェント / Git ホスティング / 運用・監視 / 課題管理 / チャット連携 / MCP サーバー / MCP トークン / AWS プロファイル/SSM / Google Cloud |
| **ワークスペース** | エージェント使用量 / クラウド費用 / 稼働時間 / マシン / ツールチェーン / データベース / プレビュー用サブドメイン / 内部リポジトリ / 書き出し・取り込み / 危険な操作 |

- 最後に開いたタブを覚えているので、次に開くとそこから始まります。
- **スマホでは一覧 → 詳細のドリルダウン**です。戻る操作で一覧に戻り、もう一度で閉じます。
- チームの**メンバー・上限・監査**の管理は、権限のある人にだけ出る**別のモーダル**（盾のアイコン）です
  （[admin/](../admin/README.ja.md)）。
- 一部のタブは**ワークスペースの起動が必要**です（設定の実体がワークスペース内にあるため）。
  停止中はその旨と「ワークスペースを起動」ボタンが出ます。

### いつ反映されるか

これを取り違えると「設定したのに変わらない」になります。

| タイミング | 対象 |
|---|---|
| **即時** | 表示・キー操作・読み上げ・通知、接続の追加と削除、停止中セッションのアーカイブ期間（次の一覧更新から） |
| **次に起動するセッションから** | エージェントの動作設定、エージェントへの指示、セッション間メッセージ、セッションからのセッション起動、フリート観測、過去セッションの検索（オフにすると起動中のセッションの検索もその場で断る）、Agent Fleet のメモリ（同じく）、画像生成、MCP サーバー |
| **次のチャット送信から** | アシスタントの設定、運用・監視の接続（アシスタントで使う場合） |
| **ワークスペースの停止 → 起動** | ツールチェーン（タイムゾーン・言語のバージョン）、マシン（管理者が変えたサイズ・種類） |

**保存先も 2 種類**あります。テーマ・背景色・メイン領域の配置は**このブラウザだけ**に保存され、
それ以外（フォント・文字サイズなど）はサーバーに保存されて別の PC やブラウザでも追従します。
サーバーへの保存に失敗すると、設定画面の上部に「設定をサーバーに保存できていません」と出ます。
その間、エージェントは前の設定のまま動くので、「再送」を押してください。

## 個人設定

### 表示

見た目まわりをまとめて扱います。

- **カラーテーマ**：アプリ全体に加えて、**セッション** / **共有セッション** / **アシスタント**の面ごとに
  色を変えられます（「継承」でアプリのテーマに従います）。面ごとに色を変えておくと、ペインを並べたときに
  どれがどれか一目で分かります。
- **ターミナル**：フォントと文字サイズ（[05](05-terminal.ja.md)）。
- **ファイルビューア**：タブ幅・行番号・折り返し・ミニマップ、Markdown 表示（[04](04-files.ja.md)）。
- **朗読ビュー** / **ファイルアイコン**（アイコンセット）。
- **メイン領域の配置**：**分割ペイン**（境界をドラッグして並べる）と**タブ付きグリッド**
  （各マスをタブで切り替える）を選べます。**このブラウザだけ**に保存され、2 つの配置はそれぞれ別に
  覚えているので行き来しても崩れません（[05](05-terminal.ja.md)）。よく切り替えるなら、
  画面最上部のバーの**外観**（ペンキ缶）からも同じ切り替えができます。

### アカウント

いまのアカウントに紐づいた**サインイン方法**（Google / Microsoft / GitHub …）の一覧です。
どの方法で入っても、同じワークスペース・同じホーム・同じ設定になります。

- **サインイン方法を追加**：会社が複数のサインイン方法を用意している場合（例: 本社は Microsoft、
  出向先の子会社は GitHub）、2 つ目を自分のアカウントに足せます。押すとその方式のサインインへ飛び、
  戻ってくると一覧に増えます。
- 追加できるのは、**いまのアカウントと同じメールアドレスを名乗る方法**だけです。別のアドレスの
  アカウント同士を 1 つにまとめることはできません（後から戻せないため）。
- その方式の入場条件（GitHub なら**組織のメンバーであること**、許可されたメールドメイン）も
  満たしている必要があります。紐づけは条件の抜け道ではありません。
- すでに**別の人のアカウント**で使われている方式は追加できません。
- サインイン画面で「このメールアドレスは、すでに別のサインイン方法で使われています」と出た人は、
  **いつも使っている方法でサインインしてから**ここで足すのが正しい直し方です。
- **解除**：使わなくなった方法は一覧から外せます。ワークスペース・ホーム・秘密情報はそのままで、
  あとから同じ方法をもう一度追加できます。外せないのは次の 2 つで、ボタンが押せない理由は
  ボタンにマウスを乗せると読めます。
  - **いまサインインしている方法**：先に別の方法でサインインし直してから解除してください。
  - **残り 1 つの方法**：解除するとどの方法でも入れなくなり、自分では戻せません
    （パスワードもメール送信も無い仕組みのため）。

### キー操作

- **ショートカットの割り当て**：直接キー（`Alt+1` など）とアプリ全体の 3 キーを変更できます。
  リーダー配下のシーケンス（例: リーダー → `p` → `r`）は構造上の操作なので変更できません。
  **?** でいつでも一覧を開けます。
- **端末入力の優先**：オンにすると、端末にフォーカスがある間は Ctrl 系のキーをすべて端末へ渡します。
  アプリ側はリーダーだけが有効で、そこからコマンドメニュー／パレットに到達できます。
- **shell / SSM 端末へキーをすべて渡す**：上よりさらに強く、リーダー（Ctrl/⌘+K）とパレット（Ctrl/⌘+P）も
  渡して純粋な端末にします。対象は shell / SSM だけで、エージェントの端末は従来どおりです。既定オフ。
- **送信キー**：**Ctrl+Enter 送信（Enter で改行・既定）** と **Enter 送信（Shift+Enter で改行）** から
  選びます。セッションのチャットとアシスタントのチャットに共通で効きます。
- **返信サジェスト**：コンポーザーの上に短い返信の候補チップを出します（[07](07-chat-memo.ja.md)）。
  ここで学習済みの候補の消去・ピン留めの解除ができます。消去は 2 種類で、**1回だけの候補を消去**は
  1 回しか送っていない使い捨ての言い回しだけを落とし（ピン留めは残ります・また送れば学習し直します）、
  **学習をすべて消去**は学習と「消した候補」をまとめて初期状態へ戻します。

### 読み上げ

セッションやアシスタントの回答を音声で読み上げます。

- **声**：音声エンジン（ずんだもん（VOICEVOX）/ Polly / 自動）、話者、**セッションごとに声を変える**
  （キャラクターのプールから割り当て）、感情の読み分け、読み上げ速度。
- **自動読み上げ**：新しい回答を自動で読む、**作業過程を小声で読む**、開いている全ペインで読む、
  長い回答は要約して読む、確認・質問を読み上げる。
- **読み方**：コード片を省略、助詞のあとで一呼吸、英語をカタカナ読み、**読み仮名辞書**
  （`表記=読み` を 1 行に 1 件）。
- **詳細**：バックグラウンドでの再生と音量、ペイン位置に合わせた左右振り、音声キャッシュ。
- **音声通知**：セッションの状態変化と、利用上限のリセットを声で知らせます。どれを読み上げるかは
  通知タブで選びます。
- **読み上げ言語**：自動（表示言語に従う）/ 日本語 / English。エンジンが「自動」のとき、
  English なら Polly の英語話者に切り替わります。アシスタントの**回答言語**とは別の設定です。
- 「設定を初期状態にリセット」で読み上げ設定だけを戻せます（読み仮名辞書は残ります）。

### 通知

- **デスクトップ通知を許可**：ブラウザにまだ尋ねていない間だけ出て、通知の許可を求めます。
  ブラウザがこのサイトの通知をブロックしているときはその旨を表示します（戻せるのはサイトの設定だけです）。
- **セッションの音声通知**のオン・オフ：下の表の「読み上げ」列の親スイッチです（通知センターの
  スピーカーボタンと同じ設定）。
- **通知の表**：通知の種類ごとに 1 行、動作ごとに 1 つのスイッチがあります。

  | 行 | 対象 |
  |---|---|
  | ターン完了 | セッションがターンを終えて入力待ちになった |
  | ターン完了（子セッション） | 同上。別のセッションが `create_session` で起動したセッション |
  | 回答が必要 | 確認・計画の承認・許可の要求 |
  | 利用上限のリセット | 当たっていた Claude／Codex の 5 時間利用枠・週次利用枠がリセットされた |
  | セッションからの報告 | セッションがアシスタントの会話に報告した |
  | レート制限 | セッションがレート制限に達した、または制限後に再開した |
  | スケジュール実行 | スケジュール実行の完了・失敗・見送り |
  | 引き継ぎ | 引き継ぎの受信・受け入れ・期限切れ |
  | クラウドへのログイン | AWS・Google Cloud へのログインが必要、または SSO の期限が近い |
  | ターミナルの通知 | セッション内のプログラムが OSC 9／99／777 を送った |
  | その他のお知らせ | アシスタントの会話の一時停止・コンテキスト逼迫、サブモジュールの同期、ターン後の停止、起動の打ち切り、今後増える種類 |

  - **未読ドット**：オフにすると届いた時点で既読にします（セッションの赤いドットも未読数も付かず、
    通知センターには既読の行として残ります）。この列はほかのブラウザにも反映されます（既読の印がもともと
    共通のため）。「回答が必要」「引き継ぎ」「クラウドへのログイン」は人の対応を待つ通知なので
    オフにできません。
  - **OS の通知**と**読み上げ**：このブラウザだけの設定です（スマホと机の PC で変えられます）。読み上げは
    「セッションの音声通知」がオンのときに鳴ります。利用上限のリセットだけは、読み上げタブの
    「音声読み上げ」がオンなら鳴ります。
  - 既定はすべてオンで、表ができる前の通知と同じ動きです。表に置き換わった 2 つのスイッチは設定を
    そのまま引き継ぎます。「子セッションの入力待ちを通知」は子セッションの行（3 つとも）に、
    「制限リセットの通知」は利用上限のリセットの行になりました。
  - 作業中のペインに出ているセッションの通知は、表の設定にかかわらず表示も読み上げもしません。
- **サービス通知**：Discord / Slack へ**接続を切らずに送信だけ**を止められます。
  接続そのものと、サービスごとに送るイベントの選択は「チャット連携」タブです（[10](10-integrations.ja.md)）。
- 通知の履歴は、画面最上部のベルから開く**通知センター**（過去 7 日間）で読めます。まだ読んでいない
  通知はそのセッションに赤いドットを付け、「**すべて既読にする**」でまとめて消せます
  （[02](02-sessions.ja.md#状態を読む-バッジと通知)）。

### 利用枠ボード

利用上限に対する自分の状況を、このテナントの誰に・どこまで見せるかを選びます。相手は非公開（既定）／
テナント全員／選んだメンバー、範囲は状態のみ／帯／正確な値です。設定はテナントごとで、このタブには
公開しているテナントがすべて表示されます。その下に、メンバーが自分に公開している状況と、集めている
範囲の表が並びます。値の読み方は [09](09-collaboration.ja.md#利用上限に対する自分の状況をメンバーに見せる) にあります。

### アシスタント

アシスタントチャットとフリート・オペレーターの挙動です（[07](07-chat-memo.ja.md)・
[08](08-organising.ja.md)）。

- **回答言語**：入力に合わせる / 日本語 / English。変わるのはチャットの回答だけです
  （読み上げの言語は**読み上げ**タブ）。
- **エージェント優先順位**：上から見て最初に接続済みの CLI をアシスタントに使います。
  タイトルや返信候補などの補助生成は別の順位で動きます（**AI 補助**タブ）。
- **アシスタントのモデル**：CLI ごとに指定します。
  「推奨（現在: …）」は接続中のカタログから安全な既定を選び、いま何に解決されているかも表示します。
  選択欄の下には、選んだ（「推奨」なら解決先の）モデルの API 定価・コンテキスト長・公開日が出ます
  （[エージェント](06-agents.ja.md)）。
- **セッション報告への自動応答**：報告が届いたときオペレーターが自動で 1 ターン動きます。
  **自動応答の上限回数**（既定 10・最大 50・無制限にはできません）、**自動応答のモデル**（報告の確認は
  定型作業なので軽量モデルにすると節約になります）、**束ね時間**（この時間内の報告をまとめて 1 回で処理）、
  **静かな完了報告**（正常完了では自動応答せずカードと通知だけにする）。
- **自動走行**：質問とプラン承認まで自動で進めます。既定オフ（[08](08-organising.ja.md)）。
- **中断時の自動再開**：接続断や一時的なレート制限で切れたターンを再開させます。既定オン。
- **コンテキストの自動圧縮**と**自動圧縮の閾値**：長くなった会話を自動で要約引き継ぎします。
- **セッション出力の取得上限**：オペレーターがセッションの出力を読むときの上限（既定 32 KiB）。
  大きいほど会話に蓄積されてトークン消費が増えます。全文はいつでもチャット表示で読めます。
- **外観**：アシスタント面のテーマと背景色（このブラウザだけに保存）。

### AI 補助

セッション・ミラー・File ペインで動く、**1 回きりの AI 生成**の設定です。アシスタントとの
会話ではありません（実装は共有していますが、出てくる場所が違います）。

- **エージェント優先順位**：補助生成に使う CLI の順位。アシスタントとは別に並べられます。
  チャットは強いモデルを選びたいのに対し、補助生成は常時動くので安くて速いものを選びたいためです。
- **短文生成のモデル** / **文章生成のモデル**：短文はタイトル・ブランチ名・返信候補、
  文章はファイル編集の提案・計画の更新に使います。用途が違うので既定も別です。
  短文の「推奨」は、その CLI が一覧に出しているモデルのうち **models.dev の公表単価がいちばん安いもの**
  （codex・agy。安いモデルが新しく出ると自動で切り替わります）、文章の「推奨」はその 1 つ上の
  決まったティアです。単価が取れないときは従来の既定に戻ります。いま何に解決されているかは
  「推奨（現在: …）」に出ます。muse はどちらも、`-contributor` でも非表示でもない最新のモデルです。
  該当が無いとき（モデル一覧が読めないときも）は、contributor の既定で動かさず、補助生成を行いません。
- **AI 補助生成を使う機能**：8 機能それぞれに 1 枚のカードがあります。オフにするとボタン自体が
  出なくなり、カードのエージェント／モデルの行も畳まれます。
  - **セッションのタイトル提案**：自動で出る提案バナーと、セッションの「表示名を変更」の
    「AI に提案してもらう」。
  - **チャットのタイトル提案**：アシスタントの「タイトルを変更」の「AI に提案してもらう」。
    チャットには自動提案のバナーはありません。
  - **ブランチ名の提案**：worktree の作成やブランチ名の変更で使います。
  - **返信候補（セッション）** / **返信候補（チャット）**：ミラーとチャットのコンポーザーに
    それぞれ独立に出る ✨ ボタン。押したときだけ消費します。片方をオフにしても、もう片方には
    影響しません。入力履歴から学習する**返信サジェスト**（キー操作タブ）は AI を使わない別機能です。
  - **ファイル編集の提案**：File ペインで選択範囲と指示から置換文を作らせます。
  - **作業計画の更新**：アシスタント・チャットの計画を、直近のやり取りから作り直す「更新」ボタン。
  - **回答の翻訳（ミラー）**：ミラーで、表示言語と違う言語で返ってきた回答に出る「翻訳」ボタン。
    押したときだけ消費し、**セッションのターンは使いません**（会話は進みません）。訳はそのセッションを
    消すまで残り、**同じ本文・同じエージェント／モデルなら**二度目以降は無料です。この機能の
    エージェントやモデルを変えると、その組み合わせでの訳がまだ無いので次の押下は作り直しになります
    （前のエージェント／モデルでの訳は消えず、戻せば残っています）。
  - **自動翻訳**：上の「翻訳」ボタンを、ターンが完了した時点で自動的に押します（既定はオフ）。
    対象は**そのセッションを開いて見ている間に届いた回答**だけです。開いた時点で既に画面にある
    回答が勝手に訳されることはありません（ボタンはこれまでどおり出ます）。翻訳の設定のうち、
    これだけは押さなくても消費します。

  各カードは、上の優先順位・モデルとは別に**このカード 1 枚だけ**のエージェントを選べます
  （既定は「自動（優先順位）」）。エージェントを 1 つに決めると、そのエージェントのモデルも
  個別に選べます。「自動」のままではモデルは既定に従うだけで、具体的な 1 個は選べません。
  カードの「いま使うのは」は、実際に今その機能が使うエージェントです（未取得のうちは表示しません）。

### エージェントへの指示

このワークスペースで新しく起動するエージェントに、自分専用の指示を足します。
配り先ごとに「どのファイルに書かれたか」「いま効いているか」が並びます。
詳しくは [06 エージェント](06-agents.ja.md#エージェントへの指示自分の働き方を一度だけ書く)。

ここで扱うのは指示だけです。個人の Claude Code のフック・スキル・サブエージェントには設定画面がなく、
作り直しでも残る claude の設定フォルダのファイルです。
[06 エージェント](06-agents.ja.md#自分の-claude-code-設定を持ち込む)を見てください。

### エージェントメモリ

Agent Fleet 自身の共有メモリです。どの種類のエージェントも af のツール `memory_index` / `memory_search` / `memory_read` /
`memory_save` / `memory_forget` で読み書きします。プロジェクトごと（worktree はリポジトリのものを共有）と、全プロジェクト
共通の範囲があり、エージェントの種類を替えても、引き継いでも、別の種類の子セッションでも、学んだことが残ります。
**既定はオフ**です。エージェントが自前のファイルに貯めるメモリの版管理は、隣の項目[メモリのスナップショット](#メモリのスナップショット)です。

先頭に状態の行が 1 本あります（オンかオフか、プロジェクト何件にメモリ何件か、最後に変わった時刻、Claude Code との
バックグラウンド同期に確認が必要なときは警告と「設定」への案内）。その下に 4 つの表示があります：
**メモリ · 変更 · 取り込み・書き出し · 設定**。最後に開いた表示は覚えています。ワークスペースが停止中に使えるのは
**設定**だけで（スイッチは次の起動に向けて保存されます）、ほかの表示には「ワークスペースを起動」が出ます。スマートフォンや縦向きのタブレットでも
タブは 1 行のままで、収まらないときは横にスクロールします。矢印キー、Home、End でタブを移れます。

#### メモリ

- **一覧と詳細**：左の一覧に、**すべての範囲**（既定。ユーザー共通と全プロジェクトをまとめ、各行に所属を表示）、または 1 つの範囲（全プロジェクトに配布される**ユーザー共通**、または 1 プロジェクト）のメモリを、作成者・最終更新・エージェントに読まれた回数・**ピン留め**の印とともに表示します。**すべて**・**ピン留め**・**忘れさせた**のチップで絞り込めます。検索は名前・説明・種別・作成者を即時に、本文を入力が止まってから（エージェントの `memory_search` と同じ順位付けで）照合します。検索は「読まれた回数」に数えません。行を選ぶと右にそのメモリが開き、本文・範囲・種別・作成者・更新・使用回数と、**編集**・**ピン留め** / **ピンを外す**・**このメモリを忘れさせる**、**その他の操作**（⋯）の中の**履歴から消去…**が出ます。**新しいメモリ**（表示中の範囲に作ります。すべての範囲を表示中はユーザー共通）と**編集**のフォームも同じ場所に開きます。選んだ範囲・チップ・メモリは、表示を行き来する間は覚えていて、ページを再読み込みすると忘れます。スマートフォンでは一覧と詳細が別の画面になり、行を選ぶと詳細が開き、**一覧に戻る**（または Escape）で戻ります。名前またはテキストが秘密情報らしいメモリは一覧に出さず、件数だけ表示します。

- **ピン留めしたメモリ**：詳細で**ピン留め**したメモリは、エージェントが作業開始時に読む索引の先頭に、ほかより前に必ず載ります。**ピンを外す**と元に戻ります。**ピン留め**のチップで一覧できます。それ以外は、種別（feedback・
  user のメモリが先）→ 読まれた回数（読み取りと、返された検索ヒットを数えます）→ 新しさの順です。ピンも索引の
  サイズ上限を共有するため、ピンだけで収まらないときは末尾のものが名前だけの一覧に落ち、エージェントにもそう伝わります。
  全セッションに必要なものだけを留めてください。`memory_search` のヒットも関連度順です（クエリの語が多く当たるものが先、次に名前 ＞ 説明 ＞ 本文の順、次にピン・読まれた回数・新しさ）。全語を含むメモリがないときは、一部の語を含むものを返し、その旨を示します。ピンは「ピン変更」としてあなたの変更に記録され、元に戻せます。
  ピン留め済みのメモリをエージェントが後で更新してもピンは残り、af のメモリツールにはピンを付け外しする手段がありません。

- **忘れさせる・忘却を取り消す・履歴**：**このメモリを忘れさせる**と全エージェントから見えなくなり、**忘れさせた**のチップに並んだものは、行または詳細から**忘却を取り消す**ことができます（直前のテキストに戻ります。今は秘密情報に見えるテキストは、確認できる「変更」の表示で、その忘却に**この変更を元に戻す**を使ってください）。どちらも「変更」の表示と同じ元に戻す・忘れさせるで、あなたの操作として記録され、取り消せます。
  忘れさせるは一覧のどのメモリにも使えます（押したときに最新の変更を探すので、古くても構いません）。**忘れさせた**には、選んだスコープ（初期値はすべてのスコープ）で忘れさせたメモリが、
  いつ忘れさせたものでも最大 300 件まで出ます（残りはスコープを絞ると見られます）。忘れさせたメモリが非常に多い（約 2000 件を超える）ときは古いものを確認せず、その旨を表示します。一覧に抜けがあることがあり、表示していない件数は最小値です。詳細の下の**このメモリの履歴**には、そのメモリ自身の変更が並び、選ぶと「変更」の表示と同じ差分が出ます。全メモリの新しい順 300 件の変更から拾うため、ずっと前に最後に変更されたメモリでは足りないことがあり、そのときはその旨を示し、**「変更」ですべて見る**で「変更」の表示を開きます。保存は、エージェントの保存と同じ版の確認と秘密情報のスキャンを通り、
  あなたが書いたものとして記録され、「変更」の表示から取り消せます。プロジェクトに書けるのは、そのプロジェクトに
  既にメモリがあるときだけです。編集しても、メモリが限定されているエージェントの種類は変わりません。ピン・
  revert・忘れさせる・保存には Control Plane が署名し、Workspace はその署名があるときだけ受け付けるので、
  Workspace 内のセッションがあなたとしてこれらを行うことはできません。この機能より前に起動した Workspace は、
  再起動するまでこれらを拒否します。また Workspace の起動から 30 秒ほどは、1 分ほどして再試行するよう求められます。

- **履歴から消去…**：**忘れさせる**は隠すだけで、以前のテキストは履歴とすべてのエクスポートに残ります。
  **履歴から消去…**（メモリの詳細の**その他の操作**の中と、忘れさせたメモリの行と詳細にあります）は、メモリの過去の版をこのワークスペース
  から完全に削除します。ダイアログに、書き換える内容がテキストなしで先に出ます：このメモリの変更記録が何件
  消えるか、過去の版を含むほかのスナップショットが何件か、どの履歴に触れるか（本流の履歴・取り込んだ履歴・
  以前の履歴の退避コピー）、過去の版でシークレットスキャンが検出したもの（ルール・行・マスクしたヒントだけ）。
  確認のため、メモリの名前を入力します。行われること：メモリのファイルをすべての履歴のすべてのコミット
  から取り除き、それだけを含んでいたコミットは捨てます。どこからも辿れなくなったオブジェクトはガベージ
  コレクションし、消した版がディスクから消えたことを一つずつ確かめます。メモリの**現在のテキストは残る**ので、
  メモリと履歴は食い違いません。現在のテキストを消したいときは、先にメモリを編集してから消去してください
  （古いテキストが過去の版になります）。忘れさせたメモリは、忘れた記録を含むすべての版が消え、あとから忘却を取り消す
  ことはできません。ほかのメモリの履歴と、その元に戻す操作には影響しません。消去後、そのメモリに残る変更は元に戻せません
  （戻る先がないため）。忘れさせることはできます。**すでに作ったエクスポートは取り消せません**：ダウンロード
  したバンドル（全履歴）やアーカイブ、ほかの場所へコピーしたものには古いテキストが残るので、自分で削除して
  ください。中断した書き出し・取り込みがワークスペース内に残した一時ファイルは、消去が取り除きます。消去は revert や保存と同じく Control Plane の署名を要するのでセッションからは始められず、
  Control Plane は `memory.entry.purge` として、プロジェクトだけを記録します（メモリの名前や本文は記録しません）。
  プレビューのあとで履歴が変わったときは、確認し直すよう求められます。

#### 変更

一覧には変更が新しい順に、いつ・どのエージェントとセッションが・何を、で並びます。メモリの最新の変更では**元に戻す**（前の内容に戻る）か**このメモリを忘れさせる**ことができ、どちらも新しい変更として記録されるので、これ自体も取り消せます。戻す内容に秘密情報らしき記述があると、伏せた検出結果が示され、確認を求められます。

「終わったセッションからメモリを提案させる」がオンの間、またはまだ承認待ちの提案が残っている間は、この表示が **公開済み**（上の一覧）と **提案** の 2 つに分かれ、**提案** の横に承認待ちの件数が付きます。同じ件数は表示バーの **変更** の横にも付き、通知（「メモリの提案が N 件、承認待ちです」。通知設定では **その他のお知らせ** の行）を押すとこの表示が開きます。承認待ちがあれば **提案** で開きます。

- **提案**には、バックグラウンドのレビューが挙げた提案が古い順に、挙げた理由と、今のメモリとの差分つきで並びます。**ここにあるものはまだメモリに入っていません。** **承認**すると「review」による変更として公開されます（作者のセッションには提案元のセッションが入ります）。ほかの変更と同じく取り消せます。**却下**すると本文は削除され、同じ提案が再び出ないよう指紋だけが残ります（そのメモリを忘れると解除されます）。**すべて却下**は全部を、**このレビューの分をすべて却下**は選んだレビューの分を却下します。
- 提案は、レビューが見たあとでそのメモリが変わったとき（差分は今のメモリとの比較です）、メモリが忘れられているとき（レビューは忘れられたメモリを元に戻しません）、提案が今の秘密情報の規則に当てはまるとき（このときは本文を一切表示しません）、プロジェクトがもうないときは、**承認できず**、却下だけができます。承認では保管庫の秘密情報の走査もあらためて行います。
- レビューが公開した変更では、**このレビューの変更を元に戻す**で、そのレビューが公開したものをすべて、新しい変更として元に戻します。そのあとで誰かが変更したメモリは戻しません。編集されて残ったものは理由つきで結果に示され、もう一度実行すると残りだけを試します。
- 承認・却下・元に戻すができるのはあなただけです。Control Plane がこれらの要求に署名し、Workspace はセッションからのものを拒否します。提案の一覧もセッションからは読めません。Control Plane は決定のたびに（本文なしで）監査ログへ記録します。

#### 取り込み・書き出し

取り込み・書き出しは、ソースごとのカードを並べたハブです。**取り込み**（Claude Code から取り込む・muse から取り込む・このバンドルの Agent Fleet のメモリ）、**書き出し**（Claude Code へ書き戻す）、**メンテナンス**（なくなったプロジェクトのメモリを移す）の 3 グループがあり、**開始**を押すとハブの代わりにそのソースのウィザードが開きます。どのウィザードも同じ枠で、手順の表示（**元の選択**・**プレビュー**・**確認**・**適用**・**結果**）、状態ごとにまとめて件数を付けたプレビュー、**キャンセル**（適用中は押せません。終わると**取り込み・書き出しに戻る**に変わります）が付きます。

- **Claude Code から取り込む**：Claude Code がプロジェクトごとに溜めたメモリを Agent Fleet の
  メモリへ一度だけ取り込めます。プロジェクトを選ぶと、何も書く前に結果が見えます：**新規**、
  **Claude 側が新しい**（Agent Fleet 側の写しを上書きします。取り込み後に自分で直していても上書きされるので、
  両方の時刻を表示します）、**変更なし**、**忘れ済み**（忘れた、または取り込みを取り消したメモリは二度と
  戻りません）、**秘密情報の疑い**（取り込まず、伏せた検出結果を表示。Claude 側のファイルを直して
  プレビューし直してください。通す手段はありません）、**取り込めない**（理由つき）。何も切り詰めません。
  `_` や `.` を含む名前、2,000 文字までの説明、200 KiB までの本文、長い行はそのまま取り込みます。
  名前・説明・本文がそれらの上限を満たし（200 KiB は本文の上限です）、通常のテキストファイルであれば
  取り込めます。満たさないものは理由つきでプレビューに並びます。以前の版が説明を切り詰めて
  取り込んだメモリは**Claude 側が新しい**として表示し、Agent Fleet 側の写しを自分で直していなければ
  Claude のファイルから更新します。Claude のプロジェクトは `~/repos` の作業コピーに
  対応づけ、対応が無い、または 2 つ以上あるものは一覧に出ますが取り込めません。取り込むには Agent Fleet の
  メモリがオンである必要があります（プレビューはオフでも使えます）。取り込んだメモリは「メモリ」の表示に「取り込み」として
  並び、書き手は不明で、ほかの変更と同じく元に戻せます。

- **muse から取り込む**：Muse Code が溜めたメモを Agent Fleet のメモリへ
  一度だけ取り込みます。使い方は Claude Code の取り込みと同じで、フォルダを選び、プレビューを見て、確定します。
  muse には 3 つの保存先があり、選択肢にそれぞれ出ます。**プロジェクトのメモ**（作業コピーの `.agents/memory`。
  そのプロジェクトへ）、**personal project のメモ**（muse 自身の作業コピー別フォルダ
  `~/.local/share/muse/memory/projects/<slug>-<hash>`。`~/repos` 配下で対応する作業コピーのプロジェクトへ。
  どの作業コピーにも合わないフォルダは「作業コピーなし」、別々の 2 プロジェクトに合うものは「複数一致」と出て、
  どちらも取り込めません）、**personal のメモ**（`~/.local/share/muse/memory/personal`）です。personal のメモは
  **すべてのプロジェクトのセッションが読むユーザー全体のメモリ**へ入ることになるため、その旨のチェックボックス
  （ターミナルでは `--into-user`）を入れるまで、プレビューも取り込みもしません。ほかのスコープがユーザー全体の
  メモリへ入ることはありません。メモにフロントマターは要りません（muse は渡された内容をそのまま保存します）。
  名前はファイル名（Agent Fleet の名前として有効でなければ「名前不正」と一覧に出ます）、説明は最初の空でない行
  （2,000 文字で切ります）、種別はなしで、こうしたメモには「フロントマターなし」と付きます。フロントマター付きの
  メモは従来どおり読みます。muse のパスにはフォルダが入り得ます：`a/b.md` はメモリ `a--b` になり、同じ名前に
  なるファイルが 2 つあれば両方とも取り込みません（ノートが 2,000 件を超えるフォルダはプレビューのみで、確認を終えられないため取り込みません）。別の muse ファイル・フォルダ・スコープに由来する同名のメモリは上書きしません。`MEMORY.md`、muse の `.muse-memory.lock`、`.md` 以外は
  メモではなく、シンボリックリンクはたどりません。**新規**は追加し、**muse 側が新しい**ものは、Agent Fleet 側の
  写しがこの取り込みの書いた内容のままである間だけ更新します（取り込み後に Agent Fleet で保存・編集・ピン留め・
  取り消しをしたメモリや、muse 由来でない同名のメモリは**Agent Fleet 側に独自の版あり**として一覧に出し、触りません）。
  忘れたメモリは戻らず、秘密情報の検査に掛かったファイルは取り込まずに一覧へ出します。作成者は不明として記録します。
  `.agents/memory` はリポジトリの中にあり、チームがコミットしていることがあります。git が追跡しているファイルには
  **共有**と付き、確定前にプレビューで警告します。取り込むとチームメンバーの文章が、あなたのセッションが読む
  メモリへ写るためです。Agent Fleet から muse への書き戻しはしません。取り込みの実行にはスイッチのオンが必要で、
  プレビューはオフでも使えます。

- **ターミナルから**：`af-memory import-sources`、`af-memory import --project <slug> --dry-run`（プレビュー）、
  `af-memory import --project <slug>`（取り込み）。`af-memory changes` で最新の変更を一覧できます。
  muse 向けは `af-memory muse-import-sources`、`af-memory muse-import --dir <name> [--scope project|personal_project] [--dry-run]`、
  `af-memory muse-import --scope personal --into-user [--dry-run]` です。スイッチと秘密検査は Console と同じです。

- **このバンドルの Agent Fleet のメモリ**：メモリのバンドルに入っている Agent Fleet のメモリを取り込みます。メモリのスナップショットでバンドルを復元しても書き込まれません
  （復元には秘密情報の検査がないため）。**開始**を押すと、手順の最初にバンドルのファイルを選びます（tar.gz には入っていないので受け付けません）。そのあと、プレビューと取り込みを単独で行えます。バンドルの各プロジェクトは、ここのプロジェクトと識別子で対応づけ、
  違う場合（パスが違う）は、リポジトリのアドレスが同じプロジェクトがここにちょうど 1 つあるときだけ対応づけます。対応が
  ないか 2 つ以上ある場合は、一覧に出して取り込みません。ユーザー全体のメモリは常に対象です。各メモリは **新規**・**すでにある**・
  **ここでは内容が違う（そのまま）**（同名のメモリがここにあれば置き換えません）・**ここで忘れ済み（戻しません）**（履歴にしか
  残っていない場合も）・**秘密情報らしき記述（スキップ）**（ファイルのすべての部分を検査し、上書きはできません）・
  **取り込めません**のどれかで表示します。取り込むのは最新の本文と、そのメモリに付いていたエージェントの制限だけで、バンドルの履歴は
  取り込みません。**リセットされるもの**：リビジョン（ここでの次の番号から始まる）、作成者（不明。Claude の取り込みと同じ）、
  日時（取り込んだ時刻）、ピン留め。出所はメモリの source（`bundle:<取り込み ID>:<プロジェクト>/<名前>@<バンドルのリビジョン>`）と
  コミット（`AF-Bundle-Import`、`AF-Bundle-Source`）に記録するので、取り込みはエージェントメモリの「変更」の表示に出て、そこで元に戻せます。スイッチの
  オン／オフを問わず使え、あなた自身の操作にだけ応じ、監査ログに記録されます。
- **Claude Code へ書き戻す**：逆向きの操作で、手動で 1 プロジェクトずつ行います。
  スイッチをオフにすると全プロジェクトの書き戻しは自動で行われます（上記）。ここは、それが残した競合を解消するときや、
  ネイティブメモリをオンに戻したあとに使います。Agent Fleet 経由で学んだ内容を Claude Code のメモリへ写します
  （対象は Claude Code のみ。codex は含みません）。プロジェクトを選ぶと、書く前に結果が見えます：
  **新規**、**Agent Fleet 側が新しい**（前に書き戻したファイルを更新）、**Agent Fleet で忘れ済み**（前に書き戻した
  ファイルを削除）、**競合**（Agent Fleet が書いていない、または書いた後にあなたが変えた Claude のファイル。
  チェックしない限り残します。取り込んだときのままのファイルは**変更なし**、取り込み後にこちらで
  メモリを直していれば**Agent Fleet 側が新しい**になります）、**秘密情報の疑い**（書かない）、**変更なし**、**Claude にだけある**（消しません）。
  更新しても、Claude がファイルの `metadata` に記録した項目（`originSessionId` など）は残します。そのままは写せない metadata を持つファイルは、更新ではなく競合として表示します。
  ユーザースコープのメモリは書きません。`MEMORY.md` は Claude の読み込み上限（200 行・24 KiB）に収めて
  作り直し、古いものを置き換えます。先に Claude のメモリをスナップショット（契機「書き戻し前」）に残すので、
  メモリのスナップショットの履歴から戻せます。スイッチのオン・オフを問わず使えます。オンのときは、オンにする前から動いている
  Claude Code のセッションを先に終了してください。

- **なくなったプロジェクトのメモリを移す**：プロジェクトはリポジトリのフォルダに結び付いているため、改名・移動・
  クローンし直したリポジトリは新しい空のプロジェクトとして始まり、古いほうのメモリはどのセッションからも届かない場所に残ります。
  ここには、作業コピーがなくなったと分かっているプロジェクトを、メモリの件数付きで一覧します（マウントされていないディスク上のフォルダ
  など、判断できないときは一覧に出ません）。1 つ選び、代わりのプロジェクト（メモリを持つか `~/repos` に作業コピーがあるもの）を選んで、
  プレビューを読んでから確定します。移動先ですでに名前が使われているメモリは**決して上書きされません**。そのまま残すか、別の名前
  （`<name>-moved`）で移すかを選びます。本文が移動先の写しと同一のものは、古い写しが消えるだけです。プレビュー後に変わったメモリや、
  秘密情報らしき内容を含むファイルは古いプロジェクトに残ります。メモリ 1 件ごとに、「変更」の表示に各プロジェクト 1 件ずつ計
  2 件が並ぶので、そこでどちらも取り消せます。途中で止まったときは、もう一度実行してください。何も失われず、止まったところから終わります。
  セッション向けのスイッチがオンでもオフでも使え、Console からだけ実行できます。古いプロジェクトと同じ git の remote（同じ
  リポジトリのクローンし直し）を使う、作業コピーのあるプロジェクトがちょうど 1 つあるときは、**移動を確認する**ボタン付きで提案します。
  ボタンは 2 つの選択欄を埋めてプレビューを出すだけで、確定するまで何も移動しません。同じリポジトリの作業コピーが 2 つあるときは
  提案しないので、移動先は自分で選んでください。Agent Fleet はプロジェクトごとに remote を覚えますが、URL 内のパスワードやトークンは
  保存しません。作業コピーがすでになくなっていたプロジェクトには remote の記録がなく、提案されません。ssh のアドレスは大手のホスティング（GitHub、GitLab、Bitbucket、Codeberg）だけを同一視し、それ以外のサーバーでは https のアドレスだけを比べます。

- **ターミナルから**：`af-memory export-sources`、`af-memory export --project <id|名前> --dry-run`（プレビュー）、
  `af-memory export --project <id|名前> [--overwrite <名前>]...`（書き戻し）。

#### 設定

**既定はオフ**です。先にこの表示の先頭の「セッションに Agent Fleet のメモリを使わせる」をオンにしてください（オンは次に起動するセッションから効き、オフは起動中のセッションの読み書きもその場で断ります。「メモリ」「変更」の表示はオフでも使えます）。オンの間は、各種類の指示ファイルに「このツールがあること・いつ呼ぶか」の短い固定の注意書きも入ります（記憶そのものは入らず、オフにするとあなた自身の文章には触れずにその部分だけ消えます）。ローカルモデル（lcpp）のセッションは、システムプロンプトにそのプロジェクトのメモリ一覧も最初から載ります。Cursor には指示ファイルを置ける場所がないため、同じ案内はツールの説明に入っています。保存は**承認なしで**すぐ共有され、秘密情報らしき記述は拒否されます。

- **Claude Code 自身のメモリ**：スイッチが自動で引き継ぎます。「セッションに Agent Fleet のメモリを使わせる」を
  切り替えると、先にプレビューから件数を示し（オンなら「6 プロジェクトから 474 件を取り込みます。1 件は
  スキップ（秘密情報）」、オフなら「473 件を Claude Code へ書き戻します。競合 0 件」）、確認してから切り替わります。
  **オン**：`~/repos` の作業コピーに対応づけられる Claude のプロジェクトをすべて、Agent Fleet がバックグラウンドで
  取り込み、以後に起動する Claude セッションは Claude Code の自動メモリを切った状態で起動します。Claude は自前の
  `MEMORY.md`（毎セッションの開始時に約 25 KB）を読み込まず、ほかの種類と同じく af のツールを使います。自動の取り込みは下の
  **Claude Code から取り込む**より厳しく、*ここで編集した* Agent Fleet のコピーより新しい Claude のファイルは、競合として報告するだけで
  上書きしません（手動の取り込みは、あなた自身の選択として従来どおり上書きします）。忘れたメモリは戻さず、秘密情報らしき記述を含む
  ファイルはスキップして一覧に出します。すでに動いていた Claude セッションは自前のメモリを使い続け、そのうち最後の 1 つが終わった時点で、
  保存された内容をもう一度取り込みます。**オフ**：Agent Fleet がすべてのプロジェクトを Claude Code のメモリへ書き戻し
  （「取り込み・書き出し」の**Claude Code へ書き戻す**と同じ規則：先にスナップショット、上書きなし、競合と秘密情報は残して一覧に出す）、
  それが終わるまで Claude Code 自身のメモリは切ったままです。間に起動したセッションが、書き戻しとぶつかるファイルを書かないようにするためです。
  書き戻しが失敗し続けるときも Claude Code のメモリは切ったままで、Agent Fleet は間隔を延ばしながら再試行します。このとき画面に
  **今すぐ再試行**と**それでもネイティブメモリをオンに戻す**が出ます。スイッチの下には、実行の進み具合、前回の結果、残したファイル
  （競合・スキップした秘密情報）が表示され、残りがあれば通知が 1 件届きます。この処理はワークスペースを再起動しても続きます：
  記録した段階から再開し、停止中にスイッチが変わっていても、起動した時点で引き継ぎます。Codex：スイッチをオンにすると codex 自身の
  `features.memories` を切り、オフにすると元の値に戻します（オンにはしません）。codex への取り込みも書き込みもありません。
  オンの間にそのフラグを自分で変えたときは、その値が戻されます。変更後に*起動した* Claude セッションだけが対象で、
  起動中のセッションは起動時のままです。

- **Muse Code 自身のメモリ**：スイッチがオンの間、Agent Fleet は Muse Code をネイティブメモリを切った状態
  （`MUSE_EXPERIMENTAL_MEMORY=0`）で起動します。Muse には `read_memory` / `add_memory` / `edit_memory`
  のツールも、コンテキスト内のメモリのスナップショットも、プロンプトの「永続メモリを使う」段落もなく、
  ほかの種類と同じく af のツールを使います。スイッチがオンの間は、自分の環境に同じ変数があってもこの設定が
  優先されます。オフのときは何も設定せず、Muse の既定のままです。対象は Muse のセッションとアシスタント
  チャットです。変更後に*起動した* Muse ホストだけが対象で、起動中のセッションは起動時のままです。

- **Agent Fleet の外から使う**（設定「Agent Fleet の外からメモリを使わせる」。**既定ではオフ**で、上のスイッチとは独立）：
  別のマシンにあるあなた自身のエージェント（MCP トークンを持つ Claude Code や Claude Desktop。運用編「守る」参照）に、
  Control Plane の `/mcp` 経由でこのメモリを使わせます。**読み取りのみ**を選ぶと、read スコープのトークンで
  `memory_projects`（プロジェクト ID の一覧）・`memory_index`・`memory_search`・`memory_read` が使えます。
  **読み書き**ではさらに write スコープのトークンで `memory_save` と `memory_forget` も使えます。プロジェクトは
  `project` 引数（`memory_projects` で得た ID）で指定し、すでにメモリを持つプロジェクトに限ります（新しいプロジェクトは
  Workspace の中から始まります）。保存は同じリビジョン確認・秘密情報検査・上限を通り、「メモリ」の表示には書き手 `external` として
  出ます（クライアントが自称する名前は、参考情報としてだけコミットメッセージに残ります）。外からの保存と忘却は、
  プロジェクト ID だけ（メモリ名は残しません）を監査ログにも記録します。メモリの本文は Workspace の外に出てそのクライアントの
  モデルに渡ります。秘密情報の検査は認証情報を止めますが、顧客名や社内の事情までは止められません。Workspace が起動して
  いる必要があり、停止中は先に起動するよう答えます。設定はメンバーごとで、`/mcp` を提供しない環境（`AF_MCP_ENABLED`）では
  外からは一切使えません。
  頼み方と記録されるものは [10 一歩進んだ使い方](10-integrations.ja.md#外部のエージェントから-agent-fleet-のメモリを使う)にあります。

- **終わったセッションからメモリを提案させる**（設定「終わったセッションからメモリを提案させる」。**既定ではオフ**で、
  上のスイッチもオンである必要があります）：**提案する**を選ぶとレビューがオンになりますが、それだけではバックグラウンドで
  何も動きません。セッションの **⋯** メニューの **「メモリを提案させる（今すぐ）」** で依頼すると、会話の抜粋を
  **ツールも MCP も持たない**エージェントに読ませ、残す価値がありそうな内容を「提案」として挙げます。抜粋は先に赤塗り
  （秘密らしき部分は除く）しますが、「AI 支援」でこの機能に選んだエージェントのプロバイダへ送られ、元のセッションと違う
  プロバイダのこともあります。トークンも消費し（1 日最大 250 回、同時に 1 件）、Workspace の停止中は動きません。
  **承認なしにメモリへ入ることはありません**。提案は最大 100 件まで [変更 › 提案](#変更) で待機し、そこで承認か却下を
  します。設定がオンの間は「AI 支援」に**メモリのレビュー**のカードが現れてエージェントとモデルを固定できます。ツールを
  無効にして実行できるエージェントでしかレビューはできず、固定したものができない場合は別のプロバイダへ切り替えずに
  実行を見送ります。
- **自動でも提案させる**（設定「自動でも提案させる」。**既定ではオフ**で、上の設定とは別のスイッチです。**提案する**を
  選んでいる間だけ働きます）：オンにすると、終わったセッションを依頼なしでバックグラウンドで見ます。セッションが
  一区切りついて 5 分ほど経ち、前回のレビュー以降に 30 ターン、またはあなたのプロンプトが 3 回たまっていて、さらに最後の
  ターンが 48 時間以内に終わっている場合だけ対象になります。それより古いものや停止中の分は「メモリを提案させる（今すぐ）」で
  行います。消費するトークンは上と同じで（1 日 250 回は手動と共通）、誰も見ていないところで使われます。オフにすると新しい
  確認はすぐ止まります。実行中の呼び出しは終わるまで待ち、出てきた提案は承認待ちになりますが、その先は始まらず、失敗した
  呼び出しも再試行しません。この設定ができる前に**提案する**をオンにしていた場合は、オフから始まるので、
  バックグラウンドのレビューを続けるには自分でオンにしてください。

### メモリのスナップショット

エージェントが自分で貯めていく記憶（claude の自動メモリ、codex の memories）の**版管理**です。「余計なことを覚えてしまった」
「いつからおかしくなった」を後から直せます。Agent Fleet 自身の共有メモリである[エージェントメモリ](#エージェントメモリ)とは別物です。
先頭に最後のスナップショット・自動スナップショットのオン/オフ・**今すぐスナップショット**があり、その下に 3 つの表示が
あります：**履歴 · 対象 · 書き出し・取り込み**。最後に開いた表示は覚えています。ワークスペースの起動中だけ使えます。

#### 履歴

- **履歴**：時刻と契機（自動 / 手動 / 巻き戻し前 / 巻き戻し / 取り込み / 書き戻し前）が新しい順に並びます。
  日時を指定してその時点へジャンプすることもできます。Agent Fleet のメモリの書き込みが残すスナップショット（契機「エージェントの記録」）は、
  エージェントメモリの「変更」にも並ぶので隠してあり、続く 1 まとまりごとに「非表示の Agent Fleet のメモリの書き込み：N 件」の行と
  「変更」へのリンクが出ます。**Agent Fleet のメモリの書き込みも表示**で並べられます（この選択はこの端末に記憶されます）。
  日時ジャンプがその 1 件に当たったときは表示され、差分と**この時点に戻す**もほかの行と同じように使えます。

- **この時点に戻す**：範囲（すべて / 選んで戻す）を指定して巻き戻します。
  **戻す直前の状態も自動で記録される**ので、この操作自体を後から取り消せます。
  対象のエージェントが実行中のときは警告が出ます。

#### 対象

- **対象**：版管理できるメモリの一覧と、ファイル数・サイズ・最終スナップショット。
  codex はメモリ機能が既定でオフなので、使うならここでオンにします。
- **自動スナップショット**：エージェントが停止して数分たつと自動で取得します（変更が無ければ積みません）。
  「今すぐスナップショット」で手動取得もできます。運用側の設定で自動取得が止められている環境もあります。

#### 書き出し・取り込み

- **書き出し・取り込み**：bundle（全履歴）または tar.gz（最新のみ）。書き出す内容に秘密情報らしき
  記述があると、書き出す前に警告が出て確認を求められます。
  - **バンドルの Agent Fleet のメモリ**：ここでバンドルを復元・取り込みしても、Agent Fleet のメモリは書き込まれません
    （復元には秘密情報の検査がないため）。選んだバンドルに Agent Fleet のメモリが入っているときは、その下に
    「このバンドルには Agent Fleet のメモリも入っています — 「エージェントメモリ › 取り込み・書き出し」で取り込めます。」と
    出ます（**取り込み・書き出しを開く**のリンク付き）。取り込み自体は、エージェントメモリの「取り込み・書き出し」にある
    **このバンドルの Agent Fleet のメモリ**で行います。

### 課題管理

左ペインの**課題管理**に並ぶ作業項目（Jira の課題、GitHub の Issue とプルリクエスト、
Bitbucket のプルリクエスト）の取得元です。行からそのままセッションを起こせます。

- **保存クエリ**がすべてです。GitHub の検索構文・Jira の JQL・Bitbucket の絞り込み式を
  そのまま保存します。**保存クエリを作るまで一度も取りに行きません。**
  ここが唯一の絞り込みで、全件は取り込みません。
- **GitHub は `assignee:` だけではプルリクエストが出ません。** GitHub は PR の作者を
  アサインにしないので、`assignee:@me` だけのクエリでは Issue しか並びません。既定の
  `is:open (is:issue OR is:pull-request) involves:@me`（`is:issue` も `is:pull-request` も無い検索を
  拒否する GitHub アカウントがあります）なら、自分が作成・アサイン・メンション・コメントした項目を拾います。
  **自分へのレビュー依頼は含まれない**ので、`is:open review-requested:@me` を 2 本目として
  足してください（両方に当たった項目も 1 行にまとまります）。`OR` と括弧も使えますが、
  Workspace の Agent が更新されてからです。古いままだと行に「クエリを解釈できない」と出ます。
- **Jira** はここで接続します。**OAuth** か、**メールアドレス＋API トークン**
  （メールアドレスも資格情報の片割れです）。**GitHub と Bitbucket は「Git ホスティング」の
  連携に相乗り**するので、ここでの接続は要りません。
- **Bitbucket** にはアカウントを横断する検索が無いので、クエリは手で書くのではなく
  **接続済みのリポジトリの一覧から組み立てます**（何を出すか × 対象）。Bitbucket の項目は
  **読み取りだけ**で、書き戻しはしません。
- **ブランチ名テンプレート**：行から起こしたセッションが切るブランチ。空欄なら既定の
  `{prefix}{ref}-{slug}`（例: `feature/45-empty-list`、`fix/PROJ-123`）です。使えるのは `{ref}` `{num}`
  `{key}` `{project}` `{type}` `{prefix}` `{slug}` で、欄の下の例に実際の結果が出ます。リポジトリ側の
  規則（git-flow など）があれば、起動時はそちらが優先されます。

一覧そのものと、行からセッションを起こす手順は
[02 セッション](02-sessions.ja.md#課題管理から始める)にあります。

### MCP サーバー

**自分で使う MCP サーバーをここに登録**すると、アシスタントやセッションから使えるようになります。
社内 Wiki、チケット管理、ドキュメント検索など、Agent Fleet が組み込みで持っていないツールを足す場所です。

- **接続方式**：**stdio**（ワークスペース内で実行ファイルを起動。コマンド・引数・環境変数を指定）か、
  **リモート (HTTP)**（URL とヘッダを指定）。
  **環境変数とヘッダの値は暗号化して保存**されます。ただし、サーバーを動かす CLI に渡す構成には
  値が含まれることがあります（ホーム内の本人しか読めないファイルで、リポジトリには置きません）。資格情報は URL ではなくヘッダに入れてください。
- **利用先**：**アシスタント** / **セッション**のどちらに配るかを選びます（両方外すと、登録は残りますが
  どこにも配られません）。**対象エージェント**を選ばなければ全エージェントが対象です。
- **接続テスト**：サーバー名・バージョン・ツール数と応答時間を確認できます。
- **有効 / 無効**：無効にすると、定義を残したままどこにも配られなくなります。
- セッションへの反映は**次に起動するセッションから**です。アシスタントは各アシスタントの編集画面で
  「MCP サーバー」から選びます（[07](07-chat-memo.ja.md)）。
- 一覧には出自のラベルが付きます。**個人**（自分の登録）、**テナント**（管理者が配布。同じ名前の個人登録は
  使われません。値の入力だけをメンバーに求める形の配布もあります）、**組み込み**（Agent Fleet 自身の
  サーバーと、運用・監視の連携）。
- 外向き通信が制限された配備では、接続先ホストの**許可を申請**して管理者の承認を待つ導線が出ます。
- リポジトリ側に置かれた MCP の定義（`.mcp.json` など）は、リポジトリ行のメニューから開く
  **プロジェクト設定**で、エージェント別の効き方と警告（秘密情報が Git 管理下にある、名前の衝突、
  ファイル間で内容が食い違う、など）を確認できます。

> **Agent Fleet 自身の MCP** は「組み込み」として最初から全セッションに配られています（設定不要）。
> セッションが完了を申告したり、次のセッションへの引き継ぎ案を出したりするのに使われています。

### AWS プロファイル/SSM

SSM ホスト（個別）の登録です。プロファイルの各行の**ログイン**で、Console から IAM Identity Center にログインできます。ログイン中の行の**ログアウト**は、そのプロファイルのログインだけを終わらせます。

### Google Cloud

`af-gcloud-exec` がコマンドを実行するときに使う Google Cloud のプロファイルです。ラベル（プロファイルの名前はここから作られ、
横に表示されます）とプロジェクト、任意で割り当てプロジェクト・ログインする Google アカウント・権限を借用するサービス
アカウント・リージョン・ゾーンを登録します。Google の認証情報はここに保存せず、サービスアカウントキーも受け付けません。
同じ名前になる 2 つのラベルは、片方の名前を変えるまでワークスペースで使えず、行にそう表示されます。使える行には
**ログイン**があり、Console からそのプロファイルでワークスペースを Google にログインさせます。ログインの画面が開き、
ログインはそこで**ログイン**を押したときに初めて始まります。Google が出す確認コードはその同じ画面に、それも自分で
始めたログインにだけ貼り付けます。ログイン済みの行には **「<アカウント> でログイン済み」** と出て、**再ログイン**で
取り消されたと分かっているログインをログインし直せます。**ログアウト**はそのアカウントについてワークスペースのログインを
削除します（同じアカウントを使うプロファイルも一緒にログアウトし、Google 側は変わりません）。WS バーの Google Cloud バッジにも同じログインが並びます。
→ [10 一歩進んだ使い方](10-integrations.ja.md#google-cloud-で自分としてコマンドを実行するaf-gcloud-exec)

## ワークスペース

### エージェント使用量

**何にトークンを使ったか**の台帳です。セッション本体だけでなく、Agent Fleet が裏で実行する補助呼び出し
（タイトル提案・要約引き継ぎ・返信候補など）も同じ基準で並びます。

- **期間**：24 時間 / 7 日 / 30 日。
- **割り方**：機能 / エージェント / モデル / セッションの出自（人が開始・オペレーターが作成・
  定時実行が作成・引き継ぎ・セッションが起動）/ 注入元（ユーザー・自動・定時実行・オペレーター・ブリッジ など）。
- **指標**：消費トークン / 呼び出し回数 / キャッシュ読取 / **API 換算相当額（推定）**。
  トークン数 × 各モデルの公表 API 単価（キャッシュ書込 ×1.25・読取 ×0.1）から計算した目安で、
  `≈` を付けて表示します。**サブスク定額の請求額ではありません。** セッション本体はコストを実測
  できないので、この列はもともと「—」でした（実測が返るのは claude の補助呼び出しだけ）。
  実測値は消えておらず、金額にカーソルを合わせると併記されます（推定とは足しません）。
- 単価は、Anthropic は内蔵の表、それ以外は **models.dev の単価カタログ**から引きます。カタログは
  Agent が 1 日 1 回取得します（取れない環境では opencode が保持しているものを読みます）。**どの単価をどこから採ったかは金額にカーソルを合わせると出ます**。
  opencode 経由の消費は opencode の価格で換算します（実際に払う額に近いのはそちらのため）。
- カタログにも無いモデルは**推定しません**。その分の消費は「計測できている範囲」に
  「消費の N% は単価を持っていないモデル」と出ます（金額 0 ではありません）。同じ欄に
  **カタログの取得日**も出ます。カタログが新しくなると過去の推定額も変わるためです。
- 時系列グラフの系列をクリックすると、その系列だけに絞り込めます。**機能 × モデル**の表もあります。
- **計測できている範囲**が明示されます。トークンを報告しない呼び出しは「回数だけ数えている」と出ます
  （消費ゼロという意味ではありません）。
- **rtk 効果**：トークン節約の累計・平均節約率・実行コマンド数を日次 / 週次 / 月次で表示します
  （RTK は [06](06-agents.ja.md#rtkトークン節約)）。

### クラウド費用

自分のワークスペースがクラウドでいくらかかっているかを見る画面です。**AWS で動く配備でだけ出るタブ**です
（他の配備には読むべきクラウドの請求がありません）。

- 出る数字は**自分のワークスペースに直接ひも付いている分**（スロットの稼働時間・永続ホームの
  ボリューム・そのスナップショット）で、画面でも「あなたのワークスペースに直接ひも付く費用
  （共有分は含みません）」と書かれています。共有インフラ（NAT・DNS・ロードバランサ・
  データベース・空きスロット）は**意図的にメンバーへ割り振りません**。したがってこれは
  **ワークスペースを動かす費用の全部ではありません**し、「あなたのコスト」でもありません。
- **約 24 時間遅れで、当日分は未確定**です。直近の日はあとから動きます。
- **期間**・**日次の推移**・**何に使ったか**の内訳が見られます。金額は請求どおりの通貨（米ドル）で、
  換算はしません。
- 費用の按分が有効になった日より前は**何も出ません**（有効にした時点からしか集計されず、
  遡って埋めることはできません）。いつからかは画面に出ます。

### 稼働時間

自分のワークスペースが**いつ動いていたか**を、縦 24 時間 × 横 日付のマス目で見ます。1 マスが
1 時間です。

- **色は金額ではありません。** クラウドの実費は 1 日単位でしか取れないので、時間ごとの金額は
  出せません（隣の「クラウド費用」がその面です）。ここに出るのは**動いていた時間と、その間に
  開いていたセッションの本数**で、たいていは「この日だけ費用が高い」の理由の方です。
- **マスは 3 種類あります。** 灰色は**止まっていた**、色つきは**動いていた**（濃いほどセッションが
  多い）、そして**空白は「記録がない」**（Control Plane がその時間を見ていなかった）です。
  空白と灰色は別の意味です。
- **濃さの意味は切り替えられます**：開いていた本数 / 実際に動いていた本数 / 稼働時間。
- マスに合わせると、その時間の内訳（稼働した分数・最大本数）が下に出ます。「**表**」に切り替えると
  同じ内容が数字で並びます。
- 時刻は**お使いの端末のタイムゾーン**で表示されます。
- **記録を始める前の時間は空白のまま**で、後から埋めることはできません。

### マシン

**自分のワークスペースが何の上で動いているか**の一覧です。読むだけの画面で、サイズと
マシンの種類を決めるのはテナント管理者です。

- **インスタンスタイプ / アーキテクチャ / vCPU / メモリ / home ディスク** が並びます。
  クラウド上の配備では 1 人に 1 台のインスタンスが割り当たるので、ここに出る数字はそのインスタンスのものです。
- 値ごとに **「実測」（コンテナの中で実際に読んだ値）** か **「設定上」（次に起動したときの値）**
  かが添えられます。停止中はすべて「設定上」です。
- **アーキテクチャは効きます。** `arm64` では rtk が入らず、JDK や Node も arm64 版が
  落とされます（[11 困ったとき](11-troubleshooting.ja.md)）。
- **メモリは「インスタンスの搭載量」ではなく「このワークスペースが使える上限」** が中心です。インスタンスの一部は
  ホスト側の常駐プロセスのために残されるので、両方あるときは `6.5 GiB（インスタンスの搭載 8 GiB）`
  のように併記されます。ビルドが強制終了されるときに見る数字はこちらです。
- 管理者がサイズや種類を変えても**反映は次の起動から**なので、いま動いているインスタンスと設定が
  食い違っているときは**両方**表示されます。
- **使用状況**：メモリ / vCPU の推移グラフ（4 秒ごとに 1 点・最大 1 時間）と home ディスクの
  使用量。**ディスクの値が自分のものなのは、1 人 1 台のインスタンスのときだけ**です。共有ホストでは
  home があるファイルシステム全体の値になるので、そう表示し、警告色も付けません（他の利用者の分も含むため）。**天井は上の行の値そのもの**（メモリはこのワークスペースの上限、CPU は vCPU 数）なので、
  「70% は何に対して 70% か」が同じ画面で分かります。値が変わらない間もグラフは進みます
  （変化が無いことは制御側が保証しているため）が、**取得できなかった時間は線を切って**表します。
  この間にメモリ不足で強制終了されたプロセスがあれば、その旨も出ます。
- **Agent Fleet が使っているディスク**：Agent Fleet 自身が `~/.cache/agent-fleet` に溜めているものの内訳
  （生成した画像・サムネイル・貼り付け・添付したファイルなど）、そのうち削除済みセッションの分、掃除の
  ごみ箱のサイズです。生成した画像は 30 日、サムネイルは 14 日で自動的に消えます。「**掃除を開く**」で
  設定を閉じて掃除モーダルが開き、削除済みセッションの分とごみ箱を片付けられます
  （[02 セッション](02-sessions.ja.md#まとめて片付ける掃除)）。作業コピーやツールのキャッシュは数えていません。
- **ツールのキャッシュ**：go・npm・uv・pip がホームに溜めるキャッシュ（`~/.cache/go-build`・
  `~/.npm/_cacache` など）です。上限なく増え（数十 GB になることも珍しくありません）、自動では消えません。
  「**測る**」で量を数え（全ファイルを読むので押したときだけ）、「**空にする**」で確認のうえ削除します。
  次にそれを使うビルドやインストールが 1 回だけ遅くなります。実行中のビルドやインストールが使っている
  キャッシュは「**使用中**」と表示され、終わるまで空にできません。
  Copilot と Cursor の CLI の古い版はここには出ません。Workspace の起動時に自動で消え、
  今の版・ピンの版・実行中のセッションがまだ使っている版だけが残ります。
- **使われなくなったファイル**：二度と読まれないものです。強制終了したヘッドレス Chromium が
  `~/.config/chromium-headless` と `~/.cache/chromium-headless` に残した使い捨てプロファイル、セッション
  （ごみ箱の中も含む）も作業コピーも無くなった `~/.af-work` のフォルダ、同じメジャーの新しいパッチに
  置き換わった Node.js、入っている版・ピンの版以外の Kiro が対象です。Agent が起動するたびに自動で消すので、
  このセクションは何週間も再起動しないワークスペースのためにあります。「**測る**」で今消えるものを数え、
  「**削除**」で種類ごとにすぐ消します。ツールのキャッシュと違って後で遅くなるものが無いので、確認は出しません。
  プロセスが使用中のものと、1 時間以内に変更されたものは残ります。
- 使用状況グラフの下（WS バーの**リソース**からも）「**マシンと使用状況**」で、この画面を直接開けます。

### データベース

このワークスペースの PostgreSQL と MySQL で、DB を使うテストが向く先です。エンジンごとの
状態・版・メモリ・ポート・接続 URL が出て、導入・開始・停止、名前を付けたデータベースの

→ [03 リポジトリと git](03-code.ja.md#db-を使うテストを回す)

### プレビュー用サブドメイン

作っているアプリを `https://＜ランダム＞-＜ポート＞.＜ドメイン＞/` で開くための設定です。
**プレビュー用サブドメインが発行される配備でだけ出るタブ**で（発行しない配備では、そもそも
設定しても URL が出ません）、公開するポート・URL の固定・同じテナントへの共有・サインイン
なしの公開・URL の再発行がここに入ります。運用者が開発用 OIDC IdP を有効にしている配備では、そのスイッチ

### 内部リポジトリ

外部の git ホスティングを使わず、**テナントの中だけで完結する git リポジトリ**の作成・リネーム・削除と、
中身の参照です。clone URL は自動で認証されるので、接続の手順はありません
（ワークスペースが停止中でも操作できます）。→ [03 リポジトリと git](03-code.ja.md)

### 書き出し / 取り込み

自分の設定を**ファイル 1 個**にまとめて持ち出し、別の環境やアカウントで読み戻せます。
入るのは **個人設定**（表示・キー操作・通知・エージェントの既定など）、**AWS プロファイル/SSM** の登録、
**Google Cloud** のプロファイル、**エージェントへの指示** の 4 つです。

- **接続（Git・エージェント・AWS のトークンや API キー、Google のログイン）は入りません。** 移った先では
  もう一度ログインしてください。裏を返すと、**このファイルは人に渡せます**
  （チームの SSM 登録一式を配る、といった使い方ができます）。
- 取り込みは**足すだけ**です。同じ名前のプロファイル、同じホスト（別名＋インスタンス）は
  そのまま残り、「既にありました」と件数で報告されます。Google Cloud のプロファイルは、同じラベル（大文字と小文字は
  区別しません）のものがあれば既にあるものとして扱い、ラベルかプロジェクトの無いものは飛ばします。
- 個人設定は今の設定に**重ねます**。学習済みの返信候補やキー割当のような溜まっていくものは、
  取り込んだファイル側が空でも消えません。
- エージェントへの指示だけは**今の文章を置き換えます**（取り込む前に確認が出ます）。
- 取り込んだ結果は件数で残ります。**入らなかった件数も同じ行に出ます**。

### 危険な操作

**ワークスペースを作り直す**（`~/repos` だけを消して最新イメージで作り直す）と、
**ホームを掃除する**（ログイン・接続以外のホームも消す、より深いリセット）。
どちらも未コミットの変更が消えます。このタブは、これらを実行できる配備でだけ表示されます。
→ [10 一歩進んだ使い方](10-integrations.ja.md#ワークスペースを作り直す危険な操作)
