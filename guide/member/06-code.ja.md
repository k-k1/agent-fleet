# 06. リポジトリと git — クローン・変更の確認・コミット・push

[English](06-code.md) | 日本語

## git プロバイダを接続する

private リポジトリをクローン／push するには、まず GitHub か Bitbucket に接続します。
**⚙設定 → 「Git ホスティング」タブ**で行います（接続はワークスペース内の Agent を経由するため、
ワークスペースの起動が必要です）。

- **GitHub**：「OAuth で接続」（推奨・ブラウザで承認するデバイスフロー）か「アクセストークンで接続」（Personal Access Token を貼付）。
- **Bitbucket**：「OAuth で接続」（推奨・別タブで承認するコードグラント）か「アプリトークンで接続」（Atlassian メール＋API トークン）。

OAuth（デバイスフロー）は、表示された**コードをコピー**して**リンクを開いて貼り付け**、
**承認を待つ**、の 3 ステップです。接続済みになると、あなたのハンドルとメールが表示されます。

テナントが GitHub を **GitHub App** で接続している場合は、カードにそう出ます。この接続が届くのは
アプリをインストールしたリポジトリだけです。接続の前でも後でもよいので、
**「アプリをインストール / リポジトリを選ぶ」** から自分のアカウントや organization に
インストールしてリポジトリを選んでください。あとから足したり変えたりするのも同じリンクです。

**「OAuth で接続」が出ていない**ときは、そのプロバイダの OAuth アプリがテナントにありません
（GitHub なら、テナント管理者が「なし」を選んでいます）。テナント側の設定なので自分では有効にできません。テナント管理者に
**テナント設定 → 連携 → 連携アプリの OAuth** での登録を依頼してください。その間は
トークン貼付で接続できます（機能が劣るわけではありません）。

git の認証は接続後、すべての git 操作に**透過的に使われます**。クローンや push のたびに
トークンを聞かれることはありません。

## リポジトリをクローンする

左ペイン **リポジトリ** の **「追加」** を開き、**種類**で **Git** を選びます。取得元は2つです。

- **接続から選ぶ**（既定）：接続済みの GitHub / Bitbucket からリポジトリとブランチを選びます。private リポジトリには 🔒 が付きます。未接続のプロバイダのタブは選べず、「未接続（設定 → Git）」と出ます。
- **URL 手入力**：「クローン URL」（`https://…`／`git@…`）と「ブランチ（任意）」を入れます。接続していないリポジトリ向けです。

**「新規ブランチ（任意）」** を指定すると、基点ブランチから新しいブランチを作って
切り替えます。このとき **「フォルダ名」** で作業コピーのフォルダも分けられます。
最後に **「クローン」** で取得します。

## 取り込み元が無いところから始める（新規フォルダ）

まだどこにも無いものを作り始めるときは、クローンする相手がありません。この場合は
**「追加」→ 種類「新規フォルダ」** で、`~/repos` の下に空のフォルダを作れます。
**「＋はじめる」→「新しいフォルダで始める…」** からも同じことができ、こちらは作成後
そのまま **作業を始める** ダイアログに続きます。

- フォルダは作ると同時に **git init** まで済みます。だから左ペインの行になり、変更の確認・
  コミット・共有・削除といった普段どおりの操作がそのまま使えます。**リモートは後から**
  端末で `git remote add` すれば繋がります（内部 Git で受け皿を作るのも手です）。
- **最初のコミットができるまでは、新しい作業コピー（worktree）は作れません**。git が
  まだ HEAD を解決できないためです。この間の起動は「このフォルダで直接」だけになります
  （起動ダイアログにその旨が出ます）。1 度コミットすれば、以後は普通のリポジトリと同じです。
- 名前は英数字始まりで、既にある作業コピーと重複しないものにしてください。

### submodule と Git LFS

- **submodule**：クローン後・作業コピー（worktree）の作成後にベストエフォートで取得します。SSH 登録の submodule は自動で HTTPS に読み替えて取得します（失敗しても親のクローンは成功します）。
  - 作業コピーごとに submodule はクローンし直されるため、**大きな submodule は起動時間内に取得しきれないことがあります**。その場合も作業は始められます（取得は裏で続きます）。未取得のまま始まったときは通知センターに「submodule が未取得のまま作業を開始しました」が出て、取得が終わると「取得が完了しました」が続きます。通知をクリックすると、その作業コピーのソース管理ビュー（submodule の取得状態が並びます）が開きます。
  - 取得が途中で切れた submodule は次の起動時に自動で修復されます。急ぐときは端末でその作業コピーに入り、`git submodule update --init --recursive` を実行してください。
- **Git LFS**：クローン／checkout 時に自動で実体を取得します（smudge）。既にある作業コピーでポインタのままのファイルは、ビュアーに「LFS ポインタ」バッジが出ます。この場合は端末でそのリポジトリに入り、`git lfs pull` で実体を取得してください。

## 内蔵の git プロバイダ（内部 Git）

外部のホスティングを使わずに、**フリート内でリポジトリを持つ**こともできます。
**⚙設定 → 「内部リポジトリ」タブ**で、名前を入れて **「作成」**
するだけです。外部アカウント不要で、テナント内のメンバーとクローン／push を共有できます
（認証は自動注入されるトークンで透過）。行からクローン URL をコピーしたり、中身を「参照」
（クローン不要のブラウズ）したりできます。試作やチーム内共有に向きます。

- 作成した名前は**リネーム**でき、不要になれば**削除**できます（削除は取り消せません）。
  どちらも**作成した人かテナント管理者**だけができ、それ以外の行にはこの 2 つのボタンが出ません。
- このタブは control plane が直接扱うため、**ワークスペースが停止中でも操作できます**。
- 外部に出せないコードの置き場としても使えます。クローンは他のリポジトリと同じく
  「はじめる」→「新しいリポジトリをクローン…」から、コピーした URL を貼って行います。

## リポジトリの行からセッションを起動する

クローンしたリポジトリは **リポジトリ** に並びます。行の **「起動」** ボタンで
**「作業を始める」** 画面が開き、エージェント・モデル・**場所**・最初のプロンプトを
選んで起動できます。**場所**は既定が **「新しい worktree」**（隔離・ブランチ切替から安全）、
もう一方が **「このコピーで直接」** です。

- **新しい worktree**（既定）：そのタスク専用の独立した作業コピーを切り出します。他のセッションと編集がぶつからないので、並行作業はこちらが安全です（基点ブランチとブランチ名を選べます。空なら暫定名 `temp/…`）。
- **このコピーで直接**：今開いているフォルダでそのまま作業します。

「起動」右の **▾** からは、設定画面を開かず種別（claude / codex / cursor / copilot / kiro / agy / opencode / lcpp / muse / shell）を選んで
**即起動**できます（Ctrl / 中クリックで新しいペインに起動）。

行には状態表示も出ます。読み方を覚えておくと、push 前に気づけます。

- **未コミット**：コミットしていない変更があります。
- worktree のバッジの「親」は、親 working copy のブランチの upstream（たとえば `origin/develop`）です。GitHub で PR をマージすると、親 working copy を fast-forward しなくても次の fetch（自動で 10 分ごと）で反映されます。upstream が無いときは親 working copy の HEAD と比べます。比較先はバッジのツールチップに出ます。親 working copy にある未 push のコミットは比較に入らず、「〜を Fast-Forward で取り込む」でも取り込まれません（比較先に入るのは push 後です）。
- worktree の **親=**：親と同じコミットです。
- worktree の **未取込 N**：親にまだ含まれない固有コミットが N 件あります。
- worktree の **親+N・FF可**：worktree の HEAD は親に含まれていて、**親のほうが N コミット進んでいます**。右クリックの **「origin/develop を Fast-Forward で取り込む」**（upstream が無いときは「親を Fast-Forward で取り込む」）で、親に入った変更をこの worktree へそのまま取り込めます（マージコミットは作られません）。
- worktree の **分岐 N↕M・FF不可**：worktree と親の両方に固有コミットがあり、マージかリベースが必要です。
- worktree の **比較不可**：detached HEAD やコミットのないリポジトリなどで関係を判定できません。
- **↑N**（先行）— origin より N コミット進んでいます（未 push）。
- **↓N FF可**：origin が N コミット進んでいて、そのまま fast-forward できます（コミットグラフの Fast-Forward）。
- **↑N ↓N 要マージ**：origin と分岐しています。fast-forward できず、マージかリベースが必要です。

worktree の状態表示は親の作業コピーにある現在のブランチとの比較、`↑` / `↓` は origin との比較です。
比較先や双方の固有コミット数は状態表示にマウスを重ねると確認できます。squash merge はコミットの
祖先関係を残さないため、ホスティングサービス上でマージ済みでも **取込済** にならないことがあります。

行末の `●N` は稼働中のセッション数、数字だけのバッジは停止中のセッション数です。リポジトリを
折りたたんでいるときは、配下の worktree のセッションも含みます。色付きの数字は、そのリポジトリの
コミットグラフを表示しているペイン番号です。詳しくは
[アイコン・バッジ・メニュー](badges-and-menus.ja.md)を参照してください。

### 最初のプロンプトのテンプレート

最初のプロンプト欄の上の **「テンプレート」** ボタンで、検索できる一覧が開きます。中身は 3 種類です。

- **マイテンプレート**：自分用のテンプレート。**「新しいテンプレート」** で作ります（名前・プロンプト・
  表示する場所＝すべてのリポジトリ／このリポジトリだけ）。選んで **「編集」** で内容や名前を変え、
  **「削除」** で消せます。
- **このリポジトリ**：リポジトリにコミットされた `.agent-fleet/launch-prompts.md` の項目（`## 見出し`
  ごとに 1 件）。クローンした全員で共有され、ここでは読むだけです。
- **履歴**：このリポジトリで最近起動したときの最初のプロンプト（最大 8 件）。1 行目で表示されます。
  **「削除」** で忘れさせ、**「テンプレートとして保存」** で自分のテンプレートにできます。

文字を打つと絞り込み、**↑ / ↓** で選択、**Enter** で挿入、**Esc** で閉じます。選んでいる項目の全文は
一覧の横のプレビューに出ます（スマホでは 1 回目のタップでプレビュー、**「挿入」** で挿入）。
`{{repo}}`・`{{branch}}`・`{{path}}` は起動した行の値に置き換わります。最初のプロンプトに入力済みの
文章があるときは **「カーソル位置に挿入」** か **「全体を置き換え」** かを確認するので、打った文章が
気づかないうちに消えることはありません。

自分のテンプレートと履歴は設定と一緒に保存され、別のブラウザや端末でも同じものが出ます。容量には上限
があります（テンプレートは 40 件・全体で 16 KB・1 件 8 KB まで）。3 KB を超えるプロンプト（または同期される設定全体を
上限の 64 KB を超えさせるもの）は、その端末の履歴にだけ残ります。リポジトリの `.claude` のコマンドやスキルを呼び出すときは、「テンプレート」の隣の
スキルボタン（**/**）を使ってください（この一覧には出なくなりました）。

### 右クリックでできること

リポジトリまたは worktree の行を右クリックすると、次の操作が表示されます。状態や場所によって
表示されない項目もあります。

- **コミットグラフを開く**／**フォルダを開く**／**変更をコミット**
- **ブランチ切替**／**ブランチ名をコピー**／**Fast-Forward**（worktree では **「origin/develop を Fast-Forward で取り込む」** など）
- **Git Flow を初期化…**（git リポジトリの元の作業コピーのみ）— [後述](#git-flow-を初期化)
- **プロジェクト設定**：そのリポジトリにコミットされている MCP の定義を、エージェント別の効き方と警告つきで確認します（[20](20-settings.ja.md#mcp-サーバー)）
- **共有する…**：この作業コピー（プロジェクト）のセッションを他のメンバーへ共有します（[12](12-collaboration.ja.md#会話を共有する共有セッション)）
- **作業グループへの割り当て**（[11](11-many-sessions.ja.md#作業グループで表示を絞る)）
- claude、codex、opencode、shell など種類別のセッション起動
- **配下のセッションを停止**：その作業コピーと、その下にぶら下がる作業コピーで動いているセッションを 1 つのモーダルからまとめて止めます（[05](05-stopping-and-tidying.ja.md#セッションを止める片付ける)）
- **作業コピーを削除**（削除できる作業コピーのみ）

### Git Flow を初期化

git-flow は設定を `.git/config` に置き、これはクローンでは写りません。そのため git-flow で運用して
いるリポジトリでも、Agent Fleet が作ったコピーには普通は何も宣言がありません。**Git Flow を初期化…**
は `git flow init` が書くのと同じ設定を書き込み、課題から作る新しいブランチが開発ブランチから
git-flow の接頭辞で始まるようにします。

- **入力欄:** 本番ブランチ、開発ブランチ、feature／release／hotfix の接頭辞、バージョンタグの接頭辞、
  任意の bugfix の接頭辞。すでにある設定、何かを宣言しているときの Bitbucket のブランチ設定、
  `develop`・`main`・`master` のどれがあるかから、最初の値が入ります。
- **書くもの:** `gitflow.branch.*` と `gitflow.prefix.*` のキーを、元の作業コピーの git 設定へ。
  `support/` は未設定のときだけ足し、bugfix の接頭辞を空にするとその設定は今のまま残ります。
  コミットもチェックアウトもしません。
- **共有:** このリポジトリのすべてのワークツリーとセッションが、この設定を同時に読みます。
  すでにあって値が変わる設定は保存の前に一覧され、ボタンは **上書きする** になります。ダイアログを
  開いている間に誰かが設定を変えた場合は、保存を断ってダイアログが読み直します。
- 本番ブランチか開発ブランチがローカルにも `origin` にもないときは **断ります**。
- **origin にだけあるとき:** `git flow` コマンドと Fork は本番ブランチと開発ブランチをローカルに必要と
  するので、保存すると `origin` のブランチを追跡するローカルブランチを作ります
  （`git branch --track develop origin/develop` と同じ）。ダイアログの欄の下にそう出て、保存後の
  メッセージが作ったブランチを示します。チェックアウトはせず、すでにあるローカルブランチは `origin` と
  違っていても動かしません。ブランチは作れたのに追跡の設定ができなかったときは、もう一度保存しても
  直りません。ダイアログが実行すべき `git branch --set-upstream-to=…` を示します。
- コミットされた `.agent-fleet/branches` や `.gitflow` は、重なる項目ではこの設定より優先されます。
  ダイアログにもそう出ます。
- `origin` に `develop` があって何も宣言していないリポジトリで課題から作業を始めると、起動ダイアログ
  が **Git Flow を初期化…** を勧めます。自分から初期化することはありません。

## コミットグラフビューでコミットする

リポジトリ行を通常クリックすると、配下のセッションや worktree を展開／折りたたみます。
**コミットグラフ**ビューは右クリックの「コミットグラフを開く」から開きます。
Ctrl／⌘+クリックまたは中クリックなら、新しいペインに直接開けます。ヘッダには現在の
ブランチと操作ボタンが並び、狭いときは **⋯** に畳まれます。

- **変更**：変更をコミットする作業画面（別ペイン）を開きます。
- **fetch**：リモートを取得します（`git fetch --prune`）。
- **Fast-Forward**：現在のブランチを upstream に fast-forward します（`pull --ff-only`）。
- **更新**：表示を最新化します。
- ブランチ名の部分をクリックすると **「ブランチ切替」**（フィルタ付き・最新コミット順）です。
- `.gitmodules` がある場合はヘッダの対象選択に **submodule** が並びます。取得済みの
  submodule を選ぶと、その submodule 自身のコミットグラフとコミット詳細を閲覧できます。
  未取得の submodule も「未取得」と表示されますが、初期化されるまで選択できません。

### 変更 → stage → コミット

「変更」を開くと、変更ファイルの一覧が出ます（`{リポジトリ名} — 変更`）。

- 各行の **stage** / **unstage** ボタンで対象を出し入れします。追跡中ファイルは**変更を破棄**もできます（「元に戻せません。」の確認あり）。
- 下の **コミットメッセージ**欄に書き、必要なら **「追跡中を全て stage (-a)」** にチェックして **「Commit」** します。メッセージが空だと「コミットメッセージが必要です」と出ます。
- コミット作者（identity）はこの画面から上書きできます。解決順は「リポ上書き ＞ プロバイダ ＞ グローバル既定」です（⚙設定 → 「Git ホスティング」でも設定できます）。

### 履歴と diff

コミットグラフの行をクリックすると、その**コミットの詳細**（変更ファイルと diff）が開きます。
diff はファイルごとに折り畳め、「全て開く」「全て閉じる」「折り返し」で見え方を調整できます。
グラフ上のコミットを右クリックすると、「詳細を表示」「ブランチ切替」「このコミットから
新規ブランチ…」などが選べます。

## push と認証

push は git の通常操作としてそのまま行えます（端末やエージェントから `git push`）。
接続済みなら**認証は自動で透過**するので、トークンの入力は不要です。Bitbucket の
トークンは失効しても自動更新されます。

> コミットしていない変更、push していないブランチは**ワークスペースの中だけ**にあります。
> 長く残したい作業はこまめに push しておきましょう（[01 初日](01-first-day.ja.md)）。

## Subversion（SVN）リポジトリ

git だけでなく **SVN** のリポジトリでも作業できます。クローンモーダルの **Git / SVN
切替**で SVN を選び、**リポジトリ URL** と、必要なら**サブパス**（例: `trunk`、
`branches/x`）・**ユーザー名 / パスワード**（基本認証）を入れてチェックアウトします。

- **特定 path だけ / 複数 path**：サブパスでサブツリーだけをチェックアウトできます。
  別の path をもう一度チェックアウトすれば別フォルダになり、git のクローン分離と同じ
  隔離になります。SVN には worktree が無いため、**並行作業はこの方法で分けます**
  （svn 行からのセッション起動は**その場起動のみ**で、worktree の選択肢は出ません）。
- **認証情報の保存（任意）**：保存にチェックすると暗号化ストアへ保存され、以後の
  「更新」で自動的に再利用されます。パスワードはプロセス一覧にも平文キャッシュにも
  残りません。
- **後から入れる**：保存しなかった場合でも、チェックアウトし直す必要はありません。行メニューの
  「**再認証（svn）**」から入れられます（認証で「更新」が失敗したときは自動で出ます）。入力内容は
  保存前にサーバへ当てて確認します。保存済みのサーバは **設定 › 接続 › Git ホスティング** に一覧され、
  そこから追加・削除もできます。
- **自己署名証明書**：社内サーバなどで証明書が信頼できない場合は、モーダルの
  「自己署名証明書を信頼」をオンにします。**そのサーバの証明書検証を無効化する**
  サーバ単位の opt-in で、以後の更新でも維持されます。
- **更新とロック解除**：svn 行の「更新（svn）」で最新リビジョンへ。中断などで作業コピーが
  ロックされた（`svn cleanup` を促すエラーになる）ときは、チェックアウト / 更新が
  自動で 1 回リカバリを試みます。残る場合は行メニューの **「ロックを解除（svn）」** を
  使ってください。
- **ログと手元の変更**：svn 行のメニューに **「ログを表示」**（リビジョンの一覧。新しい順で、
  パスでの絞り込みと「さらに読み込む」があります。作業コピーより新しいリビジョンには「未更新」と
  出て、選ぶと変更されたパスと差分が見られます）と **「ローカルの変更」**（`svn status` の
  一覧。クリックでそのファイルの差分）があります。Files ツリーで作業コピー内のフォルダやファイルを
  右クリックして **「ログを表示」** を選ぶと、そのパスで絞り込んだログが開きます。ログはサーバから、
  開いたときと「さらに読み込む」を押したときにだけ読みます（裏で更新し続けることはありません）。
  サーバがパスワードを求めたときは再認証ダイアログが出ます。どちらのビューも読み取り専用です。
- svn 行には現在のリビジョン（`r1234`）が表示されます。ブランチ切替・stage / コミットの作業台は
  git 専用なので、コミットはセッション内で `svn commit`
  を使います。**保存済みの認証情報はセッション内の `svn` にも効く**ので、`svn update` や
  `svn commit -m "…"` に `--username` は要りません。自分でパスワードを聞かれるのは 2 つの場合
  だけです: `-m` を付けない `commit`（svn がエディタを開くので端末を渡します）と、
  `--username` / `--password` を明示したコマンド（明示指定が常に優先されます）。
