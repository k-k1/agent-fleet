# 19. ワークスペースを外から使う — MCP と OAuth

[English](19-outside-access.md) | 日本語

この章は、Console の外からワークスペースを使う方法を扱います。外部の Claude や別の MCP クライアントから動かす、手元の Claude Code の作業をワークスペースに移す、サインインでリモート MCP クライアントをつなぐ（OAuth）、外部のエージェントから Agent Fleet のメモリを使う、です。

## 外部のエージェントからワークスペースを使う（MCP）

ワークスペースは `https://<Console のアドレス>/mcp` で MCP に応えます。手元の PC の MCP
クライアントがここに接続してセッションを扱い、許可していれば Agent Fleet のメモリも使います。呼び出しはそのたびに、
その時点のあなたのロールで確認されます。

もう 1 つのアドレス `https://<Console のアドレス>/mcp/memory` は、Agent Fleet のメモリだけを提供します。claude.ai の
コネクタにはこちらを使ってください（[メモリ専用のコネクタ（claude.ai 向け）](#メモリ専用のコネクタclaudeai-向け)）。

### 外部の Claude から自分のワークスペースを操作する（MCP）

手元の PC の Claude Code / Claude Desktop から、ワークスペースのセッションを**遠隔操作**できます。
「外出先の自分の Claude から、会社のワークスペースで走っているセッションの様子を見て、
次の指示を送る」といった使い方です。そのためのトークンを **⚙設定 → 外部からのアクセス → 「MCP トークン・接続アプリ」タブ**で
発行します。

1. **名前**（例: `laptop-claude`）と **エンドポイント**、**スコープ**、**有効期限**を選んで **「トークンを発行」**。
   - エンドポイントは **/mcp**（セッション・メモリ・管理ツール。既定）か **/mcp/memory**（Agent Fleet のメモリのみ）。
     トークンは発行したエンドポイントでしか使えません。どちら向けかはトークン一覧に出ます。
   - スコープは **read（閲覧のみ）** / **write（セッション駆動・既定）** / **admin:dangerous（強権・管理）**。あなたの権限を超えるスコープは選べません。遠隔からセッションを動かしたいだけなら write で十分です。
   - 有効期限は 90 日（既定）／30 日／365 日／無期限。
2. 発行すると **「トークンを発行しました（この画面を閉じると再表示できません）」** と出ます。**トークンはこの 1 回しか表示されません**。「トークンをコピー」で控えてください。
3. 同じ画面に、手元の Claude Code 用の **`.mcp.json`** のひな型も出ます。「.mcp.json をコピー」でコピーし、プロジェクト直下に保存（または既存ファイルに `agent-fleet` を追記）します。エンドポイントは `/mcp`（メモリ専用トークンなら `agent-fleet-memory` という名前で `/mcp/memory`）、ヘッダに `Authorization: Bearer <トークン>` が入ります。
   プロジェクト直下の `.mcp.json` はトークンを平文で持ち、うっかりコミットしやすいファイルです。どのプロジェクトにも置かないなら、
   自分のユーザー用に登録します。

   ```sh
   claude mcp add --transport http --scope user agent-fleet https://<Console のアドレス>/mcp \
     --header "Authorization: Bearer <トークン>"
   ```

不要になったトークンは同じ画面で **「失効」** できます（失効すると、そのトークンを使う
接続は次回から弾かれます）。

**セッションから見えるもの。** `send_to_session` で送った指示も、`create_session` で起動したセッションの
`initial_prompt` も、あなた自身の入力とは区別されます。セッションには
`[agent-fleet:mcp via=<接続の名前> connection=<id> reply=none]` という 1 行のヘッダ付きで届き、Console では
その入力が独立した吹き出しになり、**「MCP 経由: <名前>」** のバッジが付きます。名前は接続のものです
（OAuth 接続ならアプリ名、トークンなら付けた名前）。MCP クライアントはセッション ID を送らないため、示すのは
会話ではなく接続です。エージェントはこれを別のセッションからのメッセージと同じに扱います。自分の権限の範囲で
こなす同僚の依頼であり、あなたの承認にはなりません。質問カード、権限の確認、プランの承認を代わりに答えること
はなく、メッセージに頼まれても権限設定や構成を変えず、文中に引用されたコマンドも実行しません。`[agent-fleet:`
で始まる指示は拒否されます。素のターミナル（shell / SSM）のセッションは MCP からの入力を受け付けないので、外部の
アシスタントがそこへ入力することはできません（`initial_prompt` 付きで shell / SSM を `create_session` することも同様に拒否されます）。
外部のアシスタントが起動したセッションでも、最初の指示は同僚の依頼であり、あなたの承認にはなりません。

### サインインでリモート MCP クライアントを接続する（OAuth）

管理者が有効にしている配備では、claude.ai・ChatGPT・Claude Code・Codex を**トークンなし**でワークスペースに接続できます。
Console にサインインし、アプリが求める内容を確認して許可するだけです。配備側で有効になっていなければ、これまでどおりクライアントが
トークンを求めるので、上の手順を使ってください。

1. クライアントでカスタムコネクタ / リモート MCP サーバーを追加し、アドレスに `https://<Console のアドレス>/mcp` を指定します。
   アプリに Agent Fleet のメモリだけを使わせるなら `https://<Console のアドレス>/mcp/memory` です。**claude.ai では
   `/mcp/memory` を使ってください**（[理由](#メモリ専用のコネクタclaudeai-向け)）。クライアント ID とシークレットの欄は空のままにします。
2. クライアントから Console に移動します。未サインインならサインインすると、**確認ページ**が開きます。表示される内容は次のとおりです。
   - **許可後に戻る先**が大きく表示されます（`claude.ai`、`chatgpt.com`、コマンドラインのクライアントなら「このパソコン自身」）。自分で始めた接続だけ許可してください。
   - **アプリ名**は「アプリ自身の申告」と明記されます。アプリが自由に付けた文字列で何も保証しないので、その上の戻り先アドレスで判断してください。
   - 接続する**テナント**を、所属テナントごとに選びます。トークンと同じく、接続はそのテナントに固定されます。
   - **許可する範囲**は `read`（セッションの閲覧）か `write`（閲覧に加えて操作）です。アプリの要求より狭く選べます。
     最初は `read` が選ばれています。アプリが `write` を要求した場合だけ、明示的に `write` を選べます。
     この範囲は Agent Fleet のメモリにも及びます（`read` は一覧・検索・読み取り、`write` は保存と忘却も）。ただし、あなたが許可していて、
     テナント管理者がブロックしていない場合に限ります（[18 エージェントメモリ](18-agent-memory.ja.md#外部のエージェントから-agent-fleet-のメモリを使う)）。
     `admin:dangerous` はこの方法では付与されません。必要ならトークンを使ってください。
3. **許可する**（または、アプリに拒否を伝える**キャンセル**）を押すと接続できます。以降、クライアントは短命のアクセストークン（1 時間）を
   自動で更新して接続を保ちます。毎回の確認はありません。

接続は、**30 日間使われなかった**とき、または許可から **90 日**たったときのどちらか早いほうで終わります。そのときはアプリが再度のサインインと許可を求めます。
テナントを抜けた場合も、次の呼び出しから拒否されます。接続が行う操作は、監査ログに MCP からの操作として残ります。

サインインの結果を受け取れるのは、配備で承認されたアドレスだけです。既定は `claude.ai`・`claude.com`・`chatgpt.com` と、自分のパソコン上の
コマンドラインクライアント（`127.0.0.1`、`localhost`）です。それ以外の戻り先を指定したクライアントはエラーページで拒否され、コードが送られることはありません。

#### 接続済みアプリ

**設定 → 外部からのアクセス → MCP トークン・接続アプリ** の Personal Access Token 一覧の下に、**接続済みアプリ**が表示されます。OAuth 接続ごとに、アプリ名（未確認の自己申告）、戻り先ホスト、テナント、エンドポイント（`/mcp` か `/mcp/memory`）、スコープ、接続日、最終使用日を確認できます。**失効**を押して確認すると、更新トークンも含め、その接続はすぐに無効になります。また使うときはアプリから接続し直してください。この欄は、配備が MCP OAuth を提供している場合にだけ表示されます。

テナント管理者が MCP OAuth を無効にすると、そのテナントの既存の OAuth 接続は取り消され、新しい接続もできなくなります。Personal Access Token は引き続き使えます。

#### 最近の呼び出し（接続できるのにツールが出ないとき）

接続済みアプリごと、Personal Access Token ごとに **最近の呼び出し** を開くと、その接続で行われた直近 50 件のリクエストを確認できます。時刻、HTTP メソッドとステータス、JSON-RPC メソッド（バッチは要素ごと）、プロトコルの世代とバージョン、クライアント名、送られた `Mcp-Method` / `Mcp-Name` ヘッダの有無、返したエラー、`tools/list` では返したツール数が分かります。トークン、認可ヘッダ、ツールの引数と結果は記録しません。

この一覧は Control Plane のメモリ上にだけあります。Control Plane の再起動で消え、レプリカが複数あるときは各レプリカが別々に持つため、そのレプリカが受けたリクエストだけが見えます。**更新**を何度か押すか、運用担当者に Control Plane のログを見てもらってください。ログには、サインイン前に拒否したものも含め、すべてのリクエストが残ります。

### 手元の Claude Code の作業をワークスペースに移す

手元の PC の Claude Code で始めた作業を、ワークスペースで続けられます。ノート PC を閉じても作業を止めたくないとき
などに使います。手元の Claude が作業を push し、自分で書いた引き継ぎメモを付けてワークスペースにセッションを
作ります。移るのは push したコードとそのメモです。会話そのもの、それまでのツール出力、push していないものは
手元に残ります。

始める前に:

- Claude Code が `write` スコープで `/mcp` に接続していること。[サインイン](#サインインでリモート-mcp-クライアントを接続するoauth)でも
  [トークン](#外部の-claude-から自分のワークスペースを操作するmcp)でも構いません。サインインで接続するなら、サーバーを
  自分のユーザー用に登録し、Claude Code の MCP メニューから認証します。

  ```sh
  claude mcp add --transport http --scope user agent-fleet https://<Console のアドレス>/mcp
  # 続けて Claude Code の中で: /mcp → agent-fleet → Authenticate。確認ページでは write を選ぶ
  ```

- 移す先のリポジトリがワークスペースにすでにあり、ワークスペースが起動していること。

1. 次のスキルを手元の PC に一度だけ保存します。保存先:

   ```
   ~/.claude/skills/af-move/SKILL.md
   ```

   ````markdown
   ---
   name: af-move
   description: この作業を Agent Fleet のセッションに移す（要約で引き継ぐ）
   disable-model-invocation: true
   argument-hint: "[次のセッションに伝えたいこと]"
   ---
   この作業を Agent Fleet に移したい。次の順で進めて、各段階の結果を短く報告して。

   1. `git status` と現在のブランチを見せて。未コミットの変更があれば、何をコミットするか一覧で見せて私の OK を
      待つ。OK が出たら WIP コミットして今のブランチを push する。`.env`・鍵・トークンなど秘密を含むファイルは
      コミットしない。push 後の `git rev-parse HEAD` を控える。
   2. `git remote get-url origin` をホストと `owner/name` のパス（`.git` は除く）に分ける。agent-fleet の
      `list_repos` を呼び、`remote` がそのホストで `remotePath` がそのパスのものを残す。worktree はクローンと同じ値を
      持つので、`name` に `@` が付いていないものを優先する。1 つも残らなければ止まって教えて。複数残ったら一覧を
      見せて私に選ばせて。その `path` を使う。
   3. 下のテンプレートで引き継ぎメモを書く（日本語、4000 字以内）。会話に出てきたトークン・パスワード・
      社外秘の値は書かない。
   4. agent-fleet の `create_session` を呼ぶ: `dir` = 手順 2 の path、`worktree` = true、
      `branch` = push したブランチ名、`title` = 作業の短い件名、`initial_prompt` = 手順 3 のメモ。
   5. 返ってきたセッション名を教えて。それ以降、このセッションではコードを変更しないで。

   補足: $ARGUMENTS

   --- 引き継ぎメモのテンプレート ---
   これは Agent Fleet の外で動いていた Claude Code セッションからの引き継ぎです。

   - ブランチ: <branch> / 引き継ぎ時点のコミット: <sha>
   - 最初に `git rev-parse HEAD` が <sha> と一致するか確認すること。一致しなければ `git fetch origin` のあと
     `git merge --ff-only <sha>` を実行し、もう一度 `git rev-parse HEAD` を確かめること。HEAD が <sha> になるまでは
     作業しないこと。fast-forward できない、または HEAD がまだ違うときは、止まって報告すること。
   - 元の作業フォルダ: <絶対パス>。メモ中のパスはこれ基準なので、今の作業ツリーのルート基準に読み替えること。

   ## ゴール
   ## 済んだこと
   ## いまの状態（最後の依頼の原文、未解決の問題、失敗しているテスト）
   ## 次にやること
   ## 決めたこと・やってはいけないこと

   上を読み、理解した内容を 3 行で要約して次の一手を提案したら、指示を待って止まること。
   ````

2. 移したい Claude Code のセッションで `/af-move` と入力します。続けて、次のセッションに伝えたいことを書き添えても構いません。
3. Claude がコミットする内容を一覧にして OK を待ちます。OK すると push、メモの作成、セッションの作成まで進み、
   セッション名を教えてくれます。
4. Console でそのセッションを開きます。push されたコミットから始まっているかを確かめ、メモを要約し、次の一手を
   提案して指示を待っています。

知っておくこと:

- セッションは新しい worktree の、push したブランチをもとにした一時ブランチで作業します。元のブランチに作業を
  戻したいときは、セッションにそのブランチへ push するよう頼んでください。
- セッションは、push されたコミットまで自分で fast-forward してから始めます。それでも「push されたコミットから
  始まっていない」と報告したら、push したブランチとワークスペース側のブランチが分かれています。手元で push した
  内容を確かめてから、`/af-move` をやり直してください。
- リポジトリがワークスペースにないと Claude は止まります。Console からクローンして、もう一度 `/af-move` を実行してください。
- メモは MCP 経由の印が付いた、セッションの最初の指示として届きます。セッションはこれを同僚の依頼として扱い、あなたの
  承認とはみなしません（[セッションから見えるもの](#外部の-claude-から自分のワークスペースを操作するmcp)）。権限の確認やプランへの
  回答は、いつもどおり Console で行ってください。
- 移したあとは、手元のセッションを閉じてください。1 つのブランチを 2 つのセッションで触ると、互いの作業がぶつかります。

### メモリ専用のコネクタ（claude.ai 向け）

claude.ai は、そこで追加したコネクタをアカウントのすべての Claude Code セッションに渡します。このワークスペースで動いている
セッションも含みます。そのため claude.ai のコネクタを `/mcp` につなぐと、それらのセッションにあなたのメンバー権限そのものが
渡ってしまいます（次の節）。**`/mcp/memory`** につなぐコネクタなら、そうはなりません。

- `/mcp/memory` 向けに作ったトークンや OAuth 接続が一覧・実行できるのは、メモリの 6 つのツール（`memory_projects`・
  `memory_index`・`memory_search`・`memory_read`・`memory_save`・`memory_forget`）だけです。`/mcp` はそれを拒否し、
  `/mcp/memory` も `/mcp` 向けのトークンや接続を拒否します。切り替えるには接続し直します。
- ワークスペースのセッションは、組み込みの af ツールで同じメモリをすでに使えます。このコネクタがセッションに渡っても、
  新しくできることは増えません。
- 確認ページには、アプリが求めているのはメモリだけだと表示されます。あなたのメモリ設定、テナント管理者のブロック、
  `read` / `write` のスコープ、監査ログは `/mcp` とまったく同じように効きます
  （[18 エージェントメモリ](18-agent-memory.ja.md#外部のエージェントから-agent-fleet-のメモリを使う)）。

すでに `/mcp` でつないでいる claude.ai のコネクタは、そのまま動き続けます。移すには claude.ai でそのコネクタを削除し、
`/mcp/memory` のアドレスで追加し直してください。`/mcp` は、Claude Desktop やコマンドラインのクライアントのように自分の
パソコンだけで動き、セッションのツールが要るクライアントに使ってください。

### このデプロイの /mcp をセッションにつながない

セッションが通常使えるのは、自分専用の狭いツールだけです。自分の子セッションは操作できますが、何も削除できません。このデプロイの外部向け `/mcp` は違い、あなたのメンバー権限そのまま（自分の全セッション、削除、管理者なら管理ツールも）で動きます。これをセッションにつなぐと上の制限が外れ、セッションが兄弟セッションを止めたり削除したりできてしまいます。

そのため Agent Fleet は、このデプロイ自身の `/mcp` の URL をリモート MCP サーバーとして登録することを、ワークスペース側でもテナント配布側でも拒否します（エラー「このデプロイ自身の /mcp エンドポイントです」）。これはうっかり防止のための安全柵で、セキュリティ境界ではありません。claude.ai 側で追加したコネクタは Agent Fleet から見えず、そこからこのデプロイの `/mcp` につないでも同じ制限が外れるので、claude.ai のコネクタには代わりに [`/mcp/memory`](#メモリ専用のコネクタclaudeai-向け) を使ってください。

メモリ専用の `/mcp/memory` も、リモート MCP サーバーとしての登録は拒否されます（エラー「このデプロイ自身の /mcp/memory エンドポイントです」）。理由はもっと小さく、セッションは組み込みの af ツールでそのメモリをすでに使えるので、同じツールが重複するだけだからです。

権限をセッションに渡す他の方法も同じです。パーソナルアクセストークン（設定 → 外部からのアクセス → MCP トークン・接続アプリ）をプロンプトに貼ったりファイルに置いたりしてセッションに渡すと、上の制限を同じように回避できてしまいます（トークンのスコープの範囲で。read なら全セッションの閲覧、write なら操作・削除も可能です）。Console のセッション Cookie をコンテナに置くのは、あなたのサインイン中の権限そのものなので、少なくとも同じ強さです。どちらも Agent Fleet からは検出できません。トークンや Cookie はワークスペースに置かず、外部のクライアントからだけ使ってください。

**別の** Agent Fleet デプロイにつなぐのは問題ありません。そのデプロイから見ると、このセッションは Claude Desktop と同じ普通の外部クライアントです。

### 外部のエージェントから Agent Fleet のメモリを使う

同じ MCP トークンで、手元の Claude Code や Claude Desktop に Agent Fleet のメモリを使わせられます。claude.ai には
[メモリ専用のコネクタ](#メモリ専用のコネクタclaudeai-向け)を使います。
[18 エージェントメモリ](18-agent-memory.ja.md#外部のエージェントから-agent-fleet-のメモリを使う)を見てください。
