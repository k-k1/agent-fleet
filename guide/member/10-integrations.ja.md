# 10. 一歩進んだ使い方 — ブラウザペイン／軽量プレビュー・外部連携・環境設定

[English](10-integrations.md) | 日本語

必要になったところだけ読めば十分です。AWS・SSM ホスト・Google Cloud は
[15 クラウドのアカウント](15-cloud-accounts.ja.md)にあります。

## 立ち上げた Web を見る — ブラウザペインと軽量プレビュー

ワークスペース内で起動した Web サービス（各種 dev サーバー・Spring Boot・任意の Web アプリ）を、
**追加のポート公開もコンテナ作り直しも無し**でその場で確認できます。方式は 2 つあります。

ワークスペース操作バー右の**ポート入力欄**にポート番号を入れると、**「ペインで開く」**（ブラウザペイン）と
「**軽量プレビュー**」が選べます（どちらもワークスペースが稼働中のときだけ）。

- **ブラウザペイン（「ペインで開く」）**：ワークスペース内のブラウザが `127.0.0.1:{ポート}` を直接開き、
  その**描画と操作だけ**を Console のペインへ映します。クリック・スクロール・ASCII/日本語入力・戻る/進む・
  再読み込み・path 移動ができ、**HMR（ホットリロード）・WebSocket・SSE・cookie・リダイレクト・絶対パスの
  asset** がふつうの localhost と同じように動きます。画面を触って確かめたいときはこちらです。
- **軽量プレビュー**：そのポートを**新しいタブ**に開きます。**WebSocket / SSE は通ります**（HMR も
  アプリ側の設定次第で動きます）が、URL が `/preview/{ポート}/` という**サブパス**になるので、
  `/static/...` のような**絶対パス**を吐くアプリや、root path・cookie path に依存する画面は崩れます。
- **プレビュー用サブドメイン**：環境によっては、ワークスペースを起動するたびに
  `https://xxxxxxxx-3000.＜プレビュー用ドメイン＞/` のような **URL が自動で発行**されます。アプリが
  **ルート直下**に配られるので、上の「サブパスだと崩れる」問題がそもそも起きません。3000 と 8080 の
  ように**複数ポート**を同時に開けます（下の「プレビュー用サブドメイン」を参照）。

**迷ったら**: 発行済みの URL があるならそれが一番素直です。無ければ、画面を触って確かめたいときは
「ペインで開く」、HTTP 応答を一度見るだけなら「軽量プレビュー」。

> **ワークスペースを Kubernetes（プレビューのランタイム）または ECS Fargate で動かす配備には、ブラウザペインがありません。**「ペインで開く」は
> 押せない状態で表示され、そのツールチップと下のヒントが理由を示します。ワークスペースが動く制限付きの
> コンテナでは Chromium のサンドボックスが起動できず、配備はサンドボックス無しで Chromium を動かさないためです。
> セッション行のポートは代わりに軽量プレビューで開き、レイアウトに残っていたブラウザペインは理由と、
> 同じページを軽量プレビューで開くボタンを表示します。エージェントからブラウザのページを渡してもらう
> こともできません（次の節）。詳しくは [browser-pane.ja.md](../ref/browser-pane.ja.md#ブラウザペインが無い配備) を参照してください。

タブレットなどタッチ画面では、**スワイプでスクロール**（指を離した後は慣性で少し流れます）、**タップでクリック**、
**長押しでドラッグ**（テキスト選択・スライダー）、**2 本指のピンチで拡大縮小**ができます。ピンチは画像を
引き伸ばすのではなくページを縮んだ幅で描き直すので、文字は原寸で読めます。ピンチを戻せば元の表示に戻ります。
**ダブルタップ**は「幅に合わせる」表示と等倍（原寸）の行き来です。

タップでは**キーボードは出ません**（リンクやボタンを押すたびに出てしまうため）。ページの入力欄に
文字を打つときは、欄をタップしてからペイン左下の**キーボードボタン**で開いてください。開いている間は
ページをタップしても閉じません。

### 使い方

1. shell またはエージェントに開発サーバーを起動させます。サーバーはワークスペース内の `127.0.0.1`
   （または全 interface）で listen させます。
2. **デスクトップ／タブレット**のワークスペース操作バーで、ポート入力欄に `1..65535`（Agent 自身が使う
   `7700` を除く）のポート番号と、必要なら `/` で始まる path を入れます（host や外部 URL は入れません）。
3. 通常は **「ペインで開く」**、単純な HTTP 一回確認だけなら **「軽量プレビュー」** を選びます。

たとえば shell で API サーバーを 8080 で起動したら、ポート欄に `8080` を入れて「ペインで開く」を押せば、
そのアプリがペインに出ます。追加のポート開放を情シスに依頼する必要はありません。

### プレビュー用サブドメイン（発行されている環境のみ）

ワークスペースを**起動するたびに**、ランダムな文字列を含む URL が発行されます。

```
https://k7f2q9x1w3ub5nzt0abc-3000.pv.example.com/   → 3000 番（例: React / Next.js）
https://k7f2q9x1w3ub5nzt0abc-8080.pv.example.com/   → 8080 番（例: Spring Boot）
```

- **どこにあるか**：ワークスペース操作バーの「プレビュー」を開くと、**プレビュー用 URL（この起動ぶん）**
  としてポートごとに並びます。押すと新しいタブで開き、「コピー」で URL を取れます。
- **起動のたびに変わります。** 停止すると開けなくなります（前の URL は 404）。URL を貼った資料は
  すぐ古くなると思ってください。
- **既定ではサインインが必要です。** 初回は Console のサインインへ一度飛んでから戻ります。
- **公開できるポートは自分で決めます。** 既定は `3000, 8080`。設定 ›
  **プレビュー用サブドメイン** で増減できます。ここに無いポートの URL は**あなた以外には**開けません
  （次の項目を参照。意図せず立っている管理画面などを他の人に見せないための一覧です）。
- **一覧にないポートは、あなただけに開きます。** ワークスペースが待ち受けているが一覧にないポート
  （`5173` の Vite、`4000` の使い捨てサーバーなど）は、セッション行のポートチップ、またはプレビューのポップオーバーから、
  設定を変えずにサブドメインで開けます。プレビュー用 URL が発行されていればチップの単純クリックで開き、チップ横の `⋯`
  （右クリック・長押しでも）のメニューからブラウザペイン・サブドメイン・軽量プレビューを並べて選べます。この開き方は
  **あなただけ**のもので、公開モードやテナント共有の対象にもならず、そのサーバーが止まると閉じます。同じポートを後から別のプロセスが
  使っても、開き直すまでは届きません。この開き方はその起動の URL に属するので、ワークスペースの停止・再起動や
  「いま捨てて発行し直す」でも閉じます。この方法で開けるポートはワークスペースごとに最大 **16** 個です。超えると
  「一時的に開いているポートが多すぎます」と表示されるので、サーバーを止めるか、ポートを一覧に加えてください。
  ポートが素の HTTP で答えることが条件で（データベース・SSH・HTTPS 専用の開発サーバーは理由つきで断られます）、
  `AF_PREVIEW_URL_<ポート>` は設定されません。開発用 OIDC IdP も、このポートへのサインインのコールバックは受け付けません
  （[後述](#プレビュー-url-で-google-サインインを使う開発用-oidc-idp)）。アプリが自分の公開 URL を知る必要があるとき、
  その IdP でサインインするとき、他の人にも見せたいときは、メニューの **このポートを公開設定に追加…** で一覧に加えてください。

#### アプリ側で気をつけること

- **API の呼び先を `http://localhost:8080` と直書きしない。** ブラウザから見た `localhost` は
  **画面を見ている人の PC** です。dev サーバーの proxy（Vite の `server.proxy`、Next.js の
  `rewrites()`）で `/api` を 8080 へ流す書き方にすると、**手元の PC でもプレビューでも同じ設定のまま**
  動きます。
- **proxy の転送先（`destination` / `target`）は `http://127.0.0.1:8080` のままにしてください。**
  「フロントから 8080 が見えないのでは」と考えてここをプレビューの URL に書き換えると、
  **API が全部 401（`preview requires sign-in`）になります**。proxy はコンテナの中の dev サーバーが
  **サーバー側から**出す通信で、あなたのブラウザのサインイン状態を持っていないためです。
- どうしても 3000 の画面から 8080 を**直接**呼ぶ構成にするなら、設定の
  「**ポート間の呼び出しを許可する**」をオンにしてください（既定はオフ）。
- Spring Boot は `server.forward-headers-strategy=framework` を設定してください。
  Next.js の Server Actions もこの経路で正しく判定されます。
- **Next.js（15.2 以降・16 系も同じ）は `allowedDevOrigins` の設定が要ります。** dev サーバーは
  `/_next/*` への**別オリジンからのアクセスを既定でブロック**するので、プレビュー用サブドメインで
  開くと **レイアウトの枠だけ描画され、API から取るデータが出ません**（真っ白でもエラーでもないので
  アプリのバグに見えます）。dev サーバーのログに
  `⚠ Blocked cross-origin request to Next.js dev resource` が出ていたらこれです。
  **URL は起動のたびに変わるので、ワイルドカードで書いてください。**

  ```ts
  // next.config.ts
  allowedDevOrigins: ["127.0.0.1", "*.pv.example.com"],  // ドメインは AF_PREVIEW_DOMAIN
  ```
- コンテナの中には `AF_PREVIEW_URL_3000` / `AF_PREVIEW_URL_8080` / `AF_PREVIEW_DOMAIN` が入っています。
  `NEXTAUTH_URL` のように「自分の公開 URL」を環境変数から読むアプリは、これを渡してください。

#### 人に見せる（3 段階）

見せたい相手によって、使うものが違います。**下に行くほど広く開きます。**

1. **自分だけ**：何もしません（既定）。
2. **同じテナントの同僚**：設定 › プレビュー用サブドメイン の
   「**同じテナントのメンバーに見せる**」をオンにします。
   - 相手も **Console にサインインしたうえで**開きます（テナントの外の人には見えません）。
   - **停止・再起動してもオフには戻りません。** 見せ終わったら自分でオフにしてください。
   - 相手には **「共有」ボタンでコピーできるリンク**を渡してください。**こちらは起動を
     またいでも有効**です（生の `https://xxxx-3000.…` の URL は再起動のたびに 404 になります）。
   - 相手の Console では、プレビューのポップオーバーに **共有されているプレビュー**として
     並びます。**あなたのワークスペースが停止中は「停止中」と出て開けません**。相手が
     あなたのワークスペースを起動することはできないので、必要なら起動を頼んでください。
   - **相手が開いている間はワークスペースが自動停止しません。その稼働ぶんの費用は
     あなたに付きます。**（画面を開いて放置しているだけなら、やがて停止します。）
3. **テナントの外の人**：**サインインなしで公開する** をオンにすると、URL を知っていれば
   誰でも開けます。**停止・再起動すると必ずオフに戻ります**（URL も変わります）。
- **いま割り当てられている URL は、設定 › プレビュー用サブドメイン の
  「いまの URL」** に出ます。停止中は「未発行」と出ますが、**どのドメインを使うか**はその下に
  書いてあります。
- URL を渡す相手を間違えたら、「**いま捨てて発行し直す**」を押してください。今開いているタブも
  すぐ 404 になります。**停止中に押した場合は捨てるものが無いので何も起こりません**
  （次に起動すると、どのみち新しい URL になります）。

プレビュー URL で Google サインインを使うときは、後の [プレビュー URL で Google サインインを使う](#プレビュー-url-で-google-サインインを使う開発用-oidc-idp) を見てください。

### 構成別の例

| 構成 | 入力例 | どちらで開くか |
|------|--------|----------------|
| **Node / Vite** | `5173` + `/` | HMR（WebSocket）を使うので **ブラウザペイン**。 |
| **Spring Boot** | `8080` + `/` または `/actuator/health` | リダイレクト・絶対 `/assets/*`・cookie を含む画面は **ブラウザペイン**。health JSON を一度見るだけなら軽量プレビュー。 |
| **API のみ** | `8080` + `/api/health` | JSON / status の一回確認は **軽量プレビュー**。SSE・認証 cookie・リダイレクト・対話的な確認は **ブラウザペイン**。 |
| **frontend + API（複数ポート）** | frontend `5173` / API `8080` | **プレビュー用サブドメインがあるならそれが最適**（ポートごとに別 URL が出ます）。無ければ frontend の `5173` を **ブラウザペイン**で開く。そこから別ポート（`8080`）への fetch / WebSocket / SSE は使えます（ふつうのブラウザ同様、CORS 設定は必要）。 |
| **React 3000 + Spring Boot 8080** | `3000` / `8080` | プレビュー用サブドメインで両方をルート直下に出せます。API は dev サーバーの proxy で `/api` に寄せるのが一番手離れが良い（手元の PC と同じ設定のまま動きます）。 |

> **Spring Boot のリンク／リダイレクト**：正しく解決させたいときは、アプリ側で
> `server.forward-headers-strategy=framework`（または `native`）を設定してください。

### 状態表示と復旧

ブラウザペインでうまく表示されないときは、ペインに状態が出ます。

| 状態 | 意味 | 対処 |
|------|------|------|
| `target-unreachable` | ブラウザは起動したが、そのポート/path への接続がまだ成立していない。開発サーバーの**起動待ち**もこの状態。 | ポート番号と path、サーバーが listen しているかを確認し、起動後に **「再読み込み」**。残るなら **「再接続」**。 |
| `disconnected` | ペインとの通信（WebSocket）が切れた状態。必ずしもブラウザの異常終了ではありません。 | ワークスペースが稼働中か・通信が戻ったかを確認して **「再接続」**。 |
| `crashed` | ワークスペース内のブラウザが異常終了し、その表示を続けられない状態。 | **「再接続」** で開き直します。繰り返す場合はワークスペースのメモリ使用量と対象アプリを確認します（[11](11-troubleshooting.ja.md)）。 |

ワークスペースの停止中・起動中に開こうとすると専用の案内が出ます。稼働中になってから開き直してください。

### 上限と一時性（知っておくと安心）

- 同時に開けるのは **1 ワークスペースあたり 2 つまで**、表示サイズは最大 **1600×1200**、描画は最大 **12fps**
  です。動画再生や高フレームレートの確認には向きません。
- ペインを**別の表示に切り替える／背面に回す**と描画は止まり、Page は約 **60 秒**だけ保持されます。すぐ戻せば
  同じ状態が続き、時間が経つと保存済みのポート/path から作り直します。
- **ワークスペースの停止（Stop）→ 起動（Start）** や Console の再読み込みでは、表示中のブラウザペインは同じ
  ポート/path から**自動で作り直されます**が、cookie や入力途中の状態までは戻りません。
- これは**外部 URL を開く汎用ブラウザではありません**（localhost 専用で、host 欄はなくポートと path だけを受け付けます）。
  また、DOM / Network / Sources を持つ**ブラウザ開発者ツールの完全な代替でもありません**。ペイン内の「Console」では、
  そのページの `error` / `warn` などのログを確認・コピーできます（最大 200 件・永続保存はしません）。

> **スマートフォンでは**操作バーに「プレビュー」ボタンがありません。右端の **⋯** をタップすると、
> ポート・パスの入力欄と「ペインで開く」がそのポップオーバーに出ます。

## プレビュー URL で Google サインインを使う（開発用 OIDC IdP）

Google は OAuth クライアントに登録したリダイレクト URI しか受け付けず、プレビュー URL は起動のたびに変わります。
デプロイが有効にしている環境では、**開発中に限って** Control Plane が Google の代わりを務められます。
`https://<Console>/dev-idp` にある専用のサインインサーバーです。アプリ側で変えるのは**設定だけ**（issuer、
client id、client secret）。コードは変えず、Google Cloud コンソールでの登録も要りません。

- **使える条件**：既定でオンです。配備の管理者が Admin モーダルでオフにでき、運用者は `AF_DEV_IDP=0` でオフに固定
  できます（ADR 0116）。オフの間は `/dev-idp/…` は全部 404 で、何も渡されません。**プレビュー用サブドメインも必要**で、
  プレビュー用ドメインのない環境では IdP は提供されず、下の項目は出ません。**ワークスペースごとのスイッチはありません**。
  IdP が提供されている環境では、下の値が全ワークスペースに起動のたびに渡され、サインインはそのまま使えます。設定 ›
  プレビュー用サブドメインに issuer、discovery URL、client id がコピーボタン付きで出ます。client secret は表示しません。
  コンテナ内の `AF_DEV_IDP_CLIENT_SECRET` を読んでください。client id と secret は再起動しても変わりません。
  「**新しい secret を発行…**」を押すと両方とも新しくなります（古い組はすぐ使えなくなり、新しい組は次の起動で
  コンテナに届くので、ワークスペースを停止→起動してください）。本番の設定がこの issuer を信頼することは絶対にしないでください。

- **渡される値**：コンテナ内の `AF_DEV_IDP_ISSUER`、`AF_DEV_IDP_WELL_KNOWN`（discovery の URL）、
  `AF_DEV_IDP_CLIENT_ID`、`AF_DEV_IDP_CLIENT_SECRET`（`AF_PREVIEW_URL_*` の隣）。クライアントは**自分専用**で、
  id はあなたのワークスペースに結び付き、トークンはその id 宛にしか発行されません。
- **誰としてサインインするか**：Console にサインインしている本人です。パスワード入力はありません。Console に
  Google でサインインしていれば、アプリには**本物の Google の `sub` とメールアドレス**が渡るので、アプリが
  すでに持っているユーザー行とそのまま一致します。そうでなければ Console のアドレスと、`af-…` 形式の安定した
  `sub` です。共有したプレビュー（[上記](#人に見せる3-段階)）を開いた同僚は、その同僚自身としてサインインします。
- **ブラウザを戻してよい先**：あなたの**現在の**プレビュー URL の**一覧にあるポート**と、
  `http://localhost:<ポート>`／`http://127.0.0.1:<ポート>`（ブラウザペインでも使えます）だけです。それ以外は、
  再起動前の URL や、一覧に加えずに自分用に開いたポートも含めてエラーページになり、リダイレクトされません。アプリ自身の URL（たとえば `AUTH_URL`）は
  `AF_PREVIEW_URL_<ポート>` から設定し、送るコールバックがちょうどそれになるようにしてください。

設定 › プレビュー用サブドメインの「**アプリの設定例**」が、Spring Boot、Auth.js、Go、Better Auth、環境変数だけ
の各形の設定を書き出します。**形式**（Spring Boot なら「dev プロファイル（推奨）」「既定値付き 1 ファイル」
「環境変数だけ」、Auth.js なら v5 か next-auth v4）、**ポート**（一覧にあるポートから選びます）、**プレビュー用の設定も含める**
かどうか、**値**を環境変数の参照にするか埋めるかを選べます。client secret は常に環境変数の参照です。下の 2 つは考え方を
示す例です。

**Auth.js（NextAuth）v5**：変数があるときだけ Google プロバイダーの向き先を開発用 issuer にします。

```ts
// auth.ts
import NextAuth from "next-auth"
import Google from "next-auth/providers/google"

export const { handlers, auth } = NextAuth({
  providers: [
    Google(
      process.env.AF_DEV_IDP_ISSUER
        ? {
            issuer: process.env.AF_DEV_IDP_ISSUER,
            clientId: process.env.AF_DEV_IDP_CLIENT_ID,
            clientSecret: process.env.AF_DEV_IDP_CLIENT_SECRET,
          }
        : {},
    ),
  ],
})
```

v4 なら `GoogleProvider({ wellKnown: process.env.AF_DEV_IDP_WELL_KNOWN, clientId, clientSecret })` です。汎用の
OIDC プロバイダーに `issuer` と同じ 2 つの値を渡す方法でも動きます。

**Spring Boot**：登録名は `google` のまま、プロバイダー側を差し替えます。

```yaml
# application-devidp.yml  (activate with SPRING_PROFILES_ACTIVE=devidp, in the workspace only)
spring:
  security:
    oauth2:
      client:
        registration:
          google:
            client-id: ${AF_DEV_IDP_CLIENT_ID}
            client-secret: ${AF_DEV_IDP_CLIENT_SECRET}
            scope: openid,email,profile
        provider:
          google:
            issuer-uri: ${AF_DEV_IDP_ISSUER}
      resourceserver:
        jwt:
          issuer-uri: ${AF_DEV_IDP_ISSUER}   # only for a backend that verifies the ID token itself
```

`server.forward-headers-strategy=framework`（上記）を付けておくと、Spring はコールバックをプレビューのホストから
組み立てます。

> ⚠️ **本番の設定にこの issuer を信用させないでください。** Console にサインインできる人なら誰でも保証して
> しまいます。設定はプロファイルか、ワークスペースの中にしかない変数に置いてください。すべてのトークンに
> `af_dev: true` も入るので、バックエンド側で拒否することもできます。

**テスト用ペルソナ。** 権限の出し分け（admin・viewer など）を試すときは、設定 › プレビュー用サブドメイン ›
「テスト用ペルソナ」で定義します。ワークスペースに 1 つでもあると、サインインのときに確認画面が出て、自分か
ペルソナを選べます。ペルソナのアドレスは常に `<ハンドル>@example.test`、`sub` は `persona:` で始まるので、実在の
メンバーにはなれません。トークン発行の監査にはペルソナ名が残ります。ペルソナはワークスペースごとに最大 20 個で、
ハンドルは `a-z`、`0-9`、`.`、`_`、`-` からなる 1〜32 文字（先頭は英小文字か数字）です。確認画面で答えられるのは
1 回だけで、有効期間は 5 分です。**キャンセル**を押すと、アプリには `access_denied` エラーが返ります。`prompt=none` のサインインはこれまでどおり
自分として黙って通り、ペルソナのないワークスペースにこの画面は出ません。

知っておくこと：トークンの寿命は 10 分、サインイン用のコードは 60 秒です。**置き換わるのはサインインだけ**で、
Google API のアクセストークン（Calendar、Drive など）は得られず、`picture` もありません。サインインの要求に
`none` 以外の `prompt`、`max_age`、`query` 以外の `response_mode` は付けられず、アプリには `invalid_request` エラーが
返ります（Google 向けの例には `prompt: "consent"` を付けたものがあるので、開発用 issuer では外してください）。署名鍵は
30 日ごとに替わり、古い鍵も 24 時間は JWKS に残ります。鍵は固定せず、ライブラリに discovery URL から取らせてください。
認証情報を替えるときは上の「新しい secret を発行…」を使います。エンドポイントには即座に効きますが、起動中のコンテナは
次の起動まで起動時の値を持ち続けます。

### 自分の PC のアプリから使う

自分の PC の `http://localhost:<ポート>` で動くアプリも、同じ IdP でサインインできます。**ワークスペースが停止中でも**
使えます（ADR 0116）。

1. ワークスペースのターミナルで 3 つの値を読みます：`printenv AF_DEV_IDP_ISSUER AF_DEV_IDP_CLIENT_ID AF_DEV_IDP_CLIENT_SECRET`。設定 › プレビュー用サブドメインにも issuer と client id は出ますが、secret はコンテナ内
   にしかないので、読むには一度ワークスペースを起動してください。3 つを PC の環境変数に設定します。
2. アプリのコールバックを `http://localhost:<ポート>/<コールバックのパス>` にします（`127.0.0.1` も可、ポートは任意）。
3. その PC のブラウザで Console にサインインしたままにします。ほかのログインは要りません。

- **secret はパスワードと同じに扱う**：git、チャット、スクリーンショットに載せないでください。設定 › プレビュー用
  サブドメインの「新しい secret を発行…」で、コピーはすべて一度に無効になります。secret だけでなく client id も
  新しくなるので、ワークスペースは再起動で新しい値を受け取り、PC 側も両方を入れ替えます。
- **使えない場合**：配備で IdP がオフ（Admin モーダル、または `AF_DEV_IDP=0`）のとき、またはプレビュー用ドメインが
  ない環境（issuer は 404 を返します）。
- **プレビュー URL へのリダイレクトは、ワークスペースが起動中でないと使えません**。停止中に受け付けるのは
  `localhost`／`127.0.0.1` だけです。
- **PC とワークスペースで同じ設定を使う**：設定 › プレビュー用サブドメインの「アプリの設定例」がスニペットを作り、
  環境変数を参照する版もあります。考え方はフォールバックで、変数があるときだけ開発用 issuer を使います。Spring Boot
  は `devidp` プロファイル（`SPRING_PROFILES_ACTIVE=devidp`）に入れるのがおすすめです（本番の設定が開発用 issuer を
  名指ししません）。Auth.js は上の例のとおり `process.env.AF_DEV_IDP_ISSUER ? { issuer, clientId, clientSecret } : {}` です。
  開発用 issuer を本番の設定に入れてはいけません。

## エージェントが開いたブラウザを代わりに操作する

エージェントがワークスペースの中で自分のブラウザ（Chromium）を動かしていて、**人にしかできない
操作**（ログイン、ワンタイムコードの入力、同意のチェックなど）に行き当たったとき、その
ページをあなたに渡せます。上のブラウザペインとは別物です。あちらは自分で立ち上げた Web を
開くもの、こちらは**エージェントが既に開いているページを引き取る**ものです。ブラウザペインと同じく、
ワークスペースを Kubernetes（プレビューのランタイム）または ECS Fargate で動かす配備にはありません。

- エージェントの発言に **「ブラウザを開いて操作する（このタブのペインで開きます）」** という
  リンクが出ます。**押すのはあなた**で、押さない限り何も開きません（新しいタブではなく、
  いま見ているタブのペインで開きます）。
- 開いた直後は **閲覧のみ** です。画面は動いていますが、クリックもスクロールもキー入力も
  届きません。エージェントが操作を引き渡すと **ユーザー操作** に変わり、そこから触れます
  （**「反応しない」と感じたらこの状態です**。ペインの上部にもその旨が出ます）。
- 頼まれている内容は **ブラウザ操作の依頼** として出ます。終わったら **操作完了**、やめるときは
  **中止** を押すとエージェントに伝わります。伝わるのは**あなたが何をしたか**であって、
  サイト側の処理が成功したことの証明ではありません（最終的な送信・購入・同意のクリックを
  エージェントに代行させないのも同じ理由です）。
- **表示を閉じる** は表示をやめるだけで、**エージェントのブラウザもページもそのまま**です。
- 開いているものはワークスペース操作バーの**プレビュー**の **接続中のブラウザ** から開き直せます。
  同じ Chromium に他のタブがあれば **別のタブに切り替える** で移れます。

## 外部のエージェントからワークスペースを使う（MCP）

ワークスペースは `https://<Console のアドレス>/mcp` という 1 つのアドレスで MCP に応えます。手元の PC の MCP
クライアントがここに接続してセッションを扱い、許可していれば Agent Fleet のメモリも使います。呼び出しはそのたびに、
その時点のあなたのロールで確認されます。

### 外部の Claude から自分のワークスペースを操作する（MCP）

手元の PC の Claude Code / Claude Desktop から、ワークスペースのセッションを**遠隔操作**できます。
「外出先の自分の Claude から、会社のワークスペースで走っているセッションの様子を見て、
次の指示を送る」といった使い方です。そのためのトークンを **⚙設定 → 「MCP トークン」タブ**で
発行します。

1. **名前**（例: `laptop-claude`）と **スコープ**、**有効期限**を選んで **「トークンを発行」**。
   - スコープは **read（閲覧のみ）** / **write（セッション駆動・既定）** / **admin:dangerous（強権・管理）**。あなたの権限を超えるスコープは選べません。遠隔からセッションを動かしたいだけなら write で十分です。
   - 有効期限は 90 日（既定）／30 日／365 日／無期限。
2. 発行すると **「トークンを発行しました（この画面を閉じると再表示できません）」** と出ます。**トークンはこの 1 回しか表示されません**。「トークンをコピー」で控えてください。
3. 同じ画面に、手元の Claude Code 用の **`.mcp.json`** のひな型も出ます。「.mcp.json をコピー」でコピーし、プロジェクト直下に保存（または既存ファイルに `agent-fleet` を追記）します。エンドポイントは `/mcp`、ヘッダに `Authorization: Bearer <トークン>` が入ります。

不要になったトークンは同じ画面で **「失効」** できます（失効すると、そのトークンを使う
接続は次回から弾かれます）。

### サインインでリモート MCP クライアントを接続する（OAuth）

管理者が有効にしている配備では、claude.ai・ChatGPT・Claude Code・Codex を**トークンなし**でワークスペースに接続できます。
Console にサインインし、アプリが求める内容を確認して許可するだけです。配備側で有効になっていなければ、これまでどおりクライアントが
トークンを求めるので、上の手順を使ってください。

1. クライアントでカスタムコネクタ / リモート MCP サーバーを追加し、アドレスに `https://<Console のアドレス>/mcp` を指定します。
   claude.ai と ChatGPT では、トークンを使う場合と同じアドレスです。クライアント ID とシークレットの欄は空のままにします。
2. クライアントから Console に移動します。未サインインならサインインすると、**確認ページ**が開きます。表示される内容は次のとおりです。
   - **許可後に戻る先**が大きく表示されます（`claude.ai`、`chatgpt.com`、コマンドラインのクライアントなら「このパソコン自身」）。自分で始めた接続だけ許可してください。
   - **アプリ名**は「アプリ自身の申告」と明記されます。アプリが自由に付けた文字列で何も保証しないので、その上の戻り先アドレスで判断してください。
   - 接続する**テナント**を、所属テナントごとに選びます。トークンと同じく、接続はそのテナントに固定されます。
   - **許可する範囲**は `read`（セッションの閲覧）か `write`（閲覧に加えて操作）です。アプリの要求より狭く選べます。
     最初は `read` が選ばれています。アプリが `write` を要求した場合だけ、明示的に `write` を選べます。
     `admin:dangerous` はこの方法では付与されません。必要ならトークンを使ってください。
3. **許可する**（または、アプリに拒否を伝える**キャンセル**）を押すと接続できます。以降、クライアントは短命のアクセストークン（1 時間）を
   自動で更新して接続を保ちます。毎回の確認はありません。

接続は、**30 日間使われなかった**とき、または許可から **90 日**たったときのどちらか早いほうで終わります。そのときはアプリが再度のサインインと許可を求めます。
テナントを抜けた場合も、次の呼び出しから拒否されます。接続が行う操作はトークンと同じくその時点のロールで確認され、監査ログには MCP からの操作として残ります。

サインインの結果を受け取れるのは、配備で承認されたアドレスだけです。既定は `claude.ai`・`claude.com`・`chatgpt.com` と、自分のパソコン上の
コマンドラインクライアント（`127.0.0.1`、`localhost`）です。それ以外の戻り先を指定したクライアントはエラーページで拒否され、コードが送られることはありません。

#### 接続済みアプリ

**設定 → 接続 → MCP トークン** の Personal Access Token 一覧の下に、**接続済みアプリ**が表示されます。OAuth 接続ごとに、アプリ名（未確認の自己申告）、戻り先ホスト、テナント、スコープ、接続日、最終使用日を確認できます。**失効**を押して確認すると、更新トークンも含め、その接続はすぐに無効になります。また使うときはアプリから接続し直してください。この欄は、配備が MCP OAuth を提供している場合にだけ表示されます。

テナント管理者が MCP OAuth を無効にすると、そのテナントの既存の OAuth 接続は取り消され、新しい接続もできなくなります。Personal Access Token は引き続き使えます。

## Discord / Slack と連携する（チャットブリッジ）

⚙設定 → 接続グループの **「チャット連携」** タブから自分の Discord / Slack の Bot を
接続すると、席を離れていてもセッションの進捗がチャットに届き、そのまま返信で操縦
できます。

- **接続**：Discord は **Bot トークン 1 本**（カードのウィザードが検証 → サーバーへの
  招待 → チャンネル選択まで案内し、接続時にテスト通知が届きます）。Slack は Bot
  トークン（`xoxb-…`）と、双方向にする場合の App-level トークン（`xapp-…`）の 2 本。
  両方の同時接続もできます。
- **届くもの**：セッションごとにスレッドが作られ、「応答あり」「質問・計画承認」
  「許可リクエスト」「異常終了」「完了報告」が届きます（種別ごとにトグルあり）。
  opt-in の**全文モード**では応答本文そのものが届きます（トークンなどの秘密は自動で
  伏字化されます）。
- **チャットから操作**：**「返信で操縦」**（opt-in）をオンにすると、スレッドへの返信が
  そのままそのセッションへの入力になります。質問は選択肢ボタン、プラン承認は
  「承認 / 却下」、許可リクエストは「許可 / 拒否」のボタンで答えられます（ボタンの
  対応範囲はエージェント種別によって異なります）。
- **フリート・オペレーター**：常設スレッド「🛰 フリート・オペレーター」に書き込むと、
  [08 フリート・オペレーター](08-organising.ja.md)とチャットから会話できます
  （Console 側のオペレーターと同一会話）。チャット発の破壊的操作（削除など）は、
  実行前に「承認 / 却下」ボタンで一旦止まります。
- **通知だけ止めたい**：個人設定 → 「通知」タブの**サービス通知**で、接続を切らずに
  送信だけオフにできます。

## 環境設定とワークスペースの作り直し

**⚙設定 → 「ツールチェーン」タブ**で、ワークスペースの環境を調整できます。変更は**この後に
起動するセッション／シェルに反映**されます（起動中のものと既存プロセスには、ワークスペースを停止してから再び起動すると反映されます）。

- **タイムゾーン (TZ)**：既定は日本時間。変更の反映にはワークスペースの停止・起動が必要です。
- **Node.js / Java (JAVA_HOME)**：使うバージョンを選べます。Java は**このワークスペースにまだ無い**版も
  一覧に出ます。未インストールの版を選ぶと「インストール」ボタンが出て、その場で取得できます（約 200MB・
  home ボリュームへ入るので再起動しても残ります）。完了後に起動したセッションから `JAVA_HOME` に入るので、
  停止・起動は要りません。
- **エージェント CLI の更新**：「起動時にエージェント CLI と rtk を最新へ更新する」（対象は claude / opencode / codex / cursor / GitHub Copilot / Antigravity（agy）/ rtk）。既定はオフ（イメージに焼いた版で固定）。Kiro はこのトグルの対象外です — 版はイメージ再ビルド / オンデマンド導入で固定し、Kiro 自身の自動更新も無効にしています。Muse Code も対象外です。カードからイメージがピンした版を導入し、自分で更新することはありません。新しいピンの版がイメージと一緒に届くと、カードに **「Muse Code を更新」** が出ます（[06](06-agents.ja.md#muse-code)）。lcpp にはワークスペースで更新する CLI がありません。エンジンは配備側のものです。

### ワークスペースを作り直す（危険な操作）

**⚙設定 → 「危険な操作」タブ**に **「ワークスペースを作り直す」** があります。コンテナを
破棄して最新イメージで作り直す操作で、**「作り直す」** を押すと確認が出ます。何が残り、
何が消えるかは以下のとおりです。

このタブはすべての配備にあるわけではありません。作り直しとホームの掃除はホームそのものから
ファイルを消す操作で、配備によってはホームが Control Plane から届かない場所にあります
（[ref/deploy-targets](../ref/deploy-targets.ja.md)）。その配備ではタブ自体が表示されません。
ワークスペースバーからの停止・起動はどの配備でも使えます。

- **消えるもの**：実行中のセッション、および **クローン済みリポジトリ（`~/repos`・未コミット変更を含む）**。
  削除されるのは `~/repos` **だけ**です。
- **残るもの**：それ以外のホーム（`~`）はすべて残ります。ログイン・接続（GitHub / Bitbucket /
  Claude など）、`~/.local`（claude / node など）、各種設定・キャッシュは、ホームボリュームが
  作り直したコンテナへ再び接続されるので保持されます。

つまり「**`~/repos` だけが削除され、コンテナは最新イメージで作り直される。home のそれ以外
（ログイン・接続・`~/.local` 等）は残る**」操作です。イメージ更新を取り込みたい、
環境が壊れた、というときに使います。**未コミットの変更が消える**ので、実行前に
push / コミットを済ませてください（[03](03-code.ja.md)）。

### ホームを掃除する（さらに深いリセット）

作り直しは `~/repos` しか消さないため、ホーム側（`~/.local` の壊れた claude 導入、
壊れたキャッシュや設定ファイルなど）が原因のときは直りません。その場合は同じ「危険な操作」タブに
ある **「ホームを掃除する」** を使います。**ログイン・接続を除くホーム全体**（`~/repos`・
`~/.local`・各種キャッシュ・設定）を削除して最新イメージで作り直す、より深いリセットです。

- **残るもの**：ログイン・接続（GitHub / Bitbucket / Claude）**のみ**。
- **消えるもの**：実行中のセッション、クローン済みリポジトリ、および `~/.local`・キャッシュ・
  設定など**ホームのその他すべて**。

まず「作り直す」で直るか試し、それでも直らないときだけ「掃除」を使ってください。
どちらも**未コミットの変更は消えます**。
