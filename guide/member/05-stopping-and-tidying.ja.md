# 05. 止める・再開する・片付ける

[English](05-stopping-and-tidying.md) | 日本語

この章は、セッションの終わり方を扱います。停止と再開、会話の引き継ぎ、セッションを起こしたままにする・終わったら止める、削除からの保護、たまったものの片付けです。

## セッションを止める・片付ける

操作はセッション行の **⋯ メニュー**（または右クリック）にあります。迷ったときは
「**停止する**」を選んでください。会話も一覧も残る、いちばん安全な操作です。

| やりたいこと | 選ぶ操作 | 操作後 | 元に戻せるか |
|---|---|---|---|
| いったん処理を止め、あとで続きをする | **停止する** | 「停止中」として一覧に残る | 一覧から開いて再開できる |
| 終わった仕事を普段の一覧から片付ける | **アーカイブする** | 会話を残したまま一覧から隠れる | アーカイブ一覧から復帰できる |
| 同じ場所で、会話だけ最初から始める | **作り直す** | 今の会話をアーカイブし、新しい会話が開く | 古い会話はアーカイブから復帰できる |
| 使い捨ての shell / SSM を一覧から消す | **削除** | ごみ箱へ移り、一覧から消える | 掃除のごみ箱から復元できる |

表示される操作はセッションの種類と状態によって異なります。たとえば AI セッションには
「アーカイブする」、使い捨ての shell / SSM には「削除」が表示されます。AI セッションを消したい
ときは、アーカイブしてからアーカイブ一覧で削除します。**セッションの削除はどの経路でも、消す前に
ごみ箱へ退避されます**。また、セッションを削除しても作業コピー（worktree）は消えません。作業コピーを
消すのは、下の「作業コピーの削除」か掃除の②です。

**停止中のまま 7 日経ったセッションは、自動でアーカイブへ移ります。**（期間は [設定 → エージェント](20-settings.ja.md#エージェント) で変えたり止めたりできます。短くすると、新しい期間を過ぎているセッションが次の一覧更新でまとめて移ります） 終わった仕事で普段の
一覧が埋まらないようにするためで、**消えるのではなく移るだけ**です。会話はそのまま残り、
自分でアーカイブしたときと同じようにアーカイブ一覧から復帰できます。**アーカイブから自動で
消えることはありません**。本当に消えるのは掃除モーダルで削除したときだけで、そのときも
まずごみ箱へ退避されます。つまり、**残したいならアーカイブ**（または削除ロック。こちらは
普段の一覧に残したままにできます）、**消したいなら削除**で、放置して失うことはありません。

**アーカイブ（削除）したセッションのタブは自動的に閉じます。** 別のタブや別の端末で片付けた
とき、掃除でまとめて片付けたときも同じで、そのときは「タブを閉じました」と通知が出ます
（自分がこの画面で片付けたときは、その場で閉じるので通知はありません）。閉じるのはその
セッションの画面（ターミナル／チャット）だけで、そこから開いたファイルや計画のタブは
そのまま残ります。

**1 つの作業コピーの配下をまとめて止める。** リポジトリや worktree の行を右クリックして
「**配下のセッションを停止**」を選びます。モーダルにはその作業コピーと、左ペインでその下に
ぶら下がる作業コピーで動いているセッションが 1 行ずつ並び、1 回で止められます。各行には何を
送るかが出ます：「**すぐ停止**」か、応答の途中のセッションには「**ターン終了後**」（ターンが
終わった時点で止まる予約なので、書きかけの応答は失われません）。すぐ切りたいときは
「**実行中のセッションもすぐに停止する（N 件）**」にチェックを入れます。質問待ち・上限待ち・
認証切れのセッションは待つターンが無いので常にすぐ停止になり、shell / ssm の行と「起きたままに
固定中」の行は既定でチェックが外れています。付けるのはあなたの意思表示です。停止は元に戻せます。
会話は残り、セッションは再開できます。

### まとめて片付ける（掃除）

散らかってきたら、**リポジトリ**見出しのゴミ箱アイコン **「掃除を開く（点検・整理）」** から
掃除モーダルを開きます。**危ないものから順に手前で止まる**よう、2 段階に分かれています。

- **① セッションを整理**：「**まとめて整理**」で、停止中の AI セッションはアーカイブ、
  shell / SSM はごみ箱へ移ります。
- **② 作業コピー・ブランチを削除**：「**安全なものを一括削除**」で、安全と判定されたものだけを消します。
  「**掃除候補**」タブの「**安全なものを全選択**」を使うと、安全な行のチェックを 1 クリックで付けられ、
  「**選択したものを片付ける**」でチェックした行だけを片付けられます。1 件ずつ選ぶこともできます。
- **削除済みセッションのキャッシュ**：セッションに貼り付け・添付したファイルや、codex が読んだ画像は、
  セッションを削除してもディスクに残ります。セッション（またはアシスタントのチャット）が削除済みで
  **ごみ箱にも無い**ものは、もうどこからも参照されないので、種類ごとにサイズ付きの 1 行で並び、
  「**まとめて削除**」で消せます。ごみ箱のセッションや、そのセッションからフォークしたセッションが後で使うかも
  しれないものは対象にしません。

候補には**安全度**と理由が付きます。

| 安全度 | 意味 |
|---|---|
| **安全** | マージ済み・クリーンなど、消しても失うものがない |
| **要確認** | 停止中のセッション、クリーンだが未マージの worktree など。中身を見てから決める |
| **保持** | 稼働中、未コミット / 未 push、削除ロック中。掃除の対象になりません |

**保持**を片付けたいときは、先に停止するか push してください（どうしてもというときは
Console から強制削除します）。セッションが掃除に巻き込まれないようにするには、
[削除ロック](#削除ロックをかける)をかけます。

**消しすぎても戻せます。** 削除したセッションとブランチは、消す前に**ごみ箱**へ退避されます。
掃除モーダルの 「**ごみ箱（復元）**」タブから **復元**でき、もう要らないと確信できたものは
「**完全に削除**」で容量を回収します（そのアーカイブの復元が途中で止まっていたら、先にもう一度復元してください。
それまでは削除できません）。ごみ箱は自動では空になりません。溜まってきたら、ごみ箱タブの
「**30 日より古いものを完全に削除**」でまとめて回収できます（容量は **設定 → マシン** にも出ます）。
**worktree の削除もごみ箱に入ります。** 削除の直前に、その時点のコミット・ブランチ・未コミットの変更
（未追跡のファイルを含む。`.gitignore` の対象は含まない）を記録し、コミットが git の掃除（gc）で消えないよう
保護します。ごみ箱から **復元** すると、同じパスに、削除したときのコミットで worktree を作り直して変更を戻し（すべて未ステージで戻ります）、
その削除でアーカイブへ移ったセッションも一覧に戻します。ブランチが削除後に動いた・別の作業コピーが使っている
などでそのまま戻せないときは、復元は何も作らずに作り直しの画面（後述の「作業コピーを作り直す」と同じ）を開くので、
新しいブランチ名を付けて戻せます。ごみ箱から **完全に削除** すると保護を外し、
それ以降は戻せません。記録を書けないとき（ディスクが一杯など）や、worktree の中に git 管理外のリポジトリ（中で clone したものなど。
中身をごみ箱に残せない）があるときは、worktree を削除しません。ステージ済みだった新規ファイルは、未追跡のファイルとして戻ります。
その worktree の中にあった停止中の AI セッションは**アーカイブへ移り**（会話は読めますが、
作業フォルダが無いので、作り直すまでは再開できません。後述）、shell / SSM はごみ箱へ移ります。**削除済みセッションのキャッシュの
削除も取り消せません**（ごみ箱を経由しません）が、対象はもう完全に消えたセッションのものだけです。

アーカイブ済みのセッションは掃除の対象外です（アーカイブ一覧から復帰できます）。
アーカイブ一覧の「古いものを削除」では、30 日以上前の項目をまとめて削除できます（これもごみ箱へ移ります）。

同じ点検と片付けは、フリート・オペレーターにチャットで頼むこともできます
（[11](11-many-sessions.ja.md)）。

### ひと仕事ぶんをまとめて消す（作業コピーの削除）

掃除は**ワークスペース全体**を点検する道具です。**終わった仕事ひと組だけ**（親の worktree と、
そこから起こした子セッションの worktree）を片付けたいときは、その行を右クリックして
「**作業コピーを削除**」を選びます。消えるのはローカルの作業コピーだけで、履歴とリモートは残ります。左ペインでその行の下にぶら下がっている作業コピーが
そのまま一覧で出るので、**セッションのアーカイブと作業コピーの削除が 1 回で終わります**
（停止中の AI セッションはアーカイブへ、shell / SSM はごみ箱へ移ります）。

- **既定でチェックが入るのは、消しても失うものが無い行だけ**です（親に取り込み済み・未コミット無し・
  誰も作業していない）。未コミットや未マージを含む行は空のままなので、**チェックを付ける操作が
  「それでも消す」の確認**になります。
- **稼働中のセッションがある行も行き止まりではありません。** 「**稼働中のセッションを先に停止してから
  削除する（N 件）**」にチェックを入れると、同じ片付けの中で先に停止し、止めれば消せる行には自動で
  チェックが入ります（実行中のターンは中断されます）。止めても作業を失う行はチェックできるように
  なりますが、チェックは入りません。この行もチェックを付ける操作が「それでも消す」の確認です。**削除ロック中の行はチェックできません**。
  理由が行の下に出るので、先にロックを解除してください。
- 「**マージ済みブランチも削除する**」にチェックを入れると、使い捨ての `temp/…` ブランチも一緒に
  消せます（ごみ箱から戻せます）。さらに「**リモート（origin）のブランチも削除する**」を選ぶと
  origin 側も消します。**これだけは取り消せません**。親の履歴に入っていないブランチは、
  この経路では消せないようになっています。

### 予算 — 使いすぎたセッションを止める

セッションには米ドルの**予算**を付けられます。**推定の**費用が予算に達すると、そのセッションは
**実行中のターンが終わったところで停止**し（「ターン終了後に停止」と同じ、再開できる停止）、通知
センターに「**予算に達して停止**」が届きます。1 ターンだけで予算の **2 倍**に達した場合は、ターンの
途中でもすぐに止め、通知にターンの途中で停止したことが書かれます。

- **付け方。** 起動ダイアログの **詳細 → 予算（米ドル）** で。あとからはセッションのメニューの
  「**予算…**」で。設定 › エージェント ›「**新しいセッションの予算**」は、予算を指定しなかったすべての
  起動（`create_session` やスケジュールで起動したものを含む）に付く既定値です。0 で予算なし。
- **見え方。** チャットのコンテキスト行に「**≈$1.84 / $5.00**」と出ます。80% から黄色、予算に
  達すると赤。押すと予算を変えられます。`create_session` で子を起こしたセッションでは、その横に
  「**子 ≈$X**」が並びます。子の費用はここに見えるだけで、このセッションの予算には**数えません**
  （子はそれぞれ自分の予算を持ちます）。
- **続けるには。** 予算で止まった行には予算の印が付きます。行のメニューと通知にある
  「**予算を上げて再開…**」で、予算を上げて再開までを一度に行えます。これまでの費用より高い予算しか
  受け付けません。予算を上げずに再開すると、もう 1 ターン走ったところでまた止まります。
- **数字の意味。** セッション自身の会話記録から定価で見積もった値です（opencode のように CLI が
  費用を報告する場合はその値）。**請求額ではありません**。サブスクリプションのプランでは API 換算の
  値です。価格の無いモデルは見積もれないので予算は適用されません（ダイアログにそう出ます）。会話記録に
  トークン数が入らない種類（Kiro・Cursor・Antigravity）と自前エンジン（$0）が予算で止まることはありません。
  フォークは $0 から数えます。コピーした履歴の分はフォークに付きません。

## 再開できる／できない

停止中のセッションはクリックで開いて再開できます。ただし claude / codex / cursor / copilot / kiro / agy / opencode / lcpp / muse は、
**起動時の作業フォルダが消えていると再開できません**。この場合、状態表示が
**「フォルダ無し — 再開不可」** になり、行は打ち消し線でクリックできなくなります
（「作業フォルダが存在しないため再開できません」）。作業コピーを worktree ごと消したあとが
典型例です。shell は作業フォルダが無ければホームに戻って再開します。

**消した worktree は元のパスに作り直せます。** アーカイブ一覧で、消えた worktree のフォルダの見出しに
**「作業コピーを作り直す」** が出ます。作業コピーが消えたセッションの ⋯ メニューにある
**「作業コピー（worktree）を作り直す…」** からも、同じ画面が開きます。押すと、そのフォルダが最後に使っていたブランチを次の順で探し、
見つかったものから同じパスに worktree を作ります: 削除したときの状態（ごみ箱に記録があれば。未コミットの変更も戻る）→ ローカルブランチ → リモートブランチ →
Console でブランチを消したときに記録したコミット → マージコミットに残っている先頭コミット
（GitHub の PR マージなど）。どれも残っていなければ、同じ名前の新しいブランチを親から切ります。
作り直したら、戻すセッションを選んで復帰させます。フォルダが元の場所に戻れば、どの種類の
セッションも会話を元どおり再開できます。

- そのブランチを別の作業コピーがチェックアウトしている場合は、同じコミットから新しいブランチを切ります。
- 同じ名前のフォルダは、同名ブランチの別の作業で再利用されていることがあります。開始ブランチが
  作り直したブランチと違うセッションには印が付くので、日付と合わせて確かめてから戻してください。
- 未コミットの変更が戻るのは「削除したときの状態」からだけです（ごみ箱に記録がある削除に限ります）。
  `.gitignore` 対象のファイル（`node_modules`・`.env` など）はどの方法でも戻りません。
  親の作業コピーが消えている場合も作り直せません。
- 作業コピーの行を右クリックして **「この作業コピーのアーカイブ済みセッション」** を選ぶと、
  そのフォルダのアーカイブだけを開けます。

停止中のセッションを開くと、まず履歴が読み取り専用で表示され、**「再開」** で会話を
再開します。再開後は、保存されていた実行方式で続きます。ペインの中で **Ctrl+クリック**
（または中クリック）すると、今の表示を保ったまま
**新しいペインに開け**ます（[02 Console の基本](02-console-basics.ja.md#複数を並べるペイン)）。

ターミナルの中でモデル・effort・plan モードを切り替えていた場合は、起動時の設定に戻らず、
**会話に記録された最後の設定で再開します**。ただし claude / codex / kiro 以外では、モデルを
切り替えたあと 1 通もメッセージを送っていないと CLI 自身がその切り替えを記録しないため、
起動時のモデルで再開します。

ワークスペースを止めていても、**一覧そのものは見えます**。中身の操作はできませんが、
「どのセッションがあったか」はスマホからでも確認できます。

### 会話ログが削除された claude セッション

claude は会話をワークスペース内のログに保存し、放っておくと 30 日より古いログを削除します。そこで
Agent Fleet は、ワークスペースの claude の設定で、この日数による削除を無効にしています（新規・既存の
ワークスペースのどちらでも）。停止したまま（アーカイブも削除もしていない）のセッションは、
どれだけ放置しても会話が残ります。ログを消すかどうかは claude の日数による掃除ではなく、
Agent Fleet 自身のライフサイクル（アーカイブ → 削除 → 掃除）が決めます。claude 側で自分で決めた保持期間は
上書きしません。ただし短くすると日数による削除が戻り、`0` にすると claude が会話を保存しなくなります。

これに加えて Agent Fleet は、停止したセッションのログのバックアップを、claude の手の届かない場所に持ちます。
ログが無くなったセッションを再開すると、バックアップが戻されて履歴つきで続けられます。ログが残っている
ときは、バックアップで置き換えません。ただし会話がまだ入っていないログだけは、脇に移してバックアップを戻します。バックアップはセッションごとに 1 つで、セッションを
削除すると消えます。「新しい会話を始める」で脇に置いたバックアップはセッションを削除するまで残り、
Agent が止まっている間に削除されたセッションのバックアップは自動では掃除されません。バックアップは
停止中に作るため、最初のバックアップより前にログが消えた場合（停止した直後や、この仕組みより前に最後に
動いたセッション）はこの方法では戻せません。

削除したセッションの会話はクリーンアップのアーカイブに入り、バックアップのスナップショットも必ず一緒に入ります。
アーカイブを復元すると、実際のログが完全でバックアップより新しいときだけ実際のログが、そうでなければ
バックアップが戻され、もう一方は隣に残ります。読めないログがあると（消えた直後の場合を除く）削除は断られます。

使えるバックアップも無い場合（この保護より前に削除された、または自分で保持期間を短くしていた場合）、
**「再開」** は古いセッションの下で空の会話を黙って始めません。
**「このセッションの会話ログが削除されているため再開できません…」** と
**「新しい会話を始める」** ボタンが出ます。押すと同じセッションで新しい会話を始め（分岐したセッションは元の会話を再度コピーしません）、
残っていた古いログやバックアップは、そこから復元せずに脇に残します。それができないときはボタンがエラーを表示し、何も変わりません。
一度もメッセージを送っていないセッションは、従来どおり再開できます。
制限: 削除されたログを見分けられるのは、Agent Fleet に「ターンが完了した記録」が残っているセッションだけです。
そうした記録がない古いセッションは「一度も話していない」ものと区別できないため、ログがすでに
消えていても、警告なしに空の会話で始まります。

### ブランチが入れ替わったときの警告

セッションの行に**警告アイコンとブランチ名**が出ることがあります。これは、その
セッションの作業コピーが、起動時のブランチから別のブランチへ**切り替わっている**サインです。
稼働中のエージェントが見ている作業ツリーが入れ替わり、編集や差分が食い違っている
恐れがあります。心当たりがなければ、意図しないブランチ切替が起きていないか確認して
ください。並行作業では、セッションごとに worktree を分けておくとこの混乱を避けられます。

## 別のセッションで続ける — 引き継ぎ・分岐・移動

会話を新しいセッションへ持ち出す方法は 3 つあります。新しいセッションが何から始めるかを誰が
用意するかと、元のセッションがどうなるかが違います。

| | 引き継ぎ | ここから分岐 | 移動 |
|---|---|---|---|
| 操作 | **⋯** メニューの **「別のエージェントへ引き継ぐ…」** | 過去の自分の発言の下の **「ここから分岐」**（[04 会話](04-conversation.ja.md#この発言から分岐する)） | **⋯** メニューの **「別のエージェントへ移す…」** |
| 文脈を用意するのは | フリート・オペレーターが要約を書き、あなたが確認する | 誰も書かない。会話をそのまま複製する | ワークスペースが会話を引き継ぎファイルに書き出す。AI は要約しない |
| 引き継ぎ先 | 接続済みのどのエージェントでも | 同じエージェント | 別の種類のエージェントだけ |
| 元のセッション | そのまま残る | そのまま残る | 停止し、入力を受け付けなくなる |
| 引き継がれるもの | 要点・未完了タスク・変更済みファイル・次の作業 | 既定ではその発言より前の会話（一字一句そのまま）。その発言は入力欄に下書きとして入る。**この発言の続きから** を選ぶと、その発言と回答まで引き継ぐ | 会話、止まった箇所、作業コピーの状態、送られていない指示。移動先は同じ作業コピーで動く |

### 会話を引き継ぐ（handoff）

会話のあるセッション（shell と ssm 以外のすべてのエージェント）の **⋯** メニューから
**「別のエージェントへ引き継ぐ…」** を選び、開いた引き継ぎモーダルで**引き継ぎ先エージェント**を
選びます。ワークスペースが起動している必要があります（セッション自体は停止中でも構いません）。
元の会話をそのまま丸ごと渡すのではなく、
**フリート・オペレーター**が元セッションの状況を読み、要点・未完了タスク・変更済みファイル・次の作業を
引継ぎ案にまとめます。

案、作業フォルダ、開始するエージェントを確認し、あなたが明示的に同意してから新しいセッションを
作成します。元のセッションはそのまま残ります。長い会話で新しい会話の文脈を使い切らずに、別の
エージェントへ引き継いだり、別の方向を試したりできます。引継ぎ案のカードには **「メンバーへ引き継ぐ」**
もあり、セッションを共有している相手へ渡せます（[12](12-collaboration.ja.md#別のメンバーにセッションを引き継ぐ)）。

**要約ではなく会話そのものを引き継ぎたいときは、引き継ぎではなく分岐**です。チャット表示で
過去の自分の発言から **「ここから分岐」**（[04 会話](04-conversation.ja.md#この発言から分岐する)）
を使うと、その時点までの会話をそのまま複製した新セッションが同じエージェントで開きます。
言い回しや細かい経緯まで残るので、「あの指示のところからやり直す」用途にはこちらが向きます。

### 別のエージェントへ移す（move）

セッションがエージェントの利用上限に達したときや、単に別の種類で続けたいときは、**⋯** メニューの
**「別のエージェントへ移す…」**（引き継ぎの隣）を選びます。引き継ぎと違い、要約を AI が書くことは
ありません。ワークスペースが会話を**引き継ぎファイル**（止まった箇所、作業コピーの状態、変更した
ファイル、会話そのもの。秘密情報は伏せ字）に書き出し、選んだエージェントを**同じ作業コピー**で起動して、
まずそのファイルを読むよう指示します。元のセッションはそのあと**停止し、入力を受け付けなくなる**ので、
作業コピーを触るセッションは常に 1 つです。

**移せるセッション。** ワークスペースが会話を読めるセッションだけです。shell と ssm は移せません。
待機中、停止中、または利用上限・支出上限で止まっている必要があります。ターンの実行中や、質問・
計画・権限の確認があなたの返事を待っている間は断られます。ターンが終わるのを待つか止めて、先に
答えてください。種別や状態によっては移せないものもあります
（上のエージェント一覧を参照）。

利用上限（または支出上限）で止まったセッションは、チャットの上に帯も出て、「**別のエージェントへ移す**」ボタンから同じダイアログが開きます。そのとき利用枠の残っているエージェントが先頭に並び、印が付きます。使用量が表示されないエージェントも選べますが、印は付きません。移せるエージェントがない場合や、候補がすべて上限に達している場合、帯は出ません。
移動が終わると、上限の解除に合わせて予約されていた自動再開は取り消されます。元のセッションが
ひとりでに動き出すことはありません。

確定する前に、ダイアログには次が表示されます。

- **移せるエージェント**：移動元・移動先になれる種別は[エージェント一覧](../ref/agents.ja.md#別のエージェントへ移す)にあります。同じエージェントは出ません
  （同じアカウントの利用枠を使うため）。同じ種類で続けたいときは、その種類が対応していれば
  **「ここから分岐」**（[04 会話](04-conversation.ja.md#この発言から分岐する)）を使います。ファイルを読めないエージェントや未接続のエージェントは理由つきで
  並びます。
  claude、codex、muse は、いまの使用量もダイアログに出ます。それ以外のエージェントについては
  利用枠について何も表示しません。
- 新しいセッションの **「モデル」** と **「実行方式」**。起動するときと同じように選べます。
- 作業コピーの**未コミットの変更**。移動はこれをコミット・退避・破棄しません。移動先がそのまま
  引き継ぐので、必要なら先に片付けてください。
- まだ送られていない指示、届いていないセッション間メッセージ（どちらもファイルに入ります）、ファイルの
  大きさ、**動いている子セッション**。子は元のセッションのものとして残り、報告は元のセッションに
  届かなくなるので、Console で確認してください。
- マネージドの cursor セッションでは、停止すると会話の表示が空になり、ファイルが唯一の記録になること。

**引き継ぎファイル**は、移動先のセッション専用の作業用フォルダに書き出します。
作業コピーの外なので、コミットされることはありません。ダイアログにファイル名とサイズが出ます。会話のほか、止まった箇所も記録します。
送られないままだった指示や、停止で取り下げられた入力もここに入ります。最後の 3 回分の
あなたの発言以降は、ツール呼び出しを出力ごと残します。それより前は、読むだけのツール呼び出しを
省き、それ以外は出力なしの 1 行にします。thinking は入りません。約 256 KiB を超えると、古い
エージェントの返答から最初の段落だけに縮めます。あなたの発言と最後の 3 回分は縮めないので、
それでも大きくなることがあり、そのときはダイアログに出ます。秘密情報らしき文字列は伏せ、
見出しは Console の表示言語で書きます。元のエージェントが読んでいて移動先が読まないプロジェクトの
指示ファイルがあれば、その名前も書いておきます。ファイルは移動先のセッションと一緒にゴミ箱へ入り、
元に戻すと一緒に戻ります。

移したあと、元の行には **「… へ移動済み」** と出て、押すと移動先のセッションが開きます。メニューの
**「それでもここで再開する…」** は、移動先を止めずに元のセッションの入力を開き直します。
以後はどちらか一方だけを使ってください。移動先が起動したか分からないまま止まったときは、行に
**「… への移動が未完了」** と出て、ダイアログで **「やり直す」**（同じファイル・同じ名前）と
**「移動を取り消す」** を選べます。移動先が最初の指示を受け取ったか分からないときは、ダイアログから
送り直せます（二重に届くことがあります）。ワークスペースが起動している必要があります。

## セッションを自動停止させない

放っておいたワークスペースは自分で止まります。長く走らせるものがあって止められては
困るときは、⋯ メニューの**自動停止しない**で、指定した時間だけ自動停止の対象外に
できます。残り時間は行に出ます。

**時間を区切ってあるのは意図的です**。一度かけて忘れる免除は、ワークスペースが
1 か月動きっぱなしになる原因そのものだからです。

## 終わったら止めてもらう

逆に、**作業が終わった時点で止まってほしい**ときがあります。夜のうちに長い作業を
投げておいて、終わったセッションにワークスペースを起こしたままにされたくない、
というような場合です。

頼み方は 2 つあり、どちらも同じ予約になります。

- **セッションにそう言う**：「これが終わったら停止して」。セッションが予約を入れます。
- **⋯ メニューの「ターン終了後に停止する」**：自分で入れます。取り消しも同じ場所です。

予約が入っている行にはバッジが付きます。止まるのは**今動いているターンが終わってから**で、
質問待ちや作業が続いている間は止まりません。停止は**再開できる停止**なので会話は残り、
行の「起動」でそのまま続けられます。止まったときは通知が 1 通届きます。

**新しい指示を送ると予約は解除されます。**「終わったら止めて」は目の前の作業について
言った言葉で、あとから頼んだ別の作業まで含んではいないからです。

なお、これは**費用ではなく後片付けの機能**です。作業を終えたセッションはワークスペースの
アイドル自動停止を妨げていないので、止めてもワークスペースが止まる時刻は変わりません。
得られるのは、そのセッションが使っていたメモリがすぐ返ることと、一覧が「終わった＝停止中」と
読めることです（アイドル自動停止も同じことを時間差でやりますが、**そのセッションを開いている
間は対象外**なので、見ている前で停止できるのはこちらだけです）。

## 削除ロックをかける

⋯ メニューの**削除ロックをかける**は、「これは消えてはいけない」という印です。
ロック中のセッションにはバッジが付き、**掃除からも自動整理からも外れます**。
[まとめて片付ける掃除](#まとめて片付ける掃除)だけでなく、勝手に消しにいく仕組みからも外れます。

四半期末に要る会話や、まだ終わっていない worktree に使います。**ロック中のセッションが
居る worktree は掃除が拒否し**、黙って回避せず「先にロックを外してください」と言います。
