# 18. エージェントメモリ — エージェントが覚えること、その管理

[English](18-agent-memory.md) | 日本語

覚えた内容を残す機能は 2 つあります。**エージェントメモリ**は、どの種類のエージェントも共有する Agent Fleet 自身のメモリです。
**メモリのスナップショット**は、エージェントが自前のファイルに貯めるメモリを版管理します。どちらも ⚙設定 の中のページです。

## エージェントメモリ

Agent Fleet 自身の共有メモリです。どの種類のエージェントも af のツール `memory_index` / `memory_search` / `memory_read` /
`memory_save` / `memory_patch` / `memory_feedback` / `memory_forget` で読み書きします。プロジェクトごと（worktree はリポジトリのものを共有）と、全プロジェクト
共通の範囲があり、エージェントの種類を替えても、引き継いでも、別の種類の子セッションでも、学んだことが残ります。
**既定はオフ**です。オンにするのは[設定](#設定)の表示です。エージェントが自前のファイルに貯めるメモリの版管理は、この先の[メモリのスナップショット](#メモリのスナップショット)です。

先頭に状態の行が 1 本あります（オンかオフか、プロジェクト何件にメモリ何件か、最後に変わった時刻、Claude Code との
バックグラウンド同期に確認が必要なときは警告と「設定」への案内）。その下に 2 つの表示があります：
**設定 · 取り込み・書き出し**。最後に開いた表示は覚えています。ワークスペースが停止中に使えるのは
**設定**だけで（スイッチは次の起動に向けて保存されます）、もう一方の表示には「ワークスペースを起動」が出ます。スマートフォンや縦向きのタブレットでも
タブは 1 行のままで、収まらないときは横にスクロールします。矢印キー、Home、End でタブを移れます。

**メモリビュー。** 本文や差分、一覧を並べて読むには、ダイアログは狭すぎます。そこで**メモリ**・**変更**・**提案**は、画像ギャラリーと同じように
専用のペイン（*メモリ*タブ）で開きます。設定 › エージェントメモリの先頭の**メモリビューを開く**、毎日の通知（**提案**に移ります）、
コマンドパレットのメモリから開けます。メモリビューはワークスペースに 1 つで、もう一度開くと今あるものに移ります。使い方は
以下の各表示と同じで、この章の**メモリ**・**変更**・**提案**の節は、このビューの 3 つのタブのことです。

### メモリ

- **一覧と詳細**：左の一覧に、**すべての範囲**（既定。ユーザー共通と全プロジェクトをまとめ、各行に所属を表示）、または 1 つの範囲（全プロジェクトに配布される**ユーザー共通**、または 1 プロジェクト）のメモリを、作成者・最終更新・エージェントに読まれた回数・**ピン留め**の印とともに表示します。**すべて**・**ピン留め**・**忘れさせた**のチップで絞り込めます。検索は、入力したすべての語（順不同）が、名前・説明・種別・作成者・作成者のセッションを合わせた中にあるメモリを即時に探します。入力が止まると本文も探し、本文だけで見つかったメモリはそのあとに、エージェントの `memory_search` と同じ順位付けで並びます。すべての語を含むメモリがないときは、本文検索が一部の語を含むものを返し、一覧にはそれだけを「一部の語のみ」の注記つきで表示します（名前・説明・種別・作成者がすべての語に当たるメモリがあれば、それが優先されます）。検索は「読まれた回数」に数えません。コマンドパレットの **「メモリ」** の範囲でも、どの画面からでも同じメモリを検索できます（[02](../user/start/shortcuts.ja.md#コマンドパレットで探して開く)）。行を選ぶと右にそのメモリが開き、本文・範囲・種別・作成者・更新・使用回数と、**編集**・**ピン留め** / **ピンを外す**・**このメモリを忘れさせる**、**その他の操作**（⋯）の中の**履歴から消去…**が出ます。**新しいメモリ**（表示中の範囲に作ります。すべての範囲を表示中はユーザー共通）と**編集**のフォームも同じ場所に開きます。選んだ範囲・チップ・メモリは、表示を行き来する間は覚えていて、ページを再読み込みすると忘れます。スマートフォンでは一覧と詳細が別の画面になり、行を選ぶと詳細が開き、**一覧に戻る**（または Escape）で戻ります。名前またはテキストが秘密情報らしいメモリは一覧に出さず、件数だけ表示します。

- **ピン留めしたメモリ**：詳細で**ピン留め**したメモリは、エージェントが作業開始時に読む索引の先頭に、ほかより前に必ず載ります。**ピンを外す**と元に戻ります。**ピン留め**のチップで一覧できます。それ以外は、種別（feedback・
  user のメモリが先）→ 読まれた回数（読み取りと、返された検索ヒットを数えます）→ 新しさの順です。ピンも索引の
  サイズ上限（説明つきの行で約 24 KiB。索引では説明を 150 文字で切り、`memory_read` は全文を返します）を共有するため、ピンだけで収まらないときは末尾のものが名前だけの一覧に落ち、エージェントにもそう伝わります。
  全セッションに必要なものだけを留めてください。`memory_search` のヒットも関連度順です（クエリの語が多く当たるものが先、次に名前 ＞ 説明 ＞ 本文の順、次にピン・読まれた回数・新しさ）。全語を含むメモリがないときは、一部の語を含むものを返し、その旨を示します。ピンは「ピン変更」としてあなたの変更に記録され、元に戻せます。
  ピン留め済みのメモリをエージェントが後で更新してもピンは残り、af のメモリツールにはピンを付け外しする手段がありません。

- **種別とライフサイクルのフィールド（任意）**：メモリのファイルには `kind`（`preference`・`lesson`・`procedure`・`state`・`log`：古くなり方）、`anchors`（依存するパス・シンボル・テスト名・ADR 番号・コマンド）、そしてライフサイクルとして `status`（`active`・`quiet`・`archived`）と `status_by`、`superseded_by`（メモリ、またはリポジトリの文書）、`invalid_at`、`reasons`（未解決の疑い。1 つでもあるメモリは「要確認」）を付けられます。エージェントが `memory_save` で設定できるのは `kind` と `anchors` だけです（省略すると今の値を保ちます）。ライフサイクルのフィールドは lint・フィードバック・統合処理・あなたが設定し、エージェントや取り込みが設定することはありません。どれも付いていないメモリは従来どおり動きます。エージェントに見えるものは、どの経路（`memory_index`・`memory_search`・`memory_read`・外部メモリのツール・ローカルモデルのセッションのプロンプト・Claude への書き戻し）でも同じ規則で決まります。**アーカイブ済み**または**置き換え済み**のメモリは、索引にも検索にも注入にも出ず、`memory_read` は本文の代わりに stub（名前・状態・置き換え先・理由）を返します。**quiet** のメモリと `log` は、ピン留めしていても索引の説明つき部分には載りませんが、名前だけの一覧・検索・`memory_read` には出ます。**要確認**のメモリは、すべての行・ヒット・読み取りに理由が付きます。あなた自身の画面（一覧・履歴・差分・復元・書き出し）はすべてを表示します。Claude への書き戻しは、アーカイブ済み・置き換え済み・quiet・log・要確認のメモリを書かず、以前に Agent Fleet が書いた写しは、そのメモリが対象から外れた時点で**削除**します（プレビューでは **remove**）。Claude 側で編集した写しは残し、競合として表示し、`MEMORY.md` にも載せません。変更を元に戻すと、これらのフィールドも含めて以前の版がそのまま戻ります。

- **忘れさせる・忘却を取り消す・履歴**：**このメモリを忘れさせる**と全エージェントから見えなくなり、**忘れさせた**のチップに並んだものは、行または詳細から**忘却を取り消す**ことができます（直前のテキストに戻ります。今は秘密情報に見えるテキストは、確認できる「変更」の表示で、その忘却に**この変更を元に戻す**を使ってください）。どちらも「変更」の表示と同じ元に戻す・忘れさせるで、あなたの操作として記録され、取り消せます。
  忘れさせるは、履歴に変更がある一覧のどのメモリにも使えます（押したときに最新の変更を探すので、古くても構いません）。手で置いたメモリのファイルのように履歴に変更がないものは、ここからは忘れさせられません。**忘れさせた**には、選んだ範囲（初期値はすべての範囲）で忘れさせたメモリが、
  いつ忘れさせたものでも新しい順に 300 件ずつ出て、**古い忘れさせたメモリを読み込む**で次の 300 件を、末尾まで読めます。忘れさせたメモリが非常に多い（約 2000 件を超える）ときは 1 回の読み込みでは全件を確認できず、その旨を表示します。表示していない件数は最小値で、古いものは読み込むごとに確認します。詳細の下の**このメモリの履歴**には、そのメモリ自身の変更が並び、選ぶと「変更」の表示と同じ差分が出ます。全メモリの変更を新しい順に 300 件ずつ読んで拾うため、ずっと前に最後に変更されたメモリでは、**古い変更を読み込む**（押すたびに 300 件、最初の変更まで）を押すまで足りないことがあり、古い変更が残っている間はその旨を示します。**「変更」ですべて見る**で「変更」の表示を開きます。保存は、エージェントの保存と同じ版の確認と秘密情報のスキャンを通り、
  あなたが書いたものとして記録され、「変更」の表示から取り消せます。プロジェクトに書けるのは、そのプロジェクトに
  既にメモリがあるときだけです。編集しても、メモリが限定されているエージェントの種類は変わりません。ピン・
  revert・忘れさせる・保存には Control Plane が署名し、Workspace はその署名があるときだけ受け付けるので、
  Workspace 内のセッションがあなたとしてこれらを行うことはできません。Workspace の起動から
  30 秒ほどは、1 分ほどして再試行するよう求められます。

- **履歴から消去…**：**忘れさせる**は隠すだけで、以前のテキストは履歴とすべてのエクスポートに残ります。
  **履歴から消去…**（メモリの詳細の**その他の操作**の中と、忘れさせたメモリの行と詳細にあります）は、メモリの過去の版をこのワークスペース
  から完全に削除します。ダイアログに、書き換える内容がテキストなしで先に出ます：このメモリの変更記録が何件
  消えるか、過去の版を含むほかのスナップショットが何件か、どの履歴に触れるか（本流の履歴・取り込んだ履歴・
  以前の履歴の退避コピー）、過去の版でシークレットスキャンが検出したもの（ルール・行・マスクしたヒントだけ）。
  確認のため、メモリの名前を入力します。行われること：メモリのファイルをすべての履歴のすべてのコミット
  から取り除き、それだけを含んでいたコミットは捨てます。どこからも辿れなくなったオブジェクトはガベージ
  コレクションし、消した版がディスクから消えたことを一つずつ確かめます。メモリの**現在のテキストは残る**ので、
  メモリと履歴は食い違いません。現在のテキストを消したいときは、先にメモリを編集してから消去してください
  （古いテキストが過去の版になります）。忘れさせたメモリは、忘れた記録を含むすべての版が消え、あとから忘却を取り消す
  ことはできません。ほかのメモリの履歴と、その元に戻す操作には影響しません。消去後、そのメモリに残る変更は元に戻せません
  （戻る先がないため）。忘れさせることはできます。**すでに作ったエクスポートは取り消せません**：ダウンロード
  したバンドル（全履歴）やアーカイブ、ほかの場所へコピーしたものには古いテキストが残るので、自分で削除して
  ください。中断した書き出し・取り込みがワークスペース内に残した一時ファイルは、消去が取り除きます。消去は revert や保存と同じく Control Plane の署名を要するのでセッションからは始められず、
  Control Plane は `memory.entry.purge` として、プロジェクトだけを記録します（メモリの名前や本文は記録しません）。
  プレビューのあとで履歴が変わったときは、確認し直すよう求められます。

### 変更

一覧には最新 100 件の変更が新しい順に並び、いつ・どのエージェントとセッションが・何をしたかが分かります。**古い変更を読み込む**で 100 件ずつ、最初の変更まで遡れます。ターミナルでは `af-memory changes --limit N` で 300 件まで見られます。メモリの最新の変更では**元に戻す**（前の内容に戻る）か**このメモリを忘れさせる**ことができ、どちらも新しい変更として記録されるので、これ自体も取り消せます。戻す内容に秘密情報らしき記述があると、伏せた検出結果が示され、確認を求められます。

過去のメモリレビュー（レビューの廃止前のもの。下の説明を参照）が公開した変更（作者 `review`）では、**このレビューの変更を元に戻す**が使えます。そのレビューが公開したものをすべて、新しい変更として元に戻します。そのあとで誰かが変更したメモリは戻しません。編集されて残ったものは理由つきで結果に示され、もう一度実行すると残りだけを試します。元に戻せるのはあなただけです。Control Plane がこの要求に署名し、Workspace はセッションからのものを拒否します。Control Plane は（本文なしで）監査ログへ記録します。

### 取り込み・書き出し

Claude Code・muse・バンドルからの取り込み、Claude Code への書き戻し、なくなったプロジェクトのメモリの移動は、
[メモリを取り込む・書き出す](../user/memory/import-export.ja.md) にあります。

### リントレポート

**取り込み・書き出し → メモリのリントレポート**（ターミナルでは `af-memory lint [--user | --project <id|名前>] [--json]`）は、
1 つの範囲のメモリを点検するだけで、何も書き込みません。メモリは変更されず、読み取りは使用回数に数えず、作業コピーにも
触れません。メモリごとに次を報告します。

- 存在しないメモリへの `[[リンク]]`
- プロジェクトの既定ブランチにないリポジトリのパス（最初のフォルダがリポジトリに実在するパスだけが対象）、バッククォートで
  囲んだ `Test*` やコードらしい `シンボル`、`ADR 0123`
- **廃止した用語**の一覧（1 行に 1 語。同じパネルで編集。大文字小文字は区別せず、英単語は語の境界で照合）にある語。
  一覧に自動で何かが加わることはありません
- 4,096 バイトを超える本文（ほかのセッションが想起で見る範囲）

リポジトリは作業コピーではなく、リポジトリの git ディレクトリにある `origin` の既定ブランチを ref で読みます。fetch は
しないので、レポートには読んだ ref とコミットが出ます。古いクローンなら答えも古くなります。git のないプロジェクト、孤立した
プロジェクト（作業コピーがない）、ユーザー範囲はリンク・用語・サイズの検査だけで、省略したものはレポートに書かれます。名前を
変えたパスや名前は「ない」と報告されるので、指摘は断定ではなく問いとして読んでください。

パネル（と `af-memory lint`）には、同じ既定ブランチから読み取った**廃止した用語の提案**も出ます。完全に置き換えられた ADR の
名前、または最近のコミットで削除されて以降どのファイルにも出てこない `AF_*` キーです。根拠（ADR のステータス行、またはコミット）
が付き、そのスコープのメモリが使っている語だけが出ます。提案が自動で一覧に入ることはありません。**一覧に追加**で追記され、
**却下**すると覚えておいて二度と提案しません。

### リントと読み手からの理由

`af-memory lint --apply`（範囲の指定は同じ）は、レポートの結果を書き込みます。リンク・パス・シンボル・ADR・廃止用語の指摘は
メモリの `reasons` に入り（サイズの指摘は入りません）、そのメモリはエージェントが読むどこでも「疑わしい」と表示され、Claude への
書き戻しからも外れます。メモリごとに `lint` を作者とする 1 コミットで、リビジョンも 1 上がります。点検した時のリビジョンのままの
メモリにだけ書き、1 回に書くのは最大 100 件で、もう一度実行すると続きを書きます。リントの理由は、その後に誰かがメモリを変更し、
かつそのルールが当てはまらなくなったときに外れます。実行できなかったルール（リポジトリがない場合）は何も外しません。
無くなったパスが既定ブランチの git のリネームで移っていた場合は、本文（と `anchors`）のそのパスだけを置き換えます。リネームした
コミットを記録した別コミットで、ほかの変更と同じように元に戻せます。

**定期実行のリント（オプトイン）。** 設定 › エージェントメモリ › **設定** › 「lint の自動マーク」をオンにすると、
`af-memory lint --apply` と同じことを、ユーザー範囲とメモリのある全プロジェクトに対して自動で行います。コマンドを実行しなくても理由が付きます。
**既定はオフ**で、エージェントメモリがオンであることも必要です。オンにできるのは Console だけです（セッション自身のトークンでは
できません）。リントはモデルを使わずトークンも使わないため、「自動整理（提案）」のスイッチとは別です。実行を始めるのは、動作中のセッションが
なく、15 分間どのセッションもターンを実行していないときだけで、最短でも 6 時間おきです（100 件の上限で書き残しがあったときは 30 分後）。
実行中にセッションが動き出したら、範囲の切れ目で止まります。100 件の上限は 1 回の実行全体にかかります。失敗した実行は 15 分後に再試行し、
最大 6 時間まで間隔を倍にします。手動の `af-memory lint --apply` と自動の実行は重なりません。自動実行中に手動で始めると
「実行中です」と断られるので、終わってからもう一度実行してください。全範囲の実行の途中で断られた場合も、済んだ範囲の変更は残り、もう一度実行すれば残りが終わります。スイッチも実行の間隔もワークスペースの再起動をまたいで保たれます。

メモリに裏切られたエージェントは `memory_feedback`（読んだリビジョン、`stale` か `wrong`、メモ）で報告します。現在のリビジョンへの
報告は `feedback` の理由になり、本文を変更すると消えます。古いリビジョンへの報告は観察として残るだけです。数えるのは 1 セッション・
1 リビジョンにつき 1 件です。確認（confirmed）は数えますが理由は消さず、エージェントに求めるのは否定的な報告だけです。

### 統合の提案（任意）

Agent Fleet はバックグラウンドでメモリを整えられます。読み手とリントの報告（`stale` / `wrong` の理由、リントの理由、廃止した 0117 の
レビューが答えを出せないまま残した提案）を集めてメモリごとにまとめ、理由があるときだけモデルに**小さなパッチ**（全面書き換えではない）を
頼みます。**あなたの承認なしにメモリへ書かれることはありません**。実行が積むのは「提案」だけです。

- **オンにする。** 設定 › エージェントメモリ › **設定** の「メモリの自動整理（提案）」です。**既定はオフ**で、エージェントメモリが
  オンであることも必要です。オンにするとメモリの文面がモデルに送られ、ワークスペースが空いている間にトークンを使います。切り替えられるのは
  Console だけです（セッション自身のトークンではできません）。スイッチの下の**状況**に、前回の実行、次に実行できる最短の時刻、承認待ちの件数、
  そして熟しているのに先送りされているトピックと理由（トークン予算、ワークスペース停止、アイドルにならない、次の実行待ち、実行の失敗）が出ます。1 回の予算にはどうしても収まらない話題（既定の 60k で約 180 KB 以上のメモ）は、待たされ続けるのでなく
  見積もりつきで *too-large*（大きすぎる）と出ます。メモを減らすか予算を上げれば、次の実行が取り込みます。
- **いつ動くか。** どのセッションも 15 分間ターンを実行しておらず、3 時間に 1 回まで、「熟した」話題だけです。熟したとは、`wrong` か `stale` の
  報告が 1 件、または新しい観察が 3 件、または 24 時間待っている観察があること。1 回の実行が使うトークンには上限があり、収まらない分は
  次回に回ります（理由は状況表示に出ます: 予算、ワークスペース停止、アイドルにならない）。実行中にターンが始まったら、進行中のモデル呼び出しは
  終えて残りは先送りします。数値はキューの隣の `config.json`（メモリストアの作業ディレクトリ `af-memory.work/consolidation/`）、モデルは同じ場所の
  `models.json` にあります（既定は `small` が `claude:haiku`、`large` が `claude:sonnet`。置き換えと統合は `large` に回ります）。
- **今すぐ実行（手動）。** セッションが一日中動いていると、自動の実行がなかなか来ないことがあります。状況の横の**今すぐ実行**で、自分で
  実行を始められます。先に確認が出ます（モデルを呼び、トークンを使うこと、1 回の予算を示します）。アイドルの確認と 3 時間の間隔は無視し、
  ほかのセッションのターンでは止まりません。それ以外は自動の実行と同じです（スイッチがオン、トークン予算、検証、承認まで何も書かない）。
  既定では熟したトピックだけを対象にし、*まだ時期でないトピックも含める*にチェックすると待機中のすべて（すでに提案が待っているトピックは除く）が対象です。
  要求はすぐ返り、状況に進み具合（「トピック n / m」）と、そのあとに報告が出ます。同時に動く実行は 1 つで、2 つ目の要求は待たされずに断られます。
  手動の実行は、自動の 3 時間の枠を消費もリセットもしません。始められるのは Console のあなただけで、セッションからはできません。
- **提案の中身。** 1 つのメモリへの*パッチ*（完全一致の置換で、現在のリビジョンに当たることを確認済み）、*新規作成*（以前の 0117 の提案が持っていたもの、
  または本文候補のない*追加*に対して大きいモデルが書いた新しいメモリ）、そして*置き換え・統合*に対する*置き換え*（大きいモデルが新しいメモリを 1 件書き、
  置き換え対象のメモリは「置き換え済み」になって Agent から見えなくなります。履歴には残ります）。忘れられた名前、または一度でも存在した名前
  （置き換え済みのメモリも名前を持ち続けます）への新規作成・置き換えは拒否されます。大きいモデルの文面が検証に通らなかったときは、
  手で適用していただく*助言*になります。
- **古くなったメモリの退役。** 4 つ目の種類として*退役*があります。メモリ全体が古くなった（Agent に追わせている Issue が閉じた、
  回避策がもう要らない、など）と伝えるものです。承認すると、そのメモリを `consolidator` による*アーカイブ済み*にし、1 行の理由を残します。
  Agent は索引にも検索にもそのメモリを見なくなり、`memory_read` は本文の代わりに理由つきの要約を返します。**何も削除しません**：
  ファイルは残り、「変更」の 1 件として並び、（その後メモリが変わっていなければ）元に戻すとそのままの状態で復活します。
  ピン留めされたメモリは提案で退役されません（助言になります）。退役は、大きいモデルが確認してはじめて提案されます。
- **確認済みの事実。** モデルが判断する前に、Agent 自身が、メモリや観測が名指しする Issue・プルリクエスト
  （`owner/repo#12`、github.com のリンク、origin が github.com のプロジェクトでの `#12`）が closed / merged かどうかを、あなたの
  GitHub 接続で調べ、事実としてモデルに伝えます。古いレビューから書き出された観測が、数週間前に閉じた Issue を引いている場合は、
  「終わった作業を引いている」と印が付き、モデルはそのメモリを作らず*変更なし*に傾きます。調査に失敗した・時間切れ・未接続のときは
  *不明*として扱い、closed とは決して読みません。調査は 1 回の実行ごとに件数が限られ、キャッシュされます。
- **承認。** 承認の時点のメモリに対して再検証します（提案が触れるすべてのメモリを、それぞれ提案時のリビジョンと照合し、1 つでも動いていたら何も書きません）。
  通すと、通常の経路で `consolidator` を作者として公開します。**変更**に現れ、元に戻せます。置き換えは、新しいメモリと置き換え対象のすべてをまとめた
  *1 つの*変更で、行に対象の名前が並び、1 回の取り消しで全部戻ります。対象のどれかがその後に変わっていれば、取り消せません。
  14 日間決めなかった提案は期限切れになり（記録は残ります）、期限切れだけでは話題は戻りません。新しい証拠、メモリの変更、明示的な再試行で戻ります。

**確認する。** メモリビューの **提案** タブに提案が並びます。*承認待ち*、*処理済み*（承認・却下・適用不可・一部適用）、*期限切れ*で絞り込めます。
提案の題名は、まとめられた話題ではなく、変更の対象（作る・変更するメモリの名前）です。話題のメモリは無関係なこともあるため、下の小さな行に出します。
開くと、承認ボタンの前に **承認するとどうなるか** が出ます。

- 1 行の要約：「承認すると、メモリを 2 件追加します。既存のメモリは変わりません。」「承認すると、メモリ 1 件を変更します（adr-0094, リビジョン 2 → 3）。」
- 項目ごとのカード。*作成*は**新しいメモリ**のカードで、範囲・名前・種類・説明と、読める形の本文を出します。話題のメモリが作成の対象でないときは
  「話題のメモリ「…」は変更されません」と添えます。*パッチ*は、対象のリビジョン n → n+1 を**変更前**と**変更後**の左右に並べ、消える行と増える行を色で示し、
  作成者「consolidator」として書き込まれ、「変更」の一覧から元に戻せることを添えます。*置き換え*は、新しいメモリと、置き換える対象（リビジョン付き）を示し、1 つの変更として公開・取り消しされることを添えます。*退役*は、Agent から見えなくなるもの（索引の行、検索に出なくなること、読んだときに返る理由、隠れる本文を削除行で）を示します。*助言*は、実行すると何が起きるかと、承認できないことを示します。
- そのあとに根拠（元になった報告やリントの指摘）と、作成時に見たリビジョンが続きます。

- **承認**はその 1 件だけを適用します。書き込む内容を示す確認が先に出ます。まとめて承認することも、待つだけで承認されることも、通知から
  承認することもありません。毎日の通知は、この画面を開くだけです。
- **却下**で捨てます。**再検討**（却下・期限切れ・適用不可・一部適用の提案に出ます）は、その観測を開き直し、あとの実行でトピックを見直させます。
  新しい提案は最初から検証されます。
- **断られた理由は文章で出ます。** 提案の作成後にメモリが変わった（リビジョンの不一致）、期限切れ、または処理済みのとき、承認は
  汎用のエラーではなくその旨を伝えます。古くなった提案は承認できず、*適用不可*になります。*再検討*を使ってください。
- **助言のみ。** 大きいモデルが書いた置き換えや新しいメモリが検証に通らなかったとき（以前に使われた名前、スキーマや秘密情報スキャンの不合格、
  存在しないメモリへのリンク、不正な応答）は*助言のみ*と表示され、承認ボタンはありません。内容を読んで、**メモリ**から手で直してください。

**毎日の通知。** スイッチがオンで、承認待ちが 1 件でもある間、通知は 1 日に 1 回までです。「承認待ちのメモリの提案が N 件あります」。
件数だけを載せ（メモリの文面は載せません）、開くとメモリビューの**提案**に移ります。通知設定（設定 › 通知 › その他）では他の通知と同じく既定でオンです。

### 設定

**既定はオフ**です。先にこの表示の先頭の「セッションに Agent Fleet のメモリを使わせる」をオンにしてください（オンは次に起動するセッションから効き、オフは起動中のセッションの読み書きもその場で断ります。「メモリ」「変更」の表示はオフでも使えます）。オンの間は、各種類の指示ファイルに「このツールがあること・いつ呼ぶか」の短い固定の注意書きも入ります（記憶そのものは入らず、オフにするとあなた自身の文章には触れずにその部分だけ消えます）。ローカルモデル（lcpp）のセッションは、システムプロンプトにそのプロジェクトのメモリ一覧も最初から載ります。Cursor には指示ファイルを置ける場所がないため、同じ案内はツールの説明に入っています。保存は**承認なしで**すぐ共有され、秘密情報らしき記述は拒否されます。

- **Claude Code 自身のメモリ**：スイッチが自動で引き継ぎます。「セッションに Agent Fleet のメモリを使わせる」を
  切り替えると、先にプレビューの件数つきで確認を求めます。オンにするときは **Agent Fleet のメモリをオンにしますか？** に、
  今すぐ取り込むプロジェクトとメモリの件数、秘密情報らしき記述でスキップする Claude のファイルの件数が出ます（**オンにして取り込む**）。
  オフにするときは **Agent Fleet のメモリをオフにしますか？** に、Claude のメモリのスナップショットを先に取って上書きせずに書き戻す件数が
  出ます（**オフにして書き戻す**）。ワークスペースが停止中のときは件数はまだ出ず、起動した時点で取り込み／書き戻しを行います。
  **オン**：`~/repos` の作業コピーに対応づけられる Claude のプロジェクトをすべて、Agent Fleet がバックグラウンドで
  取り込み、以後に起動する Claude セッション（とアシスタントのチャットの claude）は Claude Code の自動メモリを切った状態で動きます。Claude は自前の
  `MEMORY.md`（毎セッションの開始時に約 25 KB）を読み込まず、ほかの種類と同じく af のツールを使います。自動の取り込みは「取り込み・書き出し」の
  **Claude Code から取り込む**より厳しく、*ここで編集した* Agent Fleet のコピーより新しい Claude のファイルは、競合として報告するだけで
  上書きしません（手動の取り込みは、あなた自身の選択として従来どおり上書きします）。忘れたメモリは戻さず、秘密情報らしき記述を含む
  ファイルはスキップして一覧に出します。すでに動いていた Claude セッションは自前のメモリを使い続け、そのうち最後の 1 つが終わった時点で、
  保存された内容をもう一度取り込みます。**オフ**：Agent Fleet がすべてのプロジェクトを Claude Code のメモリへ書き戻し
  （「取り込み・書き出し」の**Claude Code へ書き戻す**と同じ規則：先にスナップショット、上書きなし、競合と秘密情報は残して一覧に出す）、
  それが終わるまで Claude Code 自身のメモリは切ったままです。間に起動したセッションが、書き戻しとぶつかるファイルを書かないようにするためです。
  書き戻しが失敗し続けるときも Claude Code のメモリは切ったままで、Agent Fleet は間隔を延ばしながら再試行します。このとき画面に
  **今すぐ再試行**と**それでもネイティブメモリをオンに戻す**が出ます。スイッチの下には、実行の進み具合、前回の結果、残したファイル
  （競合・スキップした秘密情報）が表示され、残りがあれば通知が 1 件届きます。この処理はワークスペースを再起動しても続きます：
  記録した段階から再開し、停止中にスイッチが変わっていても、起動した時点で引き継ぎます。Codex：スイッチをオンにすると codex 自身の
  `features.memories` を切り、オフにすると元の値に戻します（オンにはしません）。codex への取り込みも書き込みもありません。
  オンの間にそのフラグを自分で変えたときは、その値が戻されます。変更後に*起動した* Claude セッションだけが対象で、
  起動中のセッションは起動時のままです。

- **Muse Code 自身のメモリ**：スイッチがオンの間、Agent Fleet は Muse Code をネイティブメモリを切った状態で起動します。Muse には `read_memory` / `add_memory` / `edit_memory`
  のツールも、コンテキスト内のメモリのスナップショットも、プロンプトの「永続メモリを使う」段落もなく、
  ほかの種類と同じく af のツールを使います。スイッチがオンの間は、自分の環境にネイティブメモリの設定があってもこちらが
  優先されます。オフのときは何も変えず、Muse の既定のままです。対象は Muse のセッションとアシスタント
  チャットです。変更後に*起動した* Muse ホストだけが対象で、起動中のセッションは起動時のままです。

- **Agent Fleet の外から使う**（設定「Agent Fleet の外からメモリを使わせる」。**既定ではオフ**で、上のスイッチとは独立。**読み取りのみ**か**読み書き**）：
  別のマシンにあるあなた自身の Claude Code や Claude Desktop、または OAuth で接続したアプリ（claude.ai など）に、Control Plane の `/mcp`（またはメモリ専用の `/mcp/memory`）経由でこのメモリを使わせます。
  設定はあなた自身のものですが、テナント管理者はテナント全体で止められます。何ができて何が記録されるかは
  [外部のエージェントから Agent Fleet のメモリを使う](#外部のエージェントから-agent-fleet-のメモリを使う)にあります。

- **バックグラウンドのメモリレビューは廃止されました。** 以前のバージョンには、終わったセッションからメモリを提案させる機能
  （設定「終わったセッションからメモリを提案させる」「自動でも提案させる」、セッションの ⋯ メニューの
  「メモリを提案させる（今すぐ）」、変更 › 提案）がありました。今は設定・ボタン・通知・ルートのどれもなく、「AI 補助」の
  メモリのバックグラウンドレビューのカードもありません。公開済みの変更は変更一覧に残り、元に戻せます（[変更](#変更)）。
  アップグレード時にまだ承認待ちだった提案は**捨てていません**：アップグレード後の最初の起動で一度だけ、Workspace が各提案
  （対象のメモリ、基準にした版、本文、理由、実行の ID）と却下済みの指紋の一覧を、Claude の設定ディレクトリの `af-memory.work`
  フォルダにある `review-queue-export-v1.json` へ書き出し、そのあとで待ち行列を削除します。これは観察であって承認ではありません。
  このファイルの内容はメモリに入っていません。読むのは、オンにしたときの[メモリの自動整理](#統合の提案任意)だけで、提案の材料にします。レビューを使っていなかった Workspace では何も書きません。
