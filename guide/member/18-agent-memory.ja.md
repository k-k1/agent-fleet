# 18. エージェントメモリ — エージェントが覚えること、その管理

[English](18-agent-memory.md) | 日本語

覚えた内容を残す機能は 2 つあります。**エージェントメモリ**は、どの種類のエージェントも共有する Agent Fleet 自身のメモリです。
**メモリのスナップショット**は、エージェントが自前のファイルに貯めるメモリを版管理します。どちらも ⚙設定 の中のページです。

## エージェントメモリ

Agent Fleet 自身の共有メモリです。どの種類のエージェントも af のツール `memory_index` / `memory_search` / `memory_read` /
`memory_save` / `memory_patch` / `memory_feedback` / `memory_forget` で読み書きします。プロジェクトごと（worktree はリポジトリのものを共有）と、全プロジェクト
共通の範囲があり、エージェントの種類を替えても、引き継いでも、別の種類の子セッションでも、学んだことが残ります。
**既定はオフ**です。オンにするのは[設定](#設定)の表示です。エージェントが自前のファイルに貯めるメモリの版管理は、この先の[メモリのスナップショット](#メモリのスナップショット)です。

先頭に状態の行が 1 本あります（オンかオフか、プロジェクト何件にメモリ何件か、最後に変わった時刻、Claude Code との
バックグラウンド同期に確認が必要なときは警告と「設定」への案内）。その下に 2 つの表示があります：
**設定 · 取り込み・書き出し**。最後に開いた表示は覚えています。ワークスペースが停止中に使えるのは
**設定**だけで（スイッチは次の起動に向けて保存されます）、もう一方の表示には「ワークスペースを起動」が出ます。スマートフォンや縦向きのタブレットでも
タブは 1 行のままで、収まらないときは横にスクロールします。矢印キー、Home、End でタブを移れます。

**メモリビュー。** 本文や差分、一覧を並べて読むには、ダイアログは狭すぎます。そこで**メモリ**・**変更**・**提案**は、画像ギャラリーと同じように
専用のペイン（*メモリ*タブ）で開きます。設定 › エージェントメモリの先頭の**メモリビューを開く**、毎日の通知（**提案**に移ります）、
コマンドパレットのメモリから開けます。メモリビューはワークスペースに 1 つで、もう一度開くと今あるものに移ります。使い方は
以下の各表示と同じで、この章の**メモリ**・**変更**・**提案**の節は、このビューの 3 つのタブのことです。

### メモリ

- **一覧と詳細**：左の一覧に、**すべての範囲**（既定。ユーザー共通と全プロジェクトをまとめ、各行に所属を表示）、または 1 つの範囲（全プロジェクトに配布される**ユーザー共通**、または 1 プロジェクト）のメモリを、作成者・最終更新・エージェントに読まれた回数・**ピン留め**の印とともに表示します。**すべて**・**ピン留め**・**忘れさせた**のチップで絞り込めます。検索は、入力したすべての語（順不同）が、名前・説明・種別・作成者・作成者のセッションを合わせた中にあるメモリを即時に探します。入力が止まると本文も探し、本文だけで見つかったメモリはそのあとに、エージェントの `memory_search` と同じ順位付けで並びます。すべての語を含むメモリがないときは、本文検索が一部の語を含むものを返し、一覧にはそれだけを「一部の語のみ」の注記つきで表示します（名前・説明・種別・作成者がすべての語に当たるメモリがあれば、それが優先されます）。検索は「読まれた回数」に数えません。コマンドパレットの **「メモリ」** の範囲でも、どの画面からでも同じメモリを検索できます（[02](02-console-basics.ja.md#メモリ)）。行を選ぶと右にそのメモリが開き、本文・範囲・種別・作成者・更新・使用回数と、**編集**・**ピン留め** / **ピンを外す**・**このメモリを忘れさせる**、**その他の操作**（⋯）の中の**履歴から消去…**が出ます。**新しいメモリ**（表示中の範囲に作ります。すべての範囲を表示中はユーザー共通）と**編集**のフォームも同じ場所に開きます。選んだ範囲・チップ・メモリは、表示を行き来する間は覚えていて、ページを再読み込みすると忘れます。スマートフォンでは一覧と詳細が別の画面になり、行を選ぶと詳細が開き、**一覧に戻る**（または Escape）で戻ります。名前またはテキストが秘密情報らしいメモリは一覧に出さず、件数だけ表示します。

- **ピン留めしたメモリ**：詳細で**ピン留め**したメモリは、エージェントが作業開始時に読む索引の先頭に、ほかより前に必ず載ります。**ピンを外す**と元に戻ります。**ピン留め**のチップで一覧できます。それ以外は、種別（feedback・
  user のメモリが先）→ 読まれた回数（読み取りと、返された検索ヒットを数えます）→ 新しさの順です。ピンも索引の
  サイズ上限（説明つきの行で約 24 KiB。索引では説明を 150 文字で切り、`memory_read` は全文を返します）を共有するため、ピンだけで収まらないときは末尾のものが名前だけの一覧に落ち、エージェントにもそう伝わります。
  全セッションに必要なものだけを留めてください。`memory_search` のヒットも関連度順です（クエリの語が多く当たるものが先、次に名前 ＞ 説明 ＞ 本文の順、次にピン・読まれた回数・新しさ）。全語を含むメモリがないときは、一部の語を含むものを返し、その旨を示します。ピンは「ピン変更」としてあなたの変更に記録され、元に戻せます。
  ピン留め済みのメモリをエージェントが後で更新してもピンは残り、af のメモリツールにはピンを付け外しする手段がありません。

- **種別とライフサイクルのフィールド（任意）**：メモリのファイルには `kind`（`preference`・`lesson`・`procedure`・`state`・`log`：古くなり方）、`anchors`（依存するパス・シンボル・テスト名・ADR 番号・コマンド）、そしてライフサイクルとして `status`（`active`・`quiet`・`archived`）と `status_by`、`superseded_by`（メモリ、またはリポジトリの文書）、`invalid_at`、`reasons`（未解決の疑い。1 つでもあるメモリは「要確認」）を付けられます。エージェントが `memory_save` で設定できるのは `kind` と `anchors` だけです（省略すると今の値を保ちます）。ライフサイクルのフィールドは lint・フィードバック・統合処理・あなたが設定し、エージェントや取り込みが設定することはありません。どれも付いていないメモリは従来どおり動きます。エージェントに見えるものは、どの経路（`memory_index`・`memory_search`・`memory_read`・外部メモリのツール・ローカルモデルのセッションのプロンプト・Claude への書き戻し）でも同じ規則で決まります。**アーカイブ済み**または**置き換え済み**のメモリは、索引にも検索にも注入にも出ず、`memory_read` は本文の代わりに stub（名前・状態・置き換え先・理由）を返します。**quiet** のメモリと `log` は、ピン留めしていても索引の説明つき部分には載りませんが、名前だけの一覧・検索・`memory_read` には出ます。**要確認**のメモリは、すべての行・ヒット・読み取りに理由が付きます。あなた自身の画面（一覧・履歴・差分・復元・書き出し）はすべてを表示します。Claude への書き戻しは、アーカイブ済み・置き換え済み・quiet・log・要確認のメモリを書かず、以前に Agent Fleet が書いた写しは、そのメモリが対象から外れた時点で**削除**します（プレビューでは **remove**）。Claude 側で編集した写しは残し、競合として表示し、`MEMORY.md` にも載せません。変更を元に戻すと、これらのフィールドも含めて以前の版がそのまま戻ります。

- **忘れさせる・忘却を取り消す・履歴**：**このメモリを忘れさせる**と全エージェントから見えなくなり、**忘れさせた**のチップに並んだものは、行または詳細から**忘却を取り消す**ことができます（直前のテキストに戻ります。今は秘密情報に見えるテキストは、確認できる「変更」の表示で、その忘却に**この変更を元に戻す**を使ってください）。どちらも「変更」の表示と同じ元に戻す・忘れさせるで、あなたの操作として記録され、取り消せます。
  忘れさせるは、履歴に変更がある一覧のどのメモリにも使えます（押したときに最新の変更を探すので、古くても構いません）。手で置いたメモリのファイルのように履歴に変更がないものは、ここからは忘れさせられません。**忘れさせた**には、選んだ範囲（初期値はすべての範囲）で忘れさせたメモリが、
  いつ忘れさせたものでも新しい順に 300 件ずつ出て、**古い忘れさせたメモリを読み込む**で次の 300 件を、末尾まで読めます。忘れさせたメモリが非常に多い（約 2000 件を超える）ときは 1 回の読み込みでは全件を確認できず、その旨を表示します。表示していない件数は最小値で、古いものは読み込むごとに確認します。詳細の下の**このメモリの履歴**には、そのメモリ自身の変更が並び、選ぶと「変更」の表示と同じ差分が出ます。全メモリの変更を新しい順に 300 件ずつ読んで拾うため、ずっと前に最後に変更されたメモリでは、**古い変更を読み込む**（押すたびに 300 件、最初の変更まで）を押すまで足りないことがあり、古い変更が残っている間はその旨を示します。**「変更」ですべて見る**で「変更」の表示を開きます。保存は、エージェントの保存と同じ版の確認と秘密情報のスキャンを通り、
  あなたが書いたものとして記録され、「変更」の表示から取り消せます。プロジェクトに書けるのは、そのプロジェクトに
  既にメモリがあるときだけです。編集しても、メモリが限定されているエージェントの種類は変わりません。ピン・
  revert・忘れさせる・保存には Control Plane が署名し、Workspace はその署名があるときだけ受け付けるので、
  Workspace 内のセッションがあなたとしてこれらを行うことはできません。Workspace の起動から
  30 秒ほどは、1 分ほどして再試行するよう求められます。

- **履歴から消去…**：**忘れさせる**は隠すだけで、以前のテキストは履歴とすべてのエクスポートに残ります。
  **履歴から消去…**（メモリの詳細の**その他の操作**の中と、忘れさせたメモリの行と詳細にあります）は、メモリの過去の版をこのワークスペース
  から完全に削除します。ダイアログに、書き換える内容がテキストなしで先に出ます：このメモリの変更記録が何件
  消えるか、過去の版を含むほかのスナップショットが何件か、どの履歴に触れるか（本流の履歴・取り込んだ履歴・
  以前の履歴の退避コピー）、過去の版でシークレットスキャンが検出したもの（ルール・行・マスクしたヒントだけ）。
  確認のため、メモリの名前を入力します。行われること：メモリのファイルをすべての履歴のすべてのコミット
  から取り除き、それだけを含んでいたコミットは捨てます。どこからも辿れなくなったオブジェクトはガベージ
  コレクションし、消した版がディスクから消えたことを一つずつ確かめます。メモリの**現在のテキストは残る**ので、
  メモリと履歴は食い違いません。現在のテキストを消したいときは、先にメモリを編集してから消去してください
  （古いテキストが過去の版になります）。忘れさせたメモリは、忘れた記録を含むすべての版が消え、あとから忘却を取り消す
  ことはできません。ほかのメモリの履歴と、その元に戻す操作には影響しません。消去後、そのメモリに残る変更は元に戻せません
  （戻る先がないため）。忘れさせることはできます。**すでに作ったエクスポートは取り消せません**：ダウンロード
  したバンドル（全履歴）やアーカイブ、ほかの場所へコピーしたものには古いテキストが残るので、自分で削除して
  ください。中断した書き出し・取り込みがワークスペース内に残した一時ファイルは、消去が取り除きます。消去は revert や保存と同じく Control Plane の署名を要するのでセッションからは始められず、
  Control Plane は `memory.entry.purge` として、プロジェクトだけを記録します（メモリの名前や本文は記録しません）。
  プレビューのあとで履歴が変わったときは、確認し直すよう求められます。

### 変更

一覧には最新 100 件の変更が新しい順に並び、いつ・どのエージェントとセッションが・何をしたかが分かります。**古い変更を読み込む**で 100 件ずつ、最初の変更まで遡れます。ターミナルでは `af-memory changes --limit N` で 300 件まで見られます。メモリの最新の変更では**元に戻す**（前の内容に戻る）か**このメモリを忘れさせる**ことができ、どちらも新しい変更として記録されるので、これ自体も取り消せます。戻す内容に秘密情報らしき記述があると、伏せた検出結果が示され、確認を求められます。

過去のメモリレビュー（レビューの廃止前のもの。下の説明を参照）が公開した変更（作者 `review`）では、**このレビューの変更を元に戻す**が使えます。そのレビューが公開したものをすべて、新しい変更として元に戻します。そのあとで誰かが変更したメモリは戻しません。編集されて残ったものは理由つきで結果に示され、もう一度実行すると残りだけを試します。元に戻せるのはあなただけです。Control Plane がこの要求に署名し、Workspace はセッションからのものを拒否します。Control Plane は（本文なしで）監査ログへ記録します。

### 取り込み・書き出し

取り込み・書き出しは、ソースごとのカードを並べたハブです。**取り込み**（Claude Code から取り込む・muse から取り込む・このバンドルの Agent Fleet のメモリ）、**書き出し**（Claude Code へ書き戻す）、**メンテナンス**（なくなったプロジェクトのメモリを移す）の 3 グループがあり、**開始**を押すとハブの代わりにそのソースのウィザードが開きます。どのウィザードも同じ枠で、手順の表示（**元の選択**・**プレビュー**・**確認**・**適用**・**結果**）、状態ごとにまとめて件数を付けたプレビュー、**キャンセル**（適用中は押せません。終わると**取り込み・書き出しに戻る**に変わります）が付きます。

- **Claude Code から取り込む**：Claude Code がプロジェクトごとに溜めたメモリを Agent Fleet の
  メモリへ一度だけ取り込めます。プロジェクトを選ぶと、何も書く前に結果が見えます：**新規**、
  **Claude 側が新しい**（Agent Fleet 側の写しを上書きします。取り込み後に自分で直していても上書きされるので、
  両方の時刻を表示します）、**変更なし**、**忘れ済み**（忘れた、または取り込みを取り消したメモリは二度と
  戻りません）、**秘密情報の疑い**（取り込まず、伏せた検出結果を表示。Claude 側のファイルを直して
  プレビューし直してください。通す手段はありません）、**取り込めない**（理由つき）。何も切り詰めません。
  `_` や `.` を含む名前、2,000 文字までの説明、200 KiB までの本文、長い行はそのまま取り込みます。
  名前・説明・本文がそれらの上限を満たし（200 KiB は本文の上限です）、通常のテキストファイルであれば
  取り込めます。満たさないものは理由つきでプレビューに並びます。以前の版が説明を切り詰めて
  取り込んだメモリは**Claude 側が新しい**として表示し、Agent Fleet 側の写しを自分で直していなければ
  Claude のファイルから更新します。Claude のプロジェクトは `~/repos` の作業コピーに
  対応づけ、対応が無い、または 2 つ以上あるものは一覧に出ますが取り込めません。取り込むには Agent Fleet の
  メモリがオンである必要があります（プレビューはオフでも使えます）。取り込んだメモリは「メモリ」の表示に「取り込み」として
  並び、書き手は不明で、ほかの変更と同じく元に戻せます。

- **muse から取り込む**：Muse Code が溜めたメモを Agent Fleet のメモリへ
  一度だけ取り込みます。使い方は Claude Code の取り込みと同じで、フォルダを選び、プレビューを見て、確定します。
  muse には 3 つの保存先があり、選択肢にそれぞれ出ます。**プロジェクトのメモ**（作業コピーの `.agents/memory`。
  そのプロジェクトへ）、**personal project のメモ**（muse 自身の作業コピー別フォルダ
  `~/.local/share/muse/memory/projects/<slug>-<hash>`。`~/repos` 配下で対応する作業コピーのプロジェクトへ。
  どの作業コピーにも合わないフォルダは「作業コピーなし」、別々の 2 プロジェクトに合うものは「複数一致」と出て、
  どちらも取り込めません）、**personal のメモ**（`~/.local/share/muse/memory/personal`）です。personal のメモは
  **すべてのプロジェクトのセッションが読むユーザー全体のメモリ**へ入ることになるため、その旨のチェックボックス
  （ターミナルでは `--into-user`）を入れるまで、プレビューも取り込みもしません。ほかのスコープがユーザー全体の
  メモリへ入ることはありません。メモにフロントマターは要りません（muse は渡された内容をそのまま保存します）。
  名前はファイル名（Agent Fleet の名前として有効でなければ「名前不正」と一覧に出ます）、説明は最初の空でない行
  （2,000 文字で切ります）、種別はなしで、こうしたメモには「フロントマターなし」と付きます。フロントマター付きの
  メモは従来どおり読みます。muse のパスにはフォルダが入り得ます：`a/b.md` はメモリ `a--b` になり、同じ名前に
  なるファイルが 2 つあれば両方とも取り込みません（ノートが 2,000 件を超えるフォルダはプレビューのみで、確認を終えられないため取り込みません）。別の muse ファイル・フォルダ・スコープに由来する同名のメモリは上書きしません。`MEMORY.md`、muse の `.muse-memory.lock`、`.md` 以外は
  メモではなく、シンボリックリンクはたどりません。**新規**は追加し、**muse 側が新しい**ものは、Agent Fleet 側の
  写しがこの取り込みの書いた内容のままである間だけ更新します（取り込み後に Agent Fleet で保存・編集・ピン留め・
  取り消しをしたメモリや、muse 由来でない同名のメモリは**Agent Fleet 側に独自の版あり**として一覧に出し、触りません）。
  忘れたメモリは戻らず、秘密情報の検査に掛かったファイルは取り込まずに一覧へ出します。作成者は不明として記録します。
  `.agents/memory` はリポジトリの中にあり、チームがコミットしていることがあります。git が追跡しているファイルには
  **共有**と付き、確定前にプレビューで警告します。取り込むとチームメンバーの文章が、あなたのセッションが読む
  メモリへ写るためです。Agent Fleet から muse への書き戻しはしません。取り込みの実行にはスイッチのオンが必要で、
  プレビューはオフでも使えます。

- **このバンドルの Agent Fleet のメモリ**：メモリのバンドルに入っている Agent Fleet のメモリを取り込みます。メモリのスナップショットでバンドルを復元しても書き込まれません
  （復元には秘密情報の検査がないため）。**開始**を押すと、手順の最初にバンドルのファイルを選びます（tar.gz には入っていないので受け付けません）。そのあと、プレビューと取り込みを単独で行えます。バンドルの各プロジェクトは、ここのプロジェクトと識別子で対応づけ、
  違う場合（パスが違う）は、リポジトリのアドレスが同じプロジェクトがここにちょうど 1 つあるときだけ対応づけます。対応が
  ないか 2 つ以上ある場合は、一覧に出して取り込みません。ユーザー全体のメモリは常に対象です。各メモリは **新規**・**すでにある**・
  **ここでは内容が違う（そのまま）**（同名のメモリがここにあれば置き換えません）・**ここで忘れ済み（戻しません）**（履歴にしか
  残っていない場合も）・**秘密情報らしき記述（スキップ）**（ファイルのすべての部分を検査し、上書きはできません）・
  **取り込めません**のどれかで表示します。取り込むのは最新の本文と、そのメモリに付いていたエージェントの制限だけで、バンドルの履歴は
  取り込みません。**リセットされるもの**：リビジョン（ここでの次の番号から始まる）、作成者（不明。Claude の取り込みと同じ）、
  日時（取り込んだ時刻）、ピン留め、読まれた回数。出所はメモリの source（`bundle:<取り込み ID>:<プロジェクト>/<名前>@<バンドルのリビジョン>`）と
  コミット（`AF-Bundle-Import`、`AF-Bundle-Source`）に記録するので、取り込みはエージェントメモリの「変更」の表示に出て、そこで元に戻せます。スイッチの
  オン／オフを問わず使え、あなた自身の操作にだけ応じ、監査ログに記録されます。

- **Claude Code へ書き戻す**：逆向きの操作で、手動で 1 プロジェクトずつ行います。
  スイッチをオフにすると全プロジェクトの書き戻しは自動で行われます（[設定](#設定)を参照）。ここは、それが残した競合を解消するときや、
  ネイティブメモリをオンに戻したあとに使います。Agent Fleet 経由で学んだ内容を Claude Code のメモリへ写します
  （対象は Claude Code のみ。codex は含みません）。プロジェクトを選ぶと、書く前に結果が見えます：
  **新規**、**Agent Fleet 側が新しい**（前に書き戻したファイルを更新）、**Agent Fleet で忘れ済み**（前に書き戻した
  ファイルを削除）、**競合**（Agent Fleet が書いていない、または書いた後にあなたが変えた Claude のファイル。
  チェックしない限り残します。取り込んだときのままのファイルは**変更なし**、取り込み後にこちらで
  メモリを直していれば**Agent Fleet 側が新しい**になります）、**秘密情報の疑い**（書かない）、**変更なし**、**Claude にだけある**（消しません）。
  更新しても、Claude がファイルの `metadata` に記録した項目（`originSessionId` など）は残します。そのままは写せない metadata を持つファイルは、更新ではなく競合として表示します。
  ユーザースコープのメモリと、ほかの種類のエージェントに限定したメモリは書きません。`MEMORY.md` は Claude の読み込み上限（200 行・24 KiB）に収めて
  作り直し、古いものを置き換えます。先に Claude のメモリをスナップショット（契機「書き戻し前」）に残すので、
  メモリのスナップショットの履歴から戻せます。スイッチのオン・オフを問わず使えます。オンのときは、オンにする前から動いている
  Claude Code のセッションを先に終了してください。

- **なくなったプロジェクトのメモリを移す**：プロジェクトはリポジトリのフォルダに結び付いているため、改名・移動・
  クローンし直したリポジトリは新しい空のプロジェクトとして始まり、古いほうのメモリはどのセッションからも届かない場所に残ります。
  ここには、作業コピーがなくなったと分かっているプロジェクトを、メモリの件数付きで一覧します（マウントされていないディスク上のフォルダ
  など、判断できないときは一覧に出ません）。1 つ選び、代わりのプロジェクト（メモリを持つか `~/repos` に作業コピーがあるもの）を選んで、
  プレビューを読んでから確定します。移動先ですでに名前が使われているメモリは**決して上書きされません**。そのまま残すか、別の名前
  （`<name>-moved`、次は `<name>-moved-2`、`<name>-moved-3` …）で移すかを選びます。本文が移動先の写しと同一のものは、古い写しが消えるだけです。プレビュー後に変わったメモリや、
  秘密情報らしき内容を含むファイルは古いプロジェクトに残ります。メモリ 1 件ごとに、「変更」の表示に各プロジェクト 1 件ずつ計
  2 件が並ぶので、そこでどちらも取り消せます。途中で止まったときは、もう一度実行してください。何も失われず、止まったところから終わります。
  セッション向けのスイッチがオンでもオフでも使え、Console からだけ実行できます。古いプロジェクトと同じ git の remote（同じ
  リポジトリのクローンし直し）を使う、作業コピーのあるプロジェクトがちょうど 1 つあるときは、**移動を確認する**ボタン付きで提案します。
  ボタンは 2 つの選択欄を埋めてプレビューを出すだけで、確定するまで何も移動しません。同じリポジトリの作業コピーが 2 つあるときは
  提案しないので、移動先は自分で選んでください。Agent Fleet はプロジェクトごとに remote を覚えますが、URL 内のパスワードやトークンは
  保存しません。作業コピーがすでになくなっていたプロジェクトには remote の記録がなく、提案されません。ssh のアドレスは大手のホスティング（GitHub、GitLab、Bitbucket、Codeberg）だけを同一視し、それ以外のサーバーでは https のアドレスだけを比べます。

- **ターミナルから**：`af-memory import-sources`、`af-memory import --project <slug> --dry-run`（プレビュー）、
  `af-memory import --project <slug>`（取り込み）。`af-memory changes [--limit N]` で最新の変更を一覧できます（指定しなければ 30 件）。
  muse 向けは `af-memory muse-import-sources`、`af-memory muse-import --dir <name> [--scope project|personal_project] [--dry-run]`、
  `af-memory muse-import --scope personal --into-user [--dry-run]` です。スイッチと秘密検査は Console と同じです。

- **ターミナルから**：`af-memory export-sources`、`af-memory export --project <id|名前> --dry-run`（プレビュー）、
  `af-memory export --project <id|名前> [--overwrite <名前>]...`（書き戻し）。

### リントレポート

**取り込み・書き出し → メモリのリントレポート**（ターミナルでは `af-memory lint [--user | --project <id|名前>] [--json]`）は、
1 つの範囲のメモリを点検するだけで、何も書き込みません。メモリは変更されず、読み取りは使用回数に数えず、作業コピーにも
触れません。メモリごとに次を報告します。

- 存在しないメモリへの `[[リンク]]`
- プロジェクトの既定ブランチにないリポジトリのパス（最初のフォルダがリポジトリに実在するパスだけが対象）、バッククォートで
  囲んだ `Test*` やコードらしい `シンボル`、`ADR 0123`
- **廃止した用語**の一覧（1 行に 1 語。同じパネルで編集。大文字小文字は区別せず、英単語は語の境界で照合）にある語。
  一覧に自動で何かが加わることはありません
- 4,096 バイトを超える本文（ほかのセッションが想起で見る範囲）

リポジトリは作業コピーではなく、リポジトリの git ディレクトリにある `origin` の既定ブランチを ref で読みます。fetch は
しないので、レポートには読んだ ref とコミットが出ます。古いクローンなら答えも古くなります。git のないプロジェクト、孤立した
プロジェクト（作業コピーがない）、ユーザー範囲はリンク・用語・サイズの検査だけで、省略したものはレポートに書かれます。名前を
変えたパスや名前は「ない」と報告されるので、指摘は断定ではなく問いとして読んでください。

パネル（と `af-memory lint`）には、同じ既定ブランチから読み取った**廃止した用語の提案**も出ます。完全に置き換えられた ADR の
名前、または最近のコミットで削除されて以降どのファイルにも出てこない `AF_*` キーです。根拠（ADR のステータス行、またはコミット）
が付き、そのスコープのメモリが使っている語だけが出ます。提案が自動で一覧に入ることはありません。**一覧に追加**で追記され、
**却下**すると覚えておいて二度と提案しません。

### リントと読み手からの理由

`af-memory lint --apply`（範囲の指定は同じ）は、レポートの結果を書き込みます。リンク・パス・シンボル・ADR・廃止用語の指摘は
メモリの `reasons` に入り（サイズの指摘は入りません）、そのメモリはエージェントが読むどこでも「疑わしい」と表示され、Claude への
書き戻しからも外れます。メモリごとに `lint` を作者とする 1 コミットで、リビジョンも 1 上がります。点検した時のリビジョンのままの
メモリにだけ書き、1 回に書くのは最大 100 件で、もう一度実行すると続きを書きます。リントの理由は、その後に誰かがメモリを変更し、
かつそのルールが当てはまらなくなったときに外れます。実行できなかったルール（リポジトリがない場合）は何も外しません。
無くなったパスが既定ブランチの git のリネームで移っていた場合は、本文（と `anchors`）のそのパスだけを置き換えます。リネームした
コミットを記録した別コミットで、ほかの変更と同じように元に戻せます。

メモリに裏切られたエージェントは `memory_feedback`（読んだリビジョン、`stale` か `wrong`、メモ）で報告します。現在のリビジョンへの
報告は `feedback` の理由になり、本文を変更すると消えます。古いリビジョンへの報告は観察として残るだけです。数えるのは 1 セッション・
1 リビジョンにつき 1 件です。確認（confirmed）は数えますが理由は消さず、エージェントに求めるのは否定的な報告だけです。

### 統合の提案（任意）

Agent Fleet はバックグラウンドでメモリを整えられます。読み手とリントの報告（`stale` / `wrong` の理由、リントの理由、廃止した 0117 の
レビューが答えを出せないまま残した提案）を集めてメモリごとにまとめ、理由があるときだけモデルに**小さなパッチ**（全面書き換えではない）を
頼みます。**あなたの承認なしにメモリへ書かれることはありません**。実行が積むのは「提案」だけです。

- **オンにする。** 設定 › エージェントメモリ › **設定** の「メモリの自動整理（提案）」です。**既定はオフ**で、エージェントメモリが
  オンであることも必要です。オンにするとメモリの文面がモデルに送られ、ワークスペースが空いている間にトークンを使います。切り替えられるのは
  Console だけです（セッション自身のトークンではできません）。スイッチの下の**状況**に、前回の実行、次に実行できる最短の時刻、承認待ちの件数、
  そして熟しているのに先送りされているトピックと理由（トークン予算、ワークスペース停止、アイドルにならない、次の実行待ち、実行の失敗）が出ます。1 回の予算にはどうしても収まらない話題（既定の 60k で約 180 KB 以上のメモ）は、待たされ続けるのでなく
  見積もりつきで *too-large*（大きすぎる）と出ます。メモを減らすか予算を上げれば、次の実行が取り込みます。
- **いつ動くか。** どのセッションも 15 分間ターンを実行しておらず、3 時間に 1 回まで、「熟した」話題だけです。熟したとは、`wrong` か `stale` の
  報告が 1 件、または新しい観察が 3 件、または 24 時間待っている観察があること。1 回の実行が使うトークンには上限があり、収まらない分は
  次回に回ります（理由は状況表示に出ます: 予算、ワークスペース停止、アイドルにならない）。実行中にターンが始まったら、進行中のモデル呼び出しは
  終えて残りは先送りします。数値はキューの隣の `config.json`（メモリストアの作業ディレクトリ `af-memory.work/consolidation/`）、モデルは同じ場所の
  `models.json` にあります（既定は `small` が `claude:haiku`、`large` が `claude:sonnet`。置き換えと統合は `large` に回ります）。
- **今すぐ実行（手動）。** セッションが一日中動いていると、自動の実行がなかなか来ないことがあります。状況の横の**今すぐ実行**で、自分で
  実行を始められます。先に確認が出ます（モデルを呼び、トークンを使うこと、1 回の予算を示します）。アイドルの確認と 3 時間の間隔は無視し、
  ほかのセッションのターンでは止まりません。それ以外は自動の実行と同じです（スイッチがオン、トークン予算、検証、承認まで何も書かない）。
  既定では熟したトピックだけを対象にし、*まだ時期でないトピックも含める*にチェックすると待機中のすべて（すでに提案が待っているトピックは除く）が対象です。
  要求はすぐ返り、状況に進み具合（「トピック n / m」）と、そのあとに報告が出ます。同時に動く実行は 1 つで、2 つ目の要求は待たされずに断られます。
  手動の実行は、自動の 3 時間の枠を消費もリセットもしません。始められるのは Console のあなただけで、セッションからはできません。
- **提案の中身。** 1 つのメモリへの*パッチ*（完全一致の置換で、現在のリビジョンに当たることを確認済み）、以前の 0117 の提案が持っていた
  *新規作成*、または手で適用していただく*助言*（置き換え・統合・追加。エンジンは置き換え先の本文を書きません）。忘れられた名前、
  または一度でも存在した名前への新規作成は拒否されます。
- **承認。** 承認の時点のメモリに対して再検証し、通常の経路で `consolidator` を作者として公開します。**変更**に現れ、元に戻せます。
  14 日間決めなかった提案は期限切れになり（記録は残ります）、期限切れだけでは話題は戻りません。新しい証拠、メモリの変更、明示的な再試行で戻ります。

**確認する。** メモリビューの **提案** タブに提案が並びます。*承認待ち*、*処理済み*（承認・却下・適用不可・一部適用）、*期限切れ*で絞り込めます。
提案の題名は、まとめられた話題ではなく、変更の対象（作る・変更するメモリの名前）です。話題のメモリは無関係なこともあるため、下の小さな行に出します。
開くと、承認ボタンの前に **承認するとどうなるか** が出ます。

- 1 行の要約：「承認すると、メモリを 2 件追加します。既存のメモリは変わりません。」「承認すると、メモリ 1 件を変更します（adr-0094, リビジョン 2 → 3）。」
- 項目ごとのカード。*作成*は**新しいメモリ**のカードで、範囲・名前・種類・説明と、読める形の本文を出します。話題のメモリが作成の対象でないときは
  「話題のメモリ「…」は変更されません」と添えます。*パッチ*は、対象のリビジョン n → n+1 を**変更前**と**変更後**の左右に並べ、消える行と増える行を色で示し、
  作成者「consolidator」として書き込まれ、「変更」の一覧から元に戻せることを添えます。*助言*は、実行すると何が起きるかと、まだ承認できないことを示します。
- そのあとに根拠（元になった報告やリントの指摘）と、作成時に見たリビジョンが続きます。

- **承認**はその 1 件だけを適用します。書き込む内容を示す確認が先に出ます。まとめて承認することも、待つだけで承認されることも、通知から
  承認することもありません。毎日の通知は、この画面を開くだけです。
- **却下**で捨てます。**再検討**（却下・期限切れ・適用不可・一部適用の提案に出ます）は、その観測を開き直し、あとの実行でトピックを見直させます。
  新しい提案は最初から検証されます。
- **断られた理由は文章で出ます。** 提案の作成後にメモリが変わった（リビジョンの不一致）、期限切れ、または処理済みのとき、承認は
  汎用のエラーではなくその旨を伝えます。古くなった提案は承認できず、*適用不可*になります。*再検討*を使ってください。
- **助言のみ。** 置き換え、統合、本文候補のない追加は*助言のみ*と表示され、承認ボタンはありません。置き換え先を書く仕組みがまだないためです
  （#3696 で扱います）。内容を読んで、**メモリ**から手で直してください。

**毎日の通知。** スイッチがオンで、承認待ちが 1 件でもある間、通知は 1 日に 1 回までです。「承認待ちのメモリの提案が N 件あります」。
件数だけを載せ（メモリの文面は載せません）、開くとメモリビューの**提案**に移ります。通知設定（設定 › 通知 › その他）では他の通知と同じく既定でオンです。

### 設定

**既定はオフ**です。先にこの表示の先頭の「セッションに Agent Fleet のメモリを使わせる」をオンにしてください（オンは次に起動するセッションから効き、オフは起動中のセッションの読み書きもその場で断ります。「メモリ」「変更」の表示はオフでも使えます）。オンの間は、各種類の指示ファイルに「このツールがあること・いつ呼ぶか」の短い固定の注意書きも入ります（記憶そのものは入らず、オフにするとあなた自身の文章には触れずにその部分だけ消えます）。ローカルモデル（lcpp）のセッションは、システムプロンプトにそのプロジェクトのメモリ一覧も最初から載ります。Cursor には指示ファイルを置ける場所がないため、同じ案内はツールの説明に入っています。保存は**承認なしで**すぐ共有され、秘密情報らしき記述は拒否されます。

- **Claude Code 自身のメモリ**：スイッチが自動で引き継ぎます。「セッションに Agent Fleet のメモリを使わせる」を
  切り替えると、先にプレビューの件数つきで確認を求めます。オンにするときは **Agent Fleet のメモリをオンにしますか？** に、
  今すぐ取り込むプロジェクトとメモリの件数、秘密情報らしき記述でスキップする Claude のファイルの件数が出ます（**オンにして取り込む**）。
  オフにするときは **Agent Fleet のメモリをオフにしますか？** に、Claude のメモリのスナップショットを先に取って上書きせずに書き戻す件数が
  出ます（**オフにして書き戻す**）。ワークスペースが停止中のときは件数はまだ出ず、起動した時点で取り込み／書き戻しを行います。
  **オン**：`~/repos` の作業コピーに対応づけられる Claude のプロジェクトをすべて、Agent Fleet がバックグラウンドで
  取り込み、以後に起動する Claude セッション（とアシスタントのチャットの claude）は Claude Code の自動メモリを切った状態で動きます。Claude は自前の
  `MEMORY.md`（毎セッションの開始時に約 25 KB）を読み込まず、ほかの種類と同じく af のツールを使います。自動の取り込みは「取り込み・書き出し」の
  **Claude Code から取り込む**より厳しく、*ここで編集した* Agent Fleet のコピーより新しい Claude のファイルは、競合として報告するだけで
  上書きしません（手動の取り込みは、あなた自身の選択として従来どおり上書きします）。忘れたメモリは戻さず、秘密情報らしき記述を含む
  ファイルはスキップして一覧に出します。すでに動いていた Claude セッションは自前のメモリを使い続け、そのうち最後の 1 つが終わった時点で、
  保存された内容をもう一度取り込みます。**オフ**：Agent Fleet がすべてのプロジェクトを Claude Code のメモリへ書き戻し
  （「取り込み・書き出し」の**Claude Code へ書き戻す**と同じ規則：先にスナップショット、上書きなし、競合と秘密情報は残して一覧に出す）、
  それが終わるまで Claude Code 自身のメモリは切ったままです。間に起動したセッションが、書き戻しとぶつかるファイルを書かないようにするためです。
  書き戻しが失敗し続けるときも Claude Code のメモリは切ったままで、Agent Fleet は間隔を延ばしながら再試行します。このとき画面に
  **今すぐ再試行**と**それでもネイティブメモリをオンに戻す**が出ます。スイッチの下には、実行の進み具合、前回の結果、残したファイル
  （競合・スキップした秘密情報）が表示され、残りがあれば通知が 1 件届きます。この処理はワークスペースを再起動しても続きます：
  記録した段階から再開し、停止中にスイッチが変わっていても、起動した時点で引き継ぎます。Codex：スイッチをオンにすると codex 自身の
  `features.memories` を切り、オフにすると元の値に戻します（オンにはしません）。codex への取り込みも書き込みもありません。
  オンの間にそのフラグを自分で変えたときは、その値が戻されます。変更後に*起動した* Claude セッションだけが対象で、
  起動中のセッションは起動時のままです。

- **Muse Code 自身のメモリ**：スイッチがオンの間、Agent Fleet は Muse Code をネイティブメモリを切った状態で起動します。Muse には `read_memory` / `add_memory` / `edit_memory`
  のツールも、コンテキスト内のメモリのスナップショットも、プロンプトの「永続メモリを使う」段落もなく、
  ほかの種類と同じく af のツールを使います。スイッチがオンの間は、自分の環境にネイティブメモリの設定があってもこちらが
  優先されます。オフのときは何も変えず、Muse の既定のままです。対象は Muse のセッションとアシスタント
  チャットです。変更後に*起動した* Muse ホストだけが対象で、起動中のセッションは起動時のままです。

- **Agent Fleet の外から使う**（設定「Agent Fleet の外からメモリを使わせる」。**既定ではオフ**で、上のスイッチとは独立。**読み取りのみ**か**読み書き**）：
  別のマシンにあるあなた自身の Claude Code や Claude Desktop、または OAuth で接続したアプリ（claude.ai など）に、Control Plane の `/mcp`（またはメモリ専用の `/mcp/memory`）経由でこのメモリを使わせます。
  設定はあなた自身のものですが、テナント管理者はテナント全体で止められます。何ができて何が記録されるかは
  [外部のエージェントから Agent Fleet のメモリを使う](#外部のエージェントから-agent-fleet-のメモリを使う)にあります。

- **バックグラウンドのメモリレビューは廃止されました。** 以前のバージョンには、終わったセッションからメモリを提案させる機能
  （設定「終わったセッションからメモリを提案させる」「自動でも提案させる」、セッションの ⋯ メニューの
  「メモリを提案させる（今すぐ）」、変更 › 提案）がありました。今は設定・ボタン・通知・ルートのどれもなく、「AI 補助」の
  メモリのバックグラウンドレビューのカードもありません。公開済みの変更は変更一覧に残り、元に戻せます（[変更](#変更)）。
  アップグレード時にまだ承認待ちだった提案は**捨てていません**：アップグレード後の最初の起動で一度だけ、Workspace が各提案
  （対象のメモリ、基準にした版、本文、理由、実行の ID）と却下済みの指紋の一覧を、Claude の設定ディレクトリの `af-memory.work`
  フォルダにある `review-queue-export-v1.json` へ書き出し、そのあとで待ち行列を削除します。これは観察であって承認ではありません。
  このファイルの内容はメモリに入っておらず、いまのところ読むものもありません。レビューを使っていなかった Workspace では何も書きません。

## メモリのスナップショット

エージェントが自分で貯めていく記憶（claude の自動メモリ、codex の memories）の**版管理**です。「余計なことを覚えてしまった」
「いつからおかしくなった」を後から直せます。Agent Fleet 自身の共有メモリである[エージェントメモリ](#エージェントメモリ)とは別物です。
先頭に最後のスナップショット・自動スナップショットのオン/オフ・**今すぐスナップショット**があり、その下に 3 つの表示が
あります：**履歴 · 対象 · 書き出し・取り込み**。最後に開いた表示は覚えています。ワークスペースの起動中だけ使えます。

### 履歴

- **履歴**：時刻と契機（自動 / 手動 / 巻き戻し前 / 巻き戻し / 取り込み / 書き戻し前 / エージェントの記録）が新しい順に並びます。
  日時を指定してその時点へジャンプすることもできます。Agent Fleet のメモリの書き込みが残すスナップショット（契機「エージェントの記録」）は、
  エージェントメモリの「変更」にも並ぶので隠してあり、続く 1 まとまりごとに「非表示の Agent Fleet のメモリの書き込み：N 件」の行と
  「変更」へのリンクが出ます。**Agent Fleet のメモリの書き込みも表示**で並べられます（この選択はこの端末に記憶されます）。
  日時ジャンプがその 1 件に当たったときは表示され、差分と**この時点に戻す**もほかの行と同じように使えます。

- **この時点に戻す**：範囲（すべて / 選んで戻す）を指定して巻き戻します。
  **戻す直前の状態も自動で記録される**ので、この操作自体を後から取り消せます。
  対象のエージェントが実行中のときは警告が出ます。

### 対象

- **対象**：版管理できるメモリの一覧と、ファイル数・サイズ・最終スナップショット。
  codex はメモリ機能が既定でオフなので、使うならここでオンにします。エージェントメモリをオンにすると codex のメモリは一度切られます。
  そのあとでここでオンにすると、エージェントメモリと並んでオンのままになり、エージェントメモリをオフにしてもオンのまま残ります（[設定](#設定)を参照）。
- **自動スナップショット**：エージェントが停止して数分たつと自動で取得します（変更が無ければ積みません）。
  「今すぐスナップショット」で手動取得もできます。運用側の設定で自動取得が止められている環境もあります。

### 書き出し・取り込み

- **書き出し・取り込み**：bundle（全履歴）または tar.gz（最新のみ）。書き出す内容に秘密情報らしき
  記述があると、書き出す前に警告が出て確認を求められます。
  - **バンドルの Agent Fleet のメモリ**：ここでバンドルを復元・取り込みしても、Agent Fleet のメモリは書き込まれません
    （復元には秘密情報の検査がないため）。選んだバンドルに Agent Fleet のメモリが入っているときは、その下に
    「このバンドルには Agent Fleet のメモリも入っています — 「エージェントメモリ › 取り込み・書き出し」で取り込めます。」と
    出ます（**取り込み・書き出しを開く**のリンク付き）。取り込み自体は、エージェントメモリの「取り込み・書き出し」にある
    **このバンドルの Agent Fleet のメモリ**で行います。
  - **サイズの上限**：取り込めるのは 64 MiB までの bundle / tar.gz です。管理者は `AF_MEMORY_IMPORT_MAX` で最大 128 MiB まで上げられます（[ref/limits.ja.md](../ref/limits.ja.md)）。それより大きい値は、Control Plane がそれ以上のアップロードを断るため 128 MiB に丸められます。

## 外部のエージェントから Agent Fleet のメモリを使う

同じ MCP トークン、またはサインインで接続した（OAuth）アプリは、Agent Fleet のメモリ（[エージェントメモリ](#エージェントメモリ)）も使えます。同意画面の `read` と `write` の説明にもそう書かれています。たとえば手元の Claude Code / Claude Desktop です。トークンの作り方とクライアントのつなぎ方は
[19 外から使う](19-outside-access.ja.md#外部の-claude-から自分のワークスペースを操作するmcp)にあります。
条件は 2 つ：トークンまたは OAuth 接続のスコープと、**⚙設定 → エージェントメモリ → 設定 →「Agent Fleet の外からメモリを使わせる」**
（既定は「オフ」。「読み取りのみ」か「読み書き」にする）。「MCP トークン・接続アプリ」タブ（外部からのアクセス）にこのトークンでできること（テナントがブロックしていればこれらのツールが見えないことも）と
その設定へのリンクがあり、設定側にも「接続のしかた」のリンクがあります。

- **claude.ai にはメモリ専用のエンドポイントを。** `https://<Console のアドレス>/mcp/memory` はこれらのツールだけを提供し、
  そこ向けに作ったトークンと接続だけが通ります。claude.ai はコネクタをワークスペースの Claude Code セッションにも渡しますが、
  `/mcp/memory` のコネクタならセッションがもともと持っているもの以上は渡りません。`/mcp` のコネクタだとあなたの全権限が渡ります
  （[19 外から使う](19-outside-access.ja.md#メモリ専用のコネクタclaudeai-向け)）。
- **テナント管理者がブロックしている場合。** メモリのツールは、あなたの設定やスコープにかかわらず一切提供されません（[管理 04](../admin/04-mcp-outside.ja.md#agent-fleet-の外からのメモリ利用)）。
- **ツール**：`memory_projects`・`memory_index`・`memory_search`・`memory_read` は read 以上のトークンまたは OAuth 接続、
  `memory_save`・`memory_patch`・`memory_forget` は write のトークンまたは OAuth 接続と「読み書き」が必要です。設定とスコープの両方が許した呼び出しだけが
  通り、狭いほうが優先されます。
- **エージェントへの頼み方**：手元のクライアントに普通の言葉で頼むだけです。「Agent Fleet のメモリから結合テストの
  回し方を探して」「このリポジトリは lint の前に `make gen` が要る、と Agent Fleet のメモリに保存して」など。
  書くのは事実だけで、秘密に見えるテキストは拒否されます。
- **プロジェクトの選び方**：各ツールは `repository`、つまりエージェントが作業中のリポジトリで `git remote get-url origin` が
  出力する URL を受け取ります。Agent Fleet がそれを各プロジェクトのリモート（`memory_projects` に一覧されます）と照合する
  ので、`https://`・`ssh://`・`git@host:owner/repo` のどの書き方でも、末尾の `.git` や `/` があっても、ホスト名の大文字小文字が
  違っても、同じプロジェクトに当たります。`memory_projects` が一覧するプロジェクトの `remote`
  （`github.com/owner/repo`）をそのまま渡すこともできます。`project`（`memory_projects` の ID）も引き続き使え、両方を渡す場合は同じ
  プロジェクトを指していなければなりません。どのプロジェクトにも当たらないリモート、複数に当たるリモートは、その旨の
  メッセージで拒否されます（メモリのあるプロジェクトがなければ、ワークスペースの `~/repos` にそのリモートの作業コピーがちょうど 1 つあるとき、最初の保存が
  そのプロジェクトを始めます。1 つもない、または複数ある場合は拒否されるので、リポジトリをクローンするか、`memory_projects` の
  `project` を渡してください。作業コピーだけのプロジェクトは件数 0 で一覧されます）。
  照合されるのは github.com・gitlab.com・bitbucket.org・codeberg.org の ssh / `git@` / `https://` のみです。セルフホストのホストは
  拒否されます（保存されたリモートはポートを持たず、同じホスト名の別サービスと取り違えうるため）。その場合は `project` を渡してください。
- **保存と忘却には scope が必要**：`memory_save`・`memory_patch`・`memory_forget` は `scope` が必須です。特定のリポジトリの事実なら `project`
  （`repository` か `project` を添えて）、全プロジェクトで成り立つ事実のときだけ `user`。`scope` なしの呼び出しは、何を渡すかを
  示すメッセージで拒否されるため、プロジェクトを渡し忘れてもリポジトリ固有の事実が全プロジェクトに公開されることはありません。
- **記録されるもの**：保存はエージェントメモリの一覧に作成者の種別 `external` として並び、コミットメッセージには
  クライアントが自己申告した名前の `AF-External-Client: <名前>` トレーラーが付きます（参考情報のみ）。外部からの
  保存・部分編集・忘却は監査ログにも `memory.entry.save` / `memory.entry.patch` / `memory.entry.forget` として、プロジェクト ID 付き（メモリ名は含まず）で
  残ります。一覧から戻す・忘れることもできます。
- **ワークスペースの外に出るもの**：メモリの本文は、ワークスペースの通信制御の外にあるそのクライアントのモデルに渡ります。秘密情報の検査は認証情報を止めますが、顧客名や社内の事情までは止められません。
- **保存**は、ワークスペースの中のエージェントの保存と同じリビジョン確認・秘密情報の検査・上限を通ります。
- **ワークスペースが停止中**のときは、先に起動するよう答えが返ります。Console で起動してからもう一度頼んでください。
- `/mcp` を提供しない環境では、`/mcp/memory` も含め、外からは一切使えません。

### 手元の Claude Code のメモリを Agent Fleet に移す

**Claude Code から取り込む**（取り込み・書き出し）が読むのは、ワークスペースの中の Claude Code だけです。手元の PC の
Claude Code が持っているメモリは、代わりに `/mcp` 経由で移せます。手元の Claude が自分のメモリのファイルを読み、
1 件ずつ `memory_save` で保存します。保存はすべて秘密情報の検査を通り、**変更** に残るので、1 件ずつ取り消せます。

始める前に:

1. **⚙設定 → エージェントメモリ → 設定** で「セッションに Agent Fleet のメモリを使わせる」をオンにします。
   ワークスペースのセッションが、移したメモリを読むようになります。
2. 同じ表示で「Agent Fleet の外からメモリを使わせる」を **読み書き** にします。
3. 手元の Claude Code を `write` スコープで `/mcp` に接続します（コマンドは
   [19 外から使う](19-outside-access.ja.md#手元の-claude-code-の作業をワークスペースに移す)にあります）。メモリのツールが出てこなければ、
   テナント管理者がブロックしています。
4. そのリポジトリがワークスペースの `~/repos` にクローンされていること。まだメモリのないクローンは最初の保存で
   プロジェクトが始まるので、先にセッションで保存してもらう必要はありません。同じリモートのクローンがワークスペースに
   複数あると、保存は ID を挙げて拒否されます。`project`（`memory_projects` の ID）を渡して選んでください。

次のスキルを手元の PC に一度だけ保存します。保存先:

```
~/.claude/skills/af-memory-import/SKILL.md
```

````markdown
---
name: af-memory-import
description: このプロジェクトの Claude Code のメモリを Agent Fleet のメモリに写す
disable-model-invocation: true
---
このプロジェクトについてあなたが持っているメモリを、Agent Fleet のメモリに写して。自分のメモリのファイルは変更しないこと。

1. `git remote get-url origin` を実行する。以下の呼び出しの `repository` はすべてこの値。agent-fleet の
   `memory_projects` を呼び、このリポジトリが一覧にあるか確かめる（ワークスペースにクローンされたリポジトリは、
   まだメモリがなくても件数 0 で一覧に出る）。なければ、ワークスペースにクローンされていないので、そこで止まって教えて。
2. メモリのディレクトリにあるファイルを、索引の `MEMORY.md` を除いて一覧にする。ファイルごとに名前・type・説明を
   1 つの表で見せ、scope を提案する: このリポジトリについてのことは `project`、どのプロジェクトでも成り立つ事実だけ
   `user`。表について私の OK を待つ。
3. OK したファイルごとに:
   - 名前で `memory_search` を呼ぶ。同じ名前のメモリがあれば `memory_read` で読み、本文が同じなら飛ばす。違えば両方を
     見せて、どちらを残すか聞く。置き換えるときは、読んだ `revision` を渡す。
   - `memory_save` を呼ぶ: `scope`、`repository`、`name`（小文字・数字・`-`・`_`・`.` で 64 文字まで）、
     `description`（1 行）、`type`（`user`・`feedback`・`project`・`reference` のどれか）、`body`（frontmatter を除いた本文）。
   - 秘密情報らしいなどの理由で拒否されたら、言い換えて再送しないこと。理由を控える。
4. 保存したもの・飛ばしたもの・拒否されたものを報告する。
````

そのリポジトリの Claude Code のセッションで `/af-memory-import` と入力します。終わったら、エージェントメモリの **変更** を
見てください。保存は作者の種類 `external` で並び、そこから取り消せます。

知っておくこと:

- 指示ファイル（`CLAUDE.md`）はメモリではありません。書いてあることは 設定 → エージェントへの指示 に移すか、
  リポジトリのファイルはリポジトリに置いたままにしてください。
- 手元のメモリのファイルは変わりません。手元の Claude Code を使い続けると、その後に覚えたことは手元に残るので、
  必要になったらもう一度スキルを実行してください。本文が同じメモリは飛ばされます。
