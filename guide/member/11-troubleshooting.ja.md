# 11. 困ったとき — 症状別の対処と FAQ

[English](11-troubleshooting.md) | 日本語

まず「症状別」で自分の状況を探し、当てはまらなければ末尾の FAQ を見てください。
各項目は本編の該当章にリンクしています。

## 症状別インデックス

### claude を選ぶとログイン画面（「Select login method」）が出る

接続そのものは生きていることがほとんどです。これは認証ではなく、対話画面が
オンボーディングをやり直しているだけで、多くはセッションを **再開**するか、
⋯ メニューの **「作り直す（今の会話はアーカイブへ）」** で解消します。
端末内で手動 `/login` する従来のやり方も併用できます。接続状態は
⚙設定 → 「エージェント」タブで確認できます（[06](06-agents.ja.md)）。

### claude が `/list-agents` を知らない／他のセッションへメッセージを送れないと言う

Claude Code 自身のセッション間メッセージ（cross-session messaging）は、Agent Fleet では
**意図的に無効**にしてあります。有効化すると Claude 側の利用統計送信も一緒に戻る作りのため
です。同じことは Agent Fleet 版でできます。**設定 > エージェント > セッション >
「セッション間メッセージ」** をオンにしてください（既定はオフ／反映は次に起動するセッション
から）。オンにすると、エージェントの種類をまたいで届き、停止中の相手にも届きます。
違いの一覧は [02 セッション](02-sessions.ja.md#claude-code-自身の同種機能との違い) にあります。

オンにしてもエージェントがツールを持っていないように見えるときは、そのセッションが設定前から
動いていないか確認してください。起動済みのセッションは再起動するまで変わりません。

### 左ペインからセッションやリポジトリが消えた

**作業グループで絞り込まれていないか**を最初に疑ってください。左ペイン最上部のバーが
**「すべて」**以外になっていると、そのグループに属さないリポジトリ・会話・セッションは
表示されません（消えたわけではありません）。バーを「すべて」に戻すと元通りです
（[02](02-sessions.ja.md#作業グループで表示を絞る)）。

それでも見当たらないときは、**アーカイブ**していないか（AI セッションはアーカイブ一覧から
復帰できます）、**掃除**で片付けていないか（削除したセッションはごみ箱から復元できます）を
確認してください（[02](02-sessions.ja.md#まとめて片付ける掃除)）。

### セッションが再開できない／打ち消し線になっている

状態が **「フォルダ無し — 再開不可」** なら、そのセッションの**作業フォルダが消えて**います
（worktree ごと削除した後などが典型）。claude / codex / cursor / copilot / kiro / agy / opencode はこの状態から再開できません。
同じ内容を新しいセッションとして起動し直してください。shell は作業フォルダが無ければ
ホームに戻って再開します（[02](02-sessions.ja.md)）。

### 共有したのに相手に見えない／古い会話しか出てこない

- **共有した範囲を確認してください。** セッション単位の共有はそのセッション 1 本だけです。
  セッションごとに worktree を切っている場合、ベースの作業コピー直下には古い会話しか
  残っていないことがあるので、**プロジェクト**単位（ベース＋配下の worktree のセッション）で
  共有するのが実情に合います。
- **アーカイブしたセッションは共有先の一覧から外れます。** 共有の設定自体は残っているので、
  アーカイブから復帰させれば再び見えます。
- **所有者のワークスペースが停止中は履歴を読めません。** 相手側にその旨が表示されます。
- 一覧は定期的に更新されますが、今すぐ反映したいときは共有セッションの **「最新に更新」** を
  押してください（[02](02-sessions.ja.md#会話を共有する共有セッション)）。

### 共有された側から送ったのに、エージェントが動かない

権限が **「提案可」** の場合、入力した内容は**所有者が承認するまでエージェントへ届きません**。
所有者側の共有セッションに **「承認待ち ◯件」** が出るので、確認して「承認して送信」して
もらってください。権限が **「閲覧のみ」** なら、そもそも送信欄はありません。

送信結果が確認できなかった場合は、安全のため自動で送り直しません。
**「結果を照会」** で状態を確かめてください（[02](02-sessions.ja.md#会話を共有する共有セッション)）。

### クローンに失敗する

- private リポジトリは、先に GitHub / Bitbucket の**接続**が必要です（⚙設定 → 「Gitホスティング」タブ）。「未接続」と出ていないか確認してください。
- URL とブランチ名の綴りを確認します。
- submoduleはクローン後にベストエフォートで取得され、失敗しても親のクローン自体は成功します（[04](03-code.ja.md)）。

### セッションが「submoduleが無い／壊れている」と言う

- 大きなsubmoduleは起動時間内に取得しきれないことがあります。取得は裏で続き、終わると通知センターでお知らせします（[04](03-code.ja.md)）。
- 取得が途中で切れたsubmoduleは、その作業コピーで次にセッションを起動したときに自動で修復されます。すぐ直したいときは、端末でその作業コピーに入り `git submodule update --init --recursive` を実行してください。

### private リポジトリで認証エラーになる

⚙設定 → 「Gitホスティング」タブで、該当プロバイダが **「接続済み」** かを確認してください。
未接続なら OAuth かトークンで接続します。接続後は認証が透過するので、以後は
トークン入力なしでクローン／pushできます（[04](03-code.ja.md)・[06](06-agents.ja.md)）。

### ブラウザペインが `target-unreachable` になる／真っ白・404 になる

- **`target-unreachable`** は、ブラウザは起動したものの、そのポート/path への接続がまだ成立していない状態です。
  開発サーバーの**起動待ち**でも出ます。ポート番号と path、サーバーが本当に立ち上がっているかを確認し、
  起動後に **「再読み込み」**、それでも残るなら **「再接続」** を押してください。
- **`127.0.0.1`（localhost）で listen していれば届きます。** ブラウザは同じワークスペース内から `127.0.0.1`
  へ直接つなぐため、loopback だけの listen で問題なく開けます（外部公開のための `0.0.0.0` は不要です）。
  それでも届かないときは、サーバーが本当にそのポートで起動しているか、ポート番号の打ち間違いがないかを確認します。
- **真っ白・404** は、絶対パスで asset を読むアプリを**軽量プレビュー**で開いたときに起きがちです。軽量プレビューの
  URL は `/preview/{ポート}/` という**サブパス**なので、アプリが `/static/...` を要求した瞬間にその外へ出ます。
  **プレビュー用サブドメインが発行されている環境なら、まずそちらで開いてください**（アプリがルート直下に配られるので
  この問題自体が起きません）。無ければ **「ペインで開く」（ブラウザペイン）** に切り替えます。どうしても軽量プレビューで
  見たい場合は、Spring Boot なら `server.forward-headers-strategy=framework`（または `native`）を設定、
  その他は base path をアプリ側で調整します（[08](10-integrations.ja.md)）。

### 同僚に渡したプレビューの URL が 404 になる

- **プレビュー用サブドメインの URL は、ワークスペースを起動し直すたびに変わります。**
  `https://＜ランダム＞-3000.…` をそのまま貼ると、次の起動で必ず 404 になります。
  渡すときは、プレビューのポップオーバーの **「共有」** ボタンでコピーできるリンクを使って
  ください。こちらは**起動をまたいでも有効**で、開いた時点の URL へ案内します。
- 相手が **「共有されているプレビュー」に何も出ない / 404 になる**ときは、
  設定 › ツールチェーン › プレビュー用サブドメイン の **「同じテナントのメンバーに見せる」**
  がオンになっているかを確認してください。オフにすると、相手が開いていても**次の操作から**
  見えなくなります（それが意図した動きです）。
- **相手側に「停止中」と出る**のは、あなたのワークスペースが止まっているときです。
  **相手があなたのワークスペースを起動することはできません**——起動してから知らせてください。
- ポートを設定の一覧から外した場合も 404 になります（[08](10-integrations.ja.md)）。

### HMR（ライブリロード）が効かない／自動更新されない／枠だけ出てデータが出ない

- **Next.js（15.2 以降・16 系も同じ）を、プレビュー用サブドメインで開いたとき**は、まずこれを疑って
  ください。**レイアウトの枠だけ描画され、API から取るデータの行が一切出ない**——真っ白でもエラーでも
  ないのでアプリのバグに見えますが、`127.0.0.1:＜ポート＞` で開くと正常、という形で出ます。
  dev サーバーが `/_next/*` への**別オリジンからのアクセスを既定でブロック**しており、HMR が張れないまま
  ハイドレーションが完走しないためです。dev サーバーのログに
  `⚠ Blocked cross-origin request to Next.js dev resource` が出ていたら確定です。
  `next.config.ts` に **`allowedDevOrigins`** を足してください（URL は起動のたびに変わるので
  ワイルドカード必須。書き方は [08](10-integrations.ja.md)）。
- **軽量プレビューとプレビュー用サブドメインは WebSocket / SSE を通します**。それでも HMR が繋がらないときは、
  dev サーバーが**接続先のポートをクライアントに埋め込んでいる**のが原因のことがあります（Vite など）。
  その場合はアプリ側で `server.hmr.clientPort: 443` のような設定が要ります。
- 設定を足したくない・原因を切り分けたいときは **「ペインで開く」（ブラウザペイン）** を使ってください。
  ワークスペース内のブラウザが `127.0.0.1` を直接開くので、HMR・WebSocket・SSE がふつうの localhost と
  同じように動きます（[08](10-integrations.ja.md)）。

### プレビューで API が全部 401（`preview requires sign-in`）になる

- **dev サーバーの proxy の転送先を、プレビューの URL に書き換えていませんか。**
  Vite の `server.proxy` の `target`、Next.js の `rewrites()` の `destination` は
  **`http://127.0.0.1:8080` のままにしてください**。proxy はコンテナの中の dev サーバーが
  **サーバー側から**出す通信なので、あなたのブラウザのログイン状態を持っておらず、プレビューの
  URL へ向けると認証で弾かれます。「フロントから 8080 が見えないのでは」と考えて書き換えるのが
  典型的な間違え方です（[08](10-integrations.ja.md)）。
- **ブラウザから 8080 の URL を直接叩いている**場合は、認証がポートごとに要ります。
  `https://＜ランダム＞-8080.…` を**一度タブで開いてログインを通して**ください。加えて、3000 の画面から
  8080 を直接呼ぶ構成なら設定の **「ポート間の呼び出しを許可する」** をオンにします（既定はオフ）。

### ブラウザペインが `crashed` / `disconnected` になる・繰り返し落ちる

- **`disconnected`** は通信（WebSocket）が切れた状態で、必ずしも異常終了ではありません。ワークスペースが
  稼働中かを確認して **「再接続」** を押します。
- **`crashed`** はワークスペース内のブラウザが異常終了した状態です。**「再接続」** で開き直してください。
- **短時間に繰り返し落ちる**ときは、ワークスペースのメモリ不足が疑われます。重いビルドや watcher、開いたままの
  ブラウザペインを整理し、ブラウザペインは同時 **2 つまで**である点も踏まえて使ってください。メモリの見方と
  対処は後述の FAQ「ビルドでメモリが足りず落ちる／固まる」も参照（[08](10-integrations.ja.md)）。

### 通知が来ない

ブラウザの通知許可がオフだと出ません（初回に許可を求められます）。また、そのセッションの
画面を開いている間は通知が**抑止**されます。shell / ssm は状態通知の対象外です
（[02](02-sessions.ja.md)）。

### codex を接続したいのに、承認しても進まない

ChatGPT サブスクでの接続は、**ChatGPT の「設定 > セキュリティ」で「Codex に対して
デバイスコード認証を有効にする」をオン**にしておく必要があります。オフだと承認しても
先に進みません（[06](06-agents.ja.md)）。

### 掃除で消せないものがある

安全度が **「保持」** の候補は、掃除では触りません。理由は行に出ています。

- **稼働中** — 先にセッションを停止してください。
- **未コミット／未 push** — commit / push すると「安全」または「要確認」に変わります。
  どうしても消す場合は Console から強制削除します。
- **削除ロック中** — セッションの ⋯ メニューでロックを解除してください。

なお **worktree の削除だけは取り消せません**（作業コピーが消えるだけで、履歴・リモート・
ブランチは残ります）。削除したセッションとブランチは**ごみ箱**へ退避されるので、
掃除モーダルの「ごみ箱（復元）」から戻せます（[02](02-sessions.ja.md#まとめて片付ける掃除)）。

### 使いたいモデルが選べない／指定したのに起動を断られる

⚙設定 → 「エージェント」タブの **「使わないモデル」** で除外されている可能性があります。
除外したモデルは起動ダイアログ・既定モデル・アシスタントが選ぶ一覧から消え、
**名前を明示した起動も断られます**（定時実行のモデル欄やアシスタント経由も同じです）。
そのエージェントのカードで除外を解除してください（[06](06-agents.ja.md)）。

Claude で特定のリリース（`claude-opus-4-8` のような完全 ID）を使いたいときは、
同じ画面の **「Claude の追加モデル」** に登録すると選択肢に並びます。

### 登録した MCP サーバーがセッションやアシスタントで使えない

⚙設定 → 「MCP サーバー」タブで、次の順に確認してください（[12](12-settings.ja.md#mcp-サーバー)）。

1. **有効**になっているか。無効だと定義は残りますがどこにも配られません。
2. **利用先**に「セッション」／「アシスタント」が入っているか。両方外れていると配られません。
3. **対象エージェント**を絞っていないか（未選択なら全エージェントが対象）。
4. **セッションへの反映は次に起動するセッションから**です。動いているセッションは再起動するまで変わりません。
5. **「接続テスト」**を押して、サーバー名・ツール数が返るか確認します。
6. 「テナント配布と名前が重なるため使われていない」と出ていないか。同名のテナント配布が優先されます。
7. 外向き通信が制限されたデプロイでは、接続先ホストが**承認待ち**の可能性があります（申請の導線がカードに出ます）。

### 「ログインが切れています」と出てエージェントが止まった

チャット表示のエラーに **「再認証する」** が出ます。そこから接続し直せば、**そのセッションは
そのまま続きから再開**できます。⚙設定 → 「エージェント」タブの該当カードでも接続状態を
確認できます（[06](06-agents.ja.md)）。

### Claude のセッションが「認証切れ — 再認証が必要」になっている／送っても何も始まらない

**ワークスペースの Claude のログインが期限切れ**です。資格情報はまだ手元にあるので端末は
一見ふつうの入力待ちに見えますが、この状態で送ってもターンは一つも始まりません。だから
Console は入力待ちではなく **認証切れ** のチップを出し、送信自体を断ります（断らないと
「送れたのに動かない」ように見えます）。⚙設定 → 「エージェント」の Claude カードから
**再認証**してください。セッションは止めなくてよく、再認証すればそのまま続けられます。

同じカードには期限が近づくと **「あとN日で期限切れ」**（残り3日以内）も出ます。CLI 自身の
警告は残り1日以下・しかも15秒で消えるので、切れる前に気づける場所はこのカードです。

### アシスタント（オペレーター）が自動で進めるのをやめた

**自動応答の上限**に達しています。暴走防止のため、あなたの発言なしで連続実行できる回数は
上限まで（既定 10・最大 50）で、**あなたが次のメッセージを送ると再開**します。
上限は ⚙設定 → 「アシスタント」タブで変更できます（無制限にはできません）。

正常な完了報告だけ静かにしたい場合は、同じタブの **「静かな完了報告」** をオンにすると、
報告カードと通知だけが届き、自動応答は行われません（[11](08-organising.ja.md)）。

### チャットが「コンテキストが上限を超えました」と言って答えない

会話が長くなりすぎています。コンテキストバー右端の **「圧縮」** で要約を引き継いで続けるか、
**新しいチャット**を開いて要点だけ渡してください。使用率 90% を超えたまま次のやり取りを
始めると自動で圧縮されますが（⚙設定 → 「アシスタント」で OFF 可）、それより先に上限を
超えるとこの状態になります。⚙設定 → 「アシスタント」の **「自動圧縮の閾値」** を下げておくと
再発しにくくなります（[07](07-chat-memo.ja.md#会話が長くなってきたらコンテキストの目安)）。

### 定時実行が動かない

左ペインの **スケジュール**セクションで、その行を確認してください。

- **「停止中」**のタグが付いていれば一時停止中です。行メニューの **「再開」** で戻します。
- **実行履歴**に `skipped_*` が並んでいる場合は、前回の実行がまだ走っている（重複ポリシー）か、
  対象の会話が実行中でスキップされています。
- 発火時刻・タイムゾーン・プロンプトの内容は、行メニューの **「詳細・編集」** で確認・修正
  できます（session_mode や再利用の設定など高度な項目だけはオペレーター会話から変更します）。
- **「今すぐ発火」**で試すと、定時と同じ経路で動くか確かめられます（反映まで最大 1 分ほど）。
- そもそもスケジュールのセクションが出ないデプロイでは、定時実行が無効になっています
  （[11](08-organising.ja.md#定時実行スケジュール)）。

### 端末で Ctrl+C が効かない／コピペできない

仕様です。端末では Ctrl+C は割り込み（SIGINT）としてプログラムに渡ります。**コピーは
選択で自動、またはCtrl+Shift+C、ペーストは右クリック / 中クリック / Ctrl+Shift+V** を
使ってください（[03](05-terminal.ja.md)）。

### コマンドパレットなどアプリのショートカットが効かない

端末にフォーカスがあるとき、⚙設定 → 「キー操作」の設定でキーが端末側へ渡っている可能性が
あります。

- **「端末フォーカス中はアプリより端末を優先」** — Ctrl 系がすべて端末へ行きます。アプリ側は
  リーダーだけが生きるので、既定の **Ctrl+K → ;**（macOS は **⌘K → ;**）からコマンド
  パレットを開けます。
- **「shell / SSM 端末へキーをすべて渡す」** — リーダーとパレットまで端末へ渡ります。
  アプリの操作に戻すには、別のペインへフォーカスを移してください。

どのキーが何に割り当たっているかは **?** で一覧を開けます（[03](05-terminal.ja.md#ショートカット)・
[12](12-settings.ja.md#キー操作)）。

### スマホでキーボードが勝手に出る／操作しづらい

端末下の**コントロールキー列**（`Esc` `Tab` 矢印 `^C` `⏎`）は、ソフトキーボードを
呼ばずにキーを送れます。過去の出力は**1 本指の縦スワイプ**で遡れます。左ペインは
画面左上の **≡（メニュー）**で出し入れします（[03](05-terminal.ja.md)）。

### ライトテーマにしても端末だけ暗い

既知の仕様です。テーマを切り替えても端末（黒い画面）の背景は暗いままです。ファイル
ビュアーや他の画面はテーマに追従します（[03](05-terminal.ja.md)）。

### ワークスペースがいつのまにか止まっている

しばらく操作がないと**自動で停止**します（アイドル自動停止）。ワークスペース操作バーの「起動」で
もう一度「起動」を押せば、セッション一覧もクローンも接続もそのまま戻ります（[01](01-first-day.ja.md)）。

## FAQ

**Q. 消したセッションは戻せる？**
「アーカイブする」で隠しただけなら、アーカイブ済み一覧の「復帰」で戻せます。「停止する
（あとで再開できる）」なら停止中として残り、クリックで再開できます。shell / ssm の
「削除する」は取り消せません（会話ログのファイル自体は残ります）。違いは
[02 セッション](02-sessions.ja.md) を参照。

**Q. 会社の PC と自宅の PC、両方から使える？**
はい。ログイン・接続も、フォント／文字サイズなどの表示設定もサーバーに保存され、
別の端末・ブラウザでも追従します（[03](05-terminal.ja.md)）。

**Q. ワークスペースを止めたら作業は消える？**
消えません。クローン・未コミットの変更・セッション一覧・接続はすべて残ります。ただし
未コミット変更はワークスペースの中だけにあるので、長期保存はコミット／push を
（[01](01-first-day.ja.md)・[04](03-code.ja.md)）。

**Q. 複数のタスクを同時に走らせていい？**
はい。セッションごとに独立した worktree で作業すれば、編集がぶつかりません。既定で
worktree が作られます（[02](02-sessions.ja.md)・[04](03-code.ja.md)）。

**Q. 「停止」「削除」「アーカイブ」「作り直す」の違いは？**
停止＝止めるだけ（再開可）、削除＝一覧から消す（使い捨て種別）、アーカイブ＝隠す（復帰可）、
作り直す＝同じ場所で新しい会話（今の会話はアーカイブへ）。詳細は [02](02-sessions.ja.md)。

**Q. opencode が新規セッションの種類に出てこない**
API キーを 1 つも登録していないと選べません。⚙設定 → 「エージェント」タブで opencode に
キーを登録してください（[06](06-agents.ja.md)）。

**Q. 共有を解除すれば、相手の手元からも消える？**
消えません。共有先は表示された内容を保存できるため、**解除できるのはこれ以降のアクセスだけ**で、
すでに保存されたコピーは回収できません。共有する前に、会話に秘密情報が写っていないか確認して
ください（自動検出はされません）。詳細は [02](02-sessions.ja.md#会話を共有する共有セッション)。

**Q. 「使わないモデル」に入れれば課金は防げる？**
選択事故を防ぐ設定であって、課金の強制ガードではありません。起動ダイアログ・設定・
アシスタントの一覧から消え、名指しの起動も断りますが、**端末の中で `/model` を打つなど
CLI 自身の操作までは止められません**（[06](06-agents.ja.md)）。

**Q. ビルドでメモリが足りず落ちる／固まる**
ホストは共有・メモリ制約があります。Node 系ビルドは必要なコマンドだけヒープを上げ
（例: `NODE_OPTIONS=--max-old-space-size=2048`）、テストランナーの並列は抑え、watcher や
dev サーバーを放置しないでください。Gradle は使い終わったら `./gradlew --stop`。
重いビルドは 1 つずつ実行します。

**Q. `git-delta` や `sudo` が見当たらない**
ワークスペースのイメージには意図的に含めていません（隔離維持などの理由）。必要なツールは
ユーザー領域に自分で入れられます（`pip install --user` は永続します）。

添えて相談してください。仕組み側の詳細は開発者向けの資料にあります。
