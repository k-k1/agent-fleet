# 04. MCP の配布と外からのアクセス

[English](04-mcp-outside.md) | 日本語

チーム共通のツールを配るのも、Agent Fleet の外のアプリやエージェントがテナントに接続してよいかを
決めるのも、あなたの権限です。外部通信の統制は配備管理者の担当です。

## MCP サーバーをテナント全員に配る（あなたの権限）

テナント設定の **「運用 → MCP 配布」** で、テナントの全メンバーへ MCP サーバーを配布できます。
配布したサーバーは、各メンバーの ⚙設定 → 接続 →「MCP サーバー（セッションで使う）」に **「テナント」** の出自ラベル付きで
並び、そのままアシスタントやセッションから使えます（メンバー側の見え方は
[member/20 設定](../member/20-settings.ja.md#mcp-サーバーセッションで使う)）。

### 配れるのはリモート（HTTP）だけ

**stdio（ワークスペース内でコマンドを起動する方式）は配布できません。** 配布は
「管理者が全メンバーのコンテナで任意のコマンドを実行できる」ことと等価になるためです。
配布できるのは **Streamable HTTP のエンドポイント**だけで、指定するのは URL とヘッダです。
stdio が必要なメンバーは、自分の設定に個人登録してもらってください。

### 資格情報の扱いを決める（重要）

追加フォームの **「資格情報の扱い」** で 2 通りから選びます。OAuth のサインインが要るサーバーは
3 つ目の場合です。ここが配布の設計上いちばん重要な判断です。

| 選択 | 何が配られるか | 向いている場面 |
|---|---|---|
| 値も配布する | ヘッダの値ごと配布（暗号化して保存され、サーバー起動時にだけ渡されます） | 共有の read-only トークンなど、全員が同じ資格で読むもの |
| **「認証の値は各メンバーが入力する」** | **接続先とヘッダ名だけ**。値は各メンバーが自分のワークスペースで入力 | 個人ごとのトークン、監査で個人を識別したいもの |
| **認証: OAuth** | **接続先だけ**。各メンバーが自分の設定から自分のアカウントでサインイン | OAuth のサインインしか受け付けないホスト型のサーバー |

**値を配ると、そのトークンは全メンバーのコンテナ内で読める状態になります。** 個人を識別したい
場合や、権限の強いトークンは「各メンバーが入力する」を選んでください。この形で配ると、
メンバー側のカードには **「値を入力」** の導線が出ます（入力が済むまでそのサーバーは使われません）。

フォームの並びはメンバー自身の登録と同じです。先頭が**表示名**（**ID** は編集するまで表示名から自動で入ります）、
続いて URL、上の資格情報の扱い、そして**認証**の選択（**なし** / **Bearer トークン** /
**カスタムヘッダ**）です。「各メンバーが入力する」にしている場合、Bearer トークンは `Authorization` の
ヘッダ名だけを配り、メンバーにはトークンだけの入力欄が出ます。そうでない場合はトークンが暗号化されて保存され、
画面には `Bearer ***` と戻ってきます。**OAuth** は資格情報を一切配らないので、資格情報の扱いの選択は消え、
ヘッダも足せません。各メンバーの行に **サインイン** が出て、許可（grant）はそのメンバーのワークスペースにだけ残り、
サインインしたメンバーのセッションにだけサーバーが渡ります（メンバー側の見え方は
[member/20 設定](../member/20-settings.ja.md#mcp-サーバーセッションで使う)）。既存の配布を OAuth に切り替えると、
保存してあったヘッダの値は削除されます。URL を変える・OAuth をやめる・削除すると、各メンバーのサインインは
次回の取得時に切断されます。サーバーの認可サーバーに Agent Fleet 用のクライアントを登録してあるなら、その**クライアント ID** と、
登録した認可サーバーの **issuer** を入力します。メンバーのサインインは、それぞれクライアントを登録する代わりにこれを使います。
**クライアントシークレット**は任意で、confidential クライアントのときだけ入力します。シークレットは暗号化して保存され、ワークスペースには
送られません。代わりに Agent Fleet のコントロールプレーンがトークンの要求を行うので、コントロールプレーンからその認可サーバーに
到達できるよう配備管理者に確認してください。保存したシークレットは issuer とクライアント ID に結び付くので、どちらかを変えるとシークレットの入力を求められます。クライアントを変更・削除しても、各メンバーのサインインは切断されます。confidential クライアントの場合、それまでのサインインが持っていたトークンはもう失効できず、古い認可サーバーで期限が切れるまで有効なままです。利用先・対象エージェント・**有効**は閉じた**詳細設定**にまとまり、
見出しの 1 行に今の値が出ます。既定と違う配布を編集するときは、自動で開きます。

### 反映されるまで

- 各メンバーのワークスペースは、配布内容を **5 分ごとに取得**します。
- 実際に効くのは、**その後に起動したセッションから**です。すでに動いているセッションは変わりません。
- **無効**にすると、定義は残したまま誰にも配られなくなります。**削除**すると、各ワークスペースからは
  次回の取得時に消えます。
- 配布と**同じ名前の個人登録**があるメンバーには、配布のほうが使われます（メンバー側にその旨が
  表示されます）。名前は衝突しにくいものにしてください。

### 運用の勘所

- まず**自分のワークスペースで個人登録して接続テスト**し、動く構成を確認してから配布に移すと確実です。
- 配布したトークンを失効させるときは、**先に配布側の値を差し替えて**から旧トークンを無効化します
  （順序を逆にすると、次の取得までメンバー全員のツールが失敗します）。
- 外向き通信が制限された配備では、配布しても**接続先ホストが許可されていないと動きません**。
  先に許可を依頼してください（[後述](#外部通信の統制はあなたの担当ではありません)）。

## MCP OAuth

**テナント設定 → 接続元の制限** の **MCP OAuth** 欄で、外部アプリが OAuth でこのテナントに接続できるかを設定します。配備が MCP OAuth を提供している場合だけ表示されます。テナントの設定は既定で有効で、テナント管理者または配備管理者が変更できます。

**MCP OAuth によるアプリの接続を許可する**を外し、**保存**して確認します。そのテナントの既存の OAuth 接続はすぐに取り消され、監査に記録されます。同意画面のテナント選択肢から除かれ、コード交換・トークン更新は拒否され、OAuth アクセストークンも `/mcp` で使えなくなります。他のテナントと Personal Access Token には影響しません。

OAuth 接続の `read` と `write` のスコープは、トークンと同じく、メンバーの Agent Fleet メモリにも及びます（同意画面にもそう書かれています）。使えるかどうかは、このパネルではなく**外部からのメモリ利用**（[後述](#agent-fleet-の外からのメモリ利用)）とメンバー自身の設定で決まります。そこでブロックすると、メモリのツールは OAuth 接続からもトークンからも見えなくなります。

再度有効にしても、取り消した接続は復元されません。メンバーがアプリから接続し直します。個別の接続は **設定 → 外部からのアクセス → MCP トークン・接続アプリ → 接続済みアプリ** の **失効** ボタンからも取り消せます。

## Agent Fleet の外からのメモリ利用

メンバーは、Agent Fleet の外のエージェント（自分のマシンで MCP トークンを持つ Claude Code や Claude Desktop、または MCP OAuth で接続した claude.ai などのアプリ）に、
自分の Agent Fleet メモリの一覧・検索・読み取りを許せます。もう一段階選ぶと保存と忘却も許せます
（[メンバー編](../member/18-agent-memory.ja.md#外部のエージェントから-agent-fleet-のメモリを使う)）。このときメモリの本文はワークスペースの外に出て、そのクライアントのモデルに渡ります。
秘密情報のスキャンは認証情報を止めますが、顧客名や社内の事情までは止められません。この節は、テナント全体でこれを止める方法です。

### スイッチ

テナント設定 → **外部からのメモリ利用**（運用の下）。**許可**（すべてのテナントの初期状態）ではメンバーが各自で有効にできます。
メンバー自身の設定は引き続き **オフ** から始まるので、メンバーが選ぶまで誰にも変化はありません。**ブロック**にすると、
テナント全体からメモリのツールを引き上げます。

ブロック中は次のとおりです。

- `/mcp` と `/mcp/memory` は、テナントの誰に対しても `memory_projects`・`memory_index`・`memory_search`・`memory_read`・`memory_save`・
  `memory_forget` を一覧に出さず、名前を指定した呼び出しも未知のツールとして拒否します。メンバー自身の設定やトークンのスコープは関係ありません。
- 次のリクエストから、再起動なしで、すでに発行済みのトークンにも効きます。
- メンバーの設定は保持されるので、許可に戻せば各自が選んでいた状態に戻ります。
- Agent Fleet の中でのメモリ利用（セッション、Console のエージェントメモリ画面）と、`/mcp` のほかのツールには影響しません。

スイッチを読めないとき（ストアが使えないなど）は、ツールを出さない側に倒します。

変更は [監査ログ](03-audit-usage.ja.md) に `tenant.external_memory` として、`enabled=true` または `enabled=false` つきで残ります。
変更できるのはテナント管理者と super_admin だけです。配備全体で `/mcp` エンドポイントを止めるのは運用者の `AF_MCP_ENABLED` で、別のスイッチです。

## 外部通信の統制はあなたの担当ではありません

配備のワークスペースがどこへ接続できるかは配備管理者が決めます。その画面はテナント設定には出ません
（[運用側の手順](../operate/04-secure.ja.md#egress-統制の運用)）。
関係するのは 1 か所です。配る MCP サーバーも、メンバー自身の登録も、接続先のホストが許可されていなければ
失敗します。メンバーがホストを申請すると、配備管理者が承認または却下するまで、メンバー側には
「管理者の承認待ち」と表示されます。

## 上流へ依頼するときのテンプレート

tenant_admin の権限で完結しないものは、super_admin ／ 情シスに依頼します。
次の 3 点を添えると、そのまま作業できます。

- **何を**: 許可したいホスト名（`api.example.com` か `.example.com`）
- **なぜ**: どの MCP サーバー・どの業務で使うか
- **いつまで**: 恒久か、期限付きか
