# 06. チームの既定

[English](06-team-defaults.md) | 日本語

メンバーが何を出発点にするかを決める設定が、「運用」の下に 2 つあります。起動ダイアログが提案する
ブランチ名と、ようこそカードが名指しするエージェントです。どちらも助言するだけの既定で、何も拒否
しません。

## ブランチ命名ルール

メンバーが Issue から作業を起動すると、起動ダイアログにブランチ名と起点ブランチが入ります。その元に
なるルールは 4 層あり、強い順に次のとおりです。

1. **リポジトリ**：リポジトリ自身の宣言（`.agent-fleet/branches`、git-flow、Bitbucket のブランチ設定）
2. **メンバー**：作業項目の設定にある本人のテンプレートと、本人のルール
3. **テナント**：この画面のルール
4. **組み込みの既定**：現在のブランチから `{prefix}{ref}-{slug}`（例: `feature/45-empty-list`）

層は**項目ごと**に重ねられます。起点だけを宣言しているリポジトリでは名前はあなたのルールのまま、
テンプレートだけを決めているメンバーでは起点はあなたのルールのままです。つまりテナントのルールは
チームの既定で、リポジトリやメンバーが自分で決めたものが優先されます。

**ルールは助言だけです。** 従わない名前には起動・改名のダイアログで注意が出るだけで、拒否は
されません。強制にする設定もありません。

### ルールを編集する

テナント設定 → **ブランチ命名ルール**（運用の下）。ルールは JSON の配列で、各ルールの項目は
次のとおりです。`match` 以外は省略できます。

| 項目 | 意味 |
|---|---|
| `match` | 対象のリポジトリ。`origin` の `host/owner/repo` で、`*` は 1 区切り分、`*` だけなら全リポジトリ。より具体的な match が優先されます。 |
| `name` | テンプレート。例: `{prefix}{key}`、`{prefix}{ref}-{slug}` |
| `base` | 起点。`head`（現在のブランチ）、`default`（`origin/HEAD`）、または `develop` のようなブランチ名 |
| `types.<種類>` | 種類ごとの `prefix`・`base`・`from`（その種類にする課題の種別とラベル） |

種類は `feature`・`bugfix`・`hotfix`・`release`・`support`・`docs`・`chore`・`refactor` です。

```json
[
  { "match": "*", "name": "{prefix}{key}" },
  {
    "match": "bitbucket.org/acme/*",
    "base": "develop",
    "types": { "bugfix": { "prefix": "bugfix/", "from": ["Bug", "Defect"] } }
  }
]
```

**保存**すると、メンバーのワークスペースと同じ検査がすべてのルールに掛かります。知らない種類、git が
ブランチ名として受け付けない base や prefix、綴りの違う項目は、ルールの番号と理由つきで拒否され、
何も保存されません。空のまま保存するとルールはなくなります。保存は監査ログに
`tenant.branch_rules` として残ります。

### メンバーに届くまで

各メンバーのワークスペースは、起動時とその後 5 分ごとにルールを取りに来るので、変更は動いている
ワークスペースにも 5 分以内に届きます。コントロールプレーンに届かないあいだは、組み込みの名前に
戻らず、最後に受け取ったルールを使い続けます。起動ダイアログでは、テナントから来た項目の出所が
`tenant: <match>` と表示されます。

## メンバーの既定

新しいメンバーの最初の画面はホームで、その最上部にようこそカードが出ます。カードの 2 つ目の手順は
**エージェントを接続** です。Agent Fleet は複数のエージェント（Claude、Codex、opencode など）に
対応していて、新しいメンバーには、チームがどれを契約しているかが分からないのが普通です。ここで
それを指定すると、この手順に **「このチームの既定は Claude です（ほかのエージェントでも構いません）」**
と表示されます。

これは**案内であって、制限ではありません**。ほかのエージェントで接続しても手順は完了になり、
起動ダイアログではすべてのエージェントをそのまま選べます。メンバーがどのエージェントを使えるかは、
メンバー自身のアカウントと配備で決まり、この画面では決まりません。

### 既定のエージェントを設定する

テナント設定 → **メンバーの既定**（運用の下）。Claude・Codex・opencode・Cursor・Copilot・Kiro・
Muse のどれか、または **指定しない** を選んで **保存** を押します。**指定しない** にすると、選択肢を
並べた通常の文言に戻ります。

メンバー自身のアカウントが要らないものは選べません。シェルと SSM、それに配備の推論エンジン
（誰が使えるかは [推論エンジンを使えるメンバー](02-limits.ja.md#推論エンジンを使えるメンバーあなたが設定できる) で決めます）です。

### メンバーに見えるようになるまで

メンバーは、Console を読み込むたびに既定を読みます。ワークスペースが停止していても読めます。
画面を開いたままのメンバーには、読み込み直した後に反映されます。ようこそカードは、最初の
セッションを作るか最初のチャットを始めるまでしか出ないので、効くのはまだ始めていないメンバーです。

保存は [監査ログ](03-audit-usage.ja.md) に `tenant.member_defaults` として、選んだエージェントと
一緒に残ります。
