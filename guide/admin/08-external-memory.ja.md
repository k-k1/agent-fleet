# 08. Agent Fleet の外からのメモリ利用

[English](08-external-memory.md) | 日本語

メンバーは、Agent Fleet の外のエージェント（自分のマシンで MCP トークンを持つ Claude Code や Claude Desktop、または MCP OAuth で接続した claude.ai などのアプリ）に、
自分の Agent Fleet メモリの一覧・検索・読み取りを許せます。もう一段階選ぶと保存と忘却も許せます
（[メンバー編](../member/14-agent-memory.ja.md#外部のエージェントから-agent-fleet-のメモリを使う)）。このときメモリの本文はワークスペースの外に出て、そのクライアントのモデルに渡ります。
秘密情報のスキャンは認証情報を止めますが、顧客名や社内の事情までは止められません。このページは、テナント全体でこれを止める方法です。

## スイッチ

テナント設定 → **外部からのメモリ利用**（運用の下）。**許可**（すべてのテナントの初期状態）ではメンバーが各自で有効にできます。
メンバー自身の設定は引き続き **オフ** から始まるので、メンバーが選ぶまで誰にも変化はありません。**ブロック**にすると、
テナント全体からメモリのツールを引き上げます。

ブロック中は次のとおりです。

- `/mcp` は、テナントの誰に対しても `memory_projects`・`memory_index`・`memory_search`・`memory_read`・`memory_save`・
  `memory_forget` を一覧に出さず、名前を指定した呼び出しも未知のツールとして拒否します。メンバー自身の設定やトークンのスコープは関係ありません。
- 次のリクエストから、再起動なしで、すでに発行済みのトークンにも効きます。
- メンバーの設定は保持されるので、許可に戻せば各自が選んでいた状態に戻ります。
- Agent Fleet の中でのメモリ利用（セッション、Console のエージェントメモリ画面）と、`/mcp` のほかのツールには影響しません。

スイッチを読めないとき（ストアが使えないなど）は、ツールを出さない側に倒します。

変更は [監査ログ](03-audit-usage.ja.md) に `tenant.external_memory` として、`enabled=true` または `enabled=false` つきで残ります。
変更できるのはテナント管理者と super_admin だけです。配備全体で `/mcp` エンドポイントを止めるのは運用者の `AF_MCP_ENABLED` で、別のスイッチです。
