# サインインしたらワークスペースを起動する

[English](start-at-signin.md) | 日本語

メンバーが Console を開いて操作を始めたときに、停止しているワークスペースを自動で起動させられます。
朝いちばんに「起動」を押して待つ時間がなくなります。

## 全体像

| あなたがやること | 起きること |
|---|---|
| 配備管理者に、テナントの「サインイン時の自動起動」をオンにしてもらう | メンバーが Console を開いて操作すると、停止中のワークスペースが起動する |
| メンバーに、自分だけオフにできることを伝える | 自分で起動したいメンバーは、設定でオフにできる |

起動のたびにリソースを使うので、既定ではオフです。

## オンにしてもらう

スイッチはテナントの上限にあり、配備管理者だけが変えられます。あなたの画面には出ないので、配備管理者に頼んでください。

- 設定の名前は「**サインイン時の自動起動**」（「メンバーがサインインしたとき、停止中のワークスペースを自動で起動する」）です
- オンにすると、次にメンバーが Console を開いたときから効きます
- 配備全体で自動起動を止めている配備では、オンにしても起動しません

## 起動するとき、しないとき

起動するのは、ワークスペースが停止しているメンバーが、表示中のタブで Console を開いて操作したときです。

| 起動する | 起動しない |
|---|---|
| サインイン・アドレスの入力・ブックマークで Console に着いた直後（着いたこと自体を操作と数えます） | 再読み込みだけで、そのあとキー入力・クリック・タッチ・スクロールがないとき |
| 表示中のタブで、直近 1 分以内にキー入力・クリック・タッチ・スクロールがあった（再読み込みのあとも同じです） | 誰も操作していないタブ、裏に回っているタブ |
| | タブを開いている間に止まったワークスペース（アイドル自動停止・メンバー自身の停止・強制停止） |
| | ワークスペースの状態を読めないとき |
| | テナントの最大ワークスペース数に達しているとき |

- 1 つのページが起動を求めるのは 1 回だけです。起動したあとは、同じブラウザのほかのタブや再読み込みからも、30 分は求めません
- 断られたとき（スイッチがまだオフだったときなど）は 30 分の待ちに入らないので、オンにした直後から効きます
- セッションを作るときと同じ起動なので、[テナントの最大ワークスペース数](session-limits.ja.md#テナント全体の上限を確かめる) が効きます

起動している間、メンバーのホームには「**ワークスペースを起動しています…（ホームはそのまま使えます）**」と出ます。

### 上限に達していたとき

テナントの最大ワークスペース数に達していると起動せず、メンバーのホームに次のように出ます。

> 組織のワークスペース上限に達しているため、自動では起動しませんでした。ほかのワークスペースが止まってから、自分で起動してください。

いつもこうなるようなら、最大ワークスペース数を上げてもらうよう配備管理者に相談してください。

## メンバーが自分だけオフにする

テナントでオンになっていると、メンバーの **設定 →「ツールチェーン」** に「**サインイン時の自動起動**」の行が出ます。

- 「サインインしたとき、ワークスペースを自動で起動する」をオフにすると、そのメンバーだけ自動では起動しません
- 既定はオンです。ワークスペースが停止していても変えられます
- テナントでオフのときは、この行は出ません
