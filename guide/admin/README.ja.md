# テナントを管理する

[English](README.md) | 日本語

チームを管理する側の「やりたいこと」を、1 ページに 1 つずつまとめています。今の章を、順にここへ書き直しています。
まだここにないことは、下の「まだ書き直していない章」にあります。自分の作業については [やりたいことから探す](../user/README.ja.md) を見てください。

## はじめに

| ページ | できること |
|---|---|
| [チーム管理者の仕事](overview.ja.md) | テナント設定への入り方、自分の仕事と配備管理者の仕事の境目、最初の日に見ておくことを知る |

## メンバー

| ページ | できること |
|---|---|
| [メンバーの状況を見る](members/roster.ja.md) | 名簿とメンバー詳細で、ワークスペース・ディスク・セッションの状態と、要対応のものを確かめる |
| [メンバーを追加する](members/add.ja.md) | メールアドレスで人を名簿に足す。招待制と自動参加の違いを知る |
| [メンバーを外す](members/remove.ja.md) | 退職や異動で、アクセスを止め、home とバックアップを消し、名簿から削除する |
| [メンバーの Git トークンを入れ替える](members/git-token.ja.md) | 漏れたおそれのある内部 Git のトークンを、新しいものに変える |

## サインイン

| ページ | できること |
|---|---|
| [サインインの方法を決める](access/signin-methods.ja.md) | 自社の IdP や GitHub の組織を登録し、サインイン規則を読む |
| [サインインできるネットワークを絞る](access/networks.ja.md) | テナントを使える接続元を、決まったアドレスの範囲に絞る |
| [連携に使う OAuth アプリを選ぶ](access/oauth-apps.ja.md) | GitHub・Bitbucket・Jira の「OAuth で接続」が使うアプリを決める |

## リソース

| ページ | できること |
|---|---|
| [リソースの使われかたを見る](resources/overview.ja.md) | メンバーのリソースといま動いているセッションを見て、重いと言われたときに原因を絞り込む |
| [セッション数の上限を決める](resources/session-limits.ja.md) | メンバーごとのセッション数の上限を決め、テナント全体の上限と利用枠ボードを確かめる |
| [推論エンジンを使える人とモデルを決める](resources/engines.ja.md) | セルフホストのエンジンを使えるメンバーを決め、許可があればモデルを取り込む |
| [ワークスペースの大きさを決める](resources/workspace-size.ja.md) | メモリ・CPU・ディスクとマシンの種類を決め、home を広げる |
| [放置されたワークスペースを止める](resources/idle-stop.ja.md) | アイドル自動停止の見通しを見て、暴走したワークスペースを強制停止する |
| [サインインしたらワークスペースを起動する](resources/start-at-signin.ja.md) | 停止中のワークスペースを、メンバーが Console を開いたときに起動させる |

## チームの既定値

| ページ | できること |
|---|---|
| [ブランチ名の規則を決める](defaults/branch-rules.ja.md) | 課題から始めるときに提案されるブランチ名と分岐元を、チームでそろえる |
| [メンバーの既定値を決める](defaults/members.ja.md) | 新しいメンバーに案内するエージェントを決める |
