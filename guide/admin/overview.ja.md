# チーム管理者の仕事

[English](overview.md) | 日本語

テナント管理者は、チームのメンバー・リソース・サインインの方法・既定値を、Console の **テナント設定** から管理します。
このページでは、どこから入るか、どこまでが自分の仕事か、最初の日に何を見ておくかを説明します。

## 全体像

| あなたがやること | Agent Fleet がやること |
|---|---|
| メンバーを追加する・外す | 名簿をもとに、サインインした人をテナントに入れ、ワークスペースを用意する |
| メンバーの状況を見て、要対応のものに手を打つ | 各ワークスペースの数字を集め、空きが少ない・インストールに失敗したといった変化を通知する |
| サインインの方法と接続元のネットワークを決める | 決めた方法とネットワークの外からは、テナントを使わせない |
| ブランチ名や案内するエージェントの既定値を決める | 各メンバーのワークスペースと画面に既定値を届ける |

- **見えるのは自分のテナントだけです。** ほかのテナントのメンバーやセッションは見えません
- 多くの管理者は自分も作業するメンバーです。自分の作業は **設定**、チームの管理は **テナント設定** と、入口が分かれています

## テナント設定を開く

画面右上のアカウントメニュー（メールアドレスのボタン）から **テナント設定** を選びます。

- **テナント設定** が出るのは、どこかのテナントの管理者になっている人だけです
- 同じメニューの **設定** は、自分の個人設定です
- **管理** は配備管理者の画面で、テナント管理者には出ません

左のレールは「テナント」「サインイン」「連携」「運用」のグループに分かれています。

## 自分の仕事と、配備管理者の仕事

テナントをまたいで効くこと、人を締め出しかねないことは、配備管理者の担当です。
1 つのチームに閉じることは、メンバーを外す一連の手順も含めて、テナント管理者の担当です。

| ことがら | 担当 |
|---|---|
| メンバーの追加と削除、外すときの一連の手順 | **あなた** |
| メンバーごとのセッション上限、ホームディレクトリのサイズ、ワークスペースのマシン（配備が選ばせている場合） | **あなた** |
| ワークスペースの強制停止、監査ログ・稼働時間・クラウド費用の確認 | **あなた** |
| 推論エンジンを使えるメンバー（配備管理者がテナントに許した範囲で）、許可されていればモデルの取り込み | **あなた** |
| 利用枠ボードを使うかどうか | **あなた** |
| MCP サーバーの配布、MCP OAuth の接続、外部からのメモリ利用の許可 | **あなた** |
| ブランチ命名ルール、新しいメンバーに案内するエージェント | **あなた** |
| サインイン方法の登録、接続元の制限、連携アプリの OAuth | **あなた**（サインイン方法は承認が要ります） |
| テナントの作成、テナント全体の上限とアイドル自動停止、管理者権限の付与 | 配備管理者 |
| サインイン規則の変更、サインイン方法の承認、自前の推論エンジンをテナントに許すかどうか | 配備管理者 |
| egress 統制、読み上げエンジン、共有辞書、MCP ログイン許可ホスト、開発用 OIDC IdP | 配備管理者 |
| バックアップ、アップグレード、ホストの障害対応 | 配備管理者 |

ロールごとにできることの一覧は [ロールとできること](../ref/roles.ja.md) にあります。
自分の権限で終わらないことは、配備管理者に頼みます（[運用者向けのガイド](../operate/README.ja.md)）。

## 管理者になった最初の日にやること

何も起きていないうちに一度ひととおり見ておくと、いざというときに迷いません。

1. アカウントメニューに **テナント設定** があるか確かめます。なければ、まだ権限がありません。配備管理者に頼んでください
2. **運用 → メンバー** で、いま誰がいるかを見ます（[メンバーの状況を見る](members/roster.ja.md)）
3. **テナント → 上限・自動停止** で、効いている上限を見ます。テナント全体の上限は読み取り専用です
4. **運用 → 監査** と **稼働時間** を、ふだんの状態で一度読んでおきます。あとで「いつもと違う」に気づけます

ふだんは、朝に **セッション** をひと目見て、月末に **稼働時間** を書き出す程度です。
