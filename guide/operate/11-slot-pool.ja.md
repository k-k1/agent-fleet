# 11. ecs-ec2 のスロットプール

[English](11-slot-pool.md) | 日本語

`ecs-ec2` では、ワークスペースはプールから取った EC2 スロット上のタスクとして動き、ホームは停止中も
そのスロットに付いたままの EBS ボリュームです。スロットは super_admin が
**管理 → スロット** で管理します。

## ecs-ec2: 起動テンプレートを変えたあとのスロットの入れ替え

スロットはユーザーデータを起動時にしか読まず、停止したワークスペースは次の起動で同じスロットに
戻ります。そのため、スロットの起動テンプレートの変更（リリースのセキュリティ設定など）は今ある
スロットには届きません。インスタンスを手で終了するのではなく、Console から入れ替えます。

**`$Latest` より古いスロットは自動で入れ替わります。** ワークスペースの起動時にホームがそのような
スロットにあると、その起動で予約と同じ手順で新しいスロットへ移ります（WS バーへの表示はありません）。
`$Latest` より古い空きスロットはスイーパーが終了します。新しいスロットを起動できないとき（容量・
クォータ）も起動は古いスロットで成功し、その後 10 分以内の起動はやり直さずに古いスロットのまま
動きます。自動の入れ替えは監査ログに残ります
（`pool.slot_replace_auto`）。スロット画面には **$Latest より古い・次回起動で自動入れ替え** と出ます。
止めたいときは Control Plane の `AF_ECS_EC2_AUTO_REPLACE_OUTDATED_SLOTS=false` を設定します。古いスロットへ戻すことを
禁じたいときは、次のように自分で予約します（その場合、新しいスロットを起動できなければ起動は失敗します）。

1. **管理 → スロット**（super_admin）。**テンプレート**列に各スロットを起動した起動テンプレートの
   バージョンが出て、古いものには **$Latest より古い** と付きます。
2. **N 台すべてを入れ替え予約…** は `$Latest` より古いスロットと、それぞれに載っているワークスペースを
   一覧で示し、確認するとそのスロットだけを予約します。行の **入れ替えを予約** は 1 台だけ予約し（予約済みの行には
   **次回起動で入れ替え予定** と出ます）、**予約の取消** で戻せます。予約はすべて監査ログに残ります（`pool.slot_replace_reserve` /
   `pool.slot_replace_cancel`。移るワークスペース名つき）。
3. 実行中のワークスペースには何も起きません。利用者の WS バーに **新しいスロットへ移動** が出て、次に
   停止 → 起動したときに `$Latest` から新しいスロットを起動し、ホームを移して古いスロットを終了します。
   その起動はいつもより 25 秒ほど長くかかります。ファイル・リポジトリ・ログインはそのままで、
   ホームを削除することはありません。
4. 新しいスロットを起動できないとき（容量・クォータ）は、理由つきで起動が失敗し、予約は残ります。
   予約されたスロットに戻すことはしないので、時間をおいてやり直してください。ワークスペースが
   載っていない予約済みスロットはスイーパーが終了します。

詳細と結果の確かめ方は `deploy/aws/ecs/README.md` の「Moving retained slots onto new user data」に
あります。

## ecs-ec2: 管理プレーンのメモリ保護

スロットのユーザーデータは、SSM エージェント・docker・containerd に
systemd の `MemoryMin`（192 / 256 / 128 MiB）を与えます。ECS エージェントは `ecs.service` の子ではなく
docker コンテナとして動くため、小さな補助サービス（`af-protect-mgmt`）がそのスコープを探して
192 MiB の `memory.min` を設定します。補助サービスは 30 秒ごとに再適用するのでエージェントの
再起動にも追従し、ECS・SSM エージェントの OOM スコアも下げます（初回起動時にすでに動いている
SSM エージェントのプロセスにも効きます）。下限が効くよう `system.slice` に合計 832 MiB を設定します。
メモリが逼迫するとカーネルは先にワークスペースコンテナのページを回収するため、メモリを使い切る
ワークスペースのせいで、EC2 は正常のままエージェントだけが応答しなくなるスロットは生じにくくなります。
合計はホスト予約（`AF_ECS_EC2_HOST_RESERVE_MB`、既定では 1024 MiB 以上）に収まります。予約を
832 未満にすると、保護量が予約を上回ります。これは起動テンプレートの変更なので新しい `$Latest` が
作られ、今あるスロットには上の入れ替えを通してのみ届きます。cgroup v2（Amazon Linux 2023 の既定）が前提です。

## ecs-ec2: 動かなくなったスロットの停止

スロットは **動かなくなる** ことがあります。EC2 インスタンスは起動中でステータスチェックも `ok` なのに、ECS エージェントが
未接続で、SSM も応答せず、メンバーの home がまだ載ったままの状態です。そのメンバーの Start は待たされるか失敗し続けます。
スロット画面ではこの行が起動中のまま **（まだタスクを受け付けない）** と出て、**停止（強制）**（super_admin）が使えます。

1. **管理 → スロット** の行で **停止（強制）** を押し、確認します。確認画面には載っているワークスペースが出ます。
   ECS エージェントが接続していて **かつ** SSM がオンラインのスロットは、サーバーが拒否します（`slot_healthy`）。この操作は
   応答しないスロット向けです。停止済み（`slot_not_running`）と隔離済み（`slot_quarantined`）も拒否されます。どうしても
   正常なスロットを止めるときのために、API には明示的な上書きがあります。Console は送らず、そのスロットで動いている
   ワークスペースも一緒に止まります。
2. そのスロット上のメンバーの Start を打ち切り（ワークスペースは停止に見えます）、Control Plane が積んだコマンド
   （home のロックを握り続ける未実行の umount / mount）を取り消し、インスタンスを停止します。停止はまず通常の
   シャットダウンなので、カーネルが home をアンマウントできます。3 分たっても止まらなければ Control Plane が Force 付きで
   やり直し、`stopping` 中にもう一度押すとすぐ Force で送ります。タイマーは、その後に起動し直されたインスタンスには何もしません。
3. **スロットは隔離せず、home もそのまま載ったままです。** スロットの行が休止中（停止済み）になってから、
   メンバーの次の Start が通常の経路で同じスロットを起こします。**それを待ってください。** インスタンスがまだ
   `stopping` のうちに Start すると、約 2 分で待ちきれず、claim が切れるまでワークスペースが「起動中」のままになります。
   そうなったらワークスペースを停止してから、もう一度 Start してください。再起動で詰まりが解け、スロットの ECS エージェントが再接続して、そこに `STOPPING` のまま残っていた
   タスクを報告します。証拠としてインスタンスを残すのは隔離の役目で、応答しないスロットを自動で隔離へ回すことはありません。
4. 結果（取り消したコマンド数、Force を使ったか）は呼び出し直後に画面に出て、監査ログにも残ります
   （`pool.slot_force_stop`。ワークスペース・二つの健全性シグナル・件数つき）。
   これには Control Plane のロールに `ssm:ListCommands` / `ssm:CancelCommand` /
   `ssm:DescribeInstanceInformation`（`20-platform` の `SsmSlotForceStop`）が必要です。
   **ボタンを使う前に `20-platform` スタックを更新してください。** 古いままだと健全性の確認が
   AccessDenied になり、操作を実行できません。

**STOPPING のまま残るタスク。** スロットのエージェントが停止を報告できないと、ECS はそのワークスペースの前のタスクを
`STOPPING` のまま保持し、メンバーの次の Start がそれを待ちます（サービスは同時に 1 タスクしか許しません）。エージェントが未接続の
スロットの行には **タスク STOPPING N 分** と出ます。インスタンスが再び動けばエージェントが停止を報告します。強制停止のあとの
メンバーの次の Start がそれに当たり、EC2 コンソールでインスタンスを起動しても構いません。Control Plane は自動では行いません。
