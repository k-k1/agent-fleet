# 07. 推論エンジンと読み上げ: 管理モーダルのパネル

[English](07-engines.md) | 日本語

フリート自前の GPU エンジンと音声エンジンは、管理モーダルの 1 か所から運用します。見えるのは super_admin だけです。
この章はそのパネルの章で、モードごとの費用、GPU のクラス、モデルの取り込み、状態の読み方を扱います。
エンジンをどこから持ってくるかは別の問いで、章を分けています:
[08 自前の ComfyUI](08-image-engine.ja.md)、[09 ほかの配備のエンジンを借りる](09-borrowed-engine.ja.md)、
[10 自前の llama.cpp](10-llm-lan.ja.md)。テナント管理者に縮小版のモデル画面が見えるのは、あなたが許可したときだけです
（[admin 02](../admin/02-limits.ja.md#エンジンのモデルを取り込むテナントに許可が出ている場合だけ)）。

## 推論エンジン（自前の GPU・super_admin 専用）

管理モーダルの「推論エンジン」は、Control Plane がこの画面を出せる配備なら常に出ます。エンジンが
登録されるのを待ちません。まだ 1 本も動かしていない配備でも同じ項目が空の一覧で出て、隣の
**「API トークン」**（後述の Hugging Face と Civitai のトークン）も同じように開けます。会話の役（llm）は
自前のチャットエンジン、画像の役（image）は ComfyUI です。この build が扱えない images provider を
名乗る行は、知らないうちに消されることはありません。画面がその行に印を付けて provider 名を出し、build が知っている
provider に向け直すまで、その行では `generate_image` が動きません。

この項目は画面 2 つでできています。「**推論エンジン**」は機械の側で、エンジンごとに 1 行、
モード・状態・インスタンスが並びます。行の「**モデルカタログ**」を押すとモデルが独立した
ペインで開き、**「文章」／「画像」** で役を、**「モデル」／「LoRA」** で並べるものを切り替えます。LoRA がチェックポイントの一覧に混ざることはありません。

役ごとに 3 つのうち 1 つを選びます。

| | 何が起きるか |
|---|---|
| **無効** | そのエンジンは起動メニューからも `generate_image` からも消え、要求は 503 で断られます。インスタンスはすぐ止まります。 |
| **オンデマンド** | 要求が来たときだけ GPU のインスタンスを買い、しばらく誰も使わなければ自分で止まります。**既定はこれです。** |
| **常時稼働** | インスタンスを止めません。応答は速くなりますが、**使っていない間も課金され続けます**。 |

「状態」は選んだモードではなく、**いま実際に何が動いているか**です。「無効」を押した直後は
モードが無効・状態が「停止処理中」になります。押してすぐインスタンスが消えるわけではないためで、
これは食い違いではありません。

オンデマンドで動いているエンジンには「**自動停止まで**」（分）の欄があります。最後の利用から
その時間が過ぎると自分で止まります。欄には下限が表示されます。下限は起動期限の長さで、起動の途中で
止められないためです。上限は 24 時間です。保存した値はコントローラの次の巡回から効き、監査ログに
残ります。外部管理のエンジンにこの欄はありません。ここから止めることはないからです。

⚠️ **初回の要求は待たされます。** 止まっているエンジンへの最初の要求は、インスタンスを買って
モデルを読み込む 3 分前後を待ってから答えが返ります（呼び出し自体は 1 回で完結し、
やり直しは要りません）。急いでいる作業の前に、あらかじめ「常時稼働」で暖めておく手もあります。**戻すのを忘れないでください。**

### GPU のインスタンスクラス

配備が**インスタンスクラスか提案（offer）**を宣言している場合だけ、モードの下に選択欄が
出ます。どちらも宣言していない配備には**欄そのものが出ません**（インスタンスは配備時に
決めたもので固定です）。

配備が**提案**を宣言している場合（同じ GPU の段に、「**オンデマンド**」か **Spot** かの買い方が
付いている）、Control Plane はその一覧から買います。提案は**宣言された順に上から**
試され、買えなければ次へ落ちます。画面には「**提案（宣言された順に、上から試します）**」の
一覧と、**「いまの提案:」**、「**試した順:**」が出て、それぞれが何と答えたか（**取れた**・
**在庫なし**・**クォータ**・**予算切れ**・**取り上げられた**・**要求の設定で買えず**）が
並びます。選択欄は「**自動（既定）**」になっていて、段を選ぶとそれに**固定**されます
（バッジは「**自動ではなく固定されています**」、「**自動に戻す**」で解けます）。固定した
提案は次へ落ちません。この下に書いてある「次のインスタンスから反映される」「コールドスタート
1 回ぶん」「戻す」は、提案のある配備でも同じです。

インスタンスクラスの選択欄は、VRAM を多く使うモデルを試したいときに、**より大きい GPU のインスタンスへ一時的に上げる**ためのものです。

- **選んでも、いま動いているインスタンスは変わりません。** 効くのは**次に買うインスタンス**からです。動いている
  ときは「いま動いているのは g6.xlarge のインスタンスです」と出て、隣に「**いま入れ替える**」が並びます。
- **入れ替えはコールドスタート 1 回ぶんかかります**（llm で約 9 分、image で約 3 分）。
  新しいインスタンスはモデルを取り直します。さらに、**古いインスタンスがクラスタから消えるまで新しいインスタンスは
  起動しません**。先に起こすと GPU の台数上限に当たり、*気づかないうちに配置されないまま*
  「起動が遅い」ようにしか見えないからです。
- **止まっているエンジンなら、選ぶだけで費用はかかりません。** 次に誰かが使ったときの
  起動に反映されます。
- 🔴 **既定と違うクラスのままにすると、時間単価が上がったまま戻りません。** そのときは
  「既定と違います」というバッジと「**既定に戻す**」が常に出ます。**用が済んだら戻して
  ください。**
- **買えないクラスもあります。** アカウントの GPU 台数上限を超えるクラスを選ぶと、インスタンスは
  いつまでも用意されません。そのときは「状態」の下に ECS の理由（`VcpuLimitExceeded`）が
  そのまま出ます。上限の引き上げは AWS に（アカウントの GPU 上限の引き上げとして）依頼してください。

#### Spot の提案は「中断を許容する」にチェックを入れるまで買われません

提案の一覧に **Spot** の行があっても、それだけでは買いません。一覧の下の
「**中断を許容する（Spot のインスタンスを買ってよい）**」にチェックを入れた役だけが、その行を
候補にします。チェックが無いあいだ、その行は一覧に残ったまま「**中断の許容が要ります**」の
印が付き、選択欄でも選べません（宣言そのものが無視されているわけではない、と分かるように
しています）。

同意しているのは「インスタンスが止まってもよい」ではなく、次の 2 つです。

- **そのとき処理中だった応答は失われます。** llm なら会話の途中で切れます。
- **次の要求はコールドスタートを待ちます**（llm で約 9 分、image で約 3 分）。

同じ提案が続けて 2 回取り上げられると、その回の起動ではその提案を飛ばすので、最後は VRAM の
合うオンデマンドの提案に着地します。チェックを外しても、**いま動いている Spot のインスタンスは
そのまま**です。効くのは次に買うインスタンスからで、クラスの変更と同じ性質です。

### モデルが載るかどうかの警告

モデルを**有効にするとき**、そのモデルが必要とする VRAM が選択中のクラスを超えていると、
確認を求められます。**禁止ではありません**。量子化やオフロードで載ることもあるので、
承知のうえなら続けられます。VRAM が足りないと、CUDA は遅くなるのではなく**落ちます**。

必要量の出どころは 3 通りで、画面にどれなのかが書かれます。

| 表示 | 意味 |
|---|---|
| 実測 | 運用者がそのモデルで測った値です。 |
| 重みだけの下限 | ファイルの大きさから出した**下限**で、コンテキストの分は含みません。「少なくともこれだけ」という意味です。 |
| 不明 | 誰も測っていません。🔴 **「収まる」という意味ではありません。** |

### モデルの取り込みと、テナントとの関係

モデルの取り込みは 1 押しです。モデルを**検索**し、カードの**追加**を押し、カードに出る計画を
読んで**取り込む**を押します。計画には、そのモデルに要るファイルが 1 行ずつ、その押下の費用
（ダウンロードなら MiB、配備が既にバイト列を持っていれば「**取得なし（配備が持っています）**」か
**「取得なし（バケットの中で移します）」**）と、ライセンス、出所が持つ警告が並びます。警告は、
そのファミリーに要る部品（テキストエンコーダや VAE）の宛先を別の行が既に宣言している、または
済んでいない取り込みジョブが記録しているときにも 1 行出て、先にすること（その行を揃える、
そのジョブを消す）を示します。各ファイルの
置き場所と、そのファミリーに要る部品は Control Plane が決めるので、カードは役割も鍵もファイル名も
訊きません。複数ファイルに分かれたモデルも、同じ 1 押しで入ります。検索は「**ファミリー**」で
1 つに絞れ（既定は「**すべて**」）、ComfyUI 向けの構成のリポジトリも普通のものと同じように
見つかります。スマホでは検索欄・絞り込み・並び順がカードの上に留まり、末尾まで来ると次のページが
読み込まれ、例示画像はサムネイルで届きます。

検索は一度に 1 つの出所へ尋ねます。その上のタブがこの配備の持ち物で、**Hugging Face** と
**Civitai** は常にあり、**Civitai Red**（Civitai が NSFW の閲覧用に分けた姉妹ドメイン）は
配備がそれを与えられたときにだけ出ます。標準の配備は持っていません。タブも切り替えも無く、
それでも検索を投げれば断られます。与えられている配備（Control Plane の
`AF_ENGINE_CIVITAI_RED`）では、super_admin が「**API トークン**」で再デプロイなしに
出し入れできます。🔴 これは配備が**何を提供するか**の選択であって、内容の絞り込みではありません。既定の Civitai タブにも Civitai の NSFW レベルを持つモデルは出ます（だからカードには
そのレベルが必ず出ます）。取り込みフォームへの `civitai.red` のアドレスの貼り付けは、
どちらでも通ります。

検索結果のカードには、**何かをダウンロードする前に「出所が許していないこと」** も出ます。
Hugging Face のリポジトリなら「**gated（規約に同意）**」か「**gated（作者の承認待ち）**」、
Civitai のファイルなら「**要ログイン**」（後述の Civitai トークンで通ります）、そして
ライセンスと内容の印（**商用不可**・**要クレジット表記**・**派生不可**・
**同一ライセンスのみ**・**有料**・**早期アクセス（期限付き有料）**・**非公開**・
**サイト内生成専用（DL 不可）**・**NSFW**（Civitai 自身のレベルつき）・**実在人物**・
**未成年**・**ウイルススキャン未通過**・**pickle 警告**）です。どれも出ていないカードは「判別できなかった」のであって、「誰でも
使える」ではありません。

カードは、取り込み元の名前（「SDXL 1.0」「Illustrious」など）がこの配備のファミリーに対応する
なら「**ファミリー**」が選ばれた状態で、作者が公表している Steps / CFG / サンプラーが
「**作者の記述から拾いました（未検証）:**」の下に、拾った一文を添えて入った状態で出ます。
「**この値を入れる**」で残ります。推測はしません。配備が知らない名前ならファミリーは
「**選んでください**」のままで、選ぶまで押下は断られます。保存した値はモデルの行に残り、
生成のときにファミリーの既定へ**欄ごとに**上書きされます。空欄は既定のままです（行の
「**パラメータ**」に宣言済みの値が出ます）。

登録済みの行の下には **S3 Bucket**（タブ名は「**バケット**」）があり、配備が持つオブジェクト全部と、
それを宣言している行、取り込み中・失敗が並びます。どの行も宣言していないバイト列はそこで
モデルとして登録するか消せます。ファイルが揃っていない行は行自身の**揃える**で直します。部品側
からは操作しません。**揃える**は、中身は正しいのに置き場所（キー）が違うファイルも直します。
取り直さずに S3 Bucket の中で移します（**「バケットの中で移します（ダウンロードなし）」**）。

登録済みのカードは、**ペインの幅に入るだけの列**で並び、カードごとに自分がもらった幅で中身を
畳みます。広いペインでは 1 行 1 モデルではなく、何件かを横に並べて比べられます。
登録済みの行は**ファミリー**でまとまります。区画ごとにファミリーが見出しになり、その上のチップで
1 つに絞れます。ファミリーを宣言していない行が先頭に来ます。Control Plane がそれを有効化できない
からです。ファミリーを持たないチャットエンジンの行は、代わりに**配布者**でまとまります。カードの
見出しは配布元が付けた名前とバージョン（「MeinaMix — Meina V11」）で、行の id はその下に残り、
配布元が公開している作例が右に出ます。これができる前に取り込んだ行にはどちらもありません。
ツールバーの「**名前と作例をまとめて取る**」が、配布元のページを 1 行ずつ読んで埋めます。同じ操作は
カード 1 枚ごとの「**配布元から名前を取る**」にもあります。どちらも、全部の行に名前が入ると
消えます。取り込み元が素の URL の行と、取り込み元の記録が無い行は埋められません。どちらにも
モデルのページが無いからで、カードがそう言います。S3 Bucket には何も複製しません。行が記録するのは
配布元が絵を置いた場所で、取りに行くのはブラウザです。配布元が消した画像は空の枠になり、同じ操作で
直ります。

チャットエンジンの行は、取り込み元の**リポジトリ**でまとまります。量子化のリポジトリは
1 つのモデルを十数のサイズで出したものなので、見出しはそのうち何件を配備が持っているかを言います。
「**この配布元の他の量子化を見る**」で残りが一覧になり、各行にサイズ、表の上の窓での KV キャッシュ、
そして合計がこのエンジンの GPU クラスに収まるかが出ます:
**「収まります」**・**「ぎりぎり（n%）」**・**「このクラスでは入りません」**（入る最小のクラスも
名指しします）。どの行の「**追加**」も、通常の計画カードを記入済みで開きます。この表は
重みと KV キャッシュの見積もりで、そう書いてあります。llama.cpp の計算バッファと CUDA
コンテキストは含められません。表の上の窓を変えると表が引き直されますが、行は何も変わりません。

同じ判定は、モデルを取り込むときの計画カードにも出ます。その隣の「**コンテキスト**」欄は、
モデルの公開上限ではなく、**クラスに収まる最大の窓**で開くようになりました。上限は上限として
別に表示されます。これは見た目以上に影響します: 27B の KV キャッシュは窓 262,144 で 66,560 MiB、
32,768 で 8,320 MiB なので、上限で見積もる画面は大きなモデルを全部「不可能」と報告していました。

取り込み元を読み返せる登録済みカードには、押すものがもう 1 つあります。Hugging Face の
リポジトリから来たチャットモデルには「**別サイズ…**」（同じ梯子に、どの行からでも届きます）、
Civitai から来た画像モデルには「**別バージョン…**」（そのモデルの他のバージョンに、サイズ・
収まるか・取り込み済みかを添えて。配布元がサイズを返さないバージョンには判定を出しません）。
どちらも最後は普段の計画カードに着きます。取り込むと新しい行になります。入れ替えるときは、
新しい行で「**これで起動する**」を押してから、古い行の登録を消してください。カタログは、別の
タブを見ている間も検索結果・絞り込み・スクロール位置を保ちます。

行は、取り込んだ後からでも整えられます。行の「**ファイル**」にはファイルごとの取り込み元が
記録され、「**配布元を見る**」のリンクになります。行の「**編集**」で、説明・ファミリー・
実測 VRAM・チャットモデルのコンテキストと最大出力・LoRA の「**起動語**」・生成の
「**パラメータ**」を直せます。

計画カードの判定はチャットモデルの「**編集**」にも出て、「**このクラスに収まる最大 n にする**」が
1 押しで入ります。そして役の GPU クラスを変えると、全行の窓が新しいクラスに合わせて自動で
書き換わり、動いた行（旧 → 新）と合わせられなかった行が理由つきで並びます。反映は次にエンジンが
起動したときからです。走行中のエンジンは起動時の窓のままです。

この配備で**実際に測った画像ファミリー**については、計画カードと「**編集**」の両方が、その
実測値を欄の隣に出します。測ったときの条件（測った GPU・画像の寸法・batch・参照画像の枚数。
同じ走行でも、退避の要らない大きな GPU では大きな数になります）が添えられます。
「**編集**」ではそれが 1 押しで入りますが、**取り込みは決して書きません**。この欄は「運用者が
測った数字」であり、配備が買う GPU の大きさをそこから決めるからです。空のままだと梯子は行の
ファイルの合計に落ちます。分割ファミリーでは実際の使用量より大きく（Qwen-Image-Edit では
合計 28,676 MiB に対し実測 20,862 MiB）、必要より一段大きいインスタンスを買うことになります。

画像ファミリーのうち 3 つは指示編集のモデルで、それぞれ自分の部品を持つ分割ファミリーとして
入ります。**Qwen-Image-Edit 2509** と **2511** は編集と部分描き直しだけで（素の生成も strength も
寸法の選択もありません）、参照画像は 3 枚までです。**Qwen-Image 2.1** は生成も編集もし（参照は
10 枚まで）、**この 2 つとファイルを 1 つも共有しません**。オートエンコーダが別のもので、ローダーは
それを受け取ってしまいノイズに復号するので、部品は編集ファミリーのものが既にあっても自分の
ファイルとして取り込まれます。Qwen-Image 2.1 の行が要る ComfyUI のバージョンは
[モデルは手で登録する](08-image-engine.ja.md#モデルは手で登録する)にあります。

押下が「宛先を既に何かが押さえている」で断られたときは、
カードが押さえているもの（**登録済みの行**・**取り込みジョブ**・**バケットのオブジェクト**・
**実行中のタスク**）を名指しし、次の一手を 1 つだけ出します: **「登録」**・**「揃える」**・
**「置き換える」**・**「行の登録を消す」**・**「ジョブを消す」**（済んだ取り込み履歴の 1 行を
消します）。

取り込みを起こせるのは、既定では **super_admin** だけです。テナントに許可を出すこともでき（管理モーダル → テナント →
「上限・自動停止」→ **「推論エンジンのモデル取り込み」**）、許可されたテナントの管理者には縮小版のモデル画面が出ます。
許可で何ができ、何があなたに残り、何が見えるかは、テナント管理者向けに
[admin 02](../admin/02-limits.ja.md#エンジンのモデルを取り込むテナントに許可が出ている場合だけ) に書いてあります。許可でカタログがテナントごとに分かれることは
ありません。理由は次の段落のとおりです。

2 つのトークンは管理モーダルの「**API トークン**」にあり、エンジンを 1 本も登録していなくても
開けます。Hugging Face のトークンが無いと gated でないリポジトリしか取り込めず、Civitai の
トークンが無いとログイン必須の資産は取り込めません。どちらも配備全体で 1 つで、暗号化して
保存され、読むのは取り込みタスクだけで、エンジンのインスタンスには渡りません。

🔴 **カタログは配備に 1 つで、テナントごとには分かれません。取り込まれたモデルの id は
どのテナントからも見えます。** これは意図した設計です。GPU のインスタンスはテナント間で共有していて、
有効なモデルは起動のたびに全部そのインスタンスへ同期されるので、テナントごとにカタログを持たせると
**1 テナント 1 モデルでも約 5 テナントでコールドスタートが 10 分を超えます**（実測。同期は直列で
約 159 MB/s）。分けたい境界は GPU のインスタンスであって、カタログではありません。
**この許可を「テナント間の分離」として読まないでください。**

### いまの状況を見る

モードの下に、そのエンジンの現況が出ます。**書いていない行は「分からない」という意味**で、
0 や「予定なし」で埋めてはいないので、そのつもりで読んでください。

- **インスタンスの起動**：GPU インスタンスがクラスタに入った時刻と、そこからの経過時間、
  インスタンス ID。「サービスの更新」と出ているときはインスタンスが見つからなかったときで、
  そちらは配備の更新でも動く時刻なので、インスタンスの寿命そのものではありません。
- **自動停止**：オンデマンドで動いているときだけ、**「自動停止まで」**の設定から決まる時刻で
  出ます。**「常時稼働」では出ません**。
  止まらないからです。「無効」や停止中も同じで、出ないことが答えです。
- **直近 N 分の要求**：その窓に届いた要求の数です。⚠️ この数は **Control Plane が
  自分のメモリで数えているだけ**なので、Control Plane が入れ替わると 0 に戻ります。
  数え始めてから窓ぶん経っていないときは「この CP が数えているのは直近 … だけです」と
  但し書きが付きます。隣の **「最後の要求」は保存されている**ので、そちらは入れ替えを跨いでも
  正しい値です。**0 件だからといって誰も使っていないとは限りません。**
- **モデル**：スタックが宣言しているモデル名です。`(読み込み済)` は、そのエンジンが実際に
  応答を返せる状態まで暖まっていることを表します（起動直後は `(宣言。まだ読み込まれて
  いません)` で、ここが 3 分前後かかる部分です）。
- **起動に失敗しているとき**は、ECS の理由がそのまま出ます（「配置できるインスタンスが無い」
  など）。AWS のコンソールを開かなくても、ここで読めます。

### 稼働実績（14 日）

「稼働実績」を開くと、**縦 24 時間 × 横 日付**のヒートマップが出ます。1 マスが 1 時間で、
色が濃いほどその時間の稼働が長かったことを表します。

- 濃さの意味は 2 つから選べます。「**応答できた時間**」は要求に答えられた時間、
  「**インスタンスがあった時間**」はそれに加えて、起動中（まだ答えられない）と後始末（タスクが消えた
  あとインスタンスが残っている）を含みます。**後ろ 2 つも課金されます**ので、請求書と
  突き合わせるときは「インスタンスがあった時間」で見てください。
- 🔴 **空白のマスは「止まっていた」ではなく「記録が無い」です。** Control Plane が
  動いていなかった時間、またはそのエンジンがまだ無かった時間で、後から埋めることはできません。
  止まっていた時間は灰色で、空白とは別の色です。
- **金額は出ません。** クラウドの実費は日単位でしか取れないため、時間別に金額を出すと
  「単価×秒数」の見積りにしかならないからです。この画面が答えるのは「いつ動いていたか」で、
  「いくらだったか」はクラウド費用の画面が答えます。この配備が知っている唯一の実際の単価は、
  買ったインスタンスごとの時間単価で、それは監査ログの `engine.<エンジン>.offer` の行に、実際に
  買えたインスタンスの型と一緒に 1 度だけ書かれます（[admin 03](../admin/03-audit-usage.ja.md)）。

## 読み上げ（音声エンジンと共通の読み仮名辞書）

管理モーダルの「読み上げ」には 2 つの役目があります。VOICEVOX（ずんだもん）エンジンの起動・停止と、
**テナント共通の読み仮名辞書**です。

- **エンジン**は推論エンジンと同じ 3 つのモード（**無効** / **オンデマンド** / **常時稼働**）を取ります。
  起動には 1〜2 分かかり、準備が整うまで日本語の読み上げは Polly が代読します（Polly 未設定なら音声は
  出ません）。オンデマンドでは、需要（5 分間で 2,000 文字）が溜まった時点で自動起動し、30 分だれも
  聞かなければ自動停止します。自動の起動・停止はすべて監査ログに残ります。無効にすると読み上げは
  すぐ Polly に切り替わり、AWS ではおよそ 1 分後に ECS の desired count を 0 にします。VOICEVOX
  エンジンがなく、ECS 管理下でもない配備では、この画面から起動できるものがないので、スイッチは無効の
  まま固定されます。音声エンジンはほかの配備から借りることはできません（[09](09-borrowed-engine.ja.md)）。
- **辞書**は全メンバーの読み上げに適用されます（各メンバーの個人辞書が同じ表記を上書きします）。
  1 行に 1 件「表記=読み」、`#` 始まりはコメントです。保存した変更はほかのメンバーに次回の Console
  ロードから反映されます。製品名や社内用語の読み間違いが続くときは、テナント管理者から追加を頼まれます。

## 絵に描かせないもの

「描かせないもの」を言える場所は 3 つあり、上書きではなく**足し合わされます**。

- **モデル行自身のもの**：そのチェックポイントの配布元が「避けろ」と書いているもの。同じ
  パネルの、その行で登録します。
- **利用者のもの**：要求ごと（画像ツールの `negative_prompt`）。
- **あなたのもの、エンジン全体に**：「全画像から除外する語」の欄。誰の要求でも、どの
  チェックポイントが答えても適用されます。

3 つとも空なら固定の既定（`blurry, lowres, deformed, watermark, text`）が使われます。自前の
ものを宣言した行は、その既定に足すのではなく**置き換えます**。

**これはネガティブプロンプトであって、コンテンツフィルタではありません。** 語は
「そこから離れる向き」としてサンプラーに渡されるだけです。門ではなく、強い prompt には
負けます。そして何より、**蒸留系のファミリーは完全に無視します**。Z-Image と FLUX.2 klein
は cfg 1 でサンプリングし（ネガティブ側がちょうど打ち消されます）、FLUX.1 にはネガティブの
入力自体がありません。語が届くのは誘導のあるファミリー（SD 1.5・SDXL・SD3.5・Anima・
Krea 2・Qwen-Image-Edit 2509 / 2511）で、そこでも cfg 1 の行は同じように打ち消します。
Turbo 版のチェックポイントのほか、Krea 2 と Qwen-Image 2.1 はレシピが cfg 1 から始まるので、
行が上げない限りそうなります。無視するモデルが答えた要求は**警告にそう出ます**（ファミリーの名前つき）。作られる
ものについて保証が要る配備なら、保証はここにはありません。

寸法を言わない要求が何で描かれるかもファミリーが決めます。メガピクセル世代のファミリーは
1024×1024、SD 1.5 は 512×512 です。あの UNet に 1024 を頼むと、エラーではなく被写体が
二重になったもっともらしい絵が返るからです。行自身の寸法一覧があればそちらが優先です。
