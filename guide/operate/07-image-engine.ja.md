# 07. 自前の ComfyUI で画像を生成する

[English](07-image-engine.md) | 日本語

セッションはプロンプトから画像を生成できます。既定でそれを実行するのは**メンバー自身の
CLI のプラン**——Codex の背後の ChatGPT ログイン、agy の背後の Gemini/Antigravity
ログイン——であり、フリート自身の GPU エンジンは AWS で買うものなので `ecs-ec2` 形態に
しかありません。

この章は 3 つめの選択肢です。**すでに自分の網の中で動いている ComfyUI** を、`compose` /
`native` / `docker` の配備から指します。誰かの机の下の GPU 機、WSL2 の Windows 側、
共有サーバー。中継するのは Control Plane なので、**セッションはその在り処も資格情報も
知りません**。

必要なのは環境変数 2 つと、手で維持するモデルの一覧だけです。**エンジンはあなたのもの
のまま**で、Control Plane はそれを起動も停止もしませんし、費用も付けません。

4 つめの選択肢もあり、それは別の章です。すでに AWS で Agent Fleet を運用しているなら、
この配備から**そちらのエンジンを借りられます**——
[08 別の配備のエンジンを借りる](08-borrowed-engine.ja.md)。あちらは画像だけでなく
チャットのエンジンも対象で、起こすのも払うのも向こうのフリートです。

## 環境変数 2 つ

どちらも Control Plane が**起動時に 1 回だけ**読みます。変更は CP の再起動です——
いまのところ Console に入力欄はありません。

| 変数 | 意味 |
|---|---|
| `AF_COMFY_URL` | ポートまで含めた完全な URL を、**CP から見た形**で。例: `http://192.168.1.20:8188`。これを設定することが経路を開くことです。 |
| `AF_COMFY_API_KEY` | 任意。上流へ `Authorization: Bearer` として送ります。生成の呼び出しにも**ヘルスチェックにも**付きます。 |

置き場所は形態によります。

| 形態 | 置き場所 |
|---|---|
| compose / docker | compose ファイルの隣の `.env`（CP のサービスがファイルごと読みます） |
| native | `af start` の環境、または systemd unit の `Environment=` — [deploy/native/README.md](../../deploy/native/README.md) |

サーバー版の ComfyUI は `--listen` を付けて起動するまで loopback にしか応答せず、
ホストのファイアウォールが CP の動く機械からの着信をそのポートで許可している必要が
あります。**Windows の ComfyUI Desktop は未確認です**——`--listen` に相当する設定名を
確かめていないので、ここの手順はサーバー版のものです。

## ここでのモードの意味

Console の**管理 → 推論エンジン**では、この種のエンジンは**外部管理**として出ます。
設定は **on** と **off** の 2 つだけです。「オンデマンド」はありません——あれはクラウドの
インスタンスを買って手放す設定で、ここには買うものがありません。

🔴 **「off」は経路を閉じるだけで、ComfyUI は止まりません。** セッションにエンジンが
提示されなくなり要求は断られますが、網の中の機械はそれまでどおり動き続けます。
音声エンジンが外部管理のときの「off」と同じ意味です。プロセスを止めるのは、それが
動いているホストで**あなたがやること**です。

クラウドのインスタンスを説明する欄——状態・希望台数・どの箱・いつ止まるか——は
**推測で埋めずに省略**します。配備がそれを知らないからです。

## モデルは手で登録する

ここでは何も取り込まれません。取り込みジョブもバケットも無く、CP がモデルの置き場を
読むこともありません。**カタログはあなたが書く宣言です。**モデルごとに、Console の
**管理 → 推論エンジン**で登録します。

- メンバーに見せる **id**、
- **`base_model`**——これは表示名ではなく**どのワークフローを使うかを決める鍵**なので、
  綴りを間違えると、誰かが生成しようとしたときにだけ落ちます、
- **ファイル名**——ComfyUI の loader が列挙するとおりの綴りで。

必要な役のファイルが欠けている行には**ファイル未設定**の印が付きます。この検査が見て
いるのは**あなたの宣言だけ**で、ファイルがディスクにあることの証拠ではありません。
存在しない名前を宣言すれば、失敗するのは生成のときです。

🔴 **VAE を同梱していないチェックポイントには、VAE を別に宣言してください。**
モデル配布サイトの SDXL 系チェックポイントには、UNet とテキストエンコーダだけを
同梱したものが少なくありません。そのファイル 1 枚だけを書いた行は、どの検査も通り、
エンジンのチェックポイントを切り替え（1〜2.5 分）、そのうえで**すべての**要求を
`VAE is invalid: None` で落とします——ふつうの生成では decode で、編集では encode で。
利用者の側に手立てはありません。ツールに VAE を指す引数が無いからです。その族の
単体 VAE を**同じ行の 2 つ目のファイルとして、フラグ `--vae` で**宣言してください
（SDXL 系のチェックポイントなら `sdxl_vae` 相当）。以後はそのファイルが、
チェックポイント同梱のものに代わって encode と decode に使われます。宣言するまでは
**その行を無効にしてください**——全セッションに提示され、試すたびにチェックポイントの
切り替えを払ってから落ちます。

🔴 **ファイルは ComfyUI の種別フォルダの直下に置いてください**——`checkpoints/`・
`diffusion_models/`・`clip/`・`vae/`・`loras/`。loader に渡るのは最後の `/` より後ろ
だけなので、サブフォルダに置いたファイル（`checkpoints/sdxl/x.safetensors`）は
`x.safetensors` として届き、`Value not in list` で落ちます。サブフォルダはまだ
対応していません。

## 絵に描かせないもの

「描かせないもの」を言える場所は 3 つあり、上書きではなく**足し合わされます**。

- **モデル行自身のもの**——そのチェックポイントの配布元が「避けろ」と書いているもの。同じ
  パネルの、その行で登録します。
- **利用者のもの**、要求ごと（画像ツールの `negative_prompt`）。
- **あなたのもの、エンジン全体に**——「全画像から除外する語」の欄。誰の要求でも、どの
  チェックポイントが答えても適用されます。

3 つとも空なら固定の既定（`blurry, lowres, deformed, watermark, text`）が使われます。自前の
ものを宣言した行は、その既定に足すのではなく**置き換えます**。

🔴 **これはネガティブプロンプトであって、コンテンツフィルタではありません。** 語は
「そこから離れる向き」としてサンプラーに渡されるだけです。門ではなく、強い prompt には
負けます。そして何より、**5 つのチェックポイントファミリーのうち 3 つは完全に無視します**
——Z-Image と FLUX.2 klein は cfg 1 でサンプリングし（ネガティブ側がちょうど打ち消されます）、
FLUX.1 にはネガティブの入力自体がありません。書いた列挙が効くのは SDXL と SD3.5 だけです。その族が答えた要求は**警告に
そう出ます**（族の名前つき）。作られるものについて保証が要る配備なら、保証はここにはありません。

## 網を閉じるのはあなたの仕事

AWS では GPU のエンジンに届くのは Control Plane だけで、それを保証しているのは
セキュリティグループです。**自分の網には相当するものが無く、配備はあるふりをしません。**

具体的には、ワークスペースのコンテナは NAT で網の外側へ出られるので、**セッションは
ComfyUI に直接話しかけられます**——Control Plane を迂回して。ComfyUI 自身は無認証で、
その API には変更を伴う呼び出し（プロンプトの投入、画像のアップロード）が含まれます。
**「CP からしか届かない」は、そうする手当てをしていない限り偽**だと考えてください。

真にする手は 2 つあります。

- **egress 統制を enforce にする**（[04 守る](04-secure.ja.md)）。許可リストに無い
  プライベートアドレスは落とされます。ただしそのページの但し書きに注意——いま動くのは
  観測と許可リストの管理までで、遮断そのものは今後の作業です。つまりこれは**方向で
  あって、まだ答えではありません**。
- **ComfyUI の前に reverse proxy を置く。**bearer トークンを要求し、その鍵は
  `AF_COMFY_API_KEY` で **Control Plane にだけ**渡します。今日使えるのはこちらです。
  🔴 **その proxy は `/system_stats` も同じ bearer で通さなければなりません**——それが
  ヘルスチェックで、いつまでも健康に見えないエンジンは、いつまでも答えないエンジンです。

どちらも取らないなら、正直な現状は「この配備にセッションを持つ人は誰でもその GPU を
使える。頼りにしているのはその人たちを信用していることだけ」です。

## 落ちているときの見え方

Control Plane は、自分が所有していないエンジンを待ちません。ComfyUI が落ちている間の
要求は**即座に** `503 engine_unavailable` で断られ、本文には**試した URL** と health の
パスが入ります。数分にわたって再試行することはありません——その予算はクラウドの
インスタンスを買っている間のためのもので、電源が落ちている網の中の機械は、待っても
戻ってきません。

なので見るべきは 2 つ、この順です。そのホストで ComfyUI が動いているか。CP からその
アドレスとポートに届くか。

## パネルに出るもの・出ないもの

- **warm** は**パネルを開いた瞬間**の生存確認です——1 回の要求・2 秒まで・結果は 10 秒
  キャッシュ。意味は「たったいま答えた」であって「ずっと上がっていた」ではありません。
- **稼働の履歴は出ません。**ヒートマップは制御ループが取る標本から描くもので、外部管理の
  エンジンには制御ループがありません。
- **費用は付きません。**自分の網の中の機械に、配備が知りうる時間単価はありません。
  クラウド費用には何も出ません。電気代は配備の外の話です。
