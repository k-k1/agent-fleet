# 07. 自前の ComfyUI で画像を生成する

[English](07-image-engine.md) | 日本語

セッションはプロンプトから画像を生成できます。既定でそれを実行するのは**メンバー自身の
CLI のプラン**（Codex の背後の ChatGPT ログイン、agy の背後の Gemini/Antigravity
ログイン）であり、フリート自身の GPU エンジンは AWS で買うものなので `ecs-ec2` 形態に
しかありません。

この章は 3 つめの選択肢です。**すでに自分の網の中で動いている ComfyUI** を、`compose` /
`native` / `docker` の配備から指します。誰かの机の下の GPU 機、WSL2 の Windows 側、
共有サーバー。中継するのは Control Plane なので、**セッションはその在り処も資格情報も
知りません**。

必要なのは URL（と任意のキー）と、手で維持するモデルの一覧だけです。**エンジンはあなたのもの
のまま**で、Control Plane はそれを起動も停止もしませんし、費用も付けません。
1 台に限る必要もありません。LAN の ComfyUI、借りたエンジン、OpenAI 互換のサーバは同時に
行として並べられ、どれが絵を描くかは設定で決まります（[画像エンジンを複数持つ](#画像エンジンを複数持つ)）。

4 つめの選択肢もあり、それは別の章です。すでに AWS で Agent Fleet を運用しているなら、
この配備から**そちらのエンジンを借りられます**
（[08 別の配備のエンジンを借りる](08-borrowed-engine.ja.md)）。あちらは画像だけでなく
チャットのエンジンも対象で、起こすのも払うのも向こうのフリートです。

## フリートのイメージを自分の GPU 機で動かす

その機械でまだ ComfyUI が動いていないなら、手で組み立てる必要はありません。
`deploy/comfyui-lan/comfyui-lan.sh` が、**`ecs-ec2` の画像エンジンが動かしているのと同じ、
版を固定した ComfyUI イメージ**を、その機械の docker で起動します。イメージは誰でも pull
できる `ghcr.io/k-k1/agent-fleet/comfyui` で、タグは `deploy/aws/ecs/cfn/60-engines.yaml`
が `ImageComfyImageTag` として固定しているものです。スクリプトはそのタグを、自分が置かれて
いるチェックアウトから読みます。セッションが送るワークフローのテンプレートは、この版の
ComfyUI に対して試験されています。

その機械に要るものは、x86_64 の Linux（イメージは amd64 専用）、Docker Engine、NVIDIA の
ドライバ（`nvidia-smi -L` が GPU を列挙する）、そして `docker run --gpus` を動かす
[NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)
です。どれかが欠けていれば、スクリプトは何かを変える前に止まり、欠けているものを言います。
このリポジトリをその機械に clone するか、`deploy/comfyui-lan/` を
`deploy/aws/ecs/cfn/60-engines.yaml` と一緒にコピーしてから、次を実行します。

```bash
# models/ には checkpoints/・diffusion_models/・clip/・text_encoders/・vae/・loras/ を置く
deploy/comfyui-lan/comfyui-lan.sh up --models /srv/comfy-models --bind 192.0.2.10
```

- **`--models`** は ComfyUI の `models/` として**読み取り専用で**マウントされます。足りない
  種類のフォルダはスクリプトが作ります。ファイルは
  [モデルは手で登録する](#モデルは手で登録する)のとおり、種類のフォルダの直下に置きます。
  ファイルを置くのはあなたで、何もダウンロードしてくれません。
- **`--bind`** はポートを公開するホスト側のアドレスです。既定は `127.0.0.1` で、Control
  Plane が同じ機械で動くときにしか使えません。CP が別の機械にあるなら、その機械の LAN の
  アドレスを渡します。`0.0.0.0`（すべてのインタフェース）は、`--all-interfaces` を一緒に
  付けない限り断ります。ポートは `--port` で変えられます（既定 `8188`）。
- **`--api-key-file <file>`** を付けると、bearer を確かめる proxy（compose と同じ Caddy の
  イメージ）を ComfyUI の前に置き、ComfyUI 自体はどこにも公開しません。ファイルには
  24 文字以上の鍵を 1 つ書き、読めるのは所有者だけにします。グループやその他が読めるファイルは
  断ります: `(umask 077; openssl rand -hex 32 > comfy.key)`。CP には同じ鍵を、
  パネルの鍵の欄か `AF_COMFY_API_KEY` で渡します。鍵はすべてのパスで要り、`/system_stats`
  も例外ではありません。CP はヘルスチェックにも鍵を付けて送ります。これが
  [網を閉じるのはあなたの仕事](#網を閉じるのはあなたの仕事)の reverse proxy です。
- コンテナは docker と一緒に再起動し（`--restart unless-stopped`）、docker は
  `/system_stats` から健康状態を出します。`comfyui-lan.sh status` で見えます。
  `comfyui-lan.sh down` はコンテナを消し、モデルとイメージは残します。
  スクリプトは作ったものすべてにラベルを付け、それ以外には触りません。同じ名前
  （`af-comfyui-lan` か `--name`）でラベルの無いコンテナやネットワークがあれば、置き換えずに断ります。

あとは Control Plane に `http://192.0.2.10:8188` を教えます（次の節）。

**何度実行しても安全です。** 同じ引数の `up` は何も変えません。止まっているコンテナは
起動し直し、コンテナを作り直すのはイメージか設定が変わったときだけです。proxy の鍵・Caddyfile・Caddy の
イメージが変わったときは proxy だけを作り直します。
**上げるときは配備に合わせます**。`git pull` で新しい `ImageComfyImageTag` が来れば、同じ
`up` がそのタグを pull してコンテナを作り直します。`--pull` は今のタグと proxy の Caddy の
イメージを pull し直し（タグは上書きできるため）、`--digest sha256:…` はイメージを digest で固定し、
`--build` は pull の代わりに `deploy/aws/ecs/comfyui/Dockerfile` を固定された版でその機械の
上で build します。どのオプションにも `AF_COMFY_LAN_*` の環境変数があるので（`--help` に
一覧）、機械ごとの設定を 1 つのファイルに書き、`up` の前に source しておけます。ComfyUI が
書き出した画像はコンテナの中にあり、作り直すと消えます。

🔴 **実際の GPU 機ではまだ動かしていません。** スクリプトが打つ docker のコマンド、断る
場面、再実行の振る舞いは、docker の代役に対して試験しています
（`deploy/local/comfyui-lan-stub-test.sh`）。`--gpus` でイメージが起動すること、proxy が鍵を
受け付けること、絵が返ってくることは実機で測っていません。その実行は
[#958](https://github.com/k-k1/agent-fleet/issues/958) で追っています。

## Control Plane に場所を教える

ComfyUI の場所を伝える方法は 2 つあり、どちらか 1 つで足ります。

**Console から**（再起動不要）。スーパー管理者が**管理 → 推論エンジン**を開き、ページ先頭の
**LAN の ComfyUI（画像エンジン）** パネルに URL と任意の Bearer キーを入れます。保存するとすぐに
反映されます。画像の行を作り直すので、パネルのヘルス表示はその時点から新しい URL についての
答えになり、セッションにも変更が伝わります。キーは Hugging Face のトークンと同じく暗号化して
保存され、**書き込み専用**です。パネルに出るのはキーの有無だけで、値は出ません。消すときは
**キーを削除**を使います。`http://` / `https://` 以外の URL や、ユーザー名・パスワードを含む URL
は拒否されます。Bearer はキーの欄に入れてください。

**環境変数から**（起動時に 1 回だけ読む）。下の 2 つです。どちらを変えても CP の再起動が要ります。

| 変数 | 意味 |
|---|---|
| `AF_COMFY_URL` | ポートまで含めた完全な URL を、**CP から見た形**で。例: `http://192.168.1.20:8188`。これを設定することが経路を開くことです。 |
| `AF_COMFY_API_KEY` | 任意。上流へ `Authorization: Bearer` として送ります。生成の呼び出しにも**ヘルスチェックにも**付きます。 |

**どちらが勝つか**。上ほど優先です。

1. エンジンスタックの表（AWS）にある**マネージド**な `image` の行。パネルには使用中の URL と
   理由だけが出て、入力欄は出ません。LAN の ComfyUI を使うには、スタックからこの役割を外します。
2. パネルに保存した URL。
3. `AF_COMFY_URL`。
4. インラインの表の external な行、または別のフリートから借りたエンジン。

**キーは URL と組で動きます**。パネルに保存した URL にはパネルのキーを送ります。パネルにキーが
無ければ `Authorization` ヘッダーは付けません。`AF_COMFY_API_KEY` や `AF_ENGINE_API_KEY_IMAGE`
を送ることは**ありません**。それらは環境変数が指すホストのために設定された値だからです。
キーはリダイレクトにも付いていきません。保存した URL が別のスキーム・ホスト・ポートへの
リダイレクトを返したら、Control Plane はそれに従わずに拒否します。

**パネルの設定を削除**を押すと、画像の役は上の順で次にあるものにその場で戻ります。
`AF_COMFY_URL`（とそのキー）があればそれ、無ければインラインの表の external な行です。
どちらも無くても `AF_REMOTE_ENGINE_URL` が設定されていれば、次のポーリングで借用先の `image`
エンジンが引き継ぎます。画像エンジンが無くなるのは、これらがどれも無いときだけです。そのため
削除は画像生成を止める手段では**ありません**。止めるにはエンジンを**オフ**にします。どの出どころが
使われているか、削除したら何に戻るかはパネルに出ます。

以下は環境変数の場合の説明です。

| 変数 | 意味 |
|---|---|
| `AF_COMFY_URL` | ポートまで含めた完全な URL を、**CP から見た形**で。例: `http://192.168.1.20:8188`。これを設定することが経路を開くことです。 |
| `AF_COMFY_API_KEY` | 任意。ComfyUI へ `Authorization: Bearer` として送ります。生成の呼び出しにも**ヘルスチェックにも**付きます。 |

置き場所は形態によります。

| 形態 | 置き場所 |
|---|---|
| compose / docker | compose ファイルの隣の `.env`（CP のサービスがファイルごと読みます） |
| native | `af start` の環境、または systemd unit の `Environment=`（[deploy/native/README.md](../../deploy/native/README.md) を参照） |

サーバー版の ComfyUI は `--listen` を付けて起動するまで loopback にしか応答せず、
ホストのファイアウォールが CP の動く機械からの着信をそのポートで許可している必要が
あります。**Windows の ComfyUI Desktop は未確認です**。`--listen` に相当する設定名を
確かめていないので、ここの手順はサーバー版のものです。

## 画像エンジンを複数持つ

この配備から届く画像エンジンは、どれも**エンジンテーブルの 1 行**で、絵の経路を決めるのは
その行です。背後にあるソフトの種類ではありません。`AF_COMFY_URL` は、その行を鍵 `image`
で 1 本書くための近道にすぎません。それ以外の行はテーブル自体に宣言します。`compose` /
`native` / `docker` では、Control Plane が起動時に 1 回読むインラインの `AF_ENGINES_JSON`
で、AWS ではエンジンのスタックが書くテーブルです。

- **順序はメンバーのものです**。設定 › エージェント › 「**画像生成の優先順位**」に、
  この配備のエンジンが**それぞれ自分の名前で**、メンバー自身の CLI プランで動く経路と
  並んで出ます。エンジンを名指ししない要求はその一覧を上から辿り、失敗したら次へ移り、
  答えには代わりにどのエンジンが描いたかが書かれます。「机の下の ComfyUI を先に、その PC が
  落ちていたら借りたほう」は、追加の設定なしでこの一覧そのものです。
- **要求で名指しできます**。`generate_image` には `provider` があり、エンジン行の鍵がその
  値になります。名指しされたエンジンは**次へ落ちません**。「LAN のを使え、落ちていたら
  そう言え」と頼むときは、この指定を使います。
- **行が 2 本なら鍵も 2 つ**。借りた役は向こうのフリートの鍵（たいてい `image`）で届き、
  ローカルの行がすでに持っている鍵は借りません（CP のログに巡回ごとに 1 行出ます）。
  借りた `image` の**横に**置く LAN の ComfyUI は、`AF_COMFY_URL` ではなくテーブルに、
  `comfy-lan` のような自分の鍵で宣言します。
- **OpenAI 互換の画像サーバも行です**。`external`（または `remote`）の行に
  `provider: "openai-compat"` で 1 本宣言するだけです。

  ```json
  {"key":"oai-image","api":"images","provider":"openai-compat",
   "url":"http://<host>:<port>","health":"/v1/models","lifecycle":"external"}
  ```

  サーバが bearer を要求するなら `AF_ENGINE_API_KEY_<KEY>` から読みます。`<KEY>` は行の鍵を
  大文字にし、英数字以外の文字を全部 `_` に置き換えたもので、上の行が読むのは
  `AF_ENGINE_API_KEY_OAI_IMAGE` です。この行には置くファイルも宣言するファミリーもありません。
  重みはサーバが持っています。**この経路が試されているのは、このプロジェクト自身の
  試験用の偽サーバに対してだけです**。実在の OpenAI 互換サーバに当てるまでは未実証として
  扱ってください。
- **この build が動かせない行は、消えずに印が付きます**。Control Plane が駆動できる
  provider は `comfy` と `openai-compat` です。それ以外の provider（退役した `sdcpp` など）を名乗る行は、
  以前はセッションから画像ツールが気づかないうちに消えるだけでした。いまは**管理 → 推論エンジン**が
  その行に印を付け、名乗っている provider 名を出します。直し方は行を向け直すことです。

## ここでのモードの意味

Console の**管理 → 推論エンジン**では、この種のエンジンは**外部管理**として出ます。
設定は **on** と **off** の 2 つだけです。「オンデマンド」はありません。あれはクラウドの
インスタンスを買って手放す設定で、ここには買うものがありません。

**「off」は経路を閉じるだけで、ComfyUI は止まりません。** セッションにエンジンが
提示されなくなり要求は断られますが、網の中の機械はそれまでどおり動き続けます。
音声エンジンが外部管理のときの「off」と同じ意味です。プロセスを止めるのは、それが
動いているホストで**あなたがやること**です。

クラウドのインスタンスを説明する欄（状態・希望台数・どのインスタンス・いつ止まるか）は
**推測で埋めずに省略**します。配備がそれを知らないからです。

## モデルは手で登録する

ここでは何も取り込まれません。取り込みジョブも S3 Bucket も無く、その機械へファイルを
コピーするものもありません。**カタログはあなたが書く宣言です**。モデルごとに、Console の
**管理 → 推論エンジン**で登録します。

- メンバーに見せる **id**、
- **`base_model`**：これは表示名ではなく**どのワークフローを使うかを決める鍵**なので、
  綴りを間違えると、誰かが生成しようとしたときにだけ落ちます、
- **ファイル名**：ComfyUI の loader が列挙するとおりの綴りで。

必要な役のファイルが欠けている行には**ファイル未設定**の印が付きます。この検査が見て
いるのは**あなたの宣言だけ**で、ファイルがディスクにあることの証拠ではありません。
存在しない名前を宣言すれば、失敗するのは生成のときです。

パネルが**できる**のは、名前を代わりに読むことです。外部管理の ComfyUI の行にある
「**このエンジンのファイルを調べる**」を押すと、エンジンに 1 回だけ、loader がいま列挙して
いるチェックポイント・LoRA・VAE のファイル名を訊き、それぞれを候補として
「**この名前で行を足す**」で出します。動くのは押したときだけで、網の中の機械を定期的に
見に行くことはありません。読めないのはファミリーです。ComfyUI は `base_model` を公開しない
ので、候補に付くのはせいぜいファイル名から読んだ推定で、フォームはファミリーを選ぶまで
行を書きません。間違ったファミリーは行の唯一の印を消してしまい、数分後の生成で落ちます。
借りた行には調べるものがありません。あの一覧は向こうのカタログの読み取り専用の複製です。

**VAE を同梱していないチェックポイントがあり、どれがそうかは画面に表示されます。**
モデル配布サイトの SDXL 系チェックポイントには、UNet とテキストエンコーダだけを
同梱したものが少なくありません。そういう行は宣言の検査をすべて通り、エンジンの
チェックポイントを切り替え（1〜2.5 分）、そのうえで**すべての**要求を
`VAE is invalid: None` で落とします。ふつうの生成では decode で、編集では encode で落ちます。
利用者の側に手立てはありません。ツールに VAE を指す引数が無いからです。

配備はチェックポイント自身のヘッダを読んで、次のように扱います。

- VAE を持たないファイルの行には印が付き、VAE を得るまで**有効にできません**。
- その行のボタン 1 つで、ファミリーの単体 VAE を取り込んで `--vae` として足します。
  そのファイルをこの配備が既に持っていれば、ダウンロードなしで付きます。
- 新しいチェックポイントを取り込むときは、同じ 2 本目をフォームが既定 オン で提示し、
  そのライセンスを本体のものと並べて出します。

**推測はしません。** ヘッダを読めなかった場合（`.ckpt`、消えた取り込み元、匿名では
読ませない資産）は、その行に印を付けません。「誰も見ていない」は「持っていない」では
ないからです。この配備が既定の VAE を持たないファミリー（標準のオートエンコーダが gated の
リポジトリにある SD3.5）は、印は付きますが直すボタンは出ません。その場合は
**同じ行の 2 つ目のファイルとして、フラグ `--vae` で**自分で宣言してください。
以後はそのファイルが、チェックポイント同梱のものに代わって encode と decode に
使われます。

**ファイルは ComfyUI の種別フォルダ（`checkpoints/`・
`diffusion_models/`・`clip/`・`vae/`・`loras/`）の直下に置いてください。** loader に渡るのは最後の `/` より後ろ
だけなので、サブフォルダに置いたファイル（`checkpoints/sdxl/x.safetensors`）は
`x.safetensors` として届き、`Value not in list` で落ちます。サブフォルダはまだ
対応していません。

**Qwen-Image 2.1** ファミリーの行には、そのマシンの ComfyUI が **v0.37.0 以上**であることが
要ります。エンコードに使うノードがその版で初めて入ったからです。古い版でも行は登録も有効化も
できますが、要求はすべてエンジンで失敗します。

## 絵に描かせないもの

「描かせないもの」を言える場所は 3 つあり、上書きではなく**足し合わされます**。

- **モデル行自身のもの**：そのチェックポイントの配布元が「避けろ」と書いているもの。同じ
  パネルの、その行で登録します。
- **利用者のもの**：要求ごと（画像ツールの `negative_prompt`）。
- **あなたのもの、エンジン全体に**：「全画像から除外する語」の欄。誰の要求でも、どの
  チェックポイントが答えても適用されます。

3 つとも空なら固定の既定（`blurry, lowres, deformed, watermark, text`）が使われます。自前の
ものを宣言した行は、その既定に足すのではなく**置き換えます**。

**これはネガティブプロンプトであって、コンテンツフィルタではありません。** 語は
「そこから離れる向き」としてサンプラーに渡されるだけです。門ではなく、強い prompt には
負けます。そして何より、**蒸留系のファミリーは完全に無視します**。Z-Image と FLUX.2 klein
は cfg 1 でサンプリングし（ネガティブ側がちょうど打ち消されます）、FLUX.1 にはネガティブの
入力自体がありません。語が届くのは誘導のあるファミリー（SD 1.5・SDXL・SD3.5・Anima・
Krea 2・Qwen-Image-Edit 2509 / 2511）で、そこでも cfg 1 の行は同じように打ち消します。
Turbo 版のチェックポイントのほか、Krea 2 と Qwen-Image 2.1 はレシピが cfg 1 から始まるので、
行が上げない限りそうなります。無視するモデルが答えた要求は**警告にそう出ます**（ファミリーの名前つき）。作られる
ものについて保証が要る配備なら、保証はここにはありません。

寸法を言わない要求が何で描かれるかもファミリーが決めます。メガピクセル世代のファミリーは
1024×1024、SD 1.5 は 512×512 です。あの UNet に 1024 を頼むと、エラーではなく被写体が
二重になったもっともらしい絵が返るからです。行自身の寸法一覧があればそちらが優先です。

## 網を閉じるのはあなたの仕事

AWS では GPU のエンジンに届くのは Control Plane だけで、それを保証しているのは
セキュリティグループです。**自分の網には相当するものが無く、配備はあるふりをしません。**

具体的には、ワークスペースのコンテナは NAT で網の外側へ出られるので、**セッションは
ComfyUI に直接話しかけられます**。Control Plane は迂回されます。ComfyUI 自身は無認証で、
その API には変更を伴う呼び出し（プロンプトの投入、画像のアップロード）が含まれます。
**「CP からしか届かない」は、そうする手当てをしていない限り偽**だと考えてください。

真にする手は 2 つあります。

- **egress 統制を enforce にする**（[04 守る](04-secure.ja.md)）。許可リストに無い
  プライベートアドレスは落とされます。ただしそのページの但し書きに注意してください。proxy 自体は
  遮断できますが、Workspace の通信を proxy へ通すことをまだ何も強制していません
  （[#1181](https://github.com/k-k1/agent-fleet/issues/1181)）。つまりこれは**方向で
  あって、まだ答えではありません**。
- **ComfyUI の前に reverse proxy を置く**。bearer トークンを要求し、その鍵は
  `AF_COMFY_API_KEY` で **Control Plane にだけ**渡します。今日使えるのはこちらです。
  **その proxy は `/system_stats` も同じ bearer で通さなければなりません**。それが
  ヘルスチェックで、いつまでも健康に見えないエンジンは、いつまでも答えないエンジンです。
  `comfyui-lan.sh --api-key-file` はそういう proxy を立てます
  （[フリートのイメージを自分の GPU 機で動かす](#フリートのイメージを自分の-gpu-機で動かす)）。

どちらも取らないなら、正直な現状は「この配備にセッションを持つ人は誰でもその GPU を
使える。頼りにしているのはその人たちを信用していることだけ」です。

## 落ちているときの見え方

Control Plane は、自分が所有していないエンジンを待ちません。ComfyUI が落ちている間の
要求は**即座に** `503 engine_unavailable` で断られ、本文には**試した URL** と health の
パスが入ります。数分にわたって再試行することはありません。その予算はクラウドの
インスタンスを買っている間のためのもので、電源が落ちている網の中の機械は、待っても
戻ってきません。

なので見るべきは 2 つ、この順です。そのホストで ComfyUI が動いているか。CP からその
アドレスとポートに届くか。

## パネルに出るもの・出ないもの

- **warm** は**パネルを開いた時点**の生存確認です（1 回の要求・2 秒まで・結果は 10 秒
  キャッシュ）。意味は「たったいま答えた」であって「ずっと上がっていた」ではありません。
- **稼働の履歴は出ません**。ヒートマップは制御ループが取る標本から描くもので、外部管理の
  エンジンには制御ループがありません。
- **費用は付きません**。自分の網の中の機械に、配備が知りうる時間単価はありません。
  クラウド費用には何も出ません。電気代は配備の外の話です。

どの形態が何に対応しているかは
[ref/deploy-targets.md](../ref/deploy-targets.ja.md) にあります。
