agent-fleet console · 設計提案

⌨ キーボード体系 再編案
すべての操作を、キーだけで直感的に

現状の Console にはショートカット・レジストリもコマンドパレットも存在せず、操作の大半は「マウスで押すボタン」です。本案は端末（xterm）がほぼ全キーを飲み込むという根本制約を正面から扱い、単一の capture-phase ディスパッチャ＋リーダーキー＋コマンドパレットを軸に、全操作をキーボードで到達可能かつ発見可能にします。

P0–P2 実装済・push 済（temp/slbkq45 / d88c81d）— capture-phase ディスパッチャ、Leader Ctrl+K＋which-key、コマンドパレット Ctrl+P、Alt 系ペイン移動、フォーカスリング。型 / vitest 229 / build / headless 検証済。残は P3–P5。
01

なぜ「普通の Ctrl+文字」では作れないのか

設計判断はすべて 1 つの事実から出発します。端末にフォーカスがある間、アプリに届くキーは実質 2 種類しかありません。

端末はキーの吸い込み口

term.ts の attachCustomKeyEventHandler が Ctrl+ほぼ全キー・F1〜F10 を PTY へ転送。全画面時は Keyboard Lock で W T N R L S P まで奪う。

→

唯一の抜け道

① Escape（端末が握らず document へ伝播）と ② window の capture-phase で握って preventDefault + stopPropagation したキー。既存の Ctrl+F がこの方式。

帰結：アプリが横取りしたキーは、その分シェルから奪う。だから「直接 Ctrl+文字」を大量に割り当てるのは、端末ヘビーな本アプリでは筋が悪い。横取りするキーは最小限に絞り、残りはリーダー経由で到達する——これが全体設計の背骨になります。加えて Mac の ⌘ は端末が使わないため、Mac では素の ⌘ 系が安全地帯。IME 変換中（isComposing）は一切発火させない（日本語入力の死守）。
02

アーキテクチャ — 単一レジストリと 4 つの層

現状のアドホックな keydown ハンドラ（escLayer / PaneFind / 各コンポーネント）を、1 本のディスパッチャと 1 つのコマンド・レジストリに統合します。レジストリが唯一の真実源となり、パレット・which-key・チートシート・ツールチップ・設定画面はすべてそこから生成されるため、表示と実体がずれません。

層 0

Command Registry ＋ Dispatcher

src/lib/keys/ を新設（escLayer の隣）。各コマンドは { id, keys, when(ctx), run, group, title }。window の capture-phase keydown で、コンテキスト（アクティブ領域・フォーカス要素・開いている overlay・リーダー待機中か）に照らして最初にマッチしたコマンドだけを握る。未登録キーは素通り＝端末・入力欄は無傷。

層 1

Focus / Region モデル

今ある activeId（アクティブ・ペイン 1 個）を土台に、領域（左レール／メイン／バー）の概念と、ペインのキーボード移動（方向・序数・巡回）を追加。アクティブ化に合わせて中身へ DOM フォーカスを渡し、可視フォーカスリング（新 --focus-ring トークン）を出す。

層 2

Leader ＋ which-key ＋ Command Palette

リーダー → グループ → アクションのニーモニック木と、全コマンドを曖昧検索するパレット（完全性の担保）。which-key オーバーレイが次に押せるキーを常に提示＝暗記不要。

層 3

List / Menu / Modal のキーボード化

ファイルツリーで実証済みの ARIA-tree roving をレール全体・右クリックメニューへ展開。モーダルにフォーカストラップ＋role=dialog。コンテキストメニューを Shift+F10/Menu で開けるようにし、ポインタ専用の穴を塞ぐ。

03

修飾キーの文法

4 つの入口だけ覚えれば、あとは画面が教えてくれる。プラットフォーム差は「同じ論理キー」を Ctrl↔⌘ で読み替えるだけ（既存コードも Ctrl≡⌘）。

Leader（背骨）

Ctrl+K / Mac ⌘+K

押すと which-key が開く。続けて修飾なしのキーでグループ→アクション。端末から奪うのはこの 1 キーだけで全機能に到達。再割当可。

Palette（完全性）

Ctrl+P 又は Leader 後にそのまま入力

コマンド・セッション・ファイル・repo を横断曖昧検索。アプリにある操作は必ずここに載る＝暗記ゼロで全操作到達の保証。

Accelerators（速度）

Alt+1…8 等・厳選 ~20 個

高頻度操作の直行便。端末と衝突しない修飾（既定 Alt）で、リーダーを介さず一発。全て再割当可。

Escape（撤退）

Esc 段階的に 1 枚ずつ剥がす

overlay を剥がす → which-key/パレットを閉じる → ペイン中身のフォーカスをペイン枠へ戻す → フィルタを消す。既存 escLayer を拡張。

07

発見性と直接アクセラレータ

「直感的」の正体は発見性。覚えていなくても画面が導く 4 つの仕掛けと、覚えたら速い直行便。すべて 1 つのレジストリから生成＝ズレない。

which-key

リーダー後 ~300ms で次候補パネルを表示。グループの頭文字と説明を全部見せる。

Command Palette

段階計画

各フェーズ単独で価値が出る順序。層 0 を土台に、上へ積む。P0–P1 だけでも「ペインがキーボードで回る」状態になります。

capture-phase ディスパッチャ、コマンド・レジストリ、context/when、kbd プリミティブ、--focus-ring トークン、IME ガード。escLayer を協調（or 吸収）。既存挙動はパリティ維持。

09

あなたに決めてほしいこと

下記は本当に好みが割れる分岐です。推奨は付けていますが、ここが決まると実装計画が確定します。

① リーダーキー 推奨 Ctrl/⌘+K

  • Ctrl/⌘+K — 現代的な「コマンド」筋肉記憶（VS Code/Slack/Linear/GitHub）。ただし Firefox は検索バー、シェルは kill-line と競合 → 再割当で回避。
  • Ctrl/⌘+; — readline 非衝突・ブラウザほぼ未使用。地味だが安全。
  • Ctrl/⌘+J — 空きが多い。ただしブラウザのダウンロード（一部）と競合しうる。

② スタイルの比重 推奨 ハイブリッド

  • ハイブリッド — Leader（網羅・学習）＋パレット（完全性）＋少数アクセラレータ（速度）。本案の既定。
  • Leader 一本 — 直接chordを持たず衝突を最小化。最も端末に優しいが高頻度操作が 2 打鍵。
  • chord 厚め — VS Code 風に直接chordを多用。速いが端末からキーを多く奪う。

③ 直接アクセラレータの修飾キー 推奨 Alt（⌥）

  • Alt / ⌥ — 端末衝突は readline の Meta 語移動のみ（軽微）。ただし EU 配列の AltGr に注意（JIS は無問題）。
  • Ctrl+Alt — さらに衝突が少ないが、一部配列で AltGr＝Ctrl+Alt と衝突。

④ 最初に出す範囲 推奨 P0–P2

  • P0–P2 — 基盤＋ペイン移動＋Leader/パレットまで一気に。「キーだけで回る」体感が最短で立つ。
  • P0–P1 — まず土台とペイン移動だけ堅くして目視確認、その後 Leader。
  • 全部（P0–P5） — 通しで作り切る。
