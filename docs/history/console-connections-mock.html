Agent Fleet Console · 設定 > 接続タブ 刷新提案（D フェーズ）

接続フローと「注記」を、行の詰め込みからカードと手順へ

機能は変えず、Codex の接続体験と各所に散った注記（ヘルプ文）を整理します。認証ロジック・API・シークレットの扱いは不変。下は実プロダクトのダークパレットで描いた方向性の提案です。

診断

いまの接続タブの何がつらいか

  • 横一列に認証フローを詰め込み — 未接続の Codex は「ChatGPT で接続」「API キー」のボタン2つが説明なしで並ぶだけ。どちらを選ぶべきか分からない。
  • デバイスコード手順が1行に潰れている — 大きなコード＋「→ URL でコード入力」＋「承認待ち…」が flex-wrap で折り返すだけで、①コピー ②開く ③承認 の順序が読めない。
  • 注記がバラバラ — opencode は名前の右に .muted の一言＋別枠の .field-help リンク、Claude は「別タブが開かない場合はこちら」のインラインリンク、Codex/Claude には「これで何ができるか」の説明が無い。置き場もスタイルも不統一。
  • 接続済み表示が地味 — email · plan が muted の省略テキストで、状態（接続済み/未接続）がひと目で分からない。

「注記（ヘルプ文）」の統一

Before 置き場・体裁がバラバラ
opencode プロバイダ API キー（起動時に env 注入）
→ opencode.ai/auth でサインイン → 課金設定 → API キーを発行し、下に貼り付け…
Claude 別タブが開かない場合はこちらでサインイン ↗
Codex（説明なし）

ある行は muted の一言、ある行は field-help、ある行は無し。何が要点か拾いにくい。

After 説明＋ヒントを定型化
ocopencode未接続
複数プロバイダの API キーを保存し、opencode 起動時に env として注入します。
iopencode.ai/auth でサインイン → 課金設定 → API キーを発行して貼り付け（同じキーで Zen も利用可）。
ccClaude未接続
Claude Code の OAuth 接続。サインインは新しいタブで開きます。
iタブが自動で開かない場合は サインインリンク ↗ から。承認後にコードを貼り付けます。

各プロバイダに「何ができるか（説明）」＋「どうやるか（ヒント）」を同じ体裁で。注記は左罫線つきの定型ブロックに統一。

守る点：認証フロー・各 API（/api/connections/…）・シークレットの扱い（Agent 側保管、Console は持たない）は不変。これは見た目/導線の提案で、実装は小さくコミット＋都度目視で進めます。
