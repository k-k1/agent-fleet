## なぜ共有の棚なのか

同じ問いが、利害の違う 4 人の読者から届きます。「cursor は Plan モードに対応している？」は、
エージェントを選ぶメンバーからも、何を提供するか決める管理者からも、8 つ目の種別を足す
開発者からも来ます。棚ごとに答えの写しを持つと**必ずずれ、しかも読者にはどちらが古いか
分かりません**。だから能力の事実はここにだけ置きます
（[CONVENTIONS §6](../CONVENTIONS.ja.md)）。

## この表が真であり続ける仕組み

軸がコードに在るものは、CI が突き合わせます（**生成はしません**——表現は書き手のものです）。

- エージェントの列は `workspace/agent/internal/session/session.go` の `Kind*` 定数を覆うこと。
- デプロイの行は `control-plane/runtime.go` の `newRuntimeFactory` が受け付ける
  プロファイルを覆うこと。

コードに単一の定義が無い軸——リポジトリ種別・ロール・上限——は手で保守します。
各表にその旨を明記しています。

**本文と表が食い違ったら表が正。** この棚の外で能力の話を書きそうになったら、
書かずにリンクしてください。

## 状態
