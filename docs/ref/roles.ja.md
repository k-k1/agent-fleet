# ロール — 誰が何をできるか

[English](roles.md) | 日本語

Audience: 全員（[features.md](features.ja.md) の「誰が」を解決する軸）
Source of truth: この表（手で保守）。どのロールにどの棚を配るかは Control Plane の 1 箇所で決まる
Updated: 2026-08

ロールは 3 つ。**不明なロールは最小権限として扱います**——これは意図的で、
新しいロールは届く範囲を明示的に与えられるべきで、黙って継承してはいけません。

| ロール | 画面上の表示 | 届く範囲 |
|---|---|---|
| メンバー | —（既定。バッジ無し）| 自分のワークスペース |
| テナント管理者 | 「テナント管理者（tenant_admin）」| 1 テナントの全員 |
| 配備管理者 | 「super_admin（デプロイ全体）」| 全テナントとホスト |

テナント管理者はたいてい**自分も作業するメンバー**で、2 つの帽子は入口が違います——
個人の作業は**設定**から、チームの管理は**テナント設定**から。盾アイコンの
**管理**が見えるのは配備管理者だけです。

## それぞれができること

| | メンバー | テナント管理者 | 配備管理者 |
|---|:--:|:--:|:--:|
| 自分のセッション・リポジトリ・ファイル | ✓ | ✓ | ✓ |
| 自分の接続と設定 | ✓ | ✓ | ✓ |
| テナント内の全セッションを見る | — | ✓ | ✓ |
| 他メンバーのワークスペースを強制停止 | — | ✓ | ✓ |
| メンバーの追加と削除 | — | ✓ | ✓ |
| メンバー毎のセッション上限 | — | ✓ | ✓ |
| テナント全体の上限・サイズ・アイドル自動停止 | — | —¹ | ✓ |
| テナントのサインイン方式を登録 | — | ✓² | ✓ |
| サインイン方式を承認 | — | — | ✓ |
| ログイン規則（参加方式・ドメイン）| — | —¹ | ✓ |
| メンバーの接続元を制限 | — | ✓ | ✓ |
| テナントの連携アプリ OAuth を登録 | — | ✓ | ✓ |
| 連携サーバーをチームへ配布 | — | ✓ | ✓ |
| 監査ログの閲覧 | — | ✓ | ✓ |
| 稼働時間とクラウド費用 | — | ✓ | ✓ |
| egress 統制・読み上げエンジン・共有辞書 | — | — | ✓ |
| テナントの作成と管理権限の付与 | — | — | ✓ |
| 導入・更新・バックアップ・復旧 | — | — | ✓ |
| ホストの端末 | — | — | ✓ |

¹ 見えるが**読み取り専用**。「なぜ弾かれたのか」を誰にも訊かずに読めるように
在ります。

² 登録だけでは足りず、**配備管理者の承認**が要ります。後からの変更（組織の追加、
同一アカウントの認識方法の変更）は、その行を再び承認待ちへ戻します。

## テナント管理者が「上に訊く」ことになる境目

この分割は信頼の階層ではなく、**影響範囲（blast radius）の分割**です。効果がテナントを
またぐもの、あるいは人を配備から締め出し得るものは配備管理者に置いてあります——
テナントの作成、権限の付与、ログイン規則、サインイン方式の承認、egress。
1 つのチームに閉じるものは、そのチームの管理者に置いてあります
（**退職処理の一連＝削除→停止→ホームの掃除も含めて**）。

バックアップ・アップグレード・ホストの障害対応も配備管理者のもので、多くの組織では
IT / SRE と同じ人です。

## どのロールにどの文書が届くか

棚はそのまま出荷の単位です。コンテナには**そのユーザーのロールが読んでよいものだけ**が
渡ります。棚を読者で切っているのは、そもそもこのためです。

| ロール | コンテナに入る棚 |
|---|---|
| メンバー | [use/](../use/README.ja.md), [ref/](README.ja.md) |
| テナント管理者 | ＋ [admin/](../admin/README.ja.md) |
| 配備管理者 | ＋ [operate/](../operate/README.ja.md), [build/](../build/README.ja.md) |

決定記録と凍結アーカイブは**誰にも配りません**。
