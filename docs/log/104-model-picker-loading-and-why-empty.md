# 104. 起動時のモデル選択 — 取得中を言う、空の理由を言う

2 件の申告から。(a) セッション開始時のモデル選択が少し遅れて出る、(b) opencode で
「無料枠」を選んでいる利用者からモデル一覧が出ない。**(a) と (b) は同じ画面の同じ 1 行**に
帰着した——動的カタログのピッカーは「取得中」と「この口座には 1 つも無い」を同じ絵で出す。

## 104.1 「無料枠で一覧が出ない」の切り分け

[54] §54.5 の無料枠は `keepForUsage` → `isFreeModel` で opencode.ai 側を絞る。まず疑うのは
この絞り込みだが、**絞り込みでは一覧は空にならない**。理由は 2 つあり、どちらもコード上の事実:

1. `Catalog` の空メニュー救済——絞った結果が 0 件で入力が 0 件でないなら、Zen で再計算した
   一覧を返す（off と own だけが対象外・[103]）。
2. `isFreeModel` は `freeIDs` が空なら **true**（値段が分からなければ無料として通す）。

したがって「既定しか出ない」は**列挙そのものが 0 件**のときにしか起きない。これは
`opencode models` が 10 秒予算で殺される既知の事故（[64] §64.43.8）と同じ口であって、
枠の選択とは別の話である。

### 実測（この作業機・opencode 1.18.31）

| 測ったもの | 結果 |
|---|---|
| 資格情報ゼロの `opencode models` | **7 件**（すべて `opencode/…`）・3.3〜3.5 秒（cold / warm とも） |
| 資格情報ゼロの `serve` の `GET /api/model` | **32 件・全部 cost 0**（うち 24 件が `deprecated`＝実質 8 件） |
| Agent の実経路（`Models()` → `CatalogWithRoute`）を無料枠で実行 | **8 件**が無料枠として出た（`freeIDs` は 0 件＝CLI 由来で値段不明） |

つまり**この環境では無料枠は正しく出る**。申告の環境では列挙が 0 件になっている、というのが
結論で、そこから先は画面が理由を言えないと詰む——それが 104.3。

## 104.2 見つけた欠陥: 値段表が前のスナップショットのまま残る

`freeIDs` / `retiredIDs` は **daemon 読み取りでしか更新されない**。daemon が居なくなって
一覧が CLI 由来になっても古い表が残るので、無料枠の判定が**前のカタログ**で行われる。
`isFreeModel` の doc コメント（「値段が分からない＝無料として通す」）と実挙動が食い違う。

見える症状は 2 段:

- いま無料で配られているモデルが「有料」と判定されて無料枠の一覧から落ちる。
- それで 0 件になると救済が働き、**一覧まるごと Zen の内容に置き換わる**（無料枠を選んで
  いるのに従量の id が並ぶ）。

陰性対照（修正を戻して実測）:

```
the previous daemon's price table survived a CLI read (1 entries)
free route = [opencode/muse-spark-1.3-contributor-free] (route=zen), want ... on the free route
```

修正は CLI 経路で `freeIDs, retiredIDs = nil, nil` にするだけ。**エラー経路では消さない**——
そこは stale-if-error で一覧自体も前のものを返すので、表だけ捨てると不整合になる。

## 104.3 空の理由を Agent が返す

[64] §64.43.8 の調査で残っていた穴（「正常な空」と「取れなかった空」を画面で区別できない／Agent が
理由を返さない）をここで閉じた。`GET /agents/{kind}/models` に `reason` を足す。

| reason | 意味 | 画面 |
|---|---|---|
| `catalog_empty` | CLI / daemon が 0 件で答えた | 従来どおり**原因を断定しない**一文（未ログイン・到達不能・プランが既定のみ（Copilot Free）を区別できないため） |
| `route` | opencode の枠が全 id を落とした（off / own） | 「いまの課金の選択では、選べるモデルが 1 つもありません」 |
| `hidden` | 残った id を設定で全部除外している | 「選べるモデルを設定ですべて除外しています」 |

判定は**外側から**（`emptyReason`）。元が 0 件なら「隠した」も「枠が落とした」も偽なので、
先に真になった外側の段が原因である。`hidden` と `route` は**このワークスペース自身の設定**
なので名指してよい——ここで「接続とプランを確認してください」と出すのが、人を無関係な
画面へ送っていた誤誘導そのものだった。

## 104.4 取得中はスピナー

`useModelCatalogSettled`（既存）が決着を持っているので、決着前は
「モデル一覧を取得しています…」＋回転アイコンを 1 行出すだけ。**空の注記と同じ行**に出すので
レイアウトは動かない。claude は静的カタログなので対象外（常に settled）。

実バンドルをヘッドレスで描画して確認: 取得中の 1 行、`route` の 1 行、`hidden` の 1 行が
それぞれ出る。

## 104.5 残ったもの

- **列挙が 0 件になる理由**は `catalog_empty` にまとめたままで、そこから先（未ログインか、
  到達不能か、タイムアウトか）は依然として画面からは分からない。タイムアウトだけは Agent の
  ログに所要時間つきで出る（[64] §64.43.8 で入れたもの）ので、運用者は指紋
  （毎回 10.0x 秒）で見分けられる。利用者向けに出すなら Agent が失敗理由を持ち回る必要がある。
- 設定画面の既定モデル行（`AgentCardParts` / `aiModelRow`）は同じ遅延を持つが、今回は起動
  ダイアログのピッカーだけに入れた。
