# docs/52 — 作業グループ（working set）

決定は [ADR 0036](../decisions/0036-working-sets.md)。複数の案件を並行して進めるとき、左ペインに
全リポジトリ・全会話・全セッションが混在して見通しが悪い。利用者が**名前付きの作業グループ**を作り、
「いま見たい案件のものだけ」を表示できるようにする。

## 1. 概念モデル

作業グループ = 名前付きの { 作業コピー, アシスタント会話, （repo なしセッション） } の集合。

| 対象 | 所属のさせ方 | キー |
|------|--------------|------|
| 作業コピー（base clone） | 明示割当（行メニュー） | フォルダ名（`~/repos/<name>`） |
| worktree | **親 base に自動追従**（個別割当は設けない） | — （`repo.parent` で解決） |
| セッション | **所属リポジトリから継承**（直接は持たない） | — （`sessionFolder(s)` で解決） |
| repo なしセッション（shell/ssm 等） | 明示割当 | セッション name（`s` + base32 6字） |
| アシスタント会話 | 明示割当 | 会話 id（UUID） |
| スケジュール（docs/38） | **導出優先**＋明示割当 | CP スケジュール id |

スケジュールの所属導出（`scheduleInSet`）: ① 直接割当（`set.schedules`）→ ② 起動先の
作業コピー（`worktree`/`repo` を base 名で）→ ③ 作成元会話 `owner_conv`（UUID）→
④ `reuse_target`（会話 slug は chat store で id 解決 / 会話 UUID / セッション name→
直接割当 or フォルダ経由）。スケジュールはオペレーターが MCP で作るため Console 側に
作成シームが無く「選択中グループへ自動所属」をフックできない — 代わりに **owner_conv
導出が自動所属の代替**になる（グループに入れた会話から作られたスケジュールは付いてくる）。
導出で所属している行は行メニューのトグルをチェック済み・無効で見せる（そのトグルでは
外せない — repo/会話側の所属で動くため）。

- どのグループにも属さないものは**「すべて」表示でのみ**見える。「未分類」の専用ビューは設けない
  （ADR 0036 §却下した案）。
- 1 対象が複数グループに属してよい（配列の重複を禁じない）。共有リポジトリを複数案件で使う形は普通にある。
- **グループ選択中に新規作成したものは自動でそのグループに入る**: clone した作業コピー、
  新規会話（handoff/fork 含む）、repo なしで起動したセッション。これがないと「作った直後に消える」
  体験になり運用が破綻する。リポジトリ内で起動したセッションは継承なので書き込み不要。

## 2. 保存 — フロント完結（ui-prefs 相乗り）

サーバに新しいエンティティ・REST は**作らない**。

- **定義**は Console 設定（`console/src/lib/settings.ts`）の 1 キー `workingSets` として
  `~/.config/agent-fleet/ui-prefs.json` に同期する。同一ユーザーの全端末で共有され、
  他ユーザーとは共有されない（ui-prefs が per-user コンテナ内にあるため自動的に membership スコープ）。

```jsonc
"workingSets": [
  { "id": "w3ab12x",            // フロント生成の不変 slug（"w" + base32 6字）
    "name": "案件X",
    "repos": ["agent-fleet"],   // base clone のフォルダ名
    "convs": ["<uuid>", ...],   // 会話 id
    "sessions": ["s7cd34y"] }   // repo なしセッションの name
]
```

- **選択中グループ**（どれを表示しているか）は `DEVICE_LOCAL` キー `workingSetActive`（グループ id、
  空 = すべて）。サーバへ送らない — PC では案件X・タブレットでは案件Y を見る、が自然に成立する
  （`settings.ts` の DEVICE_LOCAL 思想と同型）。
- 実体が消えた参照（削除済み repo・会話）は**放置して無害**（述語が単に当たらないだけ。hiddenModels と
  同じフェイルセーフ）。物理的な掃除は管理 UI で対象を外したときだけ。ストアのロード完了前に
  自動 prune しない — 「まだ読めていない」と「消えた」を区別できないため。
- 64KiB 上限（`ui_prefs.go:22`）は名前＋id 配列の集合には十分。壊れた値（型不一致）は
  hiddenModels 流に「グループなし」へ縮退。
- 将来サーバ側（オペレーター・通知）がグループを知る必要が出たら、Agent は `readUIPrefs()` で
  同じキーを読めばよい。v1 で先回りしない。

## 3. UI

- **切替 UI**: 左レール最上部、`LayoutMap` 直下・`app-rail-scroll` の**外**（`App.tsx`）に固定の
  グループセレクタ。「すべて」＋各グループ。選択中はグループ名を明示表示（スクロールしても常に見える
  ことが「セッションが消えた」誤認の防止線）。停止中レール（`StoppedRailSection` 側）にも同じ 1 行。
- **管理**: セレクタ内に「グループを管理…」— 作成 / 改名 / 削除。削除はグループ定義だけを消し、
  中身（repo 等）には一切触れない。
- **割当**: リポジトリ行・会話行・repo なしセッション行の ⋯/右クリックに
  「作業グループへ追加 / から外す」（複数所属のためチェックリスト形式）。
- **キーボード**: パレット（docs/29 の体系）に「作業グループ切替」を登録。
- **i18n**: 新規文言はカタログ経由（裸和文 lint 対象）。

## 4. フィルタ適用点（各セクション 1 箇所に AND するだけ）

実装は 2 モジュール: 述語・normalize は純関数の `lib/workingSets.ts`（node vitest で
テスト可能）、settings 連携（定義の読み書き・選択・自動所属・巡回）は
`lib/workingSetsStore.ts`。専用 zustand ストアは設けない — 定義も選択も settings が
真実源なので、`useSettings` 由来の `useActiveWorkingSet()` で足りる。

| セクション | 合流点 | 述語 |
|-----------|--------|------|
| リポジトリ木 | `ProjectTree.tsx` の `visible()` / `groups` | base 名が `repos` に含まれる（worktree は親で判定） |
| repo なしセッション | `OtherSessionsSection.tsx` | セッション name が `sessions` に含まれる |
| アシスタント会話 | `AssistantSection.tsx` の `startedConvs` | 会話 id が `convs` に含まれる |
| ファイル | `FilesSection.tsx` / `ProjectFiles` | グループ内 repo（＋その worktree）に絞る |
| スケジュール | `SchedulesSection.tsx` | `scheduleInSet`（§1 の導出＋直接割当） |

メモ・アーカイブモーダル・掃除モーダルは**絞らない**（全量が見えるべき管理面）。

## 5. v1 スコープ外（案A なら後から足せるもの）

- 通知・完了報告のグループ別ミュート
- オペレーター（MCP）へのグループ概念の露出
- メモの所属（スケジュールは第2弾で対応済み — §1/§4）
- グループ毎の起動既定値（kind/モデル）
- テナント内でのグループ共有（そもそも Workspace が 1 ユーザー 1 コンテナなので別機能になる）

## 6. テスト

- 述語（repo 追従・セッション継承・会話一致）の純関数 unit（vitest。`include` が対象拡張子を
  拾っているか要確認 — 過去に `.tsx` 空振りの前例）。
- ストア: 選択の永続化（DEVICE_LOCAL に載ること＝サーバ PUT のペイロードに `workingSetActive` が
  **含まれない**こと）、`workingSets` がサーバ同期されること。
- 自動追加: グループ選択中の新規会話 / clone / repo なし起動が定義に入ること。
