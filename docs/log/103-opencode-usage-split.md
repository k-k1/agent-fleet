# 103. opencode の「使う枠」を 2 つに割る（オフ / 自分の鍵だけ / 無料 / Go / Zen）

[54] §54.5 で入れた 4 択「使う枠（オフ / 無料枠 / Go / Zen）」が読めない、という申告から。
画面そのものは動いていたので、これは配線の不具合ではなく**1 本の選択肢に性質の違う決定を
載せていた**ことの症状だった。

## 103.1 何が読めなかったのか（診断）

コードと突き合わせて数えた原因は 7 つ。上から効きが大きい。

1. **「オフ」だけ粒度が違う。** オフは種別ぜんぶの電源（`connected()` の先頭で鍵も OAuth も
   否定する錠）。残り 3 つは opencode.ai のどちら側の id を一覧に出すかという整形でしかない。
   電源と整形が同じラジオに並んでいた。
2. **4 択は opencode.ai にしか効かないのに、カードの主語の位置にいた。** `keepForUsage` は
   `anthropic/…` も自前エンジンも素通しする（[54] §54.5 の設計どおり）。つまり枠が Zen でも
   実際に走るのは利用者自身の鍵かもしれないのに、ラベルは「使う枠」でカード最上段だった。
3. **表現できない状態があった。** 「opencode は使いたいが opencode.ai には一切課金しない」を
   選べない。いちばん近いのは「Go を選んで OPENCODE_API_KEY を登録しない」という**偶然の副作用**。
4. **選択が「願望」で「結果」ではなかった。** `Catalog` の空メニュー救済（`catalog.go`）は、
   Go を選んでも Go の id が 0 件なら黙って Zen で再計算した一覧を出す。UI は「Go」と言い続ける。
   課金経路の話でこの黙り方は、[54] §54.4 で比較セッション 2 本を Zen id で無駄にした事故と
   同じ形をしている。
5. **依存の向きが UI と逆だった。** 選べる枠は接続状況に依存する（Go＝キー必須 / Zen＝キーか
   サインイン / 無料＝不要）のに、枠を先に選ばせて依存を見せない。
6. **語が衝突していた。** キーのプリセット名が "OpenCode Go"。実体は Go / Zen 共通の
   `OPENCODE_API_KEY` で、同じ「Go」が 1 枚のカードに 2 つの意味で出ていた。
7. **チップが経路を言わなかった。** `pill` は free と off しか経路を出さないので、Go/Zen では
   「2 キー」だけ。いま何に課金されるのかが一目で分からない。

## 103.2 文が事実と食い違っていた 3 件

設計（[54] §54.5）は正しく、説明文だけが古い・広すぎるという形だった。

| 文字列 | 書いてあったこと | 実際 |
|---|---|---|
| `oc_usage_note_off`（ja/en） | 「既定（**Zen**）も未接続なら実質同じ挙動」 | 既定は **off**。[54] §54.5 で既定を変えたときの取り残し（`settings.ts` の `DEFAULTS`・`CatalogPref("")` とも off） |
| `oc_usage_note_free`（ja/en） | 「無料モデル**だけ**を一覧に出す／**API キーは注入しません**」 | 直結プロバイダと自前エンジンの id は残り、落ちるのは `OPENCODE_API_KEY` **だけ**（`auth.go` の `env()`） |
| `guide/member/06-agents`・`guide/ref/agents` | （4 択の説明が無い） | serve 再起動の話の中で名前だけ出てくる状態だった |

`settings.ts` の型コメントにも「既定（"zen"）」が残っていた。同じ誤りが 3 か所に複製されて
いたのは、既定を変えた変更が**値を読む側だけ**を直して、値を説明する側を直さなかったから。

## 103.3 決めたこと

**1 つの保存値（ui-prefs `opencodeCatalog`）を、2 つのコントロールで見せる。**

```
opencode を使う        [ オフ │ オン ]      ← 種別の電源（ポリシー用の錠）
opencode.ai への課金    ( ) 使わない（自分の鍵だけ）   ← 新設 = "own"
                       ( ) 無料モデルのみ
                       (•) Go（定額）
                       ( ) Zen（従量）
```

- **`own` を新設**した。opencode.ai の両側を落とし、`OPENCODE_API_KEY` を注入せず、直結
  プロバイダと自前エンジンだけを残す。`off` と同じく**空メニュー救済の対象外**——空なのが
  答えなので、Zen で埋めたら宣言の逆になる。
- **枠は縦のラジオカード**にした。4 つの説明が同時に読める。旧セグメント＋1 段落は、選んで
  みないと意味が分からない形だった（金の話でそれは高い）。
- **オフのときは資格情報の欄ごと隠す**。無視される欄に鍵を入れさせない。
- **`own` では opencode.ai のものを出さない**：アカウントのサインイン欄も、共通キーの
  プリセットも。保存済みの `OPENCODE_API_KEY` は消さずに「この枠では注入しません」と添える
  （「設定してある」と「使われている」は別の事実）。
- **黙った救済を言う**。`CatalogWithRoute` が実際に適用した枠を返し、`GET
  /agents/{kind}/models` が `route` として一緒に返す。Console は選択と食い違うときだけ
  「『Go（定額）』のモデルが 1 つも無かったため、起動一覧は『Zen（従量）』で出しています」と出す。
- **チップに経路を入れる**（`Go / 2 キー`）。一覧の見出しとは別に短い語を持たせた——
  「使わない（自分の鍵だけ）」は緑の点の横では謎かけになる。
- プリセット "OpenCode Go" を「opencode.ai（Go / Zen 共通キー）」に改名。

### `own` の起動ゲート

`connected()` は `own` のとき「`OPENCODE_API_KEY` **以外**の保存鍵があるか、af が書いた
エンジンの provider ブロックがあるか」で判定する。アカウントのサインインも opencode.ai の
ものなので数に入れない。

厳しい側に倒したのは、**緩い側の失敗が高い**から。資格情報が無いのに connected を返すと、
起動が opencode 自身の既定モデル（＝認証ゼロの opencode.ai）に落ちる。それは
[54] §54.5 の「無断の外部送信」そのもので、この枠が避けたい事象の本体である。

エンジンの有無は `HasEngineProviders()`（config を読むだけ）で見る。`EngineEnv` を呼ぶと
Control Plane への往復が接続パネルの裏に入る——`api/connections` は各エージェントの認証確認を
回すのでもともと重い（実測 1.5〜2 秒）。

### 不明な値は off に寄せた

`catalogFor` の先頭で `CatalogPref` を通す。以前は正規化されていない値（古い Console、手で
書いた ui-prefs）が `default:` 枝に落ちて「課金対象を全部残す」になっていた。誰も選んでいない
値の読み方としては、いちばん高い解釈だった。

## 103.4 採らなかった案

- **Go / Zen を「詳細」に畳んで 3 択にする**（オフ / 無料 / opencode.ai に課金）。取り違えに
  実害（残高切れ 401・[54] §54.4 の 2 本）がある以上、隠すのは逆効果。畳むなら「契約がある方を
  自動優先＋いま効いている方を必ず表示」がセットで、それは今回の可視化と同じ手間になる。
- **チェックボックス 4 つ（無料 / Go / Zen / 自分のプロバイダ）**。実装の実体（id ごとの
  フィルタ）には最も忠実だが、クリック数と既定の説明コストが増える。
- **接続 → 経路の順に並べ替え、選べない枠を理由付きで無効化**する案は残した。今回は
  「選べるが黙って別経路」を「選べて、違えば言う」に変えるところまで。無効化は、キーの有無と
  契約の有無を Console が取り違えた場合に**正しい選択を塞ぐ**ので、先に救済の可視化を測る。

## 103.5 実測（ヘッドレス Chromium・実バンドル）

`console/scripts/shots` のスタブに `/api/connections` と `/api/agents/opencode/models` を
被せて、4 状態を ja/light と en/dark で描かせた。

| 状態 | 見えたもの |
|---|---|
| オフ | チップ「オフ」・スイッチ・錠の説明だけ。鍵の欄は無い（カード高 257px） |
| own | 枠 4 つが同時に読める・選択行に枠線とチェック・`OPENCODE_API_KEY` に「この枠では注入しません」・プリセットに opencode.ai が無い |
| Go | チップ「Go / 2 キー」・サインイン欄と利用状況の導線あり |
| Go だが Go が 0 件 | 上記に加えて橙の 1 行「『Go（定額）』のモデルが 1 つも無かったため、起動一覧は『Zen（従量）』で出しています」 |

ダークでも選択行のコントラストは足りていた（`color-mix(--accent 12%)` ＋ アクセント枠線）。
