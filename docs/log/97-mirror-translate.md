# 97. 回答をミラーで訳す（ターンを使わない翻訳）— 設計・実装

> 状態: **P0 完了**（2026-09-13）。利用者の要求は「エージェントの回答が英語だったとき、
> **エージェントのターンを使わずに**、ミラービュー上で指定言語に訳す」。
> 追加で確定した形: **全自動ではなく利用者がボタンを押す**／**翻訳元のハッシュでキャッシュし、
> セッションの削除まで保持**／**共有相手は押せない（所有者のみ）**。
> 関連: [28-i18n.md](28-i18n.md) §6.6（生成物の言語軸）/ [69](69-transcript-marks.md) §69.3（マークの
> アンカー）/ [46-usage-accounting.md](46-usage-accounting.md)（台帳の feature 軸）/
> [84](84-ai-assist-settings.md)（AI 補助の設定とモデル 2 ティア）。

## 97.1 何を作ったか

ミラーの各回答のフッタに **「訳す」/「原文」** を出す。押すとその回答の**文章パートだけ**が
表示言語（回答言語を固定していればその言語）に置き換わる。

- 生成は `chatx.OneShotHeadless`（`OneShotProse`）＝タイトル提案・返信候補・編集提案と同じ
  **バックエンド非依存のワンショット**。別プロセスで 1 回 CLI を回すだけなので、**セッション本体の
  エージェントには触れない**（ターンを消費しない・文脈が増えない・実行中の作業の後ろに並ばない）。
- 消費は台帳に `translate.mirror` として載る（`usagex.FeatureTranslate`）。
- 設定 > AI補助 の `mirrorTranslateEnabled` でオフにできる（既定オン。押すまで無料なので）。

## 97.2 決めたこと（と、その理由）

| 決定 | 理由 |
|---|---|
| **自動ではなくボタン** | 自動にすると「どの回答を」「いつ」訳すかを機械が決めることになり、**追記中のターンを訳して古い訳が残る**。押した時点＝そのターンが完結している、で解ける。ミラーは毎秒ポーリングするので、自動翻訳は「押していない人の分まで 1 回答 1 モデル実行」になる |
| **キャッシュ鍵＝原文のハッシュ** | `Idx`（行序数）は compaction でずれ、`anchorId` はフォークで別 ID が付く（本文は同一）。走行中のターンは育つので「ターン」は鍵にならない。**押した本文**だけが安定している |
| **鍵はサーバが自分で計算する** | クライアントが鍵を名乗れると、古いペインが無関係な訳を引き出せる。鍵はその回答の訳を決める唯一の根拠 |
| **言語も鍵の一部** | 回答言語を切り替えたときに前の言語の訳が出る |
| **パート単位** | コードフェンス・ツール出力を自然に飛ばせ、段落が 1 つ増えた回答は**増えた分だけ**再実行になる |
| **保存はセッション削除まで** | `removeSessionSideFiles`（`cleanup_ops.go`）に 1 行足す。**セッション名はスロット名で使い回される**ので、消し忘れると次にその枠に入った会話へ他人の訳が出る。ハッシュ鍵なので誤ヒットはまず起きないが、ディスクと回答のプライバシーは別問題。派生物なので**削除アーカイブには入れない**（マークと同じ） |
| **ポーリングに載せない** | `/messages` に訳を混ぜると (a) 毎 poll のバイトが増え（スマホの電池）、(b) CP の sessionWire に欄を足す 4 か所仕事が出る。別エンドポイント＋開いたとき 1 回の GET |
| **共有相手は押せない** | 押すと**所有者のワークスペースでモデルが走り、所有者のトークンを使う**。CP の `registerSessionShareRoutes` には対の経路を置かない＝共有ビューには capability が無く、ボタン自体が描かれない（`capabilities.ts` の原則） |

## 97.4 踏みどころ（次に触る人へ）

- **ハッシュは日英 2 実装で、UTF-8 バイト列を数える。** ブラウザ側の唯一の組み込みダイジェスト
  （SubtleCrypto）は非同期で、しかも jsdom に無い＝描画テストが書けなくなる。なので FNV-1a を
  Go と TS の両方に置いた。**JS が UTF-16 コード単位を数えると ASCII のテストは全部通り、
  実際の回答だけ鍵が食い違う**ので、ベクタに日本語と絵文字を入れて両側で固定している
  （`session_translate_test.go` / `translate.test.ts`）。
- **マークは訳文の上に置けない。** マークは引用文字列でアンカーする（§69.3）ので、訳文に
  当てると「たまたま一致した別の文」に線が引かれる。訳を表示しているパートは `markRoot` を
  外す＝マークは原文に残る。
- **訳文は同じ MarkdownView に流す。** 別の描画経路を作ると Markdown の不具合が 2 セットになる
  （全角パイプ表・`<…>` の消失などは既に踏んでいる）。
- **コピーは「いま見えている方」を返す。** 訳を見ている人に読めない原文を渡すのは驚きになる。
- **返信サジェストに訳文を食わせない。** サジェストの言語軸は「会話の言語」で、訳文を渡すと
  相手セッションの出力言語まで反転する（§6.6 の地雷そのもの）。今回は経路を分けてあるだけで、
  将来まとめようとしたときに壊れる箇所。
- **persona はロケール分岐しない。** 出力言語がパラメタそのものなので、指示文を 2 本持っても
  読者が見るものは変わらず、維持コストだけが増える（`fs_suggest_edit.go` と同じ判断・§6.6 の
  判定表の「生成物の言語が UI ロケールで決まらないもの」）。
