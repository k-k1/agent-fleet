# 0080. フォルダの画像はカードで並べる——ギャラリーは新しいペイン種別 1 つ、導線は既存メニューに 1 項目ずつ

[English](0080-image-gallery-pane.md) | 日本語

- 状態: **提案**（2026-09-13）。
- 関連: [0049](0049-session-changed-files.ja.md) 決定 4 と [0046](0046-drawio-viewer.ja.md)（**新しい
  `PaneKind` は作らず面を 1 つ増やす**——本 ADR はその例外を論じる） /
  [0078](0078-sessions-overview-pane.ja.md)（直近の前例。ペイン種別 1 つ・既存メニューを借りる・
  カードのグリッド） / [0069](0069-image-generation-providers.ja.md)（生成画像の置き場所と保持期間） /
  [0063](0063-document-preview.ja.md)（`api/fs/download` は生バイトを返す唯一の口） /
  [0017](0017-keyboard-system.ja.md)（コマンド表への登録）

## 背景

Console で画像を見る手段は 2 つしかない。**ファイルペインで 1 枚開く**
（`viewer/ImageView.tsx`。ホイールとピンチで拡大・ドラッグで移動）か、**ミラーの転写に出た
共有ファイルカードを拡大する**（`mirror/transcript/blocks.tsx` の `FileCard` →
`mirror/parts/ImageLightbox.tsx`）。どちらも「1 枚」が単位で、**フォルダに何が入っているかを
一覧する面が無い**。

これがいちばん効くのは画像生成（ADR 0069）である。`generate_image` の出力は
`~/.cache/agent-fleet/generated/<sid>/image-<unixnano>-<n>.png` に溜まる
（`internal/imagegen/store.go`・保持 30 日・1 枚 2〜3MB）。

- フォルダ名は**セッション UUID** なので、ファイルツリーからは事実上たどれない。
- 転写のカードは折りたたみの中に隠れることがある（`.cache` の下は閲覧可なので開けはするが、
  「生成画像が出ない」と読まれた既知の弱点）。
- 生成は 1 回で複数枚・何度も回すのが普通で、**見比べる場所**がどこにも無い。

一方で土台はほぼ揃っている。

- **サムネイルの口が既にある**: `GET api/fs/download?path=…&thumb=<最長辺>`（`fs_thumb.go`）。
  実測で 1024x1536 / 3.2MB の PNG が 341x512 / 約 60KB になり、`Cache-Control: private, max-age=60`
  ＋ `Last-Modified` なので 2 回目以降は 304。ディスクキャッシュ付き・同時デコードは 2 本に制限
  （共有ホストはメモリが細い）。**引数は助言的**で、デコーダの無い形式や小さすぎる画像は
  原本が返る——呼ぶ側に能力判定が要らない。
- **拡大の部品がある**: `ImageView` は zoom ハンドルを外へ出しており、`ImageLightbox` が
  ボタン列を自前で描いている。
- **カードの作法がある**: 「本体＝拡大／角のボタン＝ペインで開く」。見るだけでペインを
  消費しないための分け方で、既に利用者が学んでいる。
- **ペイン種別を足す定型がある**（ADR 0078 で 8 か所を踏んだ）。

足りないのは**フォルダ単位の面**と、**そこへ行く導線**だけである。

## 決定

### 決定 1 — 新しいペイン種別 `gallery` として作る（ファイルペインの面にしない）

```ts
| { kind: "gallery"; galleryPath: string; sort?: "new" | "name"; galleryFocus?: string; gallerySession?: string }
```

- **0049 決定 4 / 0046 との関係。** 両者の結論は「**載せられる既存のペインがあるなら**面を 1 つ
  増やす方が安い」である。ここには載せる先が無い。`kind:"file"` の `filePath` は**ファイル 1 本**の
  契約で、その上に編集バッファ・差分・外部変更追従・朗読・PDF/Office 分岐がぶら下がっている
  （`fileMode.ts`）。ディレクトリを入れるとその全部が嘘になる。SCM ペインの主語はリポジトリで、
  やはりフォルダではない。**`galleryPath` は PaneContent で初めてディレクトリを指すフィールド**であり、
  それが新種別の理由そのものである。
- ペインにすれば分割・タブ・ポップアウト・レイアウト永続化・スマホの 1 ペイン表示・`Ctrl+F` が
  **すべて既存の仕組みで付く**。ミラーと並べて「生成しながら見る」も自然に出る。
- 種別追加の定型 8 か所（union・保存形式の検証・同一判定・描画 switch・タイトル・ミニマップ略号・
  ポップアウト可否・i18n）を全部踏む。**`migrate.ts` の検証を忘れると再読み込みで空ターミナルに
  化ける**。`galleryPath` は保存値＝信用できない入力なので、文字列・先頭 `/` 無し・`..` 無し・
  制御文字無し・長さ上限で弾く（`browser` 種別の `path` 検証と同じ厳しさ）。
- `sort` は React state でなく**ペインの内容に持つ**。タブ切替でこのビューは unmount されるので、
  state に置くと切替のたびに戻って壊れて見える（0078 決定 1 と同じ）。
- 同一判定（`sameTarget`）は `galleryPath` で行う。`sort` と `galleryFocus` は同じ面の状態なので
  見ない——同じフォルダを 2 度開いても 2 枚にならない。

### 決定 2 — 一覧は既存の `api/fs/tree` で取る。足すのは `fsEntry` の `mtime` 1 つだけ

- 新しい一覧エンドポイントは作らない。フォルダ 1 階層の `{name, type, size}` は既にこの口が返す。
- **`mtime` を足す**（`workspace/agent/fs.go`）。「新しい順」と「3 分前」はこれ無しには書けない。
  生成画像はファイル名に `unixnano` が入るので名前順＝時刻順だが、それは**生成画像だけの偶然**で、
  スクリーンショットの入ったフォルダには効かない。
- ツリー側への影響は無い: `ProjectFiles` の `sameEntries` は name/type だけを比べるので、
  mtime が動いても再描画は増えない。
- **サブフォルダの再帰は P0 に入れない**（決定 9・P1）。`api/fs/search` で代用してはいけない——
  `.gitignore` を尊重するので生成物やビルド出力が**黙って消え**、`q` が必須で「全部」を頼めない。
- 巨大フォルダ対策は客側の打ち切り（決定 4）。`api/fs/tree` に上限が無いのは既存の性質であり、
  本 ADR では変えない（変えるならツリーごと変える話になる）。

### 決定 3 — 画像かどうかは `imageFormat()` 1 か所で決める

Console の `lib/filemeta.ts` の `IMAGE_EXT` が唯一の判定（Agent 側の `imageContentType` が
対になっており、コメントで互いを指している）。ギャラリーが独自の拡張子表を持つと、
**ファイルペインでは画像なのにギャラリーには出ない**という食い違いが必ず出る。
サムネイル可能かどうかは見ない——`thumb` は助言的で、webp/avif/bmp/svg は原本が返って
ブラウザが描く。

### 決定 4 — サムネイルは `thumb=512`。ミラーと同じ数字にそろえ、遅延読み込みと打ち切りを付ける

- **512 はミラーの共有ファイルカードと同じ値**。サムネイルのディスクキャッシュは鍵に最長辺を
  含むので、ギャラリーだけ 256 を頼むと同じ画像を**2 回デコードする**（費用の本体はデコードで、
  約 100ms ＋ 幅×高さ×4 バイト）。小さく見せたい分は CSS で縮める。
- `loading="lazy"`＋`decoding="async"`。初期は**新しい順に 300 枚で打ち切り**、残りは「さらに表示」。
  上限が無いと、たまたま画像の多いフォルダを開いた 1 回で 300 枚 × デコード 2 並列が待ち行列になる。
- 原本を取るのは拡大したときだけ（ライトボックス）。カードは常に縮小版を見る。

### 決定 5 — カードの操作は転写のカードと同じ分け方。ライトボックスは共有して ←/→ を足す

- **本体＝拡大（ライトボックス）／角のボタン＝ファイルペインで開く**。既に `FileCard` が
  この分け方で、理由も同じ（見るだけでペインを消費させない）。
- `mirror/parts/ImageLightbox.tsx` を**共有の場所へ引き上げ**、`←`/`→` の送りと「3 / 12」の
  現在位置を足す。`ImageView` の zoom ハンドルはそのまま使う。**ミラー側の見た目と挙動は変えない**
  （送りは並びを渡されたときだけ出る）。
- Escape は `useEscLayer`、背景クリックで閉じる・画像のクリックは拡大に残す既存の判定
  （ドラッグ判定込み）をそのまま引き継ぐ。
- **スマホのスワイプで送らない**（P0）。水平ドラッグはセッション回転に取られており
  （`data-no-swipe` との綱引き）、ここを触ると既存の操作が壊れる。ボタンと矢印キーで送る。

### 決定 6 — 自動更新は「イベントが引き金・間隔は保険」の既存方針に従う

`features/files/refreshPolicy.ts` の数字をそのまま使う。

- マウント時に 1 回・`useFilesStore` の `tick`（ワークスペースの起停・アップロード）・
  **タブに戻ったとき**（`REVALIDATE_GAP_MS` = 10 秒の床）・**稼働中のセッションがある間だけ
  20 秒間隔**（`WORKING_TICK_MS`。誰も走っていなければタイマーごと畳む）・ヘッダの更新ボタン。
- **常駐ポーラーにはしない**（Console↔CP の通信削減方針）。生成は 1 回に数分かかり、
  ターン終了の合図（`sessionRefresh.ts`）では遅すぎるので、この面では 20 秒の網が主役になる。
  一覧は JSON なので CP の ETag が効き、変化が無ければ 304 で終わる。
- 新しく増えた画像はツリーと同じ「新着ハイライト」で出す（生成が着地する瞬間が見える）。

### 決定 7 — 導線は既存メニューに 1 項目ずつ。新しいボタンも新しい面も足さない

1. **左ペインのフォルダの右クリック** →「ギャラリーで開く」。
2. **左ペインの画像ファイルの右クリック** → 同じ項目。`menuDir` は既に親フォルダを指しているので、
   親のギャラリーをその画像に合わせて開く（`galleryFocus`）。画像以外のファイルには出さない。
3. **ミラーの「共有ファイル」欄** →「フォルダを開く」。その画像の**親フォルダ**を開くだけなので、
   セッションの解決は要らない。
4. **画像ビュアーのヘッダ** →「同じフォルダのギャラリー」。
5. **セッションの右クリックメニュー** →「生成した画像 (N)」。`sessions/SessionMenu.tsx` は
   行・タブ・セッション一覧のカードの 3 か所で共有されているので、**1 項目で 3 導線**になる
   （0078 決定 7 と同じ理由——項目を複製しない）。

開き方は既存の慣習に従う: 素のクリックは今のペイン、`Ctrl/⌘`・中クリックは別ペイン。
スマホは隣が無いので同じペインに開く（0078 決定 3 の改訂に同じ）。

### 決定 8 — セッションの項目は**生成物があるときだけ**出す。そのために一覧の wire に 2 フィールド足す

`session.Session`（Agent）→ `sessionWire`（CP）→ `types/session.ts`（Console）に:

- `generatedImages`（枚数・`omitempty`）
- `generatedImagesPath`（browse-root 相対のフォルダ・`omitempty`）

- **なぜ wire か。** フォルダ名は `uuidV5(dir + "|" + セッション名)`（`internal/session/uuid.go`）で、
  **Console からは導出できない**。同じハッシュを TS に写すのは、片方を直すともう片方が黙って
  ずれる類の重複である。クリック時に問い合わせる案だと「あるか無いか」がメニューを開いた**後**に
  決まり、項目が遅れて生える（マウスはもう動いている）。パスを wire に載せれば
  **新しいエンドポイントも CP の許可リストも要らず**、クリックは即座にペインを開く。
- **費用。** 一覧を組むたびにセッション 1 本あたり小さなディレクトリの `ReadDir` 1 回
  （数十 µs。一覧はすでにセッションごとに meta を読み、必要なら書いてもいる）。効いてきたら
  フォルダの mtime で memo 化する。wire のバイトは 0 件で落ちるので、生成していない配備では増えない。
- **中継の落とし穴。** `sessionWire` に無いフィールドは黙って落ちる。落ちた場合の症状は
  「項目が永久に出ない」。`wire.golden`・往復試験・Console の型との突き合わせ（`contract_session_test.go`）
  の 3 本が見張る。
- **ワークスペース停止中は DB ミラー経由なので両方とも落ち、項目も消える。** エージェントが
  居なければギャラリー自体が読めないので、これは正しい挙動である。
- **数えるのは af の `generate_image` の出力だけ。** codex 自前の `generated_images` は `.codex` の
  下＝意図的に閲覧禁止（`fsDeny`・ADR 0069 がわざわざ移した理由）なので、ここには出ない。
  貼り付け画像（`pasted`）も対象外——別の軸であり、必要なら別の導線を足す。

### 決定 9 — 1 階層だけを見る。再帰は P1 で、別の口として足す

P0 は `galleryPath` 直下のみ。再帰は「歩き回る」ことなので、`.gitignore` を無視して数を制限できる
専用の口（`GET /fs/images?path=&depth=&limit=`）が要る。それは**再帰が要ると分かってから**作る。
1 階層で足りる用途（生成画像・`docs/img`・スクリーンショット置き場）が先に来る用途のほとんどである。

## 却下した案

- **モーダルのギャラリー**（掃除／アーカイブと同型）: 安いが、ミラーと並べる・タブにする・
  別タブへ切り離す・レイアウトに残す——ペインだから只で付くものを全部捨てる（決定 1）。
- **`kind:"file"` にディレクトリを渡す**: `filePath` の契約と FileView の機構が全部嘘になる（決定 1）。
- **ギャラリー用の一覧エンドポイントを P0 で作る**: `fs/tree` ＋ `mtime` 1 つで足りる。
  端から作ると、画像判定・並び・上限が Agent と Console の 2 か所に増える（決定 2・3）。
- **`api/fs/search` で再帰一覧を作る**: `.gitignore` を尊重するので生成物が黙って消え、`q` が必須で
  「全部」を頼めない。**空の結果と走っていない検索は見分けが付かない**（決定 2）。
- **カードに W×H を出す**（P0）: `fs/tree` は寸法を持たない。サムネイルの `naturalWidth` は
  整数倍に縮んだ後の値で、原本の寸法ではない（小さい画像は原本が返るので**当たることもある**——
  当たったり外れたりする数字は、いつも外れるより悪い）。原本を読む拡大とファイルペインには
  今も出ている。寸法をカードに出すなら `DecodeConfig` でヘッダだけ読む口が必要で、それは P1。
- **サムネイルを 256 で頼む**: 帯域は減るが、同じ画像をミラーと 2 回デコードする（決定 4）。
- **クリック時に問い合わせてメニュー項目を出し分ける**: 項目が遅れて生える（決定 8）。
- **セッション UUID を Console 側で導出する**: `uuidV5` の入力（`dir + "|" + name`）が Agent の
  内部事情で、写した瞬間から黙ってずれ始める（決定 8）。
- **`generatedImagesPath` の代わりに枚数だけを載せ、パスはエンドポイントで引く**: 項目の出し分けは
  できるが、エンドポイント 1 本・CP の許可リスト 1 行・往復 1 回が増えて、得るものが無い（決定 8）。
- **左ペインにサムネイルを並べる**: 撤回済みの左ペイン IA と衝突する。レールは行、面は右
  （0078 と同じ）。
- **仮想スクロール**: 300 枚打ち切り＋`loading="lazy"` で足りる。先に測る（未解決 1）。
- **スマホのスワイプで送る**: 水平ドラッグはセッション回転が持っている（決定 5）。
- **動画・PDF も混ぜる**: 「画像のギャラリー」から始める。PDF は既に専用の面があり
  （ADR 0063）、動画は再生と帯域の話が別に要る（未解決 2）。

## 影響

- **Agent は 2 か所**: `fsEntry` に `mtime`、`wireSession` に 2 フィールド（枚数とパス）。
  新しいルートは無い。
- **CP は `sessionWire` の 2 フィールドだけ**（＋ golden と往復試験）。**新しいルートが無いので
  許可リストの追記も無い**。
- **追加のポーリングは無い**: 一覧は既存のセッション一覧に相乗りし、フォルダの再読は
  「見ている人がいるとき」だけ（決定 6）。
- **Console**: `features/gallery/`（ビュー・純関数・CSS・opener）を新設。
  `layout/{types,migrate,ops}.ts`・`features/panes/{Pane,paneTitle,LayoutMap}`・
  導線 4 か所（`project/ProjectFiles.tsx`・`sessions/SessionMenu.tsx`・
  `mirror/transcript/blocks.tsx`・`viewer/parts/FileViewerShell.tsx`）・
  `mirror/parts/ImageLightbox.tsx` の共有化・i18n（ja/en）。
- **配布物は増えない**（新しい依存は無い。サムネイルもライトボックスも既にある）。
- 試験: 純関数（画像だけ抜く・並び・打ち切り・合計）／DOM（カードが並ぶ・空状態・
  拡大と角ボタンの出し分け・送り・右クリック項目の出し分け）／Go（`mtime` が載る・
  枚数とパス・0 件で omit・denylist を越えない）／実ブラウザ（グリッドの折り返し・遅延読み込み）。

## フェーズ

- **P0**: 決定 1〜9。フォルダ 1 階層のギャラリー＋導線 5 つ。
- **P1**: カードの右クリック（ペインで開く・ダウンロード・パスをコピー・削除）／
  「送る」でセッションやアシスタントへ渡す／W×H（ヘッダだけ読む口）／サブフォルダ再帰／
  `generated` 直下を全セッション分まとめて見る面／タイルの大きさ（S/M/L）とそれに応じた `thumb`。
- **P2**: 動画・PDF を含む「メディア」への一般化（要否は未解決 2 の答えで決める）。

## 未解決

1. **300 枚の打ち切りは正しい数字か。** 実測していない。ペイン幅 1100px でカードが何枚見え、
   デコード 2 並列でどれだけ待つかを測ってから決める（`fs_thumb.go` の実測に並べて記録する）。
2. **動画と PDF を混ぜるか。** 「画像のギャラリー」で始めるが、`docs/img` のような場所には
   SVG と PNG と PDF が混ざる。混ぜるなら名前も「メディア」に変わる。
3. **`generated` 直下（全セッション）の面が要るか。** 2 階層なので `fs/tree` を N+1 回叩けば作れるが、
   セッション名との対応は wire の `generatedImagesPath` を逆に引くしかない。要望が出てから。
4. **アーカイブ／削除されたセッションの生成画像。** 画像は 30 日残るが、セッションが一覧から
   消えると決定 8 の導線も消える。ツリーからは開けるので P0 では放置し、
   `generated` 直下の面（未解決 3）が答えになるかを見る。
