## 背景

エージェントが作業中に学んだことは、学んだ CLI のメモリにしか残らない。AF が動かす種別のうち、
ローカルにメモリを持つのは 2 つ（[0022](0022-agent-memory-management.ja.md) Context）：claude の
auto-memory（既定でオン）と codex の memories（既定でオフ）。opencode・agy・kiro には無く、copilot と
cursor はベンダーのサーバー側に持つ。途中で種別を替える、別の種別へ引き継ぐ、別の種別の子を起動する、
のいずれでも、最初のエージェントが記録したものは失われる。

すぐ思いつく解 — claude のメモリを他の種別に渡す — は、1 ベンダーの非公開の形式と置き場をフリートの
正本にしてしまう。形式は Claude Code のどの版でも変わりうるし、中身は claude 向けに書かれている
（「claude の TUI は X をする」）し、書けるのは claude だけである。

設計を形づくる事実が 2 つある。どちらも 2026-10-03 に 1 つの Workspace で、このリポジトリのプロジェクト
について実測した：claude のメモリ索引（`MEMORY.md`）は **25,399 バイト**、ディレクトリは **469 ファイル・
2.7 MB**。これを全セッションの指示に押し込むのはターンごとの費用として誰も受け入れない。必要時に
取りに行く形でなければならない。

仕組みの半分ずつは AF に既にある。[0042](0042-user-instructions.ja.md) は AF が持つ 1 本の文章を全種別の
指示層に配り（cursor を除く、決定 2）、[0022](0022-agent-memory-management.ja.md) はメモリのディレクトリを
bare git リポジトリで版管理し、巻き戻しと bundle での移送ができる。欠けているのは、AF が持ち、
エージェントが書いてよい置き場である。

## 決定

1. **AF はユーザー指示とは別にメモリの置き場を持つ。** ユーザー指示は人が書き、正本である。
   [0042](0042-user-instructions.ja.md) 決定 8 はエージェントがそれを書くことを禁じており、それは変えない。
   AF メモリはエージェントが書き、参考情報である。別のファイルに置き、別のブロックとして配り、ポリシー
   文がどちらがどちらかをエージェントに伝える。統合すると 0042 決定 8 が無効になる。
2. **範囲はユーザー × プロジェクト。** プロジェクトは claude の slug と同じ方法で識別する：worktree は
   親クローンのプロジェクトに属するので、同じリポジトリ上の全セッションが 1 つのメモリを共有する。
   リポジトリではなく人についての事実のために、ユーザー全体の範囲も置く。
3. **形式は 1 メモリ 1 Markdown ファイル＋frontmatter**（`name`・`description`・`type` に加え、AF の
   `author_kind`・`author_session`・`created`・`updated`、一部の種別にだけ当てはまるメモリには任意の
   `kinds` リスト）。claude のメモリが既に使う形なので取り込みはコピー＋項目追加で済み、人がツール無しで
   読める。
4. **全種別が af MCP ツールで読み書きする** — `memory_search`・`memory_read`・`memory_save`（作成・更新）・
   `memory_forget`。全種別に届く面は MCP だけで、cursor にも届く。書き込みはどの種別・どのセッションが
   書いたかを記録し、[0022](0022-agent-memory-management.ja.md) の履歴に 1 コミットとして入るので、どの
   書き込みも追跡でき巻き戻せる。
5. **配るのは短い索引で、置き場そのものではない。** 0042 の配布器が各種別の指示層に AF メモリのブロックを
   足す：ツールがあること、いつ使うか、関連の高い項目の 1 行説明を固定の少数だけ。専用のバイト上限を
   設ける（0042 決定 7 と同じ理由：上限はセッションごとの費用のため）。本文は `memory_read` /
   `memory_search` で取る。ローカルの指示層を持たない cursor にはツールだけが届き、同じ案内はツールの
   説明に書く。
6. **claude 自身の auto-memory は 2 段で揃える。**
   - 段 1：AF は claude のメモリを AF の置き場へ片方向（claude → AF）で取り込む。契機は 0022 が既に使う
     ものと同じ。既存の 469 ファイルが置き場の種になり、claude はそのまま動く。
   - 段 2（実測してから決める）：claude の auto-memory の向き先を AF の置き場にする
     （`autoMemoryDirectory`）ことでディレクトリを 1 つにして claude にネイティブに書かせるか、
     auto-memory を切って（`autoMemoryEnabled` / `CLAUDE_CODE_DISABLE_AUTO_MEMORY`）他の種別と同じく
     MCP ツールを使わせるか。どちらの名前も 2.1.288 のバイナリから得たもので、どちらも実測していない。
7. **メモリは証拠であって命令ではない。** 読み出しツールの説明にそう書き、メモリに出てくるファイル・
   関数・フラグは頼る前に実在を確かめるよう書く。メモリはユーザー指示やフリートポリシーに優先しない。
8. **書き込みは既定で提案とし、メンバーが直接書き込みに切り替えられる。** セッションからの書き込みは
   保留として入り、Console で承認に回る。さもないと 1 つのセッションが読んだ 1 つの悪意あるページが
   全種別に配られるからである。メンバーはプロジェクト単位で直接書き込みに切り替えてよい。承認の経路は
   #1559 の自動レビューが必要とするものと同じで、1 度だけ作る。

## 却下した案

- **claude のメモリを正本として他の種別と共有する。** 1 ベンダーの非公開の形式と置き場がフリートのものに
  なり、書けるのは claude だけで、中身が claude 固有である。
- **置き場全体を全種別の指示に配る。** 索引だけで 25 KB、全セッション・全ターン。
- **外部のメモリサービス（例：Honcho）。** 会話が Workspace の外に出て、サービス側が自前の LLM で推論し、
  自前運用には Workspace に無い Docker が要る。メンバー自身が Settings → MCP で選ぶ選択肢のまま残す。
- **代わりにエージェントにユーザー指示を書かせる。** 0042 決定 8 が無効になる。
- **種別ごとの置き場を互いに同期する。** N 個の形式・N 人の書き手と、編集のたびの衝突。置き場 1 つ・
  書き込み経路 1 つの方が単純。

## 結果

- 種別を替える・引き継ぐ・別種別の子を起動する、のいずれでも知識が残る。
- 0022 がローカルメモリ無しとした種別（opencode・agy・kiro）がメモリを得る。lcpp と muse は 0022 の
  調査より後に来て、メモリについては調べていない。同じツールが届く。
- すべてのメモリに書き手と履歴があり、悪い教訓を見つけて巻き戻せる。
- 新しい故障の型：汚染されたメモリが全種別に届く。決定 8 がその対策で、書き込みツールと同時に出す
  （後回しにしない）。
- 決定 6 の段 2 が決まるまで、claude には 2 つのメモリが並存する。
