## 背景

エージェントが作業中に学んだことは、学んだ CLI のメモリにしか残らない。[0022](0022-agent-memory-management.ja.md)
が当時の CLI を調べた時点（その Context）で、ローカルにメモリを持つのは 2 つだった：claude の
auto-memory（既定でオン）と codex の memories（既定でオフ）。opencode・agy・kiro には無く、copilot は
Copilot Memory をサーバー側に持ち、cursor の旧 Memories は削除されていた。AF のメモリルートは今もこの
2 つである（`memoryx/memory_roots.go`）。lcpp と muse はその調査の後に来た：lcpp 自前のシステムプロンプトには
メモリ層が無く（`harness/systemprompt.go`）、muse がネイティブのメモリを持つかは確かめていない。途中で
種別を替える、別の種別へ引き継ぐ、別の種別の子を起動する、のいずれでも、最初のエージェントが記録した
ものは失われる。

すぐ思いつく解 — claude のメモリを他の種別に渡す — は、1 ベンダーの非公開の形式と置き場をフリートの
正本にしてしまう。形式は Claude Code のどの版でも変わりうるし、中身は claude 向けに書かれている
（「claude の TUI は X をする」）し、書けるのは claude だけである。

設計を形づくる事実が 2 つある。どちらも 2026-10-03 に 1 つの Workspace で、このリポジトリのプロジェクト
について実測した：claude のメモリ索引（`MEMORY.md`）は **25,399 バイト**、ディレクトリは **469 ファイル・
2.7 MB**。これを全セッションの指示に押し込むのはターンごとの費用として誰も受け入れない。必要時に
取りに行く形でなければならない。

仕組みの部品は AF に既にある。[0042](0042-user-instructions.ja.md) は AF が持つ 1 本の文章を各種別の
**ユーザー全体の**指示層に配る — ファイルで配る種別では種別ごとに 1 ファイルで、プロジェクトや
セッションごとではない（`agent_instructions.go`）。lcpp は同じユーザー全体の本文を各セッションの
プロンプトに組み込む（`harness/systemprompt.go`）— そして cursor にはそれが書けるローカルのユーザー層が無い（決定 2）。
[0022](0022-agent-memory-management.ja.md) はメモリのディレクトリを bare git リポジトリで版管理し、巻き戻し・
bundle での移送・輸出時の秘密検査（`memoryx/memory_secrets.go`）を持つ。af MCP はすべてのエージェント種別に
届く：7 つの CLI 種別へは `mcpreg` で、muse へは専用の配線で、lcpp へはプロセス内で。shell と ssm は
エージェントではない。欠けているのは、AF が持ちエージェントが書いてよい置き場と、1 つのセッションが
書いたものを全種別が読むときにも安全な書き込み経路である。

## 決定

1. **AF はユーザー指示とは別にメモリの置き場を持つ。** ユーザー指示は人が書き、正本である。
   [0042](0042-user-instructions.ja.md) 決定 8 はエージェントがそれを書くことを禁じており、それは変えない。
   AF メモリはエージェントが書き、参考情報である。別のファイルに置き、別のブロックとして配り、ポリシー
   文がどちらがどちらかをエージェントに伝える。統合すると 0042 決定 8 が無効になる。
2. **範囲はユーザー × Workspace × プロジェクトで、プロジェクト ID は AF が自分で定める。** Git の作業コピー
   なら、プロジェクトはその作業コピーが属するリポジトリで、絶対パスの `git-common-dir` を鍵とする（その親
   ではない。`--separate-git-dir` やサブモジュールでは複数のリポジトリが親を共有しうる）。worktree は親と
   メモリを共有する。claude の*会話*ディレクトリの命名は流用しない：cwd ごとで、
   単射でなく、worktree ごとに別の slug になる（`agents/claude/project_dir.go`）。Git でない作業コピー
   （SVN・ローカルフォルダ。どちらも正式対象、`guide/ref/repos.md`）は、AF が登録したルートを鍵とする
   独立したプロジェクトである。作業コピーの無いセッションはユーザー全体の範囲だけを見る。別のパスへの
   再クローンは、メンバーが 2 つを統合するまで別プロジェクトである（未決事項 5）。v1 ではメモリは
   Workspace をまたがない（決定 10）。
3. **形式は 1 メモリ 1 Markdown ファイル＋frontmatter**（`name`・`description`・`type` に加え、AF の
   `revision`・`author_kind`・`author_session`・`created`・`updated`、一部の種別にだけ当てはまるメモリには
   任意の `kinds` リスト、取り込んだものには `source` / `source_hash`）。AF が確かめられない書き手は
   不明と記録し、推測しない。claude のメモリが既に使う形なので取り込みはコピー＋項目追加で済み、人が
   ツール無しで読める。
   上限は 2 層（#1921）。**ストアが受け入れる**範囲は広く取り、claude 自身のメモリが持つものを断らない：
   名前は小文字・数字・`-`・`_`・`.` の 1〜64 文字で、先頭は `.` と `-` 以外、`..` を含まない。説明は
   1 行で 2,000 文字まで（バイトでなく文字で数える）。本文は 200 KiB まで。行の長さに上限はない。
   **書き方の指針**は claude 自身の lint に合わせ、警告するだけにする。保存は成功し、`memory_save` が
   警告を返す：1 ファイル 1 事実、説明は 150 文字ほど（claude は 300 文字超で警告する）、本文は 4,096
   バイト以内（claude の recall は他のセッションに、メモリファイルの先頭 4,096 バイト・200 行しか見せない
   ため）。claude の実メモリ 598 ファイル（7 プロジェクト）での実測：名前の 117 件がアンダースコアを
   含む（旧パターンは断っていた）、説明の 15 件が 300 バイト超（最長 1,800 文字）、本文の 2 件が 64 KiB
   超（最大 174,004 バイト）、136 ファイルが 4,096 バイト超。claude の同期ストアは 1 文書 102,400
   バイト、パス 1,024 バイト・20 セグメントを上限とするが、ローカルのファイルに上限はないので、ストアの
   上限は同期の上限でなくローカルの実データに合わせる。
4. **全種別が af MCP ツールで読み書きする** — `memory_index`・`memory_search`・`memory_read`・
   `memory_save`（作成・更新）・`memory_forget`。更新と忘却は元にした `revision` を持ち、古ければ断って
   エージェントに読み直して書き直させる。Markdown は機械的にはマージしないからである
   （[0022](0022-agent-memory-management.ja.md) の 3-way merge について）。変更の公開、0022 の履歴への
   コミット、索引の更新はプロジェクトごとに 1 つの手順で行い、公開された変更 1 つが書き手つきの
   1 コミットになる。
   ツールは**既定でオフ**で、利用者ごとのスイッチ（設定 → エージェントメモリ、変更一覧の隣。ui-prefs の `agentMemory`）の後ろに
   ある。あるセッションが保存したことは以後の全種別のセッションに読まれるので、メンバーが知ったうえで
   オンにするべきで、更新したらオンになっていた、という形にはしない。オフのときは af サーバーをツール
   無しで起動し、*さらに* Agent のツール用ルートも断る。ルートは `AGENT_TOKEN` を持つものなら何にでも
   答えるからである。Console の変更一覧・差分・巻き戻しはオフの間も使えるので、オンの間に書かれたものを
   確かめ、戻すことはできる。アシスタントのスナップショットのツール（0022）は claude と codex の履歴だけを
   読み、`af/` は読まない。
5. **配るのは固定の案内で、メモリではない。** 0042 の配布器が書くのはユーザー全体のファイルなので、
   そこにプロジェクト別の一覧を置くと、最後に書いたプロジェクトで上書きされるか、全プロジェクトが全
   セッションに混ざる。そこで配るブロックは、ツールがあることと呼ぶ時機 — 作業の始めに `memory_index`、
   何かを導き直す前に `memory_search` — だけを、専用のバイト上限の下で述べる（0042 決定 7 と同じ理由）。
   プロジェクトの項目は、呼び出したセッションの範囲で `memory_index` が返す。システムプロンプトを
   セッションごとに組む lcpp は直接注入してよい。cursor には同じ案内をツールの説明で渡す。
   `memory_index` は意図して部分的にする（#1702。使用回数による順位付けとピン留めは #1703、関連度順は
   #1558）。Agent が上限を掛けるので、どの利用側にも同じ答えが返る。
   - 説明つきの部分は、描画した行のバイト予算（既定 24 KiB。任意の引数 `budget` は 4〜64 KiB に丸める）に
     収める。順は `feedback` と `user` が先、残りはその後、各層で新しい順。行の説明は 150 文字で切る。
     `memory_read` と `memory_search` は全文を返す。
   - 収まらなかった分は、別枠 8 KiB で名前だけを並べる。名前は 32 バイトで「…」付きに切り（前方一致）、
     最初のハイフンまでで束ねる（`adr-{0072-…,0079-…}`）。それも溢れたら「and N more (use memory_search)」。
   - 案内には、索引が部分的であること、再び導き直す前に作業のキーワードで `memory_search` することを書く。現状は `memory_index` のツール説明が
     それを担い、配布ブロック自体は未実装で、同じ文言を上限内で載せる。
   取り込んだ claude のメモリ 473 件での実測：全行 111 KB が、説明つき 117 行（24.4 KB）と、355 件の名前を
   並べた 8.2 KB の末尾になり、1 件だけ件数に回った。
   切る長さはかつて 80 文字で、この予算以外の根拠がなかった（claude 自身の索引の目安は 1 行 200 文字
   弱）。#1921 でこのプロジェクトの取り込み済み 473 件を測り直した（説明つき行数 / 末尾の名前数、
   切られる説明の数）：80 → 114 / 359・218 件、120 → 104 / 369・53 件、150 → 103 / 370・26 件、
   200 → 102 / 371・2 件。80 から 150 にすると説明つき行は 11 減り、切られる説明は 192 件減る。150
   を超えても行数はほとんど動かないので 150 とする。ほかのプロジェクトは、どの値でも全件が収まる。
6. **claude 自身の auto-memory：今は 1 回だけの種まき、いずれメモリは 1 つ。**
   - 段 1：メンバーがプロジェクトごとに claude の既存メモリを、Console の明示的な操作または
     `af-memory import` で取り込む。読むのは `<claude の設定>/projects/<slug>/memory/*.md`（claude の
     索引 `MEMORY.md` は除く）。slug は復号できないので、`~/repos` の各作業コピーのキーを順方向に計算して
     突き合わせ、どの作業コピーにも当たらない slug や 2 つのプロジェクトが主張する slug は一覧に出すが
     取り込めない。Console はまず取り込む中身と秘密検査（決定 9）の結果を示し、メンバーが確定する。取り込んだ
     メモリはそれぞれ `source` / `source_hash` を記録し、書き手は不明とし、1 メモリ 1 コミット・操作名
     `import`・コミットの作者はメンバーとする。再実行しても安全：claude のファイルが変わっていなければ
     飛ばし、AF のメモリより claude のファイルが**新しく**内容も違えば更新する（取り込み後に AF で
     した編集を上書きする。これはメンバーが選んだ）。一度でも忘れた、または取り込みを取り消したメモリは
     **二度と戻さない**。claude の説明は切らずに丸ごと取り込み、本文の頭にも足さない（#1921）。名前が
     無効、説明が 2,000 文字超（`bad_description`）、本文が 200 KiB 超（`too_large`）のファイルは、理由を
     付けて一覧に出し、取り込まない。以前の取り込みが説明を切って保存したメモリ（全文を本文の頭に
     足していた）は、記録した `source_hash` が claude のファイルのハッシュと等しく、AF の写しがその後
     触られていなければ、claude のファイルで更新し直す（`refresh_shortened`）。触られていない、とは
     履歴上そのメモリの最新コミットが取り込みで、ファイルがそれとバイト単位で同じことを指す。保存・
     ピン留め・取り消し・手編集のどれかがあれば写しが違うので、触らない。書き込みはスイッチがオンのときだけ（決定 4 の設定）。プレビューとコマンドの
     `--dry-run` はオフでも使える。継続同期はしない：契機の
     たびの claude → AF は、AF で忘れたメモリを復活させ、AF での編集を claude の古い文章で上書きする。
   - 段 2（2026-10-08 決定、#1734）：スイッチがオンの間、claude の起動はすべて、その 1 本の
     `--settings` JSON に `autoMemoryEnabled:false` を載せる（flag 層はメンバー自身の設定に勝つ。
     `settings.json` には何も書かないので、オフにしても後始末は要らず、次の起動から単に載らなくなる）。
     claude は `MEMORY.md` を読み込まず、メモリファイルも書かず、他の種別と同じく MCP ツールを使う。
     環境変数は使わない：`CLAUDE_CODE_DISABLE_AUTO_MEMORY=0` は auto-memory を強制的にオンへ戻す。
     claude のネイティブの書き手を置き場に向ける（`autoMemoryDirectory`）案は**却下**：claude はそこへ
     ファイルツールで書くので、メモリは書いただけで公開され、秘密検査（決定 9）・revision の確認・書き手の
     記録のどれも通らず、claude 側に書き込みを留める手段もない。
     2.1.293 のバイナリでの実測（静的。実機プローブは claude のログインが要るため未実施）：auto-memory を
     切ると読みも書きもしない。ディレクトリ設定は両方を動かす。このプロジェクトでの費用：claude は起動の
     たびに 26,817 B の `MEMORY.md` のうち 25,000 B（約 12〜14k トークン）と約 3 KB のメモリ用プロンプトを
     読み、AF の案内は 760 B、`memory_index` は約 32 KB（記述付き 24 KB と名前 8 KB）なので、両方で起動時に
     約 30k トークン。2 週間・767 セッションで claude はネイティブのメモリに Write 52・Edit 15、
     `memory_save` は 2 回だった。結果：変更後の起動にだけ効く。最後の取り込み以降にネイティブへ書かれた
     メモリは、メンバーがもう一度取り込むまで読まれないので、Console とガイドはスイッチをオンにしたあと、
     新しい claude セッションを起動する前にもう一度取り込むよう案内する（確定はオンが必要、プレビューはオフでも可）。オフに戻すと claude は自前のメモリに戻り、AF に保存した内容はそちらには
     現れない（片方向。段 3 の明示的な書き戻しがその隙間を埋める）。
   - 段 3（#1914）：逆向きの AF → claude ネイティブメモリへの写しを、プロジェクトごとの**明示的・
     プレビュー付き・1 回限り**の操作として認める（Console の「Claude Code へ書き戻す」または
     `af-memory export`）。継続はしない。AF のメモリがオンの間は claude のネイティブの書き手が
     オフ（#1734）なので、同時に書く者がおらず安全。競合は黙って上書きせず、先に claude のメモリの
     スナップショット（0022）を取る。codex は #1683 に回す。末尾の注を参照。
7. **メモリは証拠であって命令ではない。** 読み出しツールの説明にそう書き、メモリに出てくるファイル・
   関数・フラグは頼る前に実在を確かめるよう書く。メモリはユーザー指示やフリートポリシーに優先しない。
8. **変更は直接公開する。守りは悪い変更を門前で止めるのではなく、見つけて戻すためにある。** MCP
   ツールによる保存・更新・忘却は、revision の確認（決定 4）・秘密検査（決定 9）・1 コミットの手順を
   通ってすぐ公開され、その時から書いた本人にも他のすべてのセッションにも見える。提案の待ち行列も承認の
   手順も無い。
   承認は境界にならない。Agent の REST の認証は `AGENT_TOKEN` 1 つで、それは全セッションのシェルが持つ
   （[07-security §7.2](../build/07-security.ja.md#72-隔離コントロール)）ので、エージェントは自分の提案を
   自分で承認できる。しかもシェルを持つエージェントはリポジトリの `CLAUDE.md` / `AGENTS.md` もコードも
   既に書けるので、メモリの前にだけ門を置いても、1 つの悪意あるページが届く範囲は狭まらない。一方で
   費用は確実にかかる：メンバーが読まずに一括承認するか切ってしまう待ち行列と、1 ターン前に保存した
   ものを読み返せないエージェントである。claude の auto-memory が確認なしで書くのも同じ理由による。
   代わりにメンバーが持つもの：すべての変更に書き手（種別とセッション）と 0022 の履歴のコミットがあり、
   Console は最近の変更を誰が・いつ・何を、で並べ、1 件ずつ忘れさせたり巻き戻したりでき、決定 7 が
   すべての読み手にメモリは証拠だと伝える。取り込みと復元は Console でのメンバー自身の操作で、その
   プレビューが確認である。レビューの待ち行列は #1559 の自動レビューが必要としたときに作り、それより
   前には作らない。
9. **秘密は保存される前に止める。** 長い行は断らない（#1921）。検査は全規則を行全体に掛けるので、4 KiB
   より後ろの値も先頭の値と同じように見つかる。候補となる本文 — 保存・更新・取り込み・復元、そして claude の
   ネイティブの書き手が作ったもの（決定 6）— はすべて、公開する前に、
   0022 の規則（`memory_secrets.go`）で検査する。エージェントの書き込みで検出したら断る：エージェントには
   規則名と行を伝えて値を除いた形で書き直させ、MCP 側から通す手段は無い。claude からの取り込みでの検出は、規則名・フィールド・行・マスクした手掛かりを添えて
   一覧に出し、取り込まない。了承の手段は無い（claude 自身のチームメモリ同期と同じ）：メンバーが
   claude 側のファイルを直して取り込み直す。復元での検出 —
   今の 0022 の復元は履歴を検査なしでコピーするが、復元もこの対象に含める — は、メンバーが Console で
   明示的に了承したときだけ通す。ある本文に与えた了承は別の本文には引き継がない（この部分は変えない）。値そのものは返さず記録もしない — 今の輸出時と同じく、規則名・パス・行・マスクした手掛かりだけ。
   既に在るメモリは、読み出しや索引で初めて公開する前に検査する。`memory_forget` はメモリを公開対象から
   外すが履歴からは消さないので、秘密を履歴から消し去るのはメンバーだけが行う別の操作とする
   （未決事項 3）。
10. **v1 は Workspace の中に置く。** 置き場は claude 専用マウントの `af-memory.git` の隣
    （`memoryx/memory_repo.go`）で、stop/start・recreate・「clean home」を越えて残る。Workspace の削除後については
    何も約束しない：ファイルが物理的に消えるかはランタイムによる（ECS では EFS のディレクトリがアクセス
    ポイントより長く残り、スタックが home タスクを持つ場合にだけ消される、`runtime_ecs.go`）ので、秘密を
    消す手段として削除には頼らない。メンバーの複数の Workspace で CP を通してメモリを共有するのは別の道筋で、0022 が満たせな
    かった条件がそのまま要る：所有者だけの ACL（0022：内部 git プロバイダはテナントの全メンバーに読ませる）、
    正本となる 1 つの履歴、Workspace が止まっている間の振る舞い、メンバーが抜けたときの削除。

## 却下した案

- **claude のメモリを正本として他の種別と共有する。** 1 ベンダーの非公開の形式と置き場がフリートのものに
  なり、書けるのは claude だけで、中身が claude 固有である。
- **置き場全体を全種別の指示に配る。** 索引だけで 25 KB、全セッション・全ターン。
- **プロジェクト別の索引を 0042 の配布器で配る。** そのファイルは種別ごとにユーザー全体なので、同時に
  開いた 2 つのプロジェクトが互いの項目を読む（決定 5）。
- **claude → AF の継続同期。** 削除の印と優先順位が無いと、忘れたメモリや却下したメモリが復活する。
  1 回だけの種まきならこの問題が起きない（決定 6）。
- **claude のネイティブの書き手に置き場へ公開させる。** revision の確認・秘密検査・書き手の記録
  （決定 4・8・9）を迂回する。
- **書き込みをメンバーが承認する保留中の提案にする**（この記録の初稿）。全セッションが `AGENT_TOKEN`
  とシェルを持つ限り境界にならず、承認の手間と、保存したばかりのものを読めないエージェントという
  費用は確実にかかる（決定 8）。#1559 の自動レビューに待ち行列が要るなら、そのために作る。
- **外部のメモリサービス（例：Honcho）。** 会話が Workspace の外に出て、サービス側が自前の LLM で推論し、
  自前運用には Workspace に無い Docker が要る。メンバー自身が Settings → MCP で選ぶ選択肢のまま残す。
- **代わりにエージェントにユーザー指示を書かせる。** 0042 決定 8 が無効になる。
- **種別ごとの置き場を互いに同期する。** N 個の形式・N 人の書き手と、編集のたびの衝突。置き場 1 つ・
  書き込み経路 1 つの方が単純。
- **v1 の置き場を CP の Postgres にする。** 0022 が持っていなかった所有者だけの ACL と、Workspace 停止中の
  答えが要る（決定 10）。

## 結果

- Workspace の中では、種別を替える・引き継ぐ・別種別の子を起動する、のいずれでも知識が残る。
- ローカルに自前のメモリを持たない種別がメモリを得る。muse については、ネイティブのメモリと重複するかが
  まだ確かめられていない（未決事項 6）。
- すべてのメモリに書き手と履歴があり、悪い教訓を見つけて巻き戻せる。
- 新しい故障の型：汚染されたメモリが全種別に届き、読まれる前に止めるものは無い。決定 9 が秘密を
  入れず、決定 7 と 8 — 命令ではなく証拠であり、すべての変更に書き手・履歴・巻き戻しがある — が悪い
  メモリを見つけて戻せるものにする。これらは書き込みツールと同時に出す（後回しにしない）。
- メンバーに承認の手間はかからない。見直しは事後に変更一覧で行い、その大半は #1559 の自動レビューが
  担う想定である。
- スイッチがオンの間、claude が読むメモリは AF のもの 1 つ（決定 6 段 2）。ネイティブのメモリはディスク上に
  そのまま残り、スイッチをオフにすると、AF のメモリ抜きで戻ってくる。

## 追記（2026-10-08）：使用実績の並べ替えとピン留め（#1703）

`memory_index` は、ピン留め → 種別の層 → 使用回数 → 新しさの順に並べます。使用とは `memory_read` と、返された
検索ヒットで、Console の一覧表示は含みません。回数は `<範囲のディレクトリ>/.usage/<name>` の副ファイルに、
使用ごとに 1 バイトを追記して持ちます（O_APPEND なので read-modify-write も取りこぼしもなく、上限 4096、
コミットも書き出しもしません）。忘却や再作成で消えます。ピンはフロントマターの `pinned: true` で、付けるのは
Console からです（MCP のピンツールはなく、ほかの Agent のルートと同じく同じ Workspace 内のシェルは防げません。書き手は経路でメンバーと記録されます）。経路は `POST /agents/memory/entries/pin`、op は `pin`、監査は `memory.entry.pin` です。
revision も `updated` も変えず、エージェントの保存はピンを引き継ぎます。バイト予算は守られます：ピンが先に説明つき
の部分を埋め、収まらないピンは名前だけの末尾へ落ちて `pinnedOmitted` に数えられ、
`memory_index` が表示します。検索の関連度は #1558 のままです。

## 注（2026-10-08）：claude ネイティブメモリへの書き戻し（#1914）

スイッチを切ると claude は自前のメモリに戻るが、そこには AF 経由で学んだ内容がない。
`memoryx/agent_memory_claude_export.go` がプロジェクトの AF メモリを
`<claude の設定>/projects/<slug>/memory/` へ写す。slug はプロジェクトのメイン作業コピー
（`project.json` の `root`）のキー。決定 6 が退けたのは継続的な claude → AF 同期で、これは別物：
明示的でプレビュー付き（`GET /agents/memory/claude-export[/preview]`、`POST` は
`memory.claude_export` として監査）、スイッチのオン・オフを問わず使える。

- プロジェクトスコープのメモリ 1 件につき 1 ファイル。claude の形（`name`・`description`・
  `metadata.type`・本文）に `metadata.af_source`（`<プロジェクト ID>/<名前>@<revision>`）と
  `metadata.af_hash`（書いた description・type・本文の sha256）を足す。AF 固有の項目は書かない。
  ユーザースコープは書かない（claude にユーザー全体のメモリ置き場がない）。他の種別限定のメモリは除く。
- 状態：`new`、`update`（AF が書いて以後変わっていないファイル）、`unchanged`、`conflict`（AF が
  書いていない、または書いた後に変わったファイル。リクエストで名指ししない限り残す。シンボリック
  リンクは置き換えない）、`native_only`（残す・消さない）、`remove`（AF が書き、変わっておらず、
  メモリが忘れ済みのファイル）、`secret`（出す前にもう一度検査。上書き不可）。適用はプレビューの
  トークンを添え、途中で何か動いていれば拒む。
- `MEMORY.md` は AF の順位（ピン・種別・利用回数・新しさ）、続いて残るファイルを新しい順に、200 行・
  24 KiB 以内で作り直し、末尾に「N more memories」行を置く。古いものは置き換えるが、最初の書き込み前に
  取るスナップショット（`pre-export`、0022）で元に戻せる。スナップショットに失敗したら何も書かない。
  書き込みはすべて、シンボリックリンクを辿らず開いたディレクトリハンドルの中で一時ファイル→rename。
- 取り込みがコピーしたファイル（#1921）には AF の印がないので、取り込みの証拠で判定する。ファイルの
  ハッシュがメモリに記録した `source_hash` と等しければ claude のファイルは元のままで、AF の写しが
  まだ取り込みのままなら `unchanged`、AF の写しが先へ進んでいれば `update`。取り込み後に claude で
  変えたファイル、またはどちらも書いていないファイルだけが `conflict`。更新では、ネイティブの
  ファイルの `metadata` のうち AF の持ち物でない行（claude の `node_type`・`originSessionId`・
  `modified`。測った 598 ファイルすべてにある）を残す。未知のトップレベルのキーは引き継がない。
- 取り込みとの輪の防止：`af_source` が AF のメモリを指し、本文が `af_hash` のままのファイルは、
  mtime が AF の更新より新しくても取り込みは `unchanged` と読む。
- codex：#1683 に回す（codex のメモリ領域は codex 自身のパイプラインが書き換えるため）。
