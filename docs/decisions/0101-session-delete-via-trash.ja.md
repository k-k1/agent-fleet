# 0101. セッションの削除はすべてごみ箱を通す——worktree の削除とセッションの削除を分ける

[English](0101-session-delete-via-trash.md) | 日本語

- 状態: **accepted**（2026-09-24）。同じ変更で実装する。設計の経緯・入口の棚卸し・ごみ箱の実測は
  [docs/log/115](../log/115-session-delete-via-trash.ja.md)。§115.7 の判断 6 件は、利用者がすべて推奨案を選んだ。
- Follow-ups: #950
- 関連: [0097](0097-session-retention.ja.md)（停止セッションの保持。決定 2「削除は人の操作だけ・回収は常に

  [0096](0096-fleet-session-graph.ja.md) 決定 6（人の削除は系譜も消す。変えない）

## 背景

セッションのメタを忘れる経路は 3 つあり、ごみ箱（`~/.local/share/agent-fleet/cleanup/` の gz）を
通るのは `DELETE /sessions/{name}?reclaim=1` だけだった。

- `POST /sessions/{name}/stop` は、メタを消し、会話ログと side files を残し、ごみ箱を通らない。さらに、
  最後のセッションだった worktree を `MaybePruneWorktree` で消すことがあった。呼ぶのは、shell / ssm の
  行の「削除」、リポジトリ行と孤児整理の一括整理、作業コピーの削除（どれも shell/ssm の分）、画像
  スタジオの「エージェントを切り替える」（AI セッション）だった。
- `DELETE /repos/{name}?prune_sessions=1`（掃除モーダル②と MCP `delete_worktree`）は、その worktree の
  停止中セッションのメタを消し、ごみ箱を通らない。

利用者から見て同じ「削除」が、入口によって戻せたり戻せなかったりした。戻せない削除は容量も回収せず
（会話ログが残る）、セッションの貼り付け画像はその瞬間にキャッシュ孤児の掃除対象になった（ADR 0097 追記）。
ガイドは「消しすぎても戻せます」と書き、shell の削除の確認は「取り消せません」と書いていた。
ADR 0097 決定 2 の「これで例外なく真になる」は、成り立っていなかった。

また、停止・削除と worktree の片付けが両方向に絡んでいた。セッションを消すと worktree が消え、
worktree を消すとセッションが消えた。

## 決定

### 決定 1 — セッションのメタを忘れる方法は「ごみ箱へ移す」1 つだけ

Agent の `trashSession` が唯一の経路になる。

1. `finalizeSessionUsage` で利用量を確定する。
2. メタと会話ログ（claude）を 1 つの gz アーカイブに入れる。**端末履歴は入れない。** 端末履歴は意図して
   短命にしてある（既定は `/tmp`、保持はテナントの設定 `AF_TERMINAL_HISTORY_RETENTION_DAYS` が決め、0 は
   「消す」という方針）ので、期限の無いごみ箱に移すとその方針を破る。shell / ssm をごみ箱から戻すと、行
   （メタ）が戻る。
3. 退避できてから、会話ログ・メタ・系譜・side files・端末履歴・managed の台帳・status の記録を消す。
   **退避に失敗したら何も消さない。**
4. worktree には触らない（決定 3）。

同じ名前の削除は 1 つずつ走り、アーカイブの ID は上書きされない。消す直前にメタのロック内で、ロック・稼働中・
会話ログが退避後に増えていないかを見直し、どれかなら何も消さずアーカイブを取り下げる（409 `session_resumed`）。
消したメタは、そのプロセスでは古いスナップショットの書き戻しでも戻らない（戻すのはごみ箱からの復元だけ）。
経緯はレビュー記録 docs/log/115-review.md。

`POST /sessions/{name}/stop` と `DELETE /sessions/{name}`（`reclaim` の有無を問わない）は、どちらもこれを通る。
稼働中のセッションは、`DELETE` なら 409 で断る。`/stop` と `DELETE …?stop=1` は halt と同じ手順で止めてから移す。
`/stop` は、古い Console が呼んでも安全になるよう残す互換の名前で、新しい Console は `DELETE …?stop=1` を使う。
CP の監査は `DELETE /api/sessions/{name}` を `session.delete` として記録する（`/stop` も同じ名前に揃える）。

### 決定 2 — 行メニューに出す項目は変えない。shell / ssm の「削除」はごみ箱へ移す

AI セッションの行には今までどおり「削除」を出さない（棚へ移し、棚から削除する 2 段を保つ）。
shell / ssm の「削除」と、一括整理・孤児整理・作業コピーの削除での shell/ssm の扱いは、決定 1 を通る。
画像スタジオの「エージェントを切り替える」は、前のセッションを消さずに**止める**（`/halt`。develop の c7fe0ccd9 が同じ判断で先に入れた）。

### 決定 3 — セッションを消しても worktree は消さない

`MaybePruneWorktree` を廃止する。worktree を消すのは、掃除モーダル②・左ペインの「作業コピーを削除」・
MCP `delete_worktree` だけになる。代償として、最後の shell セッションを消した worktree は掃除②に残る
（ADR 0097 決定 5 と同じ代償）。

### 決定 4 — worktree を消すと、中の停止中セッションは棚へ移る

`DELETE /repos/{name}` は、作業コピーを消した後、その中の停止中セッションを次のように扱う。
`prune_sessions` の有無で動きを変えない（パラメータは受け付けるが意味を持たない）。

| セッション | 扱い |
|---|---|
| 稼働中 | 削除そのものを 409 で断る（今までどおり） |
| ロック済み | 削除そのものを 403 で断る（今までどおり） |
| 棚にある | 触らない |
| 停止中の AI セッション | **棚へ移す** |
| 停止中の shell / ssm | **ごみ箱へ移す**（決定 1。作業場所の無い shell を棚に残す意味は無い）。作業コピーを消す**前に**移し、移せなければ作業コピーも消さない（500 `sessions_trash_failed`） |

worktree を消す人が決めたのは作業コピーのことで、会話を捨てることではない。会話を捨てるのは、棚から
削除するという別の操作にする。確認ダイアログで「棚へ／ごみ箱へ」を選ばせることはしない（棚からごみ箱へは
1 押しで移せる）。

作業コピーの削除は、ガードからセッションの後始末までを削除ゲートの中で行い、ロックの操作も同じゲートを取る。
削除の途中で掛けたロックは、削除の前に効くか、削除が終わるまで待つ。

作業フォルダが無くなったセッションは、棚でも一覧でも会話を読めるが、再開はできない
（「フォルダがありません」）。

### 決定 5 — オペレーターの権限と承認は変えない

`delete_session`・`delete_worktree` は今までどおり `writeEnabled()` のオペレーターだけに見え、Discord から
動くターンでは承認を求める。`delete_worktree` の説明文だけを決定 4 に合わせて直す。新しいツールは足さない。

### 決定 6 — ごみ箱に期限は付けない。人が押す「古いものを完全に削除」を足す

ADR 0097 決定 2・3 のとおり、自動では消さない。掃除モーダルのごみ箱タブに「N 日より古いものを完全に削除」
（既定 30 日、件数と容量を確認に出す）を足し、設定 → マシンのごみ箱の表示に件数と最も古い日付を足す。

### 決定 7 — 既存の「メタの無い会話ログ」は移行しない

`/stop`・`prune_sessions`・ADR 0097 以前の TTL prune が残した会話ログは、名前が分からないので
ごみ箱に戻せない。フリート以外の会話ログ（人が shell で直接起動した claude など）と区別もできない。
まず件数と容量を数え、その結果を見て扱いを決める（docs/log/115 §D7 の (a)〜(c)）。**数える仕組みはこの変更に
入っていない。** claude の sid の付け替え（`LiveSID`）・フォーク・サブエージェントのファイルを正しく扱わないと、
数そのものが誤るので、後続で別に作る。

## 却下した案

- **Console だけを `DELETE ?reclaim=1` に替え、`/stop` は残す。** 古い Console とほかの呼び手が戻せない
  削除を続ける。
- **worktree の削除で中のセッションもごみ箱へ入れる。** worktree を消す人は会話を捨てると言っていない。
- **ごみ箱に期限を付ける。** ADR 0097 決定 2・3 と衝突する。
- **AI セッションの行に「削除」を足す。** 棚を経由する 2 段が崩れる。目的（すべての削除をごみ箱に通す）には要らない。

## 影響

- shell / ssm の削除が戻せるようになり、ごみ箱が少し増える。
- セッションを消しても worktree が残り、掃除②の候補が少し増える。
- worktree を消しても会話が棚に残る。
- キャッシュ孤児の判定は変えない。消したセッションはごみ箱にあるので、貼り付け画像はアーカイブを完全に
  削除するまで守られる。
- 監査の操作名が `session.stop` から `session.delete` に変わる。
- ADR 0097 の背景（「唯一」）と決定 5、ADR 0028 の「worktree の自動 prune」には追記で訂正を入れる。
