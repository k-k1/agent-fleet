# 0064. 文書を 3 人の読者へ分け、配布をロールで切るのをやめる

[English](0064-docs-three-audiences.md) | 日本語

- 状態: **採用**（2026-09-01）。
- 関連: [0055-idle-stop-and-carried-interactions.md](0055-idle-stop-and-carried-interactions.ja.md)（同じく
  「コンテナの中から何が見えるか」で挙動が決まる系）

## 背景

利用者から 2 つの指摘があった。**リンク切れが多い**・**必要のない前置きが多い**。
どちらも同じ 1 つの原因から出ていた——**開発者向けの文書と利用者向けの文書が同じ棚に
同居し、リンクで繋がっていた**。

`scripts/docs-check.py --strict` は 0 error だった。それでも切れるのは、`check_links` が
**リポジトリ上の実在しか見ていない**から。読者が実際に開くのはコンテナへ配られた
`/usr/local/share/agent-fleet/docs` で、そこに `build/` も `decisions/` も
`CONVENTIONS` も無い。実測（2026-08-31・develop `5e54f6a3`）:

- 配布物から開発者棚・規約へ出ていくリンクが **154 本**（`use/` 48・`ref/` 68・
  `operate/` 28・`admin/` 10）。ほとんどは章末尾の定型行と「詳細は dev/NN §X」。
- 節ごと書き手向けのものがあった。`use/README` の「ここに書くもの／ここに書かないもの／
  更新トリガ」、`ref/README` の「なぜ共有の棚なのか／この表が真であり続ける仕組み」
  （ソースのパス入り）、`ref/glossary` の「利用者向けの棚で避ける語／執筆規約」。
  最後のものは、**利用者のコンテナに執筆マニュアルを配っている**状態だった。
- `use/` 32 ファイルの前置きが **429 行**（平均 13 行）。`Audience:` /
  `Source of truth:` / `Updated:` の 3 行は CI のための行で、`> 対象: …` の引用ブロックは
  その重複（26/32 ファイル）。
- H1 の章番号が **7 章ぶんファイル名とずれ**、`09-collaboration` と
  `11-troubleshooting` が**両方 09 を名乗っていた**。相互参照のラベル約 60 箇所も
  古い番号のまま。

## 決定

### 1. 読者は 3 人。ツリーもそう分ける

| 読者 | 置き場 | 配布 |
|---|---|---|
| 使ってみたい人 | ルートの `README.md` / `README.ja.md` | GitHub のみ |
| 使っている人（メンバー・テナント管理者・配備管理者）| `guide/` | **コンテナへ配る** |
| コードを変える人 | `docs/` | **誰にも配らない** |

`docs/{use,admin,operate,ref,assets}` を `guide/{member,admin,operate,ref,assets}` へ
移した。**ディレクトリの境界がそのまま配布の境界**になる。

### 2. リンクは一方通行

**`guide/` から `docs/` へはリンクしない。逆は自由。**

`docs/` は読者のコンテナに存在しないので、そこを指すリンクは**リポジトリ上では実在する
のに読者の手元では必ず切れる**。散文で「詳細は開発者向けの資料にあります」と告げるのは
正しく、それをクリックできるようにするのが誤り。`check_closure` が機械で見る。

`guide/` も GitHub で読めてよい——分離したいのは「開発者向けが利用者に混ざること」で
あって、公開範囲ではない。

### 3. 配布をロールで切るのをやめる

`docsRolePrefixes`（member は `use/` と `ref/` だけ、tenant_admin は ＋`admin/`、
super_admin は ＋`operate/` `build/`）を廃止し、**誰もが `guide/` を丸ごと受け取る**。

理由:

- **そもそも権限の境界ではなかった。** `workspace_docs.go` の設計コメント自身が
  「**not a leak (the repository is public)** but it is noise」と書いている。一方
  `docs_bridge.go` は「a member cannot ask for a shelf above its role」とアクセス制御の
  ように書いており、**同じ subsystem の 2 つのコメントが目的について食い違ったまま
  契約になっていた**。Apache-2.0 で公開しているのと同じ内容なので、`admin/` を
  メンバーから隠しても守るものは無い。
- **雑音の正体は `build/` だけだった。** 33k 行の凍結ジャーナルは配布 allowlist が
  全員に対して落としている。ロールが追加で落としていたのは admin 1,388 +
  operate 3,262 + **build 5,651** 行で、雑音なのは最後のものだけ。この分割で `build/` は
  `docs/` へ移り誰にも配られなくなるので、**ロールで切る必要が無くなった**。配備管理者の
  コンテナはむしろ 18,000 行 → 12,000 行に減る。
- **ロール切りこそが指摘 1 の原因だった。** 配布物の中のリンクが「読者によって届いたり
  届かなかったり」する。だから `use/12-settings → admin/README` の可否が判断不能になり、
  注意書きを添えるしかなかった。一様配布なら、リンクは**全員に届くか誰にも届かないか**の
  どちらかになる。
- **ロール切りのためだけに在った規則が消える。** `check_notes` の「保証されない棚を
  指すなら同じ段落に『may be absent』と断れ」は、mount が役割別だったから必要だった。
- **ロールの変化に追従しなかった。** docs はワークスペース起動時にステージされるので、
  メンバーがテナント管理者になっても**次の起動まで `admin/` は現れない**。

**残るコスト**: エージェントが grep する対象に `operate/`（ホスト側・root 前提の手順）が
入るので、メンバーの「どうやるの？」に配備側の手順を混ぜて答える余地は増える。棚の頭に
読者を明記し、`workspace-notes.md` の案内を「まず `guide/member` を見よ」にして抑える。

「リクエストがスコープを選べない」という防御と、「`decisions/` と `log/` は誰にも
出さない」は**残す**。変わるのは「誰が何を受け取るか」だけで、「何を配らないか」ではない。

### 4. 見出しの id は Console の規則で照合する

`console/src/lib/filemeta.ts` の `slug()` は**連続する空白を 1 個の**ハイフンにするが、
GitHub（github-slugger）は空白 1 個につき 1 個。`—` や `/` のように**空白に挟まれた記号**を
含む見出しで、2 つの規則は食い違う（`a — b` は Console で `a-b`、GitHub で `a--b`）。
全角括弧はさらに逆で、Console は捨て GitHub は残す。

実測すると、リポジトリ全体で **Console 規則でしか解決しないリンクが 52 本、GitHub 規則で
しかないものが 10 本**だった。`guide/` の読者が開くのは Console なので、**行き先が
`guide/` なら Console 規則、`docs/` とリポジトリ直下なら GitHub 規則**で照合する。
一律にすると `CONTRIBUTING.md#commits--prs` のような**GitHub では正しい**アンカーを
壊れていると報告してしまう（実際にそうなった）。

## 退けた案

- **`docs/` の中で閉じる（`use/` を自己完結にするだけ）。** `ref/` が 4 人の読者で
  共有される棚のまま残り、その中に「この表が真であり続ける仕組み」（ソースのパス）が
  同居し続ける。**「完全に分離」にならない**。
- **`docs/` を配布物にして開発者向けを `dev/` へ退かす。** コンテナ内のパスと
  リポジトリのパスが一致する利点はあるが、移動量が最大（decisions 126 / log 90 /
  build 34 ファイル）で、得るものは名前だけだった。
- **`Source of truth:` の行を全ファイルから消す。** `guide/ref/` では**10 ファイルすべて
  値が違い**（「この表が正」「画面欄は Console・実装欄はコード」…）、読者が矛盾に
  出会ったときにどちらを信じるかを決める本物の情報だった。消さずに front matter へ
  降格させた。`guide/member/` の 16 ファイルと `guide/admin/` の 6 ファイルでは
  値が一字句同じなので、そちらは棚の README に 1 回だけ書く。
- **`slug()` を github-slugger 互換に直す。** 1 行で 14 件の食い違いが消えるが、
  **Console 規則でしか解決しないリンク 52 本が一斉に壊れる**。多数派を壊す修正だった。

## 結果

`guide/` から外へ出るリンクはゼロ。検査は 3 本増えた（`anchors` / `closure` /
`chapters`）。CI が見るのは「配布物が自己完結しているか」であって、もはや
「リポジトリ上に在るか」ではない。
