# 0090. 利用者が見分けられる id と、読める名前

[English](0090-member-facing-model-names.md) | 日本語

- Status: **accepted**（2026-09-18）。同じ変更で実装済み。「ある」「ない」はすべて `69122d20`
  （develop、ADR 0089 マージ済み）への grep で確認し、下記の id 衝突は実際のファイル名に対して
  `engineIDFromFile` を走らせて再現した。
- [0088](0088-model-catalogue-names-and-examples.ja.md) 決定 5 と
  [0089](0089-quantisation-ladder-and-fit.ja.md) 決定 7 が両方で記録し、意図的に残していた帰結を
  閉じる。

## 背景

ADR 0088 が目録の行に配布元の名前を与え、ADR 0089 が同じモデルの複数サイズを持つことを 1 押しに
した。どちらも管理画面で止めており、どちらも同じ帰結を書き残していた——**モデルを選ぶ利用者には
いまも id が見えている**。

そしてその帰結は、ADR 0089 が出た瞬間に、どちらの ADR も予期していない形で悪化していた。
`engineIDFromFile`（`engine_plan.go`）はファイル名から id を提案するときに**量子化を削って**
いた。テストがその規則をこう明記していた——*「量子化はファイルの名前であってモデルの名前ではない:
同じモデルの 2 つの量子化は 1 つの id を提案する」*。`unsloth/Qwen3.8-27B-GGUF` の実ファイル名で
走らせると:

```
Qwen3.8-27B-UD-IQ2_XXS.gguf  -> "qwen3.8-27b-ud"
Qwen3.8-27B-UD-IQ2_S.gguf    -> "qwen3.8-27b-ud"
Qwen3.8-27B-UD-Q2_K_XL.gguf  -> "qwen3.8-27b-ud"
Qwen3.8-27B-UD-IQ4_XS.gguf   -> "qwen3.8-27b-ud"
```

4 つとも同じ id を提案するので、`enginePlanID` が 2 つ目を数字の接尾辞で一意にする。ADR 0089 の
新しいボタンを 2 回押した配備は、利用者に **`qwen3.8-27b-ud` と `qwen3.8-27b-ud-2`** を並べる
ことになる——見分ける唯一の事実が削られ、そこにカウンタが入った 2 つの文字列の選択だ。

利用者がそれに出会う場所は、ちょうど 2 つ。

- **opencode 自身のモデル選択**。Agent が設定に書く `name`
  （`internal/agents/opencode/engine.go`）で、`<id> + " (self-hosted)"` だった。
- **画像生成ペインのモデル `<option>`**（`GenerateForm.tsx`）で、`{m.id}` を描いていた。

そして行は答えをすでに持っている: ADR 0088 以来の `display_name` と、上流のファイルを正確に
記録している `source`。取りに行くものは何も無い。

## 決定

### 決定 1 — 提案する id は量子化を残す

`engineIDFromFile` はもう削らない。旧規則は配備が 1 モデル 1 サイズを持つ間は正しく、ADR 0089 が
複数を普通にした以上、見分ける語を削る規則は正反対になる。

既存の行は変わらない——id は保存済みで、これは次の取り込みの**提案**にしか効かない。提案である
ことも変わらない（人が編集できる）。

棄却——衝突するときだけ削る案。見えない規則から一貫しない目録（1 つ目は裸、2 つ目は量子化つき）が
生まれる。全体が少し長い id になるほうがましだ。

### 決定 2 — 利用者向けの中継が名前を運び、id は鍵のまま

`engineCatalogModelRow` が `label` を出す: 配布元の名前＋同じモデルの 2 行を見分ける部分
（Civitai ならバージョン、Hugging Face ならファイルの量子化）。

🔴 **id の**横**であって、id の代わりではない。** `id` はリクエストが名指すもの、opencode が
モデルを keyed するもの、ゲートウェイが routing するもの、アクティブセットが書かれている語だ。
`label` は描くための文字列で、どのリクエストにも届かない。Agent 側のテストは両方を固定している
——label がモデルの**鍵**として書かれていないことも含めて。

🔴 モデルのページを誰も読んでいない行では **空ではなく不在**。どの読み手も id に落ちる。それは
この欄ができる前に全員がやっていたことなので、不在は欠落ではなく従来の挙動である。

### 決定 3 — 合成は Control Plane で 1 度だけ

`engineModelLabel` / `engineModelVariant` は `engineSearchHit.URL` を合成する `engineSourceURL` の
隣にあり、理由も同じ: 名前とバージョンと source を同時に持っているのはこちら側だけで、Agent（Go）で
もう一度、ブラウザ（TypeScript）でもう一度合成すれば、1 つの名前に 3 つの綴りができる。

variant は `source` から読み、id からは決して読まない——id はファイル名を小文字にしたもので、手で
登録した行にはそもそもファイル名が無い。id を戻すのは、`source` が正確に記録している変換を
再導出することになる。

*（Console は ADR 0089 の梯子のために自分の `quantLabel` を持ち続ける。あれがラベルを付けるのは
**上流の候補**——行がまだ無く、したがって合成済みの label も無いファイル名だ。入力が違うので、
この規則の 2 つ目のコピーではない。）*

### 決定 4 — 5 つの継ぎ目を端から端まで試す

label は CP の行・目録 JSON・`engineCatalogModel`・2 つの id 別 map・opencode の `name` と
画像ステータスの `label` を渡る。どこか 1 つで落ちても**無音**だ（`sessionWire` がこの艦隊に
教えた失敗）。だからテストは `syncEngineProviders` を動かして**書かれた設定ファイルを読む**。
途中の構造体を assert しない。

### 決定 5 — 選択肢は名前を出し、id を落とす

`<option>` に両方を入れる余地は無い。管理カードは全カードに id を残す（ADR 0088 決定 1）——
運用者は行とバケットのファイルを突き合わせる必要があるからだ。**利用者は S3 のキーを一度も
見ない**ので、id は何も買わずに 1 行ぶんを使い切る。違う規則、理由つき。

### 範囲外のまま — 作例画像

ADR 0088 決定 2 が 1 枚を保存し、ADR 0088 決定 5 が利用者向けの中継から外した。それは変わらない:
配布元の作例を利用者の前に出すということは、Civitai のコンテンツレーティングを既定でどう扱うか、
CDN を禁じるネットワーク方針のテナントをどうするかを決めることだ。名前はどちらの問いも起こさない。
だから名前は行き、絵は行かない。

## 実測したこと

| 主張 | 方法 |
|---|---|
| 1 つのリポジトリの 4 つの量子化が同じ id を提案する | 実ファイル名に対して `engineIDFromFile` を実行、2026-09-18 |
| 2 つ目の行は `<name>-2` になる | `enginePlanID` の接尾辞ループ（`69122d20` で確認） |
| opencode の選択に `<id> (self-hosted)` が出ていた | 本変更前の `internal/agents/opencode/engine.go` |
| 画像ペインの選択肢が裸の id だった | 本変更前の `GenerateForm.tsx` |
