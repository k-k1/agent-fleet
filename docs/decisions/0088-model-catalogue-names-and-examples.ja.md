# 0088. 鍵の一覧ではなくモデルの一覧に — 配布元の名前、作例 1 枚、そしてファミリーをカテゴリに

[English](0088-model-catalogue-names-and-examples.md) | 日本語

- Status: **accepted**（2026-09-18）。同じ変更で実装済み。以下の「ある」「ない」はすべて `f9feed5b`
  （develop）への grep で確認し、「実測」はすべて同日に上流の API を直接叩いて読んだ。
- 前提: [0072](0072-engine-model-catalog.ja.md)（目録とその行）。その決定 2 は本 ADR が壊しては
  ならないもの——上流の表示名を、プロバイダがディスパッチするファミリーにしてはならない。
  [0085](0085-model-ledger-and-one-press-ingest.ja.md)（本 ADR が変える `登録済み` タブと、ここで
  必要なものをすでに読んでいる resolve）。[0081](0081-image-generation-pane.ja.md) 決定 5（先例:
  ウィザードが見せて捨てていた事実に、列を与えた）。

## 背景

`登録済み` タブは目録の行ごとにカードを 1 枚描き、その見出しは `model.id` だった
（本変更前の `adminEngineAdd.tsx:709`）。この id は誰かが選んだ名前ではない——取り込み時に
**ファイル名から**作られる（`engineIDFromFile`、`engine_plan.go:388`）。起動メニュー、アクティブ
セット、S3 の配置、他の管理画面がすべてこの鍵で書かれているからだ。結果として目録はこう読める:

```
abyssorangemix2_hard_8832          説明なし
anima-aesthetic-v1.1               説明なし
meinamix_meinav11_5038             説明なし
```

チェックポイントが 3 つ。画面のどこにも、それがどのモデルなのか、何が描けるのか、どれとどれが
互いの代替なのかは書かれていない。最後の問いに答える唯一の事実であるファミリーは、カードの本文の
真ん中、精度と VRAM の数字のあいだにタグとして埋まっていて、20 枚並んだページをそれで拾い読み
することはできない。

いま行が持っているもの: `description`（取り込みが作った行では常に空——埋めるものがない）、
`base_model`、`license*`、`source`、`trained_words`、`params`、ファイル群。持っていないもの:
**名前と、絵**。

どちらも上流にはあり、そしてここが以下の形を決める——**取り込みがすでに行っている読み取りに
乗ってくる**。

- **実測 2026-09-18**、`GET https://civitai.com/api/v1/model-versions/119057` は
  `model.name` = `"MeinaMix"`、`name` = `"Meina V11"`、そして `url` / `nsfwLevel` / `width` /
  `height` / `type` を持つ `images[]` を 10 件返す。`engineResolveCivitai`
  （`engine_ingest.go:481`）は sha256・サイズ・ライセンスのために**まさにこの文書**をすでに
  decode している。その 3 つのフィールドを decode していないだけだった。
- `探す` タブは ADR 0085 以来同じ絵を描いている（`engineSearchHit.PreviewURL` / `ThumbURL`）。
  Civitai の CDN の変換セグメントをカード用と拡大用に書き換える経路つき
  （`engineCivitaiImageVariant`、実測 2026-09-15: 原寸のまま 20 件で約 40 MB）。つまりカード側の
  やり方は実績がある。何も持っていないのは**行**のほうだ。
- Hugging Face 側の **実測 2026-09-18**: `cardData.thumbnail` は、この配備が動かしている 2 本を
  含む 4 リポジトリすべてで**存在しない**（`unsloth/Qwen3-Coder-30B-A3B-Instruct-GGUF`、
  `bartowski/Qwen2.5-7B-Instruct-GGUF`、`Qwen/Qwen2.5-7B-Instruct`、
  `black-forest-labs/FLUX.1-dev`）。**LLM の行には事実上、絵がない**。設計はそれに依存しては
  ならない。

## 決定

### 決定 1 — 行は配布元の名前を記録する。id は残し、決して置き換えない

`engine_models` に 4 列（移行 `0068` / pg `0053`）: `display_name`、`version_name`、
`preview_url`、`thumb_url`。取り込み時に resolve から埋める。上流への読み取りは 1 回も増えない。

名前が 1 つでなく 2 つなのは、それが 2 つの事実だから——モデルと、取り込んだそのバージョン。
この対こそ、ファイル名由来の id が表現できないものであり、同じモデルの 2 行を見分けさせるものだ。

**id はカードに残る。独立した等幅の 1 行として。** それがすべての S3 キー・起動メニュー・
アクティブセットの言う語だからだ。「AbyssOrangeMix2」だけのカードは、運用者が目の前のファイルと
突き合わせられないカードであり、それは今日の失敗を裏返しただけのものになる。

棄却: 行の改名（`id` を表示名にする）。id は S3 の配置と公開済みアクティブセットが参照する主鍵で
あり、読みやすさのために行を改名する目録は、次のコールドスタートで誰も宣言していない鍵を同期
する目録になる。

### 決定 2 — 絵は配備が**記録する URL** であって、配備が**持つバイト**ではない

`preview_url` / `thumb_url` は配布元自身の CDN を指す。S3 バケットには何も複製しない。

棄却——取り込み時にサムネイル 1 枚をバケットに複製する案。配布元が画像を消しても残り、ブラウザが
civitai.com に届かない配備でも出る。その代償は、`purge`・台帳（ADR 0085 決定 2）・オブジェクト
経路がそれぞれ覚えなければならない**第 3 の種類のオブジェクト**と、取り込み経路の中の取得 1 段。
JPEG 30 kB のために。防げる失敗は「1 回押せば直る空の箱」（決定 4）で、持ち込む失敗は、ただでさえ
終わりを誰も見られないタスクである削除経路の中にある。

その帰結は受け入れたうえで明記する: 配布元が消した画像は出なくなり、**利用者のブラウザ**が CDN に
届かない配備では作例が出ない。どちらも新しい話ではない（`探す` タブは ADR 0085 以来同じホストを
直リンクしている）。`<img>` には `referrerpolicy="no-referrer"` を付け、どの配備が見ているかを
配布元に渡さない。

### 決定 3 — ファミリーはタグではなくカテゴリにする

`登録済み` の一覧は、グループ名を見出しにした区画として描き、その上のチップ列で 1 つに絞る。
何で分類するかは、その行が**何であるか**による。

| 行 | 分類 | 理由 |
|---|---|---|
| 画像のチェックポイント / LoRA | `base_model`（ファミリー） | プロバイダがワークフローを選ぶ鍵であり、2 つの行が互いの代替かどうかを決めるもの |
| LLM のアダプタ | `base_model`（親モデルの id） | 同じ問いを、その役割の語彙で言ったもの |
| GGUF | **配布者**（`display_name` の最初のセグメント） | ファミリーを一切宣言しないから。そして同じ重みを別の人が量子化した 2 行は、本当に別の行だ |

🔴 **何も宣言していない行のグループは先頭に来る**——台帳の孤児と同じだ。ファミリーの無い行は
片付け残しではない。CP はそれを有効化できない（`engine_files_missing` / `base_model_missing`）
ので、この画面で誰かが手を打つべき唯一のグループである。次にエンジン自身が宣言するファミリーを
エンジン自身の順で（`row.base_models`）——どの配備でも区画の読み順が同じになる。それ以外は
アルファベット順で後ろに続く。

ここでは上流の名前を `base_model` に書き込むことは一切しない。ADR 0072 決定 2 はそのまま立って
いる。ファミリーは運用者が行う宣言であり、本 ADR はそれを**読める場所に描く**だけだ。

### 決定 4 — この列ができる前に取り込まれた行は、明示的な 1 押しで埋める

`POST /api/admin/engines/{key}/models/{id}/meta` が、行の `source` が指すページを読み直して 4 列を
書く。Console はこれを行ごとに（名前も絵も無い行にだけ——つまりこの操作は自分で引退する）、そして
ツールバーに 1 つ、全行ぶんを**1 行ずつ**歩くものとして出す。

これが無いと、この機能は「まだ誰も取り込んでいないモデル」にしか効かない。配備がすでに持っている
行はすべて、列ができる前に書かれたものだからだ。

棄却——列の無い行が一覧に出たときに、画面の裏で埋める案。画面を開くという操作が、誰も頼んでいない
上流リクエストのページ 1 枚ぶんに化ける。しかも相手は 503 で負荷を落とすサイトであり（実測、
ADR 0085 の検索リトライ）、運用者にはその費用が見えない。

この経路は、専用の狭い読み取りではなく既存の resolve をまるごと走らせる。1 回で済むところに
2〜3 回かかる。その代わりに買えるのは肝心なこと——この配備がモデルのページを読む道は **1 本** で
あり、行に載る名前が、取り込みの読まない文書から来ることは決して起こらない。

上流の無い行は専用のコード `engine_no_source` で断り、メッセージは 2 つのどちらであるかを言う:
何も記録が無い（種として入った行、またはバケットから手で登録した行）か、`url:` の source か。
後者は重みそのものを指していて、ページではない。

### 決定 5 — これは管理者の目録だけの話

利用者向けの射影（`engineCatalogModelRow`。Agent が——したがって画像生成ペインが——見られる唯一の
もの）は**変えない**。ペインこそこの次の置き場所として自然で——利用者が「どのモデルにしようか」と
考える場所だ——意図的に範囲外にした。作例を利用者の前に出すということは、Civitai のコンテンツ
レーティングを既定でどう扱うか、CDN を禁じるネットワーク方針のテナントをどうするかを決めると
いうことだ。本 ADR はその答えを持っていない。

帰結は実在するので記録しておく: モデルを選ぶ利用者には、いまも id が見えている。

## 実測したこと

| 主張 | 方法 |
|---|---|
| Civitai のバージョン文書はモデル名・バージョン名・作例 10 件を持つ | `GET /api/v1/model-versions/119057` 実機、2026-09-18 |
| Hugging Face はこの配備が使うリポジトリに `cardData.thumbnail` を出していない | `GET /api/models/<repo>` を 4 リポジトリで実機、2026-09-18 |
| 作例は 2048x4096 かそれ以上ある | 同じ読み取り。だからカードは切り抜いた箱ではなく `object-fit: contain` と高さの上限にした |
