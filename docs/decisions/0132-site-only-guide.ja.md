# 0132. 利用ガイドは agent-fleet.org/docs/ だけで読む。コンテナに同梱するコピーはやめる

[English](0132-site-only-guide.md) | 日本語

- 状態: **提案**（2026-11-07）。利用者が選んだ方針で、サイトを公開したあとに段階を追って進める。
  フォローアップ: #3463。
- 改める記録: [0064](0064-docs-three-audiences.ja.md)（`guide/` の「すべてのコンテナに配る」）/
  [0131](0131-public-docs-site.ja.md) §2（Console のガイドとエージェントの知識が、同梱のファイルを読むこと）

## 背景

ADR 0131 は `guide/` を `https://agent-fleet.org/docs/` のサイトとして公開し、同梱のコピーも残した。Control Plane は
`guide/`（と runbook、リリースノート。`deploy/release/stage-docs.sh`）をイメージに焼き込み、docker と native はそれを
各ワークスペースの `/usr/local/share/agent-fleet/docs` にマウントし、ECS は docs ブリッジで取り寄せる。Console の
**ガイド**メニューはそのコピーをファイルビューアで開き、フリートのポリシーはすべてのエージェントにそれを grep させている。

両方を残すと、同じ文章の読み方が 2 つになり、片方には変換スクリプト、もう片方にはステージングのスクリプトが要る。
しかも Console のビューアはサイトよりガイドを読みにくく表示する（検索、サイドバー、注記の表示がない）。利用者は、
読む場所を 1 つにしたいと求めた。

## 決定

1. **人はガイドをサイトで読む。** Console の**ガイド**メニューは、`https://agent-fleet.org/docs/` の該当ページ
   （日本語は `/ja/` の下）をブラウザの新しいタブで開く。
2. **同梱のコピーはやめる。** Control Plane のイメージ、native の tarball、docs ブリッジ、ワークスペースのエージェント
   から取り除く。`stage-docs.sh` はサイトの入力を作るためだけに残す。
3. **リポジトリの `guide/` は唯一の原稿のまま。** 書き方、検査、レビューは変わらない。`docs-check.py` もこれまでどおり
   検査する。
4. **エージェント向けのフリートのポリシーとトピックのノートは、同梱のまま残す**（`/usr/local/share/agent-fleet/notes/`）。
   これはガイドではなく、小さく、エージェントが何かに届く前に必要になる。ガイドを案内する箇所では、コンテナ内の
   パスではなくサイトの URL を書く。
5. **順番は「読めること」で決める。** サイトを公開してから（ADR 0131。#3463 のデプロイの段階）、Console とポリシーを
   サイトに向け、同梱のコピーは最後に取り除く。

## 結果として起きること

利用者は、この方針を選んだときに次のことを受け入れた。

- **エージェントがガイドを読むにはネットワークが要る。** 外向きの通信が閉じた環境では、エージェントはポリシー、
  トピックのノート、組み込みの知識から答え、ガイドからは答えられない。
- **サイトは最新のリリースを表示する。** アップグレードしていないデプロイでは、新しい動作を説明したページを読むことがある。
- **閉じたネットワークのデプロイでは、製品の中にガイドがない。** 運用者は、そのリリースのタグのリポジトリを読むか、
  サイトを自分でミラーする。

ほかに:

- ポリシーとガイドのパスを結び付けている `docs-check.py` の検査は、サイトの URL を `guide/` に照らして確かめる形に変える。
- docs ブリッジ（`control-plane/docs_bridge.go`、`workspace/agent/docs_sync.go`）、`workspace_docs.go`、ランタイムの
  docs のマウント、`AGENT_DOCS_DIR` / `docsRoot`、CP イメージの `docs` ステージ、リリースゲートの同梱 docs の確認は、
  最後の段階で削除する。
- runbook は、これまでどおり GitHub でスクリプトの隣で読め、サイトでも読める。

## 採らなかった案

- **エージェント向けにだけ同梱のコピーを残し、人はサイトに送る。** 読み手が 2 つ残り、利用者がなくしたかった
  ステージング、焼き込み、ブリッジもそのまま残る。
- **サイトを Console の中で開く**（iframe やブラウザペイン）。サイトは `frame-ancestors 'none'` を返し、ブラウザペインは
  メンバー自身のアプリのためのものである。
