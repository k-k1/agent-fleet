## 背景

Console UI は全文言が日本語ハードコード。i18n ライブラリ・`Intl.*`・`navigator.language` 判定は皆無で、
`index.html` は `<html lang="ja">` 固定。一方、過去の設計で継ぎ目は用意されていた——`client.ts` の
`ERR_TEXT` 直上に「i18n が来たらこのマップにロケール層を足せ」と明記され、バックエンドは
言語非依存コード＋英語 fallback を返す方式（docs/23 P0-3）。設定は自前 `useSyncExternalStore`
（`lib/settings.ts`）で `theme` を localStorage＋サーバ同期し初回描画前に `<html data-theme>` へ適用する
——`theme` が `locale` の完全なテンプレートになっている。翻訳対象はフロント約 956 文字列（123 ファイル）＋
バックエンド約 70〜90。

## 決定

1. **第 1 弾は日本語↔英語**。日本語をソースに英語を第 2 言語。カタログ/ランタイムは 3 言語目以降を
   追加できる形にするが、初版は 2 言語。

2. **外部 i18n ライブラリを採用せず、自前の軽量層を作る**。`lib/settings.ts` に `locale` を足し、その上に
   `t(key,vars)`／`useT()`／`<Trans>`／`Intl.PluralRules` 複数形を自作。根拠は (a) 既存が自前ストア/
   自前 Provider を貫く最小依存方針、(b) i18n を **React と非 React 双方**（`errText`/`wording`/読み上げ）から
   呼ぶ必要があり `settings.ts` の二重消費と同型、(c) 複数形が要るのは約 25 箇所で `Intl.PluralRules` で足り、
   日付/数値/相対時刻は重複フォーマッタを `Intl` へ集約したい整理と相乗り。react-i18next はロケール状態が
   settings と二重化し橋渡しが要る点、FormatJS/Lingui は Vite ビルドへマクロ/プラグイン導入が要る点で見送り。

3. **ロケールの単一真実源は `settings.locale`**。`theme` を踏襲（localStorage＋`/api/env/ui-prefs` 同期、
   `applyLocale` を初回描画前に適用、`document.documentElement.lang` を実行時更新）。ただし `theme` と違い
   **端末ローカルにしない**（言語は人単位で全端末追従）。既定値は `navigator.language`（`ja*`→ja、他→en、
   未対応は ja フォールバック）。

4. **型でキー欠落を守る**。`ja` を正本に `type MsgKey = keyof typeof ja`、`en` は全キー網羅を型で強制。
   CI の `typecheck` が未翻訳キーを検出するので、ライブラリのツールに頼らない。

5. **日本語専用機能は翻訳せず locale ゲート**。TTS かな読み変換・なろう形式ルビ・縦書きは
   `locale==='ja'`（実質 `provider==='voicevox'`）で切替。IME 変換ガードは全ロケール維持。

6. **範囲はフロント UI＋バックエンドのユーザー向けエラー＋サーバ描画（ログイン/OAuth）ページ**。
   マップ済みコードは `ERR_TEXT` ロケール層のみ（backend 変更不要）。`workspace/agent/` の未コード化
   和文エラー約 47 個はコード化。ログイン/OAuth の Go 描画ページは React に乗らないので `Accept-Language`／
   ロケール cookie で別途多言語化。

7. **エージェント出力言語（`outputLanguage` 軸）は対象外**。タイトル自動提案の日本語固定・chat の
   日本語強制・各種 LLM プロンプトは表示でなくモデル挙動を決めるため、UI ロケール追随は今回入れない
   （将来別途検討）。
   → **一部を [0033](0033-stored-text-locale.ja.md) が上書き**。この除外は「モデルが読む文字列」に限る。
   会話データに保存されるが**利用者が読むためだけに我々が生成する文**（`role=="notice"` のカード）は
   表示文言であり、キー＋引数で保存して Console のカタログで訳す。docs/19 の「保存データは JA 統一」は撤回。

## 捨てた案

- **react-i18next**: 定番で低ブートストラップだが、ロケール状態が i18next 内に別在し `settings.ts` と
  二重化する。非 React からの `t()` も別経路になり、単一真実源が崩れる。
- **FormatJS(react-intl) / Lingui**: ICU ネイティブで強力だが、Vite ビルドにマクロ/抽出プラグインの
  導入が必要でセットアップが重い。今回の規模（複数形 約 25・2 言語）には過剰。
- **既定ロケールをブラウザ言語で英語に倒す**: 既存ユーザーは日本語話者中心のため、判定はしつつ
  未対応/不明は日本語フォールバックとし、既存挙動を壊さない。
