# 0092. モデルカタログは居場所を保ち、行から「他の版・他のサイズ」を開く

[English](0092-catalogue-memory-and-other-editions.md) | 日本語

- Status: **accepted**（2026-09-19）。同じ変更で実装済み。
- [0085](0085-model-ledger-and-one-press-ingest.ja.md)（カタログは 2 つの面を持つペイン）と
  [0089](0089-quantisation-ladder-and-fit.ja.md)（サイズの梯子）を延長する。どちらの決定も
  改めない——ペインが何を見せるか、梯子が何を値付けするかはそのまま。変わるのは、ペインが
  「離れても生き残る」ことと、梯子が「一部の行にしか付かない見出し」ではなく**行**から
  開けることだ。

## 背景

同じ画面について、2 つの訴えが一緒に届いた。

**別のものを見た瞬間、カタログが全部忘れる。** タブ表示のセルは選ばれたビューしか描かない
（`PaneHost` の `selectedView`）ので、タブを切り替えた瞬間に `EngineAddView` は丸ごと
アンマウントされる。検索結果・情報源・並び・族・登録済みの絞り込み・スクロール位置はすべて
React の state にしか無く、一緒に消える。戻ると再検索が走る——そしてここでの検索は Civitai や
Hugging Face への**上流リクエスト**で、相手は負荷を 503 で落とす。役割タブも同じ形で、
文章 ⇄ 画像 の往復のたびにページを捨てて訊き直していた。

**すでにカタログにあるモデルの、別の版を取り込む道が無い。** ADR 0089 はリポジトリの他の
量子化の梯子を作ったが、描く場所をグループの見出しにした。GGUF の行は `display_name` で
分類されるので、配布元のページをまだ読んでいない行は名前の無いグループに落ち、梯子に
永久に届かない。画像側にはそもそも梯子が無く、チェックポイントの**他のバージョン**は
`探す` タブでそのモデルを探し直すしかなかった。しかも登録済みの行が持っているのは
`civitai:<版 id>` だけで、その裏のモデル id は別の番号——Console は持っていない。

## 決定

### 決定 1 — ペインの状態はペインの外に置く

モジュールスコープの記憶（`catalogMemory.ts`）。鍵は ペイン × エンジン × 面 × 種別。
`探す` は情報源・並び・族・検索語・hits、`登録済み` は絞り込み・並び・開いている族チップ。
バケツの目録はエンジンごと、エンジン一覧は 1 枠。ブラウザのリロードで消える——これは
ファイルビュアーの `scrollMemory` と同じ寿命で、同じ理由による。

**レイアウトストアには置かない。** あれは geometry が動くたびに直列化して保存されるもので、
作例 URL 付きの hits 100 件を入れる場所ではない。ペインに書き戻すのは開いている**面**だけで、
これはリロードしたときに同じ面へ戻るため。

🔴 面だけ。`sameTarget` は engineAdd のペインを `engineKey` と `lora` で同定するので、役割タブや
model⇄lora をペインの content に書き戻すとペインの同一性が変わり、次の `openEngineAdd` が
2 枚目のカタログを隣に開く。

**値打ちは「ページがまた出ること」ではなく「戻るのに何も要らないこと」。** 復元したときは
マウント時の検索を撃たない。ほかは全部そこから従う。

### 決定 2 — それぞれの一覧がそれぞれの居場所を持ち、新しい問いは先頭から

スクロール位置は、記憶の鍵＋そのページが答えている**問い**（確定した検索語・情報源・並び・族）
で綴じる。仕組みはビュアーの既存の `useScrollMemory`。同じ一覧に戻れば位置が戻り、文章と画像は
別の鍵なのでそれぞれの位置が戻り、違う問いを投げれば先頭から。先頭に戻すのは自前で書いた——
記録が無いときにスクロール記憶が何もしないのは正しい挙動で、放っておくと誰も読んでいない
一覧の途中に箱が留まるからだ。

🔴 復元したページで、末尾が勝手に次を取りに行ってはならない。復元位置は末尾に着地し、
sentinel は誰が何をするより先に画面に入り、`IntersectionObserver` はこの決定が避けるために
ある上流リクエストをそこで撃つ。だから人が一度触るまで観測を止める。手動ボタンは常にある。

### 決定 3 — 他の版は、行から、その行の語彙で

登録済みカードにボタンを 1 つ、押すとモーダル。行が「読める配布元」を記録しているときだけ出す。

- 出所が `hf:<owner>/<repo>/<file>` の **GGUF** の行には、ADR 0089 のリポジトリの他の量子化の
  梯子。どの行からも届くようになったので、見出しでは拾えなかった名前の無い行からも開ける。
  文章の **LoRA** は外す——アダプタは学習元のモデルで分類されるもので、梯子は持っていない
  KV キャッシュを値付けしてしまう。
- 出所が `civitai:<版 id>` の **画像**の行には、そのモデルの他のバージョン。

どちらも最後は普段の計画カードに着く。ライセンスと値段は、昔からそれを見せてきた 1 枚の画面で
見る。取り込みへの 2 本目の道は作らない。

🔴 版からモデルを解決するのは CP。行が持つのは版 id だけで、`/api/v1/models/<id>` にはモデル id
が要る。そこで `POST …/ingest/versions` は `model_ref` の無い Civitai の `ref` を受け付け、版の
ドキュメント（`engineReadCivitai`＝取り込みが元から使っている読み手）からモデルを読み、
解決した `model_ref` を版一覧と一緒に返す。Console 側にあった回避策——モデル id が無いときに
1 件だけの版一覧を作る——は**フォールバックとして残さず消す**。版のドキュメントは次に
`ingest/files` が読むものと同じなので、フォールバックは失敗を 1 押しぶん先送りするだけで、
どの上流が断ったのかを隠す。

### 決定 4 — 別の版を取り込むのは**行が増える**こと。行は書き換えない

id は起動メニュー・有効集合・あらゆる S3 パスが書かれている鍵（ADR 0088）なので、新しい版は
新しい行として入り、入れ替えはカードに元からある 2 押し——新しい行で「これで起動する」、
古い行で「登録を消す」。モーダルはそれを 1 行で言う。取引的な「差し替え」は意図して作らない:
CP に順序を保証する仕組みが無く、途中で落ちれば誰も起動できないカタログが残る。

### 決定 5 — 部品行は右端でサイズと配布元を言い、バッジは困っている部品にだけ付く

カードが 560px を切ると部品行は 4 段に折れ、サイズとリンクが、属しているはずのフラグから
離れて散っていた。行を flag / key / meta の 3 つにして meta を右端に固定し、狭いときに折るのは
key だけにする。

`present` の部品から「あり」バッジを外した。カードの見出しが既に「保存先: 3/3 ファイルあり」と
数えており、同じ事実をファイルの数だけ繰り返していた。不足・取り込み失敗・取り込み中・未確認は
残す——そうするとバッジは「この行は手が要る」の印になる。とくに未確認は、バケツを読めなかった
ときの全行の状態なので、消してはならない。

## 実測したこと

| 主張 | 方法 |
|---|---|
| タブ切替でカタログはアンマウントされ、戻ると再検索する | ヘッドレス Chromium、ビュー 2 枚のタブ表示セル。記憶を無効にすると 2 回目の `ingest/search` が出る（Expected 1 / Received 2） |
| 復元したページはスクロール位置ごと戻る | 同じ実行で、往復の前後に scrollTop を読んだ |
| 末尾に復元すると sentinel が即発火する | `CatalogMore` の番人は件数単位で、再マウントで戻る |
| paneId 無しだと dom テストが 1 つの記憶を共有する | 既存 20 ケースが赤になり、`afterEach` に `clearCatalogMemory()` を足して戻した |
| 情報源を添えない Civitai リンクは HF のリポジトリ名として解釈される | `IngestPlanDialog` は `hit` と `initialSource` からしか情報源を決めない |
| Civitai のモデル文書は版ごとのファイルサイズを持つ | `modelVersions[].files[].sizeKB` から読む。一覧が持たない版は 0 を返し、「サイズ未取得」と描く——収まり判定は出さない |
