## 背景

ファイルツリーから単一のファイルはダウンロードできる（`api/fs/download`）が、フォルダ丸ごとは 1 ファイルずつに
なる。ファイルツリーと画像ギャラリーのフォルダメニューには、その項目が無かった。

フォルダの書き出しは 1 ファイルのダウンロードとは別物である。1 回のリクエストで**数に上限の無い
ファイルを読む最初の口**なので、あらゆる軸で上限を持たねばならない。走査は不可分ではないので、
**「成功した」アーカイブが何を約束するか**を言わねばならない。そして、ファイル単位のダウンロードの防御
（`openat2` の `RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS`、`fs_fd_linux.go`）は 1 ファイルずつのものだが、
`GET /fs/images` は素の `os.Open` で歩き、シンボリックリンクも一覧作成時に飛ばすだけである
（`fs_images.go`）。名前の一覧にはそれで足りるが、バイトを読むには足りない。

## 決定

### 1. アーカイブは先に一時ファイルへ作り、`http.ServeContent` で返す

`GET /fs/download-zip?path=<フォルダ>` は走査し、**リンクを外した一時ファイル**へ `zip.Store` のアーカイブを
作り、それを返す。失敗——上限、受け付けられない名前、走査中に変わったファイル——は、**本文の最初の 1 バイトの前**に
素の JSON エラーになり、成功には `Content-Length` が付く。ストリーミングだと、200 を出した後で
「終わったように見える途中までの zip」と「切れた接続」のどちらかを選ばねばならない。しかも
`control-plane/proxy.go` は本文を `io.Copy` で中継してそのエラーを捨てるので、Agent が切れても
普通の終わりに見えうる。`Content-Length` を宣言しておけばブラウザは短い本文を見てダウンロードを失敗にする
（`TestFSDownloadZipCutUpstreamIsAnErrorNotAShortArchive` が固定）。

- **置き場所。** `<AgentStateDir>/zip-export/`（`~/.local/state/agent-fleet`）。どの実行基盤でもホームの
  ボリュームで、`/tmp` ではない（ecs-ec2 では tmpfs、kubernetes では容量制限付きの `emptyDir`——
  `docs/build/07-security.md` §7.2）。閲覧の拒否リストの下にあるので、作成中のアーカイブ自体を
  ダウンロードすることはできない。モードは 0700。
- **後片付け。** 作った直後にリンクを外すので、どの戻り経路でも、またそれ以降のクラッシュでも、
  記述子を閉じれば（プロセスが死ねば）容量は戻る。クラッシュが残しうる唯一の隙間（作成からリンク外しまでの間）には、
  作成の前に `zip-*` を掃除する処理を、下のスロットを持った状態で走らせる。
- **容量。** ペイロード上限に、名前・エントリ数の上限が抑えるエントリの付加分を足したもの（`zipOutputCap`）。
  それを超える書き込みはビルドを 413 で止め、`ENOSPC` は 507。
- **Range。** リクエストごとにアーカイブを作り直すので、あるアーカイブのバイト範囲は次のアーカイブの
  範囲ではない。`ServeContent` の前に `Range` と `If-Range` を捨て、検証子（`ETag`・`Last-Modified`）も
  出さないので、ブラウザが別のバイト列に対して再開することはできない。
- **`Content-Type: application/zip`**、`Cache-Control: private, no-store`、`Content-Disposition` は
  ASCII の `filename=` の代替と `filename*=UTF-8''…` の両方。
- **圧縮はしない**（`zip.Store`）。画像や既存のアーカイブは再圧縮が効かず、上限を考えるべき圧縮
  ワーカーも無い。

### 2. 開くのは信頼するルート fd の配下だけ

ルート fd は閲覧ルート（その下の絶対パスならスクラッチ／配布ドキュメントのルート）を `O_NOFOLLOW` で
開いたもの。開始フォルダ・各子フォルダ・各ファイルは、そこからの相対で
`openat2(RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS)` を使い、**使う瞬間に**開く。走査の後でパスが
シンボリックリンクにすり替わっても、リンク越しに読まず、開くのに失敗する
（`TestZipSwapAfterWalk…`、すり替え 5 通り）。

- **開始パスの途中（最後の要素を含む）にあるシンボリックリンク**は断る: 400 `symlink_not_allowed`。
  利用者のために別名を解決することはしない。
- **フォルダ内のシンボリックリンクと特殊ファイル**（FIFO・ソケット・デバイス）は含めず、**数える**。
  チェックがその数を返す。FIFO は決して開かないので、走査を止められない。
- **`.codex/generated_images` の 1 枚だけの例外は引き継がない。** パスの解決は専用
  （`resolveZipRoot`）で `resolveFDReadPath` ではない。あの例外は、知らされた 1 枚の画像を読むための
  ものであり、非公開の状態ツリーを列挙してよいという許可ではない。該当するパスは 403 `denied`。
- **拒否リストは子ごとの閲覧ルート相対パスで当て、降りる前に刈る**（`.local` は書き出せるが
  `.local/share/agent-fleet` は入らない）。開始パス自身も検査する。シンボリックリンクを一切たどらないので、
  閲覧ルート相対の綴りがそのまま実体であり、一覧のために `imagesDenyBase` が解いている別名の問題は起きない。
- **ルートそのものは書き出せない**（閲覧ルート・スクラッチのルート・配布ドキュメントのルート）: 400。
  「ホームを丸ごと」はメニューを押した意図ではまずなく、必ず上限に当たる唯一のリクエストである。
  スクラッチや配布ドキュメントの**中の**フォルダは可（読み取り専用のルートで、拒否リストは無い）。

### 3. アーカイブに入るもの

- エントリ名は `<フォルダ>/…`。最上位が 1 フォルダなので、展開してもカレントに散らばらない。エントリ名は
  `/` 区切りの相対パス。
- 空のフォルダは残す（`name/` のエントリ）。ファイルの種類は問わず、隠しファイルも含め、ギャラリーの
  画像フィルタとは無関係。
- 権限ビット（`& 0777`）と更新時刻は残す。それ以外（所有者・xattr）は残さない。
- **開始フォルダの下の `.git` と `node_modules` は、深さを問わず名前で除く。** 開始フォルダ**自身**が
  それなら、利用者が名指ししたものなので全部書き出す。チェックは実際に除いた名前を返し、項目の
  ツールチップが押す前にそれを言う。
- 閲覧ルート配下の拒否リストのフォルダも除く（同じ一覧に出る）。
- **保存できない名前は書き出し全体を 422 `unsafe_name` で失敗させ**、該当の名前を挙げる。不正な UTF-8、
  バックスラッシュ、制御文字、空・`.`・`..` の要素、絶対パス、先頭のドライブ指定（`C:`）、重複。
  別の名前に書き換えることも、黙って落とすこともしない——どちらも利用者が頼んだ内容を黙って変えるからである。
  （名前の途中のコロンは正当でよくあるので、そのまま残す。）

### 4. 「成功」が約束するもの：スナップショットではなく、決して欠けない

走査のサイズは一覧時点の値で、早めに断るための最適化にすぎない。ビルドは各ファイルを、順番が来た時に 1 回だけ読む。

| 走査の後に起きたこと | 結果 |
|---|---|
| ファイルが大きくなる | 読んだバイトを詰める。**バイト上限は読んだバイトで数え**、超えれば 413 |
| ファイルが小さくなる | 読んだバイトを詰める |
| 別の通常ファイルに置き換わる | 新しいファイルのバイトを詰める |
| ファイルやフォルダが消える、またはリンク・FIFO・フォルダに変わる | 409 `changed_during_zip`（「もう一度」） |
| ファイルが読めない（`EACCES`・I/O エラー） | リクエスト全体を 403 `denied` / 500 `read_failed` で失敗 |

したがってアーカイブは**ある時点のスナップショットではなく**（ファイルごとに時刻が違い、書き込み中のファイルは
途中で取れうる）、かつ**黙って短くなることも決してない**。選ばれたものは入るか、リクエストが失敗するかのどちらか。
決定 3 の明記した除外だけが、入らないものである。

### 5. あらゆる軸に上限を置き、リクエスト全体でスロットを 1 つ持つ

| 上限 | 値 | 超えると |
|---|---|---|
| ファイル数 | 20 000 | 413 |
| フォルダ数 | 4 000 | 413 |
| 深さ | 32 | 413 |
| 見たエントリ数（入れても除いても） | 100 000 | 413 |
| エントリ名のバイト数の合計 | 4 MiB | 413 |
| 読んだバイト数 | 512 MiB | 413 |
| 書いたバイト数（ペイロード上限＋付加分） | 導出 | 413 |
| 走査＋ビルドの時間 | 45 秒 | 413 |
| 転送の時間 | 15 分（書き込み期限） | 接続を閉じる |
| 同時に作れる数（Agent 全体） | 1（2 秒待つ） | 503 `zip_busy` |

2026-10-07 に Workspace のウォームなローカルディスクで測った（Go テストの走査であって、配備ではない）:
1 KiB × 20 000 ファイルのチェックが 0.2 秒、その 23 MB のアーカイブの作成が 0.8 秒、300 MiB の 1 ファイルが
1.2 秒。上限はこの場合ではなく、冷えたネットワークストレージのために置いた。**冷えた EFS や EBS が
45 秒にどこまで近づくかは測っていない**。45 秒は ALB のアイドルタイムアウト 60 秒より短い。ビルドは終わるまで無言で、ALB が諦める前に最初の
1 バイトが出ていなければならない。ディレクトリは 256 件ずつ読み、開いているディレクトリ fd は常に 1 つ、
コピーのバッファは 64 KiB 1 本。`zip.Writer` は全エントリの中央ディレクトリ情報をメモリに持つので、
その上限が 24 000 エントリである。上限を超えるフォルダは、上限の名前を挙げた 413 で断り、切り詰めはしない。

**スロットは走査の前に取り、転送と一時ファイルのクローズが終わってから返す**（`defer`）。遅いクライアントが
アーカイブを受け取っている最中こそ、2 つ目のビルドが積み上がってはならない場面だからである。2 秒以内に
スロットが取れなければ 503。待っている間に去ったクライアントは何も解放しない。転送の期限は
`http.ResponseController` で付けるが、これが接続に届くのは `httpx.Gzip` のラッパーが `Unwrap` を持つように
なったからである。

### 6. Console は先に確認し、そのあと素のアンカーでダウンロードする

素の `<a href download>` は 413・503・401・403・404 や停止中の Workspace を表示できず、fetch ベースの
セッション切れ通知も働かず、セッションが切れていればタブごとログインへ飛ばされうる。そこで 1 回の押下は:

1. `fetch` で `GET api/fs/download-zip?path=…&check=1`——同じ経路、同じ走査で、ビルドはしない。
   `{name, files, dirs, bytes, excluded[], skipped}` かエラーの封筒が返る。断られたら、ローカライズした
   `err.<code>` の文に、サーバーの詳細（どの上限か）を足したトーストにする。
2. 成功なら、`download` 付きの同一オリジンの非表示アンカーをクリックし、何が入って何を除いたかをトーストで言う。
   ブラウザがファイルをディスクへ直接ストリームし、Console が zip を Blob に読み込むことはない。

退けたもの: 「準備して、トークンで取りに行く」API（確認してからダウンロードするのと比べて得が無く、期限切れと
掃除を要するサーバー側の状態が増える）と、応答を Blob に読み込むこと（メモリを食い、ブラウザ自身の
ダウンロード管理に進捗が出ない）。確認とダウンロードの間にフォルダが大きくなる競合は、ブラウザ側では
ダウンロード失敗になり、短いアーカイブにはならない。確認は走査をもう 1 回要する（stat だけで、同じ上限）。
同じスロットを取る。

テナントは確認の前に取り、その URL を作る。確認の最中に切り替えられたら、結果は黙って捨てる。

### 7. タッチ：両方のフォルダ面に明示の長押しを置く

iOS Safari は素の要素の長押しで `contextmenu` を出さないので、ツリーのフォルダ行にもギャラリーのフォルダ
カードにも、タッチでメニューへ行く道が無かった。`useLongPressMenu`（`createLongPress` の上）が 500 ms で同じ
メニューを開き、10 px を超える移動・`touchend`・`touchcancel` で取り消し、マウスの `pointerdown` は無視し、
指を離した時のクリックを飲んで、押しただけでフォルダが開かないようにする。Android は同じ長押しに対して
ネイティブの `contextmenu` を出すことがあり、タッチ由来のものはクリックを飲む印を立て、マウスの右クリックは立てない。
「上へ」カードにはメニューも長押しも無い。配線したのはフォルダの行／カードだけで、ファイル行は変えない。

### 8. 監査：今は付けない

通常のファイルシステムの GET は監査しない（`control-plane/proxy.go`）。例外はメモリのエクスポートで、
個人のデータを環境の外へ持ち出すからである。フォルダの書き出しは、本人が自分の Workspace を、すべてのファイル読み取りと
同じセッションで丸ごと読むことで、Agent のアクセスログにはリクエストが既に残る。開始時か完了時に
記録を取りたいかは未決のままとする。状態行の下の **Follow-ups** を参照。

## 影響

- 上限以内のフォルダは、どちらの面からも、右クリック・メニューキー・タッチの長押しで `<フォルダ>.zip` として
  ダウンロードできる。どれかの上限を超えるフォルダは、黙って失敗せず、どの上限かを言う。
- Agent に経路が 1 つ増え、ホームのボリュームに 512 MiB 以内の一時ファイルが同時に 1 つだけできる。
  Control Plane には許可リストが 1 行増え、ほかのダウンロードと同じようにヘッダと本文を中継する。
- `httpx.Gzip` のライターは `Unwrap` できる。圧縮まわりはほかに変わらない（アーカイブは圧縮対象の内容ではない）。
- 除外は名前で、深さを問わない。`node_modules` という名のディレクトリに本物のソースを置くプロジェクトでは、
  そのディレクトリ自身を選ぶ必要がある。

## 未確認

トーストの流れ、メニュー項目、jsdom 上の長押しの状態遷移。

**実ブラウザ・iOS・Android では未確認**: `await` の後のアンカーのプログラムによるクリックがダウンロードとして
