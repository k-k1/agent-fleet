## 背景

セッションが 5〜6 本を超えると、左ペインの行では「どれが質問で止まっているか」「どれが動いているか」を
1 行ずつ読むことになる。行は幅 339px のレールに収まる分しか出せず（ADR 0061 決定 14〜16 の実測）、
状態チップはアイコン 1 個に畳まれている。「全部を一度に眺める面」は Console に無く、あるのは
管理者向けの表（`GET /api/admin/sessions`・テナント横断・5 秒ポーリング）だけで、これは読者が違う。

一方で必要な部品は揃っている。

- 行の状態導出 `stateInfo()`（`console/src/lib/sessionview.ts`）は「左ペインの行とペインヘッダが同じ
  描画になるように」共有されている。
- 右クリックメニュー `SessionMenu.tsx` は「セッションが出る場所すべてで同じ項目を出す」ために
  行から切り出され、タブ付きグリッドのタブでも使われている。
- セッション store は SSE と 4 秒ポーリングで常に新しい。

## 決定

### 決定 1 — 新しいペイン種別 `sessions` として作る（モーダルにしない）

`PaneContent` に `{ kind: "sessions"; showStopped: boolean }` を足す。

- **なぜペインか。** 眺めて監視する面は「開いている間ほかの作業ができない」モーダルに合わない。
  ペインなら分割・タブ・ポップアウト・レイアウト永続化・スマホの 1 ペイン表示が**すべて既存の
  仕組みで付く**。列数が「ペインの幅」で決まる（決定 4）のもペインだからである。
- **0049 決定 4 との関係。** 0049 は「既存のペインに帯を足せる時は種別を増やさない」であって、
  「種別を増やさない」ではない。本ビューは載せる先の既存ペインが無い。
- 種別追加の定型 8 か所（union・保存形式の検証・同一判定・描画 switch・タイトル・ミニマップ略号・
  ポップアウト可否・i18n）を全部踏む。**検証（`migrate.ts`）を忘れると再読み込みで空ターミナルに
  化ける**——共有セッション種別を足したときと同じ手順。
- `showStopped` は React state でなく**ペインの内容に持つ**。タブ切替でこのビューは unmount
  されるので、state に置くと切替のたびに戻って壊れて見える。同一判定は種別だけで行い、
  レイアウトに一覧は 1 つ（トグルが違っても同じ一覧）。

### 決定 2 — 既定は稼働中のみ。停止中はペインごとのトグルで足す

「稼働中を一望する」が目的なので、停止行は既定で出さない。トグルで足したときは薄く描く。
停止中を常に混ぜると、10 本の停止と 3 本の稼働が同じ重みで並び、見たいものが埋まる。

### 決定 3 — カードは**隣のペインに**開く。自分を置き換えない

行のクリックは `openSessionFromList(s, split, running)`（行とパレットの唯一の入口）に流し、
**split は常に true**。一覧は眺めているものであり、クリックで消えたら「戻る」が要る。
既に開いているペインがあればそれをフォーカスし（`sameTarget` の重複排除）、タブ表示では
同じセルの新しいタブになる。Ctrl／中クリックも同じ（区別する理由が無い）。

### 決定 4 — 列は CSS Grid の `auto-fill, minmax(240px, 1fr)`。狭幅はコンテナクエリ

- flex-wrap でも幅追従はできるが、最終行のカードが伸びて「そのセッションだけ大きい」に読める。
  Grid の auto-fill は行内の幅が揃い、最終行も伸びない。
- 狭幅の折り畳み（トグルの文言を消す）は `@media` でなく `@container paneview`。ポップアウトした
  タブは窓幅と無関係に狭く、側の列に置いたペインは広い窓でも狭い。コンテナはビューの根に自分で宣言する
  （ミラーと端末も自分の根に宣言している）。

### 決定 5 — 状態は `stateInfo()` の第 3 の消費者。導出を複製しない

カードの状態チップ・色クラス・種別アイコンは行とペインヘッダと同じ helper から引く。
カードは幅があるので、行では畳んでいる文言（「進行中…」「入力待ち」）を**畳まずに出す**。
枠色は「今この人が要る」状態（質問・プラン・許可）だけ暖色にし、チップの色と一致させる。

### 決定 6 — 並び順は「待ち → 稼働 → 停止」の段だけ。段の中は新しい順で固定

パレットの `sortSessionsByAttention` をそのまま使うが、段内の「いつ待ちに入ったか」の台帳
（`waiting.ts`——「パレットの並び以外に使うな」と明記されている）は**渡さない**。
パレットは開いた瞬間に順序を凍結できるが、一覧は開きっぱなしで、質問に答えるたびに
カードが席を替えると眺められない。段を跨ぐ移動（質問が来た・答えた）だけが、
見に行く先を教える価値のある移動である。

### 決定 7 — 操作は `SessionMenu` を借りる。項目を 1 つも複製しない

右クリック・⋯ ボタン・Menu キー／Shift+F10 の 3 経路で同じ `SessionMenu` を開く。
配置だけが呼び手の責任（カーソル位置 or ⋯ の直下）で、それはタブと行が既にやっている 2 通り。
`useSessionActions()` はコンテナで 1 回だけ呼ぶ（ProjectTree と同じ）。

### 決定 8 — 入口は 3 つ。操作バーのボタン・レール上部のレイアウト図・リーダー `g s`

レイアウト図（`LayoutMap`）はペインが 1 つのとき**自分を隠す**ので、そこだけに置くと
「一覧を開きたい」という最も普通の場面で入口が無い（実装中に気づいた）。操作バーの
「右に分割／下に分割／全て閉じる」の並びに置く——一覧はペインである。

## 却下した案

- **モーダル**（掃除／アーカイブと同型）: 安いが監視用途に合わない（決定 1）。
- **左ペインを広げてカード化**: 撤回済みの左ペイン IA と衝突する。レールは行、面は右。
- **flex-wrap**: 最終行が伸びる（決定 4）。
- **「最後の発話」「最終更新時刻」を v1 に出す**: DTO に無い。転写は mirror 経由で重く、
  Agent 側で 1 行要約を DTO に足すには CP の中継 4 か所に足さねばならず（`sessionWire` に無い
  フィールドは黙って落ちる・docs/94 §94.10）、P1 に送る。
- **待ち時刻の台帳で段内も並べ替える**: 決定 6。
- **フリート俯瞰図（相関図）と兼ねる**: ADR 0027 が別タスクに送り 0041 決定 9 が必要性を確定した
  「会話 × セッション × メッセージの相関図」は**別物**である。本ビューはカードの一覧であり、
  系譜は左スパインの色（ADR 0073）で示すにとどめる。相関図の要否はこの ADR で変えない。

## 影響

- Console のみ。サーバ変更ゼロ、追加のポーリングもゼロ。
- 触った箇所: `layout/{types,migrate,ops}.ts`・`features/panes/{Pane,LayoutMap,paneTitle}`・
  `features/overview/`（新規: ビュー・カード・純関数・CSS・opener）・`app/WsBar.tsx`・
  `features/keys/commands.ts`・i18n（ja/en）。
- 試験: 純関数（絞り込み・段・安定性）と DOM（隣に開く／メニュー 3 経路／dead は開かない）。
  見た目は headless Chromium と README 用スタブで実測（docs/96）。
