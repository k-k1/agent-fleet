## 背景

セッションが 5〜6 本を超えると、左ペインの行では「どれが質問で止まっているか」「どれが動いているか」を
1 行ずつ読むことになる。行は幅 339px のレールに収まる分しか出せず（ADR 0061 決定 14〜16 の実測）、
状態チップはアイコン 1 個に畳まれている。「全部を一度に眺める面」は Console に無く、あるのは
管理者向けの表（`GET /api/admin/sessions`・テナント横断・5 秒ポーリング）だけで、これは読者が違う。

一方で必要な部品は揃っている。

- 行の状態導出 `stateInfo()`（`console/src/lib/sessionview.ts`）は「左ペインの行とペインヘッダが同じ
  描画になるように」共有されている。
- 右クリックメニュー `SessionMenu.tsx` は「セッションが出る場所すべてで同じ項目を出す」ために
  行から切り出され、タブ付きグリッドのタブでも使われている。
- セッション store は SSE と 4 秒ポーリングで常に新しい。

## 決定

### 決定 1 — 新しいペイン種別 `sessions` として作る（モーダルにしない）

`PaneContent` に `{ kind: "sessions"; showStopped: boolean }` を足す。

- **なぜペインか。** 眺めて監視する面は「開いている間ほかの作業ができない」モーダルに合わない。
  ペインなら分割・タブ・ポップアウト・レイアウト永続化・スマホの 1 ペイン表示が**すべて既存の
  仕組みで付く**。列数が「ペインの幅」で決まる（決定 4）のもペインだからである。
- **0049 決定 4 との関係。** 0049 は「既存のペインに帯を足せる時は種別を増やさない」であって、
  「種別を増やさない」ではない。本ビューは載せる先の既存ペインが無い。
- 種別追加の定型 8 か所（union・保存形式の検証・同一判定・描画 switch・タイトル・ミニマップ略号・
  ポップアウト可否・i18n）を全部踏む。**検証（`migrate.ts`）を忘れると再読み込みで空ターミナルに
  化ける**——共有セッション種別を足したときと同じ手順。
- `showStopped` は React state でなく**ペインの内容に持つ**。タブ切替でこのビューは unmount
  されるので、state に置くと切替のたびに戻って壊れて見える。同一判定は種別だけで行い、
  レイアウトに一覧は 1 つ（トグルが違っても同じ一覧）。

### 決定 2 — 既定は稼働中のみ。停止中はペインごとのトグルで足す

「稼働中を一望する」が目的なので、停止行は既定で出さない。トグルで足したときは薄く描く。
停止中を常に混ぜると、10 本の停止と 3 本の稼働が同じ重みで並び、見たいものが埋まる。

### 決定 3 — カードは**隣のペインに**開く。ただし隣が無いスマホでは**このペインに**開く

行のクリックは `openSessionFromList(s, split, running)`（行とパレットの唯一の入口）に流す。
`split` は「隣に余地があるか」で決める。一覧は眺めているものであり、広い画面で
クリックのたびに消えたら「戻る」が要るからである。

- **広い画面**: 素のクリック＝隣に開く（`split=true`）。一覧はそのまま残る。
- **スマホ**（`max-width: 760px`・`lib/device.ts` の `MOBILE_QUERY`）: 隣が無い。
  `openInNew` はスマホでは列を上下 2 段に割るので、**半分の高さのペインが 2 枚**できる——
  電話でいちばん見たくない形である。素のタップは**このペインに開き**、一覧へは
  **端末の戻るボタン**で戻る。レイアウトの commit は history に push しているので
  （`layout/store.ts`）、戻ると一覧のあるスナップショットが復元される。`showStopped` は
  ペインの内容に入っている（決定 1）ので、トグルの状態も一緒に戻る。
- **Ctrl／⌘／中クリックは画面幅によらず「別のペインで開く」**。Console 全体の慣習
  （左レールの行・リポジトリ行・チャット）と同じ意味を保つ。デスクトップでは素のクリックと
  同じ結果になるが、修飾キーの意味が画面幅で反転しないほうが覚えやすい。
- **タブ表示では分岐しない。** `openInTab` が `split` の真偽を潰して「同じセルの新しいタブ」に
  するので、タブ表示ではスマホでも既に「全画面で開き、一覧はタブとして 1 つ隣に残る」に
  なっている。カードが見るのは画面幅だけで、レイアウトのモードは `layout/ops.ts` が吸収する。
- 既に開いているペインがあればそれをフォーカスする（`sameTarget` の重複排除）。

### 決定 4 — 列は CSS Grid の `auto-fill, minmax(240px, 1fr)`。狭幅はコンテナクエリ

- flex-wrap でも幅追従はできるが、最終行のカードが伸びて「そのセッションだけ大きい」に読める。
  Grid の auto-fill は行内の幅が揃い、最終行も伸びない。
- 狭幅の折り畳み（トグルの文言を消す）は `@media` でなく `@container paneview`。ポップアウトした
  タブは窓幅と無関係に狭く、側の列に置いたペインは広い窓でも狭い。コンテナはビューの根に自分で宣言する
  （ミラーと端末も自分の根に宣言している）。

### 決定 5 — 状態は `stateInfo()` の第 3 の消費者。導出を複製しない

カードの状態チップ・色クラス・種別アイコンは行とペインヘッダと同じ helper から引く。
カードは幅があるので、行では畳んでいる文言（「進行中…」「入力待ち」）を**畳まずに出す**。
枠色は「今この人が要る」状態（質問・プラン・許可）だけ暖色にし、チップの色と一致させる。

### 決定 6 — 段は**家系単位**で決め、家系の中は親 → 子（2026-09-12 改訂）

当初は「待ち → 稼働 → 停止」の段をカード単位で付け、段内は新しい順に固定していた。
利用者の要求「親子関係のあるセッションは親→子の順番に並べたい（停止中も）」はこれと両立しない
——子が質問に入った瞬間、子だけが段を上がって親から離れる。

改めた規則（`features/overview/overview.ts` の `orderByFamily`）:

- **段は家系（`originSession` で繋がる木）に付ける。** 家系の段＝構成員の最小段。
  待ちを抱えた家系がグループの先頭に来て、**家系は決して割れない**。
- **家系の中は親 → 子**の深さ優先。兄弟は**古い順**（家系の中では並び順＝生成順で、
  新しい子は末尾に足される）。根は**新しい順**（根同士は別々の仕事で、そこは一覧が
  最初から採ってきた順）。
- **停止中の子も親の直下に並ぶ。** 「停止中も表示」が消えているときに出ないだけで、
  段によって親から引き離されることはない。停止の出し入れは決定 2 のトグルの仕事である。
- 段内の「いつ待ちに入ったか」の台帳（`waiting.ts`——「パレットの並び以外に使うな」）は
  **並びには渡さない**（決定 11 で表示にだけ使う）。パレットは開いた瞬間に順序を凍結できるが、
  一覧は開きっぱなしで、質問に答えるたびにカードが席を替えると眺められない。
- 親がこのグリッドに居ない子（別リポジトリで起こされた・親が削除された）は**その場の根**。
  グリッドは 1 枚のカードを 2 つの見出しに出せない。血縁は左の系譜色（ADR 0073）が示す。

### 決定 7 — 操作は `SessionMenu` を借りる。項目を 1 つも複製しない

右クリック・⋯ ボタン・Menu キー／Shift+F10 の 3 経路で同じ `SessionMenu` を開く。
配置だけが呼び手の責任（カーソル位置 or ⋯ の直下）で、それはタブと行が既にやっている 2 通り。
`useSessionActions()` はコンテナで 1 回だけ呼ぶ（ProjectTree と同じ）。

### 決定 8 — 入口は 3 つ。操作バーのボタン・レール上部のレイアウト図・リーダー `g s`

レイアウト図（`LayoutMap`）はペインが 1 つのとき**自分を隠す**ので、そこだけに置くと
「一覧を開きたい」という最も普通の場面で入口が無い（実装中に気づいた）。操作バーの
「右に分割／下に分割／全て閉じる」の並びに置く——一覧はペインである。

### 決定 9 — 見出しは**リポジトリ**。同一性は remote で取り、フォルダ名では取らない（2026-09-12 追加）

カードはプロジェクトごとの見出しに分かれる。同一性は **`remote`（ホスト）＋ `remotePath`
（`owner/name`）**で、フォルダ名ではない。

- **フォルダ名は利用者のもの**である。1 つのリポジトリが `app` と `app-review` として 2 回
  clone されることがあり、`app@wip-*` の worktree はさらに別のフォルダになる。
  「同じプロジェクト」を名前から言い当てることはできない。
- そのため Agent の `GET /api/repos` に **`remotePath` を足した**（`gitx.gitRemotePath`——
  origin URL のホストより後ろ、認証情報と `.git` を落としたもの）。`remote` は
  「ホストのみ・path/token は載せない」と明記されていたので、**path を載せるのはその決定の
  変更**である。資格情報は落とす（scp 形式の `git@` は `SSHToHTTPS` が、残る `user:pass@` は
  ホストと一緒に切る）。CP は `GET /api/repos` を素通しするので中継の追加はいらない。
- **remote が無い作業コピー**（ローカルだけの git、SVN）は**ベースの作業コピー名**で束ねる
  （worktree は親の名前へ）。作業コピーに属さないセッション（home の shell など）は
  末尾の「その他」見出し——レールのツリーと同じ置き場所。
- 見出しの順は**名前順で固定**。待ちを抱えたプロジェクトを上げることはしない：見出しごと
  動くと「さっきまで上から 2 つ目だった箱」が毎回変わる。どこへ行くべきかは決定 6 の
  家系の段と枠の暖色が示す。

### 決定 10 — カードの右上は状態、ブランチの右は親との差分（2026-09-12 追加）

- **状態チップは見出し行の右端**（タイトルの右・⋯ の左）。カードのグリッドでは視線がまず
  右上に行く。専用の行を 1 本畳めるので、1 列表示でもカードが背伸びしない。チップが縮む
  ことはなく、幅が足りなければ**タイトルが先に省略される**（どのセッションかは下の行から
  読めるが、半分描かれた状態は読めない）。
- **worktree の「親との差分」はブランチの右**に、レールのリポジトリ行と**同じチップ・同じ
  文言**で出す（`features/repos/parentSync.ts` の `parentSyncLabel` / `parentSyncTitle`——
  この決定のために `RepoRow` から切り出した）。同じ Console で「親+2・FF可」が 2 通りの
  意味を持ってはいけない。
- 残りのバッジ（ロック・起こしたまま・自動停止の予約・共有）は**持っているカードだけ**の行に
  残す。普通のカードではその行ごと描かない。
- **ペイン序数のバッジは出さない**（利用者の指示・2026-09-12）。「どのペインで開いているか」は
  レールの行の仕事で、カードのグリッドでは数字が並ぶだけになる。開いていること自体は枠
  （`.open`）とホバーの相互強調で分かる。

### 決定 11 — 「待ち経過」は既存の 2 つの台帳から出す。無ければ**出さない**（2026-09-12 追加）

「最後に入力待ち／AUQ になってからの時間」を出すが、**DTO にその時刻は無い**（`Session` に
`updatedAt` も状態開始時刻も無い——決定時に確認済み）。パレットが使っている 2 つの台帳を
そのまま合成する（`waitingAtFromNotifications` と `observedWaitingAt` の max）:

- 通知台帳はサーバ側で `createdAt` を持ち、リロードや別端末でも残る。
- この端末の観測は、通知を出さない kind や保持期間を過ぎた待ちの穴を埋める。
- **どちらも知らないときは何も出さない。** 「0m」を捏造すると、答えるべき順序を嘘の数字で
  決めさせることになる。
- 待ち中は「待ち {d}」、答えた後は同じ時刻が「応答から {d}」＝あなたが答えてから動いている
  時間になる。**並び順には使わない**（決定 6）。
- 正確さが足りなければ **P1 で Agent に `waitingSince` を足す**（CP の `sessionWire` に無い
  フィールドは黙って落ちるので、足すのは 4 か所——docs/94 §94.10）。

### 決定 12 — カードの最下段に「エージェントが最後に言ったこと」を 1 行。切り詰めは Agent 側（2026-09-12 追加・P1①）

状態チップは「今なにをしているか」しか言わない。**何をしているのかはカードのどこにも無い**——
利用者が一覧から知りたいのは、まさにそこである。転写の末尾にある**最後のアシスタント発話**の
冒頭 1 行を、メタ行の**下**（カードの最下段）に出す。

- **出所は Agent。** `Session` DTO に最後の発話は無い（決定 11 と同じ確認）。claude の転写から
  `claude.TailFacts`（`tailfacts.go`）が作って DTO に載せ、CP の `sessionWire` を経て Console に
  届く。**中継に無い
  フィールドは黙って落ちる**ので、足したのは 4 か所（構造体・契約表・中継の往復試験・golden。
  docs/94 §94.10）。
- **切り詰めは Agent 側**（1 行化・空白の畳み込み・**120 文字**）。カードは幅がいくつでも
  1 行を省略記号で切るので、それ以上は**誰も読まない荷物を 4 秒ごとに全セッション分**運ぶことに
  なる。Console は受け取った文字列をそのまま描くだけで、加工も判断もしない。
- **ポーリングの代償を作らない**のがこの決定の中心である。読むのは転写の**末尾 1 窓**
  （`transcriptTailWindow` = 512 KiB）だけで、`lastLineWhere` のように**ファイル全体へ広げない**
  ——広げる実装は「codex の rollout を毎ポーリングで全部読み直していた」事件と同じ轍で、しかも
  1 ターンが大きなツール結果で窓を埋めることは珍しくない。加えて mtime のメモ（`ctxCache` と
  同じ作り）を持つので、変化の無い転写は **stat 1 回**で済む。
- **窓に発話が無いときは、直前に分かっていた行を保つ**（空にしない）。それは今も真である
  ——新しく言われたことは無い——し、長いターンの途中でカードが空になるのは「このセッションは
  黙った」と読める。
- **claude だけで始める。** 他 kind は空文字＝その行を**描かない**（場所も取らない）。
  転写の在処が kind ごとに違い、1 つずつ実測が要るため **P1.1** に送る。
- **停止中のカードにも出す。** 停止したセッションでは「最後に何を言ったか」が唯一の手がかりで、
  それが要るのは誰も開き直していないカードである。
- **表示専用。** ターンの境界も時刻も持たない答えの断片なので、並び順・状態・通知の判断に
  使ってはならない（決定 6・11 と同じ線引き）。
- **縦は 1 行だけ伸ばす**（実測 97px → 118px・+21px）。折り返しは禁止：セッションが喋った長さで
  カードが 2 行伸び縮みすると、グリッドの段が上下に跳ねる。狭さは**細い列（318px）と電話
  （376px）の 2 通り**で測った（決定 4 と §96.7 の区別）。グリッドの段は最も高いカードに揃うので、
  伸びるのは 1 枚ではなく**その段**である。

### 決定 13 — メタ行は「最後に答えたモデル」。コンテキストとトークンはミラーの部品をそのまま借りる（2026-09-12 追加・利用者の指示）

カードのメタ行から**種別の語を外し**、代わりに**最後に答えたモデル**を出す。コンテキストの
使用率は文字をやめ、**ミラーと同じ `ContextBar`**（ゲージ＋トークン消費のスパークライン）を
カードに載せる。

- **種別の語は要らない。** どのエージェントかは見出し行の**色付きの四角**が既に言っており、
  グリッドでは「Claude」という語が縦に並ぶだけだった。種別はアイコンの tooltip に残る。
- **「最後に答えたモデル」は `context.model`**（最新のアシスタントターンから読む）で、
  起動時に選んだ `model` ではない。会話の途中でモデルを変えたセッションは、一覧では
  **今そこで動いているもの**として読めなければならない。まだ 1 度も答えていない間だけ
  起動時のモデルに落ちる。
- **ゲージは `ContextBar` を借りる**——決定 5・7 と同じ理由である。「どれだけ埋まっているか」の
  計算がカードとチャットで 2 つあれば必ずずれる。カードが変えるのは**寸法だけ**で、
  ラベルは常に短縮形（`ctx` / `token`）、行は 2 段に折り返す（`overview.css`。カードは
  グリッドの下限が 240px なので**決して広くならない**——ペイン幅を見る
  `@container paneview` の折り畳みでは足りない）。
- **トークングラフの原資は DTO に無かった。** ミラーの spark は転写から作った
  ターンごとの消費で、一覧は転写を持たない。**Agent に `tokenSpends` を足した**（3 段目の
  中継 4 か所は決定 12 と同じ）。
- **1 点＝1 返答**。claude は 1 つの返答を「本文・各ツール呼び出し・続き」と**複数行**に書き、
  ミラーの `groupTurns` はその連なりを 1 ブロックに畳む。Agent 側も同じ畳み方をする
  （出力は合計・入力とキャッシュ作成は**最後の行**のもの・キャッシュ**読み**は消費ではない）。
  でなければ同じセッションのカードとチャットが別の形を描く。
- **窓に半分だけ入った返答は捨てる**（末尾 1 窓しか読まないため・決定 12）。切られた返答は
  「小さいターン」に見えてしまい、それは嘘である。点が 2 つ未満のときは既知の系列を保つ
  （ミラーの spark も 2 点未満では描かない）。
- **上限は 24 点**。カードのスパークラインは幅 120px 程度で、それ以上は見分けられない画素を
  セッション数 × 4 秒ごとに運ぶだけになる。
- **縦は 97px → 160px**（実測・3 通りの幅で同じ）。**一覧で見えるカードの枚数は減る**——
  電話では 1 画面 6〜7 枚が 4 枚になる。利用者の明示の指示による交換であり、
  ここに書き残しておく。

## 却下した案

- **モーダル**（掃除／アーカイブと同型）: 安いが監視用途に合わない（決定 1）。
- **左ペインを広げてカード化**: 撤回済みの左ペイン IA と衝突する。レールは行、面は右。
- **flex-wrap**: 最終行が伸びる（決定 4）。
- **「最後の発話」「最終更新時刻」を v1 に出す**: DTO に無い。転写は mirror 経由で重く、
  Agent 側で 1 行要約を DTO に足すには CP の中継 4 か所に足さねばならず（`sessionWire` に無い
  フィールドは黙って落ちる・docs/94 §94.10）、P1 に送る（→ 決定 12 で実装）。
- **最後の一言を Console 側で切り詰める**: 運ぶ量が変わらない。カードは 1 行しか出さないので、
  切るのは**運ぶ前**でなければ意味がない（決定 12）。
- **最後の一言を 2 行に折り返す**: 喋った長さでカードが伸び縮みし、グリッドの段が跳ねる。
  1 行・省略記号で固定した（決定 12）。
- **コンテキストを文字（「コンテキスト 12%」）のままにする**: 初版はカードに段付きバーの幅が
  無いと判断していたが、実測すると 274px でも収まる。利用者の指示で `ContextBar` に替えた
  （決定 13）。
- **カード用にゲージを自前で描く**: 「どれだけ埋まっているか」の計算が 2 つになり、必ずずれる
  （決定 5・7 と同じ理由・決定 13）。
- **トークングラフを Console 側で転写から作る**: 一覧は転写を持たない。カードごとに
  `/messages` を叩けば 4 秒ポーリング × セッション数になる——本 ADR が最も避けている形
  （決定 13）。
- **`tokenSpends` を転写行ごとに 1 点にする**: 素朴だが、ミラーは連なりを 1 ブロックに畳むので
  同じ会話が 2 通りの形で描かれる（決定 13）。
- **直近のツール実行（「編集中: foo.ts」）／待ち中の質問文**（P1 の②③）: 利用者が①を選んだ。
  ②は「何をしているか」をより直接に言うが、転写の末尾がツール列のときだけ埋まり、
  ①と競合する（同じ 1 行を奪い合う）。両方の実測が済んでから決める。
- **待ち時刻の台帳で段内も並べ替える**: 決定 6（表示にだけ使う・決定 11）。
- **フォルダ名でプロジェクトを束ねる**: 名前は利用者のもので、同じリポジトリの 2 つ目の clone を
  別プロジェクトに割ってしまう（決定 9）。
- **待ちを抱えたプロジェクトの見出しを上へ**: 見出しごと動くと箱の位置が毎回変わる（決定 9）。
- **待ち時刻を「0m」で埋める**: 台帳が知らないことを数字にすると、順序の判断が嘘に乗る（決定 11）。
- **フリート俯瞰図（相関図）と兼ねる**: ADR 0027 が別タスクに送り 0041 決定 9 が必要性を確定した
  「会話 × セッション × メッセージの相関図」は**別物**である。本ビューはカードの一覧であり、
  系譜は左スパインの色（ADR 0073）で示すにとどめる。相関図の要否はこの ADR で変えない。

## 影響

- ほぼ Console のみ。**Agent は 1 フィールド**（`gitx.Repo.RemotePath`・決定 9）で、
  CP は `GET /api/repos` を素通しするため中継の追加はゼロ。追加のポーリングもゼロ。
- **決定 12・13 が 3 段を通る**（Agent → CP → Console）。Agent は `session.Session.LastSay` と
  `TokenSpends`、`claude.TailFacts`（新規 `tailfacts.go`）、CP は `sessionWire` の 2 フィールド
  （＋契約表・往復試験・golden）、Console は型 2 つとカードの 2 行。**追加のポーリングはここでも
  ゼロ**——既存のセッション一覧（4 秒）に相乗りし、2 つの事実は**転写末尾の 1 回の走査**から
  一緒に出る。変化の無い転写は stat 1 回（決定 12）。
- **カードは高くなった**（97px → 160px・実測）。一覧で一度に見える枚数はその分減る。
- 触った箇所: `layout/{types,migrate,ops}.ts`・`features/panes/{Pane,LayoutMap,paneTitle}`・
  `features/overview/`（新規: ビュー・カード・純関数・CSS・opener）・`app/WsBar.tsx`・
  `features/keys/commands.ts`・`features/repos/{store,parentSync,RepoRow}`・i18n（ja/en）・
  `workspace/agent/internal/gitx/git.go`。
- 試験: 純関数（絞り込み・グループ化・家系の並び・安定性・経過表記）と DOM（隣に開く／
  スマホは同じペイン・修飾キーと中クリックは別ペイン／状態チップは見出し行／親差分チップ／
  待ち経過／メニュー 3 経路／dead は開かない）、Go（`gitRemotePath`）。
  見た目は headless Chromium と README 用スタブで実測（docs/96）。
