# 0127. opencode 1.x のサポートを打ち切り、opencode 2 だけを支える

[English](0127-drop-opencode-1.md) | 日本語

- 状態: **承認**（2026-11-01）。下の A〜C はユーザーが決め、いずれも推奨案を採った。
- Issue: #3132
- 関連: [docs/log/119](../log/119-opencode-caller-session-plugin.md)（opencode 2 への移植、オプトイン、切替）/
  #2101（opencode 2 対応）/ #2105（切替）

## 背景

イメージは切替以降 opencode 2（`@opencode/cli`）をピンしている。ピンはロールバックなしで 2.0.29 から 2.2.5
まで進んだ。それでも `opencode` kind には 1.x 向けの支えが 2 種類残っていて、どちらも使われていない。

- **ロールバック経路。** メジャー版で振る舞いが違うところは、どれも 3 つの判定のどれかで分岐している。
  probe した serve のメジャー（`isV2()`）、インストール済みのメジャー（`installedMajor()`）、起動 1 回分の
  メジャー（`LaunchSpec.Major()`）の 3 つ。分岐しているのは serve API、起動コマンド、サービス設定、指示ファイル、
  プラグイン、ストアの読み取り、npm パッケージ、CI。`OPENCODE_VERSION=1.19.0` だけでイメージを戻せることが、
  これらの分岐の目的だった。
- **オプトイン**（`install-opencode2`、`opencode-major`、`AF_OPENCODE_MAJOR`）。1.x ピンのワークスペースで
  opencode 2 を試せるように、専用の prefix と専用のデータベースへ入れる仕組み。ピンが 2.x の間は
  `PinnedV2()` が無効にするので、切替以降は役目がない。

ロールバック経路は見た目ほど頼れない。切替のときの実測（docs/log/119）では、2.x が移行済みのデータベースを
1.x の opencode で開くと、アップグレード前の会話しか見えない。2.x で作ったものは 1.x から見えない。
つまりロールバックすると、アップグレード後に作った会話がすべて失われる。

既定値も今では逆を向いている。`serveMajor()` は probe が結果を返すまで 1 を返す。`pathMajor()` は
パッケージもピンも読めないとき 1 を返す。そのため最初の probe より前に走るコードは、1.x の入っていない
イメージで 1.x の分岐に入る。

## 決定

### 1. サポートするメジャーは opencode 2 だけにする

`opencode` kind は opencode 2 だけをサポートし、1.x 用のコード経路は削除する。メジャー版が 2 未満の opencode は、
1.x の経路で動かさずに起動時に拒否する。そのとき見つかったバージョンをエラーに出す。

### 2. ロールバックは 2.x の以前の版へピンを戻すことで行う

**決定 A**（採用: 1.x へのロールバックを手放す）。`OPENCODE_VERSION=1.19.0` はサポートするロールバック手段では
なくなる。opencode の版に問題があったときは、同じデータベースを読める 2.x の以前の版へピンを戻して対処する。

### 3. 1.x → 2.x のストア移行は残す

切替以降 opencode を一度も起動していないホームには、1.x の `opencode.db` がまだ残っている。それを最初に開いた
opencode 2 のプロセスが 1.x の会話をその場で取り込み、その取り込みはサーバーが応答を返し始めた後も続く。
`EnsureMigrated`（`migrate.go`）は、取り込みが終わる前に af が会話を「存在しない」と扱うのを防ぐ。だから残す。

**決定 B**（採用: Agent の起動時に移行を済ませてから 1.x の読み取りを削除する）。1.x テーブルの読み取り
（`transcript.go`）が必要なのは、opencode 2 が 1.x のデータベースをまだ開いていない段階で履歴を表示する場合だけ。
Agent が起動時に移行を終えれば、その場合はなくなる。読み取りの削除は同じ変更で行う。

### 4. オプトインの残骸はマージしない

**決定 C**（採用: 残したままにして、消し方をガイドに書く）。オプトインを使ったメンバーのホームには、
`~/.local/share/agent-fleet/opencode2` に専用のインストールが、`~/.local/share/agent-fleet/opencode2-data` に
データベースが残っている。その会話はメインのデータベースへマージされたことがなく、切替の時点で af からは
読まれなくなっている。自動では削除しない。ガイドに、これが何なのかと、手で消してよいことを書く。
状態ディレクトリの名前（`opencode-major`、`opencode-serve.json`）は `statemig` に載せたままにする。古い
ワークスペースに残っているかもしれないファイルを、drift チェックが引き続き把握できるようにするため。

### 5. 1.x のサポートに当たらないもの

- `--standalone`（`AF_OPENCODE_TUI_STANDALONE=1`）は opencode 2 の起動モードなので残す。
- `entrypoint.sh` にある、`~/.local` に残った古い `opencode-ai` パッケージを片付ける処理（一方向のみ）は残す。
  1.x ピンのころに自己更新したホームにはこのパッケージが残っていて、`PATH` 上でイメージの opencode より先に
  見つかってしまう。

## 影響

- `opencode` パッケージからメジャー版の切り替えがなくなり、最初の probe より前に走るコードが 1.x の分岐に
  入らなくなる。
- opencode の契約テストの CI は 2.x だけを流す。2.x で skip するテスト（`skipOnOpencode2`）と、1.x の
  インストールを前提にするテスト（`useMajor(t, 1)`）は削除する。
- standalone の opencode スロットも必ず opencode 2 なので、Console の質問キー操作でもそこに opencode 2 の
  フォームの操作を使える。
- 作業は #3132 に並べたフェーズに分け、1 フェーズ 1 PR で入れる。どこからも到達しないオプトインから先に消す。
