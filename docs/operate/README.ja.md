# 配備を運用する

[English](README.md) | 日本語

Audience: 配備をひとつ建て、上げ、生かし続ける人（ホストの端末か AWS アカウントを持つ）
Source of truth: `deploy/` 配下のスクリプト（記述がスクリプトと食い違ったら、この棚のバグ）
Updated: 2026-08

この棚は**「どう建てて、どう生かし続けるの？」**に答えます。デプロイ形態の選択、
導入、バックアップ、アップグレード、防御、切り分け、撤去。

## ここに書くもの

- runbook。**実際のコマンドを順番に**、各手順の後に何を確認するかとセットで。
- 鍵の生成、バックアップと復旧、アップグレードと切り戻し、インシデント対応。
- 入口・TLS・サインイン方式・egress 統制、そして各シークレットの在り処。
- 規模: サイズ、アイドル自動停止、動かし続ける費用。

## ここに書かないもの

- **能力の事実**（どの形態にどの機能が在るか）→
  [ref/deploy-targets.md](../ref/deploy-targets.ja.md)。
- **なぜその構造なのか** → 仕組みは [build/](../build/README.ja.md)、
  理由は [decisions/](../decisions/)。
- **テナント単位の管理** → [admin/](../admin/README.ja.md)。
  **境目は端末の有無**です。読者が端末を必要とするならここ。

## 更新トリガ

デプロイ形態・導入/更新の手順・設定が必要な変数・見分けるべき故障モードの変更。
