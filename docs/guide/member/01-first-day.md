# 01. 初日 — ログインから最初のセッションまで

> 対象: 初めて Console を開くメンバー。ログイン、ようこそカードの 4 ステップ、最初の
> リポジトリ clone、そして「一日の終わりに Workspace を止めていいのか」までを順にたどります。

## ログインする

Console の URL をブラウザで開くと、まず **Google でのログイン**を求められます。会社の
Google アカウントでサインインしてください（許可されたアカウントだけが入れます）。

ログインすると、上段の TOP バーに**テナント選択**が出ます。テナントは部署などの
グループで、あなたの Workspace はテナントごとに分かれています。多くの場合は 1 つだけなので、
そのまま進んで構いません。複数に所属している人は、作業したいテナントを選んでください
（画面の名前は [README](README.md) を参照）。

## ようこそカードの 4 ステップ

初回はメイン領域に **「Agent Fleet へようこそ」** というカード（「数ステップで
使い始められます」）が出ます。これは**チェックリスト**で、各ステップを終えるたびに自動で
チェックが付き、最初のセッションを作ると消えます。上から順に進めてください。

1. **ワークスペースを起動** — 「起動」ボタンで、あなた専用のコンテナ（Workspace）を立ち上げます。起動中は「起動中…」と表示され、running になるとチェックが付きます。まずこれをしないと後の操作ができません。
2. **git プロバイダを接続** — 「接続する」から、GitHub または Bitbucket にサインインします。これで private リポジトリを clone できるようになります（接続の詳細は [04 リポジトリと git](04-git.md)）。
3. **エージェントを接続** — 「接続する」から、Claude / Codex / opencode のいずれかにサインインします。少なくとも 1 つ接続すればチェックが付きます（接続の詳細は [06 エージェント](06-agents.md)）。
4. **最初のセッションを作成** — 「新規セッション」で最初のセッションを起動します。shell や claude などが選べます（詳細は [02 セッション](02-sessions.md)）。

急いでいなければ、この 4 つを上から順にこなすのが最短です。

### カードを閉じても大丈夫

右下の **「あとで」** を押すとカードは消え、以後は出ません。カードを閉じても、
同じことは通常の画面からいつでもできます。対応は次のとおりです。

| ようこそカードのステップ | 閉じた後の同じ操作 |
|--------------------------|--------------------|
| ワークスペースを起動 | WS バーの起動 / 停止トグル |
| git プロバイダを接続 | ⚙設定 → 「Git」タブ |
| エージェントを接続 | ⚙設定 → 「エージェント」タブ |
| 最初のセッションを作成 | 左ペイン Sessions の「新規セッション」 |

## 最初のリポジトリを clone する

エージェントに仕事をさせるには、まず作業対象のリポジトリを Workspace に持ってきます。
左ペインの **Repos** から **「リポジトリを clone」** を開きます。

- 接続済みの GitHub / Bitbucket があれば、**「接続から選ぶ」**（既定）でリポジトリとブランチを一覧から選べます。
- 一覧に無い、あるいは未接続のものは **「URL 手入力」** で clone URL を貼ります。
- private リポジトリは、ステップ 2 の git 接続が前提です。

**「Clone」** を押すと取得が始まり、終わると Repos の一覧に並びます。その行の **「起動」**
から、そのまま最初のセッションを起動できます。詳しい手順とつまずきどころは
[04 リポジトリと git](04-git.md) にまとめています。

## 一日の終わりに — Stop していい？

**Stop して構いません。** WS バーの停止トグルで Workspace を止めても、次のものは残ります。

- clone したリポジトリと、その中の変更（コミット前の作業も含む）。
- 実行していたセッションの一覧。**停止中**として残り、次に Start したときにクリックで再開できます（再開できないケースは [02 セッション](02-sessions.md) を参照）。
- git やエージェントの**接続（ログイン）**。Stop / Start をまたいで保持されます。

停止中の Workspace でも、左ペインの**セッション一覧は見えます**（中身の操作はできません）。
つまり通勤中にスマホで「どのセッションがあったか」を眺めるくらいは、止めたままでも可能です。

止め忘れても心配は要りません。**しばらく操作がないと自動で停止**します（アイドル自動停止）。
資源の節約になるので、明示的に止めるのが面倒なら放っておいても大丈夫です。

ただし、**コミットしていない変更は Workspace の中だけにあります**。長期の作業は
こまめにコミット・push しておくと安心です（[04](04-git.md)）。

### 初日の終わりのチェック

- 大事な変更はコミット・push したか（Workspace の外に残るのは push した分だけ）。
- 走らせっぱなしにしたいセッションは、止めなくてもそのまま残ります。区切りが良ければ ⋯ メニューの「停止する（あとで再開できる）」で止めておくと、次回クリックで再開できます（[02](02-sessions.md)）。
- Workspace は Stop しても、放っておいて自動停止に任せても構いません。

初日に「あれ？」となりやすい点（claude がログイン画面を出す、セッションが再開できない、
clone に失敗するなど）は [09 困ったとき](09-troubleshooting.md) にまとめてあります。
