# 02. セッション — AI との会話を起動・切り替え・止める

> 対象: セッションを日常的に回すメンバー。新規作成、状態の見方、止め方の使い分け
> （停止／削除／アーカイブ／作り直す）、再開できる条件、fork とブランチ名変更までを扱います。

セッションは、1 つの AI エージェント（または shell）の実行です。端末 1 枚に対応し、
左ペインの **Sessions** に並びます。複数のセッションを並行して持て、それぞれが独立した
会話・作業フォルダを持ちます。

## セッションの種類（kind）

新規作成時に種類を選びます。

- **shell** — 通常のシェル（bash）。いつでも選べる既定です。
- **claude** — Claude Code を起動。
- **codex** — Codex CLI を起動。
- **opencode** — opencode を起動。

claude / codex / opencode は、対応するエージェントを接続してから選べるようになります
（接続は [06 エージェント](06-agents.md)）。未接続だと、モーダルに
「claude / codex / opencode / ssm は、設定 で認証・ホスト登録すると選べるようになります。」
と案内が出ます。（別ホストへ入る **ssm** は [08 一歩進んだ使い方](08-advanced.md)。）

## 新規セッションを作る

左ペイン Sessions の **「新規セッション」**（または WS バーの新規）から
**「新しいセッション」** モーダルを開きます。

- **種類** — 上のいずれか。既定は shell。
- **モデル** — claude のときだけ出ます。既定 / Opus / Sonnet / Haiku から選べます（初期選択は Sonnet）。他の種類では出ません。
- **リポジトリ** — claude / codex / opencode のとき、どこで作業するかを選びます。3 つの取得元があります。
  - **場所を選ぶ** — 既に clone 済みのフォルダを選んで起動（clone しない）。ホームのまま（~）でも起動できます。
  - **接続から clone** — 接続済みの GitHub / Bitbucket からリポジトリとブランチを選んで clone。
  - **URL から clone** — clone URL を手入力（接続していないリポジトリ向け）。「clone URL」と「ブランチ（任意）」を入れます。
- **タイトル（任意）** — 一覧で識別する名前。空なら自動命名（リポジトリ名＋日時）になります。あとから変更できます。

作成すると「作成して開く」で起動します（clone を伴うときは「Cloning…」と表示されます）。

### worktree と新規ブランチ — 並行作業の要

同じリポジトリで複数タスクを同時に進めたいとき、作業フォルダが 1 つだと互いに
踏み合います。Agent Fleet は既定で、セッションごとに独立した作業コピー（worktree）を
切り出してこれを防ぎます。

- clone を伴うとき、**「新規ブランチ（任意）」** を指定すると、そのブランチを基点ブランチから作成して切り替えます。空なら基点ブランチのまま進みます。ブランチ名を入れると **「フォルダ名」** も指定でき、別フォルダの作業コピーになります。
- 既に clone 済みのリポジトリでは、**「作業コピー」** の選択が出ます。「既存で作業」（今のフォルダで checkout）か、「別コピーを新規」（並行作業用に別フォルダへ clone）かを選べます。既定は、目的のブランチが既に checkout されていれば「既存で作業」、そうでなければ「別コピーを新規」です。

Repos の行から起動する場合（[04](04-git.md)）は、より明快に **「作業を始める」** モーダルで
**「新しい worktree」**（隔離・ブランチ切替から安全＝既定）と **「このコピーで直接」** を
選べます。既定は「新しい worktree」です。

## 状態を読む — バッジと通知

一覧の各行 2 行目に、種類バッジと**状態チップ**が出ます。稼働中セッションは 4 秒ごとに
自動更新されます。

| チップ | 意味 |
|--------|------|
| 進行中… | エージェントが作業中（回転） |
| 質問あり | あなたに質問していて、返事待ち |
| プランあり | 提案されたプランの確認待ち |
| 許可待ち | 操作の許可を求めている |
| 入力待ち | 手が空いていて、次の指示待ち |
| 入力待ち · BG実行中 | 入力待ちだが、裏で処理が走っている |
| 起動中 | shell など（進行中／入力待ちの区別を持たない種類） |
| 停止中 | 止まっている（クリックで開いて再開） |
| フォルダ無し — 再開不可 | 作業フォルダが消えて再開できない（後述） |

見ていない間に状態が変わると、**ブラウザ通知**が出ます（その画面を開いているときは
抑止されます）。作業が一段落＝入力待ちになると **「回答が返ってきました」**、質問が来ると
**「質問が来ています」** と通知され、本文にセッション名が入ります。通勤中にスマホで
返事を待つ、といった使い方に向きます（shell / ssm は通知しません）。

## 止め方の使い分け（重要）

行の **⋯ メニュー**（または右クリック）から操作します。似た言葉が並ぶので、
違いを押さえてください。

- **停止する（あとで再開できる）** — 稼働中のセッションを止めます。**会話は保持され、あとで再開できます**。確認は「会話は保持され、あとで再開できます。」。端末で自分で終了したのと同じ、いちばん軽い止め方です。→ 停止中として一覧に残ります。
- **アーカイブする（一覧から消す）** — claude などのエージェントで、一覧から**隠します**（消えるわけではありません）。会話は保持され、あとで復帰できます。復帰は Sessions ヘッダの**アーカイブ済み**一覧の「復帰」から。
- **削除する** — shell / ssm など使い捨ての種類で出ます。**取り消せません**（「この操作は取り消せません。」）。会話ログのファイル自体は残りますが、一覧からは消えます。
- **作り直す（今の会話はアーカイブへ）** — **同じ場所で新しい会話を始めます**。今の会話はアーカイブに退避され、あとで復帰できます。「最初からやり直したい」ときに使います。

停止中のセッションをまとめて片付けたいときは、Sessions ヘッダから
**「停止中のセッションを整理」** で一括処理できます（エージェントはアーカイブ、
shell / ssm は削除）。古いアーカイブは、アーカイブ済み一覧の「古いものを削除」
（30 日以上前）で掃除できます。

## 再開できる／できない

停止中のセッションはクリックで開いて再開できます。ただし claude / opencode は、
**起動時の作業フォルダが消えていると再開できません**。この場合チップが
**「フォルダ無し — 再開不可」** になり、行は打ち消し線でクリックできなくなります
（「作業フォルダが存在しないため再開できません」）。作業コピーを worktree ごと消したあとが
典型例です。shell は作業フォルダが無ければホームに戻って再開します。

停止中のセッションを開くと、まず履歴が読み取り専用で表示され、**「再開」** で会話を
再開します。ペインの中で **Ctrl+クリック**（または中クリック）すると、今の表示を保ったまま
**新しいペインに開け**ます（[03 ターミナル](03-terminal.md)）。

Workspace を止めていても（stopped）、**一覧そのものは見えます**。中身の操作はできませんが、
「どのセッションがあったか」はスマホからでも確認できます。

### ブランチが入れ替わったときの警告

セッションの行に**警告アイコンとブランチ名**が出ることがあります。これは、その
セッションの作業コピーが、起動時のブランチから別のブランチへ**切り替わっている**サインです。
稼働中のエージェントが見ている作業ツリーが入れ替わり、編集や差分が食い違っている
恐れがあります。心当たりがなければ、意図しないブランチ切替が起きていないか確認して
ください。並行作業では、セッションごとに worktree を分けておくとこの混乱を避けられます。

## 会話を分岐する（fork）

claude では **「分岐（会話を引き継いで新規）」** で、今の会話を引き継いだ新しい
セッションを別に作れます（元のセッションはそのまま残ります）。「ここまでの文脈を保ったまま
別の方向を試したい」ときに便利です。

## タイトルとブランチ名を変える

- **タイトルを変更** — 一覧での識別名を変えます。空のまま保存すると自動命名（リポジトリ名＋日時）に戻ります。**「AIに提案してもらう」** で会話内容から名前を提案させ、「この案にする」で採用できます。
- **ブランチ名を変更** — worktree で動いているセッションだけに出ます。その worktree のブランチを改名します（フォルダ＝セッションはそのまま）。`feat/` `fix/` `refactor/` `chore/` `docs/` のプレフィックスをチップで付け替えられ、**「AIに提案してもらう」** で会話からブランチ名を提案させられます。暫定名（`temp/…`）で始めたセッションに、あとで意味のある名前を付けるのに使います。
