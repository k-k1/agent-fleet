# テナント管理者ガイド

[English](README.md) | 日本語

あなたはチームの **テナント管理者（tenant_admin）** です。メンバーの追加、資源の使われ方の把握、
監査ログ・利用状況の確認を、ブラウザの「テナント設定」から行います。多くの管理者は自分も開発する
メンバーを兼ねています。日々の開発操作そのものは [member/](../member/README.ja.md) を読んでください。
ここでは「チームを管理する側」の話だけをします。

この分冊は独立して読めるように書いてありますが、内部の「仕組み」は開発者向けの
[dev/](../../dev/README.md) にあります。事実の重複を避けるため、仕組みが知りたくなったら
そちらへリンクで送ります。

## まず結論: あなたにできること／見える範囲

- **見えるのは自分のテナントだけ** です。他部署（他テナント）のメンバーもセッションも、あなたには
  一切見えません。デプロイ全体を見られるのは super_admin（後述）だけです。
- テナントをまたぐ設定（テナントの新規作成、テナント全体の資源上限、アイドル自動停止、egress 統制など）は
  あなたの権限の外です。必要なときは **情シス／デプロイ管理者に依頼** します。

| できること | 画面 | 詳細 |
|-----------|------|------|
| メンバーを追加する | メンバー → メンバー追加 | [01-members.md](01-members.ja.md) |
| メンバーごとのセッション上限を決める | メンバー → 該当メンバー → 操作 | [02-limits.md](02-limits.ja.md) |
| メンバーの資源（メモリ／CPU／ディスク）と稼働セッションを見る | メンバー → 該当メンバー | [02-limits.md](02-limits.ja.md) |
| 稼働中のワークスペースを強制停止する | メンバー → 該当メンバー → 操作 | [02-limits.md](02-limits.ja.md) |
| テナント全体の稼働セッションを俯瞰する | セッション | [02-limits.md](02-limits.ja.md) |
| 誰が何を変更したか（監査ログ）を見る | 監査 | [03-audit-usage.md](03-audit-usage.ja.md) |
| 利用状況（稼働時間）を見て CSV で書き出す | 使用量 | [03-audit-usage.md](03-audit-usage.ja.md) |
| チーム共通の MCP サーバーを全員へ配布する | MCP 配布 | [04-mcp-egress.md](04-mcp-egress.ja.md) |
| 自社の IdP でログインできるようにする | サインイン方式 | [operator/01 導入](../operator/01-install.ja.md) |

## テナント設定への入り方

1. 画面右上の、あなたのメールアドレスが出ているボタン（アカウントメニュー）を開きます。
2. メニューの中の **「テナント設定」** を選びます。

この項目は、**どこかのテナントで tenant_admin になっている人にだけ**表示されます。ふつうの
メンバーには出ません。同じメニューに「設定」（自分の表示・エージェント・Git などの個人設定）も
ありますが、それは別物です。チームを管理するのは「テナント設定」の方です。

同じメニューにある盾アイコンの **「管理」は super_admin（デプロイ全体の管理者）専用**で、
あなたには表示されません。テナントの新規作成やテナント全体の上限など、デプロイ全体に届く
設定がそこにあります。あなたの仕事はすべて「テナント設定」の中で完結します。

## テナント設定の構成

左のレールが 2 つのグループに分かれています。

**ログイン**

- **サインイン方式** — 自社の IdP（Entra ID / Okta / Keycloak など）、または **GitHub の組織**を
  このテナントのログイン方法として登録します。登録しただけでは動かず、デプロイ管理者の承認が
  要ります。GitHub を選んだ場合は issuer の代わりに**許可する GitHub 組織**を書き、OAuth App は
  自社の org に作ったものを使います（承認で読まれるのは「組織と受け入れドメインの組」で、
  **組織を追加すると承認がやり直し**になります）。
  → [operator/01 導入](../operator/01-install.ja.md)
- **ログイン規則** — このテナントに効いている「使えるサインイン方法」「自動参加ドメイン」
  「招待できるドメイン」を**読み取り専用**で確認します。変更はデプロイ管理者の担当です
  （招待が弾かれた理由を、人に聞かずに読めるようにするための面です）。
  ★ 他テナントとの**兼務**の人がいる場合、「使えるサインイン方法」を自社の方式だけに絞ると、
  その人はこのテナントに切り替えられなくなります（同じアドレスでも、別の IdP のアカウントは
  別のログインとして扱われるため）。その人の方式は受け入れたまま「**ボタンを出さない方式**」に
  書けば、このテナントのログイン画面には出ません。受け入れても入れる人は増えません
  （誰が入れるかを決めるのは名簿です）。変更はデプロイ管理者に相談してください。

**運用**

- **メンバー** — 名簿と、各メンバーの詳細（資源・セッション・操作）へのドリルダウン。
  日々いちばん使う区画です。→ [01-members.md](01-members.ja.md)・[02-limits.md](02-limits.ja.md)
- **セッション** — テナント内で「いま動いている」セッションを一覧で俯瞰します。→ [02-limits.md](02-limits.ja.md)
- **使用量** — 期間を区切って、メンバーごとのワークスペース稼働時間を見ます。CSV で書き出せます。→ [03-audit-usage.md](03-audit-usage.ja.md)
- **監査** — 変更操作の記録（誰が・いつ・何を）を検索します。→ [03-audit-usage.md](03-audit-usage.ja.md)
- **MCP 配布** — チーム共通の MCP サーバーを、テナントの全メンバーへ配布します。
  → [04-mcp-egress.md](04-mcp-egress.ja.md)

外部通信の統制（egress）と読み上げエンジン・共通辞書は **super_admin 専用**で、この画面には
出ません。必要になったら情シス／デプロイ管理者へ依頼してください。→ [04-mcp-egress.md](04-mcp-egress.ja.md)

どの区画でも、見えるのは自分のテナントの分だけです。**複数のテナントの管理者を兼ねている場合
だけ**、レールの一番上にテナントの切り替えが出ます。

## 誰が何を担当するか

Agent Fleet の管理は、あなた（tenant_admin）だけでは完結しません。役割の切り分けはこうです。

| 事柄 | 担当 |
|------|------|
| メンバーの追加、セッション上限、ワークスペースの強制停止、監査・使用量の確認、**退職の一式（外す → 停止 → home を掃除）** | **あなた（tenant_admin）** |
| テナントの新規作成、テナント全体の資源上限・アイドル自動停止の設定、管理者権限の付与、ログイン規則の変更、サインイン方式の承認 | デプロイ全体の管理者（super_admin） |
| チーム共通の MCP サーバーの配布 | **あなた（tenant_admin）** |
| egress（外部通信）統制、読み上げエンジンと共通辞書 | super_admin |
| 加入方式の切替（自動加入⇄招待制）、デプロイ全体の環境設定、バックアップ、アップグレード、ホストの障害対応 | 情シス／SRE（operator） |

super_admin と情シスは同じ人が兼ねていることも多く、あなたから見ればどちらも「上流に依頼する相手」です。
自分の権限で完結しないことに気づいたら、[operator/README.md](../operator/README.ja.md) の担当者に相談してください。

権限の仕組み（RBAC）や管理 API の内部設計を詳しく知りたい場合は、
開発者向けの [dev/03 コントロールプレーン](../../dev/03-control-plane.md) を参照してください。

## 管理者になったら、まず

初めてテナント管理者になった日にひととおり触っておくと、いざというとき迷いません。

1. **テナント設定に入れることを確認する** — 右上のアカウントメニューに「テナント設定」が出ていれば
   OK です。出ていなければ、あなたのアカウントにまだ tenant_admin 権限が付いていません。super_admin に
   付与を依頼してください。
2. **メンバー一覧を眺める** — 「メンバー」で、いま誰が所属しているかを確認します。
   自動加入モードなら、ログインした人が自動で並んでいるはずです。→ [01-members.md](01-members.ja.md)
3. **いま効いている上限を知る** — 同じ「メンバー」の先頭に出る「上限 — ワークスペース / セッション」を
   見ておきます。厳しすぎ／緩すぎると感じたら、テナント全体の上限は super_admin、個人のセッション上限は
   あなた自身で調整します。→ [02-limits.md](02-limits.ja.md)
4. **監査と使用量の見方を覚える** — 平常時のログと稼働量を一度見ておくと、異常時に「いつもと違う」に
   気づけます。→ [03-audit-usage.md](03-audit-usage.ja.md)

日常運用では、朝いちに「セッション」で稼働状況を俯瞰し、月末に「使用量」で稼働時間を書き出す、
といった使い方が中心になります。
