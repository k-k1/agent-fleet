# テナントを管理する

[English](README.md) | 日本語

Audience: テナント管理者（チームのメンバー・上限・連携に責任を持つ人）
Source of truth: Console のテナント設定（画面と食い違ったら画面が正）
Updated: 2026-08

あなたはチームの**テナント管理者**です。テナント設定からメンバーを追加し、資源の
使われ方を把握し、監査ログと利用状況を見ます。管理者の多くは自分も作業するメンバー
なので、日々の開発は [use/](../use/README.ja.md)、この棚は「チームを管理する側」の
半分だと考えてください。

## 要点

- **見えるのは自分のテナントだけ**です。他部署（他テナント）のメンバーもセッションも
  まったく見えません。
- テナントをまたぐ設定——テナントの作成、テナント全体の上限、アイドル自動停止、
  egress 統制——はあなたの権限外です。**配備管理者に頼んでください。**
- どのロールに何が許されているかは [ref/roles.md](../ref/roles.ja.md)。この棚は
  「やり方」です。

## 章立て

1. [メンバー](01-members.ja.md) — 追加、削除、退職処理の一連
2. [資源の上限とセッション](02-limits.ja.md) — メンバー毎の上限、いま動いているもの、強制停止

## 入口

画面右上のアカウントメニュー（メールアドレスのボタン）に**テナント設定**があります。
どこかのテナントの管理者である人にだけ出るので、普通のメンバーには見えません。
同じメニューの**設定**は**個人設定**で、別物です。

盾アイコンの**管理**は配備管理者のもので、あなたには見えません。

## あなたのものと、そうでないもの

この分割は信頼の階層ではなく、**影響範囲（blast radius）の分割**です。効果がテナントを
またぐもの、人を締め出し得るものは、あなたの上流に置いてあります。

| ことがら | 持ち主 |
|---|---|
| メンバーの追加と削除、メンバー毎のセッション上限、ワークスペースの強制停止、監査と利用状況の確認、**退職処理の一連** | **あなた** |
| 共通の連携サーバーをチームへ配る | **あなた** |
| サインイン方式の登録、ログイン規則の閲覧、接続元の制限、自テナントの OAuth アプリ | **あなた**（サインイン方式は承認が要る）|
| テナントの作成、テナント全体の上限とアイドル自動停止、管理権限の付与、ログイン規則の変更、サインイン方式の承認 | 配備管理者 |
| egress 統制、読み上げエンジン、共有辞書 | 配備管理者 |
| バックアップ、アップグレード、ホストの障害対応 | 配備管理者（多くは情シス / SRE と同じ人）|

自分の権限では終わらないことに気づいたら、相談先は [operate/](../operate/README.ja.md)
にいる人たちです。

## 管理者になった初日にやること

**何ごとも無いうちに一度回っておく**ことが、いざというときに迷わない唯一の方法です。

1. **入れることを確認する** — アカウントメニューに「テナント設定」があるか。無ければ
   まだ権限がありません。配備管理者に頼んでください。
2. **メンバー一覧を眺める** — いま誰が在籍しているか（[01 メンバー](01-members.ja.md)）。
3. **効いている上限を知る** — 「上限・自動停止」で。あなたには読み取り専用で、
   メンバー毎のセッション上限はあなたのものです（[02 上限](02-limits.ja.md)）。
4. **監査と利用状況の画面を平常時に一度読む** — それが後で「いつもと違う」に
   気づける唯一の準備です（[03 監査](03-audit-usage.ja.md)）。

日々の呼吸は、朝に「セッション」をひと目、月末に「稼働時間」を書き出す、くらいです。

## この棚に書くもの

- 効果が**他人に及ぶ**手順。
- 管理者向け画面の読み方と、**その数字が何を含み、何を含まないか**。

書かないもの: 能力の事実（[ref/](../ref/README.ja.md)）、メンバーが自分のためにやること
（[use/](../use/README.ja.md)）、配備を建てる・上げる話（[operate/](../operate/README.ja.md)）、
そして実装の語彙——**テナント管理者はホストの端末を持ちません。この棚は端末があることを
前提にしません。**
