# 執筆規範

[English](CONVENTIONS.md) | 日本語

全棚の全ファイルに適用します。機械的に検査できる部分は
`scripts/docs-check.py` が見ます。push の前に走らせてください。

```
python3 scripts/docs-check.py           # CI が走らせるもの
python3 scripts/docs-check.py --strict  # warn を error に格上げ
```

## 1. 1 ファイルに寿命は 1 つ

旧レイアウトが失い、そして崩壊した原因の規則です。文章は 3 通りの速さで古びます。
**この 3 つを同じファイルに入れてはいけません。**

| 寿命 | 置き場 |
|---|---|
| コードが変われば変わる（仕様・手順・能力表）| `use/` `admin/` `operate/` `build/` `ref/` |
| 二度と変わらない（決定・実測・事故・捨てた案）| `decisions/`、または凍結した `log/` |
| 毎日変わる（いま何が動いているか）| `HANDOFF.md` |

混ざったファイルは陳腐化のレビューができません。**どの文が「まだ真であるはず」なのかを
判別する手段が無い**からです。現役の文書に「第 7 ラウンド」を追記しそうになったら、
それはジャーナルを書いています。恒久的な結論だけを現役の文書に残し、経緯は決定記録へ。

## 2. 棚は「読者」で切る。ジャンルでは切らない

ディレクトリ構成はそのまま配布の境界です
（`control-plane/workspace_docs.go` の `docsRolePrefixes` が、読者のロールから
どの棚をコンテナへ渡すか決めます）。だから文書の置き場は**誰が読むか**で決まり、
どういう種類の文書かでは決まりません。ジャンルで切った棚は、誰にも配れません。

## 3. 必須の冒頭ヘッダ

`use/ admin/ operate/ build/ ref/` の全ファイルは、先頭 12 行以内にこう始めます。

```markdown
# タイトル

[English](title.md) | 日本語

Audience: 誰のためか（一句で）
Source of truth: この文書と食い違ったとき、どちらが正か
Updated: 2026-08
```

`Source of truth:` があると陳腐化に耐えられます。`build/` なら普通はコード、
`operate/` なら `deploy/` のスクリプト、`use/` なら Console そのもの。
**明記しておけば、矛盾を見つけた読者がどちらを信じるべきか分かります。**

## 4. 棚ごとの語彙

- **`use/` と `admin/` は画面の名前だけで話す。** 読者が Console で見る言葉が正しい
  言葉です。env 変数名・内部の種別識別子・API パス・ソースのパスは地の文に書けません
  （どうしても示すならコードブロックで引用）。CI が検査します。
- **`operate/` はコマンド・パス・変数を使ってよい**——読者は端末の前にいます。
- **`build/` はワイヤ契約と責務で書く**。どのプロセスが何を持ち、外から見た契約は何か。
  **行番号は絶対に書かない**（1 週間で腐ります）。grep できるアンカー
  （エンドポイントパス・env 名・エラーコード文字列）かコードマップを指してください。

## 5. 二言語

英語が正（`X.md`）、日本語は隣（`X.ja.md`）。**同じ変更で両方を更新します**——
訳が古い棚は、訳が無い棚より悪い。

- H1 の直後の行が言語スイッチャで、**言語をまたいでよい唯一のリンク**です。
- 他の内部リンクは言語内で閉じます（`.ja.md` からは `.ja.md` へ）。日本語のみの区画
  （`decisions/` `log/`）へは、両言語とも同じターゲットを指します。
- UI ラベルは Console の文字列を引用します（英語は
  `console/src/lib/i18n/locales/en.ts`、日本語は `ja.ts`）。ボタンの訳を勝手に作ると、
  **画面上に存在しない言葉**を読者に探させることになります。

## 6. 同じことは `ref/` に一度だけ書く

能力の事実——どのエージェントが何に対応しているか、どのプロバイダが、どのデプロイ形態が、
どのロールが何をできるか——は `ref/` にだけ置きます。他の棚は表へリンクします。
**表が 2 つあるということは、片方はもう間違っている**ということです。

軸がコードに在る表は、コードと突き合わせます。エージェントの列は
`workspace/agent/internal/session/session.go` の `Kind*` 定数を、デプロイの行は
`control-plane/runtime.go` の `newRuntimeFactory` が受け付けるプロファイルを
覆っている必要があります。CI は**突合するだけで生成はしません**（表現は人が決める）。

## 7. `log/` へリンクしない

`log/` は凍結アーカイブです。現役の文書がそこへリンクするのは「本当の答えは
ジャーナルの中にある」と言うのと同じで、旧レイアウトが 3,400 行の作業ログに仕様を
埋没させたのはまさにこれです。**必要な事実は現役の文書へ転記し、実測はその場に書く。**
CI がこのリンクを弾きます。

## 8. 機能の完了条件

利用者から見える変更は、次が済むまで終わっていません。

1. `ref/features.md` に行が在る。
2. 影響する読者の棚に節が在る。
3. 蒸し返され得る論点を決着させたなら、`decisions/` に記録が在る
   （**何を退けたか、その理由も**）。
