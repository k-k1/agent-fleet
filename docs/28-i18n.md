# 28. Console の全面 i18n（UI 文言の多言語化 — 日本語↔英語） — 設計

**Status: 🚧 P0 基盤＋Intl 集約 main マージ済（`a226d04`）／P1 設定タブ群＋P2 中核画面（複数形 `tCount`・
`<Trans>` インフラ含む全画面・モーダル・行）を `temp/sm5hcv2` に実装・push 済（typecheck/test 264/build 緑）・
P3〜P5 残（§6 引き継ぎ参照）** — Console UI を全面的に多言語対応する。
第 1 弾は日本語（ソース）↔英語。方式は**自前の軽量 i18n 層**（外部ライブラリを入れず、既存の
`lib/settings.ts` 外部ストアと `Intl.*` の上に構築）。範囲はフロント UI 文言＋バックエンドの
ユーザー向けエラー＋サーバ描画（ログイン/OAuth）ページ。エージェント出力言語（`outputLanguage`）は
別軸として本書の対象外。決定の経緯は [decisions/0016](decisions/0016-i18n.md)。

---

## 0. 要旨

- **確定した方式**: 外部 i18n ライブラリを採用せず、`lib/settings.ts` の `useSyncExternalStore`
  ストアに `locale` を足し、その上に `t(key, vars)` ランタイム＋`Intl.*` フォーマッタを自作する。
  理由は (1) 既存が自前ストア/自前 Provider を貫く最小依存方針、(2) i18n は **React と非 React
  両方**（`client.ts` の `errText`、`notifications/store.ts` の `wording`、`tts.ts` の読み上げ）から
  呼ぶ必要があり、これは `settings.ts` が既に解いている二重消費と同型、(3) 複数形が要る箇所は約 25 で
  `Intl.PluralRules` で足り、日付/数値/相対時刻は元々重複フォーマッタを `Intl` へ集約したい整理と相乗り。
- **ロケールの単一真実源**: `settings.locale`。`theme` を丸ごと踏襲する（localStorage＋サーバ同期、
  初回描画前に適用）。ただし `theme` と違い**端末ローカルにしない**（言語は人単位で全端末追従）。
- **型でキー欠落を守る**: カタログは型付き（`keyof typeof ja`）。CI の `typecheck` がキー欠落・
  未翻訳キーを検出するので、ライブラリのツールに頼らずに回帰を防げる。
- **翻訳せず「ロケールゲート」する日本語専用機能**: TTS のかな読み変換・なろう形式ルビ・縦書きは
  `locale==='ja'`（実質 `provider==='voicevox'`）でゲート。IME 変換ガードは全ロケール維持。
- **バックエンド**: 既存の `{code, message}`＋`ERR_TEXT` 方式（docs/23 P0-3）にロケール層を足すだけ。
  `workspace/agent/` の未コード化和文エラー約 47 個をコード化し、ログイン/OAuth の Go 描画ページは
  React に乗らないので別途 `Accept-Language`／ロケール cookie で多言語化する。

## 1. 背景・現状

### 1.1 現状はゼロ、ただし seam は既にある

`package.json` に i18n ライブラリ無し。`Intl.*`／`navigator.language` の使用箇所ゼロ。
`console/index.html:2` は `<html lang="ja">` 固定で実行時に更新されない。UI 文言は全て和文ハードコード。

一方、過去の設計で i18n を見越した「継ぎ目」が既に入っている。これを土台にする:

- `core/api/client.ts:91-95` — `ERR_TEXT`（エラーコード→和文マップ）の直上に
  `// Add a locale layer over this map when i18n lands` と明記済み。
- `control-plane/errcodes.go` / `workspace/agent/errcodes.go` — 言語非依存の安定コードを定義。
  バックエンドは英語 developer fallback を返し、表示文言は Console が `code` から解決する（docs/23 P0-3）。
- `lib/settings.ts` — 自前 `useSyncExternalStore`。localStorage＋`/api/env/ui-prefs` サーバ同期、
  `getSettings()`（非 React）と `useSettings()`（React）の二重口。`applyTheme()` が
  `<html data-theme>` を初回描画前に適用。**`theme` が `locale` の完全なテンプレート**。

## 2. 設計

### 2.1 ロケールの単一真実源（`settings.locale`）

`Settings` に `locale: string` を追加し、`theme` と同じ経路に載せる:

- 既定値: `navigator.language` から解決（`ja*`→`ja`、その他→`en`）。未対応言語は `ja` フォールバック。
- 端末ローカルにしない（`DEVICE_LOCAL` に入れない）＝サーバ同期し全端末で追従。
- `applyLocale(s)` を新設し、`applyTheme` と同じ 3 箇所（モジュールロード `settings.ts:622` 近傍、
  `setSettings` `:729`、`hydrateUIPrefs` `:713`）で呼ぶ。`applyLocale` は
  `document.documentElement.lang = s.locale` を書き、i18n ランタイムへ現ロケールを通知する。
- `LOCALES`（`THEMES` と同型の `{id,label}[]`。ラベルは各言語の自称: `日本語` / `English`）。

### 2.2 i18n ランタイム（`lib/i18n/`）

- `t(key, vars?)` — **React にも非 React にも同一関数**。現ロケールは `getSettings().locale` から引く
  （＝ストアが単一真実源。ライブラリの別ストアと二重化しない）。
- `useT()` — `useSyncExternalStore(subscribe, ...)` でロケール変更時に再レンダー（`useSettings` と同型）。
- 補間 — `{name}` プレースホルダを `vars` で置換。HTML はエスケープ（テキストノード前提）。
- 複数形 — `Intl.PluralRules(locale)` で `one/other/...` を選び、キーの複数形バリアント
  （`key.one`/`key.other`）を出す。日本語は常に `other` に解決。
- 型安全 — `ja` を正本カタログとし `export type MsgKey = keyof typeof jaFlat`。`t` は `MsgKey` 限定。
  `en` は `Record<MsgKey, string>` を満たすことを型で強制 → **未翻訳キーは tsc で落ちる**。
- `<Trans i18nKey ...>` — JSX 内マークアップ混在（例 `useSessionActions.tsx:121` の `<strong>` 埋め込み）用。
  プレースホルダをスロット（`<0>…</0>`）で受ける最小実装。
- カタログはロード時同梱（ja/en の 2 言語・各数十 KB で誤差）。3 言語目以降で肥大化したら
  非既定ロケールを `import()` 遅延ロードへ。

### 2.3 `Intl` フォーマッタの集約（`lib/intl.ts`）

i18n と独立に「やるべき整理」でもある。ロケール対応 util に一本化する:

- `relTime(locale, ...)` — 重複 3 個（`BranchList`/`CommitGraph`/`NotificationCenter`）を
  `Intl.RelativeTimeFormat` で統合。「本日まで/明日まで」等の特殊語はロケール別テーブル。
- `fmtDateTime(locale, ...)` — 手書き 4 個（`WsBar`/`MirrorView`/`ChatView`/`sessionview`）を
  `Intl.DateTimeFormat` へ。月日順はロケールで反転。
- `fmtNum(locale, ...)` — `Intl.NumberFormat`。`AdminTab.tsx:389` の素の `toLocaleString()`（＝ブラウザ
  ロケール追従の唯一の漏れ）も明示ロケール指定へ。単位語（トークン/件…）はカタログへ移す。
- `localeCompare` 使用箇所（`lib/project.ts` ほか）は明示ロケール＋`sensitivity` を渡す。

### 2.4 日本語専用機能は「翻訳」でなく「ゲート」

- TTS かな読み変換（`applyBuiltinReadings`/enkana/読み辞書/感情スタイル）、なろう形式ルビ
  （`readerText.ts`）、縦書き（`readerVertical`）は `locale==='ja'`（実質 `provider==='voicevox'`）で
  ゲート。英語 UI では Polly 等の英語音声へ流れ、かなパイプラインはスキップ。
- IME 変換ガード（`ChatView`/`MirrorView`/`TerminalView` の composition 判定）は
  **全ロケール維持**（中韓・アクセント入力も composition する）。
- CJK フォントスタックはそのまま（Latin でも無害）。ただし読みビューフォントのラベル
  `明朝`/`ゴシック` は UI 文言なので翻訳対象。短い和文ラベル前提の `white-space:nowrap` 幅
  （`viewer.css`/`ui.css`）は英語で溢れうるので P4 で再点検。

### 2.5 バックエンド（範囲内）

- **マップ済みコード**（`quota_sessions` ほか約 11）: バックエンド変更不要。`ERR_TEXT` にロケール層を足すだけ。
- **未コード化の和文エラー約 47 個**（`workspace/agent/` の chat_handlers/connections/session_title/
  assistants/session_paste/session_handlers/chat_providers）: 安定 `code` を割り当て、backend `message` を
  英語化、Console 側でコード→ロケール表示。両側同時変更ルール（errcodes.go のコメント）を踏襲。
- **ビルトインアシスタントの名前・説明・シード約 17 個**（`assistants.go`/`chat_handlers.go`）: 固定集合なので
  Console 側カタログへ寄せ、フロントで表示解決する（バックエンドはキー/id を返す）。
- **サーバ描画ページ約 17 個**（`oauth_google.go` の `loginPageHTML`、`oauth_bitbucket.go` の
  `bbCallbackPage`）: React に乗らないので Go 側で `Accept-Language`（ログイン前はロケール cookie 不在の
  可能性）で言語選択し、和文/英文の 2 版を持つ。

## 5. リスク・未決

- カタログ規模（約 956＋バックエンド）を一気に移すのは大きい。P0 は基盤＋PoC に絞り、P1 以降を
  ファイル群単位で分割する。英訳は下訳を付けてレビューで磨く前提。
- サーバ描画ページのロケール源（ログイン前）が別経路。`Accept-Language` を第一候補、確定後は
  ロケール cookie を発行して以降の描画に使う。
- 複数形以外の言語差（語順・単位位置）はキー設計で吸収。文字列連結（`+` 組み立て。`MirrorView` の
  読み上げラベル等）はキー化時に 1 メッセージへ畳む。

## 6. 引き継ぎ（次セッションの作業手順）

文脈ゼロの別セッションが本書だけで P1 以降を進められるようにまとめる。P0 基盤＋Intl 集約は
main（`a226d04`）に入っており、以降は「文言をキー化して `t()` に置換する」作業の反復。

### 6.1 いま使えるインフラ（実装済み・参照実装）

- `console/src/lib/i18n/index.ts` — `t(key, vars?)`（型付き）/`tMaybe(key, vars?)`（動的キー・無ければ
  `undefined`）/`useT()`（React・ロケール変更で再レンダー）/`useLocale()`（現ロケール文字列）/
  `setLocale`/`getLocale`/`MsgKey`/`SUPPORTED_LOCALES`。**`t()` は非 React からも呼べる**。
- `console/src/lib/i18n/locales/ja.ts`（正本）・`en.ts`（`Record<keyof typeof ja, string>`＝**全キー必須**、
  過不足は `tsc` が落とす＝完全性ガード）。
- `console/src/lib/settings.ts` — `locale`（既定 `navigator.language`→ja fallback・`DEVICE_LOCAL` 外＝
  サーバ同期）・`LOCALES`・`applyLocale()`（`<html lang>`＋i18n へ push）。
- `console/src/lib/intl.ts` — `relTime`/`fmtDateTime`（＋`TIME_HM`/`DATETIME_FULL`）/`fmtNum`。
- 参照実装: `core/api/client.ts`（`errText`＋`tMaybe`）／`features/notifications/store.ts`（`wording()` の
  title/body/**speech**）／`features/settings/DisplayTab.tsx`＋`app/TopBar.tsx`（言語ピッカー＋`labelKey`）。

### 6.2 文字列 1 つを i18n 化するレシピ

1. **キーを決める**（`namespace.snake`。例 `git.repo_delete_confirm`）。既存の namespace（`err`/`notif`/
   `theme`/`settings`/`common`）に寄せる。
2. **`ja.ts` に `"key": "和文"` を追加、`en.ts` に同じキーで英訳を追加**（`en` に欠けると tsc が落ちる）。
3. **使用箇所を置換**:
   - React の JSX テキスト/属性: 先頭で `const tr = useT();` → `{tr("key")}` / `title={tr("key")}`。
   - 非 React（store/util）: `import { t } from ".../lib/i18n/index.ts";` → `t("key")`。
   - 補間: `tr("key", { name })`＋カタログ値に `{name}` プレースホルダ。
   - 実行時に決まる動的キー（例 backend の `err.<code>`）: `tMaybe("err." + code)`。
   - ラベル定数（`[{id,label}]`）: `label` を `labelKey: MsgKey` に変え、描画側で `tr(x.labelKey)`
     （`THEMES`/`REGION_THEMES` が済み例）。
4. `npm run typecheck` で未翻訳キーを検出。

### 6.3 まだ無い＝最初に作るインフラ（P2 冒頭で）

- **複数形**（英 one/other・日は単一。約 25 箇所）: `lib/intl.ts` に `pluralCategory(n)=new Intl.PluralRules
  (getLocale()).select(n)` を足し、`t` に「`vars.count` があれば `key_${category}` を引く」分岐（i18next 風
  suffix）を実装。カタログは `foo_one`/`foo_other` を両言語に。
- **`<Trans>`**（JSX 内マークアップ混在。例 `useSessionActions.tsx:121` の `<strong>` 埋め込み）: スロット
  （`<0>…</0>`）で子要素を差し込む最小コンポーネントを `lib/i18n` に新設。

### 6.4 翻訳しない／ゲートする（重要・触るな）

- **LLM プロンプト**は翻訳しない（表示でなくモデル挙動）: `MirrorView.tsx:382`（要約プロンプト）、
  `memo.go`、`chat.go` の persona／`session_title.go` の日本語強制など。
- **日本語専用機能は `locale==='ja'` でゲート**（P4）: TTS かな変換（`ttsText.ts`/`tts.ts` の
  `applyBuiltinReadings`/enkana/読み辞書/`emotionOf`）・なろう形式ルビ（`readerText.ts`）・縦書き
  （`readerVertical`）。これらの UI **ラベル**は翻訳するが、変換**ロジック**は触らない。
- **IME 変換ガード**（`ChatView`/`MirrorView`/`TerminalView` の composition 判定）は全ロケール維持。
- 対象外: VOICEVOX キャラ名・コメント・`*.test.ts`・`workspace/workspace-notes.md`。

### 6.5 フェーズ別 対象ファイル（着手順）
