# mirror-handoff — 引き継ぎカードが会話を隠さないことの検証

`npm --prefix console run mirror:handoff`（先に `npm --prefix console run build` が必要）

## 何を守っているか

引き継ぎ提案カードは以前、全グループの**後ろ**＝転写スクローラの最後の子として描画されていた。
消えないカードがそこに居ると、ミラーの着地位置を恒久的に占有する——自動追従は最下部へスクロールし、
カードに着地し、直前に送ったプロンプトも流れてくる返答も画面外へ押し出される。送信も転写も
`/messages` も正常なのに「送信しても何も出ない」に見える（2026-08-04 実障害・spzdqtt）。

修正後は**提案した時刻の位置**にカードを置く。次のターンが来るまでは最後、来たら会話が下に流れる。

## 3つの検査

`../mirror-scroll/stub.mjs` に `--handoff` を渡して形を作り、実バンドルを headless Chromium
（素の CDP・Playwright なし）で開いて DOM と可視領域を測る。スマホ幅（420×780）で見るのは、
カード単体が画面より高くなる＝隠れ方が最も強い条件だから。

| モード | 期待 |
|---|---|
| `mid` | 提案の後にターンがある → カードは最後ではなく、**最新ターンが可視** |
| `new` | 提案直後で後続なし → カードが最後（配置は時刻駆動であって決め打ちではない） |
| `launched` | 起動済み → 提案は**残り**、起動済みバッジが付く |

## 効くことの確認方法

`chronoInsertIndex` の先頭に `return times.length;`（旧＝常に最後）を入れて `build` し直すと
`mid` だけが NG になる。ロジックの単体側は `src/features/mirror/handoffPlacement.test.ts`。
