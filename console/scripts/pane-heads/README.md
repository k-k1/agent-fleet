# pane-heads — タブ付きグリッドのヘッダ右上ボタンの位置検証

```bash
npm --prefix console run panes:heads
node console/scripts/pane-heads/check.mjs --widths 480,700,1100 --only chat --screenshot /tmp/heads.png
```

ビルド不要（`console/dist` も CP も不要）。終了ステータスが検査結果。

## 何を守っているか

タブ付きグリッドのセルは**浮動の操作クラスタ `.pane-controls` を描かない**。別タブで開く／折り返し／
閉じるは `headerActions` として**選択中ビューのヘッダ行の中**に入る。ここが 2026-08-14 に2系統で崩れた。

1. **使われない予約ガター**（全ビュー）。ヘッダは浮動クラスタ用の右余白 `--pane-ctl-w`
   （= 16px + ボタン数×24px・`panes.css`）と各ビューの上乗せ（`.fileview` +56px / `.scmview` +28px /
   ブラウザツールバー +6px）を予約したままで、ボタンが右端から 65〜212px 内側に押し込まれていた。
2. **auto マージンが2つ**（アシスタントチャットのみ）。`.session-state` は左レール行用に自前で
   `margin-left:auto` を持つ（`sessions.css`）。この帯の**直接の子**としてこのチップを出すのは
   チャットだけで（ミラー/ターミナルは `.pane-session` に入れ子）、auto マージン持ちが2つある行では
   flex が余白を**均等配分**し、待機中／作業計画が行の中央に取り残されていた。

## 3つの不変条件

ビュー8種（ミラー／ターミナル／チャット／SCM／ファイル／ドキュメント／共有／ブラウザ）を
幅 480・700・1100px で測る。

| 不変条件 | 落ちると | 期待値の出どころ |
|---|---|---|
| クラスタ右端がペイン右端に十分近い | 予約ガターの復活 | **同じページに置いた非タブのペイン**の `.pane-controls` を実測（9px）。ハードコードしない |
| 行の大きな穴は1つだけ | auto マージンの二重化 | 隣り合う子の隙間を全部測り、24px 超が2つ以上なら NG |
| ヘッダ1行目に載り、タブ列の下に潜っていない | 折り返し・z 重なり | クラスタの垂直中心と `.pane-tabs` の高さ(32px) |

## なぜ unit テストではないのか

原因が **CSS のカスケードとフレックスの余白配分**そのもので、jsdom はレイアウトを計算しない。
一方で React も CP も要らない——`console/src/**/*.css` は素の CSS なので、**実ファイルをそのまま
`<link>` して**ヘッダの DOM だけを置けば、出荷物と同じカスケードで寸法を測れる。

- **CSS は 1 枚も落とさず全部 link する**。最初の版は `sessions.css` を落としており、上記2番目の
  崩れを「無い」と誤報告した。だから `check.mjs` は `main.tsx` の import 順を読み取り、
  **`src` 配下の残り全部**を前に足す（`App` 経由の CSS は `main.tsx` 自身の import より先に評価
  されるため）。link 漏れが起きない作りにしてある。
- ミラー/ターミナルが**切替とクラスタのどちらを先に描くか**は CSS でなく JSX の判断なので、
  `MirrorView.tsx` / `TerminalView.tsx` から実際の並びを読み取って組み立てる。並びを元に戻すと
  `rightGap` が ~150px になり NG になる。読み取れなければ**黙って既定に倒さず exit 2**。

## 限界

ヘッダの DOM は各ビューの JSX からの**転記**であって、レンダリング結果ではない。守れるのは
カスケードと寸法で、**`.tsx` にボタンを足しても自動では現れない**（増やしたら `VIEWS` に足す）。
実バンドルを動かす検証が要るものは `../mirror-scroll` / `../mirror-handoff` の方式を使う。

## 効くことの確認方法

`panes.css` の `.pane:has(.pane-tabs)` ブロックか、`ui/ui.css` の
`.view-head .session-state ~ .view-head-actions` を消して実行する。前者は全ビューが NG（実測で
ミラー212px / ファイル121px / SCM93px / ブラウザ71px / チャット・ドキュメント65px）、後者は
チャットが「大きな穴2つ」で NG になる。
